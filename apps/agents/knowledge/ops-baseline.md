## 운영 기준선 (ADR-015 7단계 지식 파일)

@ops · 주장이 사건을 판단할 때 쓰는 정상 범위 · 조회 방법 · 측정 함정이다. 사건이 닫히면 바뀐 기준선 · 새 함정을 이 파일에 PR로 더한다. 공개 저장소라 비밀값 · 운영 사용자 ID · 개인 정보는 쓰지 않는다. 수치마다 잰 날짜를 붙인다.

### 정상 범위

- **요청량 (2026-10-16):** `offside-api` 하루 약 110만 요청(10-11부터 비슷하게 유지), 하루 순방문 약 8천. 늘어난 흐름: 09-25 하루 4천 → 10-01 12만 → 10-05 62만 → 10-11 111만. "트래픽이 몰렸다"는 제보는 먼저 이 흐름과 견준다.
- **응답 시간 (2026-10-16, Smart Placement 뒤):** 엣지 `requestDuration`(성공) p50 51–62ms, p75 106–142ms. 워커 안에서 시즌 업로드 PUT 약 70ms, 403 약 15ms. 배포 전(10-16 이전)은 p50 200–243ms, 시즌 PUT 624ms(p90 784)였다.
- **D1 (2026-10-16):** 주 DB 지역 APAC(싱가포르), 읽기 복제 auto. `queryBatchTime` p50 약 0.2ms(D1 자체는 빠르다). 쓰기는 낮 시간 시간당 약 6만 행. 저장 용량은 10GB 한도에 가깝다(10월 중순 4GB대, `infra-health.yml`이 매시 예측).
- **5xx:** 평소 거의 0. 0.5%를 넘으면 사건으로 의심한다.

### 서버 상태 판정 (`GET /v1/status`, T-11-321)

- 5분 칸마다 워커가 센 요청 수 · 평균 응답 시간 · 1초 넘은 요청 · 5xx를 준다. 엣지에 60초 담겨 운영 D1을 건드리지 않는다.
- 칸 판정: 5xx 2% 이상이면 오류, 평균 800ms 이상이거나 1초 넘은 요청이 10% 이상이면 느림. 요청 100개 아래 칸은 판정하지 않는다. 서버 상태 감시(5분마다)는 끝난 칸이 두 칸 이어 나쁘면 사건을 연다(6시간에 한 번).
- 집계는 Cloudflare 실측의 88~95%다(OPTIONS · WebSocket을 세지 않는다).
- 배포 직후 15분은 화면의 '분당 요청'이 낮게 보인다(새 isolate가 칸을 채우는 중, 일시적).

### 조회 방법

- **Workers 로그:** Cloudflare MCP의 telemetry query. 운영 API 로그는 샘플(약 10%)이라 건수는 10배로 어림한다. 시간 범위를 경보 전후 1시간처럼 좁힌다.
- **엣지 지연:** Workers 분석의 `requestDuration` 분위수(성공 요청만 걸러서).
- **D1:** D1 분석(`queryBatchTime` · 읽기 · 쓰기 행). 큰 테이블을 `COUNT(*)`로 훑지 않는다.
- **시간대:** 로그 · 분석 쿼리는 UTC다. KST = UTC+9. 결과가 0건이면 9시간 어긋남부터 의심한다.

### 측정 함정

- **WebSocket(라운지 채팅 · 실시간)이 wallTime p90을 크게 올린다.** 지연을 볼 때는 WebSocket 업그레이드 요청을 빼거나 `requestDuration`(엣지)을 쓴다.
- **Smart Placement가 풀리면 지연이 4배쯤 뛴다.** 워커가 서울 엣지에서 돌면 D1(싱가포르)까지 쿼리마다 약 100ms가 왕복하고, 순차 쿼리 수만큼 쌓인다(401 약 100ms, 시즌 PUT 600ms대). 응답 헤더 `cf-placement`가 `remote-SIN`인지, 워커 설정의 placement 상태가 SUCCESS인지 먼저 본다.
- **캐시 히트가 p25를 끌어내린다.** 공개 GET은 엣지 캐시라 p25는 10ms대다. 판단은 p50 · p75로 한다.
- **D1은 한 쿼리에 바인딩 값을 100개까지만 받는다.** 2026-10-17 00:05–01:30 KST `GET /v1/cups/current`가 `owner_teams ... IN (?, ?, …)` 100개 초과로 503을 내 5xx가 2–5%까지 올랐다(T-11-322로 고침). 5xx가 한 경로에 몰리고 오류 문구가 `Failed query`면 IN 목록 길이부터 본다.
- **GitHub 예약 워크플로는 몇 분~수십 분 늦게 돈다.** 늦은 건 실패가 아니다.
- **5xx 경보와 앱 OTA 시점이 겹치면** 옛 앱 빌드의 요청 형식이 원인일 수 있다. 플랫폼 · 앱 버전별로 나눠 본다.
