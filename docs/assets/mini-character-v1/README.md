# OFFSIDE 미니형 선수 v1

2026-10-12 사용자가 고른 `01-mini` 시안을 게임 도트 선수로 옮긴 에셋이다.

## 구성

- `hair-atlas-source.png`: 내장 image_gen으로 만든 머리 모양 9종 서 있는 시트(생성 기록 `generation.json`)
- `packages/game/src/avatar-mini-data.ts`: 서 있는 그림 9종, 48×64 재질 글자 지도
- `packages/game/src/avatar-mini-motion/<머리 모양>.ts`: 모션 자세 17종, 64×72 재질 글자 지도(길이 압축)와 얼굴 · 엠블럼 · 완장 · 앞발 · 손 자리
- `packages/game/src/avatar-mini.ts`: 재질 지도를 모습(`AvatarSpec`)대로 칠한다. 색표는 `avatar.ts`가 정본이다
- `packages/game/src/avatar-motion.ts`: 모션 12종(자세 · 몸 옮기기 · 공 · 트로피 · 흙먼지)

피부 · 머리색 · 유니폼 · 축구화 · 양말 · 밴드 · 고글은 그림에 고정하지 않고 칠할 때 정한다.
표정 · 수염 · 헤어밴드 · 고글은 그림마다 흰자 자리를 찾아 얹는다(자세 그림은 서 있는 그림의 얼굴 자리를 옮겨 쓴다).
손목 밴드는 자세 그림의 소매 끝 피부를 따라 칠한다. 선택한 표정은 움직이는 자세에도 적용한다.
목발 · 정장 · 꽃다발이 있는 선수는 무대에서도 같은 정지 자세를 유지해 소품을 보존한다.
동작 줄이기를 켜면 정지 자세로 보이며 모션 자세 파일을 불러오지 않는다. 자세 파일 로딩 실패 시 정지 그림을 유지하고 다음 열기에서 재시도한다.

## 모션 자세 만들기

머리 모양마다 서 있는 그림을 기준 이미지로 붙여 image_gen으로 시트 두 장(달리기 · 리프팅 · 슈팅 · 점프 10칸, 무릎 · 손 흔들기 · 들어 올리기 · 좌절 8칸)을 만든다.
바지는 남색, 양말은 겨자색으로 고정해 색만으로 재질을 나눈다. 시트는 저장소에 두지 않는다(장당 1MB 안팎).

변환 순서는 다음과 같다.

1. 원본 해상도에서 색을 40개로 줄인다.
2. 서 있는 키(61줄)에 맞춘 칸마다 가장 많이 나온 색을 고른다.
3. 외톨이 칸을 정리한다.
4. 색상 · 채도 · 밝기로 재질을 나누고, 재질 안의 명암 비율은 서 있는 그림에 맞춘다.
5. 몸통 가운데와 발바닥을 맞춰 64×72 프레임에 놓는다.
6. 서 있는 머리를 옮겨 대 보며 얼굴 자리를 찾는다.

## 표시 규격

| 항목 | 서 있는 그림 | 모션 프레임 |
|---|---|---|
| 실제 픽셀 | 48×64 | 64×72 |
| SVG viewBox | 0 0 24 32 | 0 0 32 36 |
| 바닥 | y=62 | y=70 |

웹과 React Native는 사각형의 `h`(0.5)를 그대로 그린다. 모션 자세는 무대(진행 시트)가 열릴 때 그 선수 머리 모양 파일 하나만 불러온다.


### 선수 카드 초상

구단주 선수 카드(라커룸·전술판·확대·이적시장·시즌 결산)는 같은 미니형 그림의 얼굴과 어깨를 `0 0 24 21`로 잘라 사용한다
커리어 ID로 정한 얼굴에 저장된 최신 `look` 코드를 적용하며 카드용 전성기 표현에는 흰머리·목발·꽃다발을 넣지 않는다
카드에는 마지막 구단 정보가 없어 기본 유니폼을 사용한다
옛 선수처럼 `look`이 없어도 동일 커리어는 동일 얼굴이고 유스 자리는 기존 유니폼 표시를 유지한다
웹과 앱은 `avatarPortraitRects`를 함께 사용하며 기존 목록 응답에 꾸미기 코드만 더해 추가 조회를 만들지 않는다

## 기존 은퇴 선수 외형 변경

내 은퇴 선수 결산의 꾸미기에서 기본 외형을 무료로 바꿀 수 있다
미리보기·취소는 저장하지 않고, 외형 저장에서만 반영한다
서버에 기록된 선수는 소유자·은퇴 상태를 확인하는 `PUT /v1/careers/:careerId/look`으로 `look` 열만 수정한다
기록·능력치·점수·자금·은퇴 시각·스냅샷·선수 카드 수치와 은퇴 보상은 변경하거나 재계산하지 않는다
서버 기록이 없는 옛 기기 기록은 이 기기에만 저장했다는 안내를 표시하며 서버 기록을 새로 만들지 않는다
기록 아이템은 저장된 획득 칭호 또는 기존 착용 값으로 확인하고, 없는 칭호를 추정하지 않는다
다른 이용자의 공개 상세·공유 화면은 편집할 수 없다
공개 목록의 캐시는 최대 1분, 다른 데이터센터의 상세 캐시는 최대 5분 뒤 외형이 갱신될 수 있다

## 진행 팝업 위 달리기와 슈팅

프리시즌 단계와 시즌 경기 중계 팝업은 계속 보이며 진행 내용·기록·건너뛰기 버튼을 그대로 쓴다
팝업 위쪽 테두리에 56px 캐릭터와 오른쪽 픽셀 골대를 배치한다
공까지 달려가 발을 들어 슛하고, 공이 골대 안으로 들어가면 짧게 기뻐한 뒤 왼쪽부터 다시 시작한다
웹·앱은 같은 시간표·자세 프레임·골대·공 궤적 데이터를 사용한다
슈팅 자세에 들어 있던 공을 제외하고 별도 공 하나만 골대까지 날린다
캐릭터는 팝업 내용과 분리된 투명한 장식 레이어이며 화면을 가리지 않고 입력·초점을 가로채지 않는다
웹은 실제 팝업 위치를 따라가는 포털, 앱은 스크롤 본문 밖의 장식 레이어를 사용한다
좁은 화면·가로 화면에서는 캐릭터가 잘리지 않도록 팝업의 최대 높이에 위쪽 여유를 둔다
진행이 끝나거나 건너뛰기를 누르면 캐릭터가 사라지고 기존 결과·확인 흐름을 유지한다
동작 줄이기·목발·은퇴 소품은 정지 그림으로 대신하며 자세 로딩 실패도 진행을 막지 않는다
연출 때문에 대기 시간을 늘리거나 게임 엔진·RNG·세이브 형식·결과 계산을 바꾸지 않는다
