## 1. 제품 목표와 우선순위

**“짧은 선택이 선수의 출전·관계·커리어에 남고, 은퇴 후에는 다른 선택으로 다시 살아보고 싶은 축구 인생 게임.”**

고도화의 첫 목표는 기능 개수가 아니라 다음 네 경험이다.

1. **끝까지 진행된다.** 첫 계약부터 이적·임대·부상·은퇴까지 진행이 끊기지 않는다.
2. **선택한 이유와 결과를 이해한다.** 높은 OVR만 정답이 아니라 팀 적합도·신뢰·컨디션·주무기를 고려한다.
3. **내 선수의 이야기가 남는다.** 지난 선택이 나중의 기회와 관계에 다시 등장한다.
4. **다음 회차가 궁금하다.** 점수 재도전뿐 아니라 다른 포지션·리그 선택·커리어 유형을 경험하고 싶어진다.

우선순위의 의미:

- P0: 진행·저장·결과 신뢰성 또는 출시를 막는 항목.
- P1: OFFSIDE의 재미와 차별성을 만드는 첫 출시 핵심 항목.
- P2: 실제 이용 데이터와 운영 기반을 확보한 뒤 확장할 항목.

## 3. 권장 실행 순서

Phase 번호를 전부 순차 실행하지 않는다. 공유 데이터 계약을 먼저 확정하고, 서로 다른 영역은 병행한다. 단, 첫 정식 시즌 개방은 장기 커리어와 시즌 보존 검증 이후다.

```text
M0 현재 기능 통합·진행 차단 해소
 ├─ M1 선택의 재미·후속 서사 강화 ──────────┐
 ├─ 초기 LINE TEST: 한 시즌 실제 사용 검증 ─┤
 └─ 공유 계약 확정                        │
     ├─ M2 장기 커리어·은퇴·Legacy ────────┤
     └─ M3 구버전 보존·서비스 시즌 ────────┤
                                         ↓
                             M4 출시 리허설·KICKOFF
                                         ↓
                             국내 서비스 시즌 기준선
                                         ↓
                             M5 WORLD STAGE 확장
```

공유 계약의 선행 항목은 통산 기록의 정본, CareerTag의 근거 ID, Archive 구조, Career별 ruleset/content pack 선택, Legacy 계산 버전이다. 날짜는 이 게이트와 실제 개발 가용량이 확인된 후 산정한다. 현재 정보만으로 “몇 주 안에 출시”를 약속하지 않는다.

### M0. 기존 플레이를 믿을 수 있게 마감한다 — P0 / Phase 3–4

- 임대 계약 표시, 종료 후 복귀, 새로고침·중복 클릭, 다시 다음 시즌까지 검증한다.
- 결산 델타·대시보드·저장 Snapshot의 최종 수치가 일치하는지 확인한다.
- 부상·대표팀·관계 이벤트의 정상/대기/오류/재시도/완료 상태를 화면과 연결한다.

**게이트:** 위 핵심 경로에 진행 차단이 없고, 관련 테스트가 격리 실행과 전체 실행 모두 통과한다. UI 구현 여부와 엔진 구현 여부를 별도 표시한다.

### M1. ‘축구 선수의 선택’이 느껴지게 만든다 — P1 / Phase 2·4 보강

**산출물:** 대표 장기 서사 3개, 실제 도달 가능한 포지션별 챕터, 선택 영향 표현 규칙.

T-4-008의 0.3.0 콘텐츠를 우선 재사용한다. 이벤트 수를 더 늘리기 전에 다음 구조를 갖추게 한다.

`상황·갈등 → 선택의 예상 대가 → 즉시 결과 → 1개 이상 후속 장면 → 시즌/은퇴에서 회수`

| 대표 서사                | 축구적인 갈등                             | 후속 회수의 예                                                    |
| ------------------------ | ----------------------------------------- | ----------------------------------------------------------------- |
| 낮은 OVR의 주전 도전     | 전술 적응 훈련 vs 주무기 강화             | 감독 평가와 출전 기회가 달라지고 핵심 경기에서 선택한 준비가 작용 |
| 임대를 통한 성장         | 유명 팀 후보 vs 작은 팀 선발              | 출전·피로·약속 이행 기록을 근거로 원소속팀 복귀 평가가 달라짐     |
| 부상 이후 두 번째 커리어 | 조기 복귀 vs 재활, 기존 역할 vs 역할 조정 | 재발 위험·팀 신뢰·출전 경로를 거쳐 복귀 장면과 연대기에 남음      |

- 선택 전에는 결과를 확정해서 보여주지 않고 유리한 점·희생하는 점·불확실성을 설명한다.
- 선택 후에는 “무엇이 얼마만큼 바뀌었는지”와 실제 판정에 사용한 주요 원인을 보여준다. 설명 문구를 엔진의 근거와 분리해 꾸며내지 않는다.
- Base OVR, 역할/전술 적합도, 컨디션, 감독 신뢰를 구분한다. 낮은 OVR도 기회를 만들되 기본 능력·체력의 가치를 지우지 않는다.
- GK/DF/MF/FW의 핵심 챕터는 판단 대상부터 달라야 한다. 같은 공격 장면의 문구만 바꾸는 방식은 피한다.
- 관계 기억은 실제 발생한 선택·약속·효과의 ID를 참조한다. 첫 버전부터 자유형 AI 대화 시스템을 추가하지 않는다.
- 아직 실제 생성 경로가 없는 화면/이벤트는 “완료”가 아니다. RUMOUR 등은 출시 대상 여부와 생성 조건을 명시한다.

**게이트:** 대표 서사 각각에 고정 seed 도달 테스트와 후속 결과 검증이 있다. 사람 대상 테스트에서 선택의 원인·결과를 설명할 수 있고, 새 팩의 노출 0건 항목은 이유와 조치를 기록한다.

### M2. 한 선수의 인생을 완결한다 — P0·P1 / Phase 5

**산출물:** 성장·노쇠, 은퇴, 통산 기록, Legacy, 엔딩, 연대기, 선수 보관함의 완성된 연결.

구현은 작은 수직 슬라이스부터 한다.

1. 개발용 fixture로 다년 진행→은퇴→불변 Archive→폴백 엔딩→새 선수 생성을 연결한다. 이것만으로 Phase 5 완료나 정식 출시를 선언하지 않는다.
2. 연령별 성장·노쇠와 은퇴 압력, 마지막 계약/코치 전환/하부리그 도전 등 기획된 마지막 선택을 연결한다.
3. 통산 집계와 Legacy 5축을 구현하고, 요약 카드에서 상위 기여 3개·대표 순간·선택하지 않은 기회를 설명한다.
4. 기존 엔딩 카탈로그 14종(폴백 포함)의 판정·우선순위·도달 fixture를 완성한다. Phase 5의 최소 12종 의미 있는 엔딩 + 폴백 기준을 함께 충족한다.
5. 이전 선수와 다른 포지션·커리어 유형으로 새 회차를 시작하도록 연결한다.

Legacy는 현재 정본인 **0–100, 성취 30·기여 25·장기성 15·관계 15·서사 15**를 유지한다. 원작처럼 큰 누적 점수로 바꾸는 문제는 별도 제품 결정이며 이번 계획에서 임의로 바꾸지 않는다.

엔딩·재플레이 표현에서는 “그때 다른 선택을 했다면 반드시 성공했다” 같은 허구의 반사실을 보여주지 않는다. 실제로 제안받았지만 선택하지 않은 기회, 이미 기록된 분기만 활용한다. 과거 선수 비교도 초기에는 점수 경쟁보다 대표 태그·커리어 유형 중심으로 제공한다.

**게이트:** 20년 fixture 완주, 은퇴 후 일반 진행 차단, 시즌 기록 합과 통산 합 일치, 중복 Legacy 가산 방지, Archive 불변성, 동일 입력 재현성. GK/DF/MF/FW 동일 품질 fixture 점수 차이는 기존 ±5 기준으로 검증한다. 정규화 참조 분포는 문서 기준 포지션군당 최소 10,000개 합성 커리어로 검증한다.

### M3. 첫 버전부터 안전한 시즌제로 운영한다 — P0 / Phase 6

**산출물:** 버전 실행 레지스트리, 시즌 전환, 개인 도전, 시즌 앨범·지난 선수 보관함.

- 선수의 축구 시즌과 운영 서비스 시즌을 UI·저장 모델에서 계속 구분한다.
- Career 생성 시 `serviceSeasonId + rulesetVersion + contentPackVersion`을 원자적으로 고정한다.
- 문자열을 저장하는 것만으로 완료하지 않는다. **해당 Career가 실제로 생성 당시 엔진·콘텐츠로 실행되는지** 검증한다. 과거 버전 자산을 유지하고 지원되지 않는 버전을 현재 버전으로 조용히 대체하지 않는다.
- 서비스 시즌이 끝나도 선수 삭제·강제 은퇴·OVR 소급 변경을 하지 않는다. 기존 선수는 계속 진행하고 신규 시즌 도전 집계는 별도로 한다.
- 복구 코드·로그인 병합·기기 변경에서도 원래 시즌 귀속을 보존한다.
- 개인 도전은 기존 KICKOFF 기본 6종부터 구현한다. 선수의 실제 이력·태그·Legacy 근거를 사용하며, 평가와 보상 수령은 멱등적으로 처리한다.
- 시즌 전환 공지는 기존 선수와 새 선수에 미치는 영향을 나눠 설명한다. LOCKED 중 생성과 진행의 허용 범위도 구분한다.

**게이트:** 전환 직전/중/후 생성 경쟁 테스트, 구버전 선수 완주, 새 버전 선수 분리 집계, 중복 보상 차단, 결산 재실행 동일 결과, 이전 시즌 복구·앨범 열람이 모두 통과한다.

### M4. 실제 사람에게 검증하고 출시한다 — P0 / LINE TEST·Phase 7 일부

**산출물:** 사람 대상 테스트 보고서, 운영 대시보드/오류 관측, 복구·롤백 리허설 기록, 출시 체크리스트.

LINE TEST는 M2·M3 완료까지 기다리지 않는다. M0의 한 시즌 안전성이 확보되면 시작하고, 장기 커리어 완성 뒤에는 은퇴·재플레이 검증을 추가한다.

- 기존 종이 테스트 1회 기록은 보존하고 나머지 2회를 채운다. 1회차에서 확인된 “관계와 신중한 선택을 기억함, 다음에는 높은 리그를 선택하고 싶음”을 가설로 활용하되 시간 측정·챕터 기억 검증은 새로 한다.
- 10–30명 LINE TEST는 이탈·혼란 발견과 기준선 수집용이다. 작은 표본의 비율 차이를 유의미한 밸런스 결론으로 단정하지 않는다.
- 테스트 대상 배포는 Git SHA, ruleset/content pack 버전과 체크섬, 서비스 시즌, 배포 시각을 기록한다. 같은 버전 이름 아래 규칙이 바뀌면 코호트를 나눠 비교한다.
- 오류 수집, 진행 실패 원인, 저장/동기화 실패, 버전 불일치, 결산 실패를 구분한다. 관측 이벤트가 사용자 선택 처리를 막지 않도록 한다.
- staging에서 DB 마이그레이션과 안전한 roll-forward/롤백·복구를 리허설한다. 코드를 되돌리는 것과 이미 변경된 데이터·콘텐츠를 안전하게 읽는 것은 별개다.
- 실제 OAuth 검증, 도메인, 오류 수집 계정, 운영 연락처, 테스터 모집 등 사용자 준비 항목은 기존 U 작업과 연결한다. Cloudflare 플랜은 프로젝트의 외부 공개 전 정책을 확인하며 여기서 새 과금 변경을 실행하지 않는다.

**게이트:** 알려진 진행 차단·저장 손상 P0/P1 결함 해소, 정식 출시 경로 검증, 복구 리허설, 관측·대응 담당과 절차 확보. 큰 파일 분리와 광범위한 구조 개선 전체를 출시 전 조건으로 확대하지 않는다.

### M5. 검증된 국내 커리어를 세계로 확장한다 — P2 / Phase 8

**산출물:** 기존 WORLD STAGE 명세의 첫 해외 슬라이스.

- 선행 조건은 국내 완결 커리어, Legacy·Archive, 콘텐츠 버전 배포·롤백, LINE TEST 및 최소 한 서비스 시즌의 국내 기준선이다.
- 첫 범위는 이미 설계한 해외 국가 2개·4개 디비전·24개 가상 구단으로 제한한다.
- 국내 주전/해외 중소 팀 주전/유명 무대 후보가 서로 다른 유효한 선택이 되도록 한다.
- 새 데이터 계약→해외 제안·등록→현지 적응→대회 기록→국제 커리어 결산 순으로 구현한다.
- 리그 이동이 Base OVR을 직접 올리거나 내리지 않게 하고, 적응과 출전 기회를 별도 상태로 설명한다.
- 해외 확장 때문에 국내 원클럽 경로가 열등한 엔딩이 되지 않는지 Legacy와 도전 분포를 다시 검증한다.

공유 이미지, 더 많은 리그, 고급 통계는 이후 이용자 수요에 따라 선택한다. 실시간 경기·PvP·실명 라이선스·유료 능력 강화는 이번 고도화 범위에 넣지 않는다.

## 7. 공통 완료 조건과 바로 다음 행동

모든 작업은 기존 로드맵의 도메인·데이터·API·화면·콘텐츠·검증·운영을 함께 확인한다. 적용되지 않는 항목은 사유를 기록한다. PR 병합만으로 사용자 경험이 완료되었다고 하지 않는다.

- 관련 요구사항 FR/화면 SCR/기존 작업 T ID, 변경 버전, 테스트 증거를 연결한다.
- 새 화면의 정상·빈 상태·오류·재시도·중복 제출과 새로고침·직접 진입을 확인한다.
- 360px 모바일, 키보드, 핵심 스크린리더 동선, 모션 감소 설정을 확인한다.
- 저장 정본과 설명을 일치시키며, 구버전 기록을 새 수치로 다시 쓰지 않는다.
- 테스트 통과·사람 검증 완료·운영 공개 가능을 별도 상태로 관리한다.

**바로 다음 권장 행동 3가지:**

1. 현재 진행 중인 T-4-005~011과 UI PR이 만들어내는 결과를 UP-01·02의 완료 기준으로 닫는다. 새 전면 UI 작업은 시작하지 않는다.
2. UP-03에서 엔딩의 실제 업적 근거, 한국 국적 범위, Archive/버전 실행 계약을 확정한다. 동시에 기존 staging 리허설과 테스터 준비를 진행한다.
3. 계약 확정 후 UP-04(한 선수 인생 완결)와 UP-08(구버전 실행 보존)을 병행한다. 이 둘이 다음 개발의 중심이다.
