# Phase 7. 운영·밸런스·확장

## 목표

데이터 손상 없이 콘텐츠와 밸런스를 반복 개선하고, 다음 서비스 시즌을 안전하게 출시한다.

## 포함 범위

- 기술·제품 지표 대시보드와 경보.
- ruleset/content pack 검증·서명·배포 파이프라인.
- 이벤트 노출·선택·결과와 OVR/커리어 분포 리포트.
- feature flag, canary, rollback/roll-forward 런북.
- 데이터 내보내기/가져오기 파일과 로그인 병합 결정. 복구 코드는 Phase 1에서 이미 제공된다.
- 접근성·성능·브라우저 호환 회귀 자동화.
- 시즌 2 이후 테마 확장 준비.

## 테마 로드맵

| 시즌 | 중심 확장 |
|---|---|
| PRESEASON: LINE TEST | 저장·OVR·이벤트 밸런스 검증 |
| SEASON 1: KICKOFF | 프로 데뷔와 주전 경쟁 |
| SEASON 2: TRANSFER WINDOW | 이적·임대·에이전트·계약 |
| SEASON 3: DERBY | 라이벌·라커룸 관계 |
| SEASON 4: EXTRA TIME | 노장·부상 복귀·은퇴 번복 |
| SEASON 5: THE FINAL | 대표팀·국제대회 중심 엔딩 |

## 밸런스 검토 질문

- 포지션·아키타입별 첫 계약과 주전 도달률이 과도하게 갈리는가?
- 낮은 OVR/높은 전술 적합도 경로가 실제로 유효한가?
- 단일 선택이 장기 Career를 과도하게 결정하는가?
- 이벤트가 반복되거나 사실상 선택지가 하나뿐인 경우가 있는가?
- 엔딩·도전 과제가 특정 포지션에 불리한가?
- 구 ruleset Career의 재개율과 오류율이 안정적인가?

## 운영 안전장치

- 운영자가 개별 사용자 결과를 임의 변경하지 않는다.
- 긴급 수정은 새 ruleset/content pack으로 배포하고 영향 범위를 기록한다.
- 데이터 보정이 필요하면 대상·이유·전후 hash·재실행 가능 스크립트를 감사 로그에 남긴다.
- PII 없이 fixture로 사건을 재현한다.

## 완료 조건

- [ ] 시즌 전환 리허설과 복구 훈련을 staging에서 통과한다.
- [ ] state hash mismatch와 저장 실패에 자동 경보가 있다.
- [ ] 규칙 버전별 핵심 분포를 비교할 수 있다.
- [ ] 콘텐츠 pack의 잘못된 참조가 production 전에 차단된다.
- [ ] 구/신 ruleset Career E2E를 매 릴리스 실행한다.
- [ ] 장애 시 신규 쓰기 차단과 기존 보관함 읽기를 분리할 수 있다.
