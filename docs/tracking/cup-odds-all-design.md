# 오프사이드 컵 모든 경기 예상 승률 설계 (T-11-407)

T-11-405는 참가 팀 본인의 다음 경기에만 예상 승 · 무 · 패를 보였다. 이 설계는 대회의 모든 경기에 같은 값을 보인다.

## 목표

- 참가하지 않았거나 탈락한 구단주, 승부 예측만 하는 유저도 모든 경기의 예상 승 · 무 · 패를 본다.
- 끝난 경기에도 경기 전 예상을 남겨 "예상 31% 팀이 이겼다"를 확인할 수 있게 한다(운 논란 대응).
- 서버 부하는 라운드마다 한 번 계산으로 끝낸다. 화면이 열릴 때마다 계산하지 않는다.

## 언제 계산하나: 명단 잠금 시각

- 참가 팀 명단은 경기 1시간 전(`lockAt`)부터 경기가 끝날 때까지 바뀌지 않는다(`checkCupLineup`). 선발 선수의 판매 등록 · 감독 전향도 막혀 있다(`checkCupListing` · `checkCupManager`).
- 그래서 `lockAt` 뒤에 계산한 값은 실제 경기와 같은 명단 · 감독으로 계산한 값이고, 경기 때까지 바뀌지 않는다. 한 번만 계산해 저장하면 된다.
- 잠금 전에는 모두에게 보이는 값은 없다. 본인 다음 경기는 지금처럼 `/me`에서 실시간으로 계산해 보인다(T-11-405 그대로).

## 저장

- `cup_matches`에 `odds_json` 열(null 허용)을 더한다. `{ "w": 31, "d": 26, "l": 43, "xh": 1.1, "xa": 1.5 }` — 홈 기준 정수 %와 기대 득점.
- 마이그레이션 하나(drizzle-kit generate). 인덱스는 필요 없다(경기 행과 함께 읽는다).
- 몰수 · 한쪽 팀 없음 · 부전승 경기는 null로 둔다.

## 계산: `runCup` cron(5분)

- `runCup`의 경기 처리 앞에 단계 하나를 더한다. `lockAt <= now`이고 `played_at`·`odds_json`이 비어 있는 경기를 라운드 순으로 골라 계산한다.
- 한 번에 `CUP_MATCHES_PER_TICK`경기까지. 64경기 라운드도 cron 몇 번이면 잠금 뒤 10~20분 안에 다 찬다. 경기 시각까지 50분 넘게 남아 있다.
- 쿼리 수: 배치 안 팀을 한 번에 읽고(`ownerTeams` inArray), 경기마다 `lineupsOf`(선발 · 감독 2번)를 부른다. 32경기면 70번 안쪽이다. 묶음 조회(`lineupsOfMany`)는 선수 id가 D1 바인딩 상한(100)을 넘어 쪼개야 해서 이번에는 두지 않았다.
- 계산은 `matchOdds(home, away, season, { neutral: true, coaches })`(T-11-405) 그대로. 경기 시뮬레이션과 같은 `matchSetup`을 써서 값이 어긋나지 않는다.
- 경기 처리(`playCupMatch`) 때 `odds_json`이 아직 비어 있으면(cron 지연 등) 그 자리에서 계산해 같이 저장한다. 끝난 경기에 예상이 빠지지 않게 한다.

## 응답

- `/v1/cups/:cupId`(엣지 캐시 30초)의 `matches[]`에 `odds: { win, draw, loss } | null`(홈 기준)를 더한다. 이미 모두가 같은 응답을 받는 공개 GET이라 요청 · 세션 조회가 늘지 않는다.
- 응답 크기: 대회 최대 경기 수 기준 경기당 30바이트 남짓. 문제없다.
- 경기 상세(`/v1/cups/:cupId/matches/:matchId`)에는 이번에 넣지 않았다. 경기 줄에 경기 전 예상이 남는다.
- `/me`의 `nextOdds`는 잠금 뒤에는 저장값을 쓰고, 잠금 전에만 실시간 계산한다. 이러면 잠금 뒤 화면 값이 서로 같다.
- 계약: `CupMatchSchema`에 `odds: CupMatchOddsSchema.nullable().optional()`(옛 앱 호환).

## 화면(웹 · 앱)

- 경기 일정 · 승부 예측 카드의 경기 줄: 두 팀 이름 아래에 승 · 무 · 패 얇은 막대와 `홈 47% · 무 26% · 원정 28%`. 토너먼트는 "비기면 승부차기" 안내를 일정 머리에 한 번만.
- 잠금 전 경기: 막대 없음. 경기 일정 머리에 "예상 승 · 무 · 패는 경기 1시간 전, 명단이 잠기면 나와요." 한 줄(경기마다 붙이면 64줄이 같은 문장으로 덮인다).
- 끝난 경기: 같은 막대에 "경기 전 예상" 라벨. 이변 표시는 두지 않았다.
- 내 경기 칸(T-11-405)은 그대로 둔다.
- 문구는 ko · en · ja `cup.ts`, 공개 가이드(`seo.mjs` 컵 단락) · FAQ · 릴리즈 노트를 같은 PR에서.

## 승부 예측과의 관계(2026-10-19 A안으로 결정)

예측은 경기 시각까지 열려 있고, 맞히면 리롤권을 준다(대회 상한 있음). 잠금 뒤 예상 승률을 보이면 예측이 쉬워진다.

- **A. 잠금 뒤 공개, 예측은 그대로(추천).** 지금도 팀 OVR이 보여 유저는 이미 강한 쪽을 고른다. 예상 승률은 그 판단을 정확하게 해 줄 뿐이고, 최대 확률도 대부분 60~70%라 정배만 골라도 많이 틀린다. 리롤권은 대회 상한이 있어 지급량이 크게 늘지 않는다.
- B. 경기 시작(예측 마감) 뒤 공개. 예측 게임은 지금과 같지만, 경기 전에 "이 경기는 몇 %"를 볼 수 없어 공지가 약속한 효과가 약하다.
- C. A + 정배를 맞히면 보상을 줄이기. 규칙이 복잡해지고 예측 보상 정산을 바꿔야 해서 이번 범위에서 뺀다.

## 테스트

- api: 잠금 전 경기는 계산하지 않음, 잠금 뒤 한 번만 계산(두 번째 cron은 쿼리 없음), 몰수 · 빈 팀은 null, 경기 처리 때 비어 있으면 채움, 저장값과 `/me` `nextOdds`가 같음, `/v1/cups/:cupId`가 쿠키가 있어도 세션 · 프로필을 조회하지 않음.
- web e2e: 참가하지 않은 계정으로 일정의 막대 · 잠금 전 안내 · 끝난 경기의 예상 표시, 일정을 여러 번 열어도 `/v1/cups/current` 요청이 늘지 않음.
- 앱: 경기 줄 렌더 단위 테스트.

## 범위 밖

- 친선전 · 리그전의 예상 승률.
- 예상 승률 기반 배당 · 보상.
- 잠금 전 모든 경기의 실시간 예상(명단이 바뀌어 매번 계산해야 해서 부하가 크다).
