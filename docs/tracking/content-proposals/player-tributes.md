## 문제·유저 니즈와 기존 콘텐츠의 차이

가설은 완성한 은퇴 선수를 숫자 높은 카드 외의 이야기로 다시 기억하고 싶을 수 있다는 것이다. 예를 들어 **게임 안에서 무관으로 은퇴한 내 선수**의 트로피 도전을 별도 시나리오로 만든다. 현실 선수 전기·실제 인물의 경력 추정이 아니라 서버에 수락된 게임 커리어 기록이 소재다. 원 선수에게 우승을 소급 지급하지 않는다.

[명예관](../owner-profile-honors-plan.md), [시즌 특별 카드 PR #777](https://github.com/tasddc1226/offside-football-simulator/pull/777), 영구결번과 헌정·표시가 겹친다. 이 모드는 추가 경기 과제이고 시즌 MVP·베스트11 선정이나 영구결번 기준을 바꾸지 않는다. #656과 겹치는 NPC 경기 대신 **어떤 실제 게임 기록으로 도전을 만들었는지**가 핵심이며 근거 없는 감동 서사를 자동으로 만들지 않는다.

## 핵심 루프와 화면 흐름

라커룸 은퇴 선수 → 헌정전 자격/기록 근거 → “원 커리어/헌정 목표” 두 영역 → 헌정 전용 선발(주인공 포함) → NPC 경기 → 성공/실패와 별도 헌정 리포트 → 헌정 카드/역사 기록. 원 무관 기록과 헌정 성공을 동시에 볼 수 있게 한다. UI 예시는 “원 커리어는 그대로 남아요”, “헌정전에서 우승했어요”로 구분하고 원본 트로피 목록에 같은 아이콘을 끼워 넣지 않는다.

**제안 예시:** 은퇴 summary `trophies === 0`이고 필요한 상세가 있는 직접 육성 선수에게 “마지막 트로피” 단판 결승을 연다. 성공은 정규 90분 승리다. 원 커리어의 실제 우승 0회와 헌정전의 가상 우승 1회는 다른 단위다. 원래 클럽·라이벌이 기록에 없으면 임의로 만들지 않고 일반 NPC를 쓴다.

## MVP·후속 범위

MVP는 무관 은퇴 한 템플릿, 근거 확인, 주인공 선발 고정, 공통 임대 보조 선수, 단판과 표시 전용 헌정 카드다. 카드라는 말은 새로운 경기 자산이 아니라 원 선수에 연결된 **비거래 전시 레코드**를 뜻한다. 기존 cards 행·peak·등급·강화·시장 가격에 더하지 않는다.

후속은 대표팀 미출전·준우승 등 기록으로 입증 가능한 템플릿이다. cs·준우승·프로/학교 구분이 누락된 옛 기록은 조건을 생성하지 않는다. 서버 summary와 상세가 불일치하면 “기록 확인 필요”로 보류하고 null을 0으로 채우지 않는다. 선수의 실제 선택·성격을 기록에 없는 문장으로 추정하는 생성형 서사는 제외한다.

## 규칙·실패·중단·재시도 경계

- 자격은 원 육성자 본인과 수락된 은퇴 상태다. MVP 시작 시 소유 카드도 필요하게 할지 기록 소유만으로 가능한지 미결정이며, 추천안은 원 육성자 기록 권리+공통 합성 주인공 복제로 카드 판매에 추억이 잠기지 않게 한다. 이 복제는 경기 사용권만 있고 거래·방출·감독 전향이 불가능하다.
- 원 summary·상세의 참조/수락 버전을 시작 때 고정한다. 자격 검증 중 상세가 archive에 있으면 필요한 한 건만 서버에서 읽는다. R2 장애는 자격 없음이 아니라 일시 대기다. 모든 선수 상세를 홈 진입 때 미리 읽지 않는다.
- 주인공은 선발 11자리 중 하나로 고정한다. 후보에만 두고 임대 선수로 승리하면 완료할 수 없다. MVP는 주인공 개인 득점 조건을 요구하지 않아 DF/GK도 참여한다. 부적합 포지션 강제·원래 능력 상승은 없다.
- 무승부·패배는 실패이고 재도전 가능하다. 앱 종료로 이미 확정된 경기를 버릴 수 없다. 명시적 새 시도는 새 seed, 재접속은 같은 결과다. 주인공 원 기록·돈·카드에 손실이 없다.
- 선수 숨김은 공개 헌정도 숨긴다. 공개 철회/삭제 시 공유 링크에서 선수 식별을 노출하지 않는다. 자격 근거 정정이 생기면 새 시작을 막고 기존 헌정은 정정 표시/검토 상태로 남기는 안을 제안한다. 원 기록을 도전 성공에 맞춰 고치지 않는다.

## 모드별 데이터·이벤트 제안

`TributeTemplate(id, version, eligibilityPredicate, npc, winCondition)`, `TributeSource(careerId, acceptedSourceVersion, evidenceDigest, evidenceFacts)`, `TributeAttempt(fullSnapshot, protagonistSlot, result)`, `TributeRecord`를 원 careers와 별도 엔티티로 둔다. digest는 검증 도구이며 근거 원문 전체를 공개 로그에 보관하지 않는다. 원 기록 참조가 삭제되면 개인 귀속 기록 처리와 익명 전시 가능 여부를 개인정보 정책에 맞춘다.

API 개념은 `/v1/tributes/eligibility?careerId=...`, `/attempts`, `/attempts/:id`, `/me`, `/records/:id`이다. 공개 조회와 본인 근거 상세 조회 권한을 분리한다. 이벤트 `tribute_eligibility_checked(reason)`, `tribute_started(templateId)`, `tribute_settled`, `tribute_record_created`를 제안한다. 보상 고유키는 `(raiserProfileId, careerId, templateId, milestoneId)`이고 정정 버전·재판매·재도전·기기 복구로 중복 획득하지 않는다.

## 데이터·서버 경계와 공통 오류 계약 제안

이 절과 아래 엔티티·API·이벤트 이름은 **신규 설계 제안**이다. 현재 존재하는 API처럼 호출하지 않는다. 서버가 정의 버전·참가 자격·전체 경기 입력·시드·성공 판정·표시 보상을 확정한다. 선수 커리어는 로컬 기원이라는 현행 한계가 있어 서버 저장 카드만으로 원 육성의 진위를 완전히 증명할 수 없다. 그래서 MVP는 비거래·비성능 보상이며 의심 신호만으로 자동 제재하지 않는다.

새 경기 생성 요청은 `(profileId, idempotencyKey)` 유일키와 payload hash를 갖는다. 같은 키·같은 입력은 같은 결과를 반환하고 다른 입력은 409다. 시작 시 소유권·거래 상태·정의 버전·편성 revision을 조건부 쓰기와 함께 검증한다. 읽은 뒤 무조건 저장하는 방식으로 거래 경합을 처리하지 않는다. 경기 ID·시드는 서버가 만들고 결과를 먼저 저장하므로 앱 종료·재전송으로 패배를 버리거나 다시 굴리지 못한다. 서버 검증 실패는 시도를 소비하지 않는다. 이미 수락된 시도는 요청이 끊겨도 조회로 복구한다. 원자적 확정에 실패하면 pending 상태와 동일 키 복구로 한 번만 마감하며 결과를 다시 계산하지 않는다.

전체 입력 스냅샷에는 11자리·좌표·실력/roles와 fallback·유형·주발·국적·raised·유스·감독 효과·시너지·모드 보정·상대 입력·규칙/엔진 버전을 포함한다. 기존 `matchDetailOf`의 줄 요약만으로 재현된다고 가정하지 않는다. 입력 hash만 저장해 원본이 사라지는 설계도 피한다. 옛 엔진을 실행할 수 없으면 저장 결과만 보여 주고 새 버전 재계산으로 순위를 섞지 않는다. 경기 중 압박·맨마킹·전술 교체는 현행 기능이 아니므로 MVP 성공 조건으로 쓰지 않는다.

일반 서버 과다 요청 제한, 본인 결과 조회 권한, 동시 편집 revision 검사는 필요하다. 정확한 요청 한도·보관 기간은 부하와 개인정보 검토 후 결정한다. 재시도 제한이 같은 키의 결과 복구를 막아서는 안 된다. 로그·계측에는 선수명·메일·채팅·세이브·팀 스냅샷 원문을 넣지 않고 콘텐츠 ID·버전·익명화된 집계 식별자·상태·오류 코드만 남긴다. 공개 이름은 현행 공개 동의·숨김·삭제 정책을 따른다.

목록은 열 때만 로드하고 웹 `cachedGet`을 사용한다. 공개 정의·집계는 세션 조회 없는 `edgeCached`, 변경 시 `purgeEdge`; 개인 진행은 개인 응답으로 분리한다. 목록마다 선수 상세를 N번 받지 않는다. 새 필터·정렬은 limit과 인덱스를 함께 설계한다. 반복 폴링·클라이언트 전체 이력 스캔을 MVP 전제로 두지 않는다.

## 경제·보상·공정성의 기본 제안

MVP 보상은 완료 기록·비거래 전시물·꾸미기다. 능력치·잠재력·카드 강화·구단 자금·리롤/강화/스카우트권·RP·기존 업적점수는 지급하지 않는다. 확률 보상, 재화 입장료, 유료 재도전, 구독으로 조건 완화·기여 배수는 제안 범위에 없다. 이 원칙을 바꾸려면 경제 영향과 기존 보상 중복을 별도로 승인받는다. 보상은 아래 고유키와 서버 원장으로 한 번만 지급하고 표시 재생은 지급이 아니다. 익명 프로필의 복구 한계를 안내하고 타 프로필 자동 병합을 전제하지 않는다. MVP 서버 기록 쓰기는 로그인 구단주를 제안하되 읽기 공개 범위는 동의 기준을 따른다.

## 저장·서비스 시즌·구버전 호환

새 모드 서버 엔티티와 전용 draft를 사용한다. 기존 `GameState`·저장 RNG·`care`·`boost`·원 은퇴 수치·카드 소유권·공식 팀 선발·컵/리그 고정 명단·friendlyJson을 덮어쓰지 않는다. 후속 구현에서 로컬 저장을 추가하면 선택 필드/별도 namespace와 `packages/game/src/save.ts`의 이전 저장 마이그레이션을 검증한다. 기존 저장을 읽지 못할 때 새 저장으로 교체하지 않는다.

신규 API는 분리하고 구형 앱의 strict 응답 스키마에 새 필드를 억지로 끼우지 않는다. 미지원 앱은 신규 모드 진입만 숨기고 기존 게임은 유지한다. 시즌 경계는 서버 시각과 서버 일정으로 판정한다. 정의 변경은 이미 수락된 입력·목표·보상 버전을 고정하고 진행 중 난도를 조용히 바꾸지 않는다. 긴급 중단은 신규 시작만 먼저 막고 기존 결과 조회·미지급 복구는 열어 둔다. 계정 삭제 시 개인 귀속 기록을 삭제/비식별 처리하는 기존 정책을 따르며 영구 전시는 개인정보 영구 보존을 뜻하지 않는다.
