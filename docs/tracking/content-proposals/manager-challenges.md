## 문제·유저 니즈와 기존 콘텐츠의 차이

가설은 팀 자산의 크기 외에 조건을 읽고 조합을 바꾸는 숙련을 시험하고 싶은 이용자가 있다는 것이다. 보유 격차를 완전히 없앤다고 약속하지 않고 공통 임대 선수단으로 입문 장벽을 줄인다. [감독 커리어](../manager-career-plan-v2.md)는 은퇴 선수의 별도 감독 성장 흐름이다. 이 문서의 “감독”은 퍼즐을 푸는 역할이며 감독 커리어·고용·새 전술 해금 모드를 추가하지 않는다.

#656의 NPC 단판·편성 비교와 겹친다. 차이는 **필수 출전 제한과 서로 다른 성공 조건**, 공통 임대 풀이며 독립 상대 클리어 수를 늘리는 것이 아니다. [카드 과제](../card-exchange-plan.md)의 조건 개념은 참고하되 카드를 제출·소모하지 않고 경기로 푼다. 문서의 옛 주간 과제 초안보다 main의 일일 3개 구현을 현행으로 본다.

## 핵심 루프와 화면 흐름

도전 목록 → 출전 제한/성공 조건/보상 확인 → 공통 임대 또는 혼합 선수단 선택 → 편성 중 조건 검사 → 경기 → 조건별 통과 이유·리포트 → 편성 수정/재도전 또는 다음 퍼즐. 각 조건은 “통과/미달/이 자료로 확인 불가”를 구분한다. 성공했는데 숨겨진 조건 때문에 실패하는 구조를 피한다.

**제안 예시(검증 전):** 선발 자리 실력 평균 상한 75로 승리, DF 그룹 5명 이상으로 무실점, 같은 국적 카드 최대 2명으로 2득점 이상. 빈 자리는 고정 유스를 포함해 평균·포지션 수를 계산한다. 카드 표면 peak와 실제 배치 slotRating은 구분하고 어떤 값으로 제한하는지 시작 전에 보여 준다. 이 문턱은 현행 규칙이 아니다.

## MVP·후속 범위

MVP는 고정 퍼즐 3개 제안, 공통 임대 선수단, 동일 조건 검사기, 일반 서버 단판, 조건별 완료 기록이다. 최소 한 퍼즐은 공통 선수만으로 도전 가능해야 한다. 임대 선수는 합성 경기 입력이며 소유 카드·시장 매물·감독 전향 대상이 아니다. 나머지 퍼즐은 보유/임대 혼합을 허용하되 기록을 구분한다.

출전 조건은 포지션 그룹 수·전체 11자리 평균/최대 slotRating·국적 상한으로 제한한다. 성공 조건은 경기 결과의 승/무/패·득점·실점만 MVP에 둔다. 점유율·유효 슈팅·패스 성공률처럼 현재 정본 결과에 없는 수치를 만들지 않는다. 특정 선수 골 조건은 엔진 이벤트와 참조 유실 검증 뒤 후속으로 둔다. 장면 수동 선택은 표준 비교를 흐려 MVP에서는 자동 경기만 제안한다.

후속은 퍼즐 묶음·선택 조건·직접 만든 편성 공유다. 유저 제작 게시·추천은 별도 기획이며 이 PR의 선행 조건이 아니다.

## 규칙·실패·중단·재시도 경계

- 출전 조건은 경기 시작 직전 서버의 최종 11자리(유스 포함)에서 검사한다. 임대/보유 카드를 중복 배치하거나 빈칸으로 평균 분모를 줄이지 못한다. 국적 누락은 유리한 “다른 국적”으로 세지 않고 해당 퍼즐에 부적격 또는 동일 임대 대체를 제공한다.
- 조건 미달은 경기 생성 전 거절한다. 출전 조건 통과 후 경기 결과가 성공 조건에 미달하면 정상 실패다. “무실점”만 요구한 퍼즐은 0:0도 성공 가능하며 “승리+무실점”은 둘 다 필요하다. AND/OR와 정규 90분 기준을 명시한다.
- 재도전은 새 서버 시드, 결과 조회/중계 재생은 같은 결과다. 퍼즐 비교가 난수 행운 경쟁이 되지 않게 최단 시간·무한 반복 횟수 랭킹은 MVP에서 제외한다. 성공은 숙련의 완전한 증거가 아니다.
- 포기는 해당 attempt 종료다. 목록으로 나가도 수락된 경기는 판정된다. 일시 서버 장애는 같은 키로 복구한다. 정정된 퍼즐은 새 버전으로 열되 이미 딴 완료 표시는 박탈하지 않는 안을 기본으로 한다.
- 임대와 혼합 기록은 별도 범주다. 보유 강화·감독 효과가 섞여 같은 조건의 의미를 바꾸지 않도록 MVP 비교 기록은 임대 모드에서는 감독/추가 효과를 고정한다. 혼합은 적용 효과를 공개하고 동일 전력이라 홍보하지 않는다.

## 모드별 데이터·이벤트 제안

`ManagerPuzzle(id, version, entryPredicate, successPredicate, loanPoolVersion, npcSnapshot, rulesVersion)`, `PuzzleDraft(revision)`, `PuzzleAttempt(mode, fullSnapshot, seed, predicateEvidence, result)`, `PuzzleCompletion`을 제안한다. 조건식은 서버가 허용한 enum와 범위만 받고 임의 JS·SQL·자유 문장 평가를 받지 않는다. 클라이언트 미리보기와 서버 판정은 같은 버전의 순수 검사기를 쓰되 서버가 정본이다.

API는 `/v1/manager-challenges/catalog`, `/me`, `/attempts`, `/attempts/:id` 제안이다. 이벤트 `puzzle_opened`, `puzzle_entry_rejected(conditionId)`, `puzzle_attempt_settled`, `puzzle_completed(mode)`로 조건 이해와 결과를 구분한다. 보상 고유키 `(profileId, puzzleId, milestoneId)`는 임대·혼합 모드 간 공통으로 두어 두 번 보상받지 못하게 한다. 기록은 `(puzzleId, version, mode)`로 분리하고 임대 카드 원본 이름은 수집하지 않는다.

## 데이터·서버 경계와 공통 오류 계약 제안

이 절과 아래 엔티티·API·이벤트 이름은 **신규 설계 제안**이다. 현재 존재하는 API처럼 호출하지 않는다. 서버가 정의 버전·참가 자격·전체 경기 입력·시드·성공 판정·표시 보상을 확정한다. 선수 커리어는 로컬 기원이라는 현행 한계가 있어 서버 저장 카드만으로 원 육성의 진위를 완전히 증명할 수 없다. 그래서 MVP는 비거래·비성능 보상이며 의심 신호만으로 자동 제재하지 않는다.

새 경기 생성 요청은 `(profileId, idempotencyKey)` 유일키와 payload hash를 갖는다. 같은 키·같은 입력은 같은 결과를 반환하고 다른 입력은 409다. 시작 시 소유권·거래 상태·정의 버전·편성 revision을 조건부 쓰기와 함께 검증한다. 읽은 뒤 무조건 저장하는 방식으로 거래 경합을 처리하지 않는다. 경기 ID·시드는 서버가 만들고 결과를 먼저 저장하므로 앱 종료·재전송으로 패배를 버리거나 다시 굴리지 못한다. 서버 검증 실패는 시도를 소비하지 않는다. 이미 수락된 시도는 요청이 끊겨도 조회로 복구한다. 원자적 확정에 실패하면 pending 상태와 동일 키 복구로 한 번만 마감하며 결과를 다시 계산하지 않는다.

전체 입력 스냅샷에는 11자리·좌표·실력/roles와 fallback·유형·주발·국적·raised·유스·감독 효과·시너지·모드 보정·상대 입력·규칙/엔진 버전을 포함한다. 기존 `matchDetailOf`의 줄 요약만으로 재현된다고 가정하지 않는다. 입력 hash만 저장해 원본이 사라지는 설계도 피한다. 옛 엔진을 실행할 수 없으면 저장 결과만 보여 주고 새 버전 재계산으로 순위를 섞지 않는다. 경기 중 압박·맨마킹·전술 교체는 현행 기능이 아니므로 MVP 성공 조건으로 쓰지 않는다.

일반 서버 과다 요청 제한, 본인 결과 조회 권한, 동시 편집 revision 검사는 필요하다. 정확한 요청 한도·보관 기간은 부하와 개인정보 검토 후 결정한다. 재시도 제한이 같은 키의 결과 복구를 막아서는 안 된다. 로그·계측에는 선수명·메일·채팅·세이브·팀 스냅샷 원문을 넣지 않고 콘텐츠 ID·버전·익명화된 집계 식별자·상태·오류 코드만 남긴다. 공개 이름은 현행 공개 동의·숨김·삭제 정책을 따른다.

목록은 열 때만 로드하고 웹 `cachedGet`을 사용한다. 공개 정의·집계는 세션 조회 없는 `edgeCached`, 변경 시 `purgeEdge`; 개인 진행은 개인 응답으로 분리한다. 목록마다 선수 상세를 N번 받지 않는다. 새 필터·정렬은 limit과 인덱스를 함께 설계한다. 반복 폴링·클라이언트 전체 이력 스캔을 MVP 전제로 두지 않는다.

## 경제·보상·공정성의 기본 제안

MVP 보상은 완료 기록·비거래 전시물·꾸미기다. 능력치·잠재력·카드 강화·구단 자금·리롤/강화/스카우트권·RP·기존 업적점수는 지급하지 않는다. 확률 보상, 재화 입장료, 유료 재도전, 구독으로 조건 완화·기여 배수는 제안 범위에 없다. 이 원칙을 바꾸려면 경제 영향과 기존 보상 중복을 별도로 승인받는다. 보상은 아래 고유키와 서버 원장으로 한 번만 지급하고 표시 재생은 지급이 아니다. 익명 프로필의 복구 한계를 안내하고 타 프로필 자동 병합을 전제하지 않는다. MVP 서버 기록 쓰기는 로그인 구단주를 제안하되 읽기 공개 범위는 동의 기준을 따른다.

## 저장·서비스 시즌·구버전 호환

새 모드 서버 엔티티와 전용 draft를 사용한다. 기존 `GameState`·저장 RNG·`care`·`boost`·원 은퇴 수치·카드 소유권·공식 팀 선발·컵/리그 고정 명단·friendlyJson을 덮어쓰지 않는다. 후속 구현에서 로컬 저장을 추가하면 선택 필드/별도 namespace와 `packages/game/src/save.ts`의 이전 저장 마이그레이션을 검증한다. 기존 저장을 읽지 못할 때 새 저장으로 교체하지 않는다.
