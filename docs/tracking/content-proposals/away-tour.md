## 문제·유저 니즈와 기존 콘텐츠의 차이

가설은 최강 선발을 만든 뒤 후보를 실제로 쓸 이유와 한 경기 밖의 판단이 부족할 수 있다는 것이다. 공식 리그의 자동 일정, 컵의 참가·토너먼트, RP 경쟁, 친구와의 한 판과 달리 짧은 원정 안에서 상대와 휴식의 손익을 선택한다. 승률 개선이나 후보 사용 요구가 이미 입증됐다고 말하지 않는다.

#656과 겹치는 부분은 NPC 상대·전용 편성·서버 판정·표시 보상이다. 추가되는 핵심은 **경로 선택과 원정 안에서만 이어지는 자원**이다. 독립 AI 3팀 클리어를 그대로 다시 만들지 않는다. [팀 시너지 기획](../team-synergy-plan.md)은 조합 계산 참고이고 연전 피로 규칙의 근거는 아니다.

## 핵심 루프와 화면 흐름

내 팀 → 원정 목록(예상 경기 수·중단 규칙) → 선발/후보 원정 명단 확정 → 경로 지도 → 상대 특징·위험/휴식 비교 → 경기 전 선발 교체 → 경기 리포트·원정 피로 → 다음 경로 또는 중단 → 완주 기록/전시물. 지도는 좁은 화면에서 세로 경로와 목록 전환을 제공한다. 휴식으로 얻는 것과 포기하는 것을 같은 화면에 표시한다.

**제안값:** 완주 경기는 5~7경기, MVP는 5경기 고정이다. 경기 사이 분기에서 상대 2안 또는 휴식/효과 선택을 제공한다. 후보 규모는 최대 7명 초안이며 골키퍼 대체 수단을 반드시 보장한다. 경로 후보와 보상은 run 생성 때 고정해 새로고침으로 더 좋은 길을 뽑지 못한다. 휴식 노드가 경기 수를 추가로 요구하지 않게 한다.

## MVP·후속 범위

MVP는 한 테마·5경기·분기 경로·경기 사이 교체·피로/컨디션 표시·중도 저장·완주 기념이다. 피로와 컨디션을 별도 수치 두 개로 늘리기 전 한 자원으로 충분한지 비교한다. 임시 효과는 다음 경기 한 번의 줄 힘 보정 또는 피로 회복처럼 설명 가능한 소수 프리셋만 제공한다. 계수·초기치·감소량·최저 보정은 미정이며 난도 검증 없이는 출시하지 않는다.

후속은 6~7경기 변형·여러 테마·서로 다른 휴식 비용이다. 경기 중 교체·부상 영구화·새 성장 수치·선수 커리어 재진행은 제외한다. 현재 `simulateMatch`는 경기 사이 상태를 관리하지 않으므로 run 상태 머신과 입력 보정 어댑터는 신규 개발이다.

## 규칙·실패·중단·재시도 경계

- 원정 명단은 시작 때 현재 소유한 은퇴 카드와 임대 대체 선수로 고정한다. 명단 안에서 경기 사이 선발·후보를 바꾼다. 공식 시즌의 와일드카드 한도를 자동으로 적용하지 않고, 원정은 과거 카드도 허용하는 안을 별도 승인 대상으로 둔다. 미래 시즌·중복 카드는 거절한다.
- 원정 피로/컨디션은 `runId + rosterSlot`에만 존재한다. 로컬 `GameState` 컨디션·care, 카드 peak·시장 가치·공식 팀 줄 힘에 반영하지 않는다. 경기 시작 직전의 보정과 종료 후 자원 변화는 한 단계로 확정한다.
- 승리하면 다음 경기로 진행, 무승부/패배면 원정 종료를 MVP안으로 제안한다. 난도에 따라 무승부 1회 허용안과 비교하되 확정하지 않는다. 승부차기 승리를 슬쩍 정규 승리로 세지 않는다.
- 뒤로가기·앱 종료는 종료가 아니라 보류다. 경기 시작을 수락했다면 결과와 피로는 유지한다. 명시적인 원정 포기는 종료 확인 후 종료하며 신규 run만 새 경로를 받는다. 실패 경기만 다시 굴리는 기능은 없다.
- 카드 판매 이후에도 이미 동결한 run의 사용권은 원정 종료까지 유효한 안을 제안한다. 이는 공식 편성·거래 제한을 풀지 않는다. 다음 run에는 현재 소유를 다시 확인한다. 영구 거래 잠금 대신 이 정책의 복제 대여 악용 가능성을 경제 보상 없는 MVP에서 검토한다.
- 서비스 시즌 마감 시 신규 run을 닫고 진행 run도 expiresAt까지 완료만 허용한다. 보류 run의 만료는 완료 실패와 구분하며 원본 선수에 손실을 주지 않는다. MVP 만료 유예 기간은 미정이다.

## 모드별 데이터·이벤트 제안

`TourDefinition(version, graph, rosterRule, fatigueRule, effects)`, `TourRun(profileId, serviceSeasonId, definitionVersion, engineVersion, status, revision, expiresAt)`, `TourRoster(snapshot, fatigue)`, `TourStep(nodeId, choice, attemptId, before/after)`와 완료 원장이 필요하다. 활성 run은 프로필당 1개 초안이다. 경로 선택과 전 단계 완료 revision을 CAS로 확인해 분기 두 개를 동시에 밟지 못하게 한다. 원정 기록은 공식 `team_matches`와 별도 저장한다.

API 개념은 `/v1/tours/catalog`, `/me`, `/runs`, `/runs/:id/choice`, `/runs/:id/matches`, `/runs/:id/abandon`이다. 이벤트는 `tour_started`, `tour_path_chosen`, `tour_lineup_changed`, `tour_step_settled`, `tour_ended`와 reason(win/loss/abandon/expired/system)이다. 자원 변화와 조건 판정은 서버 정본에서 기록하고 클라이언트 클릭 수를 경기 수로 세지 않는다.

보상 고유키는 `(profileId, tourThemeId, milestoneId)`다. 정의의 오탈자 버전이나 같은 시즌 재완주로 재지급하지 않는다. 후보 기용은 실제 출전한 서로 다른 rosterSlot으로 세며 같은 선수를 후보↔선발만 왕복해 다양성 기여를 만들지 않는다.

## 데이터·서버 경계와 공통 오류 계약 제안

이 절과 아래 엔티티·API·이벤트 이름은 **신규 설계 제안**이다. 현재 존재하는 API처럼 호출하지 않는다. 서버가 정의 버전·참가 자격·전체 경기 입력·시드·성공 판정·표시 보상을 확정한다. 선수 커리어는 로컬 기원이라는 현행 한계가 있어 서버 저장 카드만으로 원 육성의 진위를 완전히 증명할 수 없다. 그래서 MVP는 비거래·비성능 보상이며 의심 신호만으로 자동 제재하지 않는다.

새 경기 생성 요청은 `(profileId, idempotencyKey)` 유일키와 payload hash를 갖는다. 같은 키·같은 입력은 같은 결과를 반환하고 다른 입력은 409다. 시작 시 소유권·거래 상태·정의 버전·편성 revision을 조건부 쓰기와 함께 검증한다. 읽은 뒤 무조건 저장하는 방식으로 거래 경합을 처리하지 않는다. 경기 ID·시드는 서버가 만들고 결과를 먼저 저장하므로 앱 종료·재전송으로 패배를 버리거나 다시 굴리지 못한다. 서버 검증 실패는 시도를 소비하지 않는다. 이미 수락된 시도는 요청이 끊겨도 조회로 복구한다. 원자적 확정에 실패하면 pending 상태와 동일 키 복구로 한 번만 마감하며 결과를 다시 계산하지 않는다.

전체 입력 스냅샷에는 11자리·좌표·실력/roles와 fallback·유형·주발·국적·raised·유스·감독 효과·시너지·모드 보정·상대 입력·규칙/엔진 버전을 포함한다. 기존 `matchDetailOf`의 줄 요약만으로 재현된다고 가정하지 않는다. 입력 hash만 저장해 원본이 사라지는 설계도 피한다. 옛 엔진을 실행할 수 없으면 저장 결과만 보여 주고 새 버전 재계산으로 순위를 섞지 않는다. 경기 중 압박·맨마킹·전술 교체는 현행 기능이 아니므로 MVP 성공 조건으로 쓰지 않는다.

일반 서버 과다 요청 제한, 본인 결과 조회 권한, 동시 편집 revision 검사는 필요하다. 정확한 요청 한도·보관 기간은 부하와 개인정보 검토 후 결정한다. 재시도 제한이 같은 키의 결과 복구를 막아서는 안 된다. 로그·계측에는 선수명·메일·채팅·세이브·팀 스냅샷 원문을 넣지 않고 콘텐츠 ID·버전·익명화된 집계 식별자·상태·오류 코드만 남긴다. 공개 이름은 현행 공개 동의·숨김·삭제 정책을 따른다.

목록은 열 때만 로드하고 웹 `cachedGet`을 사용한다. 공개 정의·집계는 세션 조회 없는 `edgeCached`, 변경 시 `purgeEdge`; 개인 진행은 개인 응답으로 분리한다. 목록마다 선수 상세를 N번 받지 않는다. 새 필터·정렬은 limit과 인덱스를 함께 설계한다. 반복 폴링·클라이언트 전체 이력 스캔을 MVP 전제로 두지 않는다.

## 경제·보상·공정성의 기본 제안

MVP 보상은 완료 기록·비거래 전시물·꾸미기다. 능력치·잠재력·카드 강화·구단 자금·리롤/강화/스카우트권·RP·기존 업적점수는 지급하지 않는다. 확률 보상, 재화 입장료, 유료 재도전, 구독으로 조건 완화·기여 배수는 제안 범위에 없다. 이 원칙을 바꾸려면 경제 영향과 기존 보상 중복을 별도로 승인받는다. 보상은 아래 고유키와 서버 원장으로 한 번만 지급하고 표시 재생은 지급이 아니다. 익명 프로필의 복구 한계를 안내하고 타 프로필 자동 병합을 전제하지 않는다. MVP 서버 기록 쓰기는 로그인 구단주를 제안하되 읽기 공개 범위는 동의 기준을 따른다.

## 저장·서비스 시즌·구버전 호환

새 모드 서버 엔티티와 전용 draft를 사용한다. 기존 `GameState`·저장 RNG·`care`·`boost`·원 은퇴 수치·카드 소유권·공식 팀 선발·컵/리그 고정 명단·friendlyJson을 덮어쓰지 않는다. 후속 구현에서 로컬 저장을 추가하면 선택 필드/별도 namespace와 `packages/game/src/save.ts`의 이전 저장 마이그레이션을 검증한다. 기존 저장을 읽지 못할 때 새 저장으로 교체하지 않는다.

신규 API는 분리하고 구형 앱의 strict 응답 스키마에 새 필드를 억지로 끼우지 않는다. 미지원 앱은 신규 모드 진입만 숨기고 기존 게임은 유지한다. 시즌 경계는 서버 시각과 서버 일정으로 판정한다. 정의 변경은 이미 수락된 입력·목표·보상 버전을 고정하고 진행 중 난도를 조용히 바꾸지 않는다. 긴급 중단은 신규 시작만 먼저 막고 기존 결과 조회·미지급 복구는 열어 둔다. 계정 삭제 시 개인 귀속 기록을 삭제/비식별 처리하는 기존 정책을 따르며 영구 전시는 개인정보 영구 보존을 뜻하지 않는다.
