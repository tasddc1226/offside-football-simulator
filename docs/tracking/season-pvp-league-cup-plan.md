## 1. 목적과 확정 요구

기존 PVP도 실제 유저 구단을 상대한다. 리그컵은 가짜 상대를 실유저로 전환하는 일이 아니라, OVR 근접 단판 도전에 기간 접수와 공통 대진표, 우승 경쟁을 더하는 확장이다. 서비스 시즌에 귀속된 대회의 성적별 차등 보상으로 지속 플레이를 유도하려는 목표이며 효과는 출시 후 검증한다.

## 3. 대회 구성과 일정 제안

대회마다 고정 `cupId`와 `serviceSeasonId`, 접수 시작·마감, 추첨, 경기시각, 규칙 버전을 가진다. 같은 시즌 여러 회차는 서로 다른 ID다. 참가자는 구단/프로필의 안정된 ID로 등록하고 명칭 변경으로 중복 참가를 허용하지 않는다. 최소 모집 인원과 실인원 검증은 다른 문제다.

**미확정 예시:** 64팀, 16개조 × 4팀, 조별 단일 풀리그, 상위 2팀 진출이면 32강을 구성할 수 있다. 조당 6경기 × 16 = 96경기, 토너먼트는 16+8+4+2+1 = 31경기, 전체 127경기다. 조별 3라운드와 토너먼트 5라운드를 하루 1라운드로 열면 결승 진출 팀은 8경기·8경기일이 필요하다. 접수·추첨·휴식·복구일은 별도이며 8일짜리 전체 행사로 확정한 것이 아니다. 3위전은 요구사항에 없고 이 계산에 포함하지 않는다.

64팀 미달 시 모집 연장은 제안일 뿐 답변 대기다. 취소·다른 규모·추가 접수의 선택과 최대 연장 횟수, 이미 신청한 유저의 철회 권리를 함께 정해야 한다. 부족한 참가자를 AI 구단으로 채우는 안은 확정 요구와 맞지 않아 기본안으로 두지 않는다. 모집 정원 초과 시 선착순/대기열/추첨 선택, 최소 인원·조별 일정 생성 가능성, 탈퇴로 생긴 부전승 정책도 결정한다. 조별 결과로 32팀을 선발할 수 없는 규모는 승인된 대체 포맷 없이는 개시하지 않는 안을 제안한다.

실제 일시·표시 시간대는 미정이다. 서버는 UTC로 저장하고 화면에 시간대와 절대시각·T-60 마감을 함께 표시하는 안이다. 접속하지 않아도 서버가 자동 진행하고, 앱을 켜야 경기하는 구조로 만들지 않는다.

## 5. 명단 변경과 선수 잠금: 승인할 선택지

R2와 R5를 동시에 만족시키려면 잠금 범위를 먼저 정한다.

- **안 A: 최초 엔트리 대회 전체 잠금.** 최초 참가 선수를 명단에서 빼도 대회가 끝나거나 해당 팀이 탈락하기 전에는 팔거나 방출하지 못한다. 이후 투입 선수의 추가 잠금 범위·최대 엔트리와 해제 시점을 정해야 한다. 선수 이동 제약이 크다.
- **안 B: 현재 선발을 따라가는 잠금(대화에서 제안, 미확정).** 신청 시 현재 선발 잠금 → T-60까지 판매 중이 아닌 보유 선수로 교체 → 들어온 선수 잠금과 빠진 선수 잠금 해제, 명단 저장을 원자적으로 처리 → T-60부터 결과 확정까지 동결 → 경기 후 다음 경기 명단 수정 → 탈락/종료 시 해제. 최초 참가 선수가 대회 내내 잠기는 안과 다르다.

일반 팀을 복사한 **대회 전용 명단**을 권한다. 일반 팀 변경이 컵 명단을 자동 변경하지 않고, 카드 판매·방출 제약은 명단 화면에 관계없이 카드 소유에 적용한다. 공유 명단을 택하면 일반 PVP 수정도 컵 마감에 막히는 부작용을 별도로 승인받는다. 교체 대상의 시즌·지난 시즌 한도·배치·중복 카드·판매 상태를 저장 시 다시 검사한다. 참가 후 신규 영입 사용 여부와 초기 엔트리 고정 여부는 미정이다.

중복 대회는 초기에는 동일 구단 동시 참가 제한안을 권한다. 허용 시 잠금은 대회별 참조를 유지하여 한 대회 탈락으로 다른 대회의 잠금을 풀지 않는다. 명단 교체/신청과 시장 등록·구매·방출이 경합하면 서버에서 소유·판매 상태·잠금 조건을 같은 원자적 경계로 검사하고 하나만 성공시킨다. 화면의 사전 확인만으로 보호하지 않는다. 실패 시 새 선수 잠금만 남거나 기존 선수가 먼저 풀리는 중간 상태를 남기지 않는다.

계정 삭제는 개인정보 삭제와 대회 기록 익명 보존을 구분한다. 제재·철회는 접수 중과 추첨 후 정책을 나누며, 기권 패배·보상 제외·잠금 해제 시각·상대 진출·이의제기 경로를 결정한다. 철회/삭제로 잠긴 카드가 판매 가능해진 뒤 이미 동결한 경기에 출전하는 모순을 막아야 한다. 삭제 이후 푸시는 중지하며 개인정보 보존 근거 없이 원문 이름을 남기지 않는다.

## 6. 상태 전이·마감·복구 제안

대회: 준비 → 접수 중 → 접수 마감 → 추첨 확정 → 조별 진행 → 진출 확정 → 32강 → 16강 → 8강 → 4강 → 결승 → 성적 확정 → 보상 정산 → 종료. 연장·취소·운영 보류는 이유·시각·규칙 버전을 기록하는 별도 분기다. 기존 상태를 덮어써 처리 이력을 없애지 않는다.

참가: 신청 검증 → 참가 확정/잠금 → 경기 준비 → 명단 동결 → 경기 처리 → 결과 확정 → 다음 경기 준비 또는 탈락 → 보상 지급 대기 → 정산 완료. 탈락 시 잠금 해제는 보상 지급 실패와 분리하는 안이다.

| 경계           | 제안하는 서버 판정 및 복구                                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 접수 마감      | 서버 확정 시각 기준 `now < closesAt`만 허용. 동시 마지막 자리 신청은 원자적으로 정원 검사. 결제 없는 접수 실패는 자금 변동 없음                                      |
| T-60           | `now < scheduledAt - 60분`만 명단 쓰기 허용, 정확히 T-60부터 차단하는 안. 사용자 기기 시간·화면 카운트다운·요청 전송 시각은 판정 기준 아님                           |
| 동결 지연      | T-60 이전 최종 승인 명단 버전을 보존하여 작업이 늦어도 그 명단으로 동결. 늦은 작업이 그때의 일반 팀을 읽지 않음                                                      |
| 처리 재시도    | 대회/경기 고정 ID, 참가팀·명단 버전·능력치·배치·시너지·엔진/규칙 버전·비공개 시드 스냅샷으로 같은 결과 재현. ID에서 공개적으로 추측 가능한 시드만 쓰지 않는 안       |
| 작업 중단      | lease/재개 지점·중복 실행 방지, 미완료 경기만 재처리. 득점·승점·진출을 한 번만 확정. 선행 라운드 확정 전 다음 경기 생성/진행 차단                                    |
| 일정 지연      | 원래 마감 뒤 편성 재개 없이 결과 처리하는 안. 일정 이동과 편성 재개가 필요하면 양 팀에 동일 시간 보장·새 마감·변경 이력 공지. 실제 경기 시작 기준 R5 해석을 승인받음 |
| 결과/보상/푸시 | 결과 확정 후 보상과 알림 전달을 각각 재시도. 푸시 성공이 경기 완료나 보상 지급 조건이 아님                                                                           |

지연 감지·운영 보류 임계치와 담당자 복구 절차는 출시 전에 수치로 정한다. 결과 확정 전 실수는 재시도, 확정 후 정정은 감사 기록과 보상 조정 기록으로 남긴다. 승자가 바뀌는 정정이 다음 라운드에 미치는 영향·재경기 조건은 미정이다. 영구 경기/보상 중복 키는 TTL이 있는 일반 요청 멱등 캐시에만 의존하지 않는다.

## 7. 공정성과 시즌 경계

컵은 홈·원정 표시 때문에 승률이 달라지지 않는 **중립 경기**를 권한다. 현행 1.08 홈 우대를 그대로 사용하는 것이 확정 정책은 아니다. 추첨은 참가 명단을 마감 뒤 고정하고 비공개 시드·알고리즘 버전·감사 기록을 보존한다. OVR 포트/무작위 추첨·같은 상대 재매칭 회피와 공개 검증 범위는 결정 필요다. 추첨 결과 미리보기나 오류 재시도로 유리한 조를 다시 뽑지 못하게 한다.

조별 승점(예: 승 3/무 1/패 0), 동률 기준(득실·다득점·상대전적·추가 경기·추첨 중 순서), 토너먼트 무승부(연장·승부차기 등)는 모두 **제안/미결정**이다. 엔진이 제공하지 않는 승부차기를 이미 구현된 기능으로 쓰지 않는다. 32강 진출과 조 간 순위 비교 기준, 부전승·몰수 경기의 득점/승점·보상 처리까지 규칙 공표 후 접수를 연다. 일반 PVP 레이팅에 컵 결과를 반영할지도 별도로 결정한다.

실유저 신청은 한 프로필 중복 차단으로 시작할 수 있으나 한 사람이 여러 계정을 쓰는 문제까지 해결했다고 주장하지 않는다. 실인원 검증·중복계정 탐지·카드 소유 검사는 각각 다른 층위다. 서버에 카드가 있다는 것만으로 커리어 진위가 증명되는지 현행 업로드 검증을 별도 감사하고, 신고·제재·오탐 구제 기준을 정한다. 개인정보를 과도하게 수집하는 실명 인증을 기본 확정안으로 두지 않는다.

대회는 신청 당시 서비스 시즌에 고정하고 다음 시즌으로 자동 이동하지 않는 안이다. 시즌 1 종료가 미정이므로 구체적 컵 종료일을 추정하지 않는다. 시즌 종료일이 확정되면 접수+추첨+최대 라운드+복구 여유가 경계 안에 드는지 검사한다. 진행 중 시즌 종료 시 원래 시즌 규칙/스냅샷으로 완료할지 취소할지, 차기 시즌 자금·카드 자격으로 보상을 넘길지 승인받는다. 종료 시즌 일반 팀 편성 불가와 컵 전용 명단의 충돌도 함께 해결한다.

## 8. 보상 경제와 전달 제안

**확정:** 성적별 차등 보상. **미확정:** 보상 종류·금액·재화·지급 시점·참가 보상·기권/제재 보상. 우승·준우승·4강·8강·16강·32강·조별 탈락의 구간별 차등은 검토안이다. 같은 성적의 보상 차이가 생기면 기준을 사전에 공개한다.

트로피·칭호·배지와 소액 구단 자금을 제안한다. 우승자의 전력을 직접 강화하는 희귀 카드·능력치 보상은 강팀 독주를 누적시킬 위험이 있다. 큰 신규 재화 발행은 시장 가격·방출 자금과 합쳐 인플레이션을 키울 수 있다. 기존 시장 기획의 표본은 당시 자료이고 지금의 실제 경제 자료를 대신하지 않는다. 현재 잔액 분포·거래량·카드 가격·자금 발행/소각·참가 규모·반복 우승 집중도를 조사하기 전에는 금액을 확정하지 않는다. 회차/시즌 발행 예산과 인당·성적별 지급표를 먼저 승인받는다.

보상은 `(cupId, 참가 ID, 보상 항목/정책 버전)`에 영구 유일성이 있는 원장을 권한다. 잔액 반영·지급 기록을 원자적으로 묶고 재시도·재접속·중복 작업에도 한 번 지급한다. 보상 정책 버전은 접수 전 고정하며 버전 변경으로 같은 보상을 다시 주지 못하게 원래 수급 권리를 식별한다. 정정은 원지급 참조를 가진 별도 조정 기록으로 남긴다. 수령 버튼 필요 여부와 미수령 만료·탈퇴·제재·시즌 경계 처리도 결정한다.

결과 원본은 앱 푸시 권한 거부·토큰 없음·실패와 무관하게 앱/웹 경기 기록에 남긴다. 기존 알림함을 재사용해 모든 참가자에게 원본을 남기려면 현재 푸시 수신자 중심 원본 생성 정책과 달라지는 점을 검토한다. 경기+대상 참가자 기준 중복 키로 결과 알림을 만들고 동의·유효 기기·제재/삭제 상태를 전달 전에 다시 확인한다. 결과 확정 후 발송을 시도하되 실제 수신 보장을 약속하지 않는다. 기존 시간대·하루 개인 알림 한도와 충돌하는 컵 이벤트의 우선순위·묶음·TTL·지연 전달은 미정이며 무제한 재시도하지 않는다.

## 9. 계측과 인수 조건 제안

효과 지표는 개선된 성과가 아니라 검증 가설이다. 같은 시즌·유사 활동량의 비교군과 회차별 분모를 정해 해석한다.

- 참여율: 자격 있는 구단 중 상세 열람/신청/참가 확정 비율, 실패 사유와 모집 미달.
- 완주: 참가 확정팀 중 자발적 철회·제재·계정 삭제 없이 정상 종료한 비율. 탈락은 정상 완주로 취급하고 결승 진출과 구분한다.
- 다음 회차 재참가: 이전 참가자 중 다음 회차 자격자·노출자·확정 참가자, D1/D7 재방문, 커리어 진행/은퇴 등 지속 플레이.
- 신뢰성: 마감 후 명단 수정 0건, 중복 결과/중복 보상 0건, 잠금 누락·잔존, 경기 지연 분포·복구 시간, 원본 조회와 푸시 발송/영수증 실패 비율.
- 경제/공정성: 총 발행, 성적별 수급·반복 우승 집중, 시장 가격/거래량 변화, OVR별 진출 분포, 중복계정 신고·오탐.

이벤트 후보: `cup_view`, `cup_apply_result`, `cup_lineup_saved`, `cup_match_finalized`, `cup_result_viewed`, `cup_reward_posted`, `cup_reentry`. 신청·경기·보상은 서버 확정 이벤트로 중복 제거하고 정책·시즌·대회·단계·실패 코드만 필요한 범위에서 기록한다. 선수명·토큰·민감 계정 정보는 로그에 남기지 않고 측정 동의·보존 기간을 기존 [GA4 기획](ga4-measurement-plan.md)과 조정한다.

구현 승인 뒤 아래 시나리오를 인수 검사로 사용한다.

1. R1 자격 충족/부족, 실제11카드/유스 결정값, 지난 시즌 한도, 판매 중 카드와 정원 마지막 자리의 동시 신청을 검사한다.
2. 잠금 정책 A/B 승인값대로 판매·방출·구매·명단 교체 경합에서 한 작업만 성공하며 실패한 교체가 기존 명단을 보존한다. 다른 대회 잠금은 남는다.
3. 서버 T-60 직전/정각/직후, 느린 요청·다중 기기·기기 시계 조작에서 같은 판정을 한다. 지연 동결도 승인 명단을 쓴다.
4. 조 추첨 재시도, 조 동률, 무승부 토너먼트, 기권/제재/삭제에서 확정한 정책대로 32강 이후 단일 우승자에 도달한다.
5. 앱을 켜지 않은 양 팀도 경기가 진행되고 작업 중단·중복 실행·엔진 업데이트에도 저장 스냅샷과 결과가 보존된다.
6. 결과 저장/진출 갱신/보상 지급 각 경계에서 실패를 주입하여 한 번만 확정·지급하고 재시도 이력을 볼 수 있다. 푸시 거부·전송 실패에도 결과와 보상은 조회된다.
7. 탈락·종료·취소·철회·시즌 경계에서 승인된 해제 시점대로 잠금이 풀리고 보상 실패로 잠금이 계속되지 않는다.
8. 화면의 빈 상태·마감·처리 중·오류·재시도, 모바일 가독성·접근성·ko/en 안내, 경제 발행 상한과 운영 중지/복구를 확인한다.
