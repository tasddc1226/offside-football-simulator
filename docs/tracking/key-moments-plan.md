# 결정적 순간 선택지 기획 (초안)

2026-10-18 초안. 작업 ID는 구현 PR을 낼 때 정한다.

> 팀 경기 문자중계 도중 우리 팀의 결정적 찬스나 위기 때 최대 3가지 선택지를 주고, 유저가 직접 결과를 만들어 내는 느낌을 주고 싶다.
> 선수 커리어도 중요한 대회·무대에서 포지션·상황별 확률 선택지를 더한다. 같은 선택지를 팀 레이팅 경기에서도 내 선수 이름을 보여 주며
> "이런 상황인데 어떻게 할래?"로 묻고, 고른 대로 경기 결과에 반영한다. 지금 미니게임도 너무 단순해서 함께 고도화한다.

## 한 줄 요약

포지션·상황별 **상황 카드**(장면 + 선택지 최대 3개 + 선택지마다 성공 확률)를 하나의 라이브러리로 만들어 선수 커리어 큰 경기와
구단주 팀 경기 문자중계에서 같이 쓴다. 팀 경기는 서버가 확률을 굴려 판정하고, 선수 커리어는 일부 선택지를 고도화한 미니게임으로 판정한다.

## 지금 상태

- **선수 커리어:** 랜덤 이벤트 선택지와 미니게임(`minigame.ts` 타이밍 게이지, `dragShot.ts` 드래그 슛)이 있지만 실제 경기와 이어지지 않는다.
  컵·대륙 대회 결승 승패는 `comps.ts` `tie()`의 `chance(0.5 + edge)` 한 번으로 정해진다. 미니게임은 "게이지를 한 번 탭" 하나라 상황이
  달라도 손이 하는 일이 같다.
- **팀 경기:** `POST /v1/owner-team/matches` 한 번에 서버(`apps/api/src/team/sim.ts`)가 두 팀 기대 득점을 정하고 골 수를 포아송으로 뽑는다.
  `TeamLive`는 정해진 골을 보여 주기만 한다. 서버는 선발마다 자리·레이팅·커리어 유형(poacher·maker 등)·주발을 알고, 선수 이름은 모른다
  (공개 이름만). 내 선수 이름은 지금도 웹·앱이 커리어 id로 기기 안 이름을 붙인다(`scorerId`).

## 원칙

- **선택이 실제 스코어를 만든다.** 장면 결과(골·무산·실점·선방)가 그대로 스코어와 레이팅에 들어간다. 결과와 따로 노는 장면은 없다.
- **정답이 하나인 선택지는 만들지 않는다.** 선택지마다 확률과 보상이 다르다(안전하게 / 과감하게 / 동료 활용). 어느 쪽이 나은지는 그 선수의
  자리·레이팅·유형과 상황(점수·시간)에 따라 달라진다. 확률은 화면에 숫자로 보여 준다.
- **평균은 지금과 같다.** 장면이 맡는 기대 득점을 기존 기대 득점에서 떼어 온다. 아무것도 안 고르면(자동 선택) 지금과 같은 분포가 된다.
  잘 고르면 조금 더 이기는 정도로 묶는다.
- **레이팅 경기는 서버가 굴린다.** 팀 경기는 클라이언트가 고른 **선택지 번호만** 받고, 확률 판정은 서버 시드로 한다. 손 기술(미니게임)
  결과는 레이팅 경기에 넣지 않는다(공개 API라 조작할 수 있다). 미니게임은 서버가 없는 선수 커리어에서 쓴다.
- **포기해도 이득이 없다.** 경기 횟수와 결과는 시작할 때 확정되고, 중간에 나가면 남은 장면은 자동 선택으로 마감한다.

## 1. 상황 카드 라이브러리 (공용)

`@offside/contracts/moments`(zod 없는 서브패스, `balance`와 같은 방식)에 둔다. API와 `packages/game` 둘 다 import한다.

```
Situation {
  id                       // 'cb-through-ball', 'st-1v1', 'gk-pk' …
  kind: 'chance' | 'crisis'
  slots: DetailPos[]       // 이 장면의 주인공이 될 수 있는 자리
  when?: { minute?, score? }  // 막판 동점, 지고 있을 때 등
  choices: [               // 1~3개
    { id, p(rating, fit, type, foot, ctx) → 0..1,
      ok: Outcome, fail: Outcome,     // goal | miss | assist-goal | conceded | saved | card …
      mg?: MgKind }                   // 선수 커리어에서만 미니게임으로 판정
  ]
}
```

문구는 `app-core` 사전(ko·en·ja)에 `{name}`(내 선수)·`{mate}`(동료) 자리를 둔다. 서버가 만드는 문장은 없고 장면 id·선택 id·결과만
주고받는다.

### 장면 고르는 규칙

- **주인공:** 찬스는 자리별 득점·도움 가중치(`SCORE_W`·`ASSIST_W`)로, 위기는 수비 자리 가중치로 내 선발에서 뽑는다. 한 경기에 같은 선수가
  두 번 주인공이 되지 않게 한다(11명 골고루 이름이 불리게).
- **이어지는 장면:** 일부 결과는 다음 장면을 부른다(`st-offside-line` 성공 → `st-1v1`, `cb-1v1` 박스 안 파울 → 상대 `sp-pk` = 내 `gk-pk`).
  이어지는 장면도 경기당 최대 3개에 포함된다.
- **조건 장면:** 경기 흐름 장면은 점수·시간 조건이 맞을 때만, 큰 무대 장면은 결승 · 녹아웃에서만 나온다.
- **겹침 방지:** 같은 경기에서 같은 장면 id는 한 번만, 최근 5경기에서 본 장면은 가중치를 낮춘다(웹·앱이 최근 장면 id를 보내지 않고 서버가
  최근 경기 `detail_json`에서 센다).
- **확률:** 선수 레이팅(상대 줄 힘과 비교), 자리 적합도, 유형 일치(+), 주발과 측면 방향(+/−), 경기 흐름(지친 후반 −).
  과감한 선택지는 확률이 낮고 보상이 크다. 실패 결과도 선택지마다 다르다(오프사이드 트랩 실패 = 바로 1대1 허용, 파울로 끊기 = 성공해도 경고).
- **카드 · 퇴장:** 경고 두 번이나 `cb-last-man` 퇴장은 그 경기 남은 상대 장면 확률을 올린다. 다음 경기 출전 정지는 1차에선 하지 않는다.
- **문구:** 장면 문구는 장면 id마다 2~3벌(ko·en·ja)을 두고 시드로 고른다. 결과 문구는 장면으로 끝낸다(copy-style).

## 2. 팀 레이팅 경기

### 경기 흐름

1. **시작** `POST /v1/owner-team/matches { opponentTeamId, interactive: true }`
   - 서버가 지금처럼 두 팀 기대 득점을 계산한 뒤, 그중 **장면 몫(초안 35%)** 을 떼어 장면 슬롯으로 만든다. 나머지 65%로 지금처럼 일반 골을 뽑는다.
   - 장면 슬롯은 최대 3개(내 찬스·내 위기 섞어서), 분·주인공(자리 가중치로 내 선발에서 뽑음)·상황·선택지별 확률을 시드로 정한다.
   - 응답: 일반 골 이벤트 + 장면 목록(결과 없음) + 경기 상태 `pending`. 하루 경기 횟수는 여기서 센다.
2. **문자중계** `TeamLive`가 장면 분에 시계를 멈추고 카드를 띄운다. "62' 김OO(ST)가 수비 뒷공간을 파고들었어요. 키퍼와 1대1!" + 선택지 3개와 확률.
   제한 시간(초안 15초) 안에 안 고르면 자동 선택(확률 × 보상이 가장 큰 쪽이 아니라 "감독에게 맡기기" = 지금과 같은 기대값)으로 넘어간다.
3. **선택** `POST /v1/owner-team/matches/:id/moments/:i { choice }` → 서버가 `seed + i + choice`로 굴려 결과(골·무산·실점·선방)를 돌려준다.
   마지막 장면을 판정하면 서버가 경기를 마감하고 레이팅·전적·통계를 반영해 지금과 같은 경기 결과를 돌려준다.
4. **결과 바로 보기 · 이탈** 남은 장면을 자동 선택으로 한 번에 마감한다(`.../moments/auto`). 앱을 끄고 나가면 다음 경기 시작 · 경기 기록
   조회 · 일정 시간(초안 10분) 중 먼저 오는 때에 서버가 자동 마감한다(cron 없이, 다음 요청에서 지연 처리).

요청 수: 경기당 1회 → 최대 4회. 하루 약 3,400판 기준 최대 약 1만 회 늘어난다. 장면 판정은 경기 한 행만 갱신하고 공개 엣지 캐시는 마감할 때만 비운다.

### 상대 쪽

비동기 대전이라 상대 구단주는 고르지 않는다. 상대의 찬스는 **내 위기 장면**(내 수비수·키퍼가 주인공)으로 나오고, 내 찬스에서 상대 수비는
자동이다. 상대 선수 이름은 공개 이름(없으면 익명 표기)으로 보인다.

### 호환·저장

- `interactive`가 없는 요청(옛 앱)은 서버가 장면을 바로 자동 선택으로 마감해 지금처럼 한 번에 결과를 준다. 기대값은 같다.
- `team_matches`에 상태·장면 열을 더하는 마이그레이션 1개(`status`, `moments_json`). 경기 기록 `detail_json`에 장면·선택·결과를 남겨 경기
  기록·경기 리포트(T-11-379)에 "62' 김OO 칩슛 선택 → 골"로 다시 보인다.
- 친선전도 같은 흐름. 오프사이드 컵(서버 일정 경기)은 자동 선택.
- **배포 즉시 레이팅 경기에 켠다(2026-10-18 결정).** 자동 선택의 기대 득점이 지금과 같게 맞추므로, 장면을 고르지 않는 유저와 옛 앱은 지금과 같은 분포로 경기한다. 이미 치른 경기 기록은 바뀌지 않는다.

### 밸런스 (API 쪽 시뮬레이션)

- 지금 `simulateMatch`와 장면 버전을 같은 선발 표본으로 수만 판 돌려, 자동 선택일 때 득점·승률 분포가 같은지 확인하는 테스트를 둔다.
- 사람 대신 "늘 기대값 최대 선택"과 "무작위 선택"을 돌려 승률 차이를 본다. 목표: 같은 전력끼리 최선 선택이 자동 선택보다 승률 +5~8%p 안쪽.
- 장면 몫(35%)·장면 수(3)·자동 선택 제한 시간은 서버 밸런스 설정 키로 연다.

## 3. 선수 커리어 큰 무대

- **어디서:** 국내 컵·대륙 대회 4강 이후, 국가대표 대회 녹아웃, 리그 마지막 구간 우승·강등 경쟁 중일 때(순위 차가 작을 때). 내가 뛴 경기만.
  한 경기에 장면 1~3개, 시즌에 많아야 5번 안팎.
- **무엇을:** 팀 경기와 같은 상황 카드. 주인공은 늘 나다(동료 선택지는 "동료에게 내준다"로).
- **판정:** 확률 선택지는 난수, `mg`가 달린 선택지(슛·칩슛·선방·태클·프리킥)는 고도화한 미니게임으로 판정한다. 확률이 게이지 구간 넓이·
  키퍼 반응 범위가 되는 지금 방식(`roll < p`)을 이어 쓴다.
- **결과 반영:** 장면 골·실점이 그 경기 결과(`tie()` edge, 리그 구간이면 그 경기 결과)와 내 골·평점에 들어간다.
- **구조:** 대회 진행을 장면에서 멈췄다 이어 가는 형태(`s.pendingMoment`). 장면이 뜬 시점에 저장해 결과 보고 다시 하기를 막는다.
  시뮬레이터·골든은 탭 없이 난수로 판정한다. 구조 변경(결과 동일) 커밋과 결과 변경 커밋을 나눈다.

## 4. 미니게임 고도화

지금은 장면이 달라도 "왕복 바늘 한 번 탭"이다. 선택지마다 손이 하는 일이 다르게 바꾼다.

| 선택지                 | 지금            | 고도화                                                                                     |
| ---------------------- | --------------- | ------------------------------------------------------------------------------------------ |
| 낮게 강하게 · 페널티킥 | 게이지 / 드래그 | 조준(골문 9칸 중 하나) + 세기 게이지. 키퍼가 미리 기울어지는 신호를 보고 반대로 찰 수 있다 |
| 칩슛                   | 좁은 게이지     | 키퍼가 나오는 순간을 기다렸다 띄우기(너무 빠르면 잡히고 늦으면 막힌다)                     |
| 키퍼 제치기 · 돌파     | 게이지          | 좌우 스와이프 2번(수비 무게중심 반대로)                                                    |
| 프리킥(새)             | 없음            | 드래그 곡선으로 감아 차기, 벽 높이·거리가 상황마다 다르다                                  |
| 태클(새)               | 없음            | 공이 상대 발에서 떨어지는 순간 탭. 너무 빠르면 파울(위험 지역이면 페널티킥)                |
| 선방                   | 게이지          | 키커 도움닫기 신호를 읽고 방향 스와이프 + 타이밍                                           |

- 능력치는 지금처럼 판정 폭(구간 넓이·흩어짐·키퍼 범위)으로 들어간다. 능력치가 좋을수록 쉽고, 결과는 손으로 정한다.
- 접근성: 감속 모션 설정이면 시간 제한을 늘린다. "확률로 판정" 버튼으로 미니게임을 건너뛸 수 있다(기본 확률 그대로).
- 웹·앱 같이. 앱은 SVG 필터 대신 지금 장면 그리기 방식을 쓴다(앱 선수 그림 디버깅 교훈).

## 순서 (추천)

1. **상황 카드 라이브러리 + 팀 레이팅 경기 장면(API·웹·앱)** — 사용자가 매일 하는 화면이라 체감이 가장 크다. 레이팅 경기·친선전에 바로 켠다.
2. **선수 커리어 큰 무대 장면** — 같은 라이브러리를 쓰고 판정은 우선 확률 선택만.
3. **미니게임 고도화** — 슛(조준 + 세기)·선방부터, 다음에 태클·프리킥·칩슛.

## 정할 것 (추천을 기본값으로 둠)

1. 선택지 확률을 숫자(%)로 보여 준다. → 추천: 보여 준다(판단의 근거).
2. 장면 수·몫: 경기당 최대 3개, 기대 득점의 35%. → 시뮬레이션 뒤 확정.
3. 레이팅 경기 적용 시점: 배포 즉시(정함, 10-18).
4. 자동 선택 제한 시간 15초, 미완료 경기 자동 마감 10분.

## 테스트

- contracts: 장면 확률 범위(0.05~0.95), 자동 선택 기대값 = 기존 기대 득점(표본 테스트).
- api: `interactive` 없는 요청은 한 번에 마감, 장면 판정 재요청은 같은 결과(멱등), 남의 경기·이미 마감한 장면 거절, 이탈 경기 지연 마감,
  하루 횟수는 시작 때 차감, 시즌 1 경기 결과 불변.
- game: 장면 대기 세이브 왕복, 같은 시드 한·영 결과 동일, 내가 안 뛴 경기엔 장면 없음.
- e2e: 문자중계 중 장면 선택 → 요청 1회씩, 결과 바로 보기 → 자동 마감 1회.

## 배포 뒤 볼 지표

- 장면 선택률(제한 시간 안에 직접 고른 비율), 선택지별 선택 비율과 실제 성공률
- 경기당 체류 시간, 하루 경기 수 변화(느려져서 덜 하는지)
- 결과 바로 보기 비율, 이탈 후 자동 마감 비율
- 최선 선택 비율과 레이팅 상승의 관계(실력이 보상받는지)
