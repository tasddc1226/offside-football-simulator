# T-11-839 은퇴 선수 카드 체격 변경권

11월 21·22·26일 건의 세 건은 육성을 마친 카드의 키와 몸무게를 원하는 선수에 맞추고 싶다는 요청이에요. **현재 보유한 은퇴 카드의 표시용 키·몸무게를 한 번에 고치는 1회권**을 제공해요. 등록한 체격은 거래 뒤에도 카드와 함께 가요. 경기·교환 판정에서 쓰는 주발은 편집 대상에서 제외해요.

### 체격 입력안

아래 수치는 기획 범위예요. 실제 선수 분포의 통계 추정치는 아니에요. 기존 생성기의 공통 한도(160–200cm, 55–100kg, BMI 18.5–30) 안에서 포지션별 기본값을 포함해요. 키를 입력하면 몸무게 범위는 포지션 범위와 BMI로 가능한 정수 구간의 교집합을 표시해요. 기존 체격이 새 범위 밖이면 원래 값 그대로 열고 저장을 누르기 전까지 자동 교정하거나 차감하지 않아요. [공통 규칙](../../packages/contracts/src/body.ts)

| MF | 160–198 | 55–96 | 177 / 71 |

## 구현과 운영 확인

- `card_physique_edits`는 카드 ID·리비전을 복합 기본 키로 삼아요. 편집 한 번마다 키·몸무게·구단주·시각을 기록하고 가장 최근 행으로 현재 카드 체격을 표시해요. 기존 테이블의 인덱스 생성이나 백필은 없어요.
- `owner_items`의 `physique`는 구매 지급에서 환불 회수를 뺀 누계이고, `physique_used`는 사용 누계예요. 두 값의 차이가 음수면 다음 지급에서 자동 상계하고 화면에는 0장을 보여 줘요. 실제 결제별 검증·취소 여부는 기존 `iap_purchases`에서 조회해요.
- 편집 API는 `GET/POST /v1/cards/:careerId/physique`이고 요청 필드는 `height, weight, expectedRevision`이에요. 사용은 웹·앱의 구단주 → 보유 선수 관리에서 가능해요. 키·몸무게만 저장하며 현역·은퇴 세이브 버전은 바뀌지 않아요.
- 구버전 클라이언트의 엄격한 응답 스키마를 위해 지원 클라이언트만 아이템·웹 카탈로그 조회에 `physique=1`을 붙여요. 스위치를 켜도 기존 클라이언트에는 새 수량·상품을 보내지 않아요.

## 저장·표시·거래 일관성

- 카드 ID로 최근 리비전을 조회해 라커룸·시장·구단 프로필에서 편집한 값을 보여 줘요. 편집 기록이 없으면 원래 키·몸무게를 사용해요. 원래 선수를 키운 구단주가 탈퇴했어도 카드에 저장된 포지션과 현재 소유권으로 편집할 수 있어요.
- 원본 커리어와 명예의 전당은 은퇴 당시 체격·주발을 유지해요. 경기 결과, 포지션별 실력, 최고 OVR, 카드 기준가·강화 단계·구단 자금은 서버 통합 테스트에서 편집 전후로 비교해요.
- 실제 저장 쿼리가 현재 주인·포지션·감독 여부·방출/소모·열린 매물·보유권·기대 리비전을 검사해요. 편집 이력과 사용 수량을 한 D1 배치로 반영해요. 바뀐 값이 없으면 차감하지 않아요.

## API와 화면 흐름

1. 보유 선수 관리에서 카드를 골라 현재 표시 체격과 변경권 수량을 확인해요. 화면을 열 때만 카드 상태를 조회하고, 키에 맞는 몸무게 범위를 표시해요.
2. 사용 가능한 변경권이 없으면 앱은 해당 스토어의 현지 가격, 웹은 엑솔라 구매 묶음을 보여 줘요. 웹 결제에서 돌아오면 이전 카드 리비전이 유효할 때 입력값을 복원해요.
3. 변경권 1장으로 적용을 눌러야 저장해요. 구매 완료만으로 편집하거나 자동 차감하지 않아요. 열린 매물이 있으면 먼저 판매를 내려야 해요. 다른 기기에서 먼저 편집했거나 주인이 바뀌면 서버가 거절해요.

## 스토어와 운영

- 추천 단권 SKU는 `com.offsidelab.app.physique_1`이에요. App Store Connect에서 소모성 IAP로 생성하고 ID, 현지화 이름·설명, 가격·판매 지역, 심사 스크린샷·심사 메모를 입력해 제출해요. 샌드박스에서 같은 계정 재구매·앱 재시작 후 지급 복구를 확인해요. [Apple 등록 절차](https://developer.apple.com/help/app-store-connect/manage-in-app-purchases/create-consumable-or-non-consumable-in-app-purchases/)
- Play Console에는 같은 ID의 일회성 상품과 구매 옵션·지역별 가격을 준비해요. 라이선스 테스터로 승인·보류·취소를 확인하고 기존 서버 영수증 검증·지급·소비 순서를 따라요. 같은 토큰의 재전송이 중복 지급되지 않아야 해요. [Google 일회성 상품](https://developer.android.com/google/play/billing/one-time-products)
- 엑솔라에는 같은 SKU의 가상 아이템을 테스트 카탈로그에 먼저 등록해요. 현지화·한국 정가·지원 지역을 맞추고 서명 검증, 결제 완료·취소 순서 역전, 창 닫기 후 주문 복구를 확인해요. 세 채널의 지급·회수는 같은 구단주 인벤토리와 구매 원장을 사용해요. [기존 웹 결제 운영 절차](../operations/web-pay.md)
- 지급은 스토어·거래 ID당 한 번, 소비는 편집 요청당 한 번이에요. 미사용 환불은 잔액에서 회수하고 이미 쓴 경우에는 구매자 미회수 수량으로 기록해요. 거래처별 지급/소비/환불 불일치, 보류 지급, 실패 사유를 운영 화면에서 조회해요. 수동 복구는 권한과 사유를 요구하고 누가 언제 어떤 거래를 수정했는지 기록해요. 밸런스 설정 `retiredPhysiqueOpen`은 기본 0이에요. 상품 노출·구매·편집은 모두 1에서만 열려요. 닫으면 잔액과 카드에 적용된 체격을 보존해요.
