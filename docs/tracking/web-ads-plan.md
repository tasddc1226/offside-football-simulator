# T-11-027: 웹 광고 도입 기획 (Google AdSense)

작성일: 2026-10-01

상태: 기획 / 기능 미구현 / 운영 설정(사이트 승인·ads.txt) 미적용

소스 기준: 원격 main `246894871c966b8917557efa0aac6ad2ec7cfb59`

## 1. 원칙

- 광고는 유저가 원래 잠깐 멈추는 순간과 읽기 화면에만 둔다. 게임 조작 화면과 버튼 주변에는 두지 않는다(3.1).
- 광고를 봐야 진행할 수 있는 구조는 만들지 않는다. 보상형은 원하는 사람만 보는 선택 보상으로만 검토한다(5단계 3).
- 수익보다 리텐션이 우선이다. 광고가 붙은 화면의 지표가 나빠지면 그 위치를 끈다(6절).
- 이 문서의 위치·빈도·수치는 제안이다. 운영 데이터를 보고 정한다.

용어: **위치**는 광고 칸 하나가 들어가는 자리(예: `hof-bottom`), **단계**는 위치를 켜는 순서(5절)다.

## 2. 선결 조건(5절 0단계)

- **AdSense 사이트 승인**: `offside-lab.com`을 사이트로 추가하고 승인받는다. 지금 계정 메뉴에는 홈·보고서·지급·계정만 있고 사이트·광고 메뉴가 없어, 호스팅 계정 업그레이드가 필요한지 먼저 확인한다.
- **`ads.txt`**: `apps/web/public/ads.txt`에 게시자 ID 한 줄.
- **개인정보처리방침**: `/legal/privacy/` 본문(`apps/web/scripts/seo.mjs`의 `privacyBody`)에 광고 쿠키·제3자(Google) 처리·맞춤 광고 끄는 방법을 추가한다.
- **차단 관리**: 고등학생 유저가 있을 수 있어 AdSense 차단 관리에서 민감 카테고리(도박·주류 등)를 막는다.

웹에는 CSP 헤더가 없어 스크립트 로드에 막히는 것은 없다. 승인 전에도 코드는 꺼진 상태(4절 스위치)로 먼저 넣어 둘 수 있다.

## 4. 노출 정책과 구현

### 4.1 정책은 한 곳에서

위치표와 노출 판단은 웹·앱 공용 순수 모듈 `packages/app-core/adPolicy`(같은 방식: `resultTour.ts`) 하나에 둔다. 화면은 위치 이름만 넘기고 규칙을 직접 검사하지 않는다.

- **위치표**: 위치 이름 → 단계, 켜짐 여부, 재요청 간격, 화면당 최대 칸 수. 위치별 on/off도 이 표의 열이다.
- **`shouldShow(위치, ctx)`**: `ctx`는 플랫폼이 채운다(업무 모드, 신규 유저 여부, 마지막 노출 시각, 지금 화면의 칸 수).
- 규칙(초기값)
  - 신규 유저 보호: 첫 커리어의 첫 시즌이 끝나기 전에는 2단계 위치를 보이지 않는다. 판별은 게임 상태(`appState.G`, 이 기기 은퇴 기록 `loadHOF()`)에서 파생하고 새 저장 키를 만들지 않는다. 분석 장부(`offside_analytics_ledger_v1`)는 동의한 유저에게만 쌓이므로 쓰지 않는다.
  - 간격: 같은 위치는 세션 안에서 5분 안에 다시 요청하지 않는다. 하프타임은 하루 10경기까지 반복될 수 있어 특히 필요하다. 안 채워진 위치는 그 세션 동안 다시 요청하지 않는다.
  - 화면당 최대 칸 수: 읽기 화면 2칸, 쉬는 지점 1칸.
- 앱(AdMob)도 같은 위치표와 `shouldShow`를 쓰고 렌더만 다르게 한다. 규칙 검증은 `adPolicy` 단위 테스트로 하고, 웹은 `AdSlot` 스모크 테스트 하나만 둔다. 기본 빌드에는 광고가 없어 기존 e2e는 그대로다.

### 4.2 웹 `AdSlot`

- **스위치**: 빌드 환경변수가 없으면 광고 코드가 빠진다. GA4의 `analytics/config.ts` `enabled()`처럼 호스트 일치와 운영 ID 분리를 같이 검사해, 스테이징·테스트 호스트에서 실제 광고를 요청하지 않게 한다. 화면은 `AdSlot`을 상수 가드나 동적 import로만 불러 스위치가 꺼지면 번들에서도 빠지게 한다.
- **업무 모드**: `ui/skin.svelte.ts`의 `sheetOn()`(반응형)으로 칸 자체를 그리지 않는다. CSS로 숨기면 스크립트는 그대로 로드되므로 쓰지 않는다.
- **로드 시점**: 모든 방문자에게 미리 불러오지 않는다. 첫 `AdSlot`이 `shouldShow`를 통과해 붙을 때 `adsbygoogle.js`를 한 번만 삽입한다(한 번만 실행되는 Promise). 삽입은 `analytics/browser.ts`의 스크립트 삽입 방식(`loaded` 플래그, 실패 처리), 대기는 `main.ts`의 `whenIdle`을 따른다.
- **요청 시점**: 칸이 화면 근처에 올 때(`IntersectionObserver`) 한 번만 `push`한다. SPA라 화면을 오갈 때 칸을 새로 만들고 사라질 때 정리한다.
- **화면 밀림**: 칸 높이를 미리 잡는다. 안 채워지면 접는다.

### 4.3 동의

- 광고 맞춤 여부는 기존 이용 분석 동의(`analytics/browser.ts`의 `getConsent()`·`onConsent()`, `AnalyticsConsent.svelte`)를 구독해 정한다. 따로 받기로 하면(7절 2) 같은 모듈의 저장 키 방식으로 필드를 하나 더한다. 동의 창을 새로 만들지 않는다.
- 동의하지 않았거나 아직 고르지 않은 유저에게는 비개인화 광고(`requestNonPersonalizedAds`)를 요청한다.
- GA 초기화가 `ad_storage`·`ad_personalization`을 `denied`로 고정하고 있어, 맞춤 광고를 켤 때 이 기본값과 어떻게 맞출지 구현 때 정한다.
- 한국 외 EEA·영국 유입이 생기면 Google 인증 CMP가 필요하다. 1단계는 국내 기준으로 시작한다.

## 5. 단계

| 단계 | 내용                                                                      | 전제                                    |
| ---- | ------------------------------------------------------------------------- | --------------------------------------- |
| 0    | 2절 선결 조건                                                             | 오너의 AdSense 작업                     |
| 1    | 1단계 위치 + `adPolicy`·`AdSlot`                                          | 0 완료                                  |
| 2    | 2단계 위치 + 신규 유저 보호·간격                                          | 1을 2주 운영한 뒤 6절 지표 비교         |
| 3    | H5 Games Ads(`adBreak()`) 보상형 선택 보상(예: 광고 보고 오늘 팀 경기 +2) | 별도 신청·승인, 랭킹 공정성 검토(7절 4) |
| 4    | 앱 AdMob(`react-native-google-mobile-ads`)                                | 다음 스토어 빌드(아래)                  |

**앱**: AdSense는 네이티브 앱 안에서 쓸 수 없어 AdMob을 쓴다. AdMob은 네이티브 의존성이라 새 스토어 빌드가 필요하고 OTA 런타임 지문이 바뀌므로 스토어 빌드 사이에는 넣지 않는다. 그 사이 웹에만 광고가 있는 기간이 생긴다. iOS는 맞춤 광고에 앱 추적 투명성(ATT) 동의 창이 필요하다.

## 6. 측정과 중단 기준

- GA4: `ad_slot_view`(위치 이름만)를 [GA4 측정 기획](ga4-measurement-plan.md) 3절 이벤트 계약 표에 추가하고 `analytics/model.ts` 허용 목록을 따른다. 칸이 화면에 들어오고 채워졌을 때 위치별 세션당 1회만 보낸다. 요청·채움 수는 AdSense 보고서(위치별 맞춤 채널)로 본다.
- 비교: 단계 적용 전후 2주의 D1·D7 재방문율, 세션당 완료 시즌 수, 팀 매치 일일 경기 수.
- 중단: 하나라도 10% 넘게 떨어지면 그 단계 위치를 끄고(위치표 on/off) 원인을 본다.

## 7. 미결

1. AdSense 계정이 사이트를 추가할 수 있는 상태인지(2절).
2. 맞춤 광고 동의를 이용 분석 동의와 묶을지(4.3).
3. 시즌 결산 광고 위치: 결산 시트는 버튼이 많아 피하고, 닫은 뒤 커리어 탭 시즌 기록 아래가 후보.
4. 3단계 보상형의 보상 종류와 랭킹 공정성.
5. 앱 AdMob을 넣을 스토어 빌드 시점.

## T-11-108: 은퇴 직후 하단 배너 (2026-10-05)

GA4 2026-09-28~10-04 페이지 집계에서 은퇴 결과(`/retired`)는 5,831회 조회·활성 사용자 645명으로,
한 커리어를 마친 뒤의 읽기 화면 후보다. 이는 광고 수익이나 리텐션 개선의 증거는 아니며 배치 검증의 근거다.

- 새 위치 `retired-bottom`은 기존 선수 상세 `legend-bottom`과 별도로 빈도를 관리한다.
- 웹·앱 모두 리포트, 기록 보관 카드, 새 커리어·명예의 전당 버튼 아래에 본문과 같이 스크롤되는 1칸만 둔다.
  웹은 기존 28px 광고 여백, 앱은 화면 항목 간격 14px와 광고 위 여백 24px로 버튼과 구분한다.
  공유 하단 바는 기존 안전 영역과 콘텐츠 여백을 사용한다. 전면 광고·대기·자동 이동은 추가하지 않는다.
- 웹은 기존 IntersectionObserver로 화면 근처에서 요청한다. 앱은 크레딧 스크롤 계측기로 하단이 화면에
  들어온 뒤 AdSlot을 마운트하므로, 리포트 첫 화면에서 광고 요청·동의 창을 시작하지 않는다.
- 기존 위치별 세션 5분 재요청 제한, 실패 시 해당 세션 재요청 중지, 웹 업무 모드 숨김,
  앱 UMP 동의·광고 제거 구매 처리·비개인화 광고를 그대로 사용한다.
- 웹 활성화: AdSense에서 해당 위치의 단위를 만든 뒤 저장소 변수 `VITE_ADSENSE_SLOTS` JSON에
  `"retired-bottom":"실제 광고 단위 ID"`를 기존 키와 함께 추가하고 웹을 빌드한다.
  단위 ID 미설정·호스트 불일치·사이트 미승인 상태에서 노출을 보장하지 않는다. 이 PR은 계정 설정을 바꾸지 않는다.
  앱은 기존 플랫폼별 AdMob 배너 단위를 사용한다.
- 로컬 확인은 `VITE_ADSENSE_PREVIEW=1` 개발 서버의 자리 표시로 수행한다. 실제 광고 노출·수익 검증과
  운영 배포는 별도다. 배포 후 `/retired` 조회·새 커리어 시작·공유와 광고 공급자 보고서를 비교한다.
