# T-11-127 장기근속 · 원클럽맨

상태: 구현 완료, draft PR 검증. 운영 미배포. 리세·성장·이적·보상 규칙 변경 없음.

## 판정

- 장기근속(`long-service`): 한 직접 육성 은퇴 선수의 한 일반 프로 구단 누적 재적 시즌 ≥10. 이적 후 복귀 전후를 합산한다. 여러 선수의 시즌을 합치지 않는다. 상무(`clubId=sangmu`)와 현역 복무(`league=병역`)는 제외하고 원래 구단에 더하지 않는다.
- 원클럽맨(`one-club`): 기존 총 프로 시즌 ≥10 기준 유지. 고교·대학을 제외한 기존 총시즌 집계를 그대로 두고, 구단 다양성에서 `clubId=sangmu`만 제외한다. 남은 구단이 정확히 하나여야 한다. 상무만의 경력은 불인정.
- 고교·대학 리그는 공용 `LEAGUE_BASE.amateur`로 제외한다. 승격·구단명 변경은 같은 `clubId`로 합산하고 동명 다른 ID는 합치지 않는다.
- `seasonCareersOf`의 원 육성자, 은퇴 상태, peak 존재, 해당 `serviceSeason`, hidden=0 조건을 유지한다. 선수 이름 비공개(publicName=null)는 제외 조건이 아니다. 구입 선수는 구매자의 선수 업적에 들어가지 않고 판매해도 원 육성자의 기록으로 남는다.
- 3단계 기존 동급 `PTS.legend`에 따라 장기근속은 1회 50점. 최대 업적 수 +1, 달성 시 총점 +50·달성 수 +1이며 여러 선수가 충족해도 중복 지급하지 않는다. 별도 자금·아이템 보상 없음.

## 기존 기록과 한계

업적 화면 조회와 기존 은퇴·팀 저장·경기 후 갱신 경로에서 저장된 시즌 요약으로 재판정한다. 마이그레이션·운영 DB 접근·일괄 백필은 하지 않는다. 일일 cron은 기존 stale 대상만 재계산하므로 변경 없는 모든 기존 점수가 배포 즉시 갱신되는 것은 아니다. 지난 서비스 시즌도 해당 시즌 업적을 조회하면 재계산한다. 공개 랭킹은 기존 5분 캐시 정책으로 반영되며, 점수 변경 시 reached_at이 재계산 시각으로 바뀌어 동점 순위에도 영향이 있다. 등급 기준과 순위 정렬은 바꾸지 않는다.

선수 업적은 현재 기록으로 재판정하며 영구 달성 원장은 없다. TEAM·RACE의 team_kept 유지 로직은 그대로다. 기존 정상 원클럽맨의 ID·50점 기준을 보존하지만 잘못 합쳐진 이름/ID 기록은 분리되므로 판정이 달라질 수 있다.

ID 누락 기록은 이름으로만 묶는다. ID 기록과 이름 기록을 추정해서 합치지 않는다. 옛 구단명 변경, 이름만 있는 상무, 동일 이름의 실제 서로 다른 구단은 서버 자료만으로 확정할 수 없다. 같은 이름의 ID 없는 기록끼리는 기존 이름 기준 한계를 가진다. 서로 다른 ID와 이름/ID 간 충돌은 명시적으로 분리한다. 누락된 시즌 요약은 복원하지 않는다.

발견한 기존 모순: 현역 복무 요약은 club='현역 복무', league='병역', mil=true이며 기존 원클럽맨이 이를 프로 시즌·한 구단으로 집계한다. 요청의 총시즌 보존·상무 예외 범위에 맞춰 원클럽맨의 이 기존 동작은 변경하지 않았다. 따라서 현역 복무만 있는 비정상 기록도 기존 원클럽맨 판정에서는 true일 수 있다. 새 장기근속에서는 현역 복무를 제외한다. 이 별도 모순을 일반 프로 경력 전체의 정의 변경으로 확장하지 않았다.

## 근거와 검증 범위

사용자 제공 [DC 제보](https://m.dcinside.com/board/offsidegame/46)의 전북 12시즌 → 내슈빌 1시즌 → 전북 4시즌은 장기근속 충족·원클럽맨 불충족이다. 첨부 경력은 사용자 제공 확인 내용을 기준으로 했고 운영 기록을 조회하지 않았다.

단위 테스트는 9/10/11, 복귀, 상무 복귀/다른 구단/상무만, 아마추어 제외, 같은 ID 명칭·리그 변경, 다른 ID 동명, 옛 필드 혼합, 여러 선수 비합산, 50점 1회와 영어 응답을 고정한다. 로컬 D1 API 계약 테스트는 active/다른 시즌/hidden/구매 제외·비공개 이름 포함·판매 후 원 육성자 유지·clubId 전달을 검사한다. 저장 형식과 DB 스키마는 바꾸지 않는다. UI 조건은 웹·앱 공용 ko/en 안내로 제공한다. Simulator/Xcode는 사용하지 않는다.

로컬 검증: 업적 단위 31개, owner-team API 계약 39개, app-core 497개, contracts 120개 통과. 웹 빌드·번들 140.79KB/141KB, DB 스키마 변경 없음 확인. ego-browser에서 실제 Svelte 업적 컴포넌트에 합성 응답을 넣어 390×844 ko/en 조건 안내를 확인했고 가로 넘침은 없었다. 모바일 네이티브 실행은 사용자 범위에 따라 제외했다. 필수 PR CI는 최종 head의 두 잡 결과로 확인한다.
