# T-11-708: 28라운드 독립 리그

2026-11-12 사용자 결정. 같은 상대와 최대 55라운드를 치르면 경쟁의 결말이 늦다는 의견을 반영한다.

- 진행 중인 시즌 2 리그의 대진·마감·보상은 유지한다. 제3기부터 28라운드(8팀 기준 상대당 홈 2·원정 2회)로 고정한다.
- 리그 회차(`league.season`, 기존 DB/API 식별자)는 서비스 시즌과 분리해 3, 4, 5…로 증가한다. 선수·팀 자격과 경기 계산은 별도 `teamSeason`을 쓴다.
- 첫 독립 회차는 서비스 시즌 3 개막 후 5일 준비한다. 이후에는 마지막 경기 다음 날까지 결과를 보여 주고, 다음 날부터 하루 접수 후 배치한다. 자동 참가하지 않는다.
- 결산·보상·알림이 밀렸으면 다음 회차로 넘기지 않는다. 끝난 경기와 결산은 수정하지 않는다. 다음 배치는 직전 회차의 승강 결과를 쓰며 한 회차를 쉬면 새 참가자로 본다.
- 배치 시점의 팀 서비스 시즌을 `league_seasons.team_season`에 고정한다. 도중에 서비스 시즌이 바뀌어도 그 팀으로 끝까지 뛴다. 참가 중인 지난 시즌 팀은 컵과 같이 선발 편집을 허용하고, 리그 경기 1시간 전 잠금은 계속 적용한다.
- 컵의 판매·방출·감독 전향 제한은 리그에 확대하지 않는다. 컵 참가 여부와 대회 참가로 인한 편집 가능 여부의 조회를 구분한다.
- 늦은 참가 배치는 첫 배치 14일 뒤 한 번이다. 별도 7~8팀 리그에서 14라운드(7팀은 휴식 포함)를 치른다. 기존 참가자의 대진·승점은 유지한다.
- 회차당 순위·완주·빈자리 승격 보상의 수량은 기존 표를 유지한다. 늦은 참가도 같은 순위 보상표를 쓴다. 서비스 시즌이 길어 여러 회차가 열리면 보상 횟수는 늘어난다. 적용 후 주간 아이템 지급량과 늦은 참가 비중을 관찰한다.

## 호환성과 검증

기존 `season` 식별자와 과거 칭호 ID를 보존하고, nullable 열 하나만 추가한다. null인 기존 행은 종전 규칙이다. 새 형식의 `teamSeason`은 API의 선택 필드다. 클라이언트의 팀 화면 진입·프로필 시즌 선택은 서비스 시즌을 사용하고, 경기·신문·리그 복귀 주소는 리그 회차를 사용한다. 기존 `cupSeason` 응답 필드는 클라이언트 호환을 위해 유지하되, 참가 중인 컵·리그의 지난 서비스 시즌을 가리킨다. 로컬 게임 세이브 형식은 바뀌지 않는다.

일정·대진 균형, 늦은 참가, 서비스 시즌 경계, 결산 지연, 보상 중복 방지, 승강 승계, 다음 회차의 팀 시즌 분리를 테스트한다. 웹은 320/390px 확인과 빌드·번들 예산 검사, 앱은 타입·린트와 iOS/Android Hermes 번들을 확인한다. 실제 앱 화면 검증은 별도 증거로 구분한다. 웹 E2E는 푸시 후 PR CI에서 수행한다. 운영 DB 변경·배포는 이 작업의 범위가 아니다.
