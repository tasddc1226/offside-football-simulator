# T-10-082: 구단주 도전 과제와 칭호 기획

작성일: 2026-09-28

상태: 합의한 구조의 구체화 / 세부 조건은 검토안 / 기능 미구현

소스 기준: 원격 main `85679897b2ff8c9f4a5d3c2f947b57798e1f1912`

> **반영 현황(2026-09-29, main `7968afd`)**: 구단주 도전 과제·칭호는 미구현. 관련 기능으로 구단주 팀 화면의 구단 시즌 업적(T-10-092, 그 시즌 은퇴 선수·팀 기준 단계 업적)이 먼저 반영됐다 — 과제 설계 때 이 업적과 겹치지 않게 맞춘다.

## 1. 목표와 합의한 방향

선수 칭호는 한 선수의 인생을 표현한다. 구단주 칭호는 여러 선수의 커리어를 통해
유저가 어떤 육성 경험과 전문성을 쌓았는지를 표현한다.
최고 점수 공략의 반복 외에도 다음 선수를 키울 이유를 제공하는 것이 목표다.

사용자와 논의한 기본 구조는 **구단주 도전 과제 → 진행도 → 달성 → 구단주 칭호**다.

- 새로운 경험, 나만의 전문성, 특별한 도전의 세 갈래로 구성한다.
- 일일 숙제·연속 접속·미접속 손실 없이 여러 커리어에 걸쳐 완성한다.
- 대표 목표 하나를 선택할 수 있지만 선택하지 않은 과제도 자동으로 집계한다.
- 한 선수로 여러 과제를 동시에 달성할 수 있다.
- 칭호는 우선 명예·표시 보상이다. 선수 능력치·성장·잠재력·인기·레전드 점수에 보너스를 주지 않는다.
- 기존 선수 칭호를 대체하거나 기존 보상을 변경하지 않는다.

이 문서의 명칭·수치·데이터 설계·도입 순서는 구현을 위한 제안이다.
조건별 난도와 기록의 판별 가능성을 확인한 뒤 최종 확정한다. 실제 출시 일정은 약속하지 않는다.

## 2. 플레이 흐름

1. 구단주 화면에서 다음 도전을 발견하고 대표 목표로 표시한다.
2. 선수 생성 화면에서 목표와 관련된 포지션·유형을 가볍게 안내한다. 선택을 강제하거나 자동 변경하지 않는다.
3. 플레이 중에는 선수의 커리어에 집중한다. 상시 팝업이나 매 턴 서버 요청을 추가하지 않는다.
4. 은퇴 시 이번 커리어가 기여한 진행도와 새 칭호를 보여준다.
5. 대표 칭호를 장착하거나 다음 목표를 고른다. 새 선수 생성은 별도의 명시적 동작이다.

예시:

> 포지션의 이해 · 3/4
>
> 공격수·미드필더·수비수의 커리어를 완주했어요.
> 골키퍼까지 완주하면 ‘그라운드의 모든 자리’ 칭호를 획득해요.

진행도는 다음 행동을 이해할 수 있게 항목별 체크리스트로 보여준다.
‘3/4’만 보여주지 않고 남은 포지션·유형과 조건을 함께 표시한다.
이미 진행 중인 선수가 있으면 그 선수를 버리거나 덮어쓰도록 유도하지 않는다.

## 3. 선수 칭호와 구단주 칭호의 구분

| 구분 | 기존 선수 칭호 | 새 구단주 칭호 |
|---|---|---|
| 귀속 | 한 커리어 | 구단주 프로필 |
| 근거 | 그 선수의 기록·여정 | 해당 구단주가 육성한 서로 다른 커리어 |
| 보상 | 현행 선수 칭호 규칙 유지 | 표시·수집 중심, 게임 성능 영향 없음 |
| 대표 표시 | 선수 상세의 대표 칭호 | 구단주 이름 옆 대표 칭호 1개 |
| 생명주기 | 해당 선수의 기록으로 보존 | 새 선수를 시작해도 유지 |

과제 선택과 칭호 장착은 독립적이다. 과제를 바꿔도 진행도는 사라지지 않으며 칭호를
해제해도 획득 기록은 남는다. 직접 선택하기 전에는 새 칭호를 자동 장착하지 않는다.
명예의 전당에서는 선수 칭호와 구단주 칭호를 같은 라벨로 섞지 않는다.

## 4. 첫 출시 도전 과제 8개 제안

모든 조건은 공개한다. 초기에는 숨겨진 과제·무한 단계·획득 순위 경쟁을 넣지 않는다.
아래 수치는 **출시 전 분포 검증 대상인 가안**이며 난도가 높으면 낮추거나 조건을 바꾼다.

| ID | 과제 / 보상 칭호 | 조건 가안 | 진행도 |
|---|---|---|---|
| OQ-001 | 첫 번째 마침표 / 첫 선수를 배출한 구단주 | 선수 1명의 은퇴 완료 | 0/1 |
| OQ-002 | 포지션의 이해 / 그라운드의 모든 자리 | FW·MF·DF·GK 각각 1명 이상 은퇴 | 포지션 집합 0/4 |
| OQ-003 | 서로 다른 가능성 / 가능성을 보는 눈 | 조기 성장·대기만성·강철 체력·스타성 각각 1명 이상 은퇴 | 유형 집합 0/4 |
| OQ-004 | 공격수 육성 / 골잡이 양성소 | 서로 다른 FW 3명이 각각 통산 프로 100골 이상 후 은퇴 | 적격 선수 0/3 |
| OQ-005 | 중원 육성 / 중원의 설계자 | 서로 다른 MF 3명이 각각 통산 프로 100도움 이상 후 은퇴 | 적격 선수 0/3 |
| OQ-006 | 수비수 육성 / 수비의 기둥 | 서로 다른 DF 3명이 각각 통산 프로 200경기 이상 후 은퇴 | 적격 선수 0/3 |
| OQ-007 | 골키퍼 육성 / 수문장 공장 | 서로 다른 GK 3명이 각각 통산 프로 클린시트 50회 이상 후 은퇴 | 적격 선수 0/3 |
| OQ-008 | 다양한 국가대표 / 대표팀의 산실 | 서로 다른 3개 포지션에서 각각 A매치 1경기 이상 출전한 은퇴 선수 배출 | 포지션 집합 0/3 |

OQ-003의 네 항목은 현재 코드의 `trait` 분류다. 강철 체력·스타성까지 모두 성장 곡선이라고
설명하지 않고 ‘선수 유형’이라는 사용자 문구로 묶는다.
OQ-004~007은 선수 간 기록을 합산해 문턱을 넘기지 않는다. 각 선수가 조건을 충족해야 한다.
OQ-008은 U-23 대회 출전을 A매치로 새롭게 인정하지 않으며 현행 집계 정의를 따른다.

‘은퇴 완료’는 실제 게임 종료 경로로 은퇴 기록을 만든 커리어다. 생성 후 세이브 삭제·리셋은
완주로 세지 않는다. 조기 종료나 짧은 커리어가 실제 은퇴 규칙에 포함되는지는 구현 전 확인한다.
단순 나이 제한을 임의로 붙여 특이한 커리어를 배제하지 않는다.

프로 기록의 원본은 반드시 현행 계산 경로와 대조한다. 화면용 수치를 임의로 다시 계산해
다른 결과를 만들지 않는다. 공정한 비교가 어려운 과제는 출시에서 제외한다.

## 5. 특별한 도전과 후속 후보

| 후보 | 플레이 목적 | 출시 전 필요한 판별 |
|---|---|---|
| 한 구단의 시간 | 이적 대신 잔류를 선택해보기 | 같은 구단에서 연속 5개 프로 시즌 등 조건. 병역·임대·복귀의 처리와 stable clubId 필요 |
| 여러 무대의 경험 | 다른 리그에서 경력 쌓기 | 국내/해외·학교/프로·병역 리그 분류와 실제 출전 조건 |
| 다시 일어서는 선수들 | 부상·방출 이후 커리어 회복 | 사건 전후의 상태, 재기의 객관적 조건. 단순 문구 검색 금지 |
| 서로 다른 선택 | 이벤트 선택 성향 바꾸기 | 기록 수집 시작 시점과 누락 여부, 과도한 위험 선택 유도 방지 |
| 나만의 베스트 일레븐 | 다양한 육성 선수를 구단에 활용 | 구단·카드·편성 기능 도입 이후 검토 |

초기 8개는 경험·전문성 중심이다. 특별한 도전은 안정적으로 검증 가능한 항목부터
추가한다. 부상·방출·실패를 일부러 얻거나 희귀 확률을 무한 반복해야 하는 과제는 피한다.

## 6. 화면과 상태

### 구단주 화면

대표 칭호, 도전 중인 목표 하나, ‘도전 과제 전체 보기’를 표시한다.
도감은 미달성/달성 및 새로운 경험/전문성/특별한 도전으로 찾을 수 있게 한다.
달성 시각과 기여 선수 목록을 열 수 있지만 목록마다 선수 상세 API를 호출하지 않는다.

### 선수 생성

현재 목표와 맞는 선택지에 추천 표시와 이유를 붙인다.
추천이 최강 조합이라는 의미가 아니며, 목표와 다른 선택을 해도 정상적으로 시작할 수 있다.

### 은퇴 화면

이번 선수의 기여, 새로 달성한 과제, 다음에 남은 조건을 한 영역에 묶는다.
여러 과제를 동시에 달성하면 연출은 묶고 각 보상은 빠짐없이 지급한다.
추가 보상을 받기 위해 ‘수령’ 버튼을 여러 번 누르게 하지 않는다.

### 연결·오류·빈 상태

- 첫 이용: 달성 0개와 첫 도전을 안내하며 빈 목록을 오류처럼 표현하지 않는다.
- 업로드 대기: ‘기록 동기화 후 반영돼요’. 로컬 예상치와 서버 확정치를 구분한다.
- 네트워크 오류: 기존 획득 상태를 유지하고 재시도 안내. 게임 진행 자체를 차단하지 않는다.
- 과거 기록 부족: ‘이전 기록에는 필요한 정보가 없어 반영하지 못했어요’. 0점·실패로 표시하지 않는다.
- 익명 이용: 익명 프로필에도 귀속할 수 있는 안을 우선 검토하고 복구 가능 범위를 안내한다.
  구글 연결 전후에 같은 진행도가 이어져야 하며, 별도 프로필 간 자동 병합을 가정하지 않는다.

## 8. 집계·보존 규칙 제안

- 귀속 키는 프로필 ID이며 선수 이름·공개 닉네임이 아니다. 선수 개수는 서로 다른 careerId로 센다.
- 은퇴 기록의 저장 성공 시 해당 커리어의 기여분을 반영한다. MVP에서는 현역 선수 실시간 집계를 생략한다.
- 과제별 기여 근거를 저장하고, 같은 은퇴 재전송·새로고침·기기 이동으로 진행도나 보상이 늘지 않게 한다.
- 하나의 커리어가 여러 과제에 기여하는 것은 정상이다. 한 과제 안에서 같은 선수를 여러 명으로 세지 않는다.
- 대표 목표 변경·칭호 장착/해제는 업적 집계와 분리한다.
- 기존 서버 기록은 조건을 입증할 수 있는 범위에서 소급 인정한다. 표시 이름·추측·누락값 채우기로 달성시키지 않는다.
- 소급 첫 동기화에서는 보상을 묶어 보여주고 재접속 때마다 축하 연출을 반복하지 않는다.
- 실제 계정 연결/복구/소유권 이전 경로를 확인해 이전·재계산 정책을 구현한다. 두 프로필이 같은 사람이라는 추정으로 합치지 않는다.
- 카드 시장이 도입돼도 구매한 선수는 육성 과제에 포함하지 않는다. 원 육성자의 달성 기록도 카드 판매로 제거하지 않는다.

논리적으로 필요한 정보는 과제 정의(id·버전·조건·보상), 프로필별 진행과 기여 careerId,
획득 이력, 대표 목표/칭호다. 정확한 테이블명·API는 구현 설계에서 확정한다.
과제 조건을 수정할 때는 버전을 남긴다. 난도 상향으로 정상 획득한 칭호를 소급 박탈하지 않는 안을
기본으로 하고, 오류·부정 기록 정정은 별도 정책과 이력을 둔다.
계정 삭제 요청은 기존 개인정보 정책을 따르며 ‘영구 칭호’가 계정 삭제 후 개인 기록 보존을 뜻하지 않는다.

## 9. 무결성과 서버 비용

클라이언트가 보낸 ‘달성 완료’ 플래그를 그대로 수락하지 않고 서버의 수락된 커리어 자료로 판정한다.
다만 서버에 저장된 요약도 클라이언트 기원이며, 이것만으로 커리어 진위를 보증하지 않는다.
MVP의 보상은 비거래·비성능 표시로 제한하고 자동 플레이 관찰 신호만으로 정상을 보증하거나 제재하지 않는다.
재화·희소 자산·경쟁 보상으로 확장하려면 별도 진위 검증 설계가 선행돼야 한다.

공개 표시 동의와 익명 정책을 유지한다. 과제 달성을 위해 선수 실명이나 비공개 커리어를 공개하도록 강제하지 않는다.

은퇴/소급 시점에 집계를 수행하고 매 화면 진입마다 전체 커리어 스캔을 하지 않는다.
구단주 탭은 열릴 때 로드하고 `cachedGet`을 사용한다. 쓰기 성공 시 관련 캐시를 비운다.
공개 구단주 칭호 표시가 추가되면 공개 응답 캐시·무효화와 필터 인덱스를 함께 설계한다.
칭호 표시에 선수 수만큼 별도 API를 붙이는 N+1을 피한다.

## 10. 서비스 시즌과 관계

초기 출시의 과제와 칭호는 영구 누적이다. 서비스 시즌제가 없어도 독립적으로 출시할 수 있다.
별도 논의한 [T-10-078 시즌·카드·시장 기획 PR](https://github.com/tasddc1226/offside-football-simulator/pull/361)은
참고 관계이며 이번 문서의 구현 선행 조건이 아니다.

후속 시즌 도전은 서비스 시즌 ID와 표시 배지(S1 등)를 별도로 두고 기간 종료 뒤에도 획득 이력을 보존한다.
시즌 경계·참가 자격·마감 후 은퇴의 처리는 시즌 기획이 확정된 뒤 따른다.
한 커리어가 영구 과제와 시즌 과제 모두에 기여할 수 있지만 서로 다른 범위의 진행도를 섞지 않는다.
시즌 경쟁 유불리를 만드는 능력치 보상은 넣지 않는다.

## 11. 단계별 범위와 검증 기준

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| A | 과제 정의·집계 계약·근거 점검 | 각 과제의 입력·누락·중복·계정 귀속 규칙 확정 |
| B | 영구 과제와 소급 집계·보상 이력 | 같은 은퇴 재전송에도 한 번 지급, 여러 과제 동시 달성, 기존 기록 처리 |
| C | 구단주 도감·목표 선택·은퇴 요약 | 빈 상태·오류·업로드 대기·완료 상태와 기기 복구 확인 |
| D | 대표 칭호·공개 표시·생성 안내 | 선수 칭호와 구분, 보유 칭호만 장착, 공개 동의 유지 |
| E | 특별한 도전·시즌 과제 | 추가 기록과 시즌 정책 확정 후 별도 출시 |

필수 수용 사례:

1. FW 3명만 은퇴시키면 OQ-002는 1/4이다. 네 포지션을 완료해야 4/4가 된다.
2. 대표 목표를 선택하지 않은 상태에서도 은퇴 시 진행된다. 목표 변경으로 초기화되지 않는다.
3. 같은 careerId의 은퇴 요청을 반복해도 선수 수·달성 횟수는 변하지 않는다.
4. 두 번째 기기에서 같은 프로필을 복구하면 획득·장착 상태가 일치한다.
5. 학교 경기와 U-23 기록이 프로·A매치 조건에 섞이지 않는다.
6. 기록 누락은 미확인으로 처리하며 플레이 기록 자체를 삭제하거나 훼손하지 않는다.
7. 한 선수로 여러 과제를 달성하면 각 보상은 한 번씩 지급되고 연출은 묶인다.
8. 칭호 획득 전후에 같은 시드·선택의 선수 시뮬레이션 결과가 달라지지 않는다.
9. 구단주 화면 반복 진입 시 불필요한 요청이 늘지 않고 전체 커리어 재집계가 발생하지 않는다.
10. 진행 중 선수의 세이브·기존 선수 칭호는 유지된다. 형식 변경 시 이전 세이브 마이그레이션을 검증한다.
