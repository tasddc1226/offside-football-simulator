# 게임 경험 새로고침 통합 기록 — 2026-09-06

상태: 로컬 통합·검증 중. 아직 `main`에 병합하지 않았고 PR #77은 Draft다. 후속 밸런스 수정이
끝난 최종 head로 새 PR을 준비한다. 이 문서는 변경의 사용자 경험과 현재 검증 범위를 요약하며,
기존 설계 문서나 밸런스 인수 기록을 대체하지 않는다.

## 작업 분할과 통합 원칙

세 Sol 작업은 충돌을 줄이도록 다음 경계로 나눴다.

1. 선수 생성과 엔딩: 생성 여정, 스타일 비교, 확정·킥오프, 은퇴 회고·Legacy·연대기·최종 프로필.
2. 시즌과 경기 표현: pending 상태의 정직한 안내, 결과 reveal, 챕터·시즌 진행, KEEP 역할 유지 경로.
3. 계약과 저장 경계: 첫 계약·재계약 표현, 명령 원자성, 버전 고정, 실패 복구와 E2E 여정 보존.

화면 표현은 바꿨지만 도메인 명령과 저장된 커리어의 규칙·콘텐츠 버전이 정본이라는 원칙은 유지했다.
기존 커리어를 새 후보 버전으로 암묵적으로 재평가하지 않으며, 명령 중복 제출 방지와 실패 후 재진입
경로도 그대로 보존한다.

## 선수 생성에서 첫 계약까지

선수 정보 입력은 한 화면의 긴 폼 대신 `정체성 → 선호 위치 → 출발 배경`의 세 패널로 진행한다.
정체성에서 이름·성별·국적·주발을, 선호 위치에서 포지션 설명과 피치를, 출발 배경에서 실제 효과와
위험을 확인한다. 포지션은 보장된 고정 역할이 아니라 선호 위치임을 명시한다. 다음 단계의 스타일
카드는 같은 포지션 안에서 실제 역할 가중치와 능력치 자료로 장점과 상대적 약점을 비교하고,
확인 화면은 선택을 한 장의 선수 카드로 모은다. 최종 명령이 성공한 뒤에만 committed kickoff를
보여 주며, 같은 확정 명령을 두 번 보내지 않는다.

작성 중 입력과 엔진 저장은 의도적으로 구분한다. 탭 안의 `sessionStorage` scratch는 새로고침이나
생성 단계 사이 이동에서 아직 제출하지 않은 UI 입력과 현재 패널을 복구한다. 저장소 접근 실패나
형식이 잘못된 값은 무시하고 엔진의 DRAFT를 사용한다. scratch는 탭을 닫으면 사라질 수 있는 임시
편의 기능이며 영구 저장으로 표시하지 않는다. career id가 같고 상태가 DRAFT일 때만 복구하고,
엔진 명령이 성공하면 지운다. 영구적인 진행 상태와 버전은 계속 엔진 snapshot이 소유한다.

pending 화면은 처리 중인 사실만 말하며 결과를 미리 약속하지 않는다. 결과 reveal은 일반 모드에서
짧은 전환을 제공하되 키보드 입력으로 즉시 넘길 수 있다. `prefers-reduced-motion`에서는 불필요한
이동을 제거하고, FAST도 맥락을 잃는 0초 전환 대신 짧은 cue를 유지한다. 모든 주요 선택은 키보드로
도달 가능하고, 포커스는 단계 전환과 깊은 링크의 목적지를 설명하도록 이동한다.

계약 카드는 연봉·기간·역할 약속 등 결정에 필요한 핵심 조건을 먼저 보여 주고 비교 상세를 뒤에 둔다.
첫 계약은 사인 뒤 별도의 시작 ceremony에서 사용자가 `커리어 시작`을 눌러 대시보드로 간다.
시즌 시작 시 현재 포지션과 squad role이 모두 같은 KEEP 제안은 변경 없는 확인이므로 자동 수락한다.
START_SEASON은 성공했지만 자동 수락이 실패한 경우에는 `/role` 복구 화면을 남기며, START_SEASON을
다시 보내지 않는다. 역할·포지션 변경 제안은 계속 명시적 선택 화면을 사용한다. 미래 재계약 조건이
현재 계약 조건처럼 표시되던 버그도 고쳐, 현재 효력과 다음 계약의 제안을 구분했다.

## 마지막 휘슬 이후

은퇴는 되돌릴 수 없는 선택임을 확인한 뒤 하나의 명령으로 확정한다. 종료 뒤 흐름은
`커리어 회고 → Legacy Score → 근거 연대기 → 최종 프로필`이다. 회고에는 실제 Archive의 시즌,
출전, 분, 평점, 가장 빛난 시즌, 구단·트로피·대표팀·수입 coverage를 사용한다. 자발·강제 원인이
저장돼 있지 않으면 추론하지 않고 중립적인 마지막 휘슬 문구를 쓴다.

Legacy의 다섯 축과 상위 요인은 저장된 source id를 통해 연대기의 revision으로 이동한다. 시즌·계약·
이적·부상·국가대표·은퇴 같은 주요 revision은 바로 보이고, `STEP_PASSED`만 있는 일상 진행은 한 개의
상세 묶음에 접는다. 접힌 기록을 가리키는 해시로 들어오면 묶음을 자동으로 열고 정확한 revision에
포커스한다. 모든 revision anchor는 보존한다. 최종 프로필은 실제 선수 공개 정보와 Archive 결과만
표시하고, 새 커리어의 성장치로 이전하지 않는다.

네 엔딩 URL에 DRAFT 커리어로 직접 들어오면 빈 은퇴 셸을 보여 주지 않고 `screenForCareer`가 정한
실제 생성 화면으로 돌아간다. 반대로 정산 시즌이 정확히 하나인 ACTIVE 커리어는 명시적으로 은퇴할
수 있다. Archive·Legacy 계산과 보관은 atomic cohort로 다루고, ruleset/content/legacy version,
checksum, archive hash, retirement revision을 함께 검증한다. 로드·명령·결과 생성 중 일부만 성공한
상태에서는 완료한 것처럼 표시하지 않으며 기존 복구 경로를 유지한다.

## 로컬 통합 검증

`3fea40c` 기준으로 lint, dependency lint, typecheck, content validation, production build와 bundle
검사를 통과했다. bundle 측정값은 100.47 KB다. 이 값은 이후 통합된 새 밸런스 후보의 최종 gate를

실제 로컬 API와 웹(`localhost:8787`, `localhost:5173`)에서도 새 커리어를 처음부터 확인했다.
ruleset `1.0.0`, content pack `0.1.0`으로 박준서를 생성해 첫 시즌을 마치고 18세에 자발 은퇴했다.
최종 기록은 26경기, 2,210분, 평균 평점 6.6, OVR 61, Legacy 30이었다. API 조회는 200이었고
revision 23, 생성 출처 `svc_kickoff`, Archive hash는
`14997b00e56d79dc98a234a0968a838f4673dca66bf6299fe0176cfbb04f6ec1`이었다. 새로고침 뒤에도 같은
결과가 유지됐다. Legacy 근거 revision 22로 이동해 포커스되는 것과, 일상 기록 revision 15 해시로
진입했을 때 상세 묶음이 열리고 해당 항목에 포커스되는 것도 확인했다. 개인정보와 recovery code
원문은 이 기록에 남기지 않는다.

## 남은 인수 항목

Legacy 1.1 후보의 mixed 800 파일럿은 아직 제품 목표를 충족하지 못했다. LEGEND 0.38%, ICON
11.63%, 80점 이상 5.75%였고 무관 80점 이상은 31명 중 0명이었다. 이는 실제 사용자의 선택 분포가
아니라 포지션과 요청 길이를 통제한 합성 진단 표본이다. 따라서 실제 사용자 분포처럼 설명하거나,
목표 비율에 맞추기 위해 점수를 역산하지 않는다.

추가 진단에서 15분 출전의 stat 생산량이 90분과 같아질 수 있는 문제가 발견돼 별도 수정 중이다.
이 문제는 포지션별 기여와 무관 고득점 경로를 왜곡할 수 있으므로, 수정된 후보의 새 checksum과
표본으로 다시 검증하기 전에는 800 결과를 최종 밸런스나 참조 모집단으로 채택하지 않는다. 최종
head의 전체 gate, 새 파일럿과 필요한 인수 근거를 확보한 뒤 PR을 열고 Draft PR #77의 병합 여부를
판단한다.
