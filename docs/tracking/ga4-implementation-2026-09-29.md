운영 측정 시작일은 아직 없음: 이 PR은 병합·배포·운영 환경변수 적용 전이다.

## 코드 동작

- 기본 비활성: `VITE_GA4_MEASUREMENT_ID`와 `VITE_GA4_HOSTNAME`을 둘 다 지정해야 한다.
  운영 ID는 운영 호스트에서만 허용하고 테스트 ID로 운영 호스트를 측정하지 않는다.
- 분석 동의 전과 거부 상태에는 Google 태그/요청 없음. 동의 UI는 게임을 막지 않는다.
  설정에서 철회하면 GA 비활성 플래그, 분석 쿠키/ledger 삭제. 기존 세이브/복구/로그인은 유지한다.
- 최초 화면과 내부 전환을 중앙화해 수동 page_view 1회. URL은 화면 이름과 허용된 UTM만 남긴다.
  공유 ID, OAuth 쿼리/해시, 이름·제목 원문과 알 수 없는 referrer를 보내지 않는다.
- 실제 생성/첫 시즌 종료/은퇴 액션을 기록하며 기존 세이브 로드나 업로드 재시도는 재생하지 않는다.
- 커리어 ID는 로컬 ledger에만 사용한다. 최근 30일 최대 200개 + 활성 커리어, 전송 전에 중복 표시.
  다중 탭 경합/저장소 삭제는 중복 또는 누락 가능. 브라우저 동의·차단으로 인한 표본 편향도 있다.
- 분석 모듈을 지연 로드한다. 로딩 전 액션·차단·전송 실패는 누락을 허용하며 과거 행동을 재생하지 않는다.
  Google 태그의 일시 메모리 큐 외에 영구 재전송 큐를 만들지 않는다.
- 공유 클릭과 clipboard resolve를 분리한다. 복사 성공은 외부 게시/실제 유입을 의미하지 않는다.
- 엔진·RNG·세이브 스키마·API·D1 변경 및 추가 백엔드 요청 없음.

## 운영 적용 순서

1. 콘솔 보관/광고 설정, 핵심 이벤트·맞춤 정의를 재확인하고 테스트 DebugView 수신을 검증한다.
2. 개인정보처리방침 7절과 선택 UI 검토. Consent Mode가 모든 적용 지역의 법적 요구사항을 자동 충족한다고 간주하지 않는다.
3. PR CI 통과 후 운영 적용 시 production 환경 변수에 위 운영 ID/호스트 지정.
   staging에는 별도 테스트 ID/호스트 지정. 디버그는 명시적 로컬 빌드의 `VITE_GA4_DEBUG=true`만 허용.
   기존 STAGING_ENABLED 설정은 변경하지 않는다.
4. 정확한 main SHA로 기존 운영 릴리즈 절차 실행, 배포 자산·동의 전/후 네트워크·GA 실시간 수신 확인.
5. 수집 시작 시각을 기록한다. 첫 2주는 계측 검증·기준선 수집, 이후 측정 계약의 성숙한 24시간/7일 코호트로 비교.
   경로 탐색/전환율 표본이 쌓이기 전에 개선 효과를 단정하지 않는다.

비활성 롤백은 production의 측정 ID/호스트 변수를 비우고 웹을 다시 빌드·배포한다.
변수 변경만으로 이미 배포된 번들 또는 열린 탭이 즉시 바뀌지는 않는다.
