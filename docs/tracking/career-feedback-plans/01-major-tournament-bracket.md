# 주요 클럽 대회 대진표와 경기 체감 기획

> 상태: 기획 제안 · 구현 및 운영 적용 전
> 기준: 2026-10-13 원격 main `1a67ecd7`. T-11-238의 네 기능은 별도 로컬 구현이며 이 문서 PR에 포함되지 않습니다.
> 수치·새 저장 필드·새 함수명은 구현 시 검증할 설계 후보입니다. 이 PR 병합은 기능 출시 승인이 아닙니다.

## 문제와 목표

현재 커리어 대회는 단계·출전·골·도움 위주로 요약돼 어떤 상대를 이기고 결승에 갔는지 알기 어렵습니다. T-11-238의 우승 트로피는 결산의 보상감을 보완합니다. 남은 목표는 진행 중인 대회의 상대·진출 경로를 일관된 기록으로 보여 주는 것입니다.

## Phase 0 현재 구조와 사용 가능한 기반

- `packages/game/src/comps.ts`의 `seasonSetup`, `compsPhase`, `contPhase`, `tie`가 기기에서 대회를 계산합니다.
- `SeasonComp`(`packages/game/src/types.ts`)에는 단계·성적이 있고 전체 참가팀·대진·스코어는 없습니다. `CompGame`에도 상대와 스코어를 계산하지 않는다는 주석이 있습니다.
- `apps/web/src/ui/cup/CupBracket.svelte`와 앱 구단주 컵 화면은 레이아웃 참고용입니다. 서버 구단주 컵과 개인 커리어 대회는 서로 다른 게임입니다. 구단주 컵 API를 커리어에 연결하지 않습니다.

## 제안 범위와 사용자 흐름

1. 먼저 UEFA 챔피언스리그의 녹아웃 단계만 지원합니다. 전체 리그 페이즈 대진·국내 모든 컵·국가대표는 후속 단계입니다.
2. 시즌 탭의 해당 대회에서 대진표를 엽니다. 기본 화면은 내 팀의 이번 라운드와 진출 경로이며 전체 대진은 펼쳐서 봅니다.
3. 라운드별 상대·진출/탈락·다음 상대를 표시합니다. 화면을 열거나 이적 제안을 살펴본다고 대회를 진행하지 않습니다.
4. 첫 버전은 조작을 막는 별도 애니메이션 없이 라운드 결과가 확정될 때 짧게 강조합니다. 동작 줄이기에서는 최종 화면을 바로 보여 줍니다.

## 기록과 경기 규칙

전체 대진표를 표시하려면 내 팀 이외 경기의 승자도 저장해야 합니다. 화면에서 그때그때 가상의 상대나 스코어를 만들어 넣지 않습니다. 대회 인스턴스에 참가 구단의 불변 ID·라운드·각 대진·진출자·홈/원정 차전·확정 여부를 보관하는 설계를 제안합니다. 이름은 표시 시 현재 번역·구단 별칭으로 해석하되 ID는 유지합니다.

대진 생성은 시즌/대회 시작 때 한 번만, 경기 결과는 해당 구간 진행 때 한 번만 계산합니다. 화면 열기와 재접속은 저장된 값을 읽습니다. 기존 확률식을 유지할지 상대 실제 전력으로 바꿀지는 별도 밸런스 결정입니다. 상대 이름을 표시하면서 이전 임의 상대 전력과 일치한다고 주장하지 않습니다.

## Phase 1 좁은 출시

- `SeasonComp`와 `CompGame`의 현재 패턴을 기준으로 대진 기록 모델을 설계하고, 공용 엔진에 대회 생성·진행·조회 책임을 분리합니다.
- 우선 내 팀 경로와 이름이 정해진 상대를 구현합니다. 이 단계에서는 **전체 대진표 완성**으로 안내하지 않습니다.
- 기존 대회 진행 중 저장에는 이미 치른 상대를 복원하지 않고 '이전 라운드 상세 없음'으로 표시합니다. 새 상세는 다음 대회부터 기록합니다.
- 검증: 동일 세이브에서 반복 열기·새로고침·언어 전환으로 상대와 결과가 변하지 않음, 우승/탈락 경로와 트로피가 일치함, 기존 단계 세이브가 로드됨.

## Phase 2 전체 녹아웃 대진과 검증

- 나머지 참가팀 경기 결과와 차전 승자를 저장하고 전체 녹아웃 트리를 구성합니다. 내 팀은 정확히 한 번만 출전하고 승자는 다음 라운드로 한 번만 올라갑니다.
- 검증: 라운드별 참가팀 수, 중복 대진·자기 대결 없음, 탈락 후 경기 없음, 결승 우승팀 한 팀, 경기·골·수상 집계 일치. 모바일은 세로 라운드 목록과 버튼으로 탐색하고 드래그를 강제하지 않습니다.
- [결승 결정 장면](06-final-decisive-minigame.md)의 저장 상태는 같은 대회 기록을 참조해야 합니다. 시각 대진과 경기 결정이 각각 별도 승자를 만들면 안 됩니다.

## 미확정 사항

리그 페이즈부터 참가팀 전원을 생성할지, 녹아웃 시드만 생성할지 결정해야 합니다. 구단 수·리그 이동·중복 참가·동점 승자 규칙, 전체 녹아웃 추가의 번들 비용을 검증한 뒤 일정을 산정합니다. 이 기획은 실제 UEFA 규정의 모든 세부사항을 재현한다는 약속이 아닙니다.
