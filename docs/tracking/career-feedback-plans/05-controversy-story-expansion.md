# 논란과 사생활 선택지 확장 기획

> 상태: 기획 제안 · 구현 및 운영 적용 전
> 기준: 2026-10-13 원격 main `1a67ecd7`. T-11-238의 네 기능은 별도 로컬 구현이며 이 문서 PR에 포함되지 않습니다.
> 수치·새 저장 필드·새 함수명은 구현 시 검증할 설계 후보입니다. 이 PR 병합은 기능 출시 승인이 아닙니다.

## 남은 요구와 목표

T-11-238에서 성인 프로의 단발 연애설과 세 선택지를 로컬 구현했습니다. 아직 관계를 지속해서 저장하거나 후속 상황을 만드는 시스템은 없습니다. 남은 목표는 한 번의 기사에서 끝나지 않는 선택의 후속 장면을 제공하는 것입니다.

## Phase 0 현재 기반

`packages/game/src/events.ts`의 파티와 `packages/game/src/stories.ts`의 스캔들 연쇄가 기존 기반입니다. `packages/game/src/story.ts`의 `startStory`, `advanceStory`, `schedule`, `endStory` 패턴, `event-registry.ts`의 말미 등록 규칙, `event-runner.ts`의 재등장 제한을 먼저 읽습니다. T-11-238의 `dating-event.ts`는 아직 main API로 가정하지 않습니다.

## 콘텐츠 범위

1차는 성인 프로 대상의 연애설 후속 장면 하나와 SNS 발언 논란 하나를 제안합니다. 상대는 성별을 고정하지 않은 가상의 연인으로 표현합니다. 실존 인물·특정 선수의 사생활을 사건 원형으로 쓰지 않습니다. 미성년 선수의 연애·성적 스캔들은 넣지 않습니다.

연애 자체를 잘못으로 취급하지 않습니다. 선택의 갈등은 공개 여부, 상대와의 협의, 취재 대응, 훈련 일정에 둡니다. 외모·연인의 수를 스탯/인기 보상으로 만들지 않습니다. 'WAGs'는 피드백의 소재이며 화면의 필수 용어가 아닙니다.

## 흐름과 효과

첫 장면에서 비공개·상대와 협의한 공개·경기 집중을 고릅니다. 후속 장면은 선택한 대응에 맞게 인터뷰나 취재 상황으로 이어지고 마지막에는 공개 범위가 정리됩니다. 강제 결혼·결별·자녀·실시간 메시지·연인별 수집 시스템은 제외합니다.

효과는 사기·감독 신뢰·인기·컨디션 중심으로 작게 둡니다. 파티/기존 스캔들, 부상·군 복무·결승 같은 중요한 흐름을 한 구간에 여러 개 겹쳐 보여 주지 않는 우선순위를 정합니다. 기존 스캔들 엔딩 이름은 저장 키이므로 바꾸지 않습니다.

## Phase 1 콘텐츠와 상태 설계

- 기존 `STORY_EVENTS`의 연쇄 패턴을 참고해 신규 story ID와 단계·선택 결과·종료 사유를 정의합니다. 기존 스캔들을 새 연애설로 이름만 바꿔 쓰지 않습니다.
- 필수 조건은 첫 장면뿐 아니라 예약된 후속 장면에서도 다시 검증합니다. 조건을 잃으면 무한 대기하지 않고 종료하거나 유효한 다음 구간으로 넘기는 정책을 정합니다.
- 검증: 모든 선택에서 종료까지 도달, 모순된 공개/비공개 후속 없음, 은퇴·입대·나이 변화·부상 상태에서 진행 규칙이 명확함, 대사 한·영·일 키와 선택지 수 일치.

## Phase 2 확률과 기존 기록 검증

- 새 이야기의 가중치·재등장·기존 단발 이벤트를 남길지 대체할지 결정합니다. 기존에 단발 연애설을 봤다는 이유로 이미 진행 중인 스캔들 데이터를 덮어쓰지 않습니다.
- 시뮬레이션에서 사건 빈도, 미완료 연쇄 수, 성장/LS 변화, 같은 이야기 반복률을 비교합니다. 언어별 시드 결과는 문구를 제외하면 같아야 합니다.
- 스토리·특별 이벤트 도감의 기존 스포일러 공개 규칙을 유지합니다. 전체 연애 시스템 완성으로 공지하지 않습니다.

## 미확정 사항

연애설 후속 2~3단계 중 선택, 단발 이벤트와의 관계, 다른 이벤트와 겹칠 때 우선순위, 허용 효과 상한을 정해야 합니다. 여러 사건을 무조건 늘리기보다 적은 사건의 분기 완결성을 우선합니다.
