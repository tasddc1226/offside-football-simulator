## 문제와 목표

결승도 구간 계산에 묻혀 선수의 결정적인 플레이가 체감되지 않습니다. 결승 연동 단계의 목표는 실제 출전 중인 선수에게 제한된 결승 장면을 제공하고 한 번의 입력이 그 경기의 승자를 결정하도록 하는 것입니다. 모든 결승을 반드시 승리시키는 보상 기능은 아닙니다.

## Phase 0 현재 기반과 제약

- `packages/game/src/minigame.ts`: `MgKind`, `zoneWidth`, `markerAt`, `tapOffset`, `offsetToRoll`, `MG_TIME_MS`. 기존 3초 제한과 판정 구간은 재사용 후보이며 결승에 적합한 시간은 따로 검증합니다.
- `packages/app-core/src/game-actions.ts`의 `chooseEvent`, 웹/앱 `sheets/Minigame`은 이벤트 선택의 타이밍 결과를 `resolveChoice`로 넘깁니다.
- 현재 `compsPhase`의 `tie`는 같은 호출 안에서 승패·기록을 계산합니다. 전체 `playPhase`를 다시 호출해서 결승만 재생하면 훈련·투자·경기를 중복 계산하게 됩니다.
- `CompGame`은 상대/스코어를 보유하지 않습니다. '동점 결승의 마지막 킥'을 내보내려면 이를 뒷받침하는 실제 경기 상태가 먼저 필요합니다.

### 유저 니즈와 검증 경계

확인된 요구는 사용자가 제안한 결승 터치게임과 이번 미니게임 고도화 요청입니다. 코드의 조작 중복과 포지션별 제공 차이는 구조상 사실입니다. 그 차이가 실제 불만의 원인인지, 연습·방향 판단이 재미나 접근성을 높이는지, 리텐션을 개선하는지는 가설입니다. 이용률·성공률·중단율·리텐션 개선 수치는 확인되지 않았으므로 목표 달성값처럼 만들지 않습니다. 초기 관찰과 사용자 피드백으로 가설을 검증합니다.

### A. 1차 범위: 안정화와 무보상 연습, 제치기 한 종류

- 판정·입력: 목표 구간·조작 버튼·제한 시간을 시각적으로 안내하고 사용자가 시작하는 준비 단계를 둡니다. 실패 피드백은 구간 안/밖·아까움·시간 초과부터 명확히 합니다. 현재 절대 오차만으로 early/late를 알 수 없으므로 왕복 방향과 입력 시각/경과시간을 기록·해석하는 설계 전에는 빠름/늦음으로 표시하지 않습니다.
- 중단·복귀: 타임아웃은 활성 플레이 중 제한 시간 만료, 중단은 닫기·백그라운드·프로세스 종료로 구분합니다. 중단을 자동 실패나 새 도전으로 바꾸지 않습니다. 같은 장면의 구간 중심·폭·선택·판정 규칙 버전·남은 활성 시간/방향·상태를 보존하고 준비 화면을 거쳐 재개하는 안을 우선 검토합니다. 대안은 저장된 같은 확률의 자동 판정 전환이며, 최초 입력 전에 정책을 안내하고 결과를 본 뒤 재선택할 수 없게 합니다. 채택 정책은 미결정입니다.
- 무보상 연습: 별도 진입에서 장면과 난도를 고르고 재시도·나가기를 제공합니다. 커리어의 골·도움·무실점·인기·사기·신뢰·자금·도감·트로피·LS·일일 도전 보상과 시즌 업로드에 효과를 주지 않습니다. 연습 전용 상태와 RNG를 사용하고 커리어 pending·RNG를 소비하거나 덮어쓰지 않습니다. 연습 결과는 연습 계측으로만 구분합니다.
- 조작 차별화: 제치기 한 종류에서 키퍼/수비 방향 단서를 읽고 반대 빈 공간을 고르는 좌/우 버튼 조작을 연습에서 먼저 검증합니다. 키보드 화살표와 터치 버튼은 같은 선택·시간 규칙을 사용합니다. 먼저 일관된 방향 단서와 판정 규칙을 정의하며 단순 좌우 무작위 추측으로 만들지 않습니다. 본편 반영은 연습의 이해도·입력 오류·성공률 확인 이후이며, 기존 보상표·발생 빈도는 유지합니다.
- 연출·테스트: 심리전의 상대 실축/선방 결과를 구분해 텍스트와 공 궤적을 일치시킵니다. 슛·칩슛·제치기·선방 네 종류 모두 성공/실패/경계 입력/시간 초과/중복 입력/중단/복귀/저장 실패를 검증합니다.
- 제외: 네 종류 동시 교체, 드래그 슛 본편 연결, 보상 상향, 신규 일일 도전, 실제 결승 연동은 이 단계에 넣지 않습니다. 대안은 차별화 조작을 연습에만 남기고 본편 게이지 안정화를 먼저 출시하는 것입니다.
- 통과 기준: 동일 입력의 공용 판정 일치, 입력 한 번에 결과·보상 한 번, 복귀 후 재추첨 없음, 연습 전후 커리어 상태/RNG 불변, 네 장면의 텍스트·연출 일치. 저장 실패 시 확정됐다고 안내하지 않고 같은 장면의 복구 경로를 검증합니다. 본편 전환의 정량 기준은 기준선 측정 후 정합니다.

### B. 포지션 경험 보강

A 검증 이후 MF 패스와 DF 인터셉트 또는 블록을 하나씩 추가하는 안입니다. MF는 패스 경로/받는 선수의 공간, DF는 패스 차단 경로 또는 슈팅 차단 시점을 읽는 조작 후보를 먼저 연습에서 비교합니다. 인터셉트와 블록을 모두 한 번에 구현할지 확정하지 않습니다. 기존 자동 이벤트를 단순 대체할지 새 이벤트를 만들지도 미결정이며, MF 패스 성공을 항상 도움, DF 차단 성공을 항상 무실점으로 환산하지 않습니다.

제외 범위는 포지션마다 동일 횟수·동일 보상을 강제로 보장하는 구조와 전체 경기 직접 조작입니다. 대안은 기존 포지션 이벤트에 한 종류만 연결하는 좁은 출시입니다. 검증은 포지션별 노출/선택/성공률과 시즌당 기대 보상, 출전·부상 조건, 경기 기록의 중복 여부를 비교합니다. 신규 발생 빈도·효과·보상은 검증 전 확정하지 않습니다.

### C. 직접 조작·자동 판정과 플랫폼 공정성

자동 판정은 능력 기반 확률 p, 직접 조작은 p를 반영한 구간 폭과 실제 입력에 따라 결과가 갈리므로 같은 p가 같은 실측 성공률을 뜻하지 않습니다. 동일 성공/실패에는 같은 기존 보상표를 사용하고 자동 선택에 보상 페널티를 붙이지 않습니다. 초보·숙련 직접 조작과 자동의 시즌당 기대 성과 차이를 따로 공개·검증하며 같다고 약속하지 않습니다.

시행 전 [fulltime-sim](../../../tooling/fulltime-sim/simulate.ts)의 기존 `MG=<0~1>` 성공률 노브(미지정 시 능력 기반 난수 판정)를 사용해 자동 기준과 낮은/중간/높은 직접 성공률 가정을 같은 시드·포지션·능력 구간에서 비교하는 계획입니다. 장면당 효과뿐 아니라 노출 빈도×성공률에 따른 골·도움·무실점·신뢰·인기, 우승/트로피·LS 영향을 봅니다. 결과가 과도하면 신규 조작의 본편 전환을 보류하거나 별도 밸런스 제안으로 빈도/판정 규칙을 조정합니다. MG 가정은 숙련도에 대한 민감도 분석이며 실측 이용률·성공률이 아닙니다. MG 설정 시 난수 소비 경로도 달라질 수 있으므로 동일 시드를 같은 경기 경로 보장으로 해석하지 않습니다. 이번 문서 변경에서는 게임·시뮬레이터를 실행하지 않습니다.

- 웹·iOS·Android 각각 터치/키보드 지원 범위와 입력 시각 기준을 검증합니다. 프레임 수에 따른 판정 차이, 저사양·화면 주사율·지연·안전 영역·중복 pointer/click·키 반복 입력을 점검합니다. Android #426은 회귀 검증 대상으로 유지합니다.
- 목표 구간을 색상만으로 표현하지 않고 텍스트/형태 단서를 병행합니다. 포커스·스크린리더 안내·충분한 터치 영역·동작 줄이기와 자동 판정 경로를 제공합니다. 준비 단계에서 방법을 읽을 시간을 보장합니다.
- 플랫폼·입력 방식·직접/자동·연습/커리어·규칙 버전별 성공률과 입력 오류를 비교합니다. 차이가 기기 성능이나 접근 수단에서 비롯되면 본편 확대를 보류합니다. 허용 차이·표본 규모·관찰 기간은 측정 설계에서 결정합니다.

### D. 마지막 확장: 기존 결승 설계 재사용

이 문서의 아래 결승 범위와 Phase 1/2를 마지막 확장으로 재사용합니다. 선행 조건은 [대진표](01-major-tournament-bracket.md)의 대회/경기 ID, 실제 스코어·승부차기 상태·승자·진출자 정본과 한 번만 확정되는 저장·재개입니다. 시즌 합계 무승부→승리 보정을 그대로 결승 우승 판정으로 연결하지 않습니다. 대진표의 UEFA 우선 범위와 이 문서의 국내 컵 우선 범위는 별개이므로 최초 결승 대상의 공용 경기 기록 지원을 먼저 합의합니다.

연습·일반 이벤트·실제 결승의 진입점은 구분하되 판정과 확정 경로는 공용 규칙을 사용합니다. 중단 전 훈련/비용과 이후 경기/기록을 재실행하지 않고, 승자·진출·트로피·보상은 같은 장면 ID로 한 번만 적용합니다. 승부차기 골은 공식 경기 득점에 더하지 않습니다. 실제 결승 연결 전에는 이벤트 화면을 결승 엔진 완성으로 공지하지 않습니다.

### 기존 세이브·보상·측정과 미결정 사항

기존 저장의 완료 기록·효과·RNG를 소급 변경하지 않습니다. 새 미니게임 pending이 없는 옛 이벤트 저장은 시작 정보를 복원할 수 있다고 가정하지 않고 기존 이벤트 선택 화면으로 복귀하는 후보를 검토합니다. 새 형식은 `migrateSave`·옛 저장 회귀 검증과 함께 도입하고 최소 지원 버전/구버전 앱 복원 정책을 정합니다. 장면 식별자와 미입력/진행/확정 상태, 적용 이력을 함께 저장해 이중 탭·재접속·다중 화면·확정 직후 종료로 결과/보상을 중복 적용하지 않도록 설계합니다. 저장 실패·동기화 충돌의 복구 정책도 확정 전 인수 조건입니다.

기존 보상표는 유지합니다. 성공률 상승도 보상 인플레이션을 일으킬 수 있으므로 표가 같다는 이유로 무영향이라고 판단하지 않습니다. 연습 반복 보상은 없으며, 신규 포지션 장면의 누적 효과·기존 일일 도전과의 중복 지급도 검증합니다.

기존 mg 탭 절대 오차 로그(`chooseEvent`에서 저장, [업로드 스키마](../../../packages/contracts/src/careers.ts)에 정의)와 시즌 업로드 계측을 기반으로 시작·완료·시간 초과·중단·복귀·소요 활성 시간, 장면/선택·모드·직접/자동·플랫폼·입력 방식·규칙 버전 구분을 보강하는 안입니다. 제안 필드는 아직 구현되지 않았습니다. 장면 단위 식별자로 중복 계측을 제거하고 연습은 커리어 지표에서 제외합니다. 분모는 진입 가능/노출/시작/완료를 구분하며 중단을 모두 실패로 집계하지 않습니다. 시즌 업로드만으로 시작 후 이탈을 관찰할 수 없으므로 기존 수집 경로의 전송 시점·보관 범위도 설계합니다. 매 프레임 서버 요청이나 화면 진입별 재조회는 추가하지 않습니다.

미결정: 적용 시즌·최초 출시 버전, 타이머 재개/자동 전환 정책, `pk-save` 부상 조건 의도, 제치기의 방향 단서와 난도, MF/DF 장면의 기존 이벤트 대체 여부·발생 빈도·보상, 직접/자동 기대 성과의 허용 차이, 플랫폼별 관찰 표본·기간·출시/보류 기준, 계측 스키마·수집 경로·보관 정책, 구버전 복구 정책, 최초 대상 컵입니다. 모두 제안 또는 미결정으로 남기며 이 문서가 규칙 확정·구현·배포를 뜻하지 않습니다.

## 기존 결승 연동의 첫 출시 범위

클럽 국내 컵 결승 한 종류부터 적용하고, UEFA 결승·국가대표·구단주 컵은 후속으로 둡니다. 실제 출전 시간이 있는 선수만 참여합니다. 부상 결장·벤치 미출전은 자동 결과를 보여 줍니다. 같은 구간에 여러 결승이 있으면 한 장면씩 직렬로 처리합니다.

장면은 두 후보 중 하나로 좁힙니다. 필드 선수는 동점 상황의 마지막 승부차기 킥, GK는 성공하면 우승이 확정되는 상대 마지막 킥 선방입니다. GK의 선방 한 번을 맥락 없이 팀 우승으로 바꾸지 않습니다. 경기 중 결승골 장면은 분·스코어·득점 기록 지원 이후 확장합니다.

## 사용자 흐름과 접근성

결승 안내 → 내 출전/현재 승부 상황 → 직접 플레이 또는 자동 판정 선택 → 한 번의 입력 → 결과 확정 → 중계/결산 계속 순서입니다. 자동 판정은 같은 공개 능력 기반 확률을 쓰고 보상을 낮추지 않습니다. 동작 줄이기에서 강제로 시간제한 조작을 요구하지 않습니다. 키보드·터치 모두 지원하고 입력 버튼은 하단 안전 영역 안에 둡니다.

## 저장과 원자적 확정

대회/경기 ID, 장면 ID, 판정 확률, 직전 스코어/승부차기 상태, 출전 정보, 미입력/확정 상태, 이후 실행할 구간 작업을 저장하는 새 pending 모델을 제안합니다. 장면을 보여 주기 전에 저장하고 복귀 시 같은 장면을 이어갑니다.

승부와 기록 갱신을 한 공용 확정 함수에서 한 번만 실행합니다. 이미 확정된 장면의 중복 탭·재열기·복원은 기록을 더하지 않습니다. 승부차기 골은 공식 경기 득점으로 더하지 않습니다. 일반 경기 결승골을 나중에 지원하면 경기/대회/시즌 득점을 정확히 한 번 갱신합니다.

## Phase 1 엔진 중단과 재개

- `playPhase`의 기존 훈련→투자→경기→이벤트 순서를 읽고, 결승 직전 중단과 이후 재개를 명시적인 상태 기계로 설계합니다. 현재 함수에 있다고 가정한 pause API를 호출하지 않습니다.
- 비대화형 시뮬레이터도 같은 장면 확정 경로를 자동 판정으로 통과해야 합니다.
- 검증: 중단 전 비용/훈련은 한 번, 확정 후 경기/상/나이 증가는 한 번, 자동 판정과 손입력 판정이 같은 승자/기록 경로 사용, 여러 결승 순서 유지.

## Phase 2 화면과 결과 검증

- 기존 미니게임의 바늘·타이밍 판정/동작 줄이기 패턴을 참고하되 결승 상황은 엔진의 저장 상태를 그대로 표시합니다.
- 성공·실패·시간 초과·자동 선택·닫기/백그라운드·저장 실패·재접속·중복 탭을 검증합니다. 백그라운드 동안 입력 시간을 계속 흘려 강제 실패시키는 방식은 제외하는 방향을 제안합니다.
- 숙련자가 거의 항상 성공할 때의 우승률·트로피·LS 증가를 포지션별로 시뮬레이션합니다. 장면 발생 빈도/성공 구간을 조정한 뒤 주요 대회로 확대합니다.

## 미확정 사항

최초 대상 컵, 장면 발생 빈도, 자동 판정 전환·타이머 재개 정책, 성공 숙련도의 허용 우승률 차이, 골 기록을 다루는 확장 범위를 정해야 합니다. [대진표](01-major-tournament-bracket.md)와 경기 ID/승자 정본을 공유합니다.
