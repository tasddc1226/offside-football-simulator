# 선호 구단과 역오퍼 기획

> 상태: 기획 제안 · 구현 및 운영 적용 전
> 기준: 2026-10-13 원격 main `1a67ecd7`. T-11-238의 네 기능은 별도 로컬 구현이며 이 문서 PR에 포함되지 않습니다.
> 수치·새 저장 필드·새 함수명은 구현 시 검증할 설계 후보입니다. 이 PR 병합은 기능 출시 승인이 아닙니다.

## 문제와 목표

임의로 오는 제안을 기다리는 것 외에 선수가 가고 싶은 구단에 관심을 표현할 수 있게 합니다. 선호 구단을 고르는 기능과 실제 입단 제안을 얻는 기능은 구분합니다. 선호 지정만으로 항상 이적이 성사되지는 않습니다.

## Phase 0 현재 기반

`packages/game/src/season.ts`의 `makeOffers`, `offerFrom`, `bestEuropeClub`과 `events.ts`의 스카우트/에이전트/이적설 플래그를 읽습니다. `makeOffers`의 OVR·최근 평점·인기·나이·리그/아마추어 자격과 군 복무 제한을 우회하지 않습니다. 시장 옵션은 `GameState.pending`에 저장되므로 재열기마다 새 시장을 만들지 않습니다.

## 첫 출시 범위

커리어에 선호 구단 한 곳을 지정하고 이적 시장마다 한 곳에 관심 요청을 보냅니다. 선호 구단은 실제 고용 제안을 자동 생성하는 권리가 아닙니다. 진행 중 시장에서 구단을 바꿔 계속 지원하거나 요청 횟수를 초기화하지 않습니다. 동시에 여러 구단·에이전트 수수료·시즌 중 즉시 이적은 제외합니다.

## 사용자 흐름

1. 선수/커리어에서 구단 검색으로 선호 구단을 선택합니다. 긴 목록은 국가·리그로 좁히고 현재 소속도 명확히 구분합니다.
2. 이적 시장을 열면 선호 구단의 리그·전력·예상 출전 역할과 지원 가능/불가능 이유를 봅니다.
3. 지원 확인 후 한 번 판정하고 '제안 도착' 또는 '이번 시장 관심 없음'을 저장합니다. 거절이 다른 구단의 기존 제안을 취소하지 않습니다.
4. 성공하면 기존 `offerFrom` 규칙으로 만든 제안을 목록에 추가합니다. 계약서 사인 전에는 소속이 바뀌지 않습니다.

## 자격과 판정

현재 구단·아마추어 대상·복무 중 지원·강제 은퇴 시점은 제외합니다. 기본 `makeOffers`의 자격 후보 판정을 공용 함수로 분리하는 안을 검토합니다. 현재의 전체 무작위 선택 풀을 그대로 지원 제한으로 쓸지는 별도 검증합니다. 인기만 높다고 높은 리그의 입단 조건을 무시하지 않습니다.

첫 버전은 기본 제안 자격을 만족하는 구단에만 지원하는 방향입니다. 해당 구단에 이미 제안이 있으면 '이미 제안 도착'으로 안내하고 중복 제안을 만들지 않습니다. 선호 구단으로 인해 다른 제안을 무조건 줄이지 않습니다.

## 저장과 계약

불변 club ID, 선호 지정, 시장 식별자, 지원 대상, 미시도/제안/거절 결과를 저장하는 후보입니다. 지원 시 RNG 결과와 생성 제안을 저장하고 그 뒤 화면에 표시합니다. 구단 이름 변경·리그 승강에도 ID로 추적합니다. 은퇴/새 선수 시작에서 선호가 자동 이전될지 여부는 UI 편의와 게임 상태를 구분해 결정합니다.

옛 저장에는 선호 없음·지원 이력 없음으로 추가합니다. 이미 열린 시장의 기본 제안은 유지합니다. 오래된 앱이 새 지원 상태를 지워 재시도할 수 없도록 저장 복원/최소 버전 정책을 검토합니다.

## Phase 1 관심 요청과 저장

- `offerFrom`의 계약 생성과 `acceptOption`의 계약 확정을 재사용합니다. 새 서버 역오퍼 API나 실시간 구단 응답을 만들지 않습니다.
- 기존 에이전트·스카우트 제안과 지원 제안은 같은 club ID 기준으로 중복 제거합니다.
- 검증: 성공/거절/자격미달/이미제안/소속구단, 승강·구단별칭·복무·베테랑, 재접속/중복탭으로 지원 추가 없음.

## Phase 2 진행과 분포 검증

- 매번 최강 구단 지원 정책과 무지원 정책을 같은 시드로 비교합니다. 프로 데뷔·유럽 진출 나이, 구단 이동 횟수, 평균 연봉, 최고 OVR·LS를 봅니다.
- [연봉협상](03-salary-negotiation.md)과 동시에 사용할 때 제안 생성·협상·사인 순서를 확인합니다. [이적 정보](10-transfer-club-information.md)도 동일 제안을 표시해야 합니다.
- 지원 성공 확률과 기존 제안 수 상한은 결과를 보고 정합니다. 선택하지 않은 사용자도 기존 진행을 유지합니다.

## 미확정 사항

선호 구단 선택 시점, 연간 시장 횟수 기준, 지원 승인 확률/전력 문턱, 기본 제안 수 제한과의 관계, 다른 새 커리어로 선호 이전을 정해야 합니다.
