# 이적 구단 실제 순위와 대회 정보 확장 기획

> 상태: 기획 제안 · 구현 및 운영 적용 전
> 기준: 2026-10-13 원격 main `1a67ecd7`. T-11-238의 네 기능은 별도 로컬 구현이며 이 문서 PR에 포함되지 않습니다.
> 수치·새 저장 필드·새 함수명은 구현 시 검증할 설계 후보입니다. 이 PR 병합은 기능 출시 승인이 아닙니다.

## 반영된 부분과 남은 차이

T-11-238은 제안 구단의 전력으로 계산한 예상 리그 순위와 이적 후 첫 시즌 대륙 대회를 로컬 구현했습니다. 다른 모든 리그의 현재 실제 순위를 저장·진행하는 기능은 아닙니다. 남은 요구는 '현재 몇 위인 팀인가'를 실제 경기 세계의 기록으로 보여 주는 것입니다.

## Phase 0 현재 기반

- `packages/game/src/table.ts`의 `leagueTable`, `teamRank`, `finalRank`, `seasonLeagueId`는 현재 선수 시즌의 상대/승점으로 순위를 만듭니다. 모든 리그의 독립적인 실제 테이블이 아닙니다.
- `packages/game/src/comps.ts`의 `expectedRank`, `seasonSetup`, `CONT_SLOTS`는 같은 구단 잔류 시 지난 기록을, 새 구단 첫 시즌에는 전력 기준 예상 순위를 사용합니다.
- T-11-238의 `transferOutlook`·`continentalForRank`와 화면의 '예상' 문구는 로컬 구현 상태입니다. 기획 PR만 병합한 main에서 사용 가능하다고 가정하지 않습니다.

## 권장하는 단계

1차 출시에는 이미 만든 **예상 정보**를 사용하고, 시즌 중 다른 리그의 실제 현재 순위는 별도의 월드 시뮬레이션으로 분리합니다. 실제 데이터가 없는 구단에 '현재 3위'를 임의로 붙이지 않습니다.

우선 현재 소속 리그의 제안 구단만 기존 순위표에서 확인할 수 있는 경우 '이번 시즌 N위'를 추가하는 좁은 안을 검토합니다. 시즌 결산 이후에는 '지난 시즌' 또는 해당 연도를 함께 표시합니다. 같은 화면의 예상 순위·다음 시즌 참가 대회와 섞지 않습니다.

## 실제 순위의 정본과 대회 자격

모든 리그를 지원하려면 커리어별 시즌·리그·구단·경기 수·승점·승자 기준의 테이블을 한 번 생성하고 구간마다 진행해야 합니다. 화면 열기에서 추첨하지 않으며 외부 현실 축구 순위를 게임 속 2030년 구단 순위처럼 쓰지 않습니다.

월드 순위를 대륙 대회 자격에 연결하면 현재 새 구단의 `expectedRank` 규칙이 달라지는 **게임 규칙 변경**입니다. 단순 표시 PR에서 자격까지 바꾸지 않습니다. 새 세계 상태를 사용하는 커리어와 구버전 커리어의 정책을 버전으로 구분하는 설계가 필요합니다.

## Phase 1 같은 리그의 확인 가능한 순위

- 기존 `season.finalTable`/`leagueTable`에서 club ID가 확인되는 제안에만 시즌 연도·경기 수와 함께 순위를 표시합니다. 상대 수가 잘린 리그나 옛 저장에서 해당 구단이 없으면 '순위 정보 없음'을 보여 줍니다.
- 다른 리그는 전력 기준 예상 정보를 유지합니다. 실제 순위가 있다는 이유만으로 새 구단 참가 대회를 다른 계산으로 바꾸지 않습니다.
- 검증: 시즌 시작 전/진행 중/종료 후, 승강 직후 `seasonLeagueId`와 실제 제안 리그, 30팀 리그의 표시 대상 부족, 구단명 변경, 순위와 대회 예상 라벨 구분.

## Phase 2 전 리그 세계 상태

- 로컬 저장 크기·한 구간 계산 시간·RNG 흐름·구단 전력 버전을 포함해 별도 설계를 먼저 확정합니다. 대륙 대회 대진도 이 테이블과 같은 구단 ID를 사용해야 합니다.
- 이미 끝난 다른 리그 시즌을 옛 저장에 사실처럼 소급 생성하지 않습니다. 도입 후 첫 완전 시즌부터 기록하거나 구버전 경로를 유지합니다.
- 검증: 한 리그에서 중복/누락 구단 없음, 승점·경기 수·승강 일치, UI 열기/언어 변경에 따른 결과 변화 없음, 오래된 앱에서 복원 가능한 정책, 대회 자격 변경 전후 분포.

## 미확정 사항

사용자가 원하는 현재 순위의 기준 시점, 같은 리그 좁은 출시의 가치, 전 리그 시뮬레이션 범위와 비용, 도입 시즌/버전, 실제 순위를 참가 자격의 정본으로 바꿀지 여부를 정해야 합니다. 실순위가 반드시 필요하지 않다면 1차 예상 정보만 유지하는 선택도 가능합니다.

- 320px·390px 모바일에서 긴 구단명·선수명, 터치 조작, 하단 버튼 가림, 가로 넘침을 확인합니다. 앱 변경은 iOS·Android 실행 환경에서 별도로 확인합니다.
- 저장 필드가 늘면 `packages/game/src/save.ts`의 `migrateSave`와 옛 저장 회귀 테스트를 함께 냅니다. 새 필드가 없다는 이유로 진행 중인 결정을 다시 추첨하지 않습니다.
- 규칙·확률 변화는 동일 시드의 변경 전후 시뮬레이션과 포지션별 분포로 검증합니다. 기존 수상·엔딩·구단 ID 같은 저장 키를 문구처럼 바꾸지 않습니다.
- 기기에서 계산 가능한 정보는 서버에 요청하지 않습니다. 서버 읽기가 필요한 경우 화면 열기 시 캐시 조회하고 N+1·폴링을 추가하지 않습니다.
- 출시 PR에는 릴리즈 노트와 공개 가이드·FAQ 변경을 포함합니다. 로컬·CI·스토어·OTA·실기기·운영 검증을 구분합니다.
