# 연봉과 재계약 협상 기획

> 상태: 기획 제안 · 구현 및 운영 적용 전
> 기준: 2026-10-13 원격 main `1a67ecd7`. T-11-238의 네 기능은 별도 로컬 구현이며 이 문서 PR에 포함되지 않습니다.
> 수치·새 저장 필드·새 함수명은 구현 시 검증할 설계 후보입니다. 이 PR 병합은 기능 출시 승인이 아닙니다.

## 문제와 목표

현재 제안된 연봉·계약 기간을 수락하거나 다른 행선지를 선택할 수 있지만 선수 쪽에서 조건을 다시 요청할 수는 없습니다. 첫 단계는 기존 제안을 유지하면서 연봉 한 항목에만 협상 기회를 추가하는 것입니다.

## Phase 0 현재 구조와 기반

- `packages/game/src/season.ts`: `makeOffers`, `offerFrom`, `renewalSalary`, `canAcceptRenewal`, `acceptOption`.
- `packages/game/src/types.ts`: `Contract`, `OfferOption`, `RenewOption`, `MarketResult`, `Pending`.
- `packages/app-core/src/game-actions.ts`: `showMarket`, `showContract`, `signContract`. 기존 계약서 사인 뒤 확정하는 순서를 유지합니다.
- `packages/game/src/earlyRenewal.test.ts`는 잔여 1년과 추가 기간을 구분하는 연장 계약의 회귀 기준입니다. 아카이브의 서버 커리어 협상 액션을 현행 API로 사용하지 않습니다.

## 제안 범위

프로 이적 제안과 정식 재계약에서 **제안별 한 번의 연봉 인상 요청**을 제공합니다. 고교·대학·입단 테스트·군 복무·강제 은퇴는 제외하고 기존 계약의 중도 인상은 후속 단계로 둡니다. 계약 기간·이적료·출전 보장은 협상하지 않습니다.

## 사용자 흐름과 결과

1. 제안 카드에서 계약서를 열면 원래 연봉과 인상 요청 버튼을 함께 봅니다.
2. 요청 전 인상 폭, 실패해도 원래 제안이 유지된다는 점, 한 번만 요청할 수 있다는 점을 알립니다.
3. 요청 결과를 저장한 뒤 승인된 연봉 또는 원래 연봉을 보여 줍니다. 여기서 계약은 아직 확정되지 않습니다.
4. 사용자가 사인해야 `acceptOption`으로 정착합니다. 계약서 닫기는 협상 결과를 취소하거나 다시 굴리는 행동이 아닙니다.

첫 버전의 거절은 원래 제안을 철회하지 않는 방향을 제안합니다. 협상 때문에 모든 제안이 사라지는 기능은 추가하지 않습니다. 조기 연장은 기존 잔여 1년·추가 기간 규칙과 검증을 그대로 통과해야 합니다.

## 저장과 경제 경계

제안 ID, 기준 연봉, 요청 조건, 미시도/승인/거절 상태, 최종 연봉을 시장의 저장된 제안에 연결하는 설계 후보입니다. 요청 결과와 RNG 상태는 UI 결과 공개 전에 함께 저장합니다. 재열기·재접속·빠른 중복 탭으로 여러 번 요청하거나 연봉을 중첩해 올릴 수 없어야 합니다.

옛 제안은 최초 한 번의 요청이 가능한 상태로 읽되 기존 연봉·계약 기간을 덮어쓰지 않습니다. 이미 사인한 계약에는 이 제안 상태를 붙여 재협상을 열지 않습니다. 선수 자금(`GameState.money`)과 구단주 자금을 섞지 않습니다.

## Phase 1 연봉 한 항목

- `offerFrom`과 `renewalSalary`의 기본 제안 계산은 보존하고 별도 협상 결과를 붙입니다. `showContract` 패턴에서 요청·결과·사인을 구분합니다.
- 인상 폭은 기준 연봉의 일정 비율, 승인 가능성은 기량/최근 활약/구단 전력 차와 계약 상황으로 계산하는 후보입니다. 상세 계수·상한은 실험 후 확정하며 운영 수치로 간주하지 않습니다.
- 검증: 승인·거절·원래 조건 수락·다른 제안 선택·조기 연장·베테랑·입단 테스트 제외, 요청 중 종료와 저장 실패 후 재개, 한 제안에 한 번만 판정.

## Phase 2 경제 검증과 출시

- 기본 수락 정책과 매번 인상 요청 정책을 같은 시드로 비교합니다. 평생 선수 수입, 자기 투자 횟수, 잠재력 강화, 최고 OVR·LS 분포를 포지션·리그·나이별로 봅니다.
- 연봉을 기준으로 비용이 커지는 기존 기능도 함께 확인합니다. 수입 증가만 보고 성장 이득을 단정하지 않습니다.
- 과도한 이득이면 인상 폭·승인률을 줄인 뒤 다시 검증합니다. 협상을 하지 않아도 기존 계약 경로로 커리어가 끝까지 진행돼야 합니다.

## 미확정 사항

초기 인상 폭 후보, 승인 확률·상한, 첫 프로 입단 포함 여부, 에이전트와 협상 효과의 중복을 확정해야 합니다. 기간·출전 조건까지 확대하는 다변수 협상은 1차 출시 대상이 아닙니다.
