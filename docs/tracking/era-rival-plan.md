# 시대의 라이벌 기획 (초안)

T-11-475. 2026-10-23 초안, 같은 날 1단계(엔진 · 결산 카드 · 트로피 탭 카드 · 가이드)를 구현했다. 2 · 3단계는 사용 데이터를 보고 정한다.

> 내 선수와 같은 시대를 사는 라이벌 한 명이 커리어 내내 따로 성장하고, 시즌마다 기록·수상·OVR을 나란히 비교한다.
> 발롱도르를 누가 가져갔는지, 은퇴할 때 누가 더 위대했는지가 커리어의 두 번째 축이 된다.

원작(slbcareer)도 비슷한 기능을 10-14에 냈다. 아이디어만 참고하고 문구·수치·조건·화면은 가져오지 않는다.
축구에 맞게 "같은 해에 떠오른 또래 괴물과 발롱도르를 다투는 이야기"로 다시 짠다.

## 한 줄 요약

지금 있는 이야기 이벤트 **평생의 라이벌**(`stories.ts` rival-1~3)은 이름만 있는 상대다. 이 라이벌에게 **능력치·소속·시즌 기록·수상**을
붙여 기기 안에서 같이 시뮬레이션하고, 결산·커리어 탭·은퇴 리포트에서 나란히 비교한다. 1단계는 **내 선수의 결과를 하나도 바꾸지 않는다**
(별도 RNG, 내 수상은 지금 규칙 그대로). 보상(칭호·레전드 점수)은 2단계에서 시뮬레이션을 보고 정한다.

## 지금 상태

- **이야기 이벤트 `rival`:** 24세 이하 프로 선수에게 가중치 2로 뜬다. 맞대결(rival-2)·대표팀 자리(rival-3) 3단계로 끝나고 엔딩 4개
  (끝내 넘어선 벽 · 영원한 2인자 · 라이벌에서 동료로 · 어색한 휴전)가 숨김 칭호다. 라이벌은 `flags.rivalName` 문자열 하나뿐이고 기록이 없다.
- **이름:** `rival-names.ts`가 처음 나타난 리그의 나라(일본·미국·네덜란드·프랑스·독일·이탈리아·스페인·잉글랜드, 그 밖은 한국)로
  성·이름을 뽑고 한국어로 저장한 뒤 그릴 때 영어·일본어로 옮긴다. 시대의 라이벌도 이 이름을 그대로 쓴다.
- **수상:** `comps.ts` `seasonAwards()`는 경쟁자 없이 기준선(`TOP_G`·`BALLON_BAR` + 가우스 잡음)만 본다. 발롱도르 순위도 내 점수로만 정한다.
  즉 "누가 나를 이겼는지"는 지금 화면에 없다. 라이벌이 그 빈자리를 채울 수 있다.
- **독립 RNG 선례:** `manager.ts`는 `createRng(hashStr(...))`로 게임 RNG와 따로 노는 난수원을 쓴다. 시대의 라이벌도 이 방식이면
  게임 RNG 소비 순서가 바뀌지 않는다.

## 원칙

- **내 커리어 결과는 그대로.** 라이벌 시뮬레이션은 `createRng(hashStr(`${seed}:era:${year}`))` 같은 별도 난수원으로만 돈다.
  내 능력치·수상·레전드 점수·RNG 시퀀스는 라이벌이 있든 없든 같다(1단계). 골든 테스트는 `era` 필드를 뺀 해시가 같은지로 확인한다.
- **라이벌은 내 결과와 어긋나지 않게 그린다.** 한 명만 받는 상(발롱도르·같은 리그 득점왕·리그 올해의 선수)은 내가 받았으면 라이벌은 못 받는다.
  내가 못 받았고 라이벌 점수가 기준을 넘으면 라이벌이 받는다. 발롱도르 순위는 같은 칸을 겹치지 않는다.
  "발롱도르 2위, 1위는 라이벌"이 이 기능의 대표 장면이다.
- **서버 비용 0.** 1·2단계는 전부 `packages/game` 안에서 끝난다. 서버는 3단계에서 은퇴 스냅샷에 요약 몇 칸만 더 받는다.
- **언어가 결과를 바꾸지 않는다.** 이름은 한국어로 저장하고 그릴 때 옮긴다(지금 `rivalName`과 같다).

## 1. 라이벌이 나타나는 때

시즌 결산(`endSeason`) 끝에서 아래를 모두 만족하면 그 시즌 결산에 **"시대의 라이벌 등장"** 카드가 붙는다. 한 커리어에 동시에 한 명.

| 조건 | 초안                                                                                      |
| ---- | ----------------------------------------------------------------------------------------- |
| 나이 | 25세 이하                                                                                 |
| 무대 | 프로 1부(아마추어·대학·K리그2 제외)                                                       |
| 계기 | 이번 시즌 개인상 하나 이상, 또는 OVR이 같은 나이 기대치보다 높음, 또는 발롱도르 30인 후보 |
| 확률 | 계기를 만족한 시즌마다 라이벌 RNG로 굴린다(첫 기회에 꼭 뜨지는 않게)                      |

이미 이야기 이벤트 `rival`로 라이벌 이름이 생긴 커리어는 **그 사람이 그대로 시대의 라이벌이 된다**(`flags.rivalName` 재사용).
이야기 이벤트의 맞대결·대표팀 자리 결과(gap)는 라이벌 첫 능력치에 조금 반영한다. 거꾸로 시대의 라이벌이 먼저 생긴 커리어에서
이야기 이벤트가 뜨면 같은 사람으로 나온다. 엔딩 문자열·칭호 키는 건드리지 않는다(세이브 저장값).

### 세대교체

라이벌은 "평생" 한 명이 기본이다. 다만 라이벌이 크게 처지면(내 OVR이 라이벌보다 8 이상 높은 시즌이 2번 연속) 은퇴·부진 기사와 함께
**새 라이벌**(나보다 3~5살 어린 신예)이 나타날 수 있다. 한 커리어 최대 3명. 지나간 라이벌은 기록과 함께 남는다.
원작처럼 "더 센 선수가 나타나면 바로 교체"는 하지 않는다. 한 사람과 오래 다투는 쪽이 이야기로 남는다.

## 2. 라이벌 만들기

| 항목         | 정하는 법                                                                                                       |
| ------------ | --------------------------------------------------------------------------------------------------------------- |
| 이름         | `rivalName()` 그대로(나라 = 그 시즌 리그)                                                                       |
| 국적         | 이름 나라. 한국 이름이면 대한민국(같은 대표팀 자리를 두고 다툼)                                                 |
| 포지션       | 내 큰 포지션과 같다. 세부 포지션은 같은 큰 포지션 안에서 라이벌 RNG로                                           |
| 나이         | 나와 같거나 ±1                                                                                                  |
| OVR · 잠재력 | 지금 내 OVR ± 2, 잠재력은 내 잠재력 근처(± 4)에서 뽑는다. 나보다 조금 위에서 시작할 확률을 더 준다(쫓아가는 맛) |
| 성장 특성    | 조기 성장 · 보통 · 대기만성 중 하나(나이 커브만 쓴다)                                                           |
| 소속         | OVR에 맞는 1부 구단(라이벌 이름 나라의 리그가 우선)                                                             |

`GameState`에 선택 필드를 더한다.

```ts
era?: {
  cur: EraRival;            // 지금 라이벌
  past?: EraRival[];        // 세대교체로 지나간 라이벌
};
EraRival {
  name: string;             // 한국어 저장값(rivalName과 같은 규칙)
  nation: string; pos: Pos; dpos?: DetailPos;
  born: number;             // 출생 연도(나이 = year - born)
  ovr: number; pot: number; curve: 'early' | 'normal' | 'late';
  clubId: string; leagueId: string;
  since: number;            // 등장 연도
  seasons: EraSeason[];     // 시즌마다 한 줄(아래)
  h2h?: { w: number; d: number; l: number; g: number; rg: number };  // 맞대결 합계
  retired?: number;         // 은퇴 연도
}
EraSeason { year, clubId, league, apps, goals, assists, cs, rating, ovr, honors: string[], ballon?: number }
```

선택 필드라 `migrateSave`에서 채울 것은 없다. 옛 세이브는 다음 결산부터 등장 조건을 본다. 세이브 버전을 올리지 않아도 되지만,
`save.test.ts`에 `era`가 있는 세이브·없는 세이브 왕복 사례를 더한다.

## 3. 라이벌 한 시즌 시뮬레이션

내 시즌 결산 직후, 같은 연도로 한 번 돈다(라이벌 RNG만 쓴다).

1. **성장:** 나이 커브(특성별 정점·노쇠 나이는 내 선수와 같은 표)로 OVR을 잠재력 쪽으로 움직이고 잡음을 더한다. 경기 엔진은 돌리지 않는다.
2. **이적:** OVR이 구단 전력보다 크게 높으면 더 강한 구단으로 옮긴다(시즌 간 최대 한 번). 5대 리그 쏠림은 내 이적 시장 규칙을 간단히 흉내 낸다.
3. **기록:** 리그 경기 수 × 출전 비율(OVR − 구단 전력)로 출전을 정하고, 골·도움·무실점·평점은 포지션 가중과 리그 등급으로 뽑는다.
   분포는 시뮬레이터로 "같은 OVR의 내 선수"와 비슷하게 맞춘다(수치는 시뮬 결과로 정하고 문서에 옮기지 않는다).
4. **수상:** `seasonAwards()`의 점수 모양(OVR·골·도움·평점·리그 등급·팀 순위)을 라이벌에게 그대로 적용한 함수로 후보 점수를 낸다.
   그 다음 원칙대로 내 결과와 맞춘다.
   - 발롱도르: 내가 1위면 라이벌은 2위 이하. 내가 k위면 라이벌 점수가 나보다 높을 때만 k보다 위, 같은 칸은 피한다.
   - 같은 리그 득점왕·올해의 선수: 내가 받았으면 라이벌은 못 받는다.
   - 다른 리그의 상: 라이벌 리그 기준선으로 따로 본다.
5. **국가대표:** 국적이 같으면 대표팀 출전·캡을 내 대표팀 기록과 겹치지 않게 그린다(주전 자리 하나를 두고 다툼).
   국적이 다르면 월드컵·대륙 대회에서 만난 경우만 적는다.
6. **은퇴:** 라이벌도 은퇴 나이(내 `retireAt` 근처 ± 2)에서 은퇴한다. 내가 먼저 은퇴하면 라이벌의 이후 시즌은 돌리지 않는다.

## 4. 맞대결

라이벌 구단이 내 리그에 있으면 시즌 상대 목록(`S.opp`)에 그 구단이 이미 있다. 그 경기를 **라이벌 매치**로 표시한다.

- 경기 결과는 지금 엔진 그대로다. 라이벌의 골·도움만 라이벌 RNG로 그 경기 줄에 덧붙인다(내 결과를 바꾸지 않는다).
- 경기 기록 줄에 "라이벌 ○○ 1골" 같은 한 줄을 더하고, 시즌 합계는 `h2h`에 쌓는다.
- 대륙 대회·컵·대표팀 경기에서 만나면 결산 노트에만 적는다(1단계).

결정적 순간(`moments.ts`)·이야기 이벤트 `rival-2`가 라이벌 매치에서 뜨면 라이벌 이름을 넣는다. 확률·결과는 지금 그대로다.

## 6. 보상 (2단계, 시뮬레이션으로 결정)

1단계는 보상이 없다. 비교만으로 동기가 생기는지 먼저 본다. 2단계 후보:

- **칭호:** "시대의 주인공"(은퇴 때 발롱도르·주요 수상 수가 라이벌보다 많음), "숙적"(라이벌 매치 통산 ○승), "세대교체"(새 라이벌까지 넘어섬).
  `titles.ts`에 더한다. 숨김 여부는 이야기 칭호와 같이 정한다.
- **인기(fame):** 라이벌보다 높은 발롱 순위·라이벌 매치 승리에 작은 인기. 인기는 결과에 거의 영향이 없어 1단계에 같이 넣어도 된다.
- **레전드 점수:** 원작은 라이벌을 이긴 수상에 가산을 줬다. 우리는 레전드 점수가 명예의 전당 순위·카드 기준가와 이어져 있어
  라이벌이 있는 커리어와 없는 커리어 사이 형평이 깨진다. 넣는다면 작은 상한이 있는 항(`legendTermsOfRecord`에 새 항)으로,
  서버 밸런스 키(`eraBonus`, 기본 0)로 열고 `fulltime-sim`으로 분포를 본 뒤 정한다. 추천은 **넣지 않거나 아주 작게**.

## 7. 서버 · 공개 화면 (3단계)

- 은퇴 스냅샷(`legendSnapshot`, 계약 `LegendSnapshotSchema`)에 라이벌 요약(이름·국적·포지션·통산·발롱 수·맞대결 합계)을 선택 필드로 더한다.
  명예의 전당 상세에서 "시대의 라이벌" 한 줄을 보여 준다. 요청 수는 늘지 않는다(이미 받는 스냅샷에 실린다).
- 라이벌은 가상 인물이라 이름 노출 문제는 없다. 내 선수 이름은 지금처럼 스냅샷에 넣지 않는다.
- 이후 아이디어: 라운지 공유 카드("나 vs 라이벌"), 같은 시즌 다른 유저 선수를 라이벌로 잇기(서버 매칭이 필요해 비용이 커서 보류).

## 8. 밸런스 · 테스트

- 서버 밸런스 키 `eraRival`(0/1, 기본 1)로 켜고 끈다. 끄면(운영 도구에서 버전으로, 진행 중 커리어는 다음 시즌부터) 지금과 완전히 같다.
  켜 둔 기본값에서는 골든 · 특성화 스냅샷의 상태 해시만 바뀌고(라이벌 필드가 생긴다), `era`를 뺀 상태는 꺼졌을 때와 같다(`era.test.ts`).
- 켠 상태 테스트: `era`를 뺀 최종 상태 해시가 꺼진 상태와 같은지(내 결과 불변) 고정 시드 32개로 확인한다.
