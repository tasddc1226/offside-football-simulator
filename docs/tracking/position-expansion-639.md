# 시즌 1 포지션 확장 (#639)

신규 선수는 GK, CB, LB, RB, LWB, RWB, SW, DM, CM, AM, LM, RM, ST, CF, SS, LW, RW 중에서 선택한다. CDM/CAM은 DM/AM으로 통일한다. 과거 FB/W 선수는 방향을 추정해 바꾸지 않으며 기록 필터에도 남긴다.

## 수치 기준

| 신규 포지션   | 재사용하는 기존 역할 |
| ------------- | -------------------- |
| LB/RB/LWB/RWB | FB                   |
| SW            | CB                   |
| LM/RM         | CM                   |
| CF/SS         | ST                   |
| LW/RW         | W                    |

신규 포지션에 별도 보너스를 만들지 않는다. 시작 분포, OVR, 성장 가중, 골/도움 비율, 레전드 점수, 팀 경기 가중은 위 기준을 공유한다. LM/RM도 CM의 경기 장악 점수를 사용한다. 포지션 수집 업적은 기존 8개 역할의 중복 없는 수를 세어 기존 달성과 목표를 유지한다.

## 팀 배치

선수 고유 포지션과 팀의 경기 포지션을 구분한다. 웹/앱에서 배치를 옮길 때와 시즌 1 이상 팀을 저장할 때 좌표로 경기 포지션을 정한다. 과거 팀 배치와 선수 원본은 자동 덮어쓰지 않는다. 프리시즌 저장은 기존 방식을 유지한다.

공격 방향은 위쪽이다. 중앙의 y 구간은 ST(<20), CF(<28), SS(<34), AM(<43), CM(<56), DM(<67), CB(<79), SW(79~82)다. 측면은 LW/RW(<43), LM/RM(<56), LWB/RWB(<67), LB/RB다. 중앙 미드필더 프리셋 x=25/75는 중앙 역할을 유지한다. 세로 경계를 넘는 배치 변경은 역할별 실력과 팀 전력에 영향을 줄 수 있다.

기존 8개 역할만 든 peakProfile은 그대로 허용한다. 새 슬롯의 값이 없으면 대응하는 기존 역할 값을 읽으므로 NaN이나 선수 실력 소실이 없다. 저장 형식 버전은 유지하고, 기존 FB/W 및 peakProfile 보존을 save 복원 테스트로 검증한다.

## 배포 순서

새 포지션을 받는 API를 먼저 배포한 뒤 웹과 앱을 배포한다. 구버전 앱의 닫힌 포지션 enum은 신규 선수 기록을 읽지 못할 수 있으므로 배포 시 지원 중인 앱 런타임 OTA를 함께 확인한다. 현재 작업에서는 운영 배포하지 않는다.
