# T-10-093: 시즌1 Threads 유입·플레이 전환 실험

상태: 기획 검토 / 문서만 추가 / 2026-09-29 KST

## 목적과 범위

시즌1을 준비하면서 Threads를 축구선수 커리어 게임에 관심 있는 이용자가 실제 플레이를 시작하는 채널로 검증한다. 좋아요·팔로워·댓글 수 자체를 성공 지표로 삼지 않는다. 자동 소통이 유입을 늘리지 않는다는 운영자 관찰은 가설이며, 현재 기록만으로 전환 효과나 알고리즘 불이익을 입증할 수 없다.

이 문서는 콘텐츠·측정·준비 자료·2주 실험을 정의한다. 게임 기능, GA 설치, DB, 세이브, 배포, SNS 게시·예약 재개는 수행하지 않는다. 일시정지한 소통 및 업데이트 게시 예약은 별도 재개 지시 전까지 유지한다.

- main 병합은 운영 배포 증거가 아니다. 개막일·밸런스 잠금·명예의 전당 안내는 게시 직전 배포 기록과 실제 화면을 확인한다.
- [GA4 최소 행동 측정 #366](https://github.com/tasddc1226/offside-football-simulator/pull/366): 아직 기획 PR이다. 이 문서는 이벤트 명칭·동의·개인정보·중복 방지 원칙을 재사용하며 별도 태그를 중복 설치하지 않는다.

## 대상과 콘텐츠 방향

우선 대상은 축구 게임·FM·선수 육성·커리어 시뮬레이션을 좋아하거나 짧게 즐길 게임을 찾는 사람이다. 개발자 교류는 유지하되 이를 플레이어 수요와 동일시하지 않는다.

| 축          | 보여줄 내용                             | 필요한 실제 자료                       | 제외할 것                          |
| ----------- | --------------------------------------- | -------------------------------------- | ---------------------------------- |
| 선택        | 한 구단 잔류와 이적 같은 실제 선택 장면 | 선택 화면, 선택 당시 맥락, 후속 결과   | 선택 하나가 결과를 보장한다는 주장 |
| 선수 이야기 | 독특한 커리어·은퇴 기록                 | 공개 기록 또는 공유 허락, 실제 리포트  | 합성 기록, DM 무단 재공개          |
| 플레이 변화 | 출시된 기능이 바꾼 한 장면              | 배포 근거, 현재 화면, 기존 동작과 차이 | 미병합 기획을 출시 기능으로 소개   |
| 제작 이야기 | 실제로 해결한 이용자 불편               | 공개 가능한 문제·해결 근거             | 운영 비밀, 확인하지 않은 성과      |

기본 실험량은 주 3개, 2주 6개다. 선수 이야기·선택 2개와 실제 업데이트·제작 이야기 1개를 주별로 배치한다. 자료가 없으면 건너뛴다. 수동 게시도 일정에 포함하고 같은 내용을 중복 발행하지 않는다. 계정 간 품앗이·하루 댓글 수를 목표로 하지 않는다.

댓글은 관련 대화에서 구체적으로 보탤 말이 있을 때만 작성한다. 관련 게임을 찾거나 소개를 요청할 때 제작자임을 밝히고 안내한다. 인사·감사·대화 마무리는 필요하면 좋아요로 끝낸다. 자동화는 후보 수집·초안·성과 집계 용도로 제안하며 공개 실행 재개는 이 PR의 범위가 아니다.

## 게시 초안과 운영 일정

아래는 게시 전 채워야 할 템플릿이다. 대괄호를 실제 확인 자료로 교체한 뒤 검토하고, 확인되지 않은 문장은 삭제한다. 문장 끝 마침표·말줄임표는 쓰지 않는다.

고정 소개 글:

> 축구선수 한 명의 커리어를 키워가는 웹게임을 만들고 있어
> [실제 화면에서 할 수 있는 선택 하나]부터 [확인된 은퇴 후 기록]까지 내 선수 이야기가 쌓이는 게임임
> 시즌1 참가 기준은 [검증된 안내]
> 시작은 여기 [시작 링크]

선수 이야기:

> [실제로 확인한 커리어의 특징]
> [그 기록에서 흥미로운 구체적 장면 하나]

선택 장면:

> [실제 선택 화면의 상황]
> [각 선택에서 고민되는 점을 사실 범위 안에서 설명]

업데이트:

> [실제로 배포된 변화]
> 이제 [화면에서 확인한 플레이상의 차이]

D0는 운영에서 시즌1 개막이 확인된 날이다. 현재 소스 날짜가 바뀌면 일정도 옮긴다. 개막 이전에는 참가 안내와 자료 검증을 준비하고, D0/D+3/D+6 및 D+8/D+10/D+13에 각 1개를 제안한다. 첫 주는 선수 이야기·선택·개막 안내, 둘째 주는 같은 콘텐츠 축을 다른 실제 사례로 반복한다. 게시 시각은 기록하되 봇 탐지 회피를 위한 난수 실행이나 특정 시각의 효과를 주장하지 않는다.

## 링크와 측정 계약

소개·출시 글에는 시작 링크를 명확히 넣고, 일반 대화에는 링크를 강제로 붙이지 않는다. 프로필 링크는 별도 식별한다. 내부 화면 이동에는 UTM을 새로 붙이지 않는다.

- `utm_source=threads`, `utm_medium=social`, `utm_campaign=season1_launch`
- 게시물 `utm_content=s1_story_01`, `s1_choice_01`, `s1_update_01`처럼 제한된 목록을 등록한다. 프로필은 `s1_bio`다.
- 예시: `https://offside-lab.com/?utm_source=threads&utm_medium=social&utm_campaign=season1_launch&utm_content=s1_story_01`
- 값에 이용자명·선수명·프로필/커리어 ID·자유 입력을 넣지 않는다.
- #366의 UTM 허용 목록에 위 캠페인/콘텐츠 값을 추가하는 것은 후속 구현 과제다. URL을 붙인 것만으로 수집 완료로 처리하지 않는다.
- Threads 링크 클릭/방문 수와 분석 도구의 세션은 다른 지표다. 클릭 수를 세션 전환율의 분모로 대신 사용하지 않는다.

| 지표         | 정의                                                                              | 관측 시점                     |
| ------------ | --------------------------------------------------------------------------------- | ----------------------------- |
| 게시물 반응  | 공개 조회·좋아요·답글·리포스트, 본인 반응 가능 시 구분                            | 게시 24h, 72h                 |
| 방문→시작    | 해당 UTM 유입 세션 중 page_view 뒤 career_start가 있는 세션 / 해당 page_view 세션 | 게시 후 72h 유입 창           |
| 시작→첫 시즌 | 시작 사용자 중 24h 안에 first_season_complete가 있는 사용자 / 시작 사용자         | 유입 창 종료 후 24h 성숙 표본 |
| D1/D7 재방문 | 시작 코호트 중 KST 다음 날/7일 뒤 활동한 사용자 / 시작 사용자                     | 각 날짜가 완전히 지난 표본    |
| 운영 효율    | 해당 유입 창의 시작 세션 수 / 제작·소통에 쓴 시간                                 | 주간                          |

진행 퍼널은 #366처럼 측정 가능한 브라우저 사용자 흐름이며 동일 선수 완주율이나 실인원으로 부르지 않는다. 세션의 캠페인 값으로 비교하며 최초 유입 보고서는 분리한다. direct·차단·동의 거부·기기 변경·복사 재공유로 누락/오분류될 수 있다. 운영자 테스트 유입은 제외한다. 미표시·미설치는 빈칸과 사유로 남기고 0으로 입력하지 않는다.

## 2주 실험 판정

동시 광고·게임 변경·커뮤니티 노출·서버 장애를 기록한다. 콘텐츠별 UTM은 귀속 관측용이며 무작위 대조 실험이 아니므로 인과 효과를 확정하지 않는다. 과거 스하리 기간의 플레이 전환 데이터가 없으면 전후 개선률을 만들지 않는다.

- 조회는 있지만 클릭이 적으면 게임 재미와 시작 안내를 점검한다.
- 세션은 있지만 시작이 적으면 첫 화면·로딩·기존 이용자 비중을 확인한다.
- 시작은 있지만 첫 시즌 진행이 적으면 게임 진입 경험을 조사한다.
- 시작과 재방문이 확인되는 콘텐츠 축을 다음 실험에 우선한다. 좋아요만으로 확대하지 않는다.
- 초기 의사결정 기준으로 콘텐츠 축당 측정 세션 30 미만이면 우열 판정을 유보한다. 30은 통계적 유의성 보장이 아닌 운영 최소 표본 제안이다. 그 이상도 분자·분모와 표본 편향을 함께 본다.
- D+14에는 성숙한 단기 지표만 중간 검토한다. 마지막 게시의 72h 유입 창과 D7이 끝나는 D+24 이후 최종 검토한다.
- 분석 구현이 늦으면 반응·링크 관측만 기록하고 플레이 전환 실험 시작은 계측 검증 이후로 옮긴다. 전환 미측정을 실패 또는 0건으로 부르지 않는다.

## 후속 구현 수용 기준

1. #366의 실제 생성/이어서 하기/재시작 구분과 동의·철회·중복 억제 기준을 통과한다.
2. 허용된 UTM으로 방문한 테스트 세션에서 캠페인과 career_start 연결이 보고서에 확인된다.
3. 프로필·게시물별 링크가 모바일 Threads 인앱 브라우저에서 정상 열리고 기존 세이브에 영향을 주지 않는다.
4. 내부 이동이 유입을 덮어쓰지 않고 분석 실패가 게임·저장·공유를 막지 않는다.
5. 추가 Workers/D1 쓰기·세션 조회·폴링 없이 측정하고 비공개 데이터는 전송하지 않는다.
6. 시즌1 공지의 날짜·참가·기존 기록 처리와 실제 서비스가 일치한다.
7. 콘텐츠 6개는 후보일 뿐 자동 게시 큐로 등록하지 않는다. 공개 실행은 별도 운영 결정이다.
