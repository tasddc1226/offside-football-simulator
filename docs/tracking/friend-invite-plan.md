# 친구 초대 이벤트 (T-11-171)

친구를 데려온 구단주와 새로 온 구단주 모두에게 선수 후보 리롤권을 준다. 2026-10-07 브레인스토밍과
2026-10-09 결정을 정리한 문서다.

## 결정

| 항목 | 결정 |
|---|---|
| 보상 대상 | 로그인한 구단주만. 리롤권 조회·사용이 구단주 전용(`requireOwner`)이라 같은 조건을 쓴다 |
| 보상 | 초대가 성공하면 두 사람 모두 리롤권 2장(`INVITE_REROLLS`). 초대한 사람은 10번까지(`INVITE_REWARD_MAX`) |
| 성공 기준 | 초대받은 사람이 로그인한 뒤 선수 커리어를 **은퇴까지** 마쳤을 때. 25살 조기 은퇴도 은퇴라서 인정하지만, 안내는 "커리어를 끝까지 마치면"으로만 한다 |
| 명예의 전당 | 리롤한 커리어를 따로 표시하지 않는다(컵 · 상점 · 광고 리롤과 같다) |
| 초대 칭호 | 3 · 5 · 10명 칭호를 주기로 했다. 대표 칭호 시스템(#563, T-11-150)이 머지된 뒤 후속으로 붙인다 |

## 흐름

1. 초대하는 사람은 지금 있는 친구 초대 링크(`/?friend=코드`)나 친구 코드를 공유한다.
2. 받은 사람이 로그인하고 그 코드로 새 친구 신청을 하면(`POST /v1/friends/requests` · `{ code }`), 서버가 초대로 적는다.
   - 아직 은퇴시킨 커리어가 없는 사람만 적는다. 기존 유저끼리 서로 초대해 보상을 받지 못하게 한다.
   - 한 사람은 한 번만 초대받는다(`referrals.invitee_id` PK). 다른 코드로 또 신청해도 친구 신청만 간다.
   - 팀 프로필의 친구 신청(`{ teamId }`), 이미 친구거나 신청 중인 사이, 상대가 먼저 보낸 신청을 수락하는 경우는 초대로 치지 않는다.
   - 응답의 `invited: true`로 "이벤트에 참여했어요" 토스트를 띄운다.
3. 받은 사람이 커리어를 은퇴시키면(`PUT /v1/careers/:id/retirement`) 판정한다. 판정 전 초대만 끝내므로 재전송에서 다시 불려도 한 번만 준다.
   - 초대를 끝낸다(`done_at` · `career_id`).
   - 받은 사람에게 2장을 준다.
   - 초대한 사람이 지금까지 보상받은 초대가 10번 미만이면 그 사람에게도 2장을 준다(`inviter_rewarded`).
   - 두 사람의 알림함에 안내를 남긴다(`social`, 친구 화면으로 간다).
   - 같은 batch 안에서 앞 문장이 적은 줄을 조건으로 걸어서 두 번 주지 않는다.
4. 친구 화면(웹 · 앱)의 "친구 초대 이벤트" 카드에 규칙과 현황을 보인다(`GET /v1/friends`의 `invite`).
   - 현황: 진행 중 · 완료 · 받은 보상 N/10
   - 초대받은 사람에게는 누구의 초대인지와 보상을 받았는지를 보인다.

클라이언트가 초대를 따로 신청하지 않는다. 지금 깔려 있는 앱도 친구 신청만 하면 초대가 기록되고, 이벤트 카드는 OTA 뒤에 보인다.

## 어뷰징 방어

- 로그인한 구단주만(구글 · 애플 계정)
- 초대받는 사람은 은퇴 선수가 없어야 하고, 한 번만 초대받는다
- 커리어를 은퇴까지 마쳐야 한다(시즌 기록을 서버가 받아 둔 커리어만 은퇴로 기록된다)
- 초대한 쪽 보상은 10번까지
- 모든 초대는 `referrals`에 남아 운영 DB에서 확인할 수 있다. 프로필을 지우면 그 사람의 초대 줄도 지운다

## 후속

- 초대 칭호(3 · 5 · 10명): #563의 `owner-title.ts`에 초대 칭호 id를 더하고, 완료한 초대 수로 자동 부여한다.
- 하루 판정 수 상한이나 기기 신호 보류는 실제 초대 수를 보고 필요하면 넣는다.
- 공유 문구에 이벤트를 넣거나(친구 초대 링크 공유), 선수 카드 공유에 초대 링크를 붙이는 것.
