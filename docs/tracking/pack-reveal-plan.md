# 팩 오픈식 결과 공개 연출 (T-11-371)

2026-10-17 초안. 아직 구현하지 않았다. 선수를 뽑고 잠재력을 확인하는 순간을 FC온라인 선수팩 · FIFA 얼티밋 팀 워크아웃처럼
"단서가 하나씩 열리는" 연출로 바꾼다. 확률 · 결과 · 저장값은 그대로 두고 보여 주는 방식만 바꾼다.

## 한 줄 요약

후보 카드 오픈 · 후보 잠재력 공개 · 시즌 스카우트 평가 · 은퇴 때 실제 잠재력 공개 네 순간을, 결과가 저장된 뒤에 재생되는
3단계 공개 연출(뒷면 → 단서 → 결과)로 바꾸고 결과 등급에 따라 연출 강도를 세 단계로 나눈다. 언제든 탭 한 번으로 건너뛴다.

## 배경

- App Store 리뷰(2026-10-04~10-15, 21건)와 라운지 채팅에서 가장 자주 나오는 감정 표현이 뽑기 순간이다. "S급 한 번만 맛보면
  여한이 없겠다", OVR 96 · 첫 영구결번을 채팅에 직접 알리는 글이 계속 올라온다.
- 그런데 지금 그 순간의 화면은 조용하다.
  - 후보 카드는 세 장 모두 같은 뒤집기(`apps/web/src/ui/Create.svelte`의 `flipIn`, 360ms)로 열린다. 좋은 후보든 평범한 후보든 똑같다.
  - 후보 잠재력 범위는 광고 · 구단 자금으로 열면 문구 한 줄(`L.potentialRange`)로 바뀐다.
  - 은퇴 때 실제 잠재력 공개(`apps/web/src/ui/LegendReport.svelte`의 `film-pot`, T-10-073)는 엔딩 크레딧 안의 한 장면으로 스크롤하며 지나간다.
- 이미 비슷한 연출이 두 개 있다. 스카우트가 후보를 추리는 `ScoutScan`(T-10-111, 웹 · 앱)과 잠재력 강화 `BoostFx`(T-11-083, 웹 · 앱)다.
  둘 다 "결과는 먼저 정해지고 연출은 보여 주기만 한다", "감속 모션이면 짧게", "탭으로 건너뛰기" 원칙을 이미 지킨다. 이 문서는
  그 원칙을 공개 순간 전체로 넓힌다.

## 원작 레퍼런스에서 가져올 것

| 레퍼런스                | 가져올 것                                                                      | 가져오지 않을 것                  |
| ----------------------- | ------------------------------------------------------------------------------ | --------------------------------- |
| FIFA 얼티밋 팀 워크아웃 | 단서가 순서대로 열린다(국적 → 포지션 → 구단 → 선수). 좋은 결과면 전조가 다르다 | 연출 길이 강제(못 넘기는 긴 컷신) |
| FC온라인 선수팩         | 카드 테두리 색 · 빛으로 등급을 먼저 암시하고 숫자는 마지막에 공개              | 유료 팩 · 확률형 아이템 판매      |
| 기존 OFFSIDE `BoostFx`  | 끝으로 갈수록 느려지는 게이지(숨 죽이는 순간), 성공 · 실패에 다른 진동         | -                                 |

핵심은 "결과를 먼저 알려 주지 않고, 알 수 있는 단서부터 하나씩"이다. 다만 숨겨진 값(실제 잠재력)을 연출로 미리 흘리면 안 된다.

## 확정 제안

### 대상 순간

| 순간                        | 지금 위치(웹 / 앱)                                                                                           | 공개되는 값                                  | 연출 강도를 정하는 값                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------- | -------------------------------------------------------- |
| 1. 후보 카드 오픈           | `apps/web/src/ui/Create.svelte`(`pick` · `openAll` · `flipIn`) / `apps/mobile/src/screens/create/Create.tsx` | OVR · 스카우트 한마디 · 능력치               | OVR, 프리미엄 스카우트 보장(`guaranteed`) · 천장(`pity`) |
| 2. 후보 잠재력 범위 공개    | 같은 화면, `revealCandidatePotential`(광고 · 구단 자금)                                                      | 잠재력 등급 범위(`candidatePotentialGrades`) | 범위의 최고 등급                                         |
| 3. 시즌 스카우트 평가 보기  | 선수 탭 잠재력 평가(`gamePotential` 문구 `peekBtn*`)                                                         | 이번 시즌 평가 등급                          | 평가 등급                                                |
| 4. 은퇴 때 실제 잠재력 공개 | `LegendReport.svelte` `film-pot` / `apps/mobile/src/screens/retired/LegendReport.tsx`                        | 실제 잠재력 등급 · 수치                      | 실제 잠재력 등급                                         |

4번은 은퇴 직후 화면(`Retired`)에서 처음 볼 때만 연출한다. 명예의 전당 상세 · 공유 링크에서 다시 볼 때는 지금처럼 정적으로 그린다.

### 연출 단계

| 단계    | 보이는 것                                                                                            | 비고                                                                                                          |
| ------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 1. 뒷면 | 카드 뒷면, 포지션 실루엣. 강도에 따라 테두리 빛이 다르다                                             | 1번 순간은 이미 보이는 값(OVR · 보장 표시)으로만 강도를 정한다. 잠재력이 잠겨 있으면 잠재력을 암시하지 않는다 |
| 2. 단서 | 1번: 능력치 막대가 차오르고 OVR 숫자가 올라간다. 2~4번: 등급 글자가 아래 등급부터 위로 훑고 지나간다 | 끝으로 갈수록 느려진다(`BoostFx`의 `1 - (1 - x) ** 3` 곡선)                                                   |
| 3. 결과 | 결과 등급 글자 · 숫자가 멈추고 강도별 효과(빛 · 흔들림 · 진동)                                       | 결과 화면은 눌러서 닫거나 다음 행동 버튼이 바로 보인다                                                        |

### 등급별 강도 (세 단계)

| 강도 | 기준(제안, 열린 질문에서 확정)                       | 효과                                                                        |
| ---- | ---------------------------------------------------- | --------------------------------------------------------------------------- |
| 보통 | 아래 둘에 해당하지 않음                              | 짧은 뒤집기, 진동 없음                                                      |
| 좋음 | 잠재력 A(2~4번), 1번은 보장 후보 · 세 장 중 OVR 최고 | 테두리 금색, 짧은 진동                                                      |
| 대박 | 잠재력 S(2~4번), 1번은 천장 후보(`pity: 'elite'`)    | 결과 직전 한 박자 멈춤, 화면 가장자리 빛, 긴 진동, 결과 뒤 "공유" 버튼 강조 |

강도 판정은 순수 함수 하나(`packages/app-core`의 `revealTier`)로 두고 웹 · 앱이 함께 쓴다. 입력은 화면에 이미 공개된 값뿐이다.

### 건너뛰기 · 접근성

| 항목             | 제안                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| 건너뛰기         | 연출 중 어디를 눌러도 결과 단계로 바로 간다(웹은 Esc도). `ScoutScan`과 같다                                         |
| 길이             | 보통 1초 안, 대박도 2.5초 안. 처음 열린 순간이 지나면 같은 화면 안의 나머지 카드는 짧게                             |
| "연출 짧게" 설정 | 설정에 켜고 끄기 하나. 켜면 모든 공개가 결과 단계만 짧게 보인다(이 기기에만 저장)                                   |
| 감속 모션        | 웹 `motionOK`(`apps/web/src/ui/motion.ts`), 앱 `prefs.motionOK`이면 움직임 없이 결과만. 업무 모드(`sheetOn`)도 같다 |
| 화면 읽기        | 결과 단계에서 결과 문장 하나를 `aria-live`(앱은 `accessibilityLiveRegion`)로 읽는다. 중간 단계는 읽지 않는다        |

### 소리 · 진동

| 항목 | 웹                                                                                                               | 앱                                                                     |
| ---- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 진동 | `buzz`(`motion.ts`, `navigator.vibrate`). 좋음 짧게, 대박 길게                                                   | `expo-haptics`, `hapticsOn()`(`apps/mobile/src/game/host.ts`)을 따른다 |
| 소리 | `sfx.ts`처럼 음원 파일 없이 Web Audio로 합성한 짧은 음 2~3개(단서 · 결과 · 대박). 효과음 설정(`ft_sfx`)을 따른다 | 1차에는 넣지 않는다. 오디오 패키지를 새로 들이면 OTA 1.1.2가 막힌다    |

## 결과 불변 원칙

- 연출은 결과가 정해지고 저장된 뒤에 재생한다. 후보 뽑기 · 잠재력 공개 · 은퇴 처리 순서는 바꾸지 않는다. 연출 중 화면을 닫거나 새로고침해도 결과는 같다.
- 연출용 난수는 `Math.random`이다. 게임 RNG(`RngSaveState`)는 건드리지 않는다. `packages/game/src/golden.test.ts` 스냅샷이 바뀌면 안 된다.
- 확률 · 천장 · 보장 규칙과 확률 도감(`fairness`) 문구는 그대로다. 강도는 이미 공개된 값으로만 정해서, 잠재력이 잠긴 후보의 잠재력을 연출로 암시하지 않는다.
- 세이브 포맷 변경이 없다(`migrateSave` 불필요). "연출 짧게"는 세이브가 아닌 기기 설정 키에 둔다.

## 구현 범위

### 공통 (`packages/app-core`)

- `revealTier(moment, values)`와 단계별 시간 표를 둔다. 웹 · 앱이 같은 기준으로 강도를 정한다.
- 문구(ko · en · ja): 건너뛰기 안내, "연출 짧게" 설정 이름 · 설명, 화면 읽기용 결과 문장. 새 네임스페이스면 `node tooling/scripts/i18n-index.mjs`.

### 웹 (`apps/web`)

- 공개 연출 컴포넌트 하나(`RevealFx.svelte`)를 만들어 네 순간이 함께 쓴다. `BoostFx.svelte` 구조(onMount · requestAnimationFrame · `dur` · `buzz`)를 따른다.
- **번들:** 첫 화면 청크 여유가 거의 없다(145KB 예산). `RevealFx`는 선수 만들기 · 은퇴 리포트 청크에서만 불러온다. push 전에 `pnpm --filter @offside/web build && pnpm --filter @offside/web check:bundle`.
- 설정 화면에 "연출 짧게" 켜고 끄기.

### 앱 (`apps/mobile`)

- `apps/mobile/src/components/RevealFx.tsx`. `Animated` · `expo-haptics`만 쓴다(새 npm 패키지 금지, OTA 1.1.2).
- 선수 만들기(`screens/create/Create.tsx`), 은퇴 리포트(`screens/retired/LegendReport.tsx`), 선수 탭 평가 보기, 설정(`screens/settings/Settings.tsx`).
- iOS에서 SVG 필터는 UI 스레드에서 느리다(앱 선수 그림 디버깅 교훈). 빛 효과는 SVG 필터 대신 겹친 `View`의 투명도로 그린다.

### 가이드 · 공지

- 게임 규칙 · 수치가 바뀌지 않으므로 공개 가이드(`seo.mjs`의 `GUIDE_SECTIONS`)는 바꾸지 않는다. FAQ의 확률 항목에 "연출은 결과에 영향이 없다" 한 줄을 더할지는 열린 질문.
- 릴리즈 노트 `.release-notes/` 항목(ko · en · ja, `web-app`).

## 테스트

- 단위: `revealTier`가 공개된 값만으로 강도를 정하는지(잠재력이 잠긴 후보는 잠재력 값과 관계없이 같은 강도).
- 결정성: `golden.test.ts` 그대로 통과, 같은 시드 후보 · 잠재력이 연출 유무와 관계없이 같은지.
- 웹 e2e: 감속 모션(`reducedMotion: 'reduce'`)에서 결과가 바로 보이는지, 연출 중 탭하면 결과 단계로 가는지, "연출 짧게"가 다시 열어도 유지되는지.
  기존 선수 만들기 e2e가 연출 때문에 느려지지 않게 테스트는 감속 모션으로 돈다.
- 앱: 타입 검사 · 실기기에서 대박 연출 프레임(iOS 저사양 기기) 확인.
- `pnpm lint:i18n`, 세 언어 사전 키 일치(`i18n.test.ts`).

## 진행 순서

## 열린 질문

- 강도 기준: 1번 순간의 "좋음"을 세 장 중 OVR 최고로 둘지, OVR 절대값 기준으로 둘지. 2~4번의 대박을 S로만 둘지.
- 4번 순간을 엔딩 크레딧 흐름 안에 둘지(스크롤 도착 때 재생), 크레딧 앞에 따로 한 장면으로 띄울지.
- 대박 결과 뒤 "공유" 버튼을 기존 공유 카드(`ShareBar`)로 연결할지, 라운지 자동 알림(별도 기획)과 묶을지.
- 앱 소리를 나중에 넣을지(다음 네이티브 빌드에서 오디오 패키지를 함께 들일 때).

## 배포 뒤 볼 지표

- 연출 건너뛰기 비율과 "연출 짧게" 켠 비율. 높으면 길이를 줄인다.
- 후보 단계에서 선수 만들기를 끝내는 비율(연출 때문에 이탈이 늘지 않는지).
- 후보 잠재력 공개(광고 · 구단 자금) · 리롤권 · 프리미엄 스카우트 사용률 변화.
- 대박 결과 뒤 공유 버튼 누름 수.

GA4로 잴 때는 [GA4 측정 계약](ga4-measurement-plan.md)에 이벤트(강도 · 건너뜀 여부만, 선수 정보 없이)를 함께 더한다.
