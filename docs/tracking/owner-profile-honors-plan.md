# T-11-150: 구단주 프로필 · 명예관 · 대표 칭호

작성일: 2026-10-07 · 상태: 구현(PR 대기, 배포 전) · 바탕: T-11-145 오프사이드 컵(PR #558) 브랜치

컵 트로피처럼 시즌을 넘어 남는 기록을 구단주 한 사람 기준으로 모아 보여 주고, 받은 칭호 하나를 닉네임 옆에 달게 한다.
제1회 컵 결승(10/20) 전에 나가야 우승 칭호가 처음부터 붙는다.

웹은 기록실 상태 `hof.owner`(팀 프로필 대신 그 팀 구단주 프로필), 방문 기록 키는 `hof:<팀>:owner`. 앱도 같은 상태를 쓴다.
T-11-145에서 넣은 팀 프로필 '제N회 챔피언' 배지는 대표 칭호 알약으로 바꿨다.

## 2. 칭호

- id: `cup-{회차}-{champion|runnerup|sf}` (contracts `owner-title.ts`). 회차와 단계를 id에서 바로 읽어 그린다.
- 순서: 우승 > 준우승 > 4강, 같은 단계면 최근 회차. 8강 이하는 칭호가 아니다.
- 저장: `profiles.title`(보이는 칭호), `profiles.title_pinned`(0 자동, 1 직접 고름). 마이그레이션 0076.
- 자동: 컵 보상을 줄 때, 직접 고르지 않은 구단주는 새 칭호가 지금 칭호보다 좋거나 같은 단계면 바꾼다.
- 고르기 `PUT /v1/owner/title`: 칭호 id(받은 것만, 아니면 409 `TITLE_NOT_OWNED`), `'none'`(달지 않기), `null`(다시 자동 — 가장 좋은 칭호).

T-10-082 기획(구단주 도전 과제 칭호, 미구현)은 "직접 고르기 전엔 자동 장착하지 않는다"였다. 컵 칭호는 받은 사람이 드물고
자랑이 목적이라 자동으로 달고(10/7 목업 합의), 직접 고르거나 '달지 않기'를 고르면 그 뒤로는 자동으로 바꾸지 않는다.
도전 과제 칭호를 만들 때 id 형식(`cup-` 접두어)만 늘리면 같은 자리 · 같은 고르기를 쓴다.

## 3. API

| 경로                             | 인증   | 내용                                                        |
| -------------------------------- | ------ | ----------------------------------------------------------- |
| `GET /v1/owners/by-team/:teamId` | 없음   | 그 팀 구단주의 프로필 + `mine`. 프로필 id는 내보내지 않는다 |
| `GET /v1/owner/title`            | 구단주 | 지금 칭호 + 받은 칭호(좋은 순) + `pinned` + 내 최근 팀 id   |
| `PUT /v1/owner/title`            | 구단주 | 대표 칭호 고르기                                            |

`title`(보낸 때의 칭호를 방 SQLite에 저장). 랭킹은 엣지 캐시 5분이라 칭호를 바꾸면 최대 5분 뒤 보인다.

시즌 기록: 끝난 시즌은 `owner_season_records`(마감 결산), 지금 시즌은 지금 업적 점수와 지금 팀 레이팅 순위.

## 2026-10-10 영구 칭호 확장

- 고정 ID/조건 정본: `packages/contracts/src/owner-title.ts`의 `PERMANENT_TITLES`, 기준 v1.
- 직접 육성한 원 소유자(`careers.profile_id`)에게 프리시즌·시즌 1·이후 시즌을 누적해 인정한다. 육성량/최고 능력치/발롱도르에는 숨김 아닌 요약 보유·30세 이상 은퇴 조건을 적용한다. 영구결번은 실제 지급 기록, 기록 개척자는 확정된 결산 `owner_honors.kind=first`만 인정한다.
- 칭호 원장(`owner_title_awards`)은 계정+칭호 유일, 획득 시각/기준 버전/근거 수/확인 시각을 보존한다. 판매·시즌 전환·재집계로 회수하지 않는다. 계정 삭제 때 원장과 진행도를 명시적으로 삭제한다.
- 진행도(`owner_title_progress`)는 은퇴 및 영구결번 지급 때 갱신한다. 최초 개인 명예관 조회에 진행도 행이 없으면 한 번 소급 판정한다(익명에서 연결한 계정도 포함). 이후 조회는 저장된 행과 인덱스를 이용한 최신 은퇴 존재 여부만 읽는다. 응답 뒤 판정이 중단된 은퇴가 있으면 해당 구단주만 다시 판정한다. 클라이언트는 GET을 60초 메모한다. 공개 프로필에는 판정 쓰기가 없다.
- 획득한 일반 칭호는 자동 장착하지 않는다. 수동 선택은 pinned라 새 컵 성적이 덮지 않는다. 기존 자동 모드는 컵 칭호에만 적용한다. 신규 칭호는 NEW로 표시하고 선택하면 확인 처리한다.
- 배지는 구단주 홈/공개 프로필/팀 프로필/팀·업적 랭킹/상대 목록/댓글/채팅의 기존 #563 경로를 쓴다. 새 채팅에는 발송 시점 칭호가 남는다. 선택 직후 내 헤더를 갱신하고, 팀·업적 랭킹 첫 페이지 캐시를 지운다. 나머지 랭킹 페이지는 기존 5분 TTL을 따른다.

### 소급 지급 운영 절차

1. 마이그레이션과 API가 배포된 뒤 운영자 세션으로 `POST /v1/admin/owner-titles/backfill`을 호출한다. `{after:'', limit:25}`는 **읽기 전용 미리보기**다. 최대 50명, 프로필 PK 커서 순으로 처리하며 `next:null`이면 끝이다.
2. `tooling/scripts/backfill-owner-titles.mjs`에 `OWNER_TITLE_API_BASE_URL`, `OWNER_TITLE_ADMIN_TOKEN`을 환경변수로 전달한다. `--all`은 전체 미리보기, 명시적 `--apply --all`만 실제 지급이다. stdout은 익명 집계만 출력한다. 기본 200배치 상한이며 필요하면 `OWNER_TITLE_AFTER`로 커서를 이어 간다.
3. 미리보기의 칭호별 **추가 지급 예정 인원**을 검토한 뒤 같은 조건으로 실제 지급한다. 미리보기도 동작 중인 게임과 같은 판정 함수를 사용한다. 재실행은 중복 지급/기존 획득 시각 변경이 없다.
4. 배포 전에는 원격 지급을 실행하지 않는다. 최초 진입 소급 지급으로 이미 받은 사람은 배치의 추가 지급 수에서 제외된다. 컵 칭호 원본은 기존 컵 성적을 유지한다.

## 2026-10-10 시즌 업적과 영구 칭호의 연결 (기준 v2)

### 명예관 화면 분리와 도트 아이콘

- 구단주 허브에는 이적시장과 같은 전체 클릭 카드에 짧은 명예관 안내와 오른쪽 화살표만 둔다. 칭호 목록은 별도 `honors` 화면을 열 때 불러오며 기존 `cachedGet`을 재사용한다. 획득 개수·조건·진행도·대표 선택은 명예관에서 제공한다. 뒤로 가기는 공통 방문 기록으로 돌아온다.
- 웹과 앱은 공통 16×16 픽셀 경로로 영구 칭호 14종을 각각 구분한다. 칭호 이름·등급 접근성 문구를 유지하고, 컵의 기존 도트 트로피는 그대로 쓴다.

- 구단주 허브 순서: 구단주 요약 → 내 팀 → 내 선수 → 이적시장 → 명예관 → 시즌 결산 → 리롤권·부스트 상점 → 계정. 웹·앱의 노출 조건을 유지한다.

### 내 선수 전용 화면과 보유 선수 관리

- 허브의 내 선수는 이적시장과 같은 전체 클릭 진입 카드다. 전용 `players` 화면에서 선택 시즌의 선수 기록 전체와 상세를 제공한다. 상세에서 돌아올 때 선택 시즌·기록/관리 탭을 유지한다. 허브 요약은 선택 시즌과 무관하게 현재 시즌의 기존 기록 기준을 유지하며 같은 계정 목록 캐시를 재사용한다.

- 공통 컨트롤러에서 최대 50명 선택, 별도 확인, 중복 전송 차단, 부분 방출 실제 인원 표시와 충돌 후 소유권 재조회를 처리한다. 시즌 변경 시 선택은 초기화한다. 기존 `/v1/cards/release`를 사용하며 서버 권한·금액 계산 및 명예의 전당 기록 보존 정책은 변경하지 않는다. 비로그인·오프라인 기기 기록은 조회만 제공한다.
- 웹 320px에서 시즌 선택, 전체 기록, 상세 복귀, 잠금·선발·영입·판매 차단, 확인 취소, 최종 방출, 기록 보존, 재진입 캐시 및 접근성을 검증한다. 앱은 같은 컨트롤러와 안전 영역 하단 이전 버튼을 사용한다. 실제 네이티브 화면 검증은 별도로 남아 있다.

## 2026-10-10 시즌 기록 보관함 통합

명예관은 시즌 기록과 칭호를 모아 보는 개인 보관함이다. 구단주 허브의 별도 시즌 결산 카드를 없애고 명예관에 통합한다.
시즌 목록 → 해당 시즌 등급·업적 점수·팀 순위·배지·컵 성적 → 펼쳐 보는 선수단·통계·공유 순으로 읽는다.
기존 결산 스냅샷·공유 기능을 명예관 상세로 재사용하며 별도의 집계·보상 체계를 만들지 않는다.
`GET /v1/owner/archive`는 팀이 없어도 로그인한 본인의 기록을 조회한다. 요약과 배지를 한 번에 읽고, 마감 상태를 확인해 아직 집계 중인 점수·배지를 숨긴다.
선택한 시즌 상세만 기존 결산 API로 읽고, 화면 안에서 읽은 상세는 재사용한다. 늦게 도착한 이전 시즌 응답은 무시한다.
디자인은 기존 잔디·잉크·금색 토큰, 시즌을 잇는 점 목록, 시즌 등급 엠블럼과 도트 칭호를 사용한다. 160ms 선택 전환과 펼치기 반응만 추가하고 자동 카드 흐름은 통합 상세에서 제외한다.
보상 정책과 관측 분포는 [시즌 경쟁·보상·승계 정책](season-competition-rewards-policy.md)에 통합한다.

### 칭호 탭 조작 정리 (2026-10-10)

- 현재 대표 칭호를 상단에 표시하고, 적용 중일 때만 해제를 제공한다.
- 획득한 칭호와 도전 중인 칭호를 나눈다. 획득한 칭호는 중복 없이 카드 전체를 눌러 즉시 적용한다. 별도 선택·저장 버튼을 두지 않는다.
- 미획득 칭호는 달성 비율 순으로 조건·진행률·연결 업적을 보여 준다. 같은 진행률은 기존 목록 순서를 유지한다.
- 등급 설명과 프로필 이동 버튼의 반복 노출을 없앤다. 칭호 안내·시즌 업적 이동·컵 칭호 자동 선택은 접힌 안내에서 제공하며, 컵 자동 선택은 보유한 컵 칭호가 있을 때만 표시한다.
- 선택 API 실패 시 기존 대표 칭호와 획득 상태를 유지하며 다시 선택할 수 있다.


### 웹 명예관 라커룸 프로토타입 (2026-10-10)

- 입구는 녹색·황동색 도트 라커룸이다. 시즌 라커, 구단주 명패, 트로피장의 세 구역을 좌우 스와이프 또는 44px 이상 버튼으로 이동한다.

- 시즌 기록·칭호 데이터와 선택 로직은 기존 구현을 재사용한다. 입구에서 archive 요약과 처음 표시하는 칭호를 읽고, 시즌 상세는 펼칠 때만 요청한다. 다시 방문한 목록은 캐시를 재사용한다.

- CSS 원근 변환과 SVG를 사용한다. 자동 회전은 없으며 모션 감소 설정에서는 회전 전환을 생략한다.

### 구단주 프로필 편집 (2026-10-10)

- 상단 구단주 프로필 오른쪽의 연필 아이콘(44px 터치 영역, 접근성 이름: 프로필 편집)을 누르면 별도 편집창이 열린다. 모바일 웹·앱은 하단 시트에서 이름과 이미지를 변경하며, 요약 카드 안에 폼을 펼치지 않는다. 하단 계정 영역은 인증·로그아웃·연동 해제·탈퇴만 담당한다.
- 웹·앱 모두 PNG/JPG/WebP를 중앙 정사각형으로 잘라 128px 이하, 인코딩 문자열 16KB 이하로 저장한다. 원본은 서버로 전송하지 않는다. 기본 이미지로 변경하면 기존 이름 첫 글자 아바타로 돌아온다.
- `profiles.avatar_id`는 공개용 무작위 버전 ID이며 이미지 바이트는 별도 `profile_avatars`에 저장해 세션·프로필 조회에 이미지가 실리지 않는다. 공개 이미지 GET은 세션 없이 유니크 인덱스로 찾고 60초 캐시하며 변경·삭제 시 캐시를 비운다.
- 댓글은 기존 작성자 join으로 현재 이미지를 읽는다. 채팅은 작은 ID만 메시지에 담고 변경 이벤트로 보관 메시지와 연결된 작성자·열린 화면을 갱신한다. 옛 메시지·응답의 이미지 필드가 없으면 기본 아바타를 사용한다.
- 이미지 저장·초기화는 로그인한 본인에게만 허용한다. 계정 삭제 시 이미지 데이터도 삭제한다.

### 구단주 첫 진입 조회 경량화 (2026-10-10)

- 웹·앱 구단주 요약은 `/v1/owner/summary`를 1분 동안 공유한다. 관리자 여부·지난 시즌 등급과 선수 합산용 ID/시즌/점수/결번만 읽고 선수 표시 정보나 결산 선수단은 가져오지 않는다.

- 새 결산 표시에는 `/v1/owner/recap-status`만 사용한다. 명예관에서 상세를 펼칠 때 결산 전체를 조회한다.

- 로컬 18명 계정에서 탭 요청 7→5개, 통합 대상 응답 13,713→1,883바이트. 첫 진입 DOM 완성 94~171ms, 재진입 약 9ms/추가 요청 0개. 개발 서버 측정이며 운영망 성능 수치가 아니다.

### 시즌별 최종 티어 배지 (2026-10-10)

- FOW의 시즌별 등급 목록처럼 구단주 프로필에 최신 시즌부터 프리시즌까지 작은 티어 배지를 자연 줄바꿈으로 표시한다. 진행 중이거나 결산 중인 시즌은 제외한다.
- 기존 요약 응답에 `tiers`를 추가한다. `owner_season_records`의 (profile_id, season) PK와 `app_meta.key` PK를 join하여 확정 상태를 한 번에 읽는다. 시즌별 추가 요청이나 N+1 쿼리는 없다.

- 실제 로컬 데이터는 마감된 프리시즌만 존재한다. 여러 시즌 정렬·320px 줄바꿈은 별도 테스트 응답으로 확인하며, 미래 시즌 기록을 DB에 만들어 넣지 않는다.
