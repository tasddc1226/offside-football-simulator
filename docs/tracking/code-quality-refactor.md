## 보존 조건

- 구조 변경에서 결정성 골든 스냅샷을 갱신하지 않는다.
- RNG 호출 순서, pending 복구, 저장 후 연출 순서를 지킨다.
- API의 batch·멱등성·커밋 원자성·알림·캐시 무효화·공개 조회의 세션 미접근을 보존한다.
- 웹과 앱의 화면 상태·플랫폼 인증·프리셋 선택 차이는 호출자가 소유한다.
- 업로드 큐와 일반 HTTP 요청, 즉시·라이브 경기 확정, legacy·v3 감독 저장의 의도된 차이를 보존한다.
- release-notes: none — 사용자 동작·문구·밸런스를 바꾸지 않는 구조 리팩터링.

- API typecheck와 변경 파일 ESLint 통과.
- game golden/save/clubs/sangmu/military/customNamesSave: 6파일 65개 통과.
- 컵·명단·랭크·시장·강화·감독·교환의 API 9파일 199개 테스트 및 쿼리 수 회귀 검사 통과.
- 저장용 구단 원래 이름은 sangmu-data의 i18n-ignore에 이유를 명시하고 기존 military 사전 밖 한국어 기준선을 낮춘다.

## 단계 2 검증

- 공통 projectTeamDraft를 웹·앱이 소비한다. 로컬 프리셋 선택·슬롯 ID·기존 평가 규칙을 보존했다.
- app-core 편성/초안/컵 표시 관련 5파일 69개 테스트 통과. 웹·앱·app-core 타입 검사 및 변경 파일 ESLint 통과.
- 로컬 웹 320px/390px, 모의 API로 자동 편성(OVR 54), 이름 입력, 초안 이탈/복구, 즉시 재진입 요청 재사용, 저장 1회를 확인했다. 가로 넘침 없음. 실제 서버 저장 검증은 아니다.
- 실행 중인 iOS 시뮬레이터·Android 기기 없음. 네이티브 화면 검증은 수행하지 못했다.

## 단계 3 검증

- 후보 스카우팅의 시드·킵·공개·리롤·프리미엄 계획을 scouting-actions로 옮겼다. 후보를 뽑은 입력과 시작 시 킵 해제를 같은 시점에 유지한다.
- 시장 카드/계약의 목적지 설명은 transferDestination을 공유한다. 진행·pending·RNG 연출·저장 순서는 유지한다.
- app-core 전체 160파일 1,606개 테스트, 타입 검사 및 변경 파일 ESLint 통과.

## 단계 4 검증

- 공통 accountCache가 TTL 경계·singleflight·세대·계정 상태를 관리한다. 모바일 토큰 갱신과 웹 구단주 알림은 각 어댑터에 유지한다.
- 모바일 analytics는 전체 host 대신 좁은 account 모듈을 지연 로딩한다. host의 기존 계정 export는 호환 경로로 유지한다.
- api/client는 기존 export를 보존하는 facade다. transport는 단일 요청/캐시/세션 실행 경로, profile/public은 endpoint wrappers, mutationPolicy는 무효화 범위만 소유한다. outbox 전용 전송은 유지한다.
- 웹 계정 기존 4개, 공통 캐시 3개, 모바일 unit 20파일 170개 테스트 통과. app-core 전체 161파일 1,609개 통과(maxWorkers=4).
- 기본 병렬도로 전체 검사를 돌릴 때 upload의 커리어 시뮬레이션 1개가 5초 timeout에 걸렸다. 타입 검사 등 동시 작업을 줄이고 worker 4개로 전체를 재실행해 모두 통과했다. timeout 설정·테스트 표본 수는 바꾸지 않았다.
- app-core·mobile 타입 검사와 변경 파일 ESLint 통과.

## 단계 5 검증

- startRankedMatch가 경기 시작을 담당한다. 라우터는 인증·멱등 미들웨어·본문·HTTP 응답과 background/cache 어댑터를 소유한다.
- 기존 guard/query/commit 순서를 유지하고, 즉시·라이브의 전적/점수/디비전은 rankedMatchProgress를 공유한다. 라이브 확정 트랜잭션은 유지한다.
- leagueRead는 조회·순위표를, leagueNotifications는 순수 알림 계획을 소유한다. lifecycle과 news의 역방향 import를 제거했다. 알림 커서와 알림 쓰기는 기존 batch에 남는다.
- API 타입 검사와 랭크·쿼리 효율·리그·알림·뉴스 관련 6파일 98개 테스트 통과. 변경 파일 lint 확인.
- 기존 한국어 오류 원문 7덩어리를 ownerTeam에서 새 소유 모듈로 옮겼다. i18n 기준선 경로만 재배치했으며 총합 2,868로 동일하다. 새 문구는 없다.

## 단계 6 검증

- 시상은 국내 → 세계 → 포지션/연맹 단계로, manager3 시즌 리뷰는 평가 → 선수단 → 감독 성장 → 승강 → 제의 → 리뷰 상태로 나눴다. RNG와 단축 조건 순서를 유지했다.
- manager-content의 공통 데이터로 v3가 legacy 엔진 전체를 값 import하던 의존을 제거했다. 기존 manager export와 저장 버전은 보존한다.
- 은퇴 전이/엔트리 생성과 HOF 보관을 분리했다. app-core는 보관 후 표시·업로드하고, 기존 엔진 호출용 retire wrapper도 같은 순서를 유지한다.
- 변경 전 감독 8개 시드의 10시즌 최종 상태/RNG 해시를 신규 회귀 기준으로 고정한 뒤 추출했다. 변경 후 동일 해시이며 기존 커리어 골든은 갱신하지 않았다.
- game 전체 57파일 605개 통과·2개 skip, app-core 은퇴/게임/스카우팅 관련 5파일 53개 통과. 게임 타입 및 변경 파일 ESLint 통과.

## 재측정

테스트·사전·vendor 등을 제외한 추적 소스를 이전 분석과 같은 AST 분기 대리지표로 측정했다. 표준 Cyclomatic/Cognitive Complexity가 아니며 Svelte template은 제외한다. 규칙을 이동·분리하므로 전체 분기 합계가 사라졌다고 해석하지 않는다.

| ---------------------------------------------------------- | ------: | ----: |
| game-actions 파일                                          | 1,138줄 | 912줄 |
| ownerTeam 라우터 파일                                      |   883줄 | 639줄 |
| league lifecycle 파일                                      | 1,212줄 | 926줄 |
| 시상 단일 함수 / 분리 단계 중 최대 분기 지표               |      81 |    32 |
| manager3 시즌 리뷰 단일 함수 / 분리 단계 중 최대 분기 지표 |      59 |    40 |
| 1,000줄 초과 파일                                          |      21 |    19 |

정적 순환 후보 SCC는 11개에서 7개로 줄었다. 실제 소스로 확인했던 게임 구단/병역, cup/ownerTeam, league/news, 모바일 host/analytics의 고리가 제거됐다. 나머지 후보를 전부 검토하거나 순환 의존을 전부 제거한 것은 아니다.

비테스트 소스는 254,074 → 254,356줄이다. 역할별 타입·명시적 어댑터·호환 export를 추가해 전체 줄 수는 282줄 늘었다. 이번 성과는 동일 정책/계산 조립의 한곳 관리와 큰 처리 함수의 책임 축소다.

## 남은 후속 후보

- Team의 계산은 공통화했지만 큰 화면 함수·탭별 로딩/저장 상태는 남아 있다. Create/Market은 이번에 전면 분해하지 않았다.
- buildLeagueNews의 후보 선택과 선택된 상세 조회는 여전히 큰 함수다. 조회/뉴스 순환은 해소했고, 향후 후보 계획과 표시 조립을 추가 분리할 수 있다. 필요한 경기 상세만 읽는 기존 최적화를 유지해야 한다.
- 대형 UI와 남은 순환 후보는 개별 흐름을 정밀 검토한 뒤 후속 작은 작업으로 진행한다.
