# T-11-704 코드 품질 단계별 개선

기존 게임 결과·저장·HTTP 계약·쿼리 수를 보존하면서 중복 정책과 역방향 의존을 줄인다. 각 단계는 독립적인 로컬 커밋으로 검토한다. 운영 배포는 이 작업 범위에 없다.

| 순서 | 범위                                                        | 상태                             |
| ---- | ----------------------------------------------------------- | -------------------------------- |
| 1a   | 컵 명단 정책을 라우터 밖으로, KST 날짜 함수를 time으로 이동 | 로컬 구현·검증 완료              |
| 1b   | SANGMU 데이터를 진행 로직에서 분리, 초기화 지연 우회 제거   | 구현, 게임 관련 65개 테스트 통과 |
| 2    | 웹·앱 팀 편성 계산 조립 공통화                              | 대기                             |

| 4    | 계정 캐시 정책 공통화·API 모듈 응집도 개선                  | 대기                             |
| 5    | 랭크 결과 projection·경기 사용 사례·리그 조회 의존 정리     | 대기                             |

## 보존 조건

- 구조 변경에서 결정성 골든 스냅샷을 갱신하지 않는다.
- RNG 호출 순서, pending 복구, 저장 후 연출 순서를 지킨다.
- API의 batch·멱등성·커밋 원자성·알림·캐시 무효화·공개 조회의 세션 미접근을 보존한다.
- 웹과 앱의 화면 상태·플랫폼 인증·프리셋 선택 차이는 호출자가 소유한다.
- 업로드 큐와 일반 HTTP 요청, 즉시·라이브 경기 확정, legacy·v3 감독 저장의 의도된 차이를 보존한다.
- release-notes: none — 사용자 동작·문구·밸런스를 바꾸지 않는 구조 리팩터링.
