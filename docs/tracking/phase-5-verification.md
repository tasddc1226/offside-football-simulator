## 실제 브라우저 검증

다른 작업의 서버와 사용자 기록을 건드리지 않도록 별도 origin `127.0.0.1:5195`와
전용 브라우저 공간을 사용했다. 이 공간에서는 로컬 API 동기화 요청을 차단했으므로
‘저장 다시 시도 중’은 의도적인 오프라인 검증 조건이다.

- 등록 ruleset `1.0.0` / content pack `0.1.0`으로 선수를 생성하고 실제 첫 계약·시즌을 진행했다.
- 18세에 `CAREER_BREAK` 선택 후 두 시즌을 실제 명령으로 진행·결산했다.
  두 시즌 각각 출전 0분·수입 0, 20세 복무 완료, 연대기에 시작·완료가 남았다.
- 이후 화면의 ‘선수 생활 마무리’ → 확인 대화상자 → ‘은퇴 확정’으로 종료했다.
  `FULL TIME`, 3시즌·19경기·1,620분, 복무 완료, Legacy 15점으로 보관됐다.
- Legacy → 최고의 순간 → 연대기 `#revision-19`, 최종 프로필·새로고침을 확인했다.
  최종 프로필은 선호/최종 포지션과 공개 OVR만 표시한다.
- 이 결과는 참조집단 도입 전 보관 결과이며 `referencePopulationId=null`이다.
  기준 집단 추가 후에도 과거 결과의 hash와 숨김 상태를 유지하는 회귀 대상이다.
- 자동 E2E는 별도의 고정 seed로 실제 온보딩부터 첫 시즌·은퇴·보관 화면까지 진행한다.
  소스 파일 존재를 E2E 실행 통과로 간주하지 않으며 최종 CI 결과를 아래에 기록한다.
- 별도 브라우저에서 FULL TIME/Legacy/연대기/최종 프로필을 실제 로드하고 axe-core
  4.13.0으로 검사했다. 네 화면 모두 serious/critical 위반 0건, 가로 넘침 없음이었다.
  확인 대화상자까지 포함한 동일 검사는 자동 E2E에도 추가했다.

## 실제 점수 병목 진단 — v2의 2개 seed

정식 배치의 동결 생성기를 그대로 사용해 해당 seed만 재생했다. 실제 명령·선택 정책을
변경하지 않았고, 원본 번들·체크포인트에 쓰지 않았다. 아래는 전체 분포의 대체물이 아니다.

| seed    | 시즌 | 성취 | 기여 | 장기성 | 관계 | 서사 | 총점 |
| ------- | ---- | ---- | ---- | ------ | ---- | ---- | ---- |
| MF:1279 | 20   | 92   | 76   | 100    | 24   | 53   | 73   |
| DF:699  | 20   | 100  | 58   | 100    | 26   | 51   | 71   |

MF는 11회 팀 우승, 출전 24,275/36,360분, 최고 OVR 77이었다. DF는 13회 팀 우승이지만
출전 11,455/43,920분, 최고 OVR 62였다. 두 결과 모두 30/25/15/15/15 가중합과 정확히
일치한다. 관계 손실·낮은 출전 노출이 고점을 제한하며, 이 두 결과에서는 산술 오류가 없다.
샘플링 전략과 게임의 달성 가능성을 분리해서 검토해야 한다.

추가로 등록 선택지만 사용한 관계 기대효과 우선·역할 훈련·연봉 개선 제안 수락 전략을
40개 seed(포지션별 10개, 각 20시즌)에 적용했다. 최고점은 GK 62 / DF 71 / MF 61 / FW 63으로,
75/90점 도달을 확인하지 못했다. 이는 단순 전략 probe이지 최적 플레이나 불가능성 증명이
아니다. 특히 연봉 개선이 출전 기회 개선과 같지 않으므로 정식 v3 정책으로 채택하지 않았다.
정식 v2 배치·점수 정책에는 어떤 변경도 적용하지 않았다.

## 독립 리뷰 처리

- 평가 기준이 다른 terminal 재전송에 성공 응답을 주던 문제는 저장된 기준과 비교해 거부하며,
  Archive/Legacy가 바뀌지 않는 API 회귀로 보강했다.
- 최초 full LegacyResult 형식에는 `referencePopulationId`가 필수이며 null은 유효한 과거
  미탑재 결과다. 필드 자체가 없는 JSON은 지원한 적 없는 형식이므로 fail-closed를 유지한다.
  Legacy KV 자체가 없는 core-only Archive와 이미 저장된 hidden Legacy는 구분한다.
  전자는 첫 Legacy 파생 결과를 생성할 수 있지만 후자는 기존 기준과 hash를 유지한다.
- 선택 가능한 대표 엔딩 저장은 문서상 MAY다. 이번 최종 프로필은 계산된 기본 엔딩을
  표시하며, 사용자 선택 preference와 기기간 동기화를 구현했다고 주장하지 않는다.
