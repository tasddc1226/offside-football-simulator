# Phase 5 밸런스 재설계 실행 계획

상태: 실험·설계 중 (2026-09-05). 사용자가 밸런스 후속 분리 대신 이번 Phase 5에 포함하기로 결정했다.
PR #77은 검증이 끝나기 전까지 Draft로 유지하며 main에 병합하지 않는다.

## 변경 전 기준선

`phase5-population-2-registered-choices`의 4만 커리어 실행은 계속 보존한다.
등록된 콘텐츠와 실제 명령을 사용하는 유효한 **변경 전 기준선**이지, 새 밸런스의 합격 증거가 아니다.
실행 중인 번들·체크포인트를 바꾸거나, 유리한 seed만 추려 참조집단으로 사용하지 않는다.

실행은 54분 21초에 완료됐다. 전체 ICON 2건(0.005%), LEGEND 0건, REMEMBERED 7,687건(19.22%).
다만 후속 UI 검토에서 KEEP 거절 편향을 발견하여 공식 참조집단으로는 사용하지 않는다.
원본은 [별도 증거 manifest](evidence/phase5-baseline-v2/manifest.json)와 압축 파일로 보존한다.

- MF:1279: 20시즌, 11회 우승, 24,275분, Legacy 73 (92/76/100/24/53).
- DF:699: 20시즌, 13회 우승, 11,455분, Legacy 71 (100/58/100/26/51).
- 이적 때 감독 신뢰 40, 주장 관계 0, 팬 관계 30% 이월이 반복된다. 임대 복귀도 관계를 재설정한다.
- 주장 관계와 주장 직책은 다른 값이다. 관계 값 0을 곧바로 인성 실패나 리더십 부재로 해석하지 않는다.
- 낮은 출전은 성장 경험과 다음 선발 경쟁에 영향을 준다. 반면 장기성은 출전이 적어도 20시즌에 100에 도달한다.
- 기존 승격 태그와 Legacy의 실제 승격 원장이 서로 다른 조건을 사용한다. 두 의미를 같다고 표시하지 않는다.

## 실행 순서와 채택 기준

1. **원인 분리:** 같은 seed에서 계약 정책만 바꾼 paired replay로 이적·관계·출전·성장 차이를 기록한다.
   RNG/능력치/이벤트 성공을 강제로 바꾸지 않는다. 작은 진단 표본을 전체 분포라고 부르지 않는다.
2. **후보 평가식:** 현재 관계 수치와 커리어에 남긴 관계 성과를 구분하고, 실제 출전 노출과 전성기·지속성을
   함께 평가하는 후보를 실험한다. 단순 총점 가산, OVR 직접 가산, 분위수에 맞춘 역보정은 사용하지 않는다.
   서사는 기록된 사건·태그만, 장기성은 활동 근거를 평가한다. 우승 없는 고기여 경로도 유지한다.
3. **게임 경로:** 출전·성장·관계의 구조적 문제가 확인된 경우에만 새 룰셋 또는 명시적 버전 경계를 설계한다.
   Phase 3·4의 기존 로직을 무조건 바꾸거나, 기존 ruleset `1.0.0`의 재생 결과를 조용히 변경하지 않는다.
4. **버전 호환:** Legacy `1.0.0` 원본·정의·hash는 유지한다. 새 계산 정책은 별도 버전으로 관리하고,
   보관·가져오기·동기화에서 계산 버전과 참조집단을 함께 고정한다. 기존 결과의 자동 재채점은 하지 않는다.
5. **파일럿 → 전체 재생성:** 사전 고정한 seed/플레이 정책으로 작은 표본과 경계 사례를 검증한 뒤,
   확정된 생성기·정책 checksum을 고정하여 포지션별 10,000개를 다시 생성한다.
   원시 5축 점수·출전·우승·관계 진단도 남겨 총점만 보고 판단하는 일을 방지한다.
6. **인수:** 기능 회귀, 구버전 결과 보존, 포지션 공정성, 무관 경로, 실제 분포, UI/API/CI를 함께 통과한 뒤
   문서·PR 결과표를 갱신하고 main 병합 및 staging 배포 상태를 확인한다.

## 수치 목표와 주의점

기존 설계 목표(LEGEND 약 2%, ICON 약 8%, REMEMBERED 약 30%, 80점 이상 약 10%, 무관 중
80점 이상 약 3%)는 아직 충족하지 못했다. 표본 크기나 checksum 검증만으로 이 목표를 통과 처리하지 않는다.
`약`의 허용 편차와 모집단 분모(전체/장기/무관)는 최종 후보의 전체 배치 전에 명시해야 한다.
목표를 만족시키려고 표본을 사후 선별하거나 목표를 몰래 낮추지 않는다.

평균 점수 상승만으로 채택하지 않는다. 단기·벤치 경력이 무조건 고득점이 되지 않고, 같은 실제 성과의
포지션 간 점수 차이가 작으며, 좋은 선택·충분한 출전·관계 유지가 의미 있는 차이를 만드는지 확인한다.
모든 엔딩의 조건 fixture와 자연 실행에서 실제 발견한 엔딩 종류는 별도로 보고한다.

## 1차 후보 실험 — 채택 아님

`tooling/scripts/legacy-balance-probe.mjs`는 SHA로 고정한 기존 생성기를 계측하여 같은 커리어의
원본 평가와 후보 평가를 비교한다. 원본 번들을 수정하지 않으며 결과를 참조집단으로 발행하지 않는다.
후보는 기여의 커리어 평균/전성기 5시즌을 절반씩, 장기성을 실제 활동 연수로, 관계를 가장 강한
두 관계의 지속성과 전성기로 평가한다. 태그 서사는 COMMON/RARE/EPIC 8/20/35점 후보를 사용한다.
성장식이나 선수 능력치를 바꾼 실험이 아니다.

포지션별 seed 0..39, 요청 시즌 1..20 두 순환의 총 160개 비교:

| 포지션 | 기존 평균 | 후보 평균 | 후보 최고 | ICON/LEGEND |
| ------ | --------: | --------: | --------: | ----------: |
| GK     |     32.00 |     32.28 |        60 |       0 / 0 |
| DF     |     44.23 |     46.58 |        70 |       0 / 0 |
| MF     |     33.55 |     34.40 |        73 |       0 / 0 |
| FW     |     33.95 |     35.35 |        64 |       0 / 0 |

평균을 크게 올리지 않으면서 낮은 출전의 장기성 과대평가를 줄이는 효과는 있으나, 고득점 달성
경로와 분포 목표를 입증하지 못했다. **현재 후보를 최종 정책으로 승인하거나 활성화하지 않는다.**
도메인은 명시적인 `1.1.0` 후보 호출을 지원하되 기본값은 기존 `1.0.0`을 유지한다.
후보 정책의 최종 고정은 별도 인수 후이며, 일반 플레이에서 기존 결과를 자동 재평가하지 않는다.

### 선택 경로 진단

- 6개 20시즌 seed를 잔류 우선 정책과 비교하면 관계 점수는 모두 상승했지만 출전 시간은
  네 경로에서 감소했다. 잔류만으로 선발/성장 문제가 해결되지는 않는다.
- 전술식의 style/archetype 비중만 0.60/0.40에서 0.85/0.15로 바꾼 작은 paired 비교는
  GK·DF에서 오히려 출전을 줄였다. 이 일괄 변경은 채택하지 않는다.
- 같은 6개 seed의 시즌말 selection을 확인하면, 일부는 건강한 벤치지만 일부는 부상·복무가
  원인이었다. GK:127, FW:31은 경쟁자 OVR이 10~20점 높은 강팀에 오래 머물렀다.
  모든 낮은 출전을 선발식 오류로 취급하지 않는다. 시즌말 표본을 전체 경기 통계로 부르지 않는다.
- 기존 표본의 KEEP 거절은 실제 UI에서 선택할 수 없는 행동이었다. v3는 확인만 수행한다.
  같은 160개를 KEEP 확인으로 바꾼 후보 최고점은 GK 62 / DF 70 / MF 73 / FW 66이다.
  표본 정책 오류는 수정했으나 이 수정만으로 밸런스 목표를 달성했다고 보지 않는다.

다음 판단은 공개 제안 조건을 보고 출전 기회를 선택하는 경로와 임의 계약 선택의 차이를
작게 비교한 뒤 내린다. 검증 전 임의로 성장률·선발 보너스를 올리지 않는다.

출전 기회 우선 계약·같은 그룹 감독 역할 수락을 적용한 32개 20시즌 paired 비교에서는
기존 점수식 기준 평균이 GK 44.5→56.5, DF 64.8→67.3, MF 46.0→54.1, FW 50.3→55.1이었다.
평균 출전 비율도 각각 6.3→19.8%, 22.4→33.3%, 7.2→19.0%, 13.8→28.3%로 개선됐지만
개별 악화 사례가 있고 최고점은 74였다. 이 정책은 시장과 역할 선택을 함께 바꾸므로
시장만의 인과 효과나 최적 플레이의 상한으로 해석하지 않는다.
실제 플레이 선택의 대표성을 먼저 개선할 근거이며, 분포 목표 합격이나 신규 점수 정책 채택의 증거는 아니다.

## 테스트 유지 범위

사용자 지침에 따라 최소한의 필요한 검증만 유지한다.

- 상시 CI: 점수 범위·핵심 경계, 같은 입력의 재현성, 구버전 결과 보존, 은퇴 저장/복구와 핵심 화면 흐름.
- 밸런스 배치: 정책 확정 시 별도 실행하고 보고서·생성기 checksum으로 증거를 보관한다.
  4만 커리어를 매 PR마다 재생하거나 각 seed의 총점·세부 통계·엔딩을 영구 snapshot으로 고정하지 않는다.
- 배포 산출물: 생성·발행 시 원본 전체를 검증하고, 런타임에서는 형식·버전·무결성을 확인한다.
  같은 4만 행에 대한 수십만 개 assertion을 상시 단위 테스트에 중복 추가하지 않는다.
- UI: 핵심 동작·저장 여부 중심으로 검증하고, 사소한 문구·CSS 내부 구조·애니메이션 시간을 고정하지 않는다.
- 분포 목표는 밸런스 판단 지표다. 작은 무작위 표본의 정확한 비율을 CI 실패 조건으로 삼지 않는다.
