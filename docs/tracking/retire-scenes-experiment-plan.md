# T-11-669 은퇴 화면 실험: 대표 장면 · 내 구단 다음 행동 (기본 꺼짐)

상태: 구현 · 검토 중. 운영 값은 0(꺼짐)이며, 켜는 것은 별도 결정이다. 이 문서는 정본이 아니라 실험 설계다(결정은 `decision-log.md`).

## 무엇을 비교하나

- **대조군**: 지금 은퇴 화면 그대로(리포트 · 보유 카드 · 첫 은퇴의 '내 구단 만들기' · 새 커리어 · 명예의 전당 · 공유).
- **실험군**: 리포트 맨 위에 카드 하나를 더한다.
  - **대표 장면 최대 3개.** 저장된 시즌 기록(`GameState.career`)에서 출전 1경기 이상인 시즌만 본다.
    - 첫 출전 기록: 출전 기록이 있는 첫 시즌(고교 · 프로를 가리지 않아 '프로 데뷔'라고 부르지 않는다).
    - 최고 평점 시즌: 평점이 가장 높은 시즌(같으면 앞 시즌, 평점 0이면 뺀다).
    - 마지막 출전 시즌: 출전 기록이 있는 마지막 시즌.
    - 같은 시즌이면 하나만 남기고 시즌 순서로 둔다. 출전 시즌이 없으면 장면 없이 다음 행동만 보인다.
    - 글은 연도 · 나이 · 구단 · 경기 · 골 · 도움(수비 · 골키퍼는 무실점) · 평점, 펼치면 리그 · 순위 · OVR · 그 시즌 우승 · 수상만. 원인 · 감정 문장을 만들지 않는다.
  - **내 구단 다음 행동 하나.** 기기 안 업로드 상태와 계정 확인 결과로만 고른다(서버에 새로 묻지 않는다).

    | 업로드           | 계정       | 안내                                           | 버튼                              |
    | ---------------- | ---------- | ---------------------------------------------- | --------------------------------- |
    | 올라감           | 로그인     | 내 팀 편성에서 이 선수를 고를 수 있어요        | 내 팀 편성 열기(팀 화면)          |
    | 올라감           | 로그인 전  | 로그인하면 이 선수로 팀을 꾸려 겨뤄요          | 로그인하고 팀 꾸리기(구단주 화면) |
    | 올라감           | 확인 못 함 | 서버에 올라간 은퇴 선수는 보유 선수로 모여요   | 내 구단 보기                      |
    | 대기 · 보내는 중 | 무엇이든   | 올리는 중이에요. 올라가면 보유 선수에 들어가요 | 내 구단 보기                      |
    | 거절             | 무엇이든   | 올라가지 않아 내 구단에서 쓸 수 없어요         | 없음(사유 · 재시도는 공유 바)     |

  - 실험군은 같은 길을 두 번 두지 않게 맨 아래 '내 구단 만들기'를 뺀다. 새 커리어 · 명예의 전당 · 공유 · 보유 카드는 그대로다.
- 선정 · 판정 · 문구는 `packages/app-core`(`retireExperiment.ts` · `retireExperimentView.ts` · `i18n/{ko,en,ja,zh}/retireExp.ts`),
  화면은 웹 `apps/web/src/ui/RetireExp.svelte`(실험군일 때만 받는 청크) · 앱 `apps/mobile/src/screens/retired/RetireExp.tsx`.

## 배정

- **단위**: 서버 프로필 ID. 기기 난수 · 은퇴마다 다시 뽑기를 쓰지 않는다. 같은 계정이면 웹 · 앱이 같은 코드로 같은 군이 된다(익명 프로필은 기기마다 다르다).
- **방식**: 해시 두 개를 따로 쓴다(FNV-1a, 실험 이름 `retire_scenes_v1`을 섞음).
  - 참여 해시: 0~9999 칸이 `2 × 비율 × 10000`보다 작으면 실험 참여.
  - 군 해시: 비율과 상관없이 50:50으로 고정.
  - 그래서 실험군 ≈ 비율, 대조군 ≈ 비율, 나머지는 실험 밖이다. **비율을 바꿔도 이미 들어간 사람의 군은 뒤집히지 않는다**(내리면 실험 밖으로 빠질 수만 있다). 이미 남은 결과 귀속도 노출 때 군으로 남는다.
- **비율 키**: 서버 밸런스 `retireExpShare`(기본 0, 0~0.5, 0.05 단위). 0.5면 참여 100%(50:50).
- **실험 밖(지금 화면, 실험 계측 없음)**: 비율 0 · 서버 값을 못 받음 · 프로필 ID 없음(세션 없음) · 계정 확인 3초 초과 · 5분 지난 계정 캐시를 다시 확인하지 못함.
- **적용 시점**: 게임 엔진은 이 키를 읽지 않는다. 앱 시작 때 받는 서버 최신 값(`latestBalance()`)을 은퇴 화면을 열 때 바로 읽는다. 커리어에 저장된 `GameState.bal`(다음 시즌부터 적용)과 무관해 세이브를 바꾸지 않는다. 다만 운영 도구에서 값을 바꾸면 새 밸런스 버전이 생겨 진행 중 커리어가 다음 시즌에 그 버전 번호를 받고(게임 수치는 같다) 공개 밸런스 이력에 '은퇴 화면 실험 비율'로 남는다.
- **요청**: 비율이 0이면 은퇴 화면이 계정을 새로 묻지 않는다. 켜져 있으면 5분 메모된 계정 확인(`GET /v1/profile`)을 쓰고, 캐시가 없거나 5분이 지났을 때만 다시 묻는다.

## 켜는 방법(별도 승인 뒤)

설정 → 운영 도구 → 밸런스 → '화면 실험' 묶음의 '은퇴 화면 실험 비율'을 새 버전으로 올린다. 끄려면 0으로 새 버전을 낸다. 이 PR은 운영 값을 바꾸지 않는다.

## 측정

이벤트(웹 GA4 · 앱 Firebase 같은 이름, 공통 필드 `exp_id=retire_scenes_v1`, `arm=treatment|control`). 이용 분석에 동의한 사람만 보내고 기기에 귀속 기록(`offside_retire_exp_v1`)을 남긴다. 동의를 거두면 그 기록을 지운다. 동의하지 않았으면 저장도 하지 않는다.

| 이벤트                  | 언제                                                                                                   | 필드                                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `retire_exp_exposure`   | 군이 정해지고 화면에 그린 뒤, 이용 분석이 준비됐을 때 커리어마다 한 번(대조군도 같은 이름 · 같은 필드) | `retire_order`(first · repeat), `upload_state`, `account_state`(member · guest · unknown), `scene_count`(0~3, 두 군 다 계산), `ready_ms` |
| `retire_exp_scene_open` | 실험군이 장면을 펼침                                                                                   | `scene`                                                                                                                                  |
| `retire_exp_cta_click`  | 실험군 다음 행동 · 대조군 '내 구단 만들기'(`legacy_club`)                                              | `cta`                                                                                                                                    |
| `retire_exp_leave`      | 화면을 떠남(nav) · 앱 · 탭이 가려짐(hide)                                                              | `dwell`(lt10 · 10_60 · gt60), `interacted`(1 · 0), `via`                                                                                 |
| `retire_exp_outcome`    | 노출 뒤 7일 안의 실제 완료 경계(아래), 종류마다 한 번                                                  | `outcome`, `retire_order`, `elapsed`(lt1h · 1h_24h · 1d_7d)                                                                              |
| `retire_exp_error`      | 장면 고르기 실패(화면은 장면 없이 계속)                                                                | `stage`                                                                                                                                  |

- 노출이 나가기 전에는 장면 · 다음 행동 · 떠남을 보내지 않는다. 동의 · 태그 · SDK가 늦게 준비되면 그때 노출을 보내고, 그 전 클릭은 되돌려 보내지 않는다(분모 없는 상호작용 금지).
- **결과(outcome)는 화면 클릭이 아니다.**
  - `next_play`: 방금 은퇴한 커리어가 아닌 커리어에서 리그 반기 구간을 경기 1번 이상 치르고 끝냄(`play_complete`와 같은 조건).
  - `team_save`: 서버가 팀 저장(PUT `/v1/owner-team`) 성공을 돌려줌.
  - `club_match`: 서버가 구단 경기 결과를 돌려줌(바로 경기, 장면 경기의 마지막 장면 · 마감). 장면 경기 시작 응답은 아니다.
- **계정 경계**: 노출 때 계정 키와 지금 계정 키가 같다고 확인될 때만 귀속한다. 구단 결과는 요청을 보낼 때 계정 키도 같아야 한다. 계정이 바뀌거나 로그아웃 · 삭제되면 이전 귀속을 지운다. 계정을 아직 모르면 귀속을 미룬다.
  계정 키는 프로필 ID의 짧은 FNV 해시로 **기기 안 계정 구분용**일 뿐 익명화가 아니며 기기 밖으로 보내지 않는다.
- **보내지 않는 것**: 선수 이름 · 구단 기록 원문 · 커리어 ID · 프로필 ID · 계정 키.

### 지표

- **주요**: 노출 대비 `next_play` 도달률(7일), 노출 대비 `club_match` 도달률(7일). 군별 비교. 기본 분석은 `retire_order=first`(첫 은퇴), 기존 이용자(`repeat`)는 따로 본다. 웹(`client_platform=web`)과 앱(Firebase 스트림)은 나눠 본다.
- **보조**: `team_save` 도달률, 실험군 장면 펼침률 · 다음 행동 클릭률, `upload_state` · `account_state`별 나눔, 공유(아래).
- **가드레일**
  - 로딩: `ready_ms`(은퇴 화면을 연 때부터 군이 정해져 화면에 그린 때까지, 계정 확인 대기 포함)의 군별 p95.
  - 오류: `retire_exp_error` 비율, 노출의 `upload_state=rejected` 비율.
  - 즉시 이탈: `retire_exp_leave`에서 `dwell=lt10`이면서 `interacted=0`인 비율.
  - 클릭률만으로 성과를 말하지 않는다. 클릭 · 화면 진입을 경기 성공이라 부르지 않는다.
- 표본 수 · 최소 검출 효과 · 기대 효과는 정하지 않았다. 켜기 전에 지금 은퇴 이용자 수 · `next_play` 기준선을 보고 정한다. 7일 지표는 7일이 지난 노출만 본다.

### 공유와 T-11-668

- 공유 버튼은 기존 `ShareBar`를 그대로 쓰고 이 작업은 손대지 않는다. 공유 이벤트(미리보기 · OS 공유 · 복사 · 취소 · 실패)의 정의는 T-11-668(`@offside/app-core/shareMeasurement`, PR #1104)이 맡는다.
- 이 작업은 668을 가져오지 않고 origin/main에서 빌드된다. 군별 공유 분석은 668이 먼저 머지된 뒤 GA4 · BigQuery에서 같은 사용자 · 세션의 `retire_exp_exposure`(arm)와 668 공유 이벤트를 이어 본다. 가짜 공유 성공 이벤트를 따로 만들지 않는다.

## 테스트

- 앱: 타입 검사만. 실제 기기 · 시뮬레이터에서 화면을 확인하지 않았다(아래 한계).

## 남은 결정 · 한계

- 켤지, 비율(예: 0.1 · 0.25 · 0.5), 기간, 표본 · 최소 검출 효과는 오너 결정이다.
- 앱 화면은 실제 기기에서 보지 않았다. 앱 JS 변경이라 운영 배포 때 OTA로 나가며, 꺼져 있는 동안은 화면이 바뀌지 않는다.
- 웹 · 앱 같은 배정은 같은 프로필(로그인 계정)일 때만이다. 익명 프로필은 기기마다 달라 같은 사람이 다른 군일 수 있다.
- `next_play`는 기기 단위 진행이라 앱에 리그 반기 완료 신호를 처음 붙였다(이 실험에만 쓰고 앱 `play_complete`는 보내지 않는다).
- 웹 계측의 동의 · 태그 전체 흐름은 격리 GA4 빌드 e2e(`E2E_ANALYTICS=1`)로만 볼 수 있어 이 PR의 e2e는 화면 동작만 본다. 계측 규칙은 단위 테스트가 고정한다.
- 대표 장면 공유 카드(이야기형 공유물)는 이 작업 범위가 아니다.
