# 시즌1 고령 선수의 조건부 현역 연장 기획

> 상태: 구현 전 기획안 · 문서 PR
> 조사 기준: 2026-09-29 원격 main `c1164806aaa19c5606e87d9d25e4de73f647ded2`
> 결정된 방향: 시즌1부터 은퇴 상한을 높인다
> 권고안: 은퇴 나이 상한 45세, 41~44세에는 조건부 현역 연장
> 45세 및 아래 수치·출시 판정 기준은 제안값이며 구현·배포 완료를 뜻하지 않는다

## 1. 목표와 적용 범위

41세가 되었어도 팀에 기여할 수 있는 선수가 한 시즌 더 도전할 수 있게 한다. 모든 선수가 45세를 채워야 유리한 구조보다, 경기력과 계약에 따라 다른 나이에 커리어를 마치는 경험을 목표로 한다.

첫 단계는 기존 OVR·최근 시즌 출전/평점·구단 전력·계약을 활용한다. 새 신체 수명 능력치, 감독 AI, 은퇴 번복, 코치 전직, 고령 전용 이벤트 트리는 만들지 않는다. 기존 은퇴 기록과 프리시즌 세이브를 소급 변경하지 않는다.

### 운영 기록: 관측과 한계

2026-09-29 이 기획 직전 운영 D1 읽기 전용 조회 결과:

- 은퇴 커리어 4,340건, 최고 은퇴 나이 41세
- 41세 은퇴 1,358건(전체 은퇴의 약 31.3%), 40세 221건, 39세 169건
- 38세 539건, 37세 145건, 36세 140건
- 유저 수가 아니라 커리어 수다. 조기 종료·테스트·자동화 의심 기록을 분리한 표본은 아니다
- 서버에 저장된 기록이며 모든 로컬 플레이를 관측한 값은 아니다. 강제 은퇴 원인별 이벤트는 집계하지 않았으므로 1,358건 전부가 연장을 원했다고 해석하지 않는다
- 조회는 별도 SELECT 호출이며 단일 트랜잭션 스냅샷이 아니다

재현할 최소 집계 SQL(운영 조회 시점에 따라 값은 바뀜):

```sql
SELECT status, COUNT(*) AS careers, MAX(retire_age) AS max_retire_age
FROM careers GROUP BY status;
SELECT retire_age, COUNT(*) AS count
FROM careers WHERE retired_at IS NOT NULL
GROUP BY retire_age ORDER BY retire_age DESC;
```

관련 분석: [9월 29일 밸런스 보고서](../analysis/season2-balance-analysis-2026-09-29.md). 해당 보고서의 시점·분모와 위 전체 은퇴 집계를 혼합하지 않는다.

## 3. 권고 규칙: 45세 은퇴 상한

**상한 45는 44세 시즌까지 출전하고, 결산 뒤 45세에 은퇴한다는 의미다.** 45세 시즌을 끝까지 뛰게 하려면 은퇴 상한은 46이 되어야 하므로 이번 안에 포함하지 않는다. 최대 추가 선수 시즌은 41·42·43·44세의 4시즌이다.

| 시장 시점 나이          | 권고 동작                                                                      |
| ----------------------- | ------------------------------------------------------------------------------ |
| 37세 이하               | 현행 계약/오퍼/은퇴 선택 유지                                                  |
| 38~40세                 | 현행 유지; 이 구간의 재계약 제한 완화는 별도 실험으로 분리                     |
| 41~44세, 잔여 계약 존재 | 기존 계약의 잔류 권리 유지, 자발적 은퇴 선택 제공; 계약을 강제로 삭제하지 않음 |
| 41~44세, 계약 만료      | 고령 재계약 평가와 기존 이적 제의를 함께 제시; 성립한 새 계약은 1년            |
| 41~44세, 제안 없음      | 구단 제의 부재를 이유로 은퇴; 무조건 하부 리그 구제 계약을 만들지 않음         |
| 45세 이상               | 새 시즌 시작 금지, 은퇴 안내; 계약 잔여 때문이 아니라 규칙상 상한임을 설명     |

### 고령 재계약: 최초 실험값

현재 구단과 계약이 끝난 41~44세에게만 적용한다. 아래는 확정 밸런스가 아닌 시뮬레이션 시작점이다.

- OVR ≥ 현재 구단 전력−7: 기존 재계약 능력 기준 재사용
- 직전 완료 비군복무 시즌 공식전 10경기 이상, 평균 평점 6.5 이상
- 최근 기록이 없거나 평점이 비정상이면 새 고령 재계약을 생성하지 않고 기존 이적 경로만 검토
- 통과하면 1년 재계약 선택지를 확정 제공; 추가 동전 던지기식 은퇴 확률은 넣지 않음
- 이적 제의는 기존 평가·나이 감점 유지, 생성된 고령 오퍼의 계약 기간을 1년으로 제한
- 새 계약의 기간은 은퇴 상한까지 남은 시즌 수를 넘지 않음. 기존 저장 계약은 소급 축소하지 않음
- ‘로테이션/백업’은 실제 출전 로직과 연결되는지 확인 전까지 보장 문구로 쓰지 않음. `offerFrom.role` 표시만 바꾸는 구현은 제외
- 부상·컨디션은 기존 경기력/출전 감소를 통해 우선 반영. 별도 부상 은퇴 확률은 1차에서 제외

10경기/6.5는 GK, 짧은 리그, 벤치 선수에게 불리할 수 있으므로 포지션·리그별 통과율을 비교한다. 문제가 크면 출전 수를 소속 리그 경기 수 대비 비율로 바꾸는 대안을 실험하고, 출시 전에 하나로 확정한다.

## 4. 시즌1 경계와 세이브 호환성

현재 `service_seasons.ts`의 시즌1 시작은 2026-10-06 00:00 KST다. 이 문서는 개막 일정을 변경하지 않는다.

권고하는 대상은 **시즌1 개막 후 새로 생성하고, 서버에서도 시즌1로 등록된 커리어**다. 프리시즌에 만들고 첫 업로드만 개막 뒤에 한 선수는 자동으로 새 규칙을 얻지 않는다. 기존 서비스 시즌 분류는 유지하되 은퇴 규칙 버전을 별도 고정한다.

구현 제안:

1. 새 커리어에 은퇴 정책 식별자(가칭 `retirementPolicy`) 저장. 기존/필드 없는 세이브는 프리시즌 정책으로 마이그레이션
2. 시즌1 개막 후 서버 시즌 확인을 거쳐 만든 커리어만 새 정책 승인. 클라이언트 시각만으로 승인하지 않음
3. 현재는 첫 시즌 업로드 시 소속이 정해지므로, 최초 등록 응답과 정책 저장을 연결할 계약 설계가 필요. 응답 전에는 프리시즌 정책으로 진행하고 승인 후 1회 고정
4. 오프라인 신규 생성·구버전 앱·응답 유실·중복 업로드는 안전하게 구정책 유지. 승인이 필요하면 생성 화면에 온라인 확인 필요를 안내
5. 이후 선수 시즌 변경, 서비스 시즌 변경, BAL 갱신, 재접속은 정책을 바꾸지 않음. 서버 저장값을 기준으로 업로드 정책 불일치 처리
6. 41세 이상 기록이 있는 새 정책 세이브를 구버전 코드가 읽을 때 강제 은퇴시키지 않도록 최소 지원 버전 확인과 복구 안내 마련

정책 식별자는 새 저장 필드이므로 `save.ts` 마이그레이션, API 계약, 서버 저장·검증, 업로드 큐 재시도를 함께 구현해야 한다. 임의 요청 위변조를 완전히 막는 설계로 주장하지 않는다. 현재 클라이언트 시뮬레이션 신뢰 모델 내에서 정책 불일치와 정상 기록 손실을 방지하는 범위다.

## 5. 점수·순위·보상의 영향

현행 LS는 출전·골·도움·무실점·우승·개인상·대표팀 기록 등을 누적한다. 최고 OVR도 보존된다. 4시즌 연장은 추가 득점과 트로피를 얻을 기회를 늘리므로 단순히 노화가 있다는 이유로 점수 영향이 작다고 볼 수 없다.

1차 권고는 LS 공식 유지 + 시즌별 비교다. 나이가 많다는 이유로 점수를 일괄 삭감하거나 기존 커리어 점수를 재계산하지 않는다. 장수 칭호에 추가 LS 보너스도 주지 않는다.

다만 시즌1 순위가 분리되어 있어도 전체 명예의 전당·서버 기록·영구결번·구단/팀 보상에는 영향을 줄 수 있다. 아래를 출시 전 비교한다.

- 평균/중앙값/p90/p99 LS와 기존 최고 칭호 도달률
- 41세 시점 대비 최종 LS 추가분, 추가 우승·개인상·대표팀 대회 기여
- 포지션/성장 특성별 순위 구성, 특히 GK 장수와 FW 득점 누적
- 은퇴 후 팀 선수 활용과 최고 능력치 보존, 반복 커리어당 보상 및 플레이 시간
- 전체 명예의 전당에는 정책 또는 시즌을 식별할 수 있는 설명 제공; 구기록을 소급 낮추지 않음

영향이 크면 연장 적격 조건이나 노화 곡선을 재검토한다. LS 공식을 바꿔야 한다면 별도 점수 버전·서버/클라이언트 동일 계산·과거 기록 보존 기획으로 분리한다.

## 6. 검증 실험과 출시 기준

아래 실험은 **이번 문서 PR에서 수행하지 않았다**. 구현 PR의 검증 요건이다.

`tooling/fulltime-sim`이 실제 엔진을 import하므로 동일 시드·초기 조건·행동 정책으로 A/B/C를 비교한다.

- A: 현행 프리시즌 41세 상한
- B: 상한만 45세로 바꾼 대조군
- C: 45세 상한 + 위 조건부 1년 연장
- FW/MF/DF/GK × 조기완성/일반/대기만성 × 균형/포지션 특화 훈련 × 상위 구단/출전 우선 이적 정책을 균등 표집
- 세부 포지션 적용군도 별도 보고. 각 기본 셀 최소 200개 공통 시드, 총 9,600개 커리어/안에서 시작
- 41세 도달 전까지 A/C RNG와 상태가 같은지 확인. 정책 차이 이후에는 단순 동일 시드가 동일 미래 난수를 보장하지 않으므로 분기 전 상태 복제 비교를 추가
- 41세에서 자발적으로 은퇴한 분기와 연장한 분기의 추가 플레이 시간·점수·보상도 측정

제안하는 조정 신호(실측 후 확정):

| 지표               | 검토 기준                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| 나이/동기화 정합성 | 45세 이후 새 시즌 0건, 정상 기록 손실/점수 잘림 0건                                               |
| 구정책 회귀        | 동일 시드 프리시즌 결과 변경 0건                                                                  |
| 장수 희소성        | 41세 도달자 중 45세 은퇴 비율 5~20%를 최초 목표로 측정; 반드시 맞추려고 강제 추첨을 추가하지 않음 |
| LS 상승            | 전체 중앙값 +10% 또는 p99 +15% 초과 시 조건/경제 재검토                                           |
| 집단 불균형        | 포지션·특성별 생존율과 LS 상승 차이 보고; 평균 하나로 통과시키지 않음                             |
| 유저 선택          | 현역 연장/은퇴 동등한 선택지, 강제 제의 없음 사유와 상한 사유 구분                                |

숫자 목표는 출시 보증이 아니다. 표본 수·신뢰구간·실패 사례를 함께 제출하며, 조건이 미달되면 상한 숫자만 먼저 운영에 켜지 않는다.

필수 회귀 사례: 40세 결산→41세 시장, 44세 결산→45세 은퇴, 45세 직접 시작 차단, 계약 잔여/만료/오퍼 없음, 재계약 경계값, 병역·전역 경로, 로드/시장 재진입 시 재추첨, 구세이브, 서비스 시즌 경계 전후 및 지연 업로드, 오프라인 생성, 중복 은퇴 전송, 서버가 마지막 시즌+1로 계산한 은퇴 나이, 공유 화면·팀·칭호 정합성.

## 7. 구현 분할과 운영 전환

1. 계약/세이브 PR: 정책 식별과 서버 승인·호환성·경계 테스트
2. 엔진 PR: 정책별 상한, 고령 재계약, 1년 계약, 상한 도달 사유와 새 시즌 시작 방어
3. 분석 PR: A/B/C 결과, 적격 기준 확정, 점수·팀 보상 영향 및 출시 판정
4. 화면/출시 PR: 남은 계약과 연장 조건 안내, 은퇴 사유, 최소 앱 버전, 운영 공지

서버가 새 정책·기록을 먼저 수용한 뒤 클라이언트를 배포하고, 신규 커리어 승인을 개막 시점부터 활성화한다. 배포된 커밋/자산과 실제 44세 시즌 업로드→45세 은퇴 read-back을 확인한다. main 병합만으로 적용 완료라 하지 않는다.

문제가 생기면 신규 정책 승인을 중단한다. 이미 연장 중인 선수를 구정책으로 돌려 41세 강제 은퇴시키지 않고, 새 정책 reader와 업로드 호환성을 유지한다. 운영 데이터 삭제·재작성은 이 기획의 범위가 아니다.
