# 카드 바치기 과제 (T-11-374)

2026-10-17 초안, 같은 날 1차 구현(PR #780, 배포 전). 아래 "1차 구현에서 정한 것"이 앞 절의 초안보다 우선한다.
수치는 모두 시작값이다.
같은 날 정리한 도파민 콘텐츠 우선순위의 4번이다(1 결과 공개 연출, 2 시즌 1 특별 카드, 3 강화 T-11-373, 5 랭크전).

## 한 줄 요약

매주 바뀌는 과제에 조건에 맞는 은퇴 카드 N장을 내면, 카드는 사라지고 리롤권 · 잠재력 강화권 · 스카우트권 · 강화 재료 · 구단주 칭호를 받는다.
쓸 곳 없이 쌓인 하위 카드에 쓸모를 주고, 이적시장 하위 카드 수요를 만든다.

## 배경

- 구단주 카드는 은퇴할 때마다 하나씩 늘지만 쓰는 곳은 선발 11자리 · 감독 칸 · 판매 · 방출뿐이다. 오래 한 구단주일수록 선발에 못 드는 카드가 쌓인다.
- 방출(`releaseCards`)은 **직접 키운 카드만** 된다(`careers.profile_id = 나`). 이적시장에서 산 카드는 다시 파는 것 말고는 처분할 길이 없다.
- 이적시장 하루 거래는 약 100건이고 가격/가치 평균은 1.3~~1.5배다(2026-10-10~~17). 하위 카드는 등록이 많아도 잘 안 팔린다.
- 라운지 채팅과 리뷰에 "구단 자금이 쌓이는데 쓸 곳이 없다", "이벤트 · 할 거리를 더"라는 요청이 반복된다.

## 레퍼런스

FIFA 얼티밋 팀의 스쿼드 빌딩 챌린지(SBC). 조건(같은 리그 n장, 팀 평점 이상, 케미 이상)에 맞는 카드 묶음을 내면 팩 · 특별 카드를 받는다.
가져올 것은 세 가지다.

1. **조건 퍼즐:** 무엇을 낼지 고르는 재미. 카드를 "가치"가 아니라 "조건에 맞는가"로 다시 보게 된다.
2. **기한과 교체:** 이번 주에만 있는 과제라 들어올 이유가 생긴다.
3. **수요 창출:** 조건에 맞는 싼 카드를 시장에서 사 오는 흐름이 생긴다.

가져오지 않을 것: 유료 팩 보상, 보상 확률 뽑기(이 과제의 보상은 고정이다). OFFSIDE 리뷰의 별 5개 근거가 "과금 유도가 없다"라서다.

### 조건 종류

모두 `cards` · `careers`에 이미 있는 칸으로 서버가 SQL 한 번에 판정한다. 새 칸이 필요 없다.

| 조건               | 근거 칸                                | 예                               |
| ------------------ | -------------------------------------- | -------------------------------- |
| 포지션             | `cards.pos`(FW · MF · DF · GK), `dpos` | 골키퍼 2장                       |
| 국적               | `cards.nation`                         | 같은 국적 5장 · 한국 3장         |
| 최고 OVR 범위      | `cards.peak`                           | 최고 OVR 70~79만                 |
| 묶음 평균 최고 OVR | `cards.peak` 평균                      | 11장 평균 75 이상                |
| 레전드 점수        | `cards.legend_score`                   | 레전드 점수 600 이상 1장 포함    |
| 서비스 시즌        | `cards.service_season`                 | 시즌 0(사전 시즌) 카드 3장       |
| 경력               | `careers.trophies` · `caps` · `ballon` | 대표팀 출전 있는 카드 4장        |
| 이적 횟수          | `cards.transfers`                      | 이적시장에서 거래된 적 있는 카드 |
| 유형               | `careers.type` · `trait` · `foot`      | 왼발 3장                         |

`careers.last_club`(마지막 구단)으로 리그 조건을 걸 수 있지만, 구단 → 리그 대응을 서버에 둘지는 열린 질문이다.

### 보상 시작값

| 난이도    | 조건 수준                                  | 보상 예                              |
| --------- | ------------------------------------------ | ------------------------------------ |
| 쉬움      | 3~5장, 조건 1개, 하위 카드로 충분          | 리롤권 2장                           |
| 보통      | 5~7장, 조건 2개                            | 잠재력 강화권 1장 또는 강화 재료 3개 |
| 어려움    | 11장 또는 높은 평균 OVR · 레전드 점수 조건 | 스카우트권 1장 + 강화 재료 5개       |
| 시즌 과제 | 11장, 시즌 테마(예: 시즌 1 기념)           | 시즌 과제 칭호 + 스카우트권 2장      |

리롤권은 구단 자금 상점에서 이미 판다(`rerollPrice` 100억에서 시작해 같은 날 한 장마다 2배, 하루 3장 · 합 700억). 프리미엄 스카우트권은
한 주 1장 · 500억(`scoutPrice` · `scoutWeeklyCap`)이라, 과제 보상 스카우트권은 상점 상한 밖에서 한 장을 더 얻는 길이 된다.
쉬움 보상의 가치가 낸 카드 방출 가치 합보다 크게 높지 않도록, 쉬움은 "방출 3~5장 값 ≈ 리롤권 2장 값(첫 두 장 기준 300억)" 근처로 맞춘다. 정확한 값은 열기 전 운영 카드 가치 분포로 다시 잰다.

## 예시 과제 5개 (초안)

1. **수문장 모집(쉬움):** 골키퍼 카드 3장. 보상 리롤권 2장.
2. **국가대표 소집(보통):** 같은 국적 카드 5장, 그중 대표팀 출전이 있는 카드 2장 이상. 보상 잠재력 강화권 1장.
3. **중원의 일꾼(쉬움):** 최고 OVR 70~79 미드필더 4장. 보상 리롤권 2장.
4. **베스트 일레븐(어려움):** 11장, 포지션별 GK 1 · DF 4 · MF 3 · FW 3, 평균 최고 OVR 80 이상. 보상 스카우트권 1장 + 강화 재료 5개.
5. **창단 멤버의 유산(시즌 과제):** 시즌 0 · 시즌 1 카드 11장, 레전드 점수 800 이상 1장 포함. 보상 칭호 "유산을 바친 자"(가칭) + 스카우트권 2장.

## 서버 설계

### 표 (마이그레이션 1개)

- `card_exchanges`: 과제 정의. `id` · `name_json`(ko · en · ja) · `rules_json`(장수 · 조건) · `reward_json` · `max_claims` · `starts_at` · `ends_at` · `created_at`.
  `(starts_at, ends_at)` 인덱스. 운영 도구가 쓴다.
- `card_exchange_claims`: 낸 기록 한 번에 한 줄. `id`(요청 멱등 키) · `profile_id` · `exchange_id` · `careers_json` · `created_at`.
  `(profile_id, exchange_id)` 인덱스로 남은 횟수를 센다.
- `cards`에 `consumed_in`(낸 기록 id, null이면 아님)을 더한다. 사라진 이유가 방출인지 과제인지 구분하고, 자금 대조(방출 + 판매 − 영입 − 아이템 구매)에서 과제로 사라진 카드를 빼는 데 쓴다.

### 내기 (`POST /v1/exchanges/:id/claim`, 멱등 키 필수)

D1 batch 하나로 처리한다. batch는 하나의 트랜잭션이라 중간 문장이 실패하면 전부 되돌아간다.

1. `card_exchange_claims`에 줄을 넣는다. 과제가 열려 있고 내 횟수가 `max_claims` 미만일 때만(`INSERT … SELECT … WHERE`).
2. `cards`를 비운다: `owner_id = NULL, consumed_in = 이 기록 id`. 조건은 방출과 같은 가드(내 카드 · 잠금 아님 · 감독 아님 · 열린 등록 없음 · 숨김 아님)와
   과제 조건, 1번 줄이 있을 것.
3. 바뀐 카드 수가 요청 장수와 같은지 확인한다. 다르면 일부러 CHECK 위반 문장(`owner_items_qty_check`처럼 음수 수량)을 일으켜 batch 전체를 되돌린다.
4. 보상을 `owner_items`에 더하고(`ON CONFLICT … qty = qty + ?`), 칭호는 `owner_title_awards`에 `INSERT OR IGNORE`.
5. 남은 횟수와 받은 보상을 돌려준다.

묶음 조건(평균 OVR · 포지션 구성 · "그중 2장 이상")은 1번 문장의 `WHERE`에서 요청한 카드 묶음을 집계해 판정한다. 컵 선발 검사는
batch 전에 `checkCupListing`과 같은 함수로 한다. 같은 멱등 키로 다시 보내면 첫 응답을 돌려준다(`idempotency` 표).

### 읽기

- `GET /v1/exchanges`(이번 주 과제 목록): 모두에게 같은 부분(과제 정의)은 `edgeCached`, 키는 주 단위. 내 남은 횟수는 로그인한 요청에서만
  `card_exchange_claims`를 내 `profile_id`로 센다. 운영 도구에서 과제를 고치면 `purgeEdge`.
- 카드 고르기는 지금 내 카드 목록 응답을 그대로 쓴다. 카드마다 따로 조회하지 않는다. 조건 판정은 화면에서도 같은 순수 함수(`packages/contracts`)로
  미리 해서 맞지 않는 카드를 흐리게 보여 준다.

- 공개 가이드(`apps/web/scripts/seo.mjs` `GUIDE_SECTIONS`)와 FAQ에 카드 과제 단락을 더하고, 릴리즈 노트를 쓴다.

## 운영 도구

- "카드 과제" 화면: 과제 만들기 · 고치기(시작 전만) · 미리 보기(조건에 맞는 카드를 가진 구단주 수를 표본으로 보기). 운영 도구는 한국어로 둔다.
- 미리 보기 집계는 무거울 수 있어 피크(KST 19~24시)에는 막고, `cards_owner_season_idx`를 타는 범위로만 센다.

## 경제 영향

- **카드 공급:** 과제는 카드를 없애는 유일한 무상 경로다. 한 구단주가 한 주에 최대 3·3 + 5·2 + 11 = 30장 남짓을 없앨 수 있다. 하위 카드가 줄어 선발 · 시장 카드의 상대 가치가 오른다.
- **시장 수요:** 조건에 맞는 싼 카드를 사서 내는 흐름이 생긴다. 시장의 바닥 가격(가치 0.5배)이 실제 거래 가격이 될 수 있다.
  보상 가치가 "바닥 가격 × 장수 + 수수료 5%"보다 높으면 시장에서 사서 내는 것이 늘 이득이라 하위 카드 가격이 오른다. 이 정도는 의도한 범위다.
- **자금:** 보상에 자금이 없어 자금 총량은 늘지 않는다. 시장에서 사 오는 만큼 자금이 수수료로 빠진다.
- **산 카드 처분:** 방출이 안 되던 산 카드에 처분 경로가 생긴다.

## 테스트

- API: 조건 종류마다 맞음 · 안 맞음, 장수 모자람 · 남음, 잠금 · 감독 · 열린 등록 · 숨김 · 컵 선발 카드 거절, 남의 카드 거절, 횟수 초과 거절,
  같은 멱등 키 두 번 → 보상 한 번, 동시에 두 요청 → 카드 한 번만 사라짐, 마감 뒤 거절, 낸 카드가 명예의 전당 · 은퇴 기록에 그대로 남음,
  공개 과제 목록 GET이 쿠키가 있어도 `sessions` · `profiles`를 조회하지 않음.
- contracts: 조건 판정 순수 함수가 서버 SQL 판정과 같은 결과(같은 표본).
- 웹 e2e: 과제 칸 반복 이동 시 같은 API를 다시 부르지 않음, 내기 성공 · 실패 화면.
- 밸런스: 게임 진행 결과에는 영향이 없어 시뮬레이터 결과가 바뀌지 않는지만 확인한다(`golden.test.ts` 불변).

## 1차 구현에서 정한 것 (2026-10-17, PR #780)

열린 질문은 아래처럼 정하고 구현했다. 앞 절의 표 · API 설계와 다른 곳은 이 절을 따른다.

- **과제 정의는 코드에 둔다.** `packages/contracts/src/card-exchange-rules.ts`(zod 없는 서브패스 `@offside/contracts/card-exchange-rules`)의
  난이도별 묶음이 주마다 돈다(월요일 0시 KST, 주 키 `YYYY-MM-DD`). 과제 id는 `<주 키>-<난이도>`, 시즌 과제는 `s<시즌>-season`.
  `card_exchanges` 표와 운영 도구(만들기 · 미리 보기 · 내리기)는 이번에 만들지 않았다(후속).
- **목록 GET은 없다.** 웹 · 앱이 같은 함수(`exchangesAt`)로 이번 주 과제를 직접 계산한다. 서버는 내 낸 횟수
  `GET /v1/exchanges/me`(로그인 구단주, 1분 메모)와 `POST /v1/exchanges/:id/claim`(멱등 키 필수)만 연다.
  서버도 같은 함수로 과제가 지금 열려 있는지 확인하고, 아니면 404 `EXCHANGE_CLOSED`.
- **조건은 카드에 있는 값만 쓴다.** 포지션 · 포메이션 자리 수 · 최고 OVR 범위 · 평균 최고 OVR · 같은 국적 · 레전드 점수 1명 이상 ·
  시즌(0 프리시즌, `prev` · `now`) · 주발. A매치 · 트로피 · 거친 구단 · 리그 조건은 커리어 원본을 읽어야 해서 뺐다.
- **이번 시즌 선발 카드는 막는다**(방출과 같은 규칙, 409 `IN_LINEUP`). 컵 명단은 선발 안에 있어 따로 막지 않아도 된다.
- **직접 키운 카드도 아이템만 준다.** 방출 지급액 보전은 하지 않고, 확인 창에 "방출하면 받을 수 있던 자금을 받지 않는다"를 적는다.
- **칭호는 누적 칭호 하나.** `owner-exchange`(헌납의 명가 · House of Tribute · 献上の名門): 과제 10번(`owner_title_progress.exchanges`),
  등급 skilled. 기준 버전(TITLE_CRITERIA_VERSION)은 올리지 않는다(새 칭호라 기존 판정이 바뀌지 않는다).
- **표와 batch.** `card_exchange_claims`(id, profile_id, exchange_id, need, cards, reward_json, created_at, `(profile_id, exchange_id)` 인덱스,
  `cards IS NULL OR cards = need` CHECK)와 `cards.consumed_in`, `owner_title_progress.exchanges`. 내기는 한 batch다:
  ① 횟수 상한 안일 때만 claim INSERT ② 카드 소유자 비우기(잠김 · 감독 · 숨김 · 열린 판매 등록이면 건너뜀) ③ 바뀐 카드 수를 claim에 적어
  모자라면 CHECK로 batch 전체를 되돌림(409 `EXCHANGE_CARDS_GONE`) ④ claim이 있을 때만 아이템 지급. 낸 카드는 `released_at`을 비워 두어
  자금 감사(방출 지급액 합)와 섞이지 않는다.
- **화면.** 웹은 내 구단 화면 '카드 과제' 칸 → `owner/CardExchange.svelte`(열 때만 import, PopSheet). 앱은 `screens/owner/CardExchange.tsx`.
  목록 → 선수 고르기(잠김 · 판매 중 · 선발 · 조건 밖 표시, 맞는 선수로 채우기) → 확인 → 결과.
