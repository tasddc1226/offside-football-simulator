## 명령 규칙 (D-7·D-10 요약, 정본은 plan 문서)
- `CREATE_CAREER` payload `{ careerId, seed, simulationMode, rulesetVersion, contentPackVersion }` → `status 'DRAFT'`, `stage 'YOUTH'`, `age 17`, `currentStep 0`, `seasonPhase 'PRESEASON'`, 능력 20개 전부 0, `state/context/relationships` 전부 0, `player.draft` 6필드 null, `player.profile null`, `pending null`, `contract null`, `timeline []`, `rngState = seedRng(seed)`. checkpoint `CAREER_CREATED`, nextAction `'DECISION'`.
- `UPDATE_PLAYER_DRAFT` `{ draft: Partial<PlayerDraft> }`: DRAFT에서만. 준 필드만 검증·병합(검증 규칙 D-7). 실패 시 `VALIDATION_FAILED` details `{ field, reason }`. rng 소비 0. checkpoint `CAREER_CREATED`, nextAction `'DECISION'`.
- `CONFIRM_PLAYER` `{}`: DRAFT에서만, 6필드 전부 필요(`details.missing`). rng 소비 순서: 능력 jitter 20회(`ATTRIBUTE_KEYS` 순, `rollInt(rng, -2, 2)`) → `truePotential = rollInt(min,max)` → `scoutedMin = truePotential - rollInt(5,10)` → `scoutedMax = truePotential + rollInt(3,8)`(40~99 clamp). 능력 `= clamp(template + delta + jitter, 1, 99)`. `baseOvr = computeBaseOvr`. state/context/relationships는 배경 값 복사. `status 'ACTIVE'`, `currentStep 12`, `seasonPhase 'SETTLEMENT'`, `timeline += { revision, kind: 'CAREER_CONFIRMED', refId: null, age, step }`. checkpoint `CAREER_CREATED`, nextAction `'ADVANCE'`.
- `ADVANCE` `{ eligibleEvents: Array<{ eventId, version, weight }> }`: `status !== 'ACTIVE'` 또는 `pending !== null` → `VALIDATION_FAILED`(`details.reason`은 `'NOT_ACTIVE' | 'PENDING_DECISION'`). `eligibleEvents`는 eventId 오름차순이어야 하며 아니면 `VALIDATION_FAILED`(`'UNSORTED_ELIGIBLE_EVENTS'`), `weight`는 양의 정수. 1개면 그대로, 2개 이상이면 `rollInt(rng, 1, Σweight)` 한 번으로 누적 구간 선택 → `pending = { kind: 'EVENT', eventId, version }`, checkpoint `EVENT_OFFERED`, nextAction `'DECISION'`. 비어 있고 `seasonPhase !== 'SETTLEMENT'`면 현행 step 진행 유지. 비어 있고 정산 단계면 `VALIDATION_FAILED` `{ reason: 'NOTHING_TO_ADVANCE' }`.
- `RESOLVE_EVENT`: `pending.kind === 'EVENT'`이고 `eventId === payload.eventId && version === payload.definitionVersion`이어야 한다(아니면 `VALIDATION_FAILED` `'NO_PENDING_EVENT' | 'PENDING_EVENT_MISMATCH'`). 처리 후 `pending = null`, `timeline += { kind: 'EVENT_RESOLVED', refId: `${eventId}:${choiceId}:${outcomeId}` }`. 나머지(roll·효과·태그·resolvedEventIds)는 현행.
- 확정 전(DRAFT) 명령은 rng를 소비하지 않는다. DRAFT에서 `ADVANCE`·`RESOLVE_EVENT`는 `VALIDATION_FAILED`.
- `truePotential`은 오류 `details`·로그 문자열에 절대 넣지 않는다.

## golden fixture 재생성 절차
1. `career-01.json` 새 형식: `{ rulesetVersion: '1.0.0', contentPackVersion: '0.1.0', createCareer: { careerId, seed, simulationMode }, commands: [...] }`. commands는 순서대로 `UPDATE_PLAYER_DRAFT{ name '김서준', nationalityCode 'KR', preferredFoot 'LEFT' }`, `UPDATE_PLAYER_DRAFT{ position 'W', archetypeId 'inside-forward', backgroundId 'club-academy' }`, `CONFIRM_PLAYER{}`, `ADVANCE{ eligibleEvents: [{ eventId: 'EVT-CON-002', version: 1, weight: 10 }] }`, `RESOLVE_EVENT`(EVT-CON-002, choice A, outcomes는 `packages/content/packs/0.1.0/events/EVT-CON-002.json`의 A 결과를 복사하되 `addTags`에 `'진로_입단테스트'`를 넣는다 — T-1-002가 팩을 같은 값으로 고친다), `ADVANCE{ eligibleEvents: [{ eventId: 'EVT-CON-003', version: 1, weight: 10 }] }`, `RESOLVE_EVENT`(EVT-CON-003, choice B, 팩 B 결과 복사 + 각 결과 `addTags`에 `'입단테스트_완료'`와 `'테스트_성공'`(B1) / `'테스트_보통'`(B2)). 기존 Phase 0 step 진행 명령 12개는 제거한다.
2. golden JSON: `{ revision, stateHash, rngStateDraws, baseOvr, attributes, truePotential은 넣지 않음, scoutedPotential }`. 값은 새 구현으로 한 번 생성하고 PR 본문에 "golden 재생성 사유: D-7 명령 셋 변경"을 적는다.
3. 1,000회 결정론 테스트, `packages/fixtures` 복제 drift 테스트, `apps/api`의 Node·workerd 교차 해시 테스트(`cross-runtime-hash.test.ts`)가 새 golden으로 통과해야 한다.
4. 1,000회 결정론 테스트의 "5초 이내" 시간 예산은 워크스페이스 전체를 병렬로 돌릴 때 부하로 넘긴 적이 있다(2026-09-02, 단독 실행 0.7초). 예산 검사는 hash 일치 검사와 **별도 테스트**로 나누고 예산을 10초로 두되, 단독 실행 측정값(ms)을 PR 본문에 적는다.

## 제약
- domain은 외부 import·Node·브라우저 API 금지. 시간·난수는 입력으로만. `Math.random`·`Date` 금지.
- 반올림은 `Math.round` 하나(중간 반올림 없음). 부동소수 합은 가중치 표 순서(`ATTRIBUTE_KEYS` 순)로 더한다.
- 커밋 메시지는 `T-1-001: …`로 시작, 브랜치는 `T-1-001-…`.
- 서브에이전트 리뷰를 띄우지 않는다. Orca PR 게이트용 `/review:pr` 1회만 예외(`/simplify`·병렬 fork 금지).
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
