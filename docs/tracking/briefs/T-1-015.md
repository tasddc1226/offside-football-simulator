# T-1-015: content 조건 컨텍스트·적격 이벤트 선택기, 룰셋 스키마 ↔ domain 타입 바인딩

## 목표
`CareerState` 하나로 콘텐츠 팩에서 지금 제시할 수 있는 이벤트 목록(`eligibleEvents`, eventId 오름차순)을 만들 수 있다. 이것이 `ADVANCE` payload가 된다(plan D-10). 룰셋 Zod 스키마가 domain `Ruleset` 타입과 컴파일 타임에 묶이고, fixtures의 최소 룰셋과 content 1.0.0의 공통 항목이 같음을 테스트가 보증한다.

## 참조 명세
- 요구사항 ID: FR-EVT-001, ADR-004, ADR-005(2026-09-02 개정: engine-client·web → content 조건 평가기·로더 허용)
- 읽어야 할 문서(순서대로): `docs/tracking/phase-1-plan.md` **D-10, D-11, D-13**, `docs/development/04-event-engine.md`(트리거·제외 태그·쿨다운·followUp 의미), `packages/content/src/schema/condition.ts`(DSL 필드 목록·`evaluateCondition`·`ConditionContext`), `packages/content/src/schema/event.ts`, `packages/domain/src/types.ts`(머지된 T-1-001 타입)
- 정본 우선순위: docs/development > phase-1-plan.md > ADR

## 범위
- 만질 패키지·경로: `packages/content`(`src/`), 그리고 예외로 `packages/fixtures/src/ruleset-consistency.test.ts` 1개 파일 추가(fixtures → content 의존은 ADR-005 허용).
- 만들 것:
  1. `src/runtime/condition-context.ts`: `buildConditionContext(state: CareerState): ConditionContext`. 매핑(전부 명시, 없는 값은 아래 기본값):

     | DSL 필드 | 값 |
     |---|---|
     | `career.age` / `career.stage` / `career.tags` | `state.age` / `state.stage` / `state.tags` |
     | `career.currentRole` | `state.contract?.rolePromise ?? 'RESERVE'` |
     | `career.proSeasons` | `0`(Phase 1) |
     | `player.primaryPosition` / `player.positionGroup` / `player.archetypeId` / `player.baseOvr` | `state.player.profile`에서. profile이 null(DRAFT)이면 빈 문자열·0 |
     | `player.attributes.<key>` | `state.attributes[key]` 20개 전부 |
     | `season.step` / `season.phase` / `season.simulationMode` | `state.currentStep` / `state.seasonPhase` / `state.simulationMode` |
     | `season.tags` | `[]` |
     | `season.chapterHighlights` | `0` |
     | `season.stats.<stat>` | DSL이 아는 stat 이름 전부 `0` |

     DSL 필드 목록(`resolveConditionField`의 정적 목록 + 동적 prefix)에 있는 모든 경로가 컨텍스트에 존재해야 한다는 테스트를 둔다(목록이 늘면 실패해서 매핑 추가를 강제).
  2. `src/runtime/select-eligible-events.ts`: `selectEligibleEvents(pack: LoadedPack, state: CareerState): Array<{ eventId: string; version: number; weight: number }>`.
     규칙(순서대로 적용):
     - `status !== 'ACTIVE'` 또는 `pending !== null`이면 `[]`.
     - **followUp 우선**: `state.timeline`의 마지막 `EVENT_RESOLVED` 항목(`refId = eventId:choiceId:outcomeId`)의 outcome에 `followUps`가 있으면, 그 이벤트들 중 아래 기본 조건(단계·나이·제외 태그·해소 여부)을 통과하는 것만 돌려주고 트리거 조건은 보지 않는다. followUp 후보가 하나도 남지 않으면 일반 선택으로 넘어간다.
     - 일반 선택: `phases`에 현재 단계가 포함(`stage === 'YOUTH'`면 `'YOUTH'`, PRO면 `seasonPhase` 매핑: PRESEASON→PRESEASON, LEAGUE·CUP→IN_SEASON, TRANSFER_WINDOW→TRANSFER_WINDOW, SETTLEMENT→SETTLEMENT), `minAge <= age <= maxAge`(없으면 무시), `exclusionTags`와 `state.tags` 교집합 없음, `resolvedEventIds`에 없음(`repeatable`·쿨다운 필드가 스키마에 있으면 04 문서 규칙대로 적용, 없으면 1회성), `evaluateCondition(triggers, buildConditionContext(state)) === true`.
     - 결과는 eventId 코드포인트 오름차순, `version`은 정의의 `version`, `weight`는 정의의 `weight`.
  3. `RulesetSchema satisfies z.ZodType<Ruleset>`(domain 타입 import는 `import type`). T-1-002가 복제한 `ATTRIBUTE_KEYS` 목록은 타입 레벨 검사(`satisfies readonly AttributeKey[]` + 길이 20)로 바꾼다.
  4. `packages/fixtures/src/ruleset-consistency.test.ts`: `loadRuleset('1.0.0')`의 `inside-forward` 아키타입, `club-academy`·`school`·`street` 배경, `hangang-u18` 팀이 fixtures `ruleset-proto.json`의 같은 id 항목과 deep-equal. `offerRules`·`contractRules`·`scoutRange`·`draftRules`도 deep-equal.
  5. `src/index.ts` export 갱신.
- 만지지 말 것: `docs/`, 팩 데이터·룰셋 값, `packages/domain`, `packages/engine-client`, `apps/*`.

## 제약
- content는 domain을 타입으로만 import(ADR-005). 테스트 입력 `CareerState`는 리터럴로 만든다(`simulate` 호출 금지).
- 순수 함수. 시간·난수 사용 금지.
- 커밋 메시지는 `T-1-015: …`로 시작, 브랜치는 `T-1-015-…`.
- 서브에이전트 리뷰를 띄우지 않는다. Orca PR 게이트용 `/review:pr` 1회만 예외(`/simplify`·병렬 fork 금지).
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
