# T-7-033: 룰셋 1.7.0 / 콘텐츠 팩 0.6.3 운영 승격 준비

## 목표

운영 `svc_season_1`의 ID·기간·ACTIVE/non-test·`cs_season_1`을 유지하면서 신규 커리어 manifest를 ruleset `1.5.0` / content pack `0.6.0`에서 `1.7.0` / `0.6.3`으로 compare-and-set 승격할 코드·구성·가드·런북을 준비한다. 이 PR은 운영을 배포하거나 운영 D1을 변경하지 않는다.

## 참조 명세

- 요구사항: FR-SVC-001, FR-SAV-001, FR-CW-001~~005, TEST-E2E-006~~007, TEST-CW-001~~003, ADR-002~~003, D-61.
- 운영 정본: `docs/operations/production-release.md`.
- 출발 상태: `svc_season_1`, `ACTIVE`, `isTest=false`, `startsAt=2026-09-05T15:00:00Z`, `endsAt=null`, `challengeSetId=cs_season_1`, `1.5.0/0.6.0`.
- 승격 대상: 이미 등록된 `1.7.0/0.6.3`; `1.7.0`은 `1.6.1` 성장·은퇴 밸런스와 Legacy 1.2.0을 계승하고 리그 원장을 추가한다.

## 범위

- 수정: production release script·기존 테스트, API 승인 manifest 목록·기존 호환성 테스트, web 오프라인 폴백·로컬/비운영 seed·staging smoke/리허설, 이 브리프와 운영 런북.
- 보존: 최초 공개부터의 승인 pair `1.1.0/0.3.0`, `1.3.0/0.5.0`, `1.4.0/0.5.1`, `1.5.0/0.6.0`; 어느 승격 지점으로 롤백해도 오프라인 신규 커리어의 늦은 최초 sync를 허용한다. 서버에 이미 생성된 커리어는 생성 버전으로 후속 PUT을 계속한다.
- 거부: mixed pair, 승인 목록 밖 과거 버전, 다른 시즌 ID.
- 금지: 기존 ruleset/content pack/checksum/Legacy 정책·golden 변경, 공유 board/decision/dashboard 수정, 운영 배포·D1 쓰기.

## 인수 및 검증

- D-61: 새 독립 테스트 파일이나 불필요한 독립 case를 만들지 않고 기존 release/compatibility case와 table을 확장한다. 실 HTTP/D1·Web Worker 측정은 저장소 파일을 늘리지 않는 일회성 검증으로 분리한다.
- release plan은 정확한 `1.5.0/0.6.0` 현재 행에서만 `activate`를 반환하고, 역 compare-and-set은 `1.7.0/0.6.3` → `1.5.0/0.6.0`이다. 일치하는 신 행은 `noop`, mixed/예전 행은 fail closed다.
- 별도 검증 워커가 일회성 `/tmp` 스크립트로 실제 로컬 HTTP API + D1, 실제 브라우저 Web Worker의 `1.5.0/0.6.0`·`1.7.0/0.6.3` 동일 명령 replay hash/RNG 일치, 20시즌 state 256KiB·실 PUT 1MiB 게이트를 측정한다.
- 기존 snapshot-size 통합 case의 20시즌 `1.7.0/0.6.3` state 256KiB 이하, `PutCareerBodySchema`, PUT 1MiB 이하를 재확인한다. 합성 최대 shape·fake transport·CLI 모델링과 실 HTTP API/D1·브라우저 Worker 결과를 구분해 보고한다.
- Node `22.23.1` (`/Users/suyoung/.nvm/versions/node/v22.23.1/bin`)로 focused 후 전체 체인을 한 번에 하나씩, `TURBO_CONCURRENCY=2`로 실행한다. Playwright는 정확한 spec를 `--list` 후 `--workers=1`로 실행하며 wrapper에 인자를 넘기지 않는다.

## 밸런스 해석

`1.7.0`의 matched 1,000 대량 회귀에서 Legacy 상위 밴드가 `1.6.1` 33.3%에서 22.7%로 낮아진 것은 검증된 수치다. 기존 기대 승점 투영 대신 실제 리그 원장 순위를 쓰는 코드 경로 변화가 원인이라는 설명은 합리적 추정이며 별도 인과 실험은 수행하지 않았다. 사용자가 이 수치를 알고 승격을 승인했으며, 32% 목표를 통과한 것으로 기록하지 않고 Legacy 컷·가중치를 재조정하지 않는다.

## 전달

- PR에 exact SHA, focused/full/E2E 명령과 결과, 실 API/D1·Web Worker 측정값, 합성/모델링 근거, 배포 전에 남은 staging → preflight → production deploy → post-deploy 게이트를 분리해 적는다.
