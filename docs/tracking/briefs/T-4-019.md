# T-4-019: [핫픽스] e2e 헬퍼 `signFirstOffer` 정규식이 STAY 결과 URL의 `&interested=N`을 허용하도록

## 목표

> **D-61(2026-09-05 16:02 사용자 지시)**: 새 테스트 코드를 작성하지 않는다. 이 작업은 동작 변경(PR #76)으로 깨진 **기존** e2e 헬퍼의 갱신이다.

main 통합 회귀: PR #74(T-4-010)가 넣은 `apps/web/e2e/helpers/player-creation.ts`의 `signFirstOffer` 헬퍼는 `/transfer-result?rev=N`이 URL 끝이라고 가정하는데, PR #76(T-4-011)이 INTEREST 시장 안전 잔류(STAY) 수락 시 `/transfer-result?rev=N&interested=K`로 보내게 바꿨다. 두 PR은 각각 origin/main 기준으로 검증돼 함께 검증된 적이 없고, 합쳐진 main에서 `season.spec.ts:121`("시즌 1 결산 뒤 INTEREST 시장이 열리면 안전 잔류 제안을 수락하고 대시보드로 돌아온다")이 `--workers=1`로도 결정적으로 실패한다(PR #78 검증 체인 16:56, T-4-016 워커 재현).

## 1. 작업

- `signFirstOffer`의 두 정규식이 `rev=\d+` 뒤에 선택적 `&interested=\d+`(일반화: `(?:&[^#]*)?`)를 허용하게 바꾼다. 그 뒤 분기(transfer-result 화면이면 "대시보드로"/"새 시즌 준비" 링크 클릭 → 대시보드)는 STAY 결과 카드의 실제 링크 이름과 맞는지 `transfer.spec.ts` (c) 케이스를 보고 확인해, 다르면 링크 이름 정규식에 그 이름을 추가한다.
- 헬퍼 주석(120~124행)의 "loader가 대시보드로 바로 redirect한다"는 설명은 #76 이후 사실이 아니므로(STAY 결과 카드에 도착) 한 문장으로 고친다.
- 코드·문구 외 변경 없음. `transfer.spec.ts`의 `rev=\d+$` 단언(224·284·320행)은 FREE_AGENT/LOAN/RETURN 결과라 `interested`가 붙지 않으므로 건드리지 않는다.
- **(17:12 추가, 워커 1차 BLOCKED 답변)** `season.spec.ts:121` 테스트의 마지막 단언(143행 `toHaveURL(/\/career\/[^/]+$/)`)을 `/\/career\/[^/]+(?:\/preseason)?$/`로 완화한다. PR #76의 `ctaToPreseason`(시즌 1 결산 직후 `state.season === null`이면 STAY 카드 CTA가 "새 시즌 준비"→`/preseason`)이 의도된 라우팅이라 이 seed는 대시보드가 아니라 프리시즌에 닿는다. 테스트 제목의 "대시보드로 돌아온다"는 "새 시즌 준비로 이동한다"로, 141~142행 주석은 STAY 결과 카드 → 새 시즌 준비 경로로 한 문장씩 고친다. 다른 테스트·다른 행은 건드리지 않는다.
