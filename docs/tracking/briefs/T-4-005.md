## 0. 시작 전 도달성 감사와 정지 규칙

- 활성 팩은 `0.1.0`(`apps/web/src/engine/versions.ts`)이다. 0.1.0에는 `EVT-INJ-001(INJURY)`과 #68의 `EVT-NAT-001(NATIONAL_TEAM)`만 있고, `EVT-SLUMP-010(SLUMP)`·`EVT-REL-010(LOCKER_ROOM)`·`EVT-ETH-010(ETHICS)`·`EVT-MEDIA-010(MEDIA)`·`EVT-CON-010(RUMOUR)`는 0.2.0에만 있다. 시작할 때 `packages/content/packs/*/events/*.json`의 `presentation` 값을 다시 세어 PR 본문 표에 적는다.
- **D-56(오케스트레이터 결정, 2026-09-05)**: 활성 팩은 0.1.0으로 유지한다(LINE TEST 기준선). 대신 **DEV 서버 전용** 팩 오버라이드를 둔다 — `versions.ts`에 `resolveActiveContentPackVersion()`을 추가해 `import.meta.env.DEV`이고 `localStorage['offside:e2e-content-pack']`이 `PACK_VERSIONS`에 있는 값이면 그 팩을, 아니면 `ACTIVE_CONTENT_PACK_VERSION`을 돌려준다. `engine.ts`의 엔진 팩 로딩과 `content.ts`의 읽기 전용 싱글턴이 **같은 함수**를 써서 값이 어긋나지 않게 하고, 프로덕션 번들에서는 `offside:e2e-seed` 훅과 같은 방식으로 죽은 코드가 되게 한다(빌드 산출물에서 키 문자열 grep으로 확인해 PR 본문에 적는다). 오버라이드로 만든 새 커리어는 `contentPackVersion: '0.2.0'`을 저장하고, 기존 0.1.0 커리어의 replay·import는 자기 팩으로 계속 동작한다(단위 테스트). 설정·확정 화면의 팩 표시는 실제 엔진 값을 따른다.
- 도달 경로: 0.2.0 이벤트는 domain `selectEligibleEvents`가 IN_SEASON EVENT 슬롯에서 고른다. e2e는 `offside:e2e-seed` + `offside:e2e-content-pack='0.2.0'`으로 결정론 경로를 만든다. seed 탐색은 브라우저 밖에서 `@offside/domain`·`@offside/content`를 직접 돌려 후보 seed를 찾는 개발용 Node 스크립트(`apps/web/e2e/helpers/find-seed.ts` 같은 파일, e2e 실행 경로에는 포함하지 않는다)로 하고, 찾은 seed·도달 step을 상수로 고정한다. 경계: 시즌 2개(프로 첫·둘째 시즌)·seed 2,000개 안에서 못 찾는 presentation은 e2e 대신 단위 렌더 테스트만 두고 PR 본문에 "미도달"로 적는다. **가짜 pending·클라이언트 측 이벤트 강제·domain 파일 수정으로 도달성을 만들지 않는다.**
- 시작 시 `screenForCareer`가 NATIONAL_TEAM pending을 어디로 보내는지(#68 결과)와 `resolveEvent` 어댑터의 `callUp` 처리를 확인하고, 없으면 멈추고 오케스트레이터에게 묻는다.

## 1. 화면 분기 모델

- `screenForCareer`: `pending.kind === 'INJURY'` → `SCR-022`, `NATIONAL_TEAM` → `SCR-032`, `EVENT`는 활성 팩에서 `eventId` 정의를 찾아 `presentation`이 `SLUMP` → `SCR-021`, `LOCKER_ROOM` → `SCR-018`, `ETHICS` → `SCR-016`, `MEDIA` → `SCR-024`, `RUMOUR` → 기존 `SCR-019`, 없음 → `SCR-013`(기존 `EVENT_SCREEN_OVERRIDES`는 유지하되 presentation 분기보다 뒤에 둔다). `screenForCareer`는 순수 함수로 유지하고 팩 조회는 `EVENT_SCREEN_OVERRIDES`처럼 팩에서 파생한 모듈 상수 맵 또는 인자 주입으로 한다. `SCREEN_ROUTES`에 새 ID를 등록한다.
- 라우트는 하나의 결정 화면 라우트(`career.$careerId.event.tsx`)가 presentation별 본문 컴포넌트를 고르는 구조를 권장한다(공유 본문 `event-screen.tsx`의 확정·재시도·중복 클릭·revision 복구를 그대로 재사용). 새 라우트 파일을 만들어도 되지만 확정 로직을 복제하지 않는다.
- SCR-014 결과 카드는 공용이다. 결과에 관계 변화(축·delta·`sourceId`·`reasonTag`), 평판 변화(`popularityCenti` 변화를 "인기 ↑/↓ n" 정수로), 부상(진단·복귀 범위·재활 계획), 대표팀 결과(참가/사양/조건부와 "감독 신뢰 변화 없음"), 후속 이벤트 힌트를 보여준다. 리플레이·뒤로 가기가 roll을 소비하지 않는 기존 규칙을 깨지 않는다.

## 2. 화면별 요구

공통: 상황(`ScreenIntro`) → 선수·핵심 정보 → 2~3개 `ChoiceCard`(위험 라벨·`previewEffects` 라벨) → sticky 확정. 위험·예상 효과는 콘텐츠 `previewEffects`를 그대로 라벨링하고 클라이언트가 결과를 계산하지 않는다. 모든 문구는 한국어이며 실명·외부 SNS·병역 특례 문구를 쓰지 않는다.

- **SCR-022 부상·재활**(pending INJURY, `health.episodes`의 활성 에피소드): 진단(부위·심각도 라벨), 예상 복귀 범위(`diagnosisRange.minMatches~maxMatches`경기), 재발 위험(`recurrenceRiskBp` → 0.1% 단위 "n.n%"), 주요 일정(복귀 범위 안의 다음 챕터·컵 경기 라벨, 시즌 일정에 있으면), Fitness. 선택 3개는 EVT-INJ-001 choice의 `rehabPlan`(EARLY/STANDARD/CONSERVATIVE)을 라벨로 구분하고 previewEffects의 복귀 범위 이동·재발 위험 증감·출전 기회 대가를 **선택 전에** 보여준다(P4-3). 확정 뒤 대시보드 StatusStrip/일정표에 결장 잔여 경기(`availability.matchesRemaining`)와 회복 뒤 재발 판정 잔여(`recurrenceChecksRemaining`)를 표시하고, `permanentDelta`가 확정된 에피소드만 능력치 변화로 표기한다(확정 전 영구 변화 문구 금지).
- **SCR-021 슬럼프**(SLUMP): 최근 5경기(시즌 경기 기록의 평점·출전, 없으면 `season.stats` 요약), 원인 후보(서사 문단), 감독 기대(감독 이름·`managerTrust` 단계), 선택별 대가(previewEffects + Effect 만료 시점 라벨, 예 "두 step 뒤 만료"). Base OVR 감소 문구·수치를 어디에도 표시하지 않는다(테스트).
- **SCR-018 라커룸**(LOCKER_ROOM): 5축 관계의 방향(최근 `relationshipLog`에서 축별 delta 부호 → ↑/→/↓)과 단계 라벨, 축별 `memoryTags`, 이 선택이 경기·출전에 미칠 맥락 효과(previewEffects의 target → 라벨). 결과 카드에 `sourceId`·`reasonTag`가 남는다.
- **SCR-016 윤리·위기**(ETHICS): 확인된 사실/소문/위험(서사에 구분이 없으면 서사 1블록 + 위험 라벨), 지원 가능한 인물(에이전트·주장 관계 단계). FAIL outcome 뒤에도 다음 결정으로 이어지는지 확인하고 결과 원인(`reasonTag`)을 설명한다(P4-6).
- **SCR-024 SNS·평판**(MEDIA): 공개 범위 라벨, 예상 팬/감독 영향(previewEffects), 사실 여부 라벨. 어떤 선택도 외부 전송(`navigator.share`·`window.open`·외부 링크)을 하지 않는다(테스트로 금지).
- **SCR-032 대표팀 차출**(NATIONAL_TEAM, EVT-NAT-001): 대회 종류·예상 출전·체력 비용·클럽 감독 반응("감독 신뢰는 변하지 않습니다" 명시, P4-7)·명성·태그 영향. 국적 특례 항목은 `nationalityRuleState`가 기본 모듈이면 **표시하지 않는다**. 선택 참가/조건부/사양 = `callUp` ACCEPT/CONDITIONAL/DECLINE. 부상 중 자동 사양(타임라인 `NATIONAL_TEAM_DECLINED`, 이유 INJURY)은 화면을 열지 않으므로 대시보드 일정표 카드에 이유를 남긴다. 데뷔 챕터(CHP-NAT-001)는 SCR-031이 이미 연다(#68) — 헤더의 "대표팀 데뷔" 맥락만 확인한다.
- **SCR-023 경기 판단 변형**(SCR-031 안): 챕터 정의에 `positionGroups`가 있으면 헤더에 포지션군 라벨("공격수 판단" 등)과 현재 선수 포지션군을 표시하고, 없으면 아무것도 추가하지 않는다. 표시 로직 단위 테스트만 둔다(콘텐츠에 포지션 전용 챕터가 아직 없으면 fixture 정의로 테스트).

## 3. 대시보드 점진 공개(D-57)

상태에서 파생하는 3단계(새 저장 필드 없음):

1. 계약 전(`contract === null`): 라커룸은 기억 태그(`tags`)만, 휴대폰 잠김(현행 유지).
2. 첫 프로 계약 후 첫 결산 전(`contract !== null && seasonHistory.length === 0`): 라커룸에 5축 관계를 **방향·단계 라벨**로(숫자 없음), 축별 `memoryTags`, 최근 관계 변화 3건(대상·이유 태그). 휴대폰에 계약 요약 + 평판 단계 라벨 + 제안·루머·SNS 진입.
3. 첫 결산 후(`seasonHistory.length >= 1`): 2단계 항목에 숫자를 연다 — 관계 0~100 정수, 인기 `popularityCenti/100` 정수. 감독 이름·재직 시즌(`season.manager`), 주장단 상태(`captaincy`).

관계 방향·단계 라벨은 룰셋 상수가 아니라 화면 라벨 함수 한 곳(`shared/labels.ts`)에 두고 단위 테스트한다. 어느 단계에서도 대시보드에서 결정을 확정하지 않는다.
