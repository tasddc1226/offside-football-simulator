# T-1-002: content 룰셋 1.0.0 데이터·스키마·로더, 팩 0.1.0 진로 태그 수정

## 목표
`packages/content/rulesets/1.0.0/ruleset.json`이 포지션 8·아키타입 24·배경 3·국적 10·팀 8·제안·계약 규칙을 담고 Zod로 검증되며, `loadRuleset('1.0.0')`으로 읽힌다. 콘텐츠 팩 0.1.0의 진로 이벤트(EVT-CON-002·003)가 `career.pathDecision` 대신 태그로 이어진다.

## 참조 명세
- 요구사항 ID: FR-PLY-001, FR-OVR-001, FR-CON-001, FR-EVT-001, ADR-004
- 읽어야 할 문서(순서대로): `docs/tracking/phase-1-plan.md` **D-1~D-6, D-8, D-9(데이터 부분), D-11**(정본), `docs/adr/ADR-004-content-format.md`, `docs/development/04-event-engine.md`, `docs/development/03-game-simulation-engine.md`(역할 가중치·Base OVR), `docs/content/prototype/season-01-inside-forward.md`, `docs/content/README.md`(안전 규칙: 미성년·정신건강 문장)
- 정본 우선순위: phase-1-plan.md 결정 > docs/development > phases > screens > content

## 범위
- 만질 패키지·경로: `packages/content`만(`rulesets/`, `packs/0.1.0/`, `src/`).
- 만들 것:
  1. `rulesets/1.0.0/ruleset.json`(아래 형식). 인사이드 포워드·배경 3종·팀은 plan 문서 표의 값을 **그대로**. 나머지 아키타입 23개는 저작한다(포지션당 3개, 이름은 한글, 실제 선수·구단 이름 연상 금지). 템플릿 능력은 17세 기준 30~72, `potentialRange`는 55~92 안, GK 아키타입만 `goalkeeping` 가중치 > 0이고 다른 포지션은 `goalkeeping` 템플릿 5~15.
  2. `src/schema/ruleset.ts`: `RulesetSchema`와 부분 스키마(`ArchetypeSchema`, `BackgroundSchema`, `TeamSchema`, `OfferRulesSchema`, `ContractRulesSchema`). 정제 규칙: 가중치 합 `1 ± 1e-9`, 가중치 키는 domain `ATTRIBUTE_KEYS`(타입 import는 허용, 값 import는 `@offside/domain`이 devDependency이므로 **키 목록을 content에 복제하고 domain과 같은지 테스트**), 템플릿 20키 전부, 포지션당 아키타입 3개, id 중복 없음, 배경 `startTeamId`가 teams에 있음, wage band id 참조 무결, 국적 첫 항목 `KR`.
  3. `src/rulesets/load-ruleset.ts`: `loadRuleset(version: string)` — 번들에 포함된 JSON을 검증해 돌려준다(동기). 알 수 없는 버전은 throw. `RULESET_VERSIONS` 상수 export.
  4. CLI `content:validate`가 `rulesets/*/ruleset.json`도 검증하고 canonical JSON checksum을 출력한다. 팩 manifest처럼 `rulesets/1.0.0/manifest.json { version, checksum }`을 두고 drift를 검사한다.
  5. 팩 0.1.0 수정(D-11): EVT-CON-002 A `addTags ['진로_입단테스트']`, B `addTags ['늦은_출발','진로_아카데미']`(followUp 없음), C `addTags ['밑바닥부터','진로_하부리그']`(followUp EVT-CON-003 유지). EVT-CON-003 trigger를 `{ all: [ { any: [ <태그 포함: 진로_입단테스트>, <태그 포함: 진로_하부리그> ] }, { gte: ['player.baseOvr', 55] } ] }`로(DSL의 태그 포함 연산자와 `any`를 쓴다. 둘 중 하나가 DSL에 없으면 멈추고 질문). CON-003 모든 결과에 `입단테스트_완료` + 결과 종류 태그(SUCCESS `테스트_성공`, NEUTRAL `테스트_보통`, FAIL `테스트_실패`). manifest checksum 재생성, `pack.test.ts` 기대값 갱신.
  6. 조건 DSL 필드 목록에서 `career.pathDecision` 제거. 팩 어디에도 남지 않아야 한다(검증 실패로 확인).
- 만지지 말 것: `docs/`, `packages/domain`, `packages/contracts`, `packages/fixtures`, 다른 이벤트 파일의 의미(태그·효과·문장). 팩 버전은 0.1.0 유지(제자리 수정, D-11).

## 제약
- 아키타입 문장·팀 이름은 `docs/content/README.md` 안전 규칙(미성년 존중, 실명·실구단 금지)을 따른다.
- domain 값 import 금지(`@offside/domain`은 타입만, ADR-005). 키 목록 복제 + 일치 테스트로 대신한다.
- 커밋 메시지는 `T-1-002: …`로 시작, 브랜치는 `T-1-002-…`.
- 서브에이전트 리뷰를 띄우지 않는다. Orca PR 게이트용 `/review:pr` 1회만 예외(`/simplify`·병렬 fork 금지).
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
