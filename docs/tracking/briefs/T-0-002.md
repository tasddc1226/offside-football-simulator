# T-0-002: `packages/domain` 결정론 코어 — RNG, canonical hash, 순수 `simulate` fixture

## 목표

`packages/domain`에 시뮬레이션의 결정론 토대를 만든다. 고정 RNG, canonical JSON + SHA-256 state hash, 최소 `CareerState`와 Effect 적용 규칙, 그리고 `CREATE_CAREER → RESOLVE_EVENT → ADVANCE_STEP` 명령을 처리하는 순수 `simulate(input)`을 구현해, 같은 fixture 1,000회 실행의 state hash가 항상 같음을 테스트로 고정한다. 이 패키지는 이후 engine-client(Web Worker)와 apps/api(리플레이 검증)가 그대로 import한다.

### 만들 것

모두 `packages/domain/src/` 아래. 외부 `dependencies`는 계속 0개. 시간·난수·I/O는 입력으로만 받는다. 정수 연산만 쓴다(부동소수점 금지, 비율은 0~10000 basis point 또는 0~100 정수).

1. `rng.ts` — xoshiro128** (32비트 정수 연산, `Math.imul`·`>>> 0` 사용).
   ```ts
   export type RngState = { readonly s: readonly [number, number, number, number]; readonly draws: number };
   export function seedRng(seed: string): RngState;          // seed 문자열 → FNV-1a 32bit → splitmix32로 4워드 생성. 모두 0이면 금지(첫 워드에 1 OR)
   export function nextUint32(state: RngState): { value: number; state: RngState }; // 불변 갱신, draws+1
   export function rollInt(state: RngState, maxExclusive: number): { value: number; state: RngState }; // 0..max-1, rejection sampling으로 편향 제거
   export function roll100(state: RngState): { value: number; state: RngState }; // 1..100. 이벤트 outcome roll 전용
   ```
2. `canonical.ts`, `hash.ts`
   ```ts
   export type JsonValue = null | boolean | number | string | JsonValue[] | { [k: string]: JsonValue };
   export function canonicalize(value: JsonValue): string; // 객체 키 코드포인트 순 정렬, 공백 없음, undefined 속성 제거, 배열 순서 유지. 숫자는 안전 정수만(그 외·NaN·Infinity는 throw)
   export function utf8Encode(s: string): Uint8Array;      // TextEncoder 없이 직접 구현(서로게이트 쌍 포함)
   export function sha256Hex(input: string): string;       // 순수 TS SHA-256. crypto 전역 사용 금지
   export function hashState(state: CareerState): string;  // sha256Hex(canonicalize(state))
   ```
   SHA-256은 FIPS 180-4 테스트 벡터(`""`, `"abc"`, 448비트·896비트 메시지)로 검증한다.
3. `types.ts` — 문서와 같은 이름을 쓴다.
   ```ts
   export type CareerPhase = 'YOUTH' | 'PRESEASON' | 'IN_SEASON' | 'TRANSFER_WINDOW' | 'NATIONAL_TEAM' | 'REHAB' | 'SETTLEMENT';
   export type SeasonPhase = 'PRESEASON' | 'LEAGUE' | 'CUP' | 'TRANSFER_WINDOW' | 'SETTLEMENT';
   export type SimulationMode = 'FAST' | 'CHAPTER';
   export type CareerStatus = 'DRAFT' | 'ACTIVE' | 'RETIRED' | 'ARCHIVED';
   export type CareerStage = 'YOUTH' | 'PRO';
   export type SquadRole = 'STARTER' | 'ROTATION' | 'BENCH' | 'RESERVE';
   export type CheckpointType = 'CAREER_CREATED' | 'SEASON_START' | 'STEP_BOUNDARY' | 'EVENT_OFFERED' | 'EVENT_RESOLVED' | 'CHAPTER_DECISION' | 'SEASON_SETTLED' | 'CONTRACT_CONFIRMED' | 'RETIREMENT';
   export const ATTRIBUTE_KEYS = [
     'shooting','passing','dribbling','tackling','firstTouch','crossing','goalkeeping',      // 기술 7
     'pace','acceleration','agility','jumping','stamina','strength','durability',           // 신체 7
     'decisions','concentration','composure','positioning','leadership','consistency',      // 정신 6
   ] as const;
   export type AttributeKey = (typeof ATTRIBUTE_KEYS)[number];
   export type EffectKind = 'PERMANENT' | 'CURRENT' | 'CONTEXT' | 'RELATION' | 'DEFERRED';
   export type Effect = {
     kind: EffectKind;
     sourceId: string;               // `<eventId>.<choiceId>.<outcomeId>` 형식 권장
     target: string;                 // PERMANENT: AttributeKey, CURRENT: 'form'|'fitness'|'morale', CONTEXT: 'tacticalFit'|'squadStatus'|'positionProficiency', RELATION: 'managerTrust'|'captain'|'rival'|'fans'|'agent'
     delta: number;                  // 정수. REPLACE면 대입 값
     clamp: { min: number; max: number };
     appliesAt: { kind: 'IMMEDIATE' } | { kind: 'NEXT_SEASON_STEP'; step: number };
     expiresAt: null | { kind: 'STEPS_AFTER'; steps: number } | { kind: 'AT_STEP'; step: number };
     stackingRule: 'ONCE_PER_SOURCE' | 'REPLACE' | 'SUM';
   };
   export type CareerState = {
     schemaVersion: 1;
     careerId: string;
     status: CareerStatus;
     stage: CareerStage;
     age: number;
     currentStep: number;            // 0(시즌 전) 또는 1..12. 단조 증가
     seasonPhase: SeasonPhase;
     simulationMode: SimulationMode;
     attributes: Record<AttributeKey, number>;   // 0..99
     state: { form: number; fitness: number; morale: number };                     // 0..100
     context: { tacticalFit: number; squadStatus: number; positionProficiency: number }; // 0..100
     relationships: { managerTrust: number; captain: number; rival: number; fans: number; agent: number }; // 0..100
     tags: string[];                 // 항상 코드포인트 순 정렬, 중복 없음
     appliedSourceIds: string[];     // ONCE_PER_SOURCE 판정용, 정렬
     activeEffects: Effect[];        // 만료 대기 중인 CURRENT 등. 적용 순서 유지
     deferredEffects: Effect[];      // DEFERRED, NEXT_SEASON_STEP에 적용
     resolvedEventIds: string[];     // 확정된 이벤트는 다시 추첨하지 않는다
     rngState: RngState;
     rulesetVersion: string;
     contentPackVersion: string;
   };
   export type DomainSnapshot = {
     revision: number;
     checkpoint: CheckpointType;
     state: CareerState;
     stateHash: string;              // hashState(state)
     rulesetVersion: string;         // state 안의 값과 같아야 한다
     contentPackVersion: string;
   };
   ```
4. `effects.ts`
   - `applyEffects(state, effects, now: { step })` → `{ state, applied: Effect[], rejected: Array<{ effect; reason }> }`.
   - 규칙: `RELATION`·`CONTEXT`는 `attributes`를 절대 바꾸지 않는다(target이 attributes면 reject). `PERMANENT`만 `attributes`를 바꾼다. `ONCE_PER_SOURCE`는 `appliedSourceIds`에 있으면 reject. `REPLACE`는 대입, `SUM`은 합산. 적용 후 `clamp`로 자른다. `DEFERRED`는 `deferredEffects`에 넣기만 한다. `expiresAt`이 있는 효과는 `activeEffects`에 기록하고 만료 시 delta를 되돌린다(되돌릴 때도 clamp).
   - `expireEffects(state, step)` — `AT_STEP`/`STEPS_AFTER` 도달분을 되돌리고 `activeEffects`에서 제거.
5. `simulate.ts`
   ```ts
   export type Command =
     | { type: 'CREATE_CAREER'; payload: { careerId: string; seed: string; stage: CareerStage; age: number; attributes: Record<AttributeKey, number>; simulationMode: SimulationMode; rulesetVersion: string; contentPackVersion: string } }
     | { type: 'RESOLVE_EVENT'; payload: { eventId: string; definitionVersion: number; choiceId: string; outcomes: Array<{ id: string; weight: number; effects: Effect[]; addTags?: string[]; removeTags?: string[] }> } }
     | { type: 'ADVANCE_STEP'; payload: Record<string, never> };
   export type SimulationInput = {
     snapshot: DomainSnapshot | null;   // CREATE_CAREER만 null 허용
     command: Command & { commandId: string; expectedRevision: number };
     rulesetVersion: string;
     contentPackVersion: string;
   };
   export type SimulationResult =
     | { ok: true; snapshot: DomainSnapshot; roll?: number; outcomeId?: string; appliedEffects: Effect[]; nextAction: 'DECISION' | 'ADVANCE' | 'SETTLEMENT' }
     | { ok: false; error: { code: 'VALIDATION_FAILED' | 'CAREER_REVISION_CONFLICT' | 'COMMAND_ALREADY_RESOLVED' | 'VERSION_MISMATCH'; message: string; details?: JsonValue } };
   export function simulate(input: SimulationInput): SimulationResult;
   ```
   - 규칙: throw 하지 않는다(도메인 오류는 `ok: false`). `expectedRevision !== snapshot.revision`이면 `CAREER_REVISION_CONFLICT`. 입력 버전 2종이 snapshot과 다르면 `VERSION_MISMATCH`. `RESOLVE_EVENT`의 eventId가 `resolvedEventIds`에 있으면 `COMMAND_ALREADY_RESOLVED`. `status`가 `ACTIVE`가 아닌데 진행 명령이 오면 `VALIDATION_FAILED`. `ADVANCE_STEP`은 `currentStep`이 12면 `VALIDATION_FAILED`(결산은 다른 작업). 성공 시 `revision + 1`, `stateHash` 재계산, checkpoint는 CREATE→`CAREER_CREATED`, RESOLVE→`EVENT_RESOLVED`, ADVANCE→`STEP_BOUNDARY`.
   - `RESOLVE_EVENT`는 04 "결과 해결" 2~4단계: 가중치 합 > 0 검증, `rollInt(rng, weightSum)` 한 번으로 outcome 선택(누적 가중치, 배열 순서), effects 적용, tags 갱신(정렬 유지), `resolvedEventIds`에 추가. roll은 정확히 한 번만 소비한다.
   - `ADVANCE_STEP`은 `currentStep + 1`, 만료 효과 정리, step 7이면 `seasonPhase`를 `TRANSFER_WINDOW`가 아니라 유지(창 오버레이는 시즌 로직 작업의 몫), `nextAction`은 12면 `SETTLEMENT`, 아니면 `DECISION`.
   - `verifySnapshot(snapshot): { ok: true } | { ok: false; reason: string }` — `stateHash === hashState(state)`, 버전 일치, 배열 정렬 불변 검사.
6. `fixtures/` (패키지 안 `src/__fixtures__/`): `career-01.json` — 김서준 기반 초기 입력(`docs/content/prototype/season-01-inside-forward.md` "세부 능력 초기값" 표의 20개 값, `stage: 'YOUTH'`, `age: 17`, seed `"offside-fixture-01"`)과 명령 12개(RESOLVE_EVENT 4개 + ADVANCE_STEP 8개, 효과는 EVT-P01·P02 표에서 가져오되 outcome id·weight는 roll 구간 폭으로). 그리고 `career-01.golden.json`에 최종 `revision`, `stateHash`, `rngState.draws`를 고정한다.
7. `index.ts`에서 위 모두 export. `DOMAIN_VERSION`은 `'0.1.0'`으로 올린다.

### 테스트 (Vitest, `packages/domain/src/**/*.test.ts`)

- SHA-256 FIPS 벡터 4개, UTF-8 인코딩(한글·이모지 서로게이트) 1개.
- `canonicalize`: 키 순서가 달라도 같은 문자열, 비정수 숫자 throw, undefined 제거, 중첩 배열 순서 유지.
- RNG: 같은 seed 두 번 → 같은 수열 100개. `rollInt(_, 6)` 60,000회 결과가 0..5 각각 9,000~11,000회. `roll100` 범위 1..100. 상태 불변(입력 객체가 바뀌지 않음).
- 결정론: `career-01.json`을 1,000회 실행해 매번 golden hash와 같다. seed 한 글자 바꾸면 hash가 달라진다. 명령 순서를 바꾸면 hash가 달라진다.
- 변조 감지: golden snapshot의 `state.attributes.shooting`을 +1 하면 `verifySnapshot`이 실패한다.
- Effect 규칙: RELATION이 attributes를 못 바꾼다, ONCE_PER_SOURCE 두 번 적용 시 두 번째 reject, REPLACE/SUM, clamp 상한·하한, `STEPS_AFTER: 2`가 두 step 뒤 되돌아온다.
- 명령 규칙: revision 불일치 → `CAREER_REVISION_CONFLICT`, 같은 eventId 재제출 → `COMMAND_ALREADY_RESOLVED`, 버전 불일치 → `VERSION_MISMATCH`, RETIRED 상태 진행 → `VALIDATION_FAILED`, `currentStep`이 절대 감소하지 않음(property).
- property 테스트는 `fast-check`를 `devDependencies`에만 추가해 쓴다(허용된 유일한 추가 의존성). 시드 고정.
