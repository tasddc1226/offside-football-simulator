# T-4-020: [핫픽스] injury.spec `reachForcedInjury` poll의 `textContent()` 무한 대기 → 타임아웃 지정

## 목표

> **D-61(2026-09-05 16:02 사용자 지시)**: 새 테스트 코드를 작성하지 않는다. 이 작업은 **기존** e2e 헬퍼의 레이스 수정이다.

`apps/web/e2e/injury.spec.ts:134`("career-12 고정 seed의 실제 forced INJURY pending은 …")가 반복적으로 60초 타임아웃으로 실패한다(PR #75·#78 체인, T-4-014·T-4-016 워커, 격리 `--workers=1`에서도 재현). Playwright trace 분석(PR #78 체인, 2026-09-05 16:56): `reachForcedInjury`의 대시보드 분기에서 "진행" 클릭 뒤 `expect.poll` 콜백이 `page.url()` 확인(아직 대시보드) → `stepCaption.textContent()` 호출 순으로 도는데, 그 사이 엔진이 forced INJURY로 `/event`로 이동하면 `step N/12` 캡션 요소가 사라져 **타임아웃 없는 `locator.textContent()`가 영원히 대기**한다(`.catch`는 거부만 잡고 대기는 못 잡는다). 테스트 종료 시 `locator.textContent: Test ended` 오류가 남는 것이 증거. 실패 스냅샷은 이미 부상 이벤트 화면(표준·조기·보수 재활 라디오)이다.

## 참조·선행

- 정본: [T-4-010](T-4-010.md)(이 poll 도입), [T-4-006](T-4-006.md).
- 코드: `apps/web/e2e/injury.spec.ts` `reachForcedInjury`(약 60~125행: `stepCaption`, `progressButton`, `const before = await stepCaption.textContent()`, `expect.poll(...)`).

## 1. 작업

- poll 콜백의 `stepCaption.textContent()`에 짧은 타임아웃을 준다: `stepCaption.textContent({ timeout: 1_000 }).catch(() => null)`. 캡션이 사라지면(`null !== before`) true가 되어 루프가 다음 반복에서 `/event`를 감지한다.
- `const before = await stepCaption.textContent()`도 같은 방식으로 타임아웃(예: 15_000)을 준다 — 클릭 직전 이미 화면이 바뀌었을 때 무한 대기하지 않도록. 값이 `null`이면 그대로 진행.
- 같은 패턴(타임아웃 없는 `textContent()`/`innerText()`를 poll 안에서 호출)이 이 파일의 다른 헬퍼에 있으면 동일하게 고친다. 다른 spec 파일은 건드리지 않는다(발견하면 questions에 파일·행만 적는다).
