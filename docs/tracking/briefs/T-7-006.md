# T-7-006: 하단 액션 독의 가림 어포던스 — 스크롤 여백·페이드·그림자 (이슈 #146)

## 목표

운영 QA에서 360px 세로 화면의 시즌 시작·경기 결과·이벤트·설정 화면 하단 내용이 sticky 액션 독(`os-action-dock`)에 가려 "더 있다"는 신호가 없었다.
내용은 스크롤로 닿을 수 있으므로 레이아웃을 바꾸지 않고, `packages/ui`의 CSS만으로 (1) 독 위에 얇은 페이드·그림자를 넣어 가려진 내용이 있음을 보여 주고,
(2) 키보드 포커스·앵커 이동 시 독 아래로 들어가지 않게 `scroll-padding-bottom`을 준다. 화면별 마진 조정(`apps/web`)은 하지 않는다.

## 참조 명세

- 요구사항 ID: SCR 공통 셸(`docs/screens/README.md` §PageShell·§액션 독), NFR-A11Y(포커스 가시성), `docs/ui/ui-style-guide.md` §하단 액션
- 읽어야 할 문서: `docs/qa/2026-09-07-production-six-cases/README.md` 결함 8, `docs/qa/2026-09-07-production-three-perspectives/README.md` P1-3, 이슈 #146
- 코드 진입점: `packages/ui/src/game.css` `.os-shell-main`(약 41~51행, 유일한 스크롤 컨테이너, `padding-bottom: calc(24px + var(--os-safe-bottom))`), `.os-action-dock`(약 336~347행, `position: sticky; bottom: 0; z-index: 10`), `.os-action-row`(약 357~364행), 데스크톱 오버라이드(약 627~629행), `packages/ui/src/components/PageShell.tsx` 18~21행

## 범위

- 만질 패키지·경로: `packages/ui/src/game.css`만.
- 만들 것:
  1. `.os-action-dock`에 `::before` 가상 요소로 높이 20px의 상단 페이드(`linear-gradient(to bottom, transparent, var(--os-bg))`, `position:absolute; top:-20px; left:0; right:0; pointer-events:none`)와 `box-shadow: 0 -6px 18px var(--os-shadow-dock, rgba(0,0,0,.18))`를 준다. 다크·라이트 모두 토큰(`--os-bg`)을 따르게 하고, 새 색상 리터럴이 필요하면 `game.css`의 토큰 정의 블록에 `--os-shadow-dock`을 라이트·다크 각각 추가한다.
  2. `.os-action-dock`의 배경이 불투명(`background: var(--os-bg)`)인지 확인하고, 아니면 불투명으로.
  3. `.os-shell-main`에 `scroll-padding-bottom: calc(96px + var(--os-safe-bottom))`을 준다(포커스 이동·`scrollIntoView` 시 독에 가리지 않도록). 기존 `padding-bottom`은 그대로 둔다.
  4. 독 바로 위 콘텐츠와의 간격: `.os-action-dock { margin-top: 12px }`(기존 값이 있으면 더 큰 쪽).
- 만지지 말 것: `PageShell.tsx` 구조, `apps/web` 라우트, 토큰 이름 변경, 데스크톱 레이아웃(627~629행은 값 유지), docs.
