# T-0-012: `packages/platform` 골격 — `Platform` 인터페이스, web 구현(Dexie `LocalStore`), toss 스텁(문자열 KV `LocalStore`, SDK 없음), 채널 분기 lint, `apps/web` 조립 지점

## 목표

채널 차이를 `packages/platform`에만 가둔다(ADR-009 "채널 구조"). engine-client(T-0-007)가 정의한 `LocalStore` 포트의 실제 구현 두 개를 만든다: web은 Dexie(IndexedDB), toss는 문자열 KV 위에 얹은 구현(지금은 메모리 KV, 나중에 앱인토스 네이티브 `Storage`를 꽂는다). 둘 다 engine-client의 `runLocalStoreContractTests`를 통과해야 한다. `Platform` 인터페이스에 Phase 0~1이 필요한 것만 둔다(저장소, 세션 토큰, 식별키, 백버튼·종료 확인, 인셋, 분석). `apps/web`은 단 한 파일에서만 채널을 고르고, 그 밖의 화면·엔진 코드에서 `@apps-in-toss/*` import와 `'toss'` 채널 분기를 lint로 막는다. `vite build --mode toss`가 통과하고, 어댑터를 바꿔도 화면·엔진 코드가 바뀌지 않는다(phase-00 완료 조건).

### 설계 결정(변경 금지. 의문이 있으면 질문)

1. `Platform`은 engine-client가 아니라 platform이 소유한다. 화면은 `Platform`만 알고 `channel`을 읽어 분기하지 않는다(테마 고정 같은 채널 차이는 어댑터가 값으로 준다: `theme.forced`).
2. toss 구현은 SDK 없이 **`StringKV` 인터페이스**(`getItem/setItem/removeItem/keys`)에 의존한다. 지금은 메모리 KV를 주입하고, M-001에서 앱인토스 `Storage`를 같은 인터페이스로 감싼다. 그래서 스텁이 아니라 "KV 위 LocalStore"가 진짜 구현이고, 테스트도 계약 테스트 전체를 돈다.
3. Dexie 트랜잭션 안에서는 Dexie 프로미스만 기다린다(engine-client 포트 규칙). `LocalStore.transaction('readwrite', run)`는 `db.transaction('rw', tables, () => run(tx))`로 매핑하고, `run`이 throw하면 Dexie가 롤백한다.
4. 채널 선택은 `apps/web/src/platform/index.ts` 한 파일에서 `import.meta.env.MODE === 'toss'`로만 한다. 이 파일 외에서는 `'toss'`·`'web'` 리터럴 비교와 `@offside/platform/web`·`@offside/platform/toss` 직접 import를 lint로 금지한다.
5. `Platform` 인터페이스(Phase 0~1 범위. 늘리지 않는다):

   ```ts
   export type Channel = 'web' | 'toss';
   export interface Platform {
     readonly channel: Channel;
     readonly theme: { forced: 'light' | 'dark' | null };               // toss: 'dark'(ADR-009 위험 표), web: null
     createLocalStore(): Promise<LocalStore>;                            // engine-client 포트
     session: { getBearerToken(): Promise<string | null>; setBearerToken(token: string | null): Promise<void> }; // web: 항상 null·no-op(쿠키)
     identity: { getAnonymousKey(): Promise<string | null> };            // web: null; toss 스텁: null(M-001에서 SDK)
     lifecycle: { onBackPressed(handler: () => boolean): () => void; confirmExit(): Promise<boolean> }; // web: popstate 기반 최소 구현·항상 true
     insets(): { top: number; bottom: number };                           // web: 0/0(CSS env()가 처리), toss 스텁: 0/0
     analytics: { track(event: string, props?: Record<string, string | number | boolean>): void }; // web: no-op(Phase 7에서 Web Analytics), toss: no-op
     openExternal(url: string): void;                                     // web: location.assign; toss: no-op + console.warn(ADR-009 외부 이동 금지)
   }
   ```

### 만들 것

1. `packages/platform/src/types.ts`: 위 `Platform`, `Channel`, `StringKV`. 기존 `Platform { channel }`을 확장한다(기존 테스트 유지).
2. `packages/platform/src/web/dexie-store.ts`: `createDexieLocalStore(dbName = 'offside'): Promise<LocalStore>` (`kind: 'dexie'`). Dexie 스키마 v1: `careers: 'id, updatedAt'`, `snapshots: '[careerId+revision], careerId, revision'`, `commandLog: '[careerId+revision], careerId, commandId'`, `idempotency: 'commandId, careerId'`, `kv: 'key'`. `commandLog.append`는 `add`를 써서 중복이면 Dexie `ConstraintError`를 `LocalStoreConstraintError`로 바꿔 throw. `snapshots.put`·`careers.put`·`idempotency.put`·`kv.put`은 `put`(upsert). `listByCareer`·`listSince`는 인덱스 범위 조회 + revision 정렬. `careers.list`는 `updatedAt` 내림차순, 동일하면 id 오름차순. `close()`는 `db.close()`. 반환 객체는 Dexie가 주는 그대로 두되 저장 시 `structuredClone`으로 외부 참조를 끊는다.
3. `packages/platform/src/kv-store/kv-local-store.ts`: `createKvLocalStore(kv: StringKV, prefix = 'os:'): LocalStore` (`kind: 'toss-storage'`). 키 설계: `${prefix}careers/${id}`, `${prefix}snapshots/${careerId}/${revision(10자리 0패딩)}`, `${prefix}log/${careerId}/${revision(0패딩)}`, `${prefix}idem/${commandId}`, `${prefix}kv/${key}`, 목록은 `keys()` 접두 필터. `readwrite`는 직렬화 + 시작 시 관련 키 스냅샷을 잡아 throw 시 복원(메모리 구현과 같은 전략). `MemoryStringKV`(테스트·스텁용)를 `packages/platform/src/kv-store/memory-kv.ts`에.
4. `packages/platform/src/web/index.ts`: `webPlatform: Platform`(결정 5의 web 동작). `packages/platform/src/toss/index.ts`: `tossPlatform: Platform`(KV LocalStore + `MemoryStringKV`, `theme.forced: 'dark'`, 나머지 스텁). 파일 상단 주석에 "M-001에서 `@apps-in-toss/web-framework`로 교체되는 지점" 목록.
5. `packages/platform/package.json`: `exports`에 `./web`, `./toss` 유지 + `./types`(타입 전용). `dependencies`에 `dexie`. `@offside/engine-client`는 소스에서 `import type`만(테스트 파일은 런타임 import 허용).
6. `apps/web/src/platform/index.ts`: `export const platform: Platform = import.meta.env.MODE === 'toss' ? tossPlatform : webPlatform;` 딱 이것. `apps/web/src/platform/index.test.ts`: 두 모드에서 각각 `platform.channel`이 맞는지(`vi.stubEnv('MODE', 'toss')` 후 동적 import).
7. `apps/web/vite.config.ts`: 변경 없이 되면 손대지 않는다. `vite build --mode toss`가 이미 통과한다(T-0-009).
8. Lint(`tooling/eslint-config/index.mjs`에 헬퍼 추가 + 적용):
   - `noChannelBranchRules({ files, allow })`: `files`(`apps/web/src/**`, `packages/engine-client/src/**`, `packages/ui/src/**`)에서 `no-restricted-imports`로 `@offside/platform/web`·`@offside/platform/toss` 금지(`allow`: `apps/web/src/platform/index.ts` 제외), `no-restricted-syntax`로 `BinaryExpression[operator=/==|===|!=|!==/] > Literal[value='toss']`와 `Literal[value='web']`(같은 형태) 금지, 메시지 "채널 분기는 packages/platform에서만 한다". `import.meta.env.MODE` 비교도 같은 규칙에 걸린다.
   - 기존 `noTossSdkImportRules`가 `packages/platform/src/toss/**`를 제외한 모든 곳(platform/web 포함)에 적용되는지 확인하고, 아니면 적용 범위를 넓힌다.
   - 검증: 일부러 `apps/web/src/routes/index.tsx`에 `if (platform.channel === 'toss')`를 넣고 `pnpm lint`가 실패하는 것을 확인한 뒤 되돌린다(PR 본문에 출력 붙임).

### 테스트 (Vitest)

- `packages/platform`: `runLocalStoreContractTests('dexie', () => createDexieLocalStore(`test-${n}`))`(`fake-indexeddb/auto`를 setup 파일에서 import, 테스트 환경 `node`), `runLocalStoreContractTests('toss-storage', () => createKvLocalStore(new MemoryStringKV()))`. 둘 다 전체 통과.
- Dexie: 같은 DB 이름을 다시 열어도 데이터가 남아 있다(영속성); `close()` 후 다시 `createDexieLocalStore`로 열린다.
- KV: 키 정렬이 revision 숫자 순서와 같다(revision 9 → 10 순서 테스트); `keys()` 접두 필터가 다른 prefix 키를 섞지 않는다.
- Golden 통과(engine-client 런타임을 테스트에서 import): `@offside/fixtures`의 `career01EngineCommands`를 `createEngineClient({ store: <dexie>, simulator: inlineSimulator })`로 실행 → `stateHash`가 golden과 같다. KV 구현도 같은 테스트.
- `webPlatform.session.getBearerToken()`이 `null`; `tossPlatform.theme.forced === 'dark'`; `webPlatform.theme.forced === null`; `tossPlatform.openExternal`은 `location`을 건드리지 않는다(spy).
- `apps/web`: 위 6의 모드 테스트; 기존 테스트 유지.
- Lint 스캔 테스트(`packages/platform/src/boundary.test.ts`): `packages/platform/src/**`(테스트 제외)에서 `@offside/engine-client`의 non-type import가 없다(파일 스캔).
