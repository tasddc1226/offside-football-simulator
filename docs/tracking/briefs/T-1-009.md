## 목표
확정된 선수가 진로 이벤트(EVT-CON-002)를 고르고, 입단 테스트(EVT-CON-003)를 치르고, 제안을 비교해 계약에 사인한 뒤 대시보드에 도착한다. 이벤트 화면은 팩 정의로 그리는 범용 화면 하나이며 SCR-007·008은 그 변형이다. 모든 확정은 전용 결정 화면에서만 일어나고 대시보드는 아무것도 확정하지 않는다.

## 범위
- 만질 패키지·경로: `apps/web`만(`src/routes/career.$careerId.{path,tryout,event,offers,contract}.tsx`와 `career.$careerId.index.tsx`(SCR-029), 화면 모듈, `src/engine/career-actions.ts`의 `resolveEvent`·`acceptOffer` 추가, `src/shared/career-route.ts`·`labels.ts` 확장, `src/shared/narrative.ts`, `e2e/`). 다른 패키지는 만지지 않는다. 필요한 export가 없으면 PR 본문에 적고 멈춘다.
- 만들 것:
  1. **액션 추가**(`src/engine/career-actions.ts`): `resolveEvent(engine, careerId, choiceId)` — `state.pending.kind === 'EVENT'`의 `eventId`로 `pack.eventsById`에서 정의를 찾아 `RESOLVE_EVENT { eventId, definitionVersion: def.version, choiceId, outcomes: choice.outcomes.map(o => ({ id, weight, effects, addTags?, removeTags? })) }`를 보낸다. 팩 effect는 스키마 파싱으로 `EFFECT_DEFAULTS`가 채워진 완전한 domain `Effect` 형태다(변환 함수를 두고 테스트로 보증). `acceptOffer(engine, careerId, offerId)` — `ACCEPT_OFFER { offerId }`. 둘 다 `ExecuteSuccess`(`outcomeId`·`roll`·`appliedEffects`·`domainSnapshot`)를 돌려준다.
  2. **서사 렌더** `src/shared/narrative.ts`: `renderNarrative(text, tokens)` — `{name}`, `{club}`, `{manager}`, `{rival}`, `{captain}`, `{team}`, `{delta:formatted}`와 조사 접미(`{name:이/가}` 등, `PARTICLE_PAIRS`)를 치환한다. `name`은 선수 이름, `team`·`club`은 현재 팀(계약 있으면 `contract.teamName`, 없으면 배경 시작 팀 이름), 나머지는 팩 `narrativeTokens`의 첫 값. 받침 유무는 마지막 글자 유니코드 계산으로 판정(테스트: 김서준이/가, 한강 FC은/는 등).
  3. **범용 이벤트 화면 SCR-013** `/career/$careerId/event`: `pending.kind !== 'EVENT'`면 `screenForCareer`로 redirect. `PlayerHeader` + `StatusStrip`(U18: Base OVR·폼·체력) + 서사(`narrative.situation`) + 선택지 `ChoiceCard`(`RadioGroup`, `riskLevel`은 팩 `riskLabel` HIGH/MEDIUM/LOW → 라벨 "높음/보통/낮음", `effects`는 `previewEffects[].label`) + "확정" CTA(선택 전 비활성). 확정 → COMMITTING → `resolveEvent` → 결과를 라우터 상태/검색 파라미터가 아닌 **커리어 상태**에서 다시 읽어 SCR-014로 이동(`/career/$careerId/event/result?rev=<revision>`; 새로고침·뒤로 가기가 roll을 다시 소비하지 않는다). 선택 시 `choice_previewed(eventId, choiceId)`.
  4. **결과 화면 SCR-014** `/career/$careerId/event/result`: 직전 `EVENT_RESOLVED` 타임라인 항목(`refId = eventId:choiceId:outcomeId`)으로 팩의 outcome을 찾아 `ResultCard`(`kind` = outcome `kind` SUCCESS/NEUTRAL/FAIL/FIXED → 라벨 "성공/보통/실패/확정", `title` = outcome `title`, `body` = 선택지 라벨, `effects` = `appliedEffects` 요약 "전술 적합도 +6(다음 시즌 1단계부터)"처럼 라벨·부호·적용 시점, `tags` = `addTags`). "다음" → `advance` 실행 → `screenForCareer(새 상태)`로 이동(pending EVENT → 그 이벤트 화면, OFFERS → SCR-009, `NOTHING_TO_ADVANCE`면 SCR-029). "리플레이"는 같은 결과를 다시 보여 주는 것뿐(명령 없음). `rev`가 현재 revision과 다르면(뒤로 가기 등) 그 revision의 타임라인 항목을 그대로 보여 준다.
  5. **SCR-007 진로 선택** `/career/$careerId/path`: EVT-CON-002 전용 변형. 범용 화면을 재사용하되 위에 "정찰 범위 {scoutedPotentialMin}~{scoutedPotentialMax}"와 세 경로의 성격(팩 `previewEffects`)을 강조한 `CompareCards`(3열: 성장 기대·출전 기대·제안 범위)를 더한다. `EVENT_SCREEN_OVERRIDES`가 이 라우트로 보낸다(T-1-007). 확정 로직은 동일.
  6. **SCR-008 입단 테스트** `/career/$careerId/tryout`: EVT-CON-003 전용 변형. 선택지(공격적/안정적) 확정 → 명령이 **먼저** 실행되어 결과가 저장된 뒤 "테스트 진행" 연출(`Stepper` 3단계 "몸풀기 → 실전 → 평가", 총 1.5초, `reducedMotion`이면 즉시, "건너뛰기" 버튼) → SCR-014. 새로고침·건너뛰기가 결과를 바꾸지 않는다(테스트).
  7. **SCR-009 제안 비교** `/career/$careerId/offers`: `pending.kind !== 'OFFERS'`면 redirect. 제안 1개면 카드 하나, 2~3개면 `CompareCards`(행: 팀, 리그(YOUTH "유스"/1·2·3부), 기간(시즌), 주급(원, `toLocaleString('ko-KR')`), 계약금, 역할 약속(라벨), 등번호, 전술 적합도). 배지: 가장 높은 리그, 출전 기회 높음(역할 약속이 가장 높은 제안). "경쟁자 수"는 도메인에 없어 표시하지 않는다(PR 본문에 명시). 각 카드 "이 제안 보기" → `/career/$careerId/contract?offerId=…`. 제안 0개는 도메인 규칙상 없지만 `EmptyState`("제안이 없습니다. 허브로")를 둔다.
  8. **SCR-010 계약** `/career/$careerId/contract?offerId=`: 해당 제안 상세(기간·주급·보너스·역할·등번호·출전 약속 = 역할 라벨 문장), 자동 서명 표시(선수 이름을 `--os-font-display`가 아닌 본문 강조로, `signatureType: 'AUTO'` 설명 한 줄), "사인"(COMMITTING 잠금) → `acceptOffer` → 성공 시 `Toast`("계약을 맺었습니다") → SCR-029. "뒤로" → SCR-009. offerId가 pending 목록에 없거나 이미 계약이 있으면 `screenForCareer`로 redirect(사인 뒤 뒤로 가기가 계약을 재생성하지 않는다).
  9. **SCR-029 대시보드** `/career/$careerId`: `PlayerHeader`(팀 = 계약 팀 또는 배경 시작 팀, 등번호 = 계약 등번호 또는 "-"), `StatusStrip`(U18: Base OVR·폼·체력; 계약 뒤: + 전술 적합도·감독 신뢰. 처음 열리는 수치는 한 줄 설명 1회 — LocalStore kv `ui:revealed` 키에 기록), 현재 단계 문구(`age`세 · `seasonPhase` 라벨 · step), **다음 결정 카드**: pending EVENT → "결정이 기다립니다" CTA(이벤트 화면), pending OFFERS → "제안 {n}건" CTA(SCR-009), pending 없음 + nextAction `ADVANCE` → "진행" 버튼(`advance` → `screenForCareer`), 정산 단계에서 할 일이 없으면(`NOTHING_TO_ADVANCE`) 비활성 버튼 + "다음 시즌은 곧 열립니다"(D-10 5단계). 다섯 구역 `Tabs` + `DashboardSection`: 일정표(현재 step·단계, 다음 결정), 라커룸(기억 태그 = `state.tags` 칩, 관계 숫자는 표시하지 않음), 전술실(계약 전 `locked` "첫 프로 계약 후 열림"; 계약 후 역할 약속·전술 적합도·능력 20개 표), 휴대폰(계약 전 잠금; 계약 후 계약 요약), 다이어리(`CareerTimeline`: `state.timeline`을 문장으로 — CAREER_CONFIRMED "선수 생활 시작", EVENT_RESOLVED 이벤트 선택지·결과 제목, CONTRACT_SIGNED "{팀}과 계약", 비었을 때 문구). 설정·허브 링크. 대시보드에서는 어떤 명령도 확정하지 않는다(`advance`는 결정이 아니라 진행이며 결과는 전용 화면에서 확정된다).
  10. **가드·라우트 표 갱신**: `SCREEN_ROUTES`에 SCR-014(`/career/$careerId/event/result`) 추가, `career-route.ts`의 `EVENT_SCREEN_OVERRIDES` 유지. 깊은 링크가 단계와 안 맞으면 `screenForCareer`로.
