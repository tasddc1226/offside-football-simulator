# T-7-020: 시뮬레이션 해시 공급자 주입으로 `career-sim` 3배 가속 (packages/domain hash.ts + tooling/scripts, D-79 후속)

## 목표

`career-sim`(T-7-019, `tooling/scripts/career-sim.ts`)로 10만 커리어 규모를 돌리기 위해 커리어당 시간을 줄인다. 오케스트레이터 CPU 프로파일(2026-09-14 14:05, 30시즌 6커리어): self-time의 **49%가 순수 TS `sha256Hex`(`packages/domain/src/hash.ts`), 19% `encodeValue`·11% `utf8Encode`·8% 익명(`canonical.ts`), 5% GC**, 시뮬레이션 로직은 2% 미만. 도메인은 명령마다 `buildSnapshot`에서 `hashState(state)`(= `sha256Hex(canonicalize(state))`)를 계산하고(`simulate.ts` 271행), `verifySnapshot`(3967행)도 같은 값을 다시 계산한다. 끝나면 CLI가 Node `crypto`의 SHA-256을 도메인에 주입해 같은 해시 값을 훨씬 빠르게 얻고, 커리어당 시간이 30시즌 기준 3.3초 → 1.5초 이하가 된다(목표; 실측을 PR에 적는다).

## 참조 명세

- 요구사항 ID: RULE-SIM-DET(결정론), ADR-003(state hash 리플레이 검증), 도메인 순수성 규칙(CLAUDE.md — 외부 import·Node API 금지, `tooling/eslint-config` `domainPurityRules`), D-62, D-79.
- 읽어야 할 코드: `packages/domain/src/hash.ts` 전체(`sha256Hex`, `hashState`, `toHex8`), `packages/domain/src/canonical.ts`(`canonicalize`, `utf8Encode`), `packages/domain/src/simulate.ts` 260~275행(`buildSnapshot`)·3960~3975행(`verifySnapshot`), `packages/domain/src/hash.test.ts`(기존 벡터 테스트), `packages/domain/src/index.ts`(export 목록), `tooling/scripts/career-sim.ts` 상단 import·`main()`·`runParallel`(자식 프로세스도 같은 진입점이라 주입이 자식에서도 일어나야 한다), `tooling/scripts/career-sim.test.mjs`.

## 범위

- 만질 경로: `packages/domain/src/hash.ts`, `packages/domain/src/index.ts`(re-export 1줄), `packages/domain/src/hash.test.ts`(기존 파일에 케이스 2개 추가), `tooling/scripts/career-sim.ts`, `tooling/scripts/career-sim.test.mjs`(기존 케이스 안 단언 추가).
- 만들 것:
  1. `hash.ts`: `export type Sha256Provider = (input: string) => string;` 와 `export function setSha256Provider(provider: Sha256Provider | null): void`. 모듈 변수 하나에 보관하고 `sha256Hex(input)`는 provider가 있으면 `provider(input)`을 돌려주고, 없으면 지금의 순수 구현을 그대로 쓴다. provider 경로에서는 `utf8Encode`를 부르지 않는다(공급자가 UTF-8 인코딩을 직접 한다). 순수 구현·상수·기존 export는 변경하지 않는다. 도메인 순수성: Node·브라우저 API를 import하지 않는다(주입만 받는다). JSDoc에 "해시 값은 동일해야 하며(같은 입력 → 같은 64자 hex 소문자) 호스트가 검증 책임을 진다"고 적는다.
  2. `index.ts`: `setSha256Provider`·`Sha256Provider` re-export.
  3. `career-sim.ts`: 진입점(`main()` 시작, 자식 프로세스 포함)에서 `import { createHash } from 'node:crypto'`로 `setSha256Provider((input) => createHash('sha256').update(input, 'utf8').digest('hex'))`를 설치한다. 옵션 `--pure-hash`(플래그)를 두어 주입을 끄고 순수 구현으로 돌릴 수 있게 한다(동등성 검증·회귀용). `runParallel`이 자식에 옵션을 넘길 때 `--pure-hash`도 전달한다. `summary.json` `runtime`에 `hashProvider: 'node-crypto' | 'pure'`를 넣는다.
  4. `--verify`는 지금처럼 seed 3개 두 번 실행 비교를 유지하되, 첫 seed 1개는 `--pure-hash` 상태와 주입 상태 각각 돌려 최종 `stateHash`가 같은지도 확인한다(같은 프로세스에서 provider를 켰다 끄면 된다).
- 만지지 말 것: `simulate.ts`·`canonical.ts`·룰셋·팩·`apps/**`·`packages/engine-client`·`legacy-population*.ts`·docs. 해시 계산 횟수를 줄이는 변경(lazy hash·검증 생략)은 하지 않는다 — 값과 호출 위치는 그대로, 구현만 교체.
