# T-7-004: 계약 협상 결과 배너·비활성 사유 표시, 회복 안내 문구 (이슈 #141, D-69)

## 목표

운영 QA에서 "역할 협상" 버튼이 결과 없이 소진되거나(WG·CM·ST), 같은 구단 재계약에서 항상 비활성인데 이유가 없었다(GK).
코드상 원인은 두 가지다. (1) `apps/web/src/routes/career.$careerId.contract.tsx`의 `ContractScreen`이 `pending === null`이면 협상 결과 패널보다 먼저 `null`을 반환해,
**마지막 남은 제안**에서 협상이 실패(도메인은 `ok:true`로 제안을 철회하고 `pending: null`)하면 빈 화면이 된다. (2) 제안의 `negotiable` 맵이 생성 시점에 정해져
(재계약 `role:false`, 안전 잔류 전부 `false`, 임대 `wage/length:false`, 첫 계약 전부 `false`) 버튼만 비활성이고 사유가 없다. 도메인·룰셋은 바꾸지 않는다.

## 참조 명세

- 요구사항 ID: SCR-019(제안 비교·협상)·SCR-020, FR Phase 3 "제안 유효기간과 한 차례 협상", D-69(협상 결과는 항상 표시, 불가 사유 명시)
- 읽어야 할 문서: `docs/phases/phase-03-contract-and-transfer.md`, `docs/qa/2026-09-07-production-six-cases/README.md` 결함 2, `docs/qa/2026-09-07-production-three-perspectives/README.md` P1-2
- 코드 진입점: `contract.tsx`(`NegotiationResultPanel` 91~141행, 이른 반환 약 205행, `handleNegotiate` 380~415행, 버튼 632~644행), `apps/web/src/shared/transfer-view.ts`(`canNegotiateOffer` 170행, `buildNegotiationResultView` 243행), `apps/web/src/routes/career.$careerId.offers.tsx`(`shouldShowRecoveryOpportunityNotice` 53~70행, 안내 문구 218~223행). 도메인 실패 사유는 `packages/domain/src/simulate.ts` `negotiateOffer`(2365~2513행, `NOT_NEGOTIABLE` 조건 2404~2413행) — 읽기만.

## 범위

- 만질 패키지·경로: `apps/web`만 — `contract.tsx`, `transfer-view.ts`(+테스트), `offers.tsx`(+테스트), 필요 시 `apps/web/e2e/transfer.spec.ts` 기대 문자열.
- 만들 것:
  1. **결과는 항상 보인다.** `pending === null`이어도 현재 `offerId`에 대한 협상 결과(`buildNegotiationResultView`)가 있으면 `NegotiationResultPanel`과 다음 행동 버튼("제안 목록으로", 목록이 비었으면 "커리어 홈")을 렌더한다. 제안이 철회돼 목록에서 사라진 경우(기존 209~216행 경로)도 같은 패널을 쓴다.
  2. **패널로 이동.** 협상 mutation이 끝나면 결과 패널을 `scrollIntoView({ block: 'nearest' })`하고 `tabIndex={-1}`로 포커스한다. 도메인이 `ok:false`(`NOT_NEGOTIABLE`·`OFFER_EXPIRED` 등)를 돌려주면 버튼 바로 아래 인라인 오류 문구로 보여 준다(기존 400~405행 경로를 버튼 근처로).
  3. **비활성 사유.** `transfer-view.ts`에 `negotiationDisabledReason(offer, revision, ask): string | null`을 추가한다. 우선순위와 문구는 고정: 제안이 OPEN이 아니면 `'이 제안은 더 이상 열려 있지 않습니다'`; `!offer.negotiable[key]`면 `` `이 제안 유형에서는 ${label} 협상이 열리지 않습니다` ``; `offer.negotiatedAsk !== null`이면 `'협상 기회 1회를 이미 사용했습니다'`; `ask === 'ROLE' && offer.rolePromise === 'STARTER'`면 `'이미 최고 역할(주전)입니다'`; 아니면 `null`. `canNegotiateOffer`는 그대로 두고 이 함수가 `null`일 때만 활성이 되도록 버튼에서 둘을 함께 쓴다. 비활성 버튼에는 `aria-describedby`로 사유를 연결하고, 협상 카드 하단에 비활성인 항목의 사유를 한 줄씩 `os-muted` 캡션으로 보여 준다.
  4. **세 버튼이 모두 비활성인 제안**(안전 잔류·첫 계약)에는 캡션 한 줄: `현 구단 잔류·첫 계약 제안은 협상 없이 조건 그대로 결정합니다`.
  5. **회복 안내 문구.** `offers.tsx` 218~223행의 "최근 두 시즌 출전이 없었습니다"를 정책값 기반으로 바꾼다: `n = policy.zeroMinutesConsecutiveSeasons`가 1이면 `지난 시즌 출전이 없었습니다.`, 2 이상이면 `` `최근 ${n}시즌 출전이 없었습니다.` ``. 뒤 문장("현재 계약 유지와 하부리그 기회를 비교해 보세요. 역할 약속은 출전 보장이 아니며 경쟁 상황도 함께 확인하세요.")은 유지.
- 만지지 말 것: `packages/domain`·`packages/content`(협상 성공률·`negotiable` 생성 규칙은 룰셋), `ContractSignature.tsx`([T-7-007](T-7-007.md)), `labels.ts`([T-7-005](T-7-005.md)), `packages/ui`, docs.
