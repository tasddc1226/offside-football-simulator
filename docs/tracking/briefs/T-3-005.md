# T-3-005: 계약·제안·협상·이적/임대 결과 화면과 TEST-E2E-003 (web)

## 목표

T-3-003의 이적시장 상태기계와 T-3-004의 저장·동기화 계약을 실제 브라우저 여정으로 연다. 계약 마지막 시즌의 step 7 사전 협상, 결산 뒤 최소 3개 제안 비교, 제안별 1회 협상·거절·수락, 완전 이적/임대/잔류 결과와 다음 프리시즌까지 한 흐름으로 동작해야 한다. 첫 프로 계약 SCR-009·010은 회귀 없이 유지하고, Phase 3 상태에서는 SCR-017·019·020의 정보·행동 계약을 적용한다.

## 0. 시작 전 도달성 감사와 정지 규칙

- T-3-003 현재 흐름은 `OFFERS`·`CONTRACT`·`LOAN_RETURN`을 열지만, `EVT-CON-010(presentation:RUMOUR)`을 step 7에서 여는 전용 생성 경로가 main에 실제로 있는지 먼저 증명한다. `selectEligibleEvents`는 D-52에 따라 RUMOUR을 일반 EVENT 슬롯에서 제외하고, 현재 step 7 캘린더는 CONTRACT 슬롯이므로 단순히 활성 팩만 0.2.0으로 바꿔서는 SCR-019가 도달하지 않을 수 있다.
- 생성 경로가 없으면 클라이언트가 가짜 pending·태그를 만들거나 domain 파일을 조용히 수정하지 않는다. 재현 근거와 최소 상태 전이 제안(새 서버 명령 없이 `RESOLVE_EVENT` 재사용)을 Orca 질문으로 오케스트레이터에게 올리고, 독립적인 SCR-017·020·TEST-E2E-003 작업은 계속한다.
- LOAN_RETURN도 현재 `screenForCareer`가 SCR-029로 떨어뜨리므로 실제 전용 결정 UI가 없는 상태다. 이 경로는 이 작업에서 반드시 닫는다.

## 1. 화면 분기·표시 모델

- 첫 계약 `market.reason === 'FIRST_CONTRACT'`는 기존 SCR-009·010 문구·퍼널 이벤트를 유지한다. `PRE_NEGOTIATION`은 SCR-017, 결산 뒤 `EXPIRED|INTEREST` 시장은 SCR-017 제안 비교, RUMOUR 정의는 SCR-019, 수락 직후 확정 상태는 SCR-020으로 분기한다. 라우트는 기존 `/offers`·`/contract`를 재사용하거나 새 하위 라우트를 둘 수 있지만 `SCREEN_ROUTES`·deep-link guard·뒤로 가기 규칙을 한 정본으로 유지한다.
- 순수 view-model helper를 두고 단위 테스트한다. 제안 카드에는 kind, 팀·리그, 기간·주급·계약금, 역할, `appearancePromise.minutesShareBp`, `positionPlan`, `tacticalFitEstimate`, 경쟁 순위·OVR gap, 유효 revision, 협상 가능 항목/상태, LOAN의 원소속·기간·급여 분담·buy option을 표시한다. 없는 값은 `—`; 원 단위는 정수 포맷; 내부 id·bp 원문은 노출하지 않는다.
- 360px에서 3열 가로 스크롤을 만들지 않고 기존 `CompareCards`의 모바일 스택/데스크톱 비교를 사용한다. 차이가 있는 행, 안전 잔류, 철회·만료, 이미 협상한 제안이 시각·텍스트·접근성 상태로 구분돼야 한다. 색만으로 구분하지 않는다.
- SCR-017 상단과 대시보드 휴대폰 탭에 현재 팀·역할·계약 잔여 시즌·주급·출전 약속 이행/위반 수, 시장 사유와 제안 수를 표시한다. `truePotential`·내부 시장가치 입력은 노출하지 않는다.
- 이적료 표시는 `Contract` 저장 필드를 새로 만들지 않는다. TRANSFER 제안의 `offer.transferFeeMinor`, LOAN의 `loan.buyOptionMinor`를 화면 투영으로만 보여준다(T-3-003 사후 결정).

## 2. 명령·응답 유실·확정 안전성

- `career-actions.ts`에 strict domain 명령을 그대로 보내는 `negotiateOffer`, `rejectOffer`, `resolveLoanReturn` 어댑터를 추가한다. 제안별 협상 버튼은 `negotiable`이 true이고 state가 OPEN일 때만 한 번 활성화한다. 제출 중 중복 클릭은 `ScreenStateView`/committing guard로 막고, 서버 결과를 받은 뒤 최신 snapshot으로 즉시 다시 그린다.
- 협상 성공(COUNTERED)은 바뀐 항목을 전/후로, 실패(WITHDRAWN)는 철회 원인과 남은 대안을 보여준다. 개별 거절 뒤 남은 제안, 전부 거절 뒤 안전 잔류가 실제 domain 결과와 일치해야 한다. 만료된 제안 deep link는 최신 `screenForCareer` 목적지로 보낸다.
- `ACCEPT_OFFER`·`LOAN_RETURN`은 성공한 snapshot이 로컬 저장·동기화 checkpoint에 먼저 반영된 뒤 SCR-020 결과를 보여준다. 화면용 결과는 마지막 타임라인과 전/후 상태를 저장하기 전에 캡처하거나 결정론적으로 재구성하되 별도 도메인 상태를 만들지 않는다. 새로고침·성공 응답 유실·뒤로 가기에서도 같은 명령을 다시 보내거나 재협상하지 않는다.
- SCR-020은 이전/새 팀, RENEWAL/TRANSFER/FREE_AGENT/LOAN/RETURN/PERMANENT 결과, 새 계약, 역할·전술·경쟁, 관계 변화 reasonTag를 설명하고 CTA 하나로 대시보드 또는 SCR-005 프리시즌에 간다. 팀이 바뀌어도 Base OVR 전/후는 같음을 화면 테스트로 고정한다.
- LOAN_RETURN은 RETURN과 조건을 만족한 PERMANENT만 보여주며 buy option이 없거나 출전 기준 미달이면 PERMANENT를 렌더하지 않는다. 원계약 만료 자동 FA는 복귀 문맥과 새 시장을 순서대로 설명한다.

## 3. RUMOUR 변형·팩 버전

- 도달성 게이트가 해소된 경우 `presentation:'RUMOUR'`만 SCR-019 변형으로 렌더한다. 공식 `Offer`가 아님을 제목·배지·CTA에서 명시하고, 관심 표명/침묵/잔류 선언의 preview와 현 구단 팬·감독 영향을 선택 전에 보여준다. 확정은 기존 `RESOLVE_EVENT`; 결과는 SCR-014 계약을 재사용한다.
- `apps/web/src/shared/narrative.ts`의 허용 토큰에 `agent`를 추가하고 0.2.0 `{agent}`가 치환되는 단위 테스트를 둔다. `STATIC_TOKEN_KEYS`와 실제 `NarrativeTokenValues`가 어긋나지 않아야 한다.
- 0.2.0 활성화가 이 작업에 필요하면 `ACTIVE_CONTENT_PACK_VERSION`만 명시적으로 바꾸고 새 커리어/e2e가 0.2.0을 저장하는지, 기존 0.1.0 snapshot이 자기 팩으로 replay/import되는지 검증한다. `playtested:false`·`PROTOTYPE` 표시는 제거하지 않는다. 서비스 시즌 포인터·D1 seed는 이 작업에서 바꾸지 않는다.

## 4. 테스트·인수 조건

- 단위/컴포넌트: 시장 사유별 화면 분기, Offer 4종/상태별 행, 제안 유효성, 협상 가능/1회/철회, 개별·전체 거절, LOAN_RETURN 옵션, 결과 투영, deep link·뒤로 가기·응답 유실, agent 토큰, 360px CompareCards, 키보드·focus·aria-live.
- TEST-E2E-003을 최소 두 여정으로 둔다: (a) career-10 계열 제안 3개 이상 비교 → 한 제안 협상 → 완전 이적/FA 확정 → SCR-020 → 새 팀 프리시즌, (b) LOAN 수락 → 임대 시즌 → RETURN 또는 buy option 완전 이적 → SCR-020. 각 여정에 새로고침 1회와 빠른 이중 클릭 1회를 넣고 최종 revision/hash·열린 stint 1개·Base OVR 불변을 확인한다.
- SCR-017·019·020 axe 검사와 키보드만으로 제안 비교→협상→확정이 가능해야 한다. 전체 기존 e2e에서 첫 계약·시즌 helper가 새 분기를 안전하게 통과해야 한다.
- `pnpm install --frozen-lockfile && pnpm lint && pnpm lint:deps && pnpm typecheck && pnpm test && pnpm build && pnpm --filter @offside/web check:bundle && E2E_PORT=5198 pnpm --filter @offside/web e2e` 통과. 샌드박스 포트 권한 실패는 정확히 보고하고 GitHub Browser gates로 보완한다.
