# T-4-021: [핫픽스] season.spec:17 전체 흐름 테스트 — STAY 수락 뒤 프리시즌 도착 허용

## 목표

> **D-61(2026-09-05 16:02 사용자 지시)**: 새 테스트 코드를 작성하지 않는다. 이 작업은 동작 변경(PR #76)으로 깨진 **기존** e2e 테스트의 갱신이다.

`apps/web/e2e/season.spec.ts:17`("시즌 전체 흐름: … → 시즌 결산 → 다음 시즌")은 매 실행 새 seed를 쓴다. 시즌 1 결산 뒤 INTEREST 시장이 열리는 seed에서는 74~78행이 "제안 보기" → `signFirstOffer`(안전 잔류 STAY) → "계획하러 가기" 링크를 기대하는데, PR #76 이후 STAY 결과 카드의 CTA는 "새 시즌 준비"라 `/preseason`(프리시즌 계획 화면)에 바로 도착하므로 78행 `expect(planCta).toBeVisible()`이 실패한다(PR #78 검증 체인 17:30, 스냅샷 heading "프리시즌 계획"). seed 의존이라 간헐적이며 PR #78과 무관하다.

## 참조·선행

- 정본: [T-4-019](T-4-019.md)(같은 원인의 1차 수정, PR #81), [T-4-011](T-4-011.md).
- 코드: `apps/web/e2e/season.spec.ts:69~78`, `apps/web/e2e/helpers/player-creation.ts` `signFirstOffer`(STAY → "새 시즌 준비" → `/preseason` 허용됨).

## 1. 작업

- 78행을 "이미 `/preseason`에 있으면 통과, 아니면 `계획하러 가기` 링크가 보여야 한다"로 바꾼다. 예: `if (!/\/preseason$/.test(page.url())) await expect(planCta).toBeVisible();` 또는 `planCta.or(page.getByRole('heading', { level: 1, name: '프리시즌 계획' }))`. 69~70행 주석에 STAY → 프리시즌 도착 경우를 한 문장 추가한다.
- 다른 `signFirstOffer` 호출부(`injury.spec.ts:97`, `staging-rehearsal.spec.ts:55`, `transfer.spec.ts`, 헬퍼 내부 137·266행)는 첫 계약 또는 시즌 중 재계약 경로라 프리시즌에 닿지 않는다 — 읽어서 확인만 하고 수정하지 않는다(다르면 questions에).
