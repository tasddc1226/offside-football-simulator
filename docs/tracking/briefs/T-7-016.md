# T-7-016: 확인된 계약·라커룸 설명 부족 개선

## 목표
최신 운영 배포에서 확인한 #147·#165의 남은 UI 설명 문제를 게임 규칙 변경 없이 해결하고 PR을 연다.

## 참조 명세
- 요구사항: SCR-010, SCR-029 및 라커룸 관계 표시 명세.
- CLAUDE.md, docs/tracking/README.md, 관련 화면 명세를 읽는다.
- 검증 기준 배포: 3640524ce97e4e6905123c139ddec009f071ff5c. 구현은 최신 origin/main에서 시작한다.

## 범위
- apps/web의 계약 표시 함수·관련 화면, 라커룸 표시 및 기존 테스트의 필요한 기대값 갱신.
- #147: 남은 계약 0시즌을 계약 소멸처럼 읽히지 않게 마지막 계약 시즌으로 표현한다. 최소 출전 경기 가드·계약 계산은 그대로 둔다.
- #165: 공개된 수치는 현재 관계 값임을 표시한다. 화살표는 최근 로그 변화 방향임을 설명하고 이번 시즌 변화량으로 부르지 않는다. 수치 점진 공개 규칙과 비공개 상태를 보존한다.
- #169는 범위에서 제외한다. 배포판의 신규 커리어는 FAST 모드로 고정되어 주장 기억을 기록하는 일반 사건이 열리지 않으므로, 해당 사건을 발견할 수 있다는 안내를 추가하지 않는다.
- 국적 목록 확대(#161), 국적·성별의 게임상 의미 변경(#162), domain/content/API/공용 UI CSS, 추적 보드·결정 로그는 수정하지 않는다.

## 완료 조건
- 기존 관련 단위 테스트·lint·typecheck가 통과한다. D-61에 따라 새 테스트 코드는 추가하지 않으며 필요한 기존 기대값만 갱신한다.
- ego-browser 스킬로 로컬 변경 화면의 360px·다크·키보드·모션 감소 동작과 가로 넘침을 확인한다. 증거는 저장소 밖에 둔다.
- 변경을 직접 단일 패스로 검토한다. PR에 요구사항·해결 범위·검증 및 미검증 범위를 적는다.
- PR 직전 git fetch origin 후 git merge origin/main, 필요한 검증, commit/push/PR 생성까지 수행한다. merge·운영 배포·이슈 별도 종료는 하지 않는다.

## 실행 제약
- 구현자는 sol이며 서브에이전트를 만들지 않는다. 작업 디렉터리는 T-7-016-issue-ui-clarity 전용 워크트리다.
- ego-browser task space는 offside-ui-clarity-0914, 로컬 포트는 5416, E2E_PORT는 5516. 다른 작업의 브라우저·서버·데이터는 건드리지 않는다.
- 의존성 설치는 pnpm install --frozen-lockfile. 전체 테스트와 E2E는 다른 워커와 동시에 과부하를 만들지 않도록 오케스트레이터와 순서를 맞춘다.
- 상태·파일·SHA·명령 결과·PR URL을 오케스트레이터에 보고한다. 브리프는 오케스트레이터가 작성했으므로 그대로 커밋에 포함한다.
