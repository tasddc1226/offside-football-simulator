# T-3-006: 콘텐츠 팩 0.2.0 — 루머·잔류 선언·에이전트·약속 위반·친정팀 이벤트(EVT-CON/MEDIA, PROTOTYPE)·narrative 토큰 확장·팀 풀 8→12(U-013) (content)

## 목표

Phase 3 화면(T-3-005)과 시장 생성(T-3-002)이 쓸 **콘텐츠**를 만든다. 끝나면 (1) 팩 `0.2.0`이 0.1.0의 이벤트 10개·챕터 3개·토큰을 그대로 품고 PRO 단계 이벤트 5개를 더해 번들 로더에 등록되며(활성 팩은 **0.1.0 그대로** — 전환은 별도 작업), (2) 워커가 쓴 문구는 전부 `authoring: 'PROTOTYPE'`·manifest `playtested: false`로 표시되고(U-013 (A)), (3) 룰셋 1.0.0의 가상 구단이 12개가 되어(U-013 사용자 결정) 첫 계약·이적시장 후보가 넓어지고, (4) narrative 토큰 사전이 12구단·에이전트 이름을 갖는다.

## 참조 명세

- 읽는 순서: `docs/content/kickoff/event-catalog.md`(3절 계약·이적 후보, 7절 미디어 후보, "JSON 승격 전 상세화 필수 필드") → `docs/development/04-event-engine.md`(이벤트 정의·공정성 규칙·콘텐츠 검증) → `docs/development/12-brand-guidelines.md`(어휘 폐쇄 목록, 실명 금지, 조롱 금지) → `docs/tracking/phase-3-4-plan.md` D-43·D-44·D-47·D-52·5절(U-013) → `docs/tracking/briefs/T-3-001.md`의 "조건 DSL" 표(`contract.*`·`career.*` 경로)와 `presentation`.
- 현재 코드: `packages/content/packs/0.1.0/`(events·chapters·narrative·manifest), `src/packs/load-content-pack.ts`(`PACK_VERSIONS`·정적 import), `src/schema/{event,narrative,pack-manifest}.ts`, `src/cli/`(`content:validate`, 체크섬), `src/gender-invariant.test.ts`, `rulesets/1.0.0/ruleset.json`의 `teams`·`leagues`·`competitorNames`, `packages/domain/src/offers.ts`(`buildTeamPool` — 팀 풀 크기가 첫 계약 추첨에 쓰인다), `apps/web/src/engine/versions.ts`(`ACTIVE_CONTENT_PACK_VERSION` — **바꾸지 않는다**).
- 선행·투입 조건: **T-3-001(PR #48) 머지 뒤 `origin/main`에서 시작.** 동시 진행 워커: **T-3-002**(룰셋 `transferRules`를 `offerRules` 뒤에 삽입 — 이 작업은 `teams`·narrative만 만진다), **T-4-001**(content `schema/event.ts`에 `rehabPlan`·`callUp`, `schema/effect.ts`, 룰셋 트랙 B 섹션) — `schema/event.ts`에는 `authoring` 필드 한 줄만 더한다. 먼저 머지된 쪽이 있으면 `git merge origin/main` 뒤 전체 체인.

## 해야 할 일

### 1. 팩 0.2.0

- `packages/content/packs/0.2.0/`을 0.1.0 복사로 만들고 manifest `contentPackVersion: '0.2.0'`, `compatibleRulesetVersions: ['1.0.0']`, `clientMinVersion` 유지, `playtested: false`, `files`·`checksum`은 CLI로 재계산. `load-content-pack.ts`의 `PACK_VERSIONS`에 `'0.2.0'`을 더하고 정적 import로 등록(0.1.0은 그대로 — 골든·e2e는 0.1.0을 계속 쓴다). `CONTENT_VERSION`·`ACTIVE_CONTENT_PACK_VERSION`·서비스 시즌 seed는 바꾸지 않는다.
- 0.1.0의 기존 정의 10개·챕터 3개는 0.2.0에서도 **바이트 동일**(id·version 유지). 0.1.0 디렉터리는 손대지 않는다.

### 2. 새 이벤트 5개(전부 `phases: ['PRO']`, `authoring: 'PROTOTYPE'`, `safety.minorSafe: true`, 선택지 2~3개, 문구 한국어, 실명·실제 구단 금지)

| ID | presentation | 발생 조건(DSL 경로는 T-3-001 표의 것만) | 선택 축 → 효과·태그 |
|---|---|---|---|
| `EVT-CON-010` 루머와 관심 | `RUMOUR` | `season.step == 7`, `contract.kind != 'LOAN'`, `contract.isLastSeason == 0`, 그리고 `season.stats.*` 중 출전·평점 계열 하나로 "관심을 받을 만함"을 표현 | 관심 표명(태그 `이적_희망`, fans −4, managerTrust −4) / 침묵(변화 없음, fans −1) / 잔류 선언(태그 `잔류_선언`, fans +5, managerTrust +4). 선택지에 `previewEffects`로 "다음 결산 뒤 시장이 열림/안 열림"을 문구로 예고 |
| `EVT-CON-011` 에이전트 제안 | 없음 | `career.proSeasons >= 1`, `hasTag` 아님 `에이전트_계약`·`직접_협상`; `exclusionTags: ['에이전트_계약']` | 계약(태그 `에이전트_계약`, agent +8, fans −2 — "제안 수 +1" 예고) / 보류 / 직접 협상(태그 `직접_협상`, agent −5, managerTrust +3) |
| `EVT-CON-012` 약속이 지켜지지 않았다 | 없음 | `contract.promiseBreaches >= 1`, `season.step <= 3` | 면담 요구(managerTrust −3, context.squadStatus +5 CONTEXT, 태그 `이적_희망` 확률 outcome) / 언론에 말함(fans +3, managerTrust −8, 태그 `언론_충돌`) / 참는다(morale −3, captain +3) |
| `EVT-CON-013` 재계약 압박 | 없음 | `contract.seasonsRemaining <= 1`, `contract.kind == 'PERMANENT'`, `season.step` 4~6 | 장기 안정 선호(태그 `장기_계약_선호`, managerTrust +3) / 짧게 가고 싶다(태그 `단기_계약_선호`) / 시장을 보겠다(태그 `이적_희망`, managerTrust −5, agent +3) |
| `EVT-MEDIA-006` 친정팀 원정 | 없음 | `career.permanentTransfers >= 1`, `season.phase == 'LEAGUE'`, `cooldown.seasons 1` | 존중(fans +2) / 세리머니 예고(fans −6 — 라이벌 여부는 도메인이 모름, 문구로만 위험 예고 / 태그 `도발_예고`) / 질문 회피(변화 없음, 태그 `언론_회피`) |

- 태그 `이적_희망`·`잔류_선언`·`에이전트_계약`은 T-3-002 시장 생성기가 읽는 **정확한 문자열**이다(오탈자 금지, 테스트로 고정). `이적_희망`과 `잔류_선언`은 서로 `exclusionTags`로 배타. 같은 outcome이 두 태그를 같이 주지 않는다.
- 효과는 `RELATION`(managerTrust·captain·fans·agent, SUM)·`CURRENT`(morale)·`CONTEXT`(squadStatus)만, `PERMANENT` 금지, 한 outcome의 관계 변화 절댓값 ≤ 8. 모든 FAIL outcome에 회복 경로(만료 또는 후속 없이도 커리어가 막히지 않음 — 실패가 계약을 끝내지 않는다).
- 문구: 상황 `narrative.situation`은 토큰(`{club}`·`{manager}`·`{name}`·`{agent}`)을 쓰고 특정 성별·실제 인물·실제 구단을 암시하지 않는다(`gender-invariant.test.ts` 통과). 낮은 결과를 조롱하지 않는다(12 문서). 브랜드 어휘(대문자 영문)는 쓰지 않는다.
- `presentation: 'RUMOUR'`인 EVT-CON-010은 일반 EVENT 슬롯 후보에서 빠진다(T-3-001 규칙) — step 7 CONTRACT 슬롯에 클라이언트가 공급하는 것은 T-3-005. 나머지 4개는 일반 EVENT 슬롯 후보이며 PRO 단계에서만 뜬다(YOUTH 골든 불변).

### 3. 스키마 한 줄과 PROTOTYPE 표시

- `schema/event.ts` `EventDefinitionSchema`에 선택 필드 `authoring: z.enum(['PROTOTYPE', 'PLAYTESTED']).optional()` 추가(다른 변경 없음 — T-4-001과 같은 파일이므로 최소). 0.2.0의 새 정의 5개는 전부 `'PROTOTYPE'`, 0.1.0 정의에는 넣지 않는다.
- `docs/content/kickoff/event-catalog.md`: 3절·7절의 해당 행 상태를 "0.2.0 PROTOTYPE(T-3-006)"으로 표시하고, 새 절 "0.2.0 팩(PROTOTYPE)"에 5개 이벤트의 발생 조건·태그·효과 요약 표를 적는다. 이 문서 외 `docs/`는 고치지 않는다.

### 4. 팀 풀 8→12(룰셋 1.0.0 `teams`)

- 추가 4팀: 1부 1팀(`reputation 4`, `squadStrength 78`, `tacticalStyleId 'press'`, `wageBandId 'tier1'`, `leagueId 'league-tier1'`), 2부 1팀(`reputation 3`, `squadStrength 60`, `'press'`, `'tier2'`), 3부 2팀(`reputation 2`/`1`, `squadStrength 50`/`45`, `'possession'`/`'counter'`, `'tier3'`). 결과 분포: YOUTH 1·1부 3·2부 4·3부 4. `leagues[].teamCount`는 바꾸지 않는다(이름 있는 팀 수 ≤ teamCount − 1 유지).
- 이름 규칙: 기존 8팀처럼 가상 지명 + FC/유나이티드/시티/로버스/타운(예: `가온 시티`, `미르내 로버스` 식 — 실제 K리그·해외 구단명과 지명이 겹치지 않게; `서울`·`수원`·`전북`·`울산`·`포항`·`인천`·`대구`·`광주`·`대전`·`강원`·`제주`·`부산`·`성남`·`경남`·`부천`·`안양`·`김천`·`천안`·`전남`·`아산`·`화성`·`용인`·`충북`·`김포`·`안산` 금지). id는 kebab-case 영문. 팀 이름을 narrative `club`·`team` 배열에도 넣는다.
- 골든 영향: `buildTeamPool`의 후보 수가 바뀌어 첫 계약 추첨 결과(팀)가 바뀔 수 있다 → 골든 9종 재기록(`rngState.draws`는 불변, 팀 id·hash만 변경 — PR 본문 전후 표). e2e·web 테스트가 특정 팀 이름을 단정하면 그 단정만 최소 수정(허용 파일: `apps/web/e2e/*.spec.ts`, `apps/web/src/**/*.test.ts`, `packages/engine-client/src/testing/*`) — PR 본문에 목록.
- `competitorNames`·`leagues`·`cups`·`offerRules`·`contractRules`·`transferRules`는 바꾸지 않는다. 새 팀의 라이벌 짝(`transferRules.rivalPairs`)은 T-3-002 머지 뒤 후속 — PR 본문 "범위 밖"에 제안만 적는다.

### 5. narrative 토큰

- `schema/narrative.ts` `NARRATIVE_TOKEN_KEYS`에 `agent` 추가(가상 에이전트 이름 6개 이상, `competitorNames`·`manager` 토큰과 겹치지 않게). 0.1.0 `tokens.json`에도 `agent` 배열을 넣어 스키마를 통과시키되(빈 배열 금지) 0.1.0의 다른 값은 그대로.
- 0.2.0 `tokens.json`: `club`·`team`에 12구단 이름, `manager`·`rival`·`captain` 각 4개 이상 가상 이름.

## 제약

- 도메인 로직·`simulate.ts`·`types.ts`·contracts·`apps/*`(위 테스트 단정 예외 외)·`packages/platform`·api를 만지지 않는다. `ACTIVE_CONTENT_PACK_VERSION`·`CONTENT_VERSION`·서비스 시즌 seed·`schemaVersion` 불변.
- 실제 구단·선수·감독·에이전트 실명 금지, 조롱 문구 금지, 브랜드 어휘 폐쇄 목록 준수, 성별 불변 문구.
- 문구·주석 한국어. 커밋 `T-3-006: …`, 브랜치 `T-3-006-pack-0-2-0`. 커밋은 슬라이스별(팩 0.2.0 등록 / 이벤트 5개 / 스키마·카탈로그 / 팀 풀·골든 / 토큰).
- 서브에이전트를 띄우지 않는다 — 리뷰용이든 조사용이든 전부(gstack `/review`·`/codex`·adversarial·`/simplify`·병렬 fork·Agent/Explore 조사 에이전트 금지). 예외는 Orca PR 게이트용 `/review:pr` 1회(로컬 모드).
- e2e 전에 `lsof -nP -iTCP:5192 -sTCP:LISTEN`이 비어 있어야 한다.
- PR 직전 `git fetch origin && git merge origin/main` 뒤 전체 체인 재실행(T-3-002·T-4-001이 먼저 머지되면 `ruleset.json`·`schema/event.ts`·골든 충돌을 여기서 풀고 골든을 다시 기록). `pnpm-lock.yaml` 충돌은 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`.
- 명세·ADR·phase 계획을 고치지 않는다(카탈로그 문서 예외). 이 브리프가 정하지 않은 형태가 필요하면 그 항목만 PR 본문 "결정 필요"에 적고 나머지를 끝낸다.
