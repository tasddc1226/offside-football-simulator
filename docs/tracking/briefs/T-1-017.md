# T-1-017: Phase 1 완료 조건 보완(키보드 포지션 탭·선호 포지션 표시·국외 이전 표·결과 낭독·COMMITTING 이탈 경고)

## 목표

T-1-014가 만든 완료 조건 표(`docs/tracking/phase-1-completion.md`)에서 ❌·조건부로 남은 항목을 구현해 Phase 1을 닫는다. 새 기능이 아니라 명세에 이미 있는 항목의 미구현분이다. 항목 1은 08 "출시 차단 기준"(키보드로 P0 흐름 완료 불가)에 해당한다.

## 참조 명세

- 읽는 순서: `docs/tracking/phase-1-completion.md` 표 #1·#5·#14와 "범위 밖 발견 사항" 1~6 → `docs/development/08-testing-strategy.md` "접근성 체크리스트"·"출시 차단 기준" → `docs/development/06-ui-ux-specification.md` "공통 상태"(COMMITTING 중 이탈 시 경고) → `docs/development/02-domain-and-data-model.md` RULE-PLY-001(`preferredPosition`·`primaryPosition`) → `docs/screens/01-career-start.md` → `docs/adr/ADR-008-auth-and-account-merge.md` "개인정보", `docs/adr/ADR-009-apps-in-toss-channel.md`(국외 이전 문장).
- 선행: T-1-014(PR #34)가 main에 머지된 뒤 `origin/main`에서 시작한다(dispatch 스크립트가 그렇게 만든다). 동시 진행 워커는 없다.

## 만들 것

1. **SCR-002 포지션 구분 탭 키보드 도달(출시 차단)**. `apps/web/src/routes/career.$careerId.create.tsx` 330~360행에서 `Tabs`가 `RadioGroup` 안에 중첩돼 Radix roving-tabindex 관리자 둘이 충돌하고 `TabsTrigger` 4개가 전부 `tabindex="-1"`이다. 구조를 바꾼다(예: `Tabs`를 `RadioGroup` 밖으로 빼고 `TabsContent`마다 같은 값·핸들러를 공유하는 `RadioGroup`을 두거나, 포지션 라디오를 하나의 `RadioGroup`으로 유지하되 탭을 형제로 배치). 값 모델·"포지션 변경 시 아키타입 초기화" 규칙·라벨·`aria-label`·접근성 설명은 그대로. 인수: Tab으로 탭 트리거 도달 → 화살표로 탭 전환 → Tab으로 포지션 라디오 진입 → 화살표·Space로 선택. `apps/web/e2e/keyboard.spec.ts`의 우회(기본 골키퍼 그룹)를 없애고 "공격수 탭 → 윙어" 경로로 완주하도록 바꾼다(우회 설명 주석 삭제). 대시보드(SCR-029)의 `Tabs`는 건드리지 않는다.
2. **선호 포지션 표시(완료 조건 #5, RULE-PLY-001)**. 확정 뒤 화면(대시보드 SCR-029, 이벤트·결과 화면의 PlayerHeader)에 현재 주포지션과 함께 최초 선호 포지션을 구분해 보여 준다. 둘이 같으면 한 줄(예: `포지션 윙어`에 보조 문구 `선호 포지션과 같음` 또는 동등한 표기), 다르면 두 값을 구분해 표시(예: `주 포지션 윙어 · 선호 스트라이커`). 확정 전(DRAFT)은 지금처럼 선호 포지션만. 정확한 문구는 `docs/screens` 어휘와 `shared/labels.ts` 라벨을 따르고 PR 본문에 적는다. `preferredPosition`은 contracts·domain에 이미 있다(PR #32). 웹 단위 테스트에 "같을 때·다를 때" 2건 추가(다를 때는 테스트 상태를 직접 만들어 렌더).
3. **개인정보 처리방침 국외 이전 표(완료 조건 #14, ADR-008)**. `apps/web/src/legal/privacy.tsx`에 "개인정보의 국외 이전" 절과 표(열: 이전받는 자 / 국가 / 이전 항목 / 이전 목적 / 보유·이용 기간)를 넣는다. 행: (a) Cloudflare, Inc. — 미국 등 해외 리전(Workers·D1·Pages) — 프로필 식별자·세션·복구 코드 해시·게임 저장 데이터·오류 로그 — 서비스 제공과 저장·동기화 — 프로필 삭제 또는 보존 기간 만료 시까지(09 문서 삭제 규칙 참조); (b) Google LLC — 미국 — Google 로그인 시 Google 식별자(sub)·이메일 — 계정 연결·프로필 복구 — 연결 해제 또는 프로필 삭제 시까지. 이전 방법·시기(서비스 이용 시 네트워크를 통해 전송·저장)를 한 문장으로. 운영자 정보(U-010 "준비 중")는 그대로 둔다. 법률 자문이 아니라 ADR·문서에 적힌 사실만 옮겼다는 점을 PR 본문에 적는다. `apps/web/e2e/legal.spec.ts`에 절 제목·표가 보이는지 1건 추가.
4. **결과 확정 시 aria-live 낭독(08 접근성 체크리스트)**. 이벤트 확정 → 결과 화면(SCR-014, `career.$careerId.event_.result.tsx`) 전환 시 결과 요약(예: 결과 제목 한 줄)을 `aria-live="polite"` 영역에서 **한 번만** 낭독한다. `ScreenStateView`의 영역은 LOADING·COMMITTING 단계 문구 전용이므로 그것을 재사용하지 말고 결과 화면에 별도 영역을 둔다. `a11y.spec.ts`의 aria-live 특성화 테스트(현재 0건 기록)를 "정확히 1회 갱신"으로 바꾼다.
5. **COMMITTING 중 이탈 경고(06 "공통 상태" — COMMITTING 중 이탈 시 경고하고 재진입 시 command 결과를 조회)**. 확정 처리 중(SCR-004 KICKOFF, 이벤트 확정)에 뒤로 가기·페이지 이탈 시 경고한다. web: `platform.lifecycle.onBackPressed`(web 구현은 popstate)와 `beforeunload`를 COMMITTING 동안만 연결하고, 뒤로 가기는 확인 대화상자("처리 중입니다. 지금 나가면 결과는 다시 들어왔을 때 보입니다" 같은 문구, 계속·나가기)로 막는다. 재진입 시 결과 조회는 이미 동작한다(resilience (d)). `resilience.spec.ts` (d)를 경고 대화상자가 뜨고 "나가기"를 누르면 재진입 시 결과가 보이는 흐름으로 갱신. popstate와 대화상자 조합이 불안정하면 최소 구현(경고 대화상자 없이 `beforeunload`만)과 이유를 PR 본문에 적고 멈추지 않는다.
6. **`screen_viewed`의 `careerPhase`(발견 사항 6)**. SCR-002/003/004가 `'YOUTH'` 고정이다. Phase 1은 생성 단계가 YOUTH뿐이므로 고정값이 맞다 — 세 곳의 리터럴을 `shared`의 상수 하나로 모으고 이유를 주석으로 남긴다(state에서 읽지 않는다).
7. **완료 조건 표 갱신**: `docs/tracking/phase-1-completion.md`의 #1(우회 없음)·#5·#14를 ✅로, "범위 밖 발견 사항" 1~6에 "고침(이 PR)" 표기. #12(시각 토큰·폐기 어휘 자동 검사)와 #15(U-003)는 그대로 둔다.

## 제약

- `'toss'`·`'web'` 리터럴 비교 금지(lint), hex 색 리터럴 금지, 색·간격·글꼴은 13의 토큰(`--os-*`)만. `localStorage` 직접 접근 금지. 화면 컴포넌트에서 `import.meta.env.MODE` 검사 금지.
- 모든 사용자 문구는 한국어. 분석 payload·로그에 개인정보(성별·이메일) 금지.
- 커밋 메시지는 `T-1-017: …`로 시작, 브랜치는 `T-1-017-…`.
- 서브에이전트 리뷰를 띄우지 않는다. gstack `/review`·`/codex`·adversarial 리뷰·`/simplify`·병렬 fork 전부 금지. 유일한 예외는 Orca PR 게이트용 `/review:pr` 1회(로컬 모드)다. 리뷰는 오케스트레이터가 한다.
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
- 명세를 고치지 않는다. 항목 중 구현이 명세와 충돌하거나 불가능하면 그 항목만 PR 본문에 사유를 적고 나머지를 끝낸다.
