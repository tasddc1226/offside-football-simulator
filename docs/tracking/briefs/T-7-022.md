# T-7-022: 소속 리그 원장과 전체 순위표 수직 연결

## 목표

신규 룰셋 `1.7.0`/콘텐츠 팩 `0.6.2` 커리어가 소속 리그의 홈·원정 전체 라운드를 결정론적으로 확정하고, 같은 원장에서 현재 순위·내 경기·결산 최종 표·과거 표를 일관되게 제공한다.

## 참조 명세

- 요구사항: FR-CW-001~005, FR-CW-012, TEST-CW-001~003
- 기준: `origin/main` `51fb80c2f7dfcc32d120fff8884588d2d01e66c3`
- 검토 문서: `career-world-prd.md`, ADR-011, `20-career-world-plan.md`

## WP-01 확정 계약

### 지원 경계

- 현재 룰셋의 `league.teamCount`는 8/12/14/16이며 최대 지원 수는 **16**이다. 기존 `LeagueSchema`의 허용 범위는 소급 축소하지 않고, 새 `leagueLedgerRules.maxTeamCount`와 지원 버전 refinement만 16을 강제한다.
- 참가팀은 시즌 시작 시 팀 ID 오름차순으로 고정한다. 이름 있는 팀을 먼저 포함하고 부족분은 `${leagueId}-opp-${n}` ID·팩 템플릿 이름·기존 strength 분산 규칙으로 채운다.
- 짝수/홀수 모두 circle 방식 홈·원정 2회전이다. 홀수 팀은 내부 BYE 슬롯을 쓰되 BYE를 fixture/result/경기 수로 저장하지 않는다. 입력 팀 배열 순서는 결과에 영향을 주지 않는다.
- 전체 라운드를 기존 리그 구간 step 3~11에 `3 + floor(roundIndex * 9 / roundCount)`로 배치한다. 한 step의 모든 해당 라운드를 처리하며 컵·대표팀은 원장에서 제외한다.
- 계약이 있어 `START_SEASON` 가능한 유스/영구계약/임대 시즌과 `CAREER_BREAK` 복무 시즌을 지원한다. 복무 중 선수는 기존 `SERVICE` 결장이지만 구단 리그 라운드는 진행한다. FA/계약 없음/은퇴처럼 시즌을 시작하지 않는 상태에는 원장을 만들지 않는다. 이적·임대·복귀는 기존 시즌 경계에서 다음 시즌 참가팀을 다시 고정한다.

### 저장 및 공개 타입

- `FootballSeason.leagueLedger?: LeagueSeasonLedger` — 과거 버전은 필드 부재를 그대로 허용한다.
- `LeagueSeasonLedger = { policyVersion: '1.0.0'; leagueId; leagueName; seasonIndex; teamId; seed: RngState['s']; teams: LeagueTeamSnapshot[]; results: LeagueFixtureResult[]; completedRounds: number[] }`.
- `LeagueTeamSnapshot = { teamId; name; strength }`. 이름 override는 이 snapshot을 표시할 때만 적용하며 seed/strength에 섞지 않는다.
- `LeagueFixtureResult = [fixtureIndex, homeGoals, awayGoals]`. `fixtureIndex`는 입력 순서와 무관하게 정렬된 roster에서 재구성한 결정론적 전체 대진 배열의 0-based 위치다. fixture ID는 `seasonIndex:leagueId:round:homeTeamId:awayTeamId` 의미를 canonical separator로 인코딩하며 일정 연결·오류 문구에서만 재구성한다.
- 대진 전체는 `teams`와 policy로 재구성하고 진행 중에는 확정 결과와 완료 라운드만 저장한다. `StandingRow = { rank; teamId; teamName; played; won; drawn; lost; goalsFor; goalsAgainst; goalDifference; points }`는 원장에서 순수 파생하며 진행 중 중복 저장하지 않는다.
- `SeasonResult.finalLeagueTable?: FinalLeagueTable`만 결산 최종 표를 한 번 보존한다. 저장 rows는 `[rank, teamId, teamName, played, won, drawn, lost, goalsFor, goalsAgainst, goalDifference, points]` 고정 tuple이며, 순수 adapter가 public `StandingRow`로 펼친다. 이름을 tuple에 보존해 과거 표를 현재 팩에서 재추정하지 않는다. `SeasonSummary`/Archive는 기존 `result`를 통해 참조하며 별도 rows 배열을 추가하지 않는다.
- 룰셋 `leagueLedgerRules?`의 존재가 지원 버전 gate다. `1.7.0`은 `policyVersion`, `scoreKernel: MATCH_RULES_V1`(같은 버전의 `matchRules.homeBonus/resultTable/scoreTable`을 쓰며 결과+스코어 고정 3 draw), 승점 3/1/0, 정렬 `POINTS → GOAL_DIFFERENCE → GOALS_FOR → TEAM_ID`, 최대 팀 16을 명시한다. 구버전은 optional absence와 기존 근사 순위/hash/golden을 유지한다.

### 결과·난수·원자성

- 내 팀 fixture는 기존 `playMatch` 결과가 유일한 정본이다. 리그 원장은 그 확정 score를 홈/원정 방향으로 투영하며 재추첨하지 않는다.
- 타팀 fixture는 시즌 시작 RNG `s`를 복사한 불변 ledger seed와 `policy/season/league/fixture` namespace로 `seedRng`를 매 fixture 독립 파생해 계산한다. 기존 main RNG와 `matchRngState`를 소비하거나 갱신하지 않는다. 입력/조회/계산 순서도 결과를 바꾸지 않는다.
- 한 리그 라운드는 내 팀 결과(또는 BYE)와 모든 타팀 결과를 한 명령의 새 snapshot에 함께 넣고 그 후에만 injury/event/chapter pending을 외부에 반환한다. `fixtureId`와 `completedRounds`로 resume/retry 중복을 막는다.
- `competitions`의 리그 W/D/L/GF/GA/position, DECIDER, 우승/Legacy/결산은 모두 같은 standings 파생값을 사용한다. 컵 기록은 기존 경로를 유지한다.
- 결산에서 완전한 final table을 hash 전에 생성한다. 이미 존재하면 재생성/중복 append하지 않고 불일치면 지원 버전 데이터 오류로 실패한다.

### 상태와 UI

- 시작 전/구버전 optional 부재는 `기록 없음`으로 구분하고 0점 표를 합성하지 않는다. 지원 버전에서 진행 중 원장 부재·충돌은 데이터 오류로 처리한다.
- pending 화면에서는 마지막 원자 확정 라운드만 표시한다. 현재 표와 결산 표는 같은 domain selector/view model을 쓴다.
- 대시보드에 실제 순위/팀 수/바로 위 팀 승점 차와 완료 라운드를 표시하고, 일정·결과·과거 시즌에서 같은 표를 조회한다. 내 팀을 강조하고 상세 열은 접근 가능한 가로 스크롤 표로 제공한다.
- 승격/강등 표시는 룰셋 spot이 0보다 클 때만 하며 `순위 기준 구간이며 다음 시즌 리그 이동은 지원하지 않음`을 함께 표시한다. 대륙 진출이나 실제 승강격을 만들지 않는다.

### 예산

- 최대 16팀: 시즌당 30라운드, 240 fixture, 팀당 30경기다. 20시즌 보존은 최대 320개의 최종 row이며 타팀 fixture 상세는 결산 후 누적하지 않는다.
- UTF-8 직렬화 state hard acceptance: **262,144 bytes 이하**. commands를 포함한 실제 PUT body: **1,048,576 bytes 이하**.
- 기존 snapshot-size 및 통합 fixture 안에서 1시즌/20시즌/최대팀 사례를 확장해 실측한다. Worker 시간은 같은 명령을 baseline과 새 버전으로 반복 측정해 PR에 환경·횟수·중앙값/최댓값을 기록한다.
- 최대 shape 실측(UTF-8 canonical state / `PutCareerBody` JSON): compact fixture index 적용 후 선수 경기 기록까지 일치시킨 16팀·240결과 active 원장 **62,226 / 86,476 bytes**, compact 16행 최종 표를 가진 20시즌 history **148,467 / 185,249 bytes**, 과거 19개 final table과 시즌 20 active 원장을 동시에 둔 combined shape **180,876 / 222,540 bytes**다. 모두 domain invariant와 schema parse를 통과하며 각각 256KiB/1MiB 이하이다. 이 수치는 합성 최대 shape이며 서버 replay 증거로 부풀려 설명하지 않는다.
- 자연 명령 실행 계측은 기본 대량 실행 비용과 CSV 계약을 보존하도록 명시적 `--measure-storage` opt-in으로만 켠다. `ledger-fast-20:FW:0`, FAST, 1.7.0/0.6.2, 20시즌, 212 commands, 실패 0에서 압축 전 시즌 20 active peak state가 **269,799 bytes**로 hard cap을 7,655 bytes 넘는 것을 확인한 뒤 active result를 fixture index tuple로 바꿨다. 같은 seed 재실행은 peak state **233,701 bytes**, revision 0부터 모든 실제 command payload를 포함해 `buildSyncBody`와 같은 shape로 수동 모델링한 unsynced PUT 최대 **347,364 bytes**, CLI wall **1,992ms**였다. 이는 실제 EngineClient 호출 실측이 아니라 모델링 값이다. 최종 state hash는 압축 전후 모두 `c8f19c7f57b559c4546e08d8bebf4fd241ad6fbd130025de7c2ee3fe4b113aab`로 final table 정본이 동일했다.
- 최초 최대 팀 수 자연 실행 `ledger-tier3-probe:FW:1`은 state **250,949 bytes**, 수동 모델링 unsynced PUT **377,112 bytes**였다. 로그가 더 많은 입력을 배제하지 않기 위해 `t7-022-storage-40`, GK/DF/MF/FW 각 10개, FAST 20시즌을 제한 재측정하자 `DF:13`이 state **262,851 bytes**로 hard cap을 707 bytes 넘었다. 한도를 올리지 않고 과거 시즌마다 반복되던 final table object row를 위 고정 tuple로 압축했다.
- 같은 40개를 재실행한 결과 실패 0, CLI wall **18,267ms**, state 최대 **229,715 bytes**(`DF:13`, 여유 32,429), 수동 모델링 unsynced PUT 최대 **363,635 bytes**였다. 포지션별 state 최대는 GK **220,844**, DF **229,715**, MF **221,006**, FW **226,508**이며 초과는 0건이다. storage/hash 열을 제외한 40개 career CSV 값은 전후 전부 같고, 저장 표현이 바뀌었으므로 state hash는 의도대로 40/40 달라졌다. tuple을 펼친 최종 행 값은 결산 당시 `StandingRow`와 동일함을 focused test에서 확인했다.
- `--measure-storage`의 PUT 숫자는 revision 0부터 명령을 모두 쌓아 `buildSyncBody`와 같은 JSON shape를 매 명령 수동 구성한 보수적 **CLI 모델링 값**이다. 실제 EngineClient/WebWorker SDK PUT의 네트워크 body byte 실측으로 보고하지 않는다.

## 범위

- 수정 가능: `packages/domain`, `packages/contracts`, `packages/content`, `packages/engine-client`의 저장/재생 정합, `apps/api`의 버전 호환 DTO, `apps/web`의 대시보드·일정·경기 결과·시즌 결산·과거 순위 UI와 해당 DTO.

- 비범위: 은퇴 UI, 면담 receipt, 신규 서사 이벤트, 승강격 이동, 대륙대회, 전 세계/NPC 선수 시뮬레이션, public HTTP/D1 리그 테이블, 서비스 시즌 활성화·배포, 공유 보드/결정 로그/인덱스 수정.
