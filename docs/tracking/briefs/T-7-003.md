# T-7-003: 룰셋 1.4.0 로컬 QA 서비스 시즌 seed (이슈 #140 검증 준비)

## 목표

[T-7-001](T-7-001.md)·[T-7-002](T-7-002.md)의 회복 규칙을 운영 포인터를 건드리지 않고 로컬·staging에서 실제 플레이로 검증할 수 있게,
`1.4.0 / 0.5.0` 쌍을 쓰는 **INSERT-only 테스트 서비스 시즌** seed를 추가한다. PR #115가 `apps/api/seeds/bootstrap-gameplay-recovery.sql`로 했던 방식과 같다.
운영 시즌 `svc_season_1`의 1.4.0 승격과 `apps/api/src/sync/season-version-compatibility.ts`의 CURRENT/PREVIOUS 전환은 **사용자 결정 뒤 별도 작업**이며 이 브리프에서 하지 않는다.

선행: T-7-001 머지(콘텐츠 패키지가 1.4.0을 알아야 API 검증이 통과한다). T-7-002와 병행 가능.

## 참조 명세

- 요구사항 ID: API service-seasons(`docs/development/`의 서비스 시즌 절), D-67
- 읽어야 할 문서: `docs/design/nineteen-kickoff.md` §5(버전과 저장 호환성), `docs/design/realistic-career-opening.md` §버전과 로컬 환경, `docs/operations/two-environments.md`
- 본보기 파일: `apps/api/seeds/bootstrap-gameplay-recovery.sql`, `apps/api/seeds/bootstrap-realistic-story.sql`

## 범위

- 만질 패키지·경로: `apps/api/seeds/bootstrap-recovery-rules.sql`(신규) 1개. `apps/api/package.json`에 seed 적용 스크립트가 파일별로 등록돼 있으면 같은 패턴으로 한 줄 추가.
- 만들 것: `service_seasons`에 `('svc_recovery_rules_qa', '회복 규칙 1.4.0 QA', 'PRESEASON', '2026-09-07T00:00:00Z', NULL, '1.4.0', '0.5.0', 'cs_recovery_rules_qa', 1)` `ON CONFLICT(id) DO NOTHING`. 본보기 파일이 challenge set 행도 넣으면 같은 방식으로 `cs_recovery_rules_qa`를 넣는다. 파일 머리 주석에 "운영 포인터는 변경하지 않는다"를 남긴다.
- 만지지 말 것: `season-version-compatibility.ts`, 운영·staging 배포 설정, 마이그레이션, `apps/web`, docs.
