# T-7-018: 구단 면담·다음 시즌 목표·결과 확인

## 목표와 범위

프리시즌에 선수가 구단에 출전 기회·임대·이적을 요청하고, 구단 응답과 다음 시즌 목표를 확인한 뒤 결산에서 실제 결과를 확인할 수 있게 한다. 사용자가 2026-09-14 첫 개선 묶음의 구현을 승인했다. 작업은 최신 main `7146f551b38eb0b9786594fa06d1be0590a5312e`에서 시작한 전용 워크트리에서 sol 한 명이 구현하고, 별도 sol이 읽기 전용 검토·브라우저 검증을 한다. 산출물은 단일 통합 PR이며 merge·운영 배포는 수행하지 않는다.

요구사항 ID: **FR-CM-001**(시즌당 면담), **FR-CM-002**(실제 구단 응답), **FR-CM-003**(다음 시즌 목표), **FR-CM-004**(영구적인 결과 확인), SCR-005, SCR-011, SCR-029. 공유 명령·엄격한 저장 스키마·도메인·웹의 원자적 정합이 필요하므로 이 묶음은 단일 패키지 브리프 관례의 예외로 함께 배포 가능한 한 PR로 만든다. 외부 API는 추가하지 않는다.

## Phase 1 — 저장·버전 계약

1. 새 `REQUEST_CLUB_MEETING` 명령 payload는 `{ request: 'PLAYING_TIME' | 'LOAN' | 'TRANSFER' }`만 받는다. 판정·목표·효과는 도메인이 계산하며 클라이언트 수치를 신뢰하지 않는다.
2. schemaVersion은 1로 유지하되 `clubMeeting?` 같은 exact-optional 필드를 추가한다. 기존 저장에서 필드가 없는 것은 정상이다. 기존 CREATE·parse·리플레이·무관한 명령에서 필드를 자동 생성하거나 기본값을 넣지 않는다. 이 호환 정책을 PR 본문에도 명시한다.
3. 기록에는 다음 시즌 인덱스, 요청 종류, 수락/거절 및 이유, 원래 구단/계약 식별, 실제 즉시 효과, 합의한 역할·출전 비중 목표, 평가 상태와 실제 결과를 보존한다. 예정 목표는 현재 상태에, 확정 결과는 해당 `SeasonResult`/`SeasonSummary`의 optional 결과 필드에 복사한다. 다음 면담이 과거 시즌 결과를 덮어쓰면 안 된다.
4. 새로운 기능 규칙은 **ruleset 1.6.0**에만 추가한다. 1.5.0을 복제한 새 버전의 optional `clubMeetingRules`로 활성화한다. 새 저작 이벤트가 없으므로 팩 0.6.0을 재사용한다. 기존 ruleset·pack·golden 파일은 변경하지 않는다.
5. 1.6.0 로딩/검증/선택에 필요한 registry·schema·fixture 버전 목록 정합은 포함한다. 운영 시즌 행, 운영 active fallback 상수, release manifest 승격은 건드리지 않는다. PR에는 **운영 적용은 후속 1.6.0 승격이 필요**함을 적고, 로컬 1.6.0/0.6.0 신규 커리어로 실제 검증한다. 로컬 서비스 시즌 또는 기존 DEV override를 사용하고 글로벌 기본값을 바꾸지 않는다.

검증: 기존 strict schema/round-trip/import/replay/hash 검증 통과, 기존 버전 파일 diff 없음, 새 버전 로드 가능. 명령 discriminant·로그 schema·engine action·UI mutation이 한 계약을 사용해야 한다.

## Phase 2 — 면담과 실제 효과

### 진입과 횟수

- `canPlanNextSeason`과 같은 시점: ACTIVE, 프로 영구 계약, `season === null`, `pending === null`.
- 목표 시즌 인덱스는 기존 START_SEASON과 같은 `seasonHistory.length + 1`. 같은 인덱스로 이미 면담한 경우 두 번째 명령은 거절하고 상태·해시·관계·RNG를 추가 변경하지 않는다. 같은 idempotency key 재시도는 기존 엔진 멱등성으로 처리한다.
- 유스·은퇴·보관·임대 중 커리어에서는 면담을 제공하지 않는다. 계약/임대복귀/역할 등 pending을 우회하지 않는다.
- 면담은 선택 사항이다. 건너뛰면 기존 시작 흐름과 결과가 그대로 유지된다.

### 초기 밸런스 계약(모두 새 ruleset의 정수 설정)

| 요청 | 조건/수락 | 즉시 실제 효과 | 구단 계획 |
|---|---|---|---|
| 출전 기회 | STARTER를 제외한 영구 계약. 감독 신뢰 45 이상 수락 | 수락: 신뢰 +2, 사기 +3. 거절: 신뢰 0, 사기 -1 | 수락 시 역할 약속 한 단계 상향 및 해당 출전 비중 반영. 기존 역할 변경 수락과 같은 순수 helper 사용 |
| 임대 | 잔여 계약 2시즌 이상. BENCH/RESERVE이면서 신뢰 30 이상 수락 | 수락: 신뢰 -1, 사기 +2. 거절: 신뢰 -2, 사기 -1 | 다음 가능한 이적시장에서 임대 제안 탐색 |
| 이적 | 영구 계약. 신뢰 40 이하 또는 기존 계약의 약속 위반 1회 이상이면 수락 | 수락: 신뢰 -2, 사기 +2. 거절: 신뢰 -3, 사기 -2 | 다음 가능한 이적시장에서 이적 제안 탐색 |

- 즉시 효과는 기존 effect/clamp/log 경로로 적용하고 **실제 적용된 변화량**을 응답 기록에 저장한다. 별도 난수는 쓰지 않는다.
- 출전 계획은 계약 역할 약속과 실제 START_SEASON 선발 계산에 연결한다. UI는 실제 역할이 프리시즌 경쟁 후 조정될 수 있음을 설명하며 선발 보장을 약속하지 않는다.
- 임대/이적 수락은 `이적_희망` 및 요청 종류 선호를 저장한다. 다음 해당 커리어의 eligible INTEREST 시장에서 기존 후보·안전 제안을 유지하면서 첫 유효한 비안전 제안에 요청 종류를 반영한다. **기존 버전 및 면담 미사용 경로의 난수·해시는 완전 불변**이다. 새 면담의 제안 종류 변경 경로는 결정론을 지키되 LOAN/TRANSFER의 서로 다른 후속 난수 소비를 허용한다. 원래 kind roll 뒤에 선호를 적용하고 나머지는 해당 종류의 기존 로직을 따른다.
- 선호는 요청한 계약/시즌에 귀속한다. eligible INTEREST 시장의 실제 생성 시 한 번 탐색하고, 유효 제안이 있으면 OFFERED, 유효 후보가 없으면 NO_CANDIDATE라는 명시적 결과로 종료한다. 판정이 null이거나 아직 갱신 단계라면 소비하지 않는다. 계약이 만료·교체되면 선호를 취소하고 기존 EXPIRED/새 계약 경로를 우선하며 다음 구단으로 이월하지 않는다. 보장된 이동이나 존재하지 않는 제안을 만들어내지 않는다. 검색 경과는 현재 면담 기록/정규 로그에 남기며 이미 해시 확정된 SeasonResult는 재작성하지 않는다.
- 문구는 “다음 이적시장에서 제안을 알아보기로 했다”이며, 이동 자체는 기존 제안 수락·서명으로 확정된다.

### 다음 시즌 목표와 후속 결과

- 수락한 출전 요청은 상향 역할, 그 밖의 요청/거절은 당시 계약 역할을 기준으로 기존 `contractRules.promiseMinutesShareBp`의 목표값을 가져와 고정 저장한다.
- 목표는 출전시간 비중이며, 정확한 대상 시즌을 표시한다. 사전에 설명된 목표만 평가한다.
- 해당 시즌 결산의 기존 실제 출전 비중과 비교해 MET/MISSED를 한 번 확정한다. 달성 보상은 신뢰 +3·사기 +2. **미달 추가 효과는 0**이며, 기존 계약 약속 위반과 별개로 불이익을 중복 부과하지 않는다.
- 평가와 효과/실제 delta를 **최종 SeasonResult 생성·hash 및 seasonHistory 확정 전에** 포함한다. 기존 출전 비중 계산으로 평가 → 목표 보상 실제 적용 → plan+평가 결과를 담은 최종 result 생성·hash·history 순서를 지킨다. 그 뒤 기존 settlement 관계 hook은 새 목표 보상이 반영된 상태를 읽는다. 면담 미사용 경로의 기존 hook 순서는 바꾸지 않는다. 이미 확정된 과거 결과 해시를 다음 명령에서 다시 쓰지 않는다. 다음 면담 후에도 지난 시즌의 목표·결과·이유가 남아야 한다.
- 면담·평가의 timeline/log 기록을 추가하고 cap/허용 schema와 정합을 맞춘다. goal로 기존 contract.promiseBreaches를 증가시키지 않는다.

검증: 세 요청의 수락/거절, 조건 미충족, 두 번 클릭·새로고침·재시도, 목표 달성/미달/중복 평가, 계약 만료·이적 후보 없음, 시즌 경계·과거 결과 보존. 기존 명령과 RNG 결과는 새 면담을 하지 않았을 때 불변이어야 한다.

## Phase 3 — 화면 연결

- SCR-005 프리시즌에 선택적인 “구단 면담” 블록을 추가한다. 기존 훈련 선택을 유지한다. 요청 선택 → 명시적 면담 버튼 → 저장된 구단 응답·실제 효과·목표를 보여준다.
- 구조상 불가능한 선택만 이유와 함께 disabled 처리한다(이미 STARTER의 출전 상향, 잔여 2시즌 미만 임대 등). 신뢰·역할 등 **구단 수락 판정** 조건을 충족하지 않아도 요청 버튼은 활성화해 실제 거절 응답을 받을 수 있어야 한다. 면담을 쓰지 않아도 다음 화면으로 갈 수 있어야 한다. busy 동안 모든 관련 조작 잠금, 오류 때 선택 보존·재시도, 다른 탭에서 이미 제출했으면 최신 저장 상태로 회복한다.
- SCR-011에 저장된 면담 계획과 다음 시즌 목표를 요약한다. `screenForCareer`와 기존 pending 우선순위를 유지한다. 새 EVENT/필수 모달·추가 경유 화면을 만들지 않는다.
- 대시보드에 해당 시즌의 목표를 간결히 표시하고, 시즌 결과/이력에서 목표값·실제값·달성 여부·적용 효과를 확인하게 한다. 다음 시즌의 면담 때문에 지난 목표를 잃지 않는다.
- 수치/결과는 domain에서 받은 값만 표현한다. 화면에서 합격 판정·효과·새 상태를 계산하지 않는다. 기존 숫자 공개 정책을 지킨다.
- 출전 비중은 선수 혼자 통제하지 못하므로 “시즌 출전 확인 기준”으로 설명하고 선발 보장이 아님을 명시한다. MISSED는 선수의 잘못으로 표현하지 않으며 “기준 미달 · 추가 불이익 없음”을 표시한다. 목표 달성 보상과 즉시 면담 효과는 별개로 표시한다.
- 거절된 요청에도 현재 역할 기준의 출전 확인 목표는 남지만, 이를 수락된 약속이나 새 의무로 표현하지 않는다. 구단의 거절과 기존 역할 기준을 분리해 보여준다.
- FAST는 그대로 유지한다. 신기능은 일반 EVENT slot에 의존하지 않는다.

## Phase 4 — 검증·리뷰·PR

- D-61: 새 test/spec 파일이나 새 독립 `it`/`test`를 추가하지 않는다. 기존 케이스 내부의 설정·parameter/schema 목록·assertion은 새 계약 검증과 기존 동작 보존을 위해 확장할 수 있다. 새로운 golden 파일을 만들거나 기존 버전 golden의 기대 해시를 새 구현에 맞추려고 재기록하지 않는다. 새 동작은 기존 synthetic 설정을 재사용해 1.6.0으로 명시적으로 구성하고 실제 브라우저 확인을 함께 수행한다.
- 기존 검증: contracts commands/career-state/snapshot-size, domain 결정론·시즌/시장, engine-client sync golden/import/fork, 웹 기존 역할·시즌·프리시즌 관련 테스트를 실행한다.
- 최종 체인: `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm lint:deps`, `pnpm typecheck`, `pnpm content:validate`, `pnpm test`, `pnpm build`, web `check:bundle`, 관련 e2e. 전체 체인은 한 번에 한 워커만 실행한다. 실패는 같은 main 기준과 대조하고 미실행·부하 실패를 통과로 보고하지 않는다.
