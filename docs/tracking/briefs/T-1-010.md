# T-1-010: web E2E 도구 도입 — Playwright + axe, 스모크, 브라우저 Web Worker 해시 검증

## 목표
`pnpm --filter @offside/web e2e`가 Chromium에서 허브·법적 문서 화면을 열어 스모크와 접근성(axe)을 검사하고, 실제 브라우저 Web Worker에서 career-01 golden fixture를 실행한 state hash가 golden과 같음을 확인한다. Phase 1 화면 E2E(TEST-E2E-001·007·008·009)는 T-1-014가 이 기반 위에 쓴다.

## 참조 명세
- 요구사항 ID: TEST-E2E(08 문서), TEST-E2E-009(접근성 기준), ADR-003(브라우저 Worker 결정론), T-0-011 잔여(브라우저 Web Worker 해시)
- 읽어야 할 문서(순서대로): `docs/tracking/phase-1-plan.md` D-18, `docs/development/08-testing-strategy.md` E2E 절, `docs/adr/ADR-003-simulation-location.md`, `docs/tracking/briefs/T-0-011.md`(교차 런타임 해시 테스트의 입력·기대값), `packages/fixtures/src/career-01/`(golden)
- 정본 우선순위: docs/development > phase-1-plan.md > ADR

## 범위
- 만질 패키지·경로: `apps/web`만(`e2e/`, `playwright.config.ts`, `package.json` 스크립트·devDependencies, dev 전용 probe 라우트 1개).
- 만들 것:
  1. `@playwright/test`·`@axe-core/playwright` devDependency(정확한 버전 고정). `playwright.config.ts`: Chromium 1개 프로젝트, `webServer`로 `vite dev --port 5174` 자동 기동(재사용 허용), `baseURL`, 모바일 뷰포트 360×780 기본, trace `retain-on-failure`, 스크린샷 파일은 스크래치패드 밖으로 커밋되지 않도록 `test-results/`를 `.gitignore`.
  2. 스크립트: `"e2e": "playwright test"`, `"e2e:install": "playwright install chromium"`. Turbo 파이프라인에는 넣지 않는다(CI 연결은 T-0-010 이후).
  3. `e2e/hub.spec.ts`: 허브가 열리고 빈 상태 문구와 "커리어 시작" 버튼이 보인다. `e2e/legal.spec.ts`: 개인정보·이용약관 라우트가 200이고 제목이 있다. `e2e/a11y.spec.ts`: 위 세 화면에서 axe `serious`·`critical` 위반 0건(결과 요약을 콘솔에 출력).
  4. 브라우저 Web Worker 해시 검증: dev 전용 라우트 `/__dev/hash-probe`(`import.meta.env.DEV`가 아닐 때는 라우트를 등록하지 않는다)가 `@offside/fixtures` career-01을 `packages/engine-client`의 Worker 호스트로 실행해 최종 `revision`·`stateHash`를 `data-testid="hash-probe-result"`에 JSON으로 렌더한다. `e2e/hash-probe.spec.ts`가 이를 읽어 `career01.golden`과 비교한다. fixtures는 devDependency로만(ADR-005). 프로덕션 번들에 probe 코드와 fixture가 들어가지 않음을 `pnpm build` 후 `dist/` grep(`hash-probe`, `car_gimseojun`)으로 확인하고 `check:bundle` 예산이 그대로 통과해야 한다.
  5. golden이 T-1-001에서 바뀌면(명령 셋 변경) probe는 `@offside/fixtures`가 export하는 현재 fixture·golden을 그대로 쓰므로 테스트 코드 수정 없이 따라간다. probe는 fixture의 룰셋 복제본(`ruleset-proto.json`)이 있으면 그것을 `SimulationInput.ruleset`으로 넘긴다(없으면 Phase 0 형식).
- 만지지 말 것: `docs/`, 다른 패키지, 기존 화면·라우트 동작, Turbo 설정, CI.

## 제약
- E2E는 Vitest와 분리한다(`vitest` include에 `e2e/`가 잡히지 않게).
- 네트워크 요청은 없어야 한다(API 호출 화면은 T-1-014). 외부 CDN 접근 금지.
- 커밋 메시지는 `T-1-010: …`로 시작, 브랜치는 `T-1-010-…`.
- 서브에이전트 리뷰를 띄우지 않는다. Orca PR 게이트용 `/review:pr` 1회만 예외(`/simplify`·병렬 fork 금지).
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
