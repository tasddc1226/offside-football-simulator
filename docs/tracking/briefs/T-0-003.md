# T-0-003: `packages/contracts` 응답 봉투·오류 코드·Snapshot·명령 로그 Zod 계약

## 목표

클라이언트(engine-client, web)와 서버(api)가 공유하는 와이어 계약을 `packages/contracts`에 Zod로 고정한다. 07의 응답 봉투와 오류 코드 표, 05의 Snapshot 계약, 02의 `CommandLogEntry`·`LocalProfile`·`ProfileSettings`, 07의 `PUT /careers/{id}` 본문과 로컬 명령 봉투를 스키마와 타입으로 제공하고, 07 문서의 JSON 예시가 그대로 파싱되는 것을 테스트로 고정한다.

- 요구사항 ID: 07 "공통 규칙"·"응답 봉투"·"프로필·인증 API"·"커리어 동기화 API"·"오류 코드"·"로컬 명령 계약"·"계약 테스트", 05 "Snapshot 계약"·"버전 정책", 02 DATA-PRO-001·`CommandLogEntry`·`ProfileSettings`, ADR-005(contracts → domain 타입만), ADR-009(채널·Bearer)

### 만들 것

`packages/contracts/src/` 아래. `zod`(3.x 안정 최신, `dependencies`)를 쓴다.

1. `envelope.ts`
   ```ts
   export const MetaSchema = z.object({ requestId: z.string().min(1), careerRevision: z.number().int().nonnegative().optional(), rulesetVersion: z.string().optional() });
   export const successEnvelope = <T extends z.ZodTypeAny>(data: T) => z.object({ data, meta: MetaSchema });
   export const ErrorEnvelopeSchema = z.object({ error: z.object({ code: ErrorCodeSchema, message: z.string(), retryable: z.boolean(), details: z.unknown().optional() }), meta: MetaSchema });
   export const envelope = <T extends z.ZodTypeAny>(data: T) => z.union([successEnvelope(data), ErrorEnvelopeSchema]);
   ```
2. `errors.ts` — 07 "오류 코드" 표를 그대로 옮긴다(16개, 표 순서 유지).
   ```ts
   export const ERROR_CODES = ['VALIDATION_FAILED', 'RECOVERY_CODE_INVALID', 'TOSS_KEY_INVALID', 'ORIGIN_NOT_ALLOWED', 'PROFILE_REQUIRED', 'CAREER_NOT_OWNED', 'CAREER_NOT_FOUND', 'CAREER_REVISION_CONFLICT', 'COMMAND_ALREADY_RESOLVED', 'RECOVERY_CONFLICT', 'MERGE_REQUIRED', 'CAREER_ARCHIVED', 'VERSION_MISMATCH', 'VERIFICATION_FAILED', 'RATE_LIMITED', 'SERVICE_UNAVAILABLE'] as const;
   export const ErrorCodeSchema = z.enum(ERROR_CODES);
   export const HTTP_STATUS_BY_CODE: Record<ErrorCode, 400 | 401 | 403 | 404 | 409 | 422 | 429 | 503>;
   export const RETRYABLE_BY_CODE: Record<ErrorCode, boolean>; // RATE_LIMITED, SERVICE_UNAVAILABLE만 true
   ```
3. `versions.ts` — `SemverSchema`(`^\d+\.\d+\.\d+$`), `VersionTripleSchema = { schemaVersion: z.literal(1), rulesetVersion, contentPackVersion }`, `CLIENT_MIN_VERSION_HEADER = 'X-Client-Version'`.
4. `snapshot.ts` — 05 Snapshot 계약.
   ```ts
   export const CheckpointTypeSchema = z.enum([...]);  // domain CheckpointType과 같은 9개. 타입 동일성은 expectTypeOf로 검사
   export const RngStateSchema = z.object({ s: z.tuple([u32, u32, u32, u32]), draws: z.number().int().nonnegative() });
   export const CareerSnapshotSchema = z.object({
     id: z.string(), careerId: z.string(), revision: z.number().int().positive(),
     checkpoint: CheckpointTypeSchema,
     state: z.string().max(SNAPSHOT_STATE_MAX_BYTES),  // canonical JSON 문자열. 256KB 권장, 1MB 상한(07 요청 본문 상한과 같다)
     stateHash: z.string().regex(/^[0-9a-f]{64}$/),
     rulesetVersion: SemverSchema, contentPackVersion: SemverSchema,
     rngState: RngStateSchema, createdAt: IsoUtcSchema,
   });
   export function decodeSnapshotState(snapshot): CareerState;  // JSON.parse 후 domain `hashState`로 stateHash와 `rngState` 동일성 검증. 불일치면 { ok: false, reason }
   ```
   `decodeSnapshotState`는 `@offside/domain`의 런타임 함수가 필요하다. 의존 방향 표는 "contracts → domain(타입만)"이므로 **이 함수는 contracts에 두지 않는다**. 대신 `SnapshotStateEnvelopeSchema`(파싱된 state의 최상위 형태만 검사: `schemaVersion: 1`, `careerId`, `revision` 없음 확인)까지만 두고, 해시 검증은 engine-client(T-0-007)와 api(T-0-008) 몫으로 남긴다. PR 본문에 이 결정을 적는다.
5. `commands.ts` — 07 "로컬 명령 계약".
   ```ts
   export const COMMAND_TYPES = ['CREATE_CAREER','UPDATE_PLAYER_DRAFT','CONFIRM_PLAYER','RESOLVE_EVENT','START_SEASON','ADVANCE','SETTLE_SEASON','NEGOTIATE','ACCEPT_OFFER','REJECT_OFFER','LOAN_RETURN','RETIRE'] as const;
   export const CommandTypeSchema = z.enum(COMMAND_TYPES);
   export const CommandRequestSchema = z.object({ commandId: z.string().uuid(), expectedRevision: z.number().int().nonnegative(), type: CommandTypeSchema, payload: z.record(z.unknown()) });
   export const CommandLogEntrySchema = z.object({ careerId, revision, commandId, commandType: CommandTypeSchema, payload: z.record(z.unknown()), resultHash: hex64, createdAt: IsoUtc });
   export const NextActionSchema = z.enum(['DECISION', 'ADVANCE', 'SETTLEMENT']);
   export const CommandResponseSchema = successEnvelope(z.object({ snapshot: CareerSnapshotSchema, nextAction: NextActionSchema, roll: z.number().int().optional(), outcomeId: z.string().optional() }));
   ```
   domain의 Phase 0 명령 이름(`ADVANCE_STEP`)과 07의 `ADVANCE`가 다르다. 계약은 07을 따르고, 매핑은 engine-client가 한다. 타입 테스트로 07 목록이 12개임을 고정한다.
6. `careers.ts` — 07 "커리어 동기화 API".
   - `PutCareerBodySchema`: `baseRevision`(int ≥ 0), `snapshot`(`CareerSnapshotSchema`에서 `id`·`careerId`·`createdAt` 생략한 `pick`), `commands`(`CommandLogEntrySchema`에서 `careerId`·`createdAt` 생략, 배열, revision이 연속 증가하는지 `superRefine`), `createdServiceSeasonId`, `rulesetVersion`, `contentPackVersion`.
   - `PutCareerResponseSchema`: `{ revision: int, syncedAt: IsoUtc, verificationStatus: z.enum(['PENDING','VERIFIED','FAILED']).optional() }`.
   - `CareerSummarySchema`(API-CAR-001): `id, status(DRAFT|ACTIVE|RETIRED|ARCHIVED), revision, lastSyncedAt, createdServiceSeasonId, rulesetVersion, contentPackVersion`. 목록 응답은 `{ items, nextCursor: string | null }`.
   - `GetCareerResponseSchema`(API-CAR-002): `{ snapshot: CareerSnapshotSchema, commands: CommandLogEntrySchema[] }`.
   - `RevisionConflictDetailsSchema`: `{ serverRevision: int, serverSnapshotUrl: string }`.
7. `profile.ts` — 02 DATA-PRO-001·`ProfileSettings`, 07 API-PRO-001/002.
   - `ProfileSettingsSchema`(reducedMotion `SYSTEM|ON|OFF`, textScale `100|125|150`, theme `SYSTEM|LIGHT|DARK`, defaultSimulationMode `FAST|CHAPTER`), `ProfileSchema`(클라이언트에 노출되는 필드만: `id`, `settings`, `linked: { google: boolean; toss: boolean }`, `recoveryCodeIssuedAt: IsoUtc | null`, `createdAt`), `PatchProfileSettingsBodySchema = ProfileSettingsSchema.partial()`.
   - `TossSessionBodySchema = { anonKey: z.string().min(1) }`(API-AUTH-005), `TossSessionResponseSchema = { sessionToken: string, expiresAt: IsoUtc }`.
8. `headers.ts` — 상수: `IDEMPOTENCY_KEY_HEADER = 'Idempotency-Key'`, `IF_MATCH_HEADER = 'If-Match'`, `AUTHORIZATION_HEADER = 'Authorization'`, `REQUEST_ID_HEADER = 'X-Request-Id'`, `CORS_ALLOWED_HEADERS = [...]`(07 공통 규칙), `REQUEST_BODY_MAX_BYTES = 1_048_576`, `SNAPSHOT_STATE_RECOMMENDED_BYTES = 262_144`.
9. `health.ts` — `HealthResponseSchema = successEnvelope(z.object({ ok: z.literal(true) }))`.
10. `index.ts`에서 스키마와 `z.infer` 타입을 모두 export. `CONTRACTS_VERSION = '0.1.0'`.

### 테스트 (Vitest)

- 07 문서의 JSON 예시 3개(성공 봉투, 오류 봉투, `PUT /careers/{id}` 본문)를 문자열 그대로 붙여 넣어 파싱 성공. 단, 예시의 `"state": "..."`·`"stateHash": "..."`·`"resultHash": "..."`는 형식 검사를 통과하는 값으로 바꾸고 주석으로 표시.
- 오류 코드 16개 모두 `HTTP_STATUS_BY_CODE`·`RETRYABLE_BY_CODE`에 있고, 표의 HTTP 값과 같다(테스트 안에 표를 다시 적는다).
- `CommandTypeSchema` 12개, `CheckpointTypeSchema`가 domain `CheckpointType`과 타입 동일(`expectTypeOf<z.infer<...>>().toEqualTypeOf<CheckpointType>()`), `RngStateSchema`도 domain `RngState`와 동일.
- `PutCareerBodySchema`: commands revision이 `baseRevision + 1`부터 연속이 아니면 실패, 빈 배열은 성공, `stateHash` 63자리는 실패.
- `ProfileSettingsSchema`: `textScale: 110` 실패.
- `envelope(HealthData)`가 성공·오류 양쪽을 받아들이고, `meta.requestId` 없으면 실패.

## 제약

- Zod 스키마는 `.strict()`를 기본으로 하되 `meta`·`details`·`payload`처럼 확장이 예정된 곳만 `passthrough`/`unknown`.
- 날짜는 ISO 8601 UTC(`Z` 접미) 문자열만. `Date` 객체 금지.
- 버전은 안정 최신. 프리릴리스 금지. `zod` 외 새 의존성 금지.
- 커밋 메시지 `T-0-003: …`. 브랜치 `T-0-003-contracts-zod`.
- 커밋 트레일러: `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
- 서브에이전트 리뷰를 띄우지 않는다. 예외는 하나뿐이다. Orca가 `gh pr create` 앞에 요구하는 게이트를 위해 `/review:pr`을 **한 번만** 실행한다(`/simplify`·병렬 fork 금지). 리뷰 결과 중 실제 버그·테스트 누락만 고치고 나머지는 PR 본문에 적는다. PR을 연 뒤에는 멈추고 피드백을 기다린다.
