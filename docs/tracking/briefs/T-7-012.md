# T-7-012: `.os-eyebrow` 캡션 색 대비 axe 위반 수정 (main e2e a11y 회귀, packages/ui)

## 목표

origin/main 전체 e2e에서 a11y.spec 11개 테스트와 service-season.spec:75가 axe `color-contrast`(serious)로 실패한다. 위반 대상은 거의 전부 `<p class="os-eyebrow">`(MY OFFSIDE·PRE-SEASON·PLAYER REPORT·나의 다음 팀·새로운 유니폼 등 화면 상단 캡션)이고, 일부 노드는 `.os-shell` 배경을 대상으로 잡힌다.
9/6 UI/UX 개편(PR #120)에서 `packages/ui/src/game.css` 677행 `.os-eyebrow { color: var(--os-text-2) }`가 캡션 크기(`--os-fs-caption`, 굵기 750)로 쓰이면서 라이트·다크 중 한쪽 이상에서 4.5:1을 못 넘는 것으로 보인다. 이 작업은 **`packages/ui`만** 고쳐 axe 위반을 없앤다. 테스트 완화는 하지 않는다.

## 참조 명세

- 요구사항 ID: NFR-A11Y(axe serious·critical 0, `docs/development/08-testing.md` §a11y), D-12(색은 `--os-*` 토큰만), D-70
- 읽어야 할 문서: `packages/ui/src/tokens.css`(라이트·다크 토큰), `packages/ui/src/game.css` 191~196행·677행, `packages/ui/scripts/check-contrast*`(`pnpm --filter @offside/ui check:contrast`가 검사하는 쌍), `apps/web/e2e/a11y.spec.ts` 40~75행(`expectNoSeriousOrCriticalViolations`)
- 재현: 워크트리에서 `E2E_PORT=5273 pnpm --filter @offside/web exec playwright test e2e/a11y.spec.ts --workers=2` — 실패 출력의 JSON에 위반 id·노드 html이 있다(`DEBUG`용 상세는 spec 60~68행이 출력). a11y.spec의 A 분류(흐름 드리프트)로 도달하지 못하는 테스트는 [T-7-011](T-7-011.md)이 고치므로, 이 작업은 도달되는 테스트(173·191·270·303·311·345·353·364·376·532·550)와 service-season 75만 본다.

## 범위

- 만질 패키지·경로: `packages/ui/src/game.css`(+필요 시 `tokens.css`에 **새** 토큰 추가만), `check:contrast` 스크립트의 검사 쌍 목록(기존 구조에 행 추가).
- 만들 것:
  1. `.os-eyebrow` 색을 라이트·다크 모두에서 그 배경(`--os-bg`·`--os-surface`·`--os-surface-2`) 대비 4.5:1 이상인 기존 토큰으로 바꾼다(`--os-text` 또는 강조 텍스트 토큰). `--os-text-2` 자체는 바꾸지 않는다(다른 캡션·본문에 영향).
  2. `.os-shell`이 대상으로 잡히는 노드가 남으면 원인을 적고(배경이 그라디언트·반투명이라 axe가 대비를 계산하지 못하는 경우 등) 배경을 단색 토큰으로 바꾸거나 해당 텍스트의 배경을 명시한다.
  3. `check:contrast`에 eyebrow 쌍(라이트·다크 × 배경 3종)을 추가해 회귀를 막는다.
- 만지지 말 것: `apps/web/**`(dl 구조는 T-7-013), e2e 테스트, 토큰 이름 변경·삭제, docs.
