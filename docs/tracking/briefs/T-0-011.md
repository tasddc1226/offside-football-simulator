# T-0-011 — 런타임 간 state hash 일치 테스트(Node·Cloudflare Workers)

> 상태: todo → 워커 배정 시 in-progress. 브랜치 `T-0-011-cross-runtime-hash`. 선행: T-0-007 머지(`@offside/fixtures` 공용 fixture와 `TEST_ONLY_PACKAGES` 규칙).

## 목표

08 테스트 전략 "같은 fixture의 state hash가 브라우저 Web Worker, Node(Vitest), Cloudflare Workers(Miniflare)에서 모두 같다"를 자동화한다. Phase 0 범위는 **Node(Vitest)와 workerd(Miniflare)**. 브라우저 Web Worker 검증은 Playwright E2E가 들어올 때(Phase 1) 같은 fixture로 추가한다(보드 후속 항목).

동기화 API(T-0-008)는 서버(workerd)에서 `verifySnapshot`·`hashState`로 클라이언트(브라우저) 해시를 재검증한다. 두 런타임의 해시가 1비트라도 다르면 모든 동기화가 422로 실패하므로, 이 테스트는 그 전제를 지키는 회귀 방지선이다.

## 범위

만질 경로: `apps/api/src/test/**`, `apps/api/package.json`(devDependencies·scripts), `apps/api/vitest.config.ts`(있으면 timeout만), `pnpm-lock.yaml`(의존성 추가에 따른 재생성).

만지지 말 것: `packages/**`(domain·fixtures·contracts 포함), `tooling/**`, `apps/api/src/`의 테스트 외 코드, `apps/web/**`, `docs/**`. `packages/domain/src/__fixtures__/` 원본은 **삭제하지 않는다**(T-0-007 브리프 10의 "domain 원본 삭제는 T-0-011의 몫" 문구는 철회. domain이 fixtures를 devDependency로 가지면 워크스페이스 순환이 생기므로 domain이 원본, fixtures가 드리프트 테스트 붙은 복사본으로 유지).

새 의존성(apps/api devDependencies, 정확한 버전 고정):
- `miniflare`: `pnpm why miniflare`로 wrangler 4.127.1이 끌어오는 것과 **같은 버전**을 명시한다(중복 설치 금지).
- `esbuild`: wrangler가 내부에서 쓰는 버전과 같은 버전.
- `@offside/fixtures`: `workspace:*`(테스트 전용, `TEST_ONLY_PACKAGES` 규칙).
- `@offside/domain`: `workspace:*`를 **dependencies**에 추가(T-0-008이 런타임에 쓴다. ADR-005 `api → domain, contracts` 허용).

## 설계 결정(변경 금지. 의문이 있으면 질문)

1. **프로브 워커.** `apps/api/src/test/hash-probe.worker.ts`: `@offside/domain`의 `simulate`·`hashState`·`sha256Hex`·`verifySnapshot`과 `@offside/fixtures`의 `career01`을 import한다. `fetch` 핸들러는 요청 본문 JSON `{ kind: 'replay' } | { kind: 'sha256', inputs: string[] }`을 받아
   - `replay`: `career01.createCareer`부터 `career01.commands`를 순서대로 `simulate`로 재생해 마지막 Snapshot의 `revision`·`stateHash`·`rngState.draws`(또는 fixtures가 노출하는 동등 필드)와 `verifySnapshot(snapshot).ok`를 반환한다.
   - `sha256`: 각 문자열의 `sha256Hex`를 반환한다.
   이 파일은 프로덕션 번들에 포함되지 않는다(`src/test/` 아래, wrangler 엔트리는 `src/index.ts`).
2. **번들·실행.** 테스트 `apps/api/src/test/cross-runtime-hash.test.ts`는 `beforeAll`에서 `esbuild.build({ entryPoints: [probe], bundle: true, format: 'esm', platform: 'browser', write: false, conditions: ['workerd','worker','browser'] })`로 한 파일을 만들고 `new Miniflare({ modules: true, script, compatibilityDate: wrangler.jsonc와 같은 값 })`로 띄운다. `mf.dispatchFetch('http://probe/', { method: 'POST', body })`로 호출하고 `afterAll`에서 `mf.dispose()`. Node 프로세스 안에서 `require`·파일 경로 트릭으로 우회하지 않는다(진짜 workerd에서 실행돼야 의미가 있다).
3. **비교 대상.**
   - Node 쪽: 같은 테스트 파일에서 `@offside/domain`을 직접 import해 동일 재생을 수행한 값.
   - golden: `career01.golden.stateHash`·`revision`·draws.
   세 값(Node·workerd·golden)이 모두 같아야 한다. `verifySnapshot`도 workerd에서 `ok: true`.
4. **SHA-256 경계 입력.** `sha256` 프로브에 다음 문자열을 보내 Node와 workerd 결과가 같은지 확인한다: 빈 문자열, `abc`, 55·56·63·64·65·119·120바이트 ASCII(블록 패딩 경계), 한글·이모지(서로게이트 쌍)·결합 문자(`é`, NFC 정규화 **하지 않음**을 확인: `é`와 `é`의 해시가 다르다), U+FFFF·U+10FFFF, 200KB 문자열 1개. 기대값은 Node `node:crypto`의 `createHash('sha256')`로 계산해 domain 순수 구현·workerd 구현 모두와 대조한다(테스트 파일에서만 `node:crypto` 허용. purity 테스트가 `src/test/**`를 제외하는지 확인).
5. **canonicalize 경계.** `{ b: 1, a: [ '가', 'z', 'Z', '😀' ], '\u{1F600}': null }`처럼 키 순서·코드포인트 정렬·유니코드 키가 섞인 값을 Node와 workerd에서 `canonicalize`해 문자열이 같은지 비교한다(프로브에 `{ kind: 'canonical', value }` 추가).
6. **실행 시간.** 테스트 전체 10초 이내. Miniflare 인스턴스는 파일당 1개. 첫 실행 시 workerd 바이너리 다운로드가 필요하면 그 사실을 PR 본문에 적는다.
7. 새 스크립트 없음. `pnpm test`(turbo)로 함께 돈다. CI(T-0-010)에서도 그대로 돈다.

## 하지 않는 것

- 브라우저 Web Worker 검증(Playwright 도입 시).
- domain 해시·canonicalize 구현 변경. 불일치가 발견되면 **고치지 말고** 재현 입력과 두 런타임의 출력값을 첨부해 멈추고 보고한다(domain 수정은 별도 작업).
- `@cloudflare/vitest-pool-workers` 도입(전체 테스트 풀 변경은 범위 밖).
