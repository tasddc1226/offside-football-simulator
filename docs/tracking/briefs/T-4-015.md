# T-4-015: 감사 확인 finding — content 묶음 (season.stats 파생·슬럼프 게이트·INJURY previewEffects 검증기)

## 목표

Phase 3·4 코드 감사 재검증(`wf_28e6ca87-b91`, 3렌즈 3/3 확인)에서 확정된 content 결함 4건을 `packages/content` 안에서 고친다. 조건 DSL 파생 필드가 실제 시즌 통계를 내고, 슬럼프 이벤트가 평점 없는 선수에게 열리지 않으며, INJURY 미리보기 수치가 룰셋과 어긋나면 팩 검증이 실패하게 만든다.

- 정본: [phase-3-4-plan.md](../phase-3-4-plan.md) D-49·D-50(슬럼프 파생 조건)·P4-3, [T-4-002](T-4-002.md), [T-4-003](T-4-003.md), [T-4-008](T-4-008.md)(팩 0.3.0).
- 선행: **T-4-008(팩 0.3.0) 머지 뒤** 최신 `origin/main`에서 시작한다(`packages/content/packs/0.3.0` 존재로 확인). 0.3.0의 EVT-SLUMP-011도 같은 필드를 쓴다.

## 1. 작업

- **F2 season.stats 파생**: `buildConditionContext`의 `season.stats.goals/assists/appearances/starts/minutes/rating/yellowCards/redCards`를 `state.season.playerStats`에서 파생한다(appearances = `appearances.total`, starts = `started`, rating = `ratedMatches > 0 ? floor(ratingSumTenths / ratedMatches) : 0`… 단위는 기존 DSL 문서 값과 맞춘다 — `docs/`의 DSL 표를 읽고 PR 본문에 단위를 명시). season이 null이면 기존대로 0. `condition-context.test.ts`에 실측값 케이스 추가.
- **F1 슬럼프 게이트**: 화이트리스트에 `season.stats.recentRatedMatches`(최근 5경기 중 평점 받은 경기 수)를 추가하고 `recentFormAverage`는 평점이 0건이면 조건이 걸리지 않는 값(예: 100 상한 sentinel)을 돌린다. EVT-SLUMP-010(0.2.0)·EVT-SLUMP-011(0.3.0) 트리거를 `all[gte season.stats.recentRatedMatches 3, lt season.stats.recentFormAvg 60]`로 고친다. 0.1.0 팩은 바이트 불변. condition-context.test.ts의 'season null → 0' 기대값은 새 sentinel로 갱신하고, "출전 0경기 선수에게 슬럼프가 열리지 않는다" 테스트를 `select-eligible-events` 수준에서 고정한다.
- **F2 EVT-CON-010 phase**: 이벤트의 `phases`를 실제로 매칭되는 값(step 7이 속한 캘린더 phase — `select-eligible-events.ts`의 매핑을 읽고 결정)으로 고치거나, calendar `windowOpen` step에서 phase가 `TRANSFER_WINDOW`로 매핑되도록 매핑을 바꾼다. 어느 쪽이든 **팩 0.2.0/0.3.0 도달 가능성 테스트(T-4-008 `reachability.test.ts`)에서 EVT-CON-010이 최소 1회 선택**돼야 한다. validate-pack에 "상수(NOT_MODELED) 필드만 참조하는 트리거" 경고를 추가한다(파생 뒤에도 상수로 남는 필드 목록을 코드에서 도출).
- **F4·C14 INJURY previewEffects 검증기**: `validate-pack.ts`에 `checkInjuryPreview` 추가 — presentation `INJURY`인 이벤트의 각 choice에 `rehabPlan`이 있으면 previewEffects에 복귀 범위(`availability.matchesRemaining`)·재발 위험(`health.recurrenceRiskBp`)·출전 기회 항목이 있어야 하고, 라벨의 수치(`-2경기`, `+1500bp` 등)를 `loadRuleset(manifest.rulesetVersion).injuryRules.rehabPlans[plan]`의 `returnShiftMatches`·`recurrenceAddBp`와 대조해 불일치면 error. `validate-pack.test.ts`에 불일치 케이스, `load-content-pack.test.ts:83~`의 고정 문자열 기대값은 룰셋에서 생성하도록 바꾼다.
