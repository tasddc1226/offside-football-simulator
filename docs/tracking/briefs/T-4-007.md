## 1. 브랜치·병합 방식

- 작업 브랜치는 PR #66의 head 브랜치 그대로다: `git fetch origin design/tds-game-screens main && git checkout -B design/tds-game-screens origin/design/tds-game-screens`. 시작 시 원격 head가 `620e8e5`인지 확인하고 다르면 멈춘다(사용자가 그 사이 push한 것이므로 오케스트레이터에게 알린다).
- `git merge origin/main`으로 최신 main을 **merge 커밋**으로 합친다(rebase·force-push 금지 — 사용자 커밋 `35ee004`·`620e8e5`의 SHA를 보존한다). 충돌은 "기능은 main, 시각 구조는 design" 원칙으로 푼다: main 쪽의 command·pending 분기·route guard·데이터 투영·테스트 기대값을 남기고, design 쪽의 480px 게임 프레임·`ScreenIntro`·패널·sticky CTA·토큰을 입힌다. 어느 쪽의 기능 assertion도 지우지 않는다.
- `pnpm-lock.yaml` 충돌은 README 규칙대로 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한다. PR #66은 의존성을 바꾸지 않았으므로 충돌이 없어야 하며, 있으면 원인을 PR 본문에 적는다.
- push는 `git push origin design/tds-game-screens`(force 금지). push 직전 `git fetch origin && git rev-parse origin/design/tds-game-screens`가 시작 시 값(`620e8e5`)과 같을 때만 push한다. 다르면 push하지 않고 `BLOCKED`로 멈춘다.
