# T-7-017: 헤드리스 커리어 일괄 시뮬레이션 CLI `career-sim` (tooling/scripts, D-79)

## 목표

UI·브라우저·서버 없이 Node에서 커리어 N개를 seed별로 끝까지(또는 지정 시즌 수까지) 재생하고, 밸런스 조정에 필요한 분포(성장 곡선·리그 도달·부상·계약·은퇴·Legacy 등급)를 CSV·JSON으로 뽑는 CLI를 만든다(D-79). 끝나면 아래 한 줄이 3분 안에 끝나고 결과 디렉터리에 4개 파일이 생긴다.

```bash
pnpm sim:career --ruleset 1.5.0 --pack 0.6.0 --seeds 100 --seasons 20 --policy opportunity --position all --jobs 8 --out tooling/sim-out/base-1.5.0
```

이 작업은 **도구만** 만든다. 룰셋 수치 조정은 하지 않는다(D-62). 조정은 결과를 보고 오케스트레이터·사용자가 새 룰셋 버전(1.5.1)으로 별도 작업한다.

## 범위

- 만질 경로: `tooling/scripts/career-sim.ts`(신규, 본체), `tooling/scripts/career-sim.test.mjs`(신규 1개, 아래 케이스 3개까지 — `legacy-population-identity.test.mjs`처럼 `.mjs`에서 `.ts`를 import), `tooling/scripts/package.json`(devDependencies `"tsx": "4.23.13"` — lockfile에 이미 있는 버전, scripts `"sim:career": "tsx career-sim.ts"`), 루트 `package.json`(scripts `"sim:career": "pnpm --filter @offside/scripts sim:career --"`), `tooling/scripts/tsconfig.population.json`(include에 `career-sim.ts` 추가), `.gitignore`(`tooling/sim-out/`), `pnpm-lock.yaml`(`pnpm install`로만 갱신).
- 만들 것 — `career-sim.ts`:
  1. **인자**(전부 `--이름 값`, 기본값 표기): `--ruleset 1.5.0` `--pack 0.6.0`(둘 다 `RULESET_VERSIONS`/`PACK_VERSIONS`에 있어야 하고 팩 `compatibleRulesetVersions`에 룰셋이 포함돼야 한다, 아니면 즉시 오류) · `--seeds 20`(커리어 수) · `--seed-prefix career-sim`(seed 문자열은 `${prefix}:${position}:${index}`) · `--seasons 20`(상한) · `--to-retirement`(플래그: `retirementDecisionRequired`가 true인 시즌 경계에서 `RETIRE {choice:'RETIRE'}`; 없으면 상한 시즌 뒤 가능하면 RETIRE) · `--policy first|random|opportunity`(기본 `opportunity`) · `--position GK|DF|MF|FW|all`(기본 `all` = index % 4로 그룹 순환) · `--archetype <id>` `--background <id>`(주면 고정, 없으면 legacy-population.ts 305~312행처럼 seed 결정론 표본) · `--mode CHAPTER|FAST`(기본 `CHAPTER`) · `--jobs 1`(자식 프로세스 수, seed 범위 분할) · `--out <dir>`(필수) · `--verify`(플래그: 처음 3개 seed를 두 번 돌려 최종 `hashState`가 같은지 검사, 다르면 exit 2) · `--help`.
  2. **정책**: `first` = 스모크 테스트와 같은 "항상 첫 선택지·첫 제안·ROLE ACCEPT·LOAN_RETURN 첫 옵션". `random` = `chooseDeterministicIndex(careerId, key, n)`로 선택(제안은 `offers.length + 1` 중 하나로 REJECT 포함, 단 무계약이면 첫 제안). `opportunity` = legacy-population.ts `opportunityOffer`(경쟁 순위 → 전술 적합 → 잔류) + ROLE_PROPOSAL은 KEEP 또는 같은 포지션 그룹이면 ACCEPT + LOAN_RETURN 첫 옵션. 이벤트·챕터는 세 정책 모두 `commandForPending`(random·opportunity)·첫 선택지(first)로 닫는다. 정책 코드는 `closePending()` 하나에 `switch`로 모은다.
  3. **루프**: CREATE_CAREER → UPDATE_PLAYER_DRAFT ×2(이름 `표본 ${position} ${index}`, gender·foot은 seed 표본, `nationalityCode: 'KR'`) → CONFIRM_PLAYER → pending을 닫거나 pending null이면 (계약 있고 시즌 없으면 START_SEASON `{ simulationMode, serviceSeasonId: 'career-sim' }`, 아니면 ADVANCE `advancePayload`) → SETTLEMENT면 SETTLE_SEASON. 커리어당 명령 상한 5,000(초과는 실패로 기록). `simulate()`가 `ok:false`면 그 커리어를 실패로 기록하고 다음 seed로 간다(throw로 전체를 멈추지 않는다).
  4. **출력**(`--out` 디렉터리, 덮어쓰기, UTF-8, 헤더 있는 CSV):
     - `careers.csv`: `seed,index,position,primaryPosition,archetypeId,backgroundId,mode,policy,truePotential,baseOvrStart,peakOvr,peakOvrAge,finalOvr,seasons,retiredAge,status,finalChoice,clubs,firstTier,bestTier,seasonsInTier1,seasonsInTier2,seasonsInTier3,totalApps,totalMinutes,totalGoals,totalAssists,avgRatingTenths,injuries,severeInjuries,contracts,peakWageMinorPerWeek,totalIncomeMinor,nationalCallUps,captainSeasons,legacyScore,legacyBandId,legacyEndingId,commands,ms,stateHash`.
     - `seasons.csv`: `seed,index,seasonIndex,age,teamId,teamName,leagueTier,contractKind,squadRoleAtStart,squadRoleAtEnd,finalRank,apps,started,minutes,possibleMinutes,goals,assists,avgRatingTenths,injuries,ovrBefore,ovrAfter,formAfter,fitnessAfter,moraleAfter,managerTrustAfter,wageMinorPerWeek,promiseFulfilled,captaincyAtEnd`. (goals·assists는 `playerStats.totals`에서 포지션 그룹에 맞는 키를 읽고 없으면 빈 칸.)
     - `summary.json`: `{ runtime: {rulesetVersion, contentPackVersion, policy, mode, seeds, seasonsCap, toRetirement, jobs, startedAt, elapsedMs}, careers: {count, failed}, overall: {peakOvr: {mean, p10, p50, p90}, finalOvr: {...}, retiredAge: {...}, seasons: {...}, injuriesPerSeason, tier1ReachRate, tier1ReachBySeason: {5: rate, 10: rate}, legacyBand: {bandId: count}}, byPosition: {GK: {...같은 키...}, DF, MF, FW}, ovrByAge: {age: {mean, p50, n}}, tierBySeasonIndex: {seasonIndex: {1: n, 2: n, 3: n}} }`. 분위수는 정렬 뒤 최근접 순위법, 소수 둘째 자리.
     - `failures.csv`: `seed,index,seasonIndex,commandIndex,pendingKind,commandType,errorCode,message`.
     - stdout: 커리어 수·실패 수·소요 시간·`overall` 요약 8줄, stderr에 진행률(10커리어마다 1줄). 선수 이름·seed 외 개인정보 없음.
  5. **병렬**: `--jobs N`이면 seed 범위를 N개로 나눠 자기 자신을 자식 프로세스(`process.execPath`, 같은 tsx 로더 — `legacy-population-node.mjs` `runParallel` 방식)로 띄우고 각자 `--out <dir>/part-<k>`에 쓴 뒤 부모가 seed 순서로 합쳐 최종 파일을 만든다. 자식이 실패해도 부모는 다른 자식 결과를 합치고 exit 1.
  6. **결정론**: 명령 ID는 `${seed}-${n}`처럼 seed에서만 만든다. `Date.now()`는 `startedAt`·`elapsedMs`에만 쓰고 시뮬레이션 입력에 넣지 않는다. `--verify`가 seed 3개에서 hash 동일을 확인한다.
- 만지지 말 것: `packages/domain/**`, `packages/content/**`(룰셋·팩 수치 포함), `packages/engine-client/**`, `apps/**`, `legacy-population*.ts`·`legacy-balance-probe.mjs`·`legacy-training-diagnostics.ts`, CI 워크플로, docs.

## 제약

- `tooling/scripts`는 ADR-005 워크스페이스 패키지가 아니라 `../../packages/*/src/...ts` 상대 import를 쓴다(legacy-population.ts와 같은 방식). `@offside/*` 패키지 이름 import·`apps/web` import 금지.
- 도메인 순수성은 그대로: 시간·난수는 도메인에 넣지 않는다. CLI 자체는 Node API를 써도 된다.
- `.ts/.tsx/.css` 주석·문자열에 `#숫자` 표기 금지(`이슈 207`처럼 쓴다).
- 브랜치 `T-7-017-career-sim`, 커밋 `T-7-017: …`. `docs/tracking/worker-brief-template.md` 제약(서브에이전트 금지, 새 테스트 파일은 위 1개만, PR 직전 `git merge origin/main`, `gh pr create`가 막히면 push + 본문 반환, 프로세스 종료는 자기 PID로만)을 따른다.
