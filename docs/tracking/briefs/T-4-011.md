# T-4-011: SCR-020 잔류 결과 — INTEREST 시장에서 안전 잔류 수락 시 결과 화면(STAY) 렌더·loader redirect 튕김 제거 (web)

## 목표

시장 사유가 `INTEREST`(계약 미만료 + 타 구단 관심)일 때 안전 잔류 제안을 수락하면 지금은 계약 화면이 `/transfer-result?rev=N`으로 보내고 loader가 전환 엔트리를 못 찾아 대시보드로 되돌린다(결과 화면 없음, 화면 깜빡임). [화면 03](../../screens/03-career-events.md)과 [phase-03](../../phases/phase-03-contract-and-transfer.md)이 SCR-020을 "이적·임대·잔류 결과"로 정의하므로 잔류도 결과 카드로 보여 준다. 도메인은 바꾸지 않는다.

## 참조·선행

- 원인 분석: [T-4-010](T-4-010.md) 원인 2 (`wf_77670be2-155`). 코드: `apps/web/src/routes/career.$careerId.contract.tsx` `handleAccept`(무조건 `goToResult`), `apps/web/src/shared/transfer-result.ts` `TRANSITION_KINDS`·`isCurrentTransferResultRevision`·`resolveTransferResultView`, `apps/web/src/routes/career.$careerId.transfer-result.tsx` loader, `packages/domain/src/simulate.ts` `buildStayState`(timeline `OFFER_REJECTED` reason `ALL`, contract·clubHistory 불변), `career-10-transfer.test.ts:46-75`.
- 선행: **T-4-007(디자인 PR #66 재통합) 머지 뒤** 최신 `origin/main`에서 시작(`docs/design/mobile-game-refresh.md` 존재로 확인). T-4-010이 먼저 머지돼 있으면 그 helper 변경(두 경로 허용)은 그대로 두고, 잔류 결과 화면이 생기면 helper가 `transfer-result` 분기로 자연히 들어간다.

## 1. 작업

- `shared/transfer-result.ts`: 잔류를 결과 종류로 추가한다(예: `kind: 'STAY'`). `OFFER_REJECTED`(reason `ALL`, 시장 사유 `INTEREST`, 같은 revision) 엔트리를 현재 전환으로 인정하고 뷰 모델(제목 "잔류", 구단·남은 계약 시즌·시장 사유·"관심을 보인 구단 N곳" 요약, 관계·평판 변화는 없음을 명시)을 만든다. `EXPIRED` 시장에서 전부 거절→안전 잔류 계약은 기존 `CONTRACT_RENEWED` 경로이므로 건드리지 않는다.
- `career.$careerId.contract.tsx` `handleAccept`: 잔류든 이적이든 결과 화면으로 가되, `resolveTransferResultView`가 `null`이면 결과 화면 대신 현재 결정 화면으로 이동한다(loader redirect 튕김 제거).
- `career.$careerId.transfer-result.tsx`: STAY 뷰 렌더(디자인 계약: T-4-007의 게임 프레임·패널·sticky CTA, 폐기 어휘 금지, 360px 무가로스크롤). CTA는 기존과 같이 "대시보드로"/"새 시즌 준비".
- 단위 테스트: `transfer-result.test.ts`에 STAY 뷰 모델(INTEREST 잔류 timeline 고정 입력) 1건, `EXPIRED` 재계약과 구분되는 케이스 1건. e2e: `season.spec.ts`의 INTEREST 고정 seed 케이스(T-4-010이 만들었다면)를 STAY 카드 확인으로 갱신, 없으면 `transfer.spec.ts`에 seed 고정 케이스 추가(seed 탐색은 e2e 안에서 최대 20개).
