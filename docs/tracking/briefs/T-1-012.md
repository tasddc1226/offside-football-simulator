# T-1-012: SCR-030 데이터 섹션(복구 코드 재발급·프로필 복구·프로필 삭제·이 기기 데이터 삭제·로그아웃)·법적 문서 본문·api의 contracts 스키마 채택

## 목표
사용자가 설정 화면에서 데이터 권리를 행사한다. 복구 코드를 재발급하고, 다른 브라우저에서 코드로 같은 프로필과 모든 커리어를 되찾고, 프로필을 2단계로 삭제하고, 이 기기 데이터만 지운다. 약관·개인정보 처리방침이 앱 안에서 읽힌다.

## 범위
- 만질 경로: `apps/web/src/**`, `apps/web/e2e/**`, `apps/web/playwright.config.ts`, `packages/platform/src/**`(`clearLocalData` 추가), `packages/engine-client/src/import.ts`(신설)·`import.test.ts`·`src/index.ts`(export 한 줄), `apps/api/src/routes/profile.ts`와 그 테스트(아래 1번만). 그 외 금지.
- 만들 것:
  1. **api의 contracts 스키마 채택**(작게): `apps/api/src/routes/profile.ts`의 `parseRecoverBody`·`parseDeleteBody`를 contracts `RecoverProfileBodySchema`·`DeleteProfileConfirmBodySchema`(빈 본문은 1단계)로 바꾼다. 오류는 지금처럼 `VALIDATION_FAILED` + `details.issues`. 응답은 `successEnvelope(IssueRecoveryCodeResponseSchema | RecoverProfileResponseSchema | DeleteProfileStartResponseSchema).parse`로 검증한다. 기존 api 테스트는 그대로 통과해야 하고, 소문자·공백·`ofs` 접두가 섞인 코드가 받아들여지는 테스트 1건을 추가한다. 다른 api 파일은 만지지 않는다.
  2. **platform** `Platform.clearLocalData(): Promise<void>` 추가(`src/types.ts`). web: `Dexie.delete('offside')`(호출 전에 앱이 `store.close()`를 부른다는 것을 주석으로). toss KV 스텁: 전체 삭제. 경계 테스트(`boundary.test.ts`)는 그대로.
  3. **가져오기(engine-client)** `packages/engine-client/src/import.ts`:
     ```ts
     export async function importCareerFromServer(
       store: LocalStore,
       response: GetCareerResponse,           // contracts
       meta: { createdServiceSeasonId: string; now: string },
     ): Promise<{ ok: true; revision: number } | { ok: false; error: EngineError }>;
     ```
     `decodeSnapshot`으로 검증(hash·rngState·careerId) → 실패면 `VERIFICATION_FAILED`. 성공이면 `readwrite` 트랜잭션 하나로 `snapshots.deleteByCareer`·`commandLog.deleteByCareer`·`idempotency.deleteByCareer` 뒤 `snapshots.put(snapshot)`, `commandLog.append`(서버가 준 `commands` 전부, 순서대로), `careers.put({ id, ownerProfileId: null, status: state.status, revision, lastSyncedRevision: revision, createdServiceSeasonId, rulesetVersion, contentPackVersion, createdAt: 기존 레코드가 있으면 그 값 아니면 now, updatedAt: now })`. 로컬에 미전송 revision(`revision > lastSyncedRevision`)이 있는 커리어는 덮어쓰지 않고 `{ ok: false, error: { code: 'CAREER_REVISION_CONFLICT' } }`. 테스트: golden Snapshot 가져오기 → `loadCareer`가 같은 state, 손상 hash 거부, 미전송분 있으면 거부.
  4. **API 클라이언트 확장** `src/api/client.ts`: `recoverProfile(body)`, `startProfileDeletion()`, `confirmProfileDeletion(confirmToken)`, `logout()`, `listRemoteCareers(cursor?)`, `getRemoteCareer(id)`. 응답은 contracts 스키마로 검증. 오류 정규화에 `details`를 포함(`RECOVERY_CONFLICT`의 `currentCareerCount`·`targetCareerCount`).
  5. **복구 뒤 대조** `src/engine/reconcile.ts`: `reconcileAfterRecovery(choice: 'MOVE_TO_LINKED' | 'KEEP_LINKED_ONLY' | 'NONE')`(D-20). `KEEP_LINKED_ONLY`면 서버 목록(`listRemoteCareers` 전 페이지)에 없는 로컬 커리어를 `engine.deleteCareer`(서버 호출 없이 로컬만). `MOVE_TO_LINKED`·`NONE`이면 로컬을 지우지 않고 미전송 커리어를 `notifyCommitted`. 그 다음 서버 목록 중 로컬에 없거나 로컬 `revision < summary.revision`이면서 미전송분이 없는 커리어를 `getRemoteCareer` → `importCareerFromServer`. kv `profile:id`를 새 `profileId`로 갱신. 쿼리 전부 무효화. 순수 함수 부분(무엇을 지우고 무엇을 받을지 결정하는 표)은 분리해 단위 테스트한다.
  6. **SCR-030 데이터 섹션** `/settings`(T-1-007이 둔 "준비 중" 행을 채운다. Google 행은 그대로 "준비 중", T-1-013):
     - **복구 코드** 행: `['profile']`의 `recoveryCodeIssuedAt`이 있으면 "발급일 YYYY-MM-DD"(`<time>`)와 "재발급", 없으면 "아직 없음"과 "발급". 재발급 전 확인 대화상자 "이전 코드는 즉시 쓸 수 없게 됩니다. 새 코드를 적어 두세요." → `POST /profile/recovery-code` → 결과 대화상자에 코드를 한 번만 표시(`font-variant-numeric: tabular-nums`, 복사 버튼, 복사 성공 토스트) + "적어 두었습니다"로 닫힘. 코드는 상태·kv·분석에 저장하지 않는다. `RATE_LIMITED`면 "발급 횟수를 넘었습니다. 잠시 뒤 다시 시도하세요." 발급 성공 뒤 `['profile']` 무효화.
     - **프로필 복구** 행: 코드 입력(자동 대문자, 붙여넣기 허용, `autocomplete="off"`, `inputmode="latin"`) + "복구". contracts `RecoveryCodeInputSchema`로 먼저 검사(형식 오류는 필드 옆 문장). `POST /profile/recover` → `RECOVERY_CODE_INVALID` "코드가 맞지 않습니다"(입력·포커스 유지), `RATE_LIMITED` "시도 횟수를 넘었습니다. 잠시 뒤 다시 시도하세요.", `RECOVERY_CONFLICT` → 선택 대화상자: "이 기기의 커리어 n개를 복구할 프로필로 옮기기"(`MOVE_TO_LINKED`) / "복구할 프로필(커리어 m개)만 사용하고 이 기기의 커리어는 지우기"(`KEEP_LINKED_ONLY`) / "취소". 선택하면 같은 요청에 `mergeChoice`를 붙여 재전송. 성공 → 5번 대조 → 토스트 "프로필을 복구했습니다. 커리어 m개" → 허브로.
     - **동기화 상태** 행: T-1-011 것 그대로.
     - **로그아웃** 행: `['profile'].linked.google`이 true일 때만 활성. Phase 1(T-1-013 전)에는 항상 비활성이며 이유 문장 "Google을 연결한 프로필에서만 쓸 수 있습니다. 지금 로그아웃하면 이 프로필을 되찾을 수 없습니다." 활성일 때 동작: `POST /auth/logout` → 로컬은 그대로(ADR-008) → 동기화가 LOCAL_ONLY가 된다 → 토스트.
     - **이 기기 데이터 삭제** 행: 확인 대화상자에 미전송 커리어 수(`revision > lastSyncedRevision`)와, 복구 코드가 없으면 "복구 코드가 없어 되돌릴 수 없습니다" 경고. 실행: sync `flush()` 시도(실패 무시) → `store.close()` → `platform.clearLocalData()` → 온보딩으로(`location.assign('/onboarding')`, 엔진 싱글턴이 다시 만들어지도록).
     - **프로필 삭제** 행: 1단계 `startProfileDeletion()` → 대화상자 "모든 커리어, 복구 코드, 서버 저장 데이터가 즉시 삭제됩니다. 되돌릴 수 없습니다."와 만료 시각(`expiresAt`) 안내 + "삭제" → 2단계 `confirmProfileDeletion(token)` → 204 → 이 기기 데이터 삭제와 같은 절차 → 온보딩. 토큰 만료·`VALIDATION_FAILED`면 "확인 시간이 지났습니다" 후 1단계부터.
     - 데이터 내보내기 행은 두지 않는다(Phase 7). 모든 위험 동작 버튼은 `--os-danger` 토큰, 대화상자 기본 포커스는 취소.
  7. **법적 문서 본문** `src/legal/operator.ts`(`OPERATOR = { name: 'OFFSIDE 운영팀', contactEmail: '' , effectiveDate: '2026-09-02' }`; 빈 값은 화면에서 "준비 중"), `src/legal/privacy.tsx`·`terms.tsx`(본문 컴포넌트), 라우트 `legal.privacy.tsx`·`legal.terms.tsx`가 렌더. 본문은 D-20의 사실 목록만 쓴다: 수집 항목(익명 프로필 id·설정·커리어 데이터·복구 코드 해시·Google 연결 시 sub·이메일·요청 로그와 요청 id), 보관(삭제 요청 시 즉시 삭제, 병합으로 빈 프로필 30일 뒤 삭제, 요청 로그 보관 기간은 "운영 문서 기준"으로 적고 수치는 넣지 않는다), 처리 위탁(Cloudflare 호스팅·저장, Google 로그인 시 Google), 이용자 권리(복구·삭제·문의). 약관: 서비스 정의, 가상 인물·구단(실명 없음), 계정·복구 코드 책임, 서비스 변경·중단, 준거법(대한민국). 문장은 평이한 한국어, 브랜드 어휘 금지, 제목 계층 `h1`→`h2`, 시행일 `<time>`. 법률 자문이 아닌 초안임을 파일 주석에 적는다(화면에는 적지 않는다). 최종 문안은 U-010.
  8. **분석**: `recovery_code_issued`, `profile_recovered { mergeChoice }`, `profile_deleted`, `local_data_cleared`, `screen_viewed`(SCR-030 섹션 진입). 코드·이름 금지.
  9. **E2E** `apps/web/e2e/settings-data.spec.ts`(`page.route` 스텁): 재발급 확인 → 코드 대화상자 → 복사 → 닫힘, `['profile']` 갱신; 복구 오류 3종 문구; `RECOVERY_CONFLICT` 선택 대화상자 → `mergeChoice` 붙은 재전송; 프로필 삭제 2단계 → 온보딩; 이 기기 데이터 삭제 → 온보딩 → 허브 빈 상태. `apps/web/e2e/recovery-api.spec.ts`(D-18: 실제 API. `E2E_WITH_API=1`일 때만 실행, 아니면 `test.skip`): `playwright.config.ts`의 `webServer`를 배열로 바꿔 `pnpm --filter @offside/api dev`(포트 8787, `reuseExistingServer`)를 같은 플래그로 추가. 컨텍스트 A에서 커리어 생성·확정 → 코드 발급, 컨텍스트 B에서 코드 입력 → B 허브에 같은 커리어 카드. `a11y.spec.ts`에 `/settings` 대화상자들과 `/legal/*` 추가.

## 제약
- `'toss'`·`'web'` 리터럴 비교 금지(lint), hex 색 리터럴 금지, 색·간격·글꼴은 13의 토큰(`--os-*`)만.
- 모든 사용자 문구는 한국어. 저장·삭제·복구에는 브랜드 어휘 금지(12).
- 복구 코드 원문을 로그·분석·kv·URL·오류 details 어디에도 남기지 않는다.
- `localStorage` 직접 접근 금지. 화면 컴포넌트에서 `import.meta.env.MODE` 검사 금지.
- 커밋 메시지는 `T-1-012: …`로 시작, 브랜치는 `T-1-012-…`.
- 서브에이전트 리뷰를 띄우지 않는다. Orca PR 게이트용 `/review:pr` 1회만 예외(`/simplify`·병렬 fork 금지).
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
