# T-1-007: web 엔진 배선·룰셋/팩 로딩·온보딩 SCR-034·허브 SCR-001·라우트 골격·설정 영속화

## 목표
브라우저에서 커리어를 만들고(DRAFT), 허브에서 이어하고, 삭제할 수 있다. 시뮬레이션은 Web Worker에서 돌고 저장은 platform LocalStore(Dexie)다. 이후 화면 작업(T-1-008·009·012)은 이 작업이 만든 훅·액션·라우트 골격 위에 화면만 얹는다.

  1. **엔진 부트스트랩** `src/engine/engine.ts`: `createAppEngine(deps)`와 지연 싱글턴 `getAppEngine(): Promise<AppEngine>`. 기본 deps: `platform.createLocalStore()`, `new Worker(new URL('@offside/engine-client/worker', import.meta.url), { type: 'module' })` + `createWorkerSimulator`, `loadRuleset(ACTIVE_RULESET_VERSION)`, `loadContentPack(ACTIVE_CONTENT_PACK_VERSION)`, `createEngineClient({ store, simulator, ruleset, newId: () => crypto.randomUUID() })`. `AppEngine = { client: EngineClient; store: LocalStore; ruleset: Ruleset; pack: ContentPack; versions }`. `src/engine/versions.ts`: `ACTIVE_RULESET_VERSION = '1.0.0'`, `ACTIVE_CONTENT_PACK_VERSION = '0.1.0'`, `ACTIVE_SERVICE_SEASON_ID = 'svc_kickoff'`(api 로컬 시드 `apps/api/seeds/local.sql`의 활성 서비스 시즌과 같다. 서버에서 현재 시즌을 받아오는 것은 Phase 6이라는 주석). 부트 시 `pack.manifest.compatibleRulesetVersions`에 룰셋 버전이 없으면 throw. engine-client가 인스턴스당 룰셋 하나만 받는 것은 Phase 1에 버전이 하나라 문제없고, 커리어별 버전 선택은 Phase 6 항목이라는 주석을 남긴다. 테스트(jsdom)에서는 Worker 대신 `inlineSimulator`와 `MemoryLocalStore`를 주입한다.
  2. **커리어 액션** `src/engine/career-actions.ts`(EngineClient 위의 순수 함수, React 없음): `createCareer(engine, { simulationMode })` — `careerId = crypto.randomUUID()`, `seed`는 `crypto.getRandomValues` 8바이트의 hex 문자열, `CREATE_CAREER { careerId, seed, simulationMode, rulesetVersion, contentPackVersion }`, `expectedRevision 0`, `createdServiceSeasonId: ACTIVE_SERVICE_SEASON_ID`; `updateDraft(engine, careerId, draft)`; `confirmPlayer(engine, careerId)`; `advance(engine, careerId)` — 최신 상태로 `selectEligibleEvents(pack, state)`를 계산해 `ADVANCE { eligibleEvents }`; `deleteCareer(engine, careerId)`; 공통 `execute(engine, careerId, command)`는 `loadCareer`로 최신 revision을 읽어 `expectedRevision`을 채우고 `commandId = crypto.randomUUID()`. 각 실행에서 `platform.analytics.track`으로 06의 `command_submitted(commandType)`, `command_resolved(commandType, outcomeClass = nextAction, latencyBucket ∈ '<100ms' | '<500ms' | '<2s' | '>=2s')`, `command_failed(commandType, errorCode)`를 보낸다. `RESOLVE_EVENT`(팩 outcome → domain Effect 변환)와 `ACCEPT_OFFER`는 T-1-009가 여기에 추가한다(주석으로 자리 표시).
  3. **React 훅** `src/engine/use-career.ts`(TanStack Query): `useCareerList()` — `listCareers()` + 각 커리어의 최신 Snapshot(`loadCareer`)로 카드 요약 `{ record, state }`, `sortCareers`(platform `careers-sort.ts`)로 정렬; `useCareer(careerId)` — `{ record, snapshot, state }`; `useCareerMutation(kind)` — 액션 실행 후 관련 쿼리 무효화. 쿼리 키는 `['careers']`, `['career', careerId]`.
  4. **화면 해석기** `src/shared/career-route.ts`: 순수 함수 `screenForCareer(state: CareerState): { screenId: keyof typeof SCREEN_ROUTES; params: { careerId } }`. 규칙: `DRAFT`는 `draft.archetypeId`를 뺀 5개 필드 중 하나라도 null → SCR-002, `archetypeId` null → SCR-003, 그 외 → SCR-004. `ACTIVE`는 `pending.kind === 'EVENT'` → `EVENT_SCREEN_OVERRIDES[eventId] ??   8. **설정 영속화** `src/shared/ui-store.ts` 확장: `defaultSimulationMode: 'FAST' | 'CHAPTER'`(기본 `FAST`), `onboardingSeen: boolean`. `hydrateUiStore(store: LocalStore)`가 LocalStore `kv` 키 `'ui:settings'`에서 읽어(contracts `ProfileSettingsSchema` + `onboardingSeen`으로 검증, 실패·없음이면 기본값) 스토어를 채우고, 모든 setter는 같은 키에 다시 쓴다(실패는 콘솔 경고, 화면은 막지 않음). `main.tsx`의 `bootstrap`이 첫 렌더 전에 `getAppEngine()` → `hydrateUiStore(engine.store)`를 기다린다(그동안 루트 컨테이너는 비어 있어도 된다. 실패하면 `ErrorState`를 그린다). 저장은 localStorage가 아니라 LocalStore다(T-0-009·T-0-012 결정).
  9. **설정 SCR-030 로컬 부분** `/settings`: 테마(SYSTEM/LIGHT/DARK)·모션 감소·텍스트 크기·시뮬레이션 기본 모드를 `RadioGroup`으로(즉시 저장), "온보딩 다시 보기" 링크, 버전 행(룰셋 1.0.0·콘텐츠 팩 0.1.0·엔진 클라이언트 `ENGINE_CLIENT_VERSION`), 데이터 섹션은 행만 두고 비활성 "준비 중"(복구 코드, 프로필 복구, Google 연결(D-16), 동기화, 내보내기, 프로필 삭제, 이 기기 데이터 삭제 — T-1-012·013이 채운다). 채널 문구 분기는 `platform`이 주는 값으로만.
  10. **분석**: 허브·온보딩·설정 진입에서 `screen_viewed(screenId, careerPhase)`(커리어 없으면 `'NONE'`).
  11. **E2E**(`apps/web/e2e/`): `hub.spec.ts` 갱신 — 첫 방문은 `/onboarding`으로 감, 건너뛰기 후 허브 빈 상태와 "커리어 시작" 버튼, KICKOFF로 DRAFT가 만들어져 `/career/<id>/create`에 도착, 허브로 돌아오면 카드("이름 없는 선수", "만드는 중")가 보이고, 삭제 대화상자 확인 후 카드가 사라짐. `a11y.spec.ts`에 `/onboarding`, `/settings`, 카드가 있는 허브를 추가(serious·critical 0건). `hash-probe.spec.ts`·`legal.spec.ts`는 그대로 통과해야 한다.
