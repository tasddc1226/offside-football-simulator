## D-54 서비스 시즌 포인터와 테스트 시즌(이 브리프로 확정)

- **포인터는 환경 변수**: API `ACTIVE_SERVICE_SEASON_ID`(wrangler `vars`). local·preview·CI 테스트 = `svc_kickoff`(기존 테스트 불변), staging = `svc_line_test`, production은 값을 두지 않아 라우트가 `SERVICE_SEASON_UNAVAILABLE`(503)을 돌려준다(출시 게이트 전 실수 방지). 09 런북 6번 "ACTIVE 포인터 원자 교체"는 이 변수 교체 + 재배포다.
- **`service_seasons.is_test`**(integer 0/1, 기본 0, drizzle 마이그레이션 추가): `svc_line_test`는 1. Phase 6 도전·앨범 집계는 `is_test = 0`만 읽는다(지금은 집계 코드가 없으므로 필드와 주석·테스트만). 테스트 시즌에서 만든 커리어는 삭제·강제 은퇴하지 않는다(05 "서비스 시즌 종료는 Career 삭제가 아니다").
- **API-SVC-001 `GET /v1/service-seasons/current`**(프로필 세션 불필요, 공개): `{ id, name, status, isTest, startsAt, endsAt, rulesetVersion, contentPackVersion, notice: string | null }`. `notice`는 테스트 시즌이면 D-55의 고정 문구 키(`'LINE_TEST'`), 아니면 null(문구 자체는 웹이 갖는다 — 서버가 문장을 보내지 않는다, D-12 관례). 캐시 헤더 `Cache-Control: public, max-age=60`. 포인터가 가리키는 행이 없으면 503 `SERVICE_SEASON_UNAVAILABLE`.
- **커리어 생성 검증**: `PUT /careers/{id}` 신규 생성 시 `createdServiceSeasonId`는 (a) 존재하고 (b) status가 `PRESEASON` 또는 `ACTIVE`여야 한다(LOCKED·ARCHIVED면 409 `SERVICE_SEASON_CLOSED`). 기존 커리어의 후속 PUT은 검사하지 않는다(시즌이 닫혀도 진행은 계속).
- **웹**: `career-actions.ts`·`reconcile.ts`가 `ACTIVE_SERVICE_SEASON_ID` 상수 대신 `useServiceSeason()`(TanStack Query, `GET /service-seasons/current`, staleTime 5분, kv-store에 마지막 성공 값 저장)을 쓴다. 오프라인·스텁·실패 시 폴백 순서: kv-store 저장값 → 상수 `svc_kickoff`. 커리어 생성 버튼은 시즌 조회가 끝나기 전에도 눌리되(폴백 사용), 조회가 `LOCKED`·`ARCHIVED`를 돌려주면 SCR-001 허브의 "새 선수" 버튼을 비활성화하고 안내 문구를 보인다.
- **허브 테스트 보관함 표시**: 커리어 카드의 `createdServiceSeasonId`가 현재 시즌과 다르거나 그 시즌이 `isTest`이면 카드에 "테스트 시즌" 배지(`data-testid="career-card-test-badge"`)를 단다. 정렬·삭제 동작은 바꾸지 않는다. 허브 상단에 시즌 배너 1줄(테스트 시즌일 때만): 문구는 `apps/web/src/shared/labels.ts`에 `SERVICE_SEASON_NOTICE_KO.LINE_TEST = 'LINE TEST 시즌입니다. 이 커리어는 테스트 보관함에 남고 정식 시즌 도전에는 집계되지 않습니다.'`(12 브랜드 어휘 준수, 해요체 금지 규칙은 12 문서 확인).

## D-55 분석 이벤트 수집(이 브리프로 확정)

- **전송 경로**: 웹 `packages/platform/src/web/index.ts`의 `analytics.track`이 메모리 큐에 넣고, (a) 큐 20건 또는 (b) 10초 경과 또는 (c) `pagehide`/`visibilitychange: hidden`에 `navigator.sendBeacon` 우선, 없으면 `fetch(keepalive)`로 **`POST /v1/analytics/events`**(신규 API-ANA-001, 프로필 세션 선택 — 있으면 `profileId` 기록, 없으면 익명)에 `{ clientId, events: [{ name, props, clientTs }] }`(최대 50건, 본문 32KB 이하)로 보낸다. 재시도 없음(유실 허용, 01 "최종 일관성 허용"). `clientId`는 kv-store에 저장한 무작위 UUID(프로필·커리어와 무관, 설정 "이 기기 데이터 삭제"가 지운다). toss 어댑터는 no-op 유지. 개발 모드(`import.meta.env.DEV`)에서는 콘솔에도 찍는다.
- **서버**: `analytics_events` 테이블(id, client_id, profile_id nullable, name, props JSON text, client_ts, received_at) + drizzle 마이그레이션. 라우트는 `packages/contracts/src/analytics.ts`의 zod 스키마로 **이벤트 이름 화이트리스트와 prop 키·값 타입**을 검증하고 맞지 않는 이벤트는 건별로 버린다(요청 전체는 202). 문자열 prop은 64자 이하, 키는 아래 표의 것만. `bodyGuard`·`originGuard`·rate limit(분당 60요청/clientId, 기존 미들웨어 패턴)을 태운다. 개인정보: 선수 이름·성별·자유 입력·서사 전문은 스키마에 키 자체가 없다(06 "분석 이벤트").
- **이벤트 표**(기존 것은 그대로, 신규 ★):

| 이름 | props | 언제 |
|---|---|---|
| `screen_viewed` | screenId, careerPhase | 기존 |
| `choice_previewed` | eventId, choiceId | 기존 |
| ★ `choice_selected` | eventId, choiceId, riskLabel | RESOLVE_EVENT 제출 직전(선택지 분포) |
| `chapter_decision_resolved` / `role_proposal_resolved` | 기존 | 기존 |
| `command_submitted` / `command_resolved` / `command_failed` | commandType(+outcomeClass·latencyBucket / errorCode) | 기존 |
| ★ `funnel_reached` | stage(`ONBOARDING_STARTED`·`PLAYER_CONFIRMED`·`CONTRACT_SIGNED`·`SEASON_STARTED`·`SEASON_SETTLED`), careerIndex(이 기기에서 몇 번째 커리어인지), elapsedSecBucket(`<60`·`<180`·`<360`·`<720`·`<1800`·`>=1800`) | 단계 도달 시 1회. 기준 시각은 kv-store에 커리어별로 저장한 `ONBOARDING_STARTED` 시각(웹은 `Date` 사용 가능, 도메인 아님). 세션 길이 = SCR-034→SCR-010과 CMD-SIM-001→003(D-31) |
| ★ `step_passed` | seasonIndex, step, simulationMode | ADVANCE 응답으로 `currentStep`이 오를 때마다(이탈 step은 마지막 `step_passed`로 계산) |
| ★ `season_settled` | seasonIndex, simulationMode, decisionsOpened(`season.steps[].summary.decisionsOpened` 합, SETTLE_SEASON 제출 직전 상태에서), matchesPlayed, elapsedSecBucket(SEASON_STARTED 이후) | SETTLE_SEASON 성공 시 |
| ★ `career_abandoned_hint` | seasonIndex, step, seasonPhase | 커리어 삭제 확인 시(삭제 자체는 기존 이벤트 없음) |

- 값은 전부 열거형·정수·버킷 문자열이다. 시각은 `clientTs`(epoch ms)만 — 서버가 `received_at`을 별도로 찍는다.

- 문구·주석 한국어, 브랜드 어휘(12 문서). 커밋 `T-2-012: …`, 브랜치 `T-2-012-…`. 커밋은 슬라이스별(api 시즌 라우트·검증 / 마이그레이션·시드 / contracts / platform 큐 / web 시즌 주입·허브 / web 이벤트 발화 / e2e).
- 서브에이전트를 띄우지 않는다 — 리뷰용이든 조사용이든 전부(gstack `/review`·`/codex`·adversarial·`/simplify`·병렬 fork·Agent/Explore 조사 에이전트 금지). 예외는 Orca PR 게이트용 `/review:pr` 1회(로컬 모드).
- e2e 전에 `lsof -nP -iTCP:5189 -sTCP:LISTEN`이 비어 있어야 한다. PR 직전 `git fetch origin && git merge origin/main` 뒤 전체 체인 재실행. `pnpm-lock.yaml` 충돌은 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`.
