# T-1-005: domain 제안 생성·`ACCEPT_OFFER`·Contract — 첫 계약까지 golden 확장

## 목표
입단 테스트(또는 진로 선택)가 끝난 커리어에 `ADVANCE{ eligibleEvents: [] }`를 보내면 룰셋 `offerRules`에 따라 제안 1~3개가 결정론적으로 생성되어 `pending`에 실리고, `ACCEPT_OFFER{ offerId }`로 계약이 확정되어 golden fixture가 계약까지 이어진다.

## 참조 명세
- 요구사항 ID: FR-CON-001, FR-EVT-001, RULE-RNG-001, TEST(결정론)
- 읽어야 할 문서(순서대로): `docs/tracking/phase-1-plan.md` **D-9, D-10(3·5단계), D-12**(정본), `docs/tracking/briefs/T-1-001.md`(이미 머지된 타입·명령 규칙), `docs/tracking/briefs/T-1-002.md` §룰셋 파일 형식(`offerRules`·`contractRules`), `docs/phases/phase-01-career-vertical-slice.md`, `docs/content/prototype/season-01-inside-forward.md`(EVT-P10 제안 수 수식)
- 정본 우선순위: phase-1-plan.md 결정 > docs/development > phases

## 범위
- 만질 패키지·경로: `packages/domain`. 예외: `packages/fixtures/src/career-01/*`(golden·룰셋 복제본 갱신)과 다른 패키지 테스트의 fixture 참조 최소 수정(파일 목록을 PR에).
- 만들 것:
  1. `ADVANCE` 3단계(T-1-001이 건너뛴 자리): `status === 'ACTIVE'`, `pending === null`, `eligibleEvents.length === 0`, `contract === null`일 때 `offerRules.branches`를 배열 순서대로 검사해 첫 일치 분기로 제안을 만든다. 일치 분기가 없으면 4·5단계로 넘어간다.
  2. 제안 개수: 분기에 `fixedCount`가 있으면 그 수. 없으면 `1 + Σ hasTag(countBonusTags)`(챕터 활약 항은 Phase 1에서 0), 상한 `maxOffers`, 하한 1. 팀 풀: `fixedTeamId`가 있으면 그 팀 1개 고정. 아니면 `teams`에서 `leagueTier ∈ branch.tiers`인 팀을 id 오름차순으로 모아 비복원 추출. `topTierMinOvr`가 있고 `baseOvr >= topTierMinOvr`이면 첫 제안은 tier 1 풀에서, 나머지는 전체 풀에서. 풀이 개수보다 작으면 풀 크기만큼만.
  3. 제안 1개당 rng 소비 순서(고정, 테스트로 검증): 팀 추출 `rollInt(0, poolSize-1)` → `lengthSeasons = rollInt(min,max)` → `rolePromise = rolePromiseByTier[tier][rollInt(0,1)]` → `shirtNumber = rollInt(min,max)` → `tacticalFitEstimate = rollInt(min,max)`. 고정 팀이면 팀 추출 roll은 생략. 주급·계약금은 rng 없이 `contractRules.ovrBands`(baseOvr 구간)와 `wageBands[team.wageBandId]`에서 읽는다.
  4. `Offer` 필드: `id = 'OFR-' + <이 명령이 만드는 revision> + '-' + index`, `teamId, teamName, leagueTier, lengthSeasons, wageMinorPerWeek, signingBonusMinor, rolePromise, shirtNumber, tacticalFitEstimate`. `pending = { kind: 'OFFERS', offers }`, checkpoint `CHAPTER_DECISION`, nextAction `'DECISION'`.
  5. `ACCEPT_OFFER` payload `{ offerId }`: `pending.kind === 'OFFERS'`이고 목록에 있어야 한다(아니면 `VALIDATION_FAILED` `'NO_PENDING_OFFERS' | 'OFFER_NOT_FOUND'`). `contract = { id: 'CTR-' + revision, offerId, teamId, teamName, leagueTier, lengthSeasons, wageMinorPerWeek, signingBonusMinor, rolePromise, shirtNumber, signatureType: 'AUTO', signedAtRevision }`. `stage`: tier `'YOUTH'`면 유지, 아니면 `'PRO'`. `context.squadStatus = squadStatusByRole[rolePromise]`. 새 클럽(`teamId !== background.startTeamId`)이면 `relationships.managerTrust = contractRules.newClubManagerTrust`, 같은 클럽이면 유지. `context.tacticalFit = offer.tacticalFitEstimate`. `pending = null`, `timeline += { kind: 'CONTRACT_SIGNED', refId: contract.id }`, checkpoint `CONTRACT_CONFIRMED`, nextAction `'SETTLEMENT'`. rng 소비 없음.
  6. 계약 후 `ADVANCE{ eligibleEvents: [] }`는 정산 단계이므로 `VALIDATION_FAILED { reason: 'NOTHING_TO_ADVANCE' }`(T-1-001 5단계 그대로).
  7. golden fixture 확장: `career-01.json` commands 끝에 `ADVANCE{ eligibleEvents: [] }`, `ACCEPT_OFFER{ offerId: 'OFR-<revision>-0' }`를 추가. golden JSON에 `contract`(id·teamId·leagueTier·rolePromise·lengthSeasons)와 `offersCount`를 추가. 사유를 PR에 적는다.
- 만지지 말 것: `docs/`, `packages/content`(룰셋 값은 그대로 사용), `packages/contracts`, `apps/*`. `ATTRIBUTE_KEYS`·`canonicalize`·`hashState`·`rng` 변경 금지.
