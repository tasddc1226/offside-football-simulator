# T-10-087: K리그2 우승 구단의 K리그1 승격 기획

> 상태: 1차 구현 T-10-110 (서비스 시즌 1 개막 때 배포) — 결정은 맨 아래 '1차 구현 결정'
> 기준: 원격 main `40407d3920dfe80afec081b322e33943f8d16256` (2026-09-28)
> 이 문서는 게임 내 단순화한 승격 규칙을 제안한다. 실제 K리그의 연도별 승강·라이선스·참가 규정을 재현하는 문서가 아니다.

## 1. 목적과 핵심 경험

K2에서 우승해도 같은 리그가 반복되는 단절을 줄이고, 선수가 키운 구단과 함께 상위 무대에 도전하는 이유를 만든다. 단순히 K1 팀의 이적 제의를 주는 이벤트와 구분한다.

**K2 최종 1위 → 구단 승격 확정 → 잔류/재계약 또는 이적 선택 → 잔류했다면 같은 구단으로 다음 해 K1 출전**이 기본 흐름이다.

이름·엠블럼·구단 ID·등번호·원클럽 기록은 유지한다. 승격은 구단의 성과이며 선수의 OVR·잠재력이나 재계약 여부에 따라 취소되지 않는다. 선수는 승격 구단을 떠날 수 있고, 은퇴해도 우승 시즌의 승격 성취는 기록에 남는다.

## 2. 현재 구현과 연결 지점

분석 기준 SHA에서 확인한 내용:

| 현재 구조                                                                                  | 승격을 넣을 때 필요한 변화                                                      |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| `season.ts:endSeason`이 `finalRank`로 최종 순위를 산출하고 우승·개인상·CareerRecord를 기록 | 같은 최종 순위를 승격 판정에 재사용하고 K2 기록 확정 후 다음 연도 변경 예약     |
| `table.ts:leagueTable`은 기대 승점 기반 표시 순위, `finalRank`는 추가 난수를 사용          | 결산 화면과 승격 판정이 다른 순위를 보여주지 않도록 최종 결과를 한 번 확정·저장 |
| `data.ts:CLUBS`와 `player.ts:clubsIn`은 정적 소속 리그 사용                                | 세이브별 소속 리그를 조회하는 공통 경로 도입                                    |
| 구단 ID는 `club-names.ts:clubIdOf`의 리그·인덱스로 생성                                    | ID의 접두사는 출생 당시 식별자로 유지하고 현재 소속 리그를 추론하지 않음        |
| `market`은 잔류·재계약·이적·병역·은퇴 선택, `acceptOption`은 정적 CLUBS에서 이적 대상 복사 | 시장 생성부터 선수 소속 갱신까지 동적 소속 일관성 유지                          |
| `engine.ts:newSeason`은 현재 `leagueId`로 상대 전력 생성                                   | 승격 적용 후 K1 규칙으로 새 시즌 생성                                           |
| K2/K1 경기 수는 게임 설정상 36/38, 평균 전력은 57/63                                       | 경기 수와 대회는 K1 기준, 구단 자체 전력은 즉시 강팀으로 바꾸지 않음            |
| `military.ts`는 입대 전 구단과 리그를 저장하고 전역 때 복원                                | 전역 복귀 시 구단의 현재 소속을 다시 해석                                       |

현재 전체 구단이 실제 일정을 치르는 공유 리그 시뮬레이션은 아니다. 단순히 `s.leagueId = 'k1'`만 바꾸면 순위표·이적·대회·서버 기록이 서로 어긋날 수 있다.

## 3. 1차 범위

- 플레이어가 K2 구단에 소속된 채 완료한 시즌의 확정 최종 순위가 1위이면 자동 승격한다.
- 선수 개인의 출전 수·득점·포지션·잠재력·성장 특성을 추가 조건으로 걸지 않는다.
- 중간 순위, 코리아컵 우승, K2 구단에서 K1 구단으로의 일반 이적은 승격 조건이 아니다.
- 전 세계나 다른 유저의 구단 소속을 변경하지 않는다. 승격 세계는 각 선수 세이브에 한정한다.
- 과거 은퇴 기록에 승격을 소급 생성하지 않는다. 새 기능 도입 후 정상 결산한 시즌부터 적용한다.
- K2 플레이오프, 매년 자동 승강, K3 승격, 타국 승강, 승강 전용 감독·이사회 시스템은 제외한다.
- 1차에서는 승격한 플레이어 구단의 다음 해 성적 부진에 따른 자동 강등을 넣지 않는다. 안내에 단순화 범위를 밝힌다.

## 4. 화면과 선택 흐름

### 시즌 결산

K2 우승·개인상·최종 기록을 먼저 확정하고 승격 소식을 같은 결산에서 보여준다.

> K리그2 우승, 다음 무대는 K리그1
>
> 이번 시즌 1위로 구단의 승격이 확정됐습니다
> 다음 시즌에는 K리그1에서 새로운 도전을 시작합니다

우승과 승격을 구별하여 기록하되 두 번의 우승 트로피로 세지 않는다. 확률로 실패하거나 재접속 때 결과가 달라지는 이벤트가 아니다.

### 오프시즌

| 상황                  | 표시·처리                                                               |
| --------------------- | ----------------------------------------------------------------------- |
| 계약이 남음           | 기존 잔류 선택에 “이 구단과 K1 도전” 설명 추가, 연봉·잔여 계약은 그대로 |
| 계약 만료·재계약 가능 | 승격 후 리그 조건으로 재계약 제안 산정, 기존 재계약 자격은 유지         |
| 계약 만료·재계약 불가 | 구단의 승격과 선수의 계약 종료를 구분하여 설명하고 기존 이적 경로 제공  |
| 다른 구단으로 이적    | 승격 공헌 기록은 보존, 실제 다음 리그는 이적 대상 구단의 현재 소속 사용 |
| 은퇴                  | 우승과 승격 기록은 남기되 가상의 K1 출전 시즌은 생성하지 않음           |
| 입대·전역             | 기존 의무 입대 우선순위 유지, 복귀 구단 소속을 동적 상태로 확인         |

잔류를 누르기 전 K1에서 상대 수준이 높아져 출전 기회·성적이 달라질 수 있음을 설명한다. 능력치·급여·주전 보장은 자동 지급하지 않는다.

### 다음 시즌 및 기록실

리그 표시·경기 수·상대·대회·수상 조건을 K1으로 전환한다. 직전 연도의 우승과 통계는 K2로 남긴다. 구단별 통산 기록은 같은 ID로 이어져 원클럽·구단 공헌·영구결번의 정체성을 보존한다.

## 5. 리그 소속과 팀 수 정책

권장안은 **정적 구단 원본 + 커리어별 소속 변경표**다. 전역 `CLUBS`를 수정하지 않는다.

- 세이브 안의 소속 변경표로 `현재 연도에서 구단이 속한 리그`를 조회한다.
- K1에 승격 구단을 넣을 때 기존 K1 구단 하나를 K2로 이동시켜 양쪽 팀 수를 유지한다.
- 현재는 플레이어가 뛰지 않은 K1의 완전한 시즌 결과가 없으므로 “실제 K1 최하위”를 지어내지 않는다. 1차 후보는 현재 K1 소속 구단 중 기본 전력이 가장 낮은 일반 구단을 선택하고 동률은 구단 ID로 정렬하는 단순화 규칙이다.
- 이 상대 구단 선정 규칙은 출시 전 검토 항목이다. 운영 화면에는 검증되지 않은 상대 구단의 순위·승점·강등 경기 서사를 만들지 않는다.
- 군 복무용 특수 구단은 교체 후보에서 제외한다. 정적 군 구단 표기와 `SANGMU` 특수 ID의 관계를 구현 시 명시적으로 정리한다.
- 다음 연도 소속 변경은 선수가 다른 팀으로 이적해도 해당 세이브 안에서 유지한다. 나중에 돌아와도 원래 K2로 되돌아가지 않는다.
- 순위표에서 같은 구단이 두 번 등장하거나 K1/K2 양쪽에 동시에 나오는 것을 금지한다. 여러 차례 다른 K2 구단으로 승격해도 동일 규칙을 사용한다.

이 정책의 구현 범위가 과도하면 1차 출시를 미룬다. 구단만 바꿔치기하거나 K1 팀 수를 조용히 늘리는 임시 구현은 하지 않는다.

## 6. 처리 순서·저장·멱등성

후보 필드명은 설계 예시이며 확정 API 계약이 아니다.

1. 시즌 결산 최종 순위와 필요 시 최종 표를 한 번 산출하고 저장한다. 기존 경기 RNG 소비와 결과 변화는 별도로 검증한다.
2. 기존 K2 `CareerRecord`, 우승·개인상·대회 기록을 완성한다.
3. `career + 종료연도 + clubId + k2→k1`을 키로 승격 이벤트를 생성하고 `effectiveYear`를 기록한다.
4. 다음 연도 소속 변경과 K1 교체 구단을 한 번 확정한다. 결산 도중 승격 연출을 닫아도 이벤트는 보존한다.
5. 기존 `endSeason` 내부 병역 처리와 연도 증가 순서를 고려해, 새 연도의 시장/복귀 처리 전에 동일한 소속 resolver가 적용되도록 원자적 전환 지점을 정한다.
6. 선택 후 `s.club.leagueId`와 `s.leagueId`를 일치시키고 `newSeason`을 실행한다. 이적 시 새 대상의 동적 소속을 사용한다.

저장 필드는 소속 변경 이력·승격 이벤트·결산 완료 상태·시즌별 리그 식별자를 최소 단위로 검토한다. 기록의 연도별 리그는 현재 구단 소속으로 역산하지 않는다.

`migrateSave`에서 필드가 없는 기존 저장은 정적 소속으로 해석한다. 과거 우승 기록만 보고 승격을 재실행하지 않는다. 결산 중 새로고침, 세이브 복구, 중복 클릭, 업로드 재시도에도 승격·구단 교체·보상이 한 번만 적용되어야 한다.

## 7. 보상과 기존 시스템 정합성

- K2 우승 트로피는 기존 1개만 지급한다. 승격 자체를 우승·개인상으로 중복 집계하지 않는다.
- 1차는 승격 로그·커리어 기록·화면 연출을 보상으로 삼는다. 별도 LS 가산·OVR·잠재력·영구 버프는 추가하지 않는다.
- “승격의 주역” 같은 칭호는 선택 확장안이다. 현재 칭호 획득이 명성을 올리는 점까지 포함해 검증한 뒤 추가하며 출전 없는 선수에게 주역 표현을 자동 부여하지 않는다.
- 원클럽, 구단 통산 기록, 영구결번 후보 자격에서 승격은 이적으로 취급하지 않는다.
- 영구결번의 전역 `clubId + 등번호` 자원은 그대로 유지한다. 유저별 승격이 같은 구단을 별개 구단으로 복제하지 않는다.
- 서버가 구단 ID의 정적 소속·등급으로 시즌 실적을 판정하는 경로를 점검한다. 시즌 당시 리그의 제출·검증 계약 없이 클라이언트의 K1 주장만 믿고 보상 자격을 확대하지 않는다.
- 아시아 대회는 승격했다는 이유만으로 출전권을 자동 부여하지 않는다. 기존 대회 설정이 직전 리그 순위를 사용한다면 K2 1위를 K1 1위로 오인하지 않도록 이전 리그를 함께 확인한다.
- 공개 구단 이름·엠블럼은 정체성만 나타내며 커리어별 리그를 전역 설정에 쓰지 않는다.

## 8. 구현 후보 영역

- 게임: `data.ts`, `player.ts`, `table.ts`, `season.ts`, `engine.ts`, `comps.ts`, `military.ts`, `types.ts`, `save.ts`
- 표시: 시즌 결산, 시장 선택, 순위표, 선수 상세·커리어 기록의 리그 표시
- 계약/API: 시즌 요약과 은퇴 snapshot의 리그 이력, 서버 기록 검증과 영구결번 심사
- 검증: `league-table.test.ts`, `season.test.ts`, 저장 복구 테스트와 헤드리스 시뮬레이터

명칭으로 파일을 추측해 바로 고치지 않고 구현 시 최신 main에서 관련 호출 경로를 다시 확인한다. 기존 시즌/은퇴 업로드에 요약을 묶어 보내며 새 폴링·클릭별 DB 쓰기를 추가하지 않는다. 신규 조회 조건은 인덱스·캐시 정책을 함께 검토한다.

## 9. 수용 기준과 QA

- [ ] K2 확정 1위만 승격하며 2위·중간 1위·컵 우승에는 발동하지 않는다.
- [ ] 시즌 결산의 최종 순위와 승격 판정이 동일하고 재접속 시 변하지 않는다.
- [ ] 우승 시즌은 K2, 잔류 후 다음 시즌은 K1으로 기록된다.
- [ ] 같은 구단 ID·엠블럼·별칭·등번호·원클럽 기록이 유지된다.
- [ ] 두 리그 팀 수와 구단 소속의 유일성이 유지되고 자기 팀이 중복 상대가 되지 않는다.
- [ ] 재계약 실패·이적·은퇴·입대·전역·이전 구단 복귀를 각각 검증한다.
- [ ] 구단 승격은 선수가 떠나도 유지되고 다른 세이브/유저에게 전파되지 않는다.
- [ ] 승격만으로 대륙대회 출전권·LS·트로피·개인상이 중복 지급되지 않는다.
- [ ] 기존 세이브와 이름만 있는 옛 기록을 읽을 수 있고 과거 우승 소급 승격이 없다.
- [ ] 복구·새로고침·중복 결산·중복 업로드가 승격을 반복하지 않는다.
- [ ] 서버 기록/영구결번의 리그 판정과 공개 화면이 일치한다.
- [ ] 고정 시드로 변경 전후 K2 우승률, 승격 후 출전·득점·LS·이적·은퇴 분포를 비교한다.

K2 우승 판정 자체를 쉽게 만들거나 성장률을 올리는 변경은 분리한다. 시뮬레이션은 실제 게임 엔진으로 실행하며, 이번 문서 PR에서는 구현·실험을 실행하지 않았다.

## 1차 구현 결정 (T-10-110, 2026-09-29)

- 판정: `endSeason`의 최종 순위(`rec.rank`)가 1위이고 K2 소속일 때 — 'K리그2 우승'과 같은 판정이라 재접속해도 변하지 않는다. 경기 중 순위표(`leagueTable`)와의 차이는 기존 동작 그대로 둔다.
- 소속: 세이브의 `leagueMoves`(구단 id → 지금 리그)만 두고 정적 `CLUBS`는 그대로. `clubsIn(id, s)`·`clubLeagueId(c, s)`가 순위표·경기 상대·이적 오퍼·재기 도전·대륙 대회 순위·세이브 로드 이름 갱신에 쓰인다.
- 교체 구단: K1에서 기본 전력(`str`)이 가장 낮은 구단(동률은 id 순). 상무는 `CLUBS` 밖이라 후보가 아니다.
- 승격 구단 전력(`str`)은 그대로 둔다. 자동 강등은 없다.
- 승격 첫해는 대륙 대회에 나가지 않는다(같은 구단인데 지난 시즌 리그가 다르면 건너뜀). 두 번째 시즌부터 지난 K1 순위로 판정.
- 기록: 승격은 트로피·영예·LS에 넣지 않는다. 결산 시트 승격 카드, 이적 시장 안내·잔류 설명, 로그 한 줄. 과거 기록 소급 없음.
- 서버·계약 변경 없음. 영구결번 점수는 구단 id의 정적 리그로 계속 센다(승격 뒤 K1 시즌이 K2 배수로 조금 낮게 잡힘).
- 세이브: 필드가 없으면 정적 소속. `SAVE_VERSION`은 그대로.
