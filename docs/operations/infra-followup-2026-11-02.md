## 도구 실행

Cloudflare 인증은 환경 변수 `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN`으로 전달한다.
자격 증명·원문 SQL을 명령 출력이나 보고서에 넣지 않는다.

```bash
node tooling/scripts/infra-health.mjs
node tooling/scripts/infra-health.mjs --resources
node tooling/scripts/r2-inventory.mjs --prefix d1/ --max-pages 20
node tooling/scripts/r2-inventory.mjs --prefix season-events/ --max-pages 5
```

Inventory는 GET만 사용한다. 완료한 prefix의 현재 payload만 합산하며 live pagination은 snapshot이 아니다.
R2는 마지막 짧은 페이지에서 `result_info`를 생략하기도 한다. 꽉 찬 페이지의 cursor/종료 정보가 없으면 실패한다.
보존 후보로 분류돼도 원장·참조·법정 보관 확인 없이 삭제하지 않는다. 기존 일일 30일/매월 1일 보존 정책을 유지한다.

다운로드한 조각은 `0001.sql`~`0055.sql` 순서로 둔다. Wrangler는 Content-Encoding을 풀어서 저장하므로
평문 SQL일 수 있고, S3로 받은 gzip도 도구가 자동 구별한다. 신뢰하는 자체 백업 SQL만 실행한다.

```bash
umask 077
python3 tooling/scripts/restore-backup.py \
  --source "$RESTORE_DIR" --destination "$RESTORE_DIR/new-local.sqlite" \
  --chunks 55 --tables 94 --rows 4968958
```

기존 목적지 파일·symlink는 거절한다. 누락 조각·SQL 오류·행 수 불일치·FK 위반은 실패한다.
출력은 집계만 포함하며 SQL 오류 원문은 노출하지 않는다. 입력과 복원 DB는 비공개 위치에 보관한다.

## 남은 운영 결정과 한계

1. DLQ 잔여 2건의 삭제는 현재 원장을 다시 대조한 뒤 해당 두 메시지에만 제한한다. 이번 PR은 삭제·재전송을 수행하지 않는다.
2. SQL 사본의 정합성을 보장하려면 별도의 일관 snapshot 설계 또는 격리된 Time Travel 복구 훈련이 필요하다. 이번 변경으로 기존 백업을 정상 판정하지 않는다.
3. Worker는 GitHub 예약 지연을 독립적으로 기록하지만 Slack 전달은 기존 GitHub workflow에 의존한다. GitHub 장애 중 즉시 외부 경보까지 보장하지 않는다. public API rate limit/접근 실패는 unknown 이슈로 남는다.
4. archive 전체 inventory·DB 참조 확인·월별 청구 확인 전에는 R2 삭제나 계정 비용 절감액을 확정하지 않는다.
5. 운영 배포와 새 시간별 보고서 read-back은 별도 단계다. 릴리즈 노트는 내부 진단·도구·동작 보존 refactor이므로 생략한다.
