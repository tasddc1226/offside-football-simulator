# T-11-063 시즌 1 개막 준비

## 개막 시각과 적용 대상

- 개막은 **2026-10-06 00:00 KST** (`2026-10-05T15:00:00.000Z`). `SERVICE_SEASONS`의 시각 판정으로 전환한다. 자정 재배포·Cron은 필요하지 않다.
- 새 선수의 세부 포지션·은퇴 상한은 클라이언트의 생성 확정 시각에 결정한다. 개막 전은 세부 포지션 없음·41세, 개막 이후는 세부 포지션 있음·45세다.
- 순위에 참가하는 서비스 시즌은 서버의 **첫 시즌 업로드 시각**에 고정한다. 재전송이나 개막 이후 은퇴로 바꾸지 않는다.
- 오프라인에서 만들고 개막 뒤 처음 업로드한 선수는 생성 규칙과 순위 소속 시즌이 다를 수 있다. 현재 참가 기준을 유지한다. 생성 시각 기준으로 변경하거나 옛 클라이언트의 참가를 제한하지 않는다.
- 기존 프리시즌 저장에 세부 포지션·45세를 덧붙이지 않는다. 저장 형식·마이그레이션·RNG·성장 계수는 변경하지 않는다.

## 이번 보완

개막 전에 생성 화면을 열고 후보를 고른 채 자정을 넘기면 세부 포지션 없이 45세 규칙만 받는 선수가 만들어질 수 있었다.

- 생성 확정 시각을 한 번 읽고 세부 포지션·은퇴 상한을 함께 결정한다.
- 개막 뒤 세부 포지션을 고르지 않았거나 큰 포지션과 맞지 않으면 기존 화면의 기본값 FW=ST, MF=AM, DF=CB, GK=GK를 쓴다. 유효한 선택은 유지한다.
- 웹·앱 생성 화면은 개막 경계에서 한 번 알림을 받아 다시 열지 않고도 선택지를 표시한다. 후보·주력·입력을 초기화하지 않는다. 화면을 닫으면 타이머를 해제한다. 서버 요청·주기적 폴링은 없다.

## 확정하지 않는 정책

추가 성장 튜닝과 영구결번 자격 기준은 미결이다. 개막 준비 지시를 이 수치의 승인으로 해석하지 않는다. 관리자 밸런스 활성화는 서비스 시즌 1 전용 예약이 아니며 진행 중 선수의 다음 게임 연도에도 적용되므로 새로운 값을 활성화하지 않는다.

개막 이후 일반 관리자 밸런스 활성화는 `SEASON_BALANCE_LOCKED`로 막힌다. 긴급 수정의 `override=season`은 기존 감사 로그가 남는 예외이며 이번에는 쓰지 않는다.

## 기존 앱 호환 경로

최신 main의 1.0.2 runtime으로만 OTA를 올리면 기존 1.0.0에는 전달되지 않는다. 1.0.0용은 옛 네이티브 구성을 유지한 호환 번들을 별도로 검증한다.

- iOS 1.0.0 build 3/4와 1.0.1 build 6: `9e9ebda2cb46d3a9ea51c3288f2bcdbd9b43bf29`.
- Android 1.0.0 build 3: `965907c7b123479e8f0829473ecca7859c14f1e8`.
- 호환 후보는 03f6ad9f의 mobile/native 설정·의존성을 유지하고 6518dc29의 공용 game/contracts/app-core와 이번 경계 수정을 쓴다. 기존 네이티브에 없는 image-picker/manipulator는 추가하지 않는다. runtime을 문자열로 강제 덮지 않고 실제 fingerprint가 위 빌드와 같은지 확인한다.
- 양 플랫폼의 호환 후보 fingerprint 일치와 모바일 타입 검사 통과를 확인했다. 최신 game을 사용하므로 조기 계약 연장도 포함한다. 신규 네이티브 기능을 쓰는 최신 앱 화면은 새 스토어 빌드에서 제공한다.
- iOS 1.0.1 build 5는 별도 runtime이다. 완성된 빌드를 스토어 출시로 취급하지 않는다.
- 최소 버전은 스토어에서 업데이트를 받을 수 있을 때까지 올리지 않는다. 심사 중에도 대응 OTA로 게임 개막을 준비할 수 있다.

## 10/5 최종 판단과 개막 확인

18:00 KST까지 추가 성장 조정을 채택할지 정한다. 근거가 약하면 이미 구현한 규칙으로 개막하고 계수를 더 올리지 않는다. 새 조정을 채택한다면 기존 프리시즌을 보호하는 적용 경계, 복수 seed, 저장 복원과 양 플랫폼을 다시 검증한다.

개막 당일에는 이전 저장 이어하기, 새 선수 생성, 첫 업로드와 시즌 표시를 소수의 QA 선수로 확인한다. 운영 집계는 필요한 기간·항목만 읽고 전체 선수에 대량 폴링하거나 무제한으로 다시 집계하지 않는다.
