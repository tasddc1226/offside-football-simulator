# 첫 커리어 독려와 성과 추적 (T-11-208)

선수를 만들고 아직 한 번도 은퇴시키지 않은 계정의 복귀를 돕는다. 보상·긴급성·손실을 암시하지 않는다.

## 대상과 피로도

- 업데이트된 웹·앱에서 생성/저장/복원/포그라운드 이벤트로 현재 커리어 ID, active/retired/none, 언어만 전송한다. 세이브 본문·선수명은 전송하지 않는다. 같은 상태는 30분에 한 번, 실패 후 5분 간격으로 합치며 폴링하지 않는다.
- 서버 기록과 활동 신호 모두 은퇴 이력이 없어야 한다. 활동 신호가 없는 옛 계정은 자동으로 새 캠페인에 편입하지 않는다.
- 앱 푸시를 켜 등록된 유효한 앱 세션·기기가 있어야 한다. 가장 최근 기기 하나에만 전송한다. 별도 독려 수신 설정은 없으며, 기기 알림 해제로 중단한다.
- 마지막 활동 3/7/14일 단계, 계정 생애 최대 3회, 시도 간격 최소 4일. 복귀·새 선수·재설치로 예산을 초기화하지 않는다. 지나간 단계는 건너뛴다. 30일 초과 미접속은 제외한다.
- KST 11시 이상 19시 미만만 발송한다. 최근 24시간에 다른 알림이 생성되었거나 최근 3일에 어느 기기든 활동·커리어 업로드가 있으면 제외한다.
- 발송 직전에 다시 검사한다. 돌아오거나 은퇴·삭제·로그아웃·알림 해제한 경우 취소한다. 예약 후 취소/실패도 단계 예산은 복구하지 않는다.
- 새 활동 신호가 있는 계정은 기존 일반 재방문 알림에서 제외한다. 옛 클라이언트는 기존 정책을 유지한다.

## 인프라와 장애 복구

`hourly cron → D1 원자적 대상 예약/알림/성과 코호트/배송 원장 → offside-career-push-production → Expo → APNs/FCM`

관리자 푸시와 별도 Queue/DLQ를 사용한다. 메시지는 무작위 batchId만 포함하고 토큰·프로필 ID·문구는 포함하지 않는다. 소비자 동시성 1, 최대 재시도 3회, 배치당 최대 100명. 기존 D1 claim/리스/영수증 회수/중복 방지 정책을 유지한다. Queue 게시 실패 시 5분 뒤부터 기존 5분 cron이 복구한다. Expo 접수 결과 불명은 중복 발송 대신 unknown으로 남긴다.

`CAREER_REMINDER_ENABLED=0`으로 새 예약과 전송을 중단한다. 재시작 후에도 지난 단계 몰아 보내기는 없다. 운영 최초 배포 전에 production Queue와 DLQ(각 보관 24시간)를 만들고, DB preflight 및 마이그레이션 후 Worker를 배포한다. 일반 5분 cron은 receipt 확인을 계속한다.

## 운영 도구

설정 → 운영 도구 → 앱 푸시 → **첫 커리어 독려**. 7/30/90일의 알림 생성일 코호트를 3/7/14일 단계별로 나눈다. 같은 API와 1분 캐시를 재사용하며 열 때만 읽는다.

| 지표                   | 뜻                                                                                |
| ---------------------- | --------------------------------------------------------------------------------- |
| 선정된 알림            | 해당 단계의 알림 건수. 단계 사이 같은 계정을 합쳐 고유 사용자라고 부르지 않는다   |
| 발송 접수              | Expo ticket 접수 알림                                                             |
| 전달 확인              | Expo receipt에서 APNs/FCM 접수 확인. 화면 표시 증거는 아님                        |
| 클릭                   | 업데이트된 앱에서 OS 알림 응답을 받은 알림, 알림별 1회                            |
| 7일 내 복귀            | 최신 접수된 독려 알림 후 7일 안에 서버가 active/retired 신호를 받은 알림          |
| 7일 내 첫 은퇴         | 위 기간에 retired 신호를 받은 알림. 클라이언트 신호이며 업로드 리포트 검증과 구분 |
| 진행 중/취소/실패/불명 | 기존 배송 원장의 상태                                                             |

복귀/은퇴는 인증된 계정의 최근 접수 알림 **하나에만** 귀속하고 최초 시각을 보존한다. 클릭 없는 자연 복귀도 포함한다. 알림 생성일은 코호트 기준, 성과는 조회 시점까지 갱신된다. 최근 발송은 7일 관측이 미완료다. 홀드아웃 비교가 없으므로 인과적 순증가/리텐션 향상으로 해석하지 않는다. 활동 보고 누락·오프라인·옛 앱은 미관측이며 0은 반드시 행동 없음이 아니다. 90일 알림 삭제와 함께 성과가 삭제되며 계정 삭제도 연쇄 삭제된다. 생애 단계 예산은 계정 존속 기간 유지한다.

## Firebase Analytics / GA4

기존 Firebase 네이티브 Analytics SDK와 동의 경계를 재사용한다. 지원 바이너리·플랫폼 설정·수집 활성화·사용자 분석 동의가 모두 있어야 전송된다. 운영 화면에서는 전송하지 않는다. 거부/미결정이면 수집하지 않고 이후 동의 시 과거 클릭을 재생하지 않는다.

- `offside_push_open`: 실제 OS 푸시 클릭. `push_category` 허용 목록만 전송한다.
- 독려 푸시에는 `push_campaign=career_reminder`, `reminder_stage=1|2|3`를 추가한다.
- 기존 `career_resume`, `screen_view`, `first_action_complete`, `career_progress_milestone`, `career_retire`로 이후 화면·플레이·은퇴 퍼널을 구성한다. `first_action_complete`는 생애 첫 행동 성격이므로 모든 복귀 플레이를 뜻하지 않는다.
- 알림 ID·프로필 ID·커리어 ID·토큰·제목·본문은 GA로 보내지 않는다. 클릭 중복 키는 기기에 최대 50개만 보관한다. 자동 `notification_open`과 합산하지 않는다.

GA4 관리 → 맞춤 정의에서 이벤트 범위 `push_category`, `push_campaign`, `reminder_stage`를 등록한다. 탐색 → 유입경로에서 `offside_push_open`(campaign 필터) → `career_resume` 또는 game 화면 → `career_retire`를 7일 범위로 비교하고 iOS/Android·단계로 분해한다. 은퇴 이벤트의 주요 이벤트 등록 여부는 기존 측정 정책에 맞춘다. 실제 DebugView/실시간 수집과 바이너리 설정을 별도 검증한 뒤 운영 지표로 사용한다. 이 변경만으로 GA 속성 설정/맞춤 보고서를 생성하지 않는다.

운영 도구는 계정/서버 기준, GA4는 동의한 설치/사용자 기준이라 수치가 일치하지 않는다. Expo를 통한 발송은 FCM 자동 캠페인 통계에 모두 잡힌다고 가정하지 않는다. 다른 분석 SDK나 푸시 공급자 추가 없이 현재 연결로 측정한다.

- [Firebase custom events](https://firebase.google.com/docs/analytics/ios/events)
- [Expo receipts](https://docs.expo.dev/push-notifications/faq/)
