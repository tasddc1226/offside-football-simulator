# PR 테스트 범위

웹 E2E 범위는 `.github/scripts/ci-web-e2e.mjs`에서 판정한다. 패키지별 린트·타입·단위 테스트,
API 테스트 3개 shard, 푸시 전달 테스트, 마이그레이션 검사는 기존 Turbo 영향 분석을 유지한다.
웹 빌드와 운영 번들 예산 검사도 생략하지 않는다.

| 변경 범위                                          | 웹 E2E                                           |
| -------------------------------------------------- | ------------------------------------------------ |
| 검토된 앱 푸시 운영 지표 파일만 변경               | 운영 화면 3개 spec + 계정 + 언어 전환, 1개 shard |
| 게임·저장·공통 UI·공통 API·설정·의존성·CI 변경     | 전체 3개 shard + 별도 동의 기반 분석 테스트      |
| 미등록 파일 또는 운영 지표와 다른 코드가 함께 변경 | 전체                                             |
| 변경 파일·Turbo·사전 index 판정 실패               | 전체                                             |
| 웹에 영향 없는 패키지 변경                         | 기존 정책대로 웹 검사 없음                       |

현재 축소 대상은 앱 푸시 운영 화면, 성과 조회 저장소/계약/표시 도우미, 관련 테스트,
`cupPush`·`retention` 한국어·영어·일본어 사전이다. 정확한 파일 목록이 코드의 기준이다.
운영 폴더 전체를 자동으로 신뢰하지 않는다. 공통 운영 라우터·권한·실제 발송 로직 변경은 전체 대상이다.
생성된 en/ja 사전 index는 해당 두 namespace의 정확한 import와 객체 항목만 추가/삭제한 경우에만
축소할 수 있다. 다른 한 줄이라도 바뀌면 전체로 돌아간다. Git diff는 rename을 삭제+추가로 보므로
이름 변경 전후 경로도 모두 분류한다.

축소 실행에서도 `admin-retention`, `admin-balance`, `admin-club-strength`, `account`, `locale`
spec을 실행한다. 푸시 운영 화면의 320/390px 검사와 계정·언어 기본 회귀 검사가 포함된다.
API 권한은 기존 API 테스트에서 확인한다. Playwright는 API를 mock하므로 실서버 통합 검증이나
앱 실기기 검증을 대신하지 않는다.

PR plan 로그와 job summary에서 `admin` / `full` / `none` 및 shard 수를 확인할 수 있다.
새 축소 대상을 추가할 때는 영향 경로, 연결된 spec, 혼합 변경의 전체 fallback 테스트를 함께 검토한다.
공통 코드에 영향이 있거나 불확실하면 목록에 추가하지 않는다.
수동 `Full Validation` 워크플로는 전체 검사를 계속 제공한다.
CI 정책 자체를 바꾸는 PR도 전체 검사를 실행한다. 이 정책 변경에는 운영 앱 배포가 필요하지 않다.
