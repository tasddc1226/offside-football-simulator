# 공개 소식 페이지

T-11-198. 기존 공개 페이지 CSS와 빌드된 HTML 셸을 Web Worker에서 사용한다.

- `/news/`: 공지·릴리즈 목록. 홈 푸터의 실제 링크로 진입한다.
- `/news/<postId>/`: 제목·설명·본문·canonical·OG 메타가 서버 HTML에 있는 글.
- 슬래시 없는 주소, `index.html`, 쿼리 변형은 정규 주소로 308 이동한다.
- 홈 글의 일반 클릭은 기존 게임 게시판을 열고, 새 탭·주소 복사는 공개 URL을 사용한다.
- 공개 글의 댓글 링크는 `/?news=<postId>&board=<board>`에서 게임 게시판을 연다. 이 주소는 noindex이고 새로고침해도 글을 다시 연다.
- 홈 소식 위젯은 기존 홈의 다른 부가 컴포넌트처럼 지연 로드한다. 공개 목록·가이드·FAQ·공정성 링크는 홈 서버 HTML에 남는다.

## 공개 데이터 경계

현재 `board_posts`에는 비공개·초안 상태가 없다. 관리자만 게시하는 `notice`와 `release`에서 `deleted_at IS NULL`인 한국어 원문만 공개한다. 작성자, 번역 초안, 댓글, 세션, 라운지, 개인 기록은 읽지 않는다. 추후 공개 상태 필드가 생기면 두 읽기 함수의 필터와 테스트를 함께 수정해야 한다.

목록은 기존 `(board, created_at)` 인덱스로 게시판별 최신 1,000건의 제목·ID·날짜만 읽는다. 본문이나 글별 추가 요청은 없다. 목록과 sitemap의 발견 범위도 이 상한을 따른다. 이전 글의 직접 URL은 계속 유효하다. 게시판이 1,000건을 넘기 전에 목록·sitemap 페이지 분할을 추가한다.

목록은 게시판별 두 캐시 키만 60초 보관하고, 기존 관리자 작성·수정·삭제 및 자동 릴리즈 게시가 해당 키를 비운다. 기존 `purgeEdge`는 데이터센터 단위이므로 다른 위치의 목록 제목은 최대 60초 남을 수 있다. **상세 본문은 캐시하지 않는다.** 삭제된 본문을 다른 위치의 캐시에서 계속 공개하지 않도록 공용 GET 캐시 원칙의 예외로 두며, PK 조회 하나만 수행한다. HTML에도 `no-store`를 사용한다.

본문은 기존 `parseBody` 규칙으로 제목·목록·문단을 나눈 뒤 모든 텍스트와 속성을 이스케이프한다. HTML·Markdown 링크·스크립트를 실행하지 않는다. API에 쿠키를 전달하지 않고 리디렉션은 실패로 처리한다. 잘못된/없는/삭제된 글은 실제 404, 일시적 API 실패는 503과 `Retry-After`를 반환한다.

검색은 기존 `seo-policy.json`의 공개 허용과 origin 일치가 모두 필요하다. sitemap은 정적 URL에 공개 목록·글 URL을 덧붙인다. API 장애를 빈 sitemap으로 오인하지 않도록 503으로 처리한다. 영어·일본어 별도 공개 페이지는 이 범위에 없다.

## 검증

- `apps/web/src/public-news.test.ts`: 실제 Worker 분기, canonical, 중복 URL, HEAD, 404/503, noindex, XSS, 요청 수.
- `apps/api/src/routes/boards.test.ts`: 공개 필드 허용 목록, 미등록 게시판·삭제 제외, 세션·댓글 조회 없음.
- `apps/web/e2e/public-news.spec.ts`: 실제 Worker 렌더러에 API/ASSETS 픽스처를 주입해 320px Chromium에서 직접 진입·새로고침·뒤로가기·중복 클릭·게임 게시판 연결을 확인한다. 운영 데이터는 사용하지 않는다.
- 기존 board/history/structure E2E, SEO 테스트, 웹 빌드·초기 번들 예산 검사도 함께 실행한다.
