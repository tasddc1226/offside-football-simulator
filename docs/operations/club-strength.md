# 일별 구단 전력표

고교·대학·K2·K3의 기본 전력은 고정한다. 나머지 K1·J1·MLS·에레디비시·리그1·분데스리가·세리에A·라리가·PL은 갱신 가능한 대상으로 제한한다. 계산식과 ±3/기본 대비 ±6 제한은 기존 것을 유지한다. 이 변경 자체는 강팀 편중 개선을 입증하지 않는다.

## 현재 준비 상태

**운영 수집은 기본 비활성**이다. 무료 football-data.org 계정 인증과 로컬 키 설정을 완료했고 유럽 6개 리그의 실제 자료로 로컬 연결을 검증했다. 웹·앱과 서버 연결, 일별 실행, 운영자 이력과 제공자 어댑터를 포함한다. 계정/키·현재 시즌 접근·명시적 구단 ID 대응표·사용 범위가 확인되기 전 운영 자동 수집을 켜지 않는다. 운영 배포도 별도이다.

무료 첫 후보는 football-data.org의 유럽 6개 리그(DED/FL1/BL1/SA/PD/PL)다. K1/J1/MLS는 이 무료 범위에 없다. API-Football 어댑터도 준비하지만 요금 가입이나 권한 확보를 대신하지 않는다. J1 특수 시즌/승부차기 승점, 승점 삭감, 분리 리그는 현재 검사를 통과하는 자료인지 먼저 검토한다. 경기 중인 순위표 때문에 전체 득실 합이 맞지 않으면 그날은 갱신을 보류한다.

## 실행과 저장

- 기존 5분 cron에서 KST 13시 이후 하루 한 번 실행한다. 실행 간격은 5분이지만 외부 호출·전력 발행은 하루 한 번이다. UTC 정각 일치를 요구하지 않는다.
- D1 `app_meta`의 PK 인덱스를 재사용한다(새 테이블/마이그레이션 없음).
- `club-strength:run:YYYY-MM-DD`: 일별 처리 이력. 변경·동일·실패·미설정, 리그별 변경 전후 수치와 현실 시즌을 기록한다. 30개씩 날짜 커서로 조회한다.
- `club-strength:version:N`: 발행한 불변 전체 전력표. `club-strength:current`: 현재 표와 원자료 해시, 마지막 처리일. 현재표/이력/버전은 하나의 D1 batch로 기록한다.
- 임대 잠금으로 중복 실행을 막고 만료 뒤 늦게 끝난 실행의 쓰기를 차단한다. 이미 처리된 날/더 오래된 cron 호출은 무시한다. 실패/미설정 처리도 이력으로 남기며, 설정 수정 후에는 다음 날 실행부터 반영된다.
- 원자료(정렬한 팀별 성적·현실 시즌·명시적 대응표)가 같으면 다시 계산하지 않는다. 경기 없는 날 반복 계산으로 ±3씩 움직이는 현상을 막는다.
- 리그별로 검증한다. 한 리그 실패가 다른 리그의 정상 갱신을 막지 않는다. 실패한 리그는 기존 전력을 보존한다. 이전 시즌 자료나 같은 시즌의 경기 수 감소는 오래된 자료로 판단해 거절한다. 아직 현실 자료에 없는 게임 구단은 이전 값을 유지한다.
- 공개 GET `/v1/club-strength`에는 전력표만 포함한다. 세션을 조회하지 않고 60초 엣지 캐시, 발행 시 canonical API origin의 캐시를 무효화한다. 다른 데이터센터에는 최대 TTL만큼 지연될 수 있다.
- 웹·앱은 열기/포그라운드 복귀 때 1시간 메모를 거쳐 받는다. 커리어는 다음 가상 시즌 시작 때만 더 높은 버전을 채택한다. 오프라인이어도 저장된 더 높은 버전을 기본 v1로 되돌리지 않는다.
- `GameState.cs`의 기존 `{v,values}`를 그대로 쓴다. 새 저장 필드를 추가하지 않는다. 기본 표 v1과 시드 RNG·계산식은 그대로다.

## 운영자만 보는 이력

설정 → 운영 도구 → 구단 전력. `/v1/admin/club-strength`는 기존 검증된 Google 관리자 인증에 더해 `CLUB_STRENGTH_OWNER_EMAIL` 한 계정만 허용한다. 이 설정이 없고 `ADMIN_EMAILS`가 한 명이면 그 한 명을 사용한다. 여러 명이고 소유자를 지정하지 않으면 접근을 거절한다. 응답은 `private, no-store`, 클라이언트는 1분 메모한다. 조회할 때만 요청하고 폴링하지 않는다. 공개 사용자는 이력이나 제공자 정보·키를 받지 않는다.

## 무료 연결 준비

1. 사용자가 football-data.org 계정을 만들고 현재 6개 리그의 순위표·팀 목록 접근과 데이터 이용 조건을 확인한다. 키를 소스/채팅/명령행 인수에 넣지 않는다.
2. 로컬 환경변수 `FOOTBALL_DATA_TOKEN` 설정 후 `node tooling/scripts/prepare-club-strength.mjs /tmp/club-strength-source-review.json`. 팀 목록만 읽어 검토용 템플릿을 만든다. 전력 발행·운영 변경은 없다.
3. 제공자 team ID를 `packages/contracts/src/club-names.ts`의 게임 club ID와 사람이 연결한다. 이름 유사도/현재 순위로 자동 연결하지 않는다. 현실 승강이 있어도 기존 저장 ID를 바꾸지 않는다. 게임에 없는 새 현실 팀은 검토 후 명시적으로 exclude에 둔다. 기존 게임 구단의 대응 ID는 모두 있어야 한다. 자료에서 빠진 기존 구단은 이전 전력을 유지한다.
4. 템플릿의 `review` 필드를 제거하고 SourceSchema 검사(league/provider/competition/teams/exclude)로 검토한다. 확정 JSON 배열을 `CLUB_STRENGTH_SOURCES`로 설정한다. API-Football을 쓰면 provider=`api-football`, competition=숫자 리그 ID, season=명시적 연도와 `API_FOOTBALL_KEY`가 필요하다. 시즌 전환 때 연도 설정도 검토한다.
5. 격리 로컬/staging에서 실제 자료 수집과 구단별 변화·미대응·잔존 구단·무료 quota를 검증한다. API 키는 서버 secret으로만 설정한다. GitHub Actions나 클라이언트에는 넣지 않는다.
6. 검토·배포 이후 `CLUB_STRENGTH_ENABLED=1`을 운영에 명시적으로 설정한다. 기본은 off다. 무료 계정 인증과 로컬 키 연결은 완료했다. 과금·운영 배포·운영 설정 활성화는 별도이다.

중단은 `CLUB_STRENGTH_ENABLED`를 0으로 설정한다. 마지막 정상 표와 이력은 유지한다. 과거 불변 버전을 덮어서 롤백하지 않는다. 값 복원이 필요하면 더 높은 새 버전으로 발행하는 관리 절차를 별도 추가한다(이번에는 수동 쓰기/롤백 API 없음).

## 검증 경계

합성 자료로 일별 중복·동시 실행·오류·인증·다음 시즌 채택·화면을 검증한다. 실제 외부 API를 사용한 수동 로컬 검증은 아래에 기록했다. 운영 cron 실행과 실제 iOS·Android UI 검증은 별도 증거가 필요하다. 기본 v1을 쓰는 고정 시드 결과는 그대로여야 한다. 실제 전력표를 적용한 분포 검증은 아래에 기록했다. 신규 영결 구단 편중 비교는 배포 이후 별도로 확인한다.

## 무료 서비스 조사 (2026-10-10, Ego 브라우저)

- [football-data.org 요금](https://www.football-data.org/pricing): 무료 €0/월, 분당 10회, 순위표 포함. [커버리지](https://www.football-data.org/coverage)의 무료 목록에 DED/FL1/BL1/SA/PD/PL 6개가 모두 있다. K1/J1/MLS는 무료 목록에 없다. 요금 페이지에 일별 한도는 표시되지 않으므로 무제한으로 단정하지 않는다.
- 정기 수집은 유럽 6개에 하루 6회(30일 기준 180회). 이용자 수와 무관한 서버 일괄 수집이다. 초기 팀 목록 6회와 순위표 6회를 같은 1분에 연이어 실행하면 10회 한도를 넘으므로 실행 간격/남은 한도를 확인한다. 429가 발생하면 그 리그는 마지막 정상 값을 유지하고 재시도 폭주를 하지 않는다.
- [가입 화면](https://www.football-data.org/client/register)의 약관: 키는 웹·모바일을 포함한 하나의 앱에 사용하며 비공개로 보관한다. 화면에 `Football data provided by the Football-Data.org API` 출처 표기가 필요하다. 웹·앱의 홈/설정 푸터에 출처를 추가했다. 로고·사진 사용 권리는 별도이며 이번 연결은 순위표 숫자만 요청한다.
- 가입 필수 정보는 이름·이메일·약관 동의다. 사용자가 가입 후 전달한 발급 메일을 확인해 인증 링크를 처리했고, 계정 Free/Forever와 실제 HTTP 200 접근을 확인했다.
- [API-Football 요금](https://www.api-football.com/pricing): 무료 $0/월, 100회/일, 카드 불필요, 모든 대회/엔드포인트를 포함하지만 이용 가능한 시즌은 제한된다. 한도 소진 시 요청이 오류로 중단되며 초과 과금하지 않는다고 안내한다. K1/J1/MLS의 **현재 시즌 순위표 권한은 미확인**이다. 무료 가입만으로 현재 시즌이 가능하다고 단정하지 않는다.
- [API-Football 약관](https://www.api-football.com/terms)은 원자료 재판매를 금지하고, 제3자 데이터의 게시/상업 이용 권한을 제공하지 않는다고 명시한다. 무료 쿼터를 늘리기 위한 복수 계정도 금지한다. 현재 시즌 접근과 OFFSIDE에서 필요한 사용 범위가 확인되기 전 이 제공자로 운영 자동 수집을 활성화하지 않는다.

## 실제 로컬 연결 증거 (2026-10-10)

- 키는 격리 워크트리의 Git 제외 파일 `apps/api/.dev.vars`(0600)에만 저장했다. 저장소·클라이언트·문서에는 키를 포함하지 않는다. 2026-10-10 운영 배포 승인 후 Worker secret에 토큰·유럽 6개 대응표·단일 소유자·활성화 플래그를 설정했다. 키는 GitHub Actions secret이나 클라이언트에 넣지 않았다. 운영 코드 배포와 자연 cron 실행은 아래 로컬 증거와 별도로 검증한다.
- [검토한 대응표](../../tooling/fulltime-sim/club-strength/football-data-sources.json)는 2025 참가 팀 API의 영문 구단 정체와 기존 게임 별칭을 대조해 명시적으로 작성했다. 6개 리그의 기존 114개 club ID를 모두 보존한다. 현재 2026 순위표에 없는 17개 기존 팀은 이전 전력 유지, 새로 등장한 현실 17개 팀은 명시적 exclude다. 배열 순서/게임 팀 이름 변경은 없다.
- 유럽 6개 현재 시즌 순위표 GET이 모두 200이며 TOTAL 표·경기수/WDL/승점/득실 검사를 통과했다. 응답 `x-requests-available-minute`, `x-requestcounter-reset`을 확인했다. 초기 팀 목록 수집 중 남은 호출이 0이 된 때 기다린 뒤 다음 요청이 200으로 성공했다. 일별 수집과 준비 도구에도 헤더 기반 대기를 반영했다.
- 실제 제공자 요청 6회를 일별 처리 함수에 연결해 격리 Miniflare D1에서 v20738과 82개 팀 변경 이력을 생성했다(에레디비시13/리그1 11/분데스리가13/세리에A16/라리가13/PL16). 모두 기존 ±3/기본 ±6 제한을 적용했다. 같은 날짜 재호출은 수집 없이 종료했다.
- 로컬 검증은 수동으로 지정한 `2026-10-10T13:00 KST` 스케줄 시각을 사용했다. 자연 cron 실행 증거가 아니다. 공개 조회200, 로컬 테스트 소유자 조회200, 익명 이력 조회401을 확인했다. 로컬 웹은 실제 Hono 조회 경로와 위 D1에 연결했으며 인증 신원은 로컬 테스트 관리자다.
- K1/J1/MLS는 미설정이고 현재 기존값을 유지한다. 운영 배포·운영 자동 수집·실제 모바일 기기 검증은 아직 하지 않았다.

### 배포 전 회귀 검증 (2026-10-10)

- 동일 시드 1010, smart 정책으로 기존 기본 전력과 실제 수집 v20738을 각각 1,000커리어 실행·분석했다. 양쪽 모두 오류 0이며 성장·출전·리그 진출의 전체 분포를 검토했다. 결과는 로컬 `tooling/fulltime-sim/results/daily-strength-{baseline,live}-1010`에 있으며 기본 패리티 기준선을 바꾸지 않았다.
- 이 러너는 영구결번의 구단별 집중도를 집계하지 않는다. 영결 편중 개선 증거로 해석하지 않는다.
- 첫 화면 요청 기준선은 신규 공개 전력 GET 1회를 포함하도록 갱신한다. 게임 탭 이동에서 추가 요청이 없다는 검사는 유지한다.
