# 앱 푸시 발송·클릭 성과 (2026-10-05 작업본, 운영 미배포)

운영자 계정에서 **구단주 → 운영 도구 → 앱 푸시**를 연다. 웹 Svelte와 iOS/Android
React Native에 같은 집계를 제공한다. 최근 7/30/90일(KST), 테스트 푸시 포함·제외,
종류별 결과, 일별 추이와 발송별 목록을 제공한다. 목록은 20개씩 불러오며 최초 조회의
생성 시각 상한을 유지해 조회 중 새 발송이 생겨도 페이지가 밀리지 않는다.

## 지표의 의미

| 지표                 | 기준                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 발송 대상 기기       | 큐에 등록된 기기별 발송 기록. 수신 설정으로 큐에 들어오지 않은 알림함 원본은 제외        |
| 발송 접수            | Expo ticket 접수된 기기 수. 이후 실패·토큰 정리에도 접수 사실은 유지                     |
| 전달 확인            | Expo receipt `ok`인 기기 수. APNs/FCM 접수 확인이며 OS 표시·사용자 열람 증거는 아님      |
| 진행 중              | pending/sending/accepted/checking인 기기 수                                              |
| 실패·결과 불명·취소  | 현재 결과 상태별 기기 수. 접수와 상태별 수치는 중복될 수 있음                            |
| 접수된 알림          | 한 알림을 여러 기기로 보내도 프로필별 알림 하나로 계산                                   |
| 클릭한 알림 / 클릭률 | 기본 OS 알림 응답이 보고된 접수 알림 / 접수된 알림. 같은 알림의 재클릭·여러 기기는 한 번 |
| 연결 화면 이동       | 해당 푸시 클릭 뒤 24시간 안에 알림 상세의 이동 버튼을 누른 알림 수                       |

연결 화면 이동은 탐색 성과이며 실제 시즌 진행·구매·재참여 유지율로 해석하지 않는다.
알림함 상세 조회·읽음·모두 읽음과 앱의 일반 실행·포그라운드 푸시 수신은 클릭이 아니다.
종료된 앱을 푸시로 열 때와 실행 중 OS 알림을 누를 때 모두 기록한다. 오래된 앱과
추적 시작 전 발송의 클릭은 소급해서 만들지 않는다. 결과 불명 상태에서 클릭 보고가
있어도 접수 사실이 확인되기 전에는 접수 기준 클릭률에 넣지 않는다.

## 저장과 권한

- `0065_push_preferences_results.sql`은 토큰·세션 원문이 없는 결과와 클릭 기록, 집계용 시각 인덱스를
  만든다. `0066_push_result_triggers.sql`은 Drizzle custom migration으로 등록한 큐 트리거다.
  큐 insert/update/delete와 같은 트랜잭션에서 결과를 남겨 발송 경로의 누락을 막는다.
  결과 키는 내부 큐 식별자이며 기기 설치 해시가 포함될 수 있지만 운영 응답에는 노출하지 않는다.
- 기기 해제는 큐의 토큰 사본을 그대로 지운다. 발송 중 해제된 큐의 뒤늦은 응답은 결과만
  갱신하며 기기·큐를 복원하지 않는다. 접수 후 영수증 확인이 끊긴 기록은 결과 불명으로 표시한다.
- 수동 테스트도 큐에 발송 중 상태를 먼저 기록하고 직접 본인 기기로 한 번 보낸다. 기존
  개인 푸시 작업이 ticket 영수증만 확인한다. 수동 테스트를 자동 재발송하지 않는다.
- `/v1/notifications/:id/interaction`은 앱 Bearer 세션·본인 알림·실제 발송 기록만 허용한다.
  클릭은 PK로 중복을 막고 이동은 첫 클릭 후 24시간으로 제한한다. 시각은 서버 시각 또는
  최근 24시간/미래 5분 이내의 앱 시각을 사용하며 미래 시각은 서버 시각으로 보정한다.
- 네이티브 보고 버퍼는 24시간/50개로 제한한다. 오프라인 보고는 다음 앱 활성화에 다시
  시도한다. 세션 토큰은 저장하지 않고 SHA-256 연결값을 쓰며 계정 전환 시 버퍼를 지운다.
  클릭을 이동보다 먼저 전송하고 실패해도 화면 이동을 막지 않는다. 백그라운드 폴링은 없다.
- 운영 집계는 `requireAdmin` 후 `private, no-store`로만 제공한다. 클라이언트는 요청을
  1분 재사용하고 수동 새로고침에서만 캐시를 비운다. 클릭 쓰기는 다른 조회 캐시를 비우지 않는다.
- 이 기록은 서비스의 자체 운영 기록이며 Google Analytics/Firebase로 전송하지 않는다.
  기존 선택적 Google Analytics 동의·거절 처리는 변경하지 않는다. 설정과 개인정보 안내에
  보관 내용을 설명한다. 결과·상호작용은 알림함의 90일 만료와 계정 삭제 시 FK로 함께 지워진다.
- 기존 큐의 남은 상태만 마이그레이션 때 복사한다. 초기 기록의 시각은 큐의 마지막 갱신
  시각이며 완전한 과거 발송·클릭 이력을 뜻하지 않는다. 화면에 추적 시작 시각을 표시한다.

## 로컬 확인과 운영 반영

격리 환경 API 8808의 로컬 D1에 0065/0066을 적용했다. 실제 사용자에게 발송하지 않았다.
웹 검증용 별도 QA 프로필에 예시 발송 결과를 넣었으며 예시 수치는 운영 성과가 아니다.

서버 테스트에서 개인·공지·수동 테스트의 결과 보존과 영수증, 발송 중 기기 해제,
다중 기기 클릭 중복, 소유권·관리자 권한, 읽음/이동만의 오집계 방지, 24시간 귀속,
KST 기간·테스트 필터·안정적인 페이지 조회를 확인했다. 모바일 테스트에서 OS 기본 응답,
종료 상태 실행, 오프라인 버퍼·계정 전환·캐시 보존을 확인했다.

웹 320/390px에서 기간·테스트 필터, 상세 펼침·더 보기와 가로 넘침을 확인했다.
최신 main 통합 뒤 iOS 화면 제어 연결이 복구되어 시즌 1 홈·알림함·종류별 설정을
다시 확인했다. 개발 바이너리의 알림 Keychain 오류로 실제 APNs/FCM 수신·클릭은
검증하지 못했으며 네이티브 운영 집계 화면과 Android 화면 확인은 남아 있다.

운영 반영에는 운영 0064 다음의 0065/0066 DB 마이그레이션, API·웹 배포와 호환 앱의 JS 업데이트가
필요하다. 네이티브 설정·버전·EAS 런타임은 변경하지 않았다. 배포와 실제 기기 수신·클릭
검증은 별도 단계이며 이번 작업은 운영 미배포 상태다.

## 시즌 1 배포 통합 (2026-10-06)

최신 main의 `0064_owner_achievements_team_kept.sql`과 해당 스냅샷은 그대로 보존한다.
미배포 푸시 테이블은 `0065_push_preferences_results.sql`로 다시 생성하고,
`0066_push_result_triggers.sql`을 이어 적용한다. 배포 기대 테이블은 40개다.
기존 격리 로컬 DB에는 이전 작업의 푸시 테이블이 이미 있으므로 운영 마이그레이션의
검증 근거는 빈 D1에 전체 파일을 적용하는 테스트와 운영 preflight로 삼는다.

개막 뒤 경기 상세의 내부 `synergy` 배열이 공개 응답에 섞여 엄격한 응답 계약에서
503이 나는 기존 main 문제를 고쳤다. 시너지 계산과 저장 상세는 보존하며 `toMatch`가
공개 계약 필드만 선택한다. 시즌 1 랭크 경기·최근 기록·동일 요청 재전송과
프리시즌/시즌 1 친선전 회귀를 확인한다. 모바일 푸시 41개 테스트는 PR 및 수동 전체
검증 workflow에 연결해 운영 배포 전 필수 검증에 포함한다.
