# 화면 문구 다국어 (T-11-102)

웹·앱 화면 문구를 한국어·영어로 낸다. 1단계는 **화면 문구(UI)** 만 옮긴다. 이벤트·스토리·로그·기록 문장처럼
게임이 만들어 세이브에 문장째 저장하는 내용은 2단계에서 "키+값 저장"으로 바꾼 뒤 옮긴다.

## 구조

- 코어: `packages/app-core/src/i18n/core.ts` — `ns()` · `setLocale()` · `resolveLocale()` · `AUTO_DETECT`.
- 한국어 원문: `packages/app-core/src/i18n/ko/<네임스페이스>.ts`. 쓰는 화면이 그 파일을 import하므로 문구는 지금처럼
  그 화면의 청크에 남는다(웹 첫 화면 예산).
- 영어: `packages/app-core/src/i18n/en/<네임스페이스>.ts`(`Translation<…Msgs>` 타입이라 키가 빠지면 타입 오류),
  `en/index.ts`가 묶는다(직접 고치지 않고 `pnpm --filter @offside/app-core i18n:index`로 만든다). 웹은 영어 사용자에게만 지연 청크로 받고, 앱은 번들에 함께 넣는다.
- 언어 정하기: 설정 → 언어. 저장 키 `ft_lang`. 고른 값이 없으면 기기 언어(첫 언어가 한국어가 아니면 영어,
  `AUTO_DETECT`, 2단계에서 켰다). e2e는 한국어 브라우저(`playwright.config.ts` `locale: 'ko-KR'`)로 돈다.
- 언어를 바꾸면 웹은 새로고침, 앱은 루트를 다시 그린다(`_layout`의 `key`). 문구에 반응성은 없다.
- 검사: `packages/app-core/src/i18n/i18n.test.ts` — 네임스페이스마다 영어 사전이 있고 키·값 종류가 같으며 영어에
  한글이 남지 않았는지, `en/index.ts`가 생성 결과와 같은지.
- 영어 복수형·서수는 `en/_util.ts`의 `plural(n, 'match', 'matches')`·`ordinal(n)`을 쓴다.

## 쓰는 법

```ts
// packages/app-core/src/i18n/ko/home.ts
import { ns } from '../core';
const ko = {
  title: '홈',
  seasons: (p: { n: number }) => `${p.n}시즌`,
};
export type HomeMsgs = typeof ko;
export const homeText = ns('home', ko);

// packages/app-core/src/i18n/en/home.ts
import type { Translation } from '../core';
import type { HomeMsgs } from '../ko/home';
export const home: Translation<HomeMsgs> = {
  title: 'Home',
  seasons: (p) => `${p.n} season${p.n === 1 ? '' : 's'}`,
};
```

화면에서는 `import { homeText as L } from '@offside/app-core/i18n/ko/home'` 뒤 `{L.title}`, `L.seasons({ n })`.

## 옮길 때 규칙

1. **한국어 결과는 한 글자도 바꾸지 않는다.** 공백·줄바꿈·문장부호까지 그대로다. e2e·단위 테스트가 한국어
   문구로 화면을 찾는다. 문장을 고치고 싶어도 이 작업에서는 고치지 않는다.
2. **모듈 최상위에서 문구를 읽어 상수로 굳히지 않는다.** `const TABS = [{ label: L.home }]`처럼 import 때 평가되는
   자리는 함수(`const tabs = () => [...]`)로 바꾸거나 그릴 때 읽는다. 언어 등록 전에 평가되면 영어가 안 나온다.
3. 숫자·이름이 끼는 문장은 문자열을 이어 붙이지 말고 함수 문구 하나로 둔다(어순이 언어마다 다르다). 조사
   (`을/를` 등) 처리는 한국어 함수 안에 둔다.
4. 웹·앱이 같은 문구면 키 하나를 함께 쓴다. 다르면 `…Web` / `…App` 접미사로 나눈다(원문을 맞추지 않는다).
5. 옮기지 않는 것: 주석, `data-*`·`testID`·분석 이벤트 이름·URL·저장 키, 운영 도구(admin) 화면, 게임이 만든 문구
   (`packages/game`의 이벤트·로그·능력치·포지션·구단·리그·국가 이름), 서버(API)가 보내는 문장, 금액·날짜 서식(2단계).
6. HTML이 섞인 문장(`<b>`, `<kbd>` 등)은 앞·뒤 조각으로 나누거나 함수가 조각을 돌려주게 한다. `{@html}`을 새로
   쓰지 않는다.
7. 네임스페이스 이름(`ns('…')`)은 앱 전체에서 하나뿐이다. 파일 이름 = 네임스페이스 이름 = `en/index.ts`의 키.
8. **웹 첫 화면 청크를 지킨다.** 네임스페이스는 파일 단위로 청크에 들어간다. 첫 화면에 실리는 모듈(홈·명예의 전당
   미리보기·시트 틀·`boardText`·`api/chat` 등)이 큰 네임스페이스의 키 몇 개만 쓰면 그 화면 문구 전체가 첫 화면에 실린다.
   그때는 첫 화면이 쓰는 키만 작은 네임스페이스로 나눈다(예: `board` ↔ `boardLabel`, `sheetPlay` ↔ `sheetCore`,
   `shell` ↔ `shellMore`). `pnpm --filter @offside/web check:bundle`이 첫 화면 청크에 실린 네임스페이스를
   허용 목록(`EAGER_NAMESPACES`)과 비교해 새로 끼면 실패한다.

## 영어 문체

- 짧고 담백하게. 버튼·제목은 첫 글자만 대문자(sentence case): "Start a new career", "Hall of Fame"(고유명은 예외).
- 2인칭 "you". 느낌표는 한국어에 있을 때만.
- 축구 용어는 영국식: match, pitch, kit, fixture, transfer window, manager, season, league table, clean sheet.
- 한국 고유 제도(병역 등)는 풀어 쓴다: "military service".
- "OFFSIDE", 화면 위 영어 눈썹 글자(Settings·Display 등)는 원래 영어라 그대로 둔다.

## 2단계: 게임 문구 (T-11-106)

게임 엔진(`packages/game`)이 만드는 문구도 옮긴다. 코어는 엔진도 쓰도록 `@offside/contracts/i18n`에 있고
(`app-core/i18n/core.ts`는 다시 내보내기만 한다), 엔진의 사전은 `packages/game/src/i18n/`에 있다. 영어 묶음
(`en/index.ts`)은 두 패키지 모두 `node tooling/scripts/i18n-index.mjs`로 만들고, 화면 묶음이 게임 묶음을 함께 싣는다.

1. **저장값은 한국어 그대로 둔다.** 트로피·수상·마일스톤·구단·리그·대회·단계·스토리 이름·엔딩·역할(`주전` 등)처럼
   세이브나 서버에 남거나 코드가 비교하는 문자열은 식별자다(영구결번·업적·칭호·최초 기록이 이 문자열로 판정한다).
   바꾸지 않고, 화면에 그릴 때 `tn()`(`@offside/game/i18n/names`)으로 옮긴다. 영어 대응은 `i18n/en/_names.ts`
   (정확한 이름 → 없으면 `X 우승` 같은 패턴). 그래서 세이브 마이그레이션도, 서버 데이터 변경도 없다.
2. **새로 만드는 문장은 그 시점의 언어로 만든다.** 로그(`log()`), 이적 시장 안내·선택지 설명, 시즌 결산 문장은
   엔진 네임스페이스(`packages/game/src/i18n/ko/<이름>.ts` ↔ `en/<이름>.ts`)에서 읽는다. 로그는 쓴 시점의 언어로
   남는다(언어를 바꿔도 지난 로그는 그대로). 로그는 서버에 올라가지 않는다.
3. **이벤트**는 정의(`events.ts` 등)를 고치지 않고 `i18n/en/events-*.ts`에 id별 영어 문구(`EventText`)를 둔다.
   `eventById()`가 지금 언어의 문구를 입혀 돌려준다(조건·확률·효과는 원래 정의 그대로).
4. **문구 함수는 난수를 쓰지 않는다.** 같은 시드면 한국어·영어 결과가 문구 말고는 같아야 한다
   (`packages/game/src/i18n/i18n.test.ts`). 한국어 결과는 한 글자도 바꾸지 않는다(결정성 골든).
5. **만든 문장을 다시 읽어 판단하지 않는다**(`log.text.includes('부상')` 같은 것). 종류(`kind`)·플래그를 쓴다.
6. 숫자·날짜 서식은 `intlLocale()`(`ko-KR` / `en-US`)을 쓴다. 금액은 원화 그대로다.
7. 운영 도구(admin)는 운영자가 한국어를 쓰므로 옮기지 않는다.
8. 게임이 지은 한국 이름(무작위 선수 이름·라이벌)은 `personName()`이 로마자로 보여 준다(`i18n/en/_roman.ts`).
9. **서버 문장**: 웹·앱 API 클라이언트(`app-core/api/client.ts` `withLang`)가 영어일 때만 `lang=en`을 붙이고,
   서버는 `apps/api/src/lang.ts` `reqLang(c)`로 오류·업적·서버 최초 기록·배지·알림함 문장을 영어로 돌려준다. 판정은 한국어
   그대로 하고 응답을 만들 때만 옮긴다. 엣지 캐시하는 응답에 언어별 문장이 있으면 캐시 키에 `lang=en`을 넣는다.
   공지·릴리즈 노트 푸시는 기기 언어를 저장하지 않아 한국어다.
10. 첫 화면 청크 감시(`check:bundle` `EAGER_NAMESPACES`)는 게임 엔진 네임스페이스도 본다.
