# 명예의 벽 칭호

T-11-115. 영구결번 후보 자격을 충족한 공개 은퇴 선수에게 후보 구단의 번호가 모두 이미 결번인 경우 부여한다. 영구결번 자리를 차지하지 않으며 인기·경기·성장·레전드 점수·카드 가치·구단 가치 보상은 없다. 대표 칭호를 자동 변경하지 않는다.

## 저장과 확인

- `careers.wall_of_honor_json`은 서버 전용이며 후보 구단·번호·부여 시각을 기록한다. 은퇴 PUT과 소유자 결번 확인 GET에서 판정한다. 후보 번호 확보 시도와 칭호 기록은 D1 batch로 묶는다. 재시도는 기존 기록을 반환하며 최초 시각을 보존한다.
- 칭호 `wall_of_honor`는 레지스트리에 있지만 게임의 칭호 판정은 부여하지 않는다. 클라이언트 스냅샷의 같은 id는 최초·후속 업로드와 공개 응답에서 제거한다. 서버 기록이 있을 때만 공개 스냅샷의 받은 칭호와 대표 칭호 선택에 허용한다.
- 번호 보유자 삭제 등으로 자리가 비어도 이미 부여한 칭호를 지우거나 결번으로 바꾸지 않는다. 익명 전환도 획득 사실을 지우지 않는다. 숨김 커리어는 공개 응답·신규 판정에서 제외한다.
- 로컬 백업의 칭호·심사 결과는 증거가 아니다. 백업 병합에서 가져온 증거를 버리고 상세를 열 때 소유자 API로 다시 확인한다. 같은 화면 재진입은 1분 요청 메모를 사용하고 은퇴 PUT 성공은 메모를 무효화한다. 소유자 확인·은퇴 응답에서 서버의 대표 칭호 선택도 복구한다. 서버 상세와 로컬 은퇴 기록이 겹칠 때 서버 칭호·대표 칭호를 우선한다.

## 기존 커리어 적용 한계

과거 `taken` 응답은 저장되지 않았다. 당시 결과 전체를 복원할 수 없으며 `rn:taken`과 `snapshot.titles`로 추정하지 않는다. 기존 선수는 상세 확인 또는 은퇴 재업로드 시 다음 증거를 모두 확인할 수 있을 때만 기록한다.

1. 커리어의 저장된 `service_season` 기준 `rnCut`과 은퇴 나이 기준을 충족한다. 현재 시즌의 기준을 프리시즌에 소급하지 않는다.
2. 서버에 은퇴 시점까지 도착한 시즌 기록으로 동일한 후보 구단 집합을 재현할 수 있다. 늦게 추가된 시즌이나 현재의 구단 이름 변경만으로 자격을 복원하지 않는다.
3. 같은 서비스 시즌의 모든 후보 구단·번호에 `granted_at <= retired_at`인 선점 기록이 있다. 하나라도 비었거나 은퇴 후에 점유됐으면 과거 명예의 벽으로 기록하지 않는다.
4. 이미 영구결번을 보유한 선수·익명·숨김·미달·짧은 커리어에는 새로 부여하지 않는다.

이 조건은 보수적인 증거 범위다. 삭제된 보유자, 누락된 시즌·번호, 옛 커스텀 이름처럼 당시 상태를 재현할 수 없는 기록은 제외한다. 모든 프리시즌 대상의 복원을 보장하지 않는다. 기존 영구결번 로직은 빈 후보 번호를 발견하면 해당 번호를 부여하므로 칭호와 구분한다.

## 이관과 검토 계획

Drizzle 생성 마이그레이션은 nullable 열 하나를 추가하며 기존 행은 NULL로 남긴다. 전체 칭호 백필을 자동으로 돌리는 마이그레이션·배치·공개 GET은 없다. 구버전 업로드는 서버 기록을 삭제할 수 없고, 은퇴 당시 번호가 없는 기록은 늦은 스냅샷으로 번호를 만들어 판정하지 않는다. 상세 복원은 가능하지만 결번·칭호 심사 근거로 쓰지 않는다. 새 필드를 모르는 기존 앱은 업데이트 후 받은 칭호 목록을 확인할 수 있다.

운영 DB 읽기·쓰기 또는 실제 백필은 이 작업에서 수행하지 않았다. 일괄 복원이 필요하면 별도 승인 후 먼저 오프라인 복사본에서 dry-run을 검토한다: 서비스 시즌별 검사 수·안전 판정 수·제외 사유 수를 집계하고, 후보 집합과 각 선점 시각을 대조한다. 개인정보 없이 집계를 검토하고 변경될 행 수와 근거를 승인받은 뒤 별도 실행 계획을 작성한다. 이 문서는 실행 승인이나 운영 명령을 제공하지 않는다.
