# 앱 알림 동의와 스토어 리뷰 안내

## 사용자 결정

- 앱 사용자에게 푸시 수신 동의를 바로 안내한다. OS 권한 요청은 명시적인 버튼 탭 뒤에만 한다.
- 리뷰는 설치 후 3일·3회 플레이 제한 없이 첫 커리어 완료부터 요청한다.
- 커리어 점수·성적·별점 예상·만족도에 따라 대상을 고르거나 보상을 주지 않는다.

## 알림 안내

앱 홈의 커리어 카드 바로 아래에 '새 소식을 알림으로 받아볼까요?' 카드를 둔다.
모든 버튼은 최소 48 높이이며, 좁은 화면에서도 세로로 배치한다. 홈을 여는 것만으로는
OS 권한 요청·토큰 등록·서버 요청을 하지 않는다. 권한 상태 조회는 앱 실행 중 한 번 재사용한다.

- 이미 앱 알림을 켠 기기, OS에서 재요청을 막은 기기, 안내를 닫은 기기에서는 카드를 숨긴다.
- Android 13+의 첫 요청 전 권한은 `status=denied`일 수 있다. `canAskAgain=true`이면
  명시적인 동의 버튼을 안내한다. 버튼으로 거절하거나 닫은 선택은 기기에 보존한다.
  iOS의 `denied`는 그대로 숨긴다.
- '알림 받기'를 누르면 기존 등록 흐름을 사용한다. 연결 실패는 카드에서 다시 시도할 수 있다.
- '나중에'는 기기에 7일간 보류를 저장한다. 앱 재시작으로 초기화되지 않으며,
  만료 후 홈 방문·홈에서 앱으로 복귀할 때 권한 상태를 다시 확인한다. 타이머·서버 폴링은 없다.
- 수신 허용/거절, 설정에서 직접 수신을 켜거나 끄면 기기에 안내 종료를 저장한다.
  이후에는 설정에서 직접 바꿀 수 있다. 수신을 끈 뒤 다시 동의를 재촉하지 않는다.
- 이전 버전의 안내 종료 기록은 선택 이유를 구분할 수 없어 그대로 보존한다.
- 공지·릴리즈 노트의 새 글을 게시판별 한국 시간 하루 한 번 발송한다는 현재 정책을 안내한다.

## 리뷰 요청

은퇴 직후 `retired` 결과 화면이 2초 동안 안정된 뒤 OS의 기본 리뷰 API를 호출한다.
홈·게임·선수 생성·다른 선수 상세에서는 자동 요청하지 않는다. 앱이 백그라운드이거나
Android 알림창에 가려졌을 때, 키보드·시트·토스트·다른 알림이 떠 있을 때는 기다린다.
비동기 네이티브 가용성 확인 뒤에도 현재 커리어·화면·안전 상태를 다시 확인한다.

- 같은 앱 버전·같은 커리어에서 재요청하지 않는다.
- 다음 버전·새 커리어라도 최소 120일 간격, 최근 365일 최대 3회다.
- 요청 이력을 먼저 저장한다. 저장에 실패하면 요청하지 않는다. OS가 창을 생략하거나
  오류를 내도 반복 요청하지 않는다. 리뷰 제출 여부와 별점은 수집하지 않는다.
- 설정의 '스토어에 리뷰 남기기'는 해당 플랫폼의 스토어 URL을 직접 연다.
  직접 연 뒤에도 자동 요청을 쉬게 한다. 링크 실패에는 오류 문구를 표시한다.

`offside_review_prompt_v1`, `offside_push_offer_handled`는 앱 기기의 별도 설정 키다.
게임 세이브 형식·커리어 결과·밸런스·서버 API를 변경하지 않는다.

## 빌드와 검증

`expo-store-review ~57.0.3`를 SDK 57 공식 설치 명령으로 추가했다. 새 네이티브 빌드가 필요하며
기존 푸시 테스트 앱과 runtime fingerprint가 달라진다. 기존 바이너리에는 모듈이 없으면
자동 요청을 건너뛰는 보호가 있다. 앱 버전·운영 채널은 이 로컬 작업에서 변경하지 않는다.

정책 10건과 실제 네이티브 어댑터 mock 테스트 11건, 기존 푸시 토큰 회귀 6건을 통과했다.
모바일 타입 검사와 변경 파일 ESLint를 통과했다. 전체 배포 검증은 아직 실행하지 않았다.
Android 설정 카드·스토어 이동 및 iOS 첫 알림 안내·권한 요청·거절 유지·리뷰 카드의 실제 화면을 확인했다.
iOS 스토어 이동은 Safari 오류로 완료하지 못했다. 커리어 완료 후 OS 기본 리뷰 창의 실제 확인도 남아 있다.

스토어 기본 리뷰 창은 OS가 표시 여부를 결정하므로 API 완료를 리뷰 작성 성공으로 기록하지 않는다.
iOS 시뮬레이터의 기본 창 확인은 실제 App Store 제출 증거가 아니다. 현재 Google APIs Android
에뮬레이터는 Google Play 서비스로 푸시를 받지만, 스토어 리뷰 창은 Play Store가 있는
기기와 Play 설치 테스트 경로에서 별도로 확인해야 한다. 실제 리뷰를 대신 작성·제출하지 않는다.

참고: [Expo SDK 57 StoreReview](https://docs.expo.dev/versions/v57.0.0/sdk/storereview/),
[Google Play 리뷰 지침](https://developer.android.com/guide/playcore/in-app-review).
PR 준비 시 새 스토어 버전에 맞춘 앱 적용 예정 릴리즈 노트를 함께 추가한다.

### 2026-10-04 실제 화면 확인

사용자가 Android 전용 테스트 기기의 ADB 캡처·터치 사용을 지정했다.
기존 알림 연결 기기의 설정 화면에서 새 '스토어 리뷰' 카드와 버튼이 정상 표시됐고,
버튼을 누르면 Chrome에서 Google Play의 오프사이드 상세 페이지가 열렸다.
현재 Google APIs 이미지에는 Play Store 앱이 없어 네이티브 리뷰 작성 창 검증과는 구분한다.
실제 리뷰를 작성·제출하지 않았다. 이미 연결된 기기의 홈 안내는 숨겨져 있었다.

첫 설치를 확인하려고 별도 `OFFSIDE_Engagement_UI_API_36` 기기를 만들었다.
첫 실행에서도 안내가 숨겨져 있었고 SDK 57의 네이티브 `NotificationPermissionsModule.kt`에서
알림 비활성 상태를 `denied`로 반환하는 조건을 확인했다. Android에서 `canAskAgain=true`인
경우에도 안내하도록 `6b5d1a77`에서 수정했다. 네이티브 어댑터 회귀 테스트 21건과 모바일
타입 검사·변경 파일 ESLint를 통과했다. 네이티브 의존성·앱 버전·운영 채널은 바꾸지 않았다.

iOS 18.1은 재부팅·동일 앱 재설치 뒤에도 프로세스 생성 단계에서 멈췄고 Safari 실행도
20초 안에 끝나지 않았다. 별도 `OFFSIDE Engagement UI iOS 26` 기기는 최초 마이그레이션에서
지연되고 호스트 load average가 414 이상이어서 종료했다. 기존 기기나 앱 데이터를 지우지 않았다.
iOS 새 UI 검증과 OS 기본 리뷰 창 표시는 완료로 기록하지 않는다.

Android 화면 증거: `[로컬 비공개 경로]`.
추가로 스크롤된 기존 설정 내용이 상태 표시줄 뒤에 보이는 것을 관찰했다.
이는 새 리뷰 카드의 가로 잘림이나 하단 탭 가림과 구분되는 공통 화면 확인 사항이다.

수정본은 Android `push-test` 채널/브랜치에만 테스트 OTA로 게시했다.

- 그룹: `dbfcbffa-7885-4a8c-8c2a-ca064b2886fd`
- 업데이트: `01a10480-d6bf-78fc-ae48-46b800e9ee6d`
- runtime: `07eb3c0f5042e9d6add077682ac5c8a344cecac6` — 설치된 내부 빌드와 같다.
- 게시 시각: `2026-10-04T01:21:54.879Z`.
- Hermes 번들에 staging API URL이 포함된 것을 확인했다. 운영 채널·main은 변경하지 않았다.

수정 후 표시·닫기 유지 확인을 위해 새 기기를 재실행했으나 QEMU 로그에
`detected a hanging thread 'QEMU2 main loop'`가 기록되고 ADB가 offline으로 전환됐다.
전용 기기만 연결된 상태에서 ADB 재시작·재연결을 시도했지만 복구되지 않았다.
따라서 수정된 첫 카드의 실제 표시, OS 권한 창, 닫기 후 유지 및 커리어 완료 뒤
기본 리뷰 창 표시는 아직 실제 기기 검증을 마치지 않았다. 테스트 통과와 구분한다.

### 2026-10-04 iOS 후속 확인

사용자 지시에 따라 Android 에뮬레이터를 종료했다. ADB 연결 기기가 없는 것을 재확인했다.
전용 `OFFSIDE Engagement UI iOS 26` (`144BE5E6-A0CB-4440-B503-EA728DB43FF8`)은
초기 마이그레이션이 8분 20초 뒤 완료됐으며 기존 내부 빌드를 설치·실행했다.

- 빈 기기 홈에 첫 알림 동의 카드가 표시되는 것을 실제 화면에서 확인했다.
- '알림 받기'로 iOS의 실제 알림 권한 요청 창이 열렸다.
- 테스트 기기에서 '허용 안 함'을 선택하면 카드가 사라졌다. 앱을 종료·재실행해도
  안내가 다시 나타나지 않았다. 기존 로그인·알림 연결 기기의 데이터는 변경하지 않았다.
- 화면 조작 도구의 스크롤은 `noWindowsAvailable`, 키 입력은 `timeoutReached`로 실패했다.
  사용자 지정으로 Orca emulator CLI를 전용 기기에 연결해 실제 '스토어 리뷰' 카드와
  '스토어에 리뷰 남기기' 버튼을 확인했다. 문구·버튼은 하단 탭에 가리지 않았다.
  스크롤된 기존 내용이 상태 표시줄 뒤로 보이는 공통 화면 문제는 남아 있다.
- 리뷰 버튼으로 Safari가 열렸으나 '주소가 유효하지 않기 때문에 페이지를 열 수 없습니다'가
  표시됐다. 국가 코드 없는 링크는 HTTP 404, 한국 주소는 HTTP 200 및 오프사이드 상세 페이지
  리다이렉트를 확인해 `0136a35b`에서 한국 주소로 바꿨다. 수정 후에도 시뮬레이터의 Safari
  오류는 남았다. 실제 iPhone의 App Store 리뷰 화면 이동은 검증 완료로 기록하지 않는다.
- 첫 홈 카드의 안내 링크 우측이 기존 채팅 FAB와 겹쳤다. 링크를 문구에 맞는 폭으로 줄이고
  공통 버튼의 최소 높이 48을 유지하는 로컬 수정에 타입 검사·변경 파일 ESLint를 통과했다.

iOS 테스트 OTA 그룹 `1f42969f-2b73-41c1-a1f3-9e07dd77ad09`, 업데이트
`01a1049c-7010-7f86-8c8d-31b26fdeb957`, 게시 `2026-10-04T01:52:03.600Z`.
`push-test` 브랜치/채널, staging API이며 runtime `0bbafe19d474aebcbb4e549549429a837374c73a`는
설치된 내부 빌드와 같다. 전용 기기의 Expo 업데이트 DB에서 해당 ID의 성공 실행 1회·실패 0회를
읽기 전용으로 확인했다. 회귀 21건·타입 검사·변경 파일 ESLint를 통과했다.

첫 표시 증거: `[로컬 비공개 경로]`.
운영 배포·main 병합·실제 리뷰 제출은 수행하지 않았다. 커리어 완료 후 OS 기본 리뷰 창,
화면 회전·최대 글자 크기·양 테마의 전체 검증도 완료로 간주하지 않는다.

### 운영 배포 준비

사용자가 iOS 실기기에서 App Store 이동을 확인했다고 보고했다. 시뮬레이터 오류와 구분한다.
최신 main을 합치며 기존 careers 인덱스 migration 0053을 보존하고 푸시 migration을
0054_grey_anthem으로 다시 생성했다. 이는 staging 테스트에 쓴 두 migration의 합본이며
이미 해당 두 migration이 적용된 staging DB에 그대로 재적용하지 않는다.
새 모듈은 기존 production 1.0.2 빌드에 없어 이번 스토어 빌드는 1.0.3으로 준비한다.
전체 사용자 자동 푸시 발송은 이 배포에 포함하지 않는다.
