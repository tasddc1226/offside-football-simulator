# 앱 알림 동의와 스토어 리뷰 안내

## 사용자 결정

- 앱 사용자에게 푸시 수신 동의를 바로 안내한다. OS 권한 요청은 명시적인 버튼 탭 뒤에만 한다.
- 리뷰는 설치 후 3일·3회 플레이 제한 없이 첫 커리어 완료부터 요청한다.
- 커리어 점수·성적·별점 예상·만족도에 따라 대상을 고르거나 보상을 주지 않는다.

## 알림 안내

앱 홈의 커리어 카드 바로 아래에 '새 소식을 알림으로 받아볼까요?' 카드를 둔다.
모든 버튼은 최소 48 높이이며, 좁은 화면에서도 세로로 배치한다. 홈을 여는 것만으로는
OS 권한 요청·토큰 등록·서버 요청을 하지 않는다. 권한 상태 조회는 앱 실행 중 한 번 재사용한다.

- 이미 앱 알림을 켠 기기, OS에서 거절한 기기, 안내를 닫은 기기에서는 카드를 숨긴다.
- '알림 받기'를 누르면 기존 등록 흐름을 사용한다. 연결 실패는 카드에서 다시 시도할 수 있다.
- '나중에', 수신 허용/거절, 설정에서 직접 수신을 켜거나 끄면 기기에 안내 종료를 저장한다.
  이후에는 설정에서 직접 바꿀 수 있다. 수신을 끈 뒤 다시 동의를 재촉하지 않는다.
- 공지·릴리즈 노트 자동 발송은 아직 준비 중이므로 카드에서도 연결 준비 단계임을 안내한다.

## 리뷰 요청

은퇴 직후 `retired` 결과 화면이 2초 동안 안정된 뒤 OS의 기본 리뷰 API를 호출한다.
홈·게임·선수 생성·다른 선수 상세에서는 자동 요청하지 않는다. 앱이 백그라운드이거나
Android 알림창에 가려졌을 때, 키보드·시트·토스트·다른 알림이 떠 있을 때는 기다린다.
비동기 네이티브 가용성 확인 뒤에도 현재 커리어·화면·안전 상태를 다시 확인한다.

- 같은 앱 버전·같은 커리어에서 재요청하지 않는다.
- 다음 버전·새 커리어라도 최소 120일 간격, 최근 365일 최대 3회다.
- 요청 이력을 먼저 저장한다. 저장에 실패하면 요청하지 않는다. OS가 창을 생략하거나
  오류를 내도 반복 요청하지 않는다. 리뷰 제출 여부와 별점은 수집하지 않는다.
- 설정의 '스토어에 리뷰 남기기'는 해당 플랫폼의 스토어 URL을 직접 연다.
  직접 연 뒤에도 자동 요청을 쉬게 한다. 링크 실패에는 오류 문구를 표시한다.

`offside_review_prompt_v1`, `offside_push_offer_handled`는 앱 기기의 별도 설정 키다.
게임 세이브 형식·커리어 결과·밸런스·서버 API를 변경하지 않는다.

## 빌드와 검증

`expo-store-review ~57.0.3`를 SDK 57 공식 설치 명령으로 추가했다. 새 네이티브 빌드가 필요하며
기존 푸시 테스트 앱과 runtime fingerprint가 달라진다. 기존 바이너리에는 모듈이 없으면
자동 요청을 건너뛰는 보호가 있다. 앱 버전·운영 채널은 이 로컬 작업에서 변경하지 않는다.

정책 10건과 실제 네이티브 어댑터 mock 테스트 11건, 기존 푸시 토큰 회귀 6건을 통과했다.
모바일 타입 검사와 변경 파일 ESLint를 통과했다. 전체 배포 검증은 아직 실행하지 않았다.
새 빌드 설치 후 홈 카드·설정 버튼의 실제 모바일 화면 확인을 진행한다.

스토어 기본 리뷰 창은 OS가 표시 여부를 결정하므로 API 완료를 리뷰 작성 성공으로 기록하지 않는다.
iOS 시뮬레이터의 기본 창 확인은 실제 App Store 제출 증거가 아니다. 현재 Google APIs Android
에뮬레이터는 Google Play 서비스로 푸시를 받지만, 스토어 리뷰 창은 Play Store가 있는
기기와 Play 설치 테스트 경로에서 별도로 확인해야 한다. 실제 리뷰를 대신 작성·제출하지 않는다.

참고: [Expo SDK 57 StoreReview](https://docs.expo.dev/versions/v57.0.0/sdk/storereview/),
[Google Play 리뷰 지침](https://developer.android.com/guide/playcore/in-app-review).
PR 준비 시 새 스토어 버전에 맞춘 앱 적용 예정 릴리즈 노트를 함께 추가한다.
