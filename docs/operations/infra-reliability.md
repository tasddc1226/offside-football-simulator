# 기록 업로드와 정기 작업 복구

T-11-337. API·웹 배포와 앱 OTA를 함께 적용한다. 기존 게임 세이브 형식은 바꾸지 않는다.

## 기록 업로드

시즌·은퇴 본문은 네트워크 모듈을 불러오기 전에 `ft_outbox`에 동기로 저장한다. 저장 성공 뒤에만 시즌 이벤트 버퍼를 비운다. 미전송 항목은 개수 초과로 제거하지 않는다. 저장소가 일시적으로 막히면 메모리에 보관하고 저장부터 재시도한다. 저장 공간 자체가 영구적으로 없거나 사용자가 앱 데이터를 지우면 기기 내 보존을 보장할 수 없다.

각 항목의 `revision`은 큐에 저장해 재전송에도 유지한다. 시즌 API는 본문 해시와 마지막 revision을 시즌 행에 요약·측정 기록과 같은 D1 batch로 저장한다. 같은 본문은 재반영하지 않고, revision이 있는 과거 요청은 최신 시즌을 덮지 않는다. 헤더가 없는 기존 앱은 기존 갱신 동작을 유지하면서 동일 본문의 연속 재전송만 중복 제거한다. 기기 시계 차이가 큰 경우의 여러 기기 동시 편집은 별도 충돌 해결 범위다.

연결 끊김·인스턴스 초기화에만 서버 제한 재시도를 한다. 과부하·검증 오류는 즉시 반복하지 않는다. 클라이언트는 5xx·429를 간격을 늘려 재전송한다. 영구적인 4xx는 `ft_outbox:rejected`에 보존하고 자동 재시도를 멈춘다. 이 보관함을 원인 수정 없이 일괄 재전송하거나 삭제하지 않는다. 소유권 충돌은 기존 계정 선택 흐름을 유지한다.

## 일일 작업

`cron:daily:state`에 업무 날짜·단계·실행 토큰·임대 만료·다음 재시도 시각·단계 결과를 저장한다. 기존 5분 스케줄러가 단계마다 저장하며 진행한다. 한 틱에서 새 단계를 시작할 때 5초 예산을 확인하고 최대 세 단계만 실행한다. 실행 중인 단계를 5초에 강제 중단하지는 않으며, 각 단계의 행 수 제한으로 작업량을 제한한다. 미완료 묶음은 즉시 다음 틱으로 넘긴다. 정리·자동화 점검·보관·업적 재계산은 제한된 묶음만 처리하며 남은 것은 같은 단계에서 이어간다. 성공한 단계는 다시 실행하지 않는다. 단계 실행 후 체크포인트 저장 전에 종료된 경우에는 그 단계가 다시 실행될 수 있으므로 단계의 DB/R2 작업은 재실행 가능해야 한다.

중복 실행은 체크포인트 비교 교환으로 막는다. 임대가 만료되거나 다른 실행이 소유권을 가져갔으면 이전 실행은 체크포인트·최종 완료 기록을 바꿀 수 없다. 모든 단계가 끝났을 때만 `cron:daily:last`와 완료 체크포인트를 같은 batch로 저장한다. 마지막 정상 완료 날짜 다음부터 누락 날짜를 따라잡는다. `cron:daily:last.ts`가 갱신됐다는 사실만으로 모든 외부 부작용의 성공을 추정하지 말고 단계별 결과도 확인한다.

`cron:daily:state.status=retry`이면 실패 단계, attempts, nextAttemptAt를 확인한다. 자동 재시도는 최대 1시간 간격이다. 체크포인트를 삭제하거나 완료 날짜를 임의로 앞당기지 않는다. 백업은 별도 체크포인트를 유지하며 시간 정각의 아카이브·알림 집중 구간에는 시작하지 않는다. 정기 작업이 D1 과부하를 감지한 틱에는 뒤의 대량 보관·백업을 양보한다.

## 공개 컵 캐시

`/v1/cups/current`만 30초 엣지 캐시한다. 과거 대회별 키를 무제한 만들지 않는다. 참가·철회·일정·팀 변경·계정 삭제·cron 경기 처리 시 홈과 현재 대회 캐시를 함께 무효화한다. 개인 자격·잠금 판단과 쓰기는 캐시하지 않는다. Cache API 무효화는 해당 데이터센터에만 적용되므로 다른 곳은 TTL 이내에 갱신된다.

## 배포 검증

추가 컬럼 마이그레이션을 preflight 뒤 적용한다. 기존 앱·기존 시즌 행을 보존한다. 배포 직전/직후 같은 길이의 구간에서 요청량, 정상 응답 durationMs p95/p99, 503·D1 연결 오류·과부하를 비교한다. 정상 로그는 10% 표본이며 Cloudflare 집계도 적응형 추정일 수 있으므로 원시 로그 비율을 전체 실패율로 제시하지 않는다. 저트래픽 구간에서 오류가 없었다는 사실만으로 장애가 해결됐다고 판정하지 않는다.

일일 작업은 완료 기록과 단계 결과까지, 백업은 완료 기록과 실제 R2 객체까지 확인한다. 웹/API 배포·OTA 게시·설치 앱 적용·실기기 검증은 각각 구분해 보고한다.

## T-11-340 운영 관찰 보완

초기 복구의 이상 징후 단계에서 기존 하루치 윈도 쿼리가 D1 요청을 막는 과부하를 관찰했다. 정기 검사는 `careers_automation_updated_idx`로 업무 날짜까지 변경된 커리어를 최대 100개 읽고, 해당 ID의 시즌만 기본 키로 읽어 계산한다. 시각과 ID의 복합 커서를 일일 체크포인트 결과에 보존하고 마지막 묶음까지 끝나야 완료 시각을 갱신한다. 같은 시각의 경계 행과 예전 시즌 비교를 생략하지 않는다. 관리자 전체 보고는 기존 수동 조회를 유지한다.

T-11-341: 체크포인트 읽기·claim 자체가 실패해도 재시도 신호를 반환한다. 중첩 D1 원인은 바인딩 값을 뺀 오류 요약으로 보존해, 과부하·연결 끊김 때 후속 대량 작업을 양보한다. 이 경우 체크포인트나 완료 기록을 만들지 않고 다음 틱에서 다시 시도한다.

T-11-342: 분할 검사의 증분 범위도 기존 검사와 맞춘다. 커리어 갱신만으로 과거 시즌을 새 대상으로 삼지 않고, 선택한 최대 100커리어 중 최근 시즌이 올라온 것만 검사한다. 레전드 점수 검사는 기존처럼 최초 전체 검사에만 적용한다. 같은 fixture를 기존·분할 검사에 각각 적용해 숨김 결과가 같은지 대조한다.

T-11-343: 추가 관찰에서 감독 생성 POST의 D1 연결 유실 503 한 건을 확인했다. 이 경로는 생성 ID·시드·SQL 인자를 고정한 원자 배치에만 제한 재시도를 적용한다. 이미 커밋된 재전송은 카드의 감독 표시 때문에 INSERT가 0행이어도 같은 ID의 생성 결과를 반환한다. 소유권·진행 중 커리어 유니크 조건과 판매 취소를 유지한다. 다른 쓰기 경로에 포괄 재시도를 적용하지 않는다.

T-11-350: 일일 업무 날짜·시즌·백업 마감은 예약 시각을 유지하되, 인프라 건강 상태는 앞선 작업이 끝난 실제 조회 시각으로 평가한다. 늦은 cron이 방금 완료한 기록을 미래 시각으로 오인하지 않게 한다. 일일 전용 트리거도 전체 완료 직후에는 같은 시간대의 경보를 다시 평가한다.

T-11-351: 활동 기록 API의 연결 유실은 부작용 없는 소유권 SELECT와 시각·본문을 고정한 활동 UPSERT에만 제한 재시도한다. 더 최신 활동이 들어온 경우 과거 재시도가 커리어·상태·언어·활동 시각을 되돌리지 않으며 최초 은퇴 시각과 기존 알림 단계는 보존한다. 커밋 전·후 유실과 최신 요청 사이의 경쟁을 테스트한다. 과부하에는 즉시 재시도하지 않고, 다른 알림 결과 쓰기에는 포괄 재시도를 적용하지 않는다.

T-11-370: 밀린 업무 날짜로 환불 동기화를 재개할 때 Google 서비스 계정 JWT의 `iat`·`exp`에는 현재 시각을 쓴다. 업무 시각을 그대로 서명하면 이미 만료된 토큰이 되어 `Google token 400`으로 멈춘다. 조회 시작 시각(업무일 기준 7일), DB 기록 시각, 회수 정책과 재전송 멱등성은 바꾸지 않는다. 실패한 환불 단계만 기존 백오프로 다시 시도하며 앞선 완료 단계를 반복하거나 체크포인트를 수동 초기화하지 않는다. [Google 인증 시간 요건](https://developers.google.com/identity/protocols/oauth2/service-account#error-codes).
