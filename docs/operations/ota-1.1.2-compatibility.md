# 1.1.2 심사 빌드 OTA 호환 배포

1.1.2 스토어 심사 빌드는 AdMob을 포함하지만 현재 main의 네이티브 구성은
AppLovin MAX를 사용한다. 버전 문자열이나 runtimeVersion만 바꿔 동일 번들을
게시하면 안 된다. 기존 production 배포 흐름에서 API·웹 배포가 성공한 뒤,
현재 구성과 1.1.2 호환 구성의 iOS·Android 번들을 각각 게시한다.

## 고정한 심사 빌드

## 배포 동작

- `.github/workflows/deploy-production.yml`의 `app-update`는
  `current / 1.1.2 × ios / android` 네 개의 독립 체크아웃으로 실행한다.
- `current`는 원래 소스로 게시한다. 현재 구성은 기존 1.1.1 런타임을 대상으로 한다.
- `1.1.2`는 `prepare-ota-112.mjs`로 app.json, 모바일 의존성 및 lockfile,
  광고 배너·보상·동의 어댑터만 심사 빌드의 소스로 복원한다.
  명예관·구단주 등 나머지 앱 및 공용 기능은 배포 커밋의 최신 소스를 사용한다.
- 준비 스크립트는 수정 파일 또는 생성된 ios/android 프로젝트가 있으면 중단한다.
  로컬 개발 체크아웃에서 직접 실행하지 않는다.
- frozen install, 모바일 타입 검사, AdMob 보상 테스트를 통과해야 한다.
  EAS production 환경으로 계산한 fingerprint가 위 런타임과 정확히 일치하고
  같은 런타임의 완료된 production 빌드가 있어야 1.1.2 OTA를 게시한다.
  runtimeVersion 강제 지정은 하지 않는다.
- 변경 생략 여부는 플랫폼과 런타임별 마지막 production OTA 커밋으로 판단한다.
  한 플랫폼 실패 후 재시도하거나 다른 버전에 게시했어도 필요한 업데이트가
  누락되지 않는다. export/upload 오류는 작업 실패로 처리한다.
- 네 작업이 성공해야 기존 흐름에 따라 게임 내 릴리즈 노트 게시가 진행된다.

## 운영 및 유지보수

이 PR을 병합한 뒤 해당 main SHA로 기존 production preflight/deploy를 실행해야
새 경로가 적용된다. 코드 준비만으로 OTA가 게시되거나 스토어 심사가 바뀌지는 않는다.
1.1.2가 승인·출시되어도 production 채널과 호환 런타임으로 배포된 OTA를 받을 수 있다.
실제 반영 시점은 앱의 업데이트 다운로드·재시작 정책에 따른다.

의존성 또는 네이티브 설정이 변경되어 설치·타입 검사·fingerprint 검사가 실패하면
실패를 무시하거나 해시를 강제로 바꾸지 않는다. 심사 빌드와 호환 가능한 JS 변경인지
확인하여 overlay를 명시적으로 갱신하거나 새 스토어 빌드를 배포한다. 고정 lockfile과
광고 어댑터의 보안·버그 수정도 이 호환 경로에 별도 반영해야 한다.
1.1.2 지원 종료 시 matrix에서 해당 target과 준비 단계를 함께 제거한다.

## 로컬 검증 (2026-10-11)

별도 임시 체크아웃에 현재 PR 작업을 복사한 뒤 1.1.2 호환 구성을 적용했다.
모바일 타입 검사, AdMob 보상 테스트 9개, 배포 실패 전파/런타임 차단/기존 작업
보호 테스트와 actionlint를 확인했다. iOS·Android fingerprint는 위 심사 빌드와
일치했고, iOS·Android production URL을 사용한 Expo 번들 export도 모두 성공했다.
실제 production OTA 게시 및 스토어 앱 수신 검증은 수행하지 않았다.
