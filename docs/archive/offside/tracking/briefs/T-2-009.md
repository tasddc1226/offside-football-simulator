# T-2-009: web 시즌 결산 SCR-015(+SCR-006 유소년 변형) — CompareCards·변화 원인 분리·연대기 요약·결산 응답 유실 복구 (TEST-E2E-002)

## 목표

`SETTLE_SEASON` 뒤 `seasonHistory[].result`(T-2-005 `SeasonResult`)를 SCR-015에서 결산으로 보여준다: 공통 지표·포지션 카드·팀 성적·역할 시작/종료·출전 약속 이행·OVR 전후와 원인. "OVR 변화"(능력·원인 태그)와 "경기 예상치 변화"(폼·체력·사기·맥락)를 분리하고, 0·미집계·애니메이션 중을 구분한다. 결산 명령의 응답이 유실돼도 같은 결과로 복구된다. 대시보드 다이어리에 이번 시즌 연대기 요약을 붙인다.

- 읽어야 할 문서(순서대로): `docs/tracking/phase-2-plan.md` **D-29·D-30·D-39**, `docs/screens/02-season-flow.md`(SCR-015·SCR-006), `docs/tracking/briefs/T-2-005.md`(`SeasonResult` 필드: competitions·playerStats·selectionSummary·roleChanges·promiseFulfilment·attributeDeltas{key,delta,causes[]}·baseOvr{before,after}·stateDeltas·chapters·hash), `docs/tracking/briefs/T-2-007.md`(자리표시 `SCR-015: /career/$careerId/season-result`, 대시보드 "시즌 결산" CTA·`settleSeason` 액션·`latestSeasonResult`), `docs/tracking/briefs/T-1-009.md`(결과 카드 규칙)

## 범위

- 만질 패키지·경로: `apps/web`만. `src/routes/career.$careerId.season-result.tsx`(자리표시 대체), `career.$careerId.index.tsx`(결산 CTA 목적지·다이어리 구역), `src/shared/{season-result-view,season-compare,countup}.ts(x)`, `labels.ts`(원인 태그·OutReason·통계 항목 라벨), `e2e/`.
- 만들 것:
  1. **`season-result-view.ts`**: `deriveSeasonResultView(state, index, ruleset)` — `seasonHistory[index].result`가 없으면 null. 공통 지표(출전 `appearances.total`/선발/교체/0분/결장, 분, 평균 평점 `ratingSumTenths / ratedMatches` 소수 1자리 — `ratedMatches === 0`이면 **미집계 `—`**, 경고·퇴장·부상), 포지션 카드(`totals.group`에 맞는 항목만: FW 득점·도움·xG(`xgCenti/100`)·슈팅·오프사이드, MF 도움·기회 창출·전진 패스·패스 성공률(`passesCompleted/passesAttempted`, 시도 0이면 `—`)·볼 회수, DF 태클·인터셉트·공중볼·실점 관여·클린시트, GK 세이브·PSxG−실점(`/100`)·클린시트·크로스 처리·빌드업 패스 — **포지션에 무관한 지표는 숨긴다**), 팀 성적(`competitions`: 리그 순위/팀 수·승무패·득실, 컵 라운드 라벨 "R1 탈락"/"결승 진출" 등), 역할 시작/종료(`selectionSummary.squadRoleAtStart→AtEnd`, 최종 순위, 출전 시간 비율 `minutes/possibleMinutes`), 출전 약속(`promiseFulfilment`: 약속·실제·이행 여부 문장), 역할 변화(`roleChanges` 목록), 챕터(`chapters` 목록: 챕터 라벨·판단 수).
  2. **변화 원인 분리**(D-29): 두 섹션 — **"OVR 변화"**: `baseOvr.before → after`와 `attributeDeltas`(delta≠0인 능력을 묶음별로, 각 `causes`를 라벨 TRAINING 훈련·MINUTES 출전·EXPERIENCE 경험·AGE_DECLINE 연령·POTENTIAL_CAP 잠재력 상한과 `centi/100` 소수 1자리), 상단 한 줄 "가장 큰 원인: {cause}"; **"경기 예상치 변화"**: `stateDeltas`(폼·체력·사기·감독 신뢰 before→after; 경계 회귀로 after가 룰셋 기본값이면 "시즌 경계 회귀" 캡션). 두 섹션 사이에 "능력은 결산 때만, 예상치는 경기마다 움직입니다" 한 줄.
  3. **CompareCards**: 기준 행 고정(이번 시즌), 비교 대상 세그먼트(`지난 시즌` = `seasonHistory[index-1].result` 있을 때 / `계약 약속` = 출전 약속 기준 — 첫 시즌은 후자만), 항목 하나씩 전환, "차이만 보기" 토글(같은 값 행 숨김). 360px에서 세로 카드만.
  4. **0·미집계·애니메이션 구분**(`countup.tsx`): 숫자는 확정값을 `data-value`와 접근성 이름에 먼저 쓰고 표시값만 800ms 카운트업, "건너뛰기" 버튼, `useReducedMotion`이면 즉시. 0은 "0"으로, 미집계는 `—`로, 애니메이션 중은 `aria-busy` 없이 `data-animating="true"` — 셋을 구분하는 단위 테스트.
  5. **SCR-015 라우트** `/career/$careerId/season-result?season=<index>`: `season` 없으면 마지막 결산. 결과가 없고 pending SETTLEMENT면 대시보드로(결산은 대시보드 CTA가 확정한다 — 화면은 확정하지 않는다). **SCR-006 변형**: 결산 시즌의 계약 `leagueTier === 'YOUTH'`(`seasonHistory[index]`의 teamId가 룰셋 `teams`에서 YOUTH)이면 제목 "유소년 시즌 결과", 포지션 카드 위에 정찰 범위 `scoutedPotentialMin~Max` 한 줄, 팀 성적 대신 "성장 기록" 강조("관심 구단"은 도메인에 없어 표시하지 않는다 — PR 본문에). "다음 시즌" → SCR-005(T-2-007), "대시보드" → SCR-029, "대회별 상세"는 같은 화면의 `Tabs`(리그/컵).
  6. **결산 응답 유실 복구**: 대시보드 "시즌 결산" CTA(T-2-007 `settleSeason`)가 실패해도(네트워크·PUT 유실) `commandId` 멱등 재시도로 같은 revision·같은 `result.hash`가 되고, 재시도 뒤 SCR-015로 간다. 재시도 중 화면은 "저장 다시 시도 중" 배지(기존 `SyncBadge` 계약)와 CTA 잠금. 새로고침하면 `seasonHistory`가 늘어난 상태를 읽어 SCR-015가 바로 열린다. E2E: `resilience.spec.ts` (c)와 같은 방식으로 첫 PUT을 실패시킨 뒤 검증(`result.hash` 동일).
  7. **다이어리 연대기 요약**(SCR-029 구역): 이번 시즌(`season` 있으면 현재, 없으면 마지막 결산 시즌)의 타임라인 항목을 시간순 카드로 — SEASON_STARTED·ROLE_RESOLVED·EVENT_RESOLVED·CHAPTER_RESOLVED·STEP_PASSED(경기 결과 요약 "3승 1무", `StepSummary.results`)·SEASON_SETTLED(→ SCR-015 링크). 과거 시즌은 "시즌 {n} 결산 보기" 링크 목록(SCR-027 전체 연대기는 Phase 5).
  8. **분석**: `screen_viewed`(SCR-015/006), `season_result_viewed { seasonIndex, compareTarget }`, `countup_skipped`.
  9. **E2E**(`e2e/season-result.spec.ts`, TEST-E2E-002 "프리시즌→핵심 경기→시즌 결산"): 계약 → SCR-005 FAST → 시즌 시작 → 역할 제안 → "진행" 반복(이벤트·챕터가 뜨면 첫 선택으로 확정; 챕터 화면은 T-2-008 머지 여부에 따라 자리표시일 수 있으므로 `chapter` URL이면 "대시보드로" 버튼) → "시즌 결산" → SCR-015: 헤더 OVR after와 결산 after 일치, 공통 지표 합(선발+교체+0분+결장 = total), 평균 평점 또는 `—`, CompareCards 세그먼트 전환·차이만 보기, 카운트업 건너뛰기 뒤 `data-value`와 표시값 일치, "다음 시즌" → SCR-005. 두 번째: PUT 유실 복구(6번). `a11y.spec.ts`에 SCR-015 추가.
  10. **단위 테스트**: `deriveSeasonResultView` 포지션군 4종(fixtures 골든의 result로) — 무관 지표 미포함, 미집계 규칙, 원인 라벨·최대 원인, CompareCards 행 생성·차이만 보기, 카운트업 상태 3종, 다이어리 요약 항목 순서.
