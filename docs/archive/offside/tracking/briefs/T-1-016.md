# T-1-016: 선수 성별·선호 포지션 프로필 계약

## 목표

현재 6필드 선수 생성에 성별을 프로필 정보로 추가하고, 생성 시 고른 포지션을 불변 선호 포지션과 변경 가능한 현재 주포지션으로 분리한다. 성별은 어떤 시뮬레이션 결과도 바꾸지 않는다.

## 참조 명세

- 요구사항: FR-PLY-001, RULE-PLY-001, DATA-PLY-001, SCR-002~004.
- 읽는 순서: `docs/tracking/phase-1-plan.md` D-23 → `docs/development/02-domain-and-data-model.md` RULE-PLY-001 → `docs/screens/01-career-start.md` → `docs/development/06-ui-ux-specification.md`.
- 선행: T-1-009와 T-1-011이 main에 머지된 뒤 착수한다. 완료된 T-1-008의 화면 흐름과 복구 코드 단계는 바꾸지 않는다.

## 데이터 계약

```ts
type PlayerGender = 'FEMALE' | 'MALE' | 'UNSPECIFIED';

type PlayerDraft = {
  name: string | null;
  gender: PlayerGender | null;
  nationalityCode: string | null;
  preferredFoot: PreferredFoot | null;
  position: Position | null; // 생성 UI 라벨은 "선호 포지션"
  archetypeId: string | null;
  backgroundId: string | null;
};

type PlayerProfile = {
  name: string;
  gender: PlayerGender;
  nationalityCode: string;
  preferredFoot: PreferredFoot;
  preferredPosition: Position;
  primaryPosition: Position;
  // 기존 확정 필드 계속
};
```

- `CONFIRM_PLAYER`는 gender까지 7개 DRAFT 필드를 요구한다.
- `preferredPosition`과 `primaryPosition`은 DRAFT `position`으로 함께 초기화한다. 이후 `primaryPosition`만 포지션 전환으로 바뀔 수 있다.
- `PlayerPublic`에는 세 필드를 포함하지만 `gender`를 분석·로그·오류 details에 복사하지 않는다.
- `gender`는 RNG draw를 소비하지 않고 ruleset·content pack 분기 입력도 아니다.
- 출시 전 `schemaVersion: 1`을 유지한다. 구 개발 fixture는 `gender = UNSPECIFIED`, `preferredPosition = primaryPosition = profile.position`으로 올리고 golden hash를 갱신한다.

## 화면 계약

- SCR-002 이름 다음에 성별 RadioGroup을 둔다: 여성, 남성, 선택하지 않음. 기본 선택 없음.
- 그룹 설명 `능력치와 성장에는 영향을 주지 않습니다`를 시각적으로 표시하고 `aria-describedby`로 연결한다.
- 현재 `포지션` 라벨은 `선호 포지션`으로 바꾼다. 포지션 변경 시 기존 아키타입 초기화 규칙은 유지한다.
- SCR-004 확인 요약에 성별과 선호 포지션을 표시한다. PlayerHeader의 포지션은 확정 전 선호, 확정 뒤 현재 주포지션이다.
- 이름 자동 서명, 복구 코드, 진로·계약 흐름은 불변이다.

## 구현 범위

- `packages/domain`: 타입, DRAFT 검증, 확정 변환, 상태 검증, 결정론·golden.
- `packages/contracts`: DRAFT/Profile/Public 스키마와 공개 변환, 구 fixture migration.
- `apps/web`: SCR-002/004 입력·표시·유효성·접근성, 생성 E2E.
- `packages/fixtures`와 cross-runtime hash 소비처: 새 정본 hash로 원자 갱신.
- `packages/content`: gender를 조건 DSL 경로에 추가하지 않는다. 이 불변식 검사만 추가한다.

## 테스트와 인수 조건

- [ ] 같은 seed·나머지 DRAFT에서 성별 세 값의 attributes, truePotential, Base OVR, RNG state가 같다.

- [ ] 선호 W로 생성하면 `preferredPosition === primaryPosition === 'W'`; 주포지션 전환 뒤 선호 W는 유지된다.

- [ ] 성별 세 선택과 선호 포지션을 키보드로 완료하고 axe serious·critical 0건이다.

### 제약
- `'toss'`·`'web'` 리터럴 비교 금지(lint), hex 색 리터럴 금지, 색·간격·글꼴은 13의 토큰(`--os-*`)만.
- 모든 사용자 문구는 한국어. 성별 선택지 문구는 계약 그대로("여성", "남성", "선택하지 않음").
- `gender`를 분석 payload·로그·오류 details·URL 어디에도 남기지 않는다.
- `localStorage` 직접 접근 금지. 화면 컴포넌트에서 `import.meta.env.MODE` 검사 금지.
- 커밋 메시지는 `T-1-016: …`로 시작, 브랜치는 `T-1-016-…`.
- 서브에이전트 리뷰를 띄우지 않는다. gstack `/review`·`/codex`·adversarial 리뷰·`/simplify`·병렬 fork 전부 금지. 유일한 예외는 Orca PR 게이트용 `/review:pr` 1회(로컬 모드)다. 리뷰는 오케스트레이터가 한다.
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
