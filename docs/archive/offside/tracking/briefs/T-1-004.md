# T-1-004: api 복구 코드·프로필 삭제·로그아웃·커리어 삭제·rate limit

## 목표
다른 브라우저에서 복구 코드로 같은 프로필을 잇고(충돌 시 병합 선택), 프로필을 2단계로 삭제하고, 로그아웃하고, 커리어 하나를 삭제할 수 있다. 복구 코드 시도는 rate limit에 걸린다.

## 참조 명세

## 범위
- 만질 패키지·경로: `apps/api`만(라우트·repos·migration·테스트). 예외: `packages/contracts`는 만지지 않는다(필요한 오류 코드 `RECOVERY_CODE_INVALID`·`RECOVERY_CONFLICT`·`RATE_LIMITED`는 이미 있다. 요청·응답 Zod 스키마는 T-1-006이 contracts에 넣으므로 이 작업은 api 안에서 로컬 스키마로 검증한다).
- 만들 것:
  1. Migration: `profiles.deleted_at TEXT NULL`, 테이블 `auth_attempts (id, kind 'RECOVERY', subject TEXT, window_start TEXT, count INTEGER)` 와 `audit_log (id, kind, profile_id, payload_json, created_at)`(ADR-008 감사 로그: `PROFILE_MERGED{fromProfileId,toProfileId,careerIds}`, `PROFILE_DELETED`, `RECOVERY_CODE_ISSUED`). `db:check`가 통과하도록 migration 파일·스냅샷 갱신.
  2. 복구 코드 생성기 `auth/recovery-code.ts`: 알파벳 30자(`ABCDEFGHJKMNPQRSTVWXYZ` 22자 + `23456789` 8자. `I L O U 0 1` 제외), 12자리, `OFS-XXXX-XXXX-XXXX` 표기, `crypto.getRandomValues` + rejection sampling(모듈로 편향 금지). `normalize(code)`: 대문자화, 공백·하이픈 제거, 앞의 `OFS` 제거. 저장은 `sha256Hex(normalized)`.
  3. `POST /profile/recovery-code`: 세션 필요. 새 코드 발급, `recovery_code_hash`·`recovery_code_issued_at` 갱신(이전 코드 즉시 무효). 응답 `{ code, issuedAt }`. 프로필당 시간당 5회 초과 → 429 `RATE_LIMITED`(`auth_attempts` kind `'RECOVERY_ISSUE'`).
  4. `POST /profile/recover`: 본문 `{ code, mergeChoice?: 'MOVE_TO_LINKED' | 'KEEP_LINKED_ONLY' }`. 현재 세션(익명 프로필 포함) 필요. 코드 정규화 → 해시 조회. 없거나 대상 프로필이 `deleted_at`이면 400 `RECOVERY_CODE_INVALID`(존재 여부를 구분하는 문구 금지, 응답 시간 차이도 두지 않는다). 대상이 현재 프로필과 같으면 200 그대로. 현재 프로필에 커리어가 있고 `mergeChoice`가 없으면 409 `RECOVERY_CONFLICT` details `{ currentCareerCount, targetCareerCount }`. `MOVE_TO_LINKED`: 현재 프로필의 커리어(스냅샷·명령 로그·idempotency 포함)를 대상 프로필로 소유권 이동(careerId 유지, `runBatch` 한 트랜잭션), 감사 로그 `PROFILE_MERGED`. `KEEP_LINKED_ONLY`: 이동 없음. 둘 다 끝에 현재 세션을 대상 프로필로 재바인딩(세션 행의 `profile_id` 갱신, 토큰은 유지). 응답 `{ profileId, careerCount }`. 실패 시도는 `IP + 세션` 주체로 시간당 5회 → 429(`kind 'RECOVERY_REDEEM'`). IP는 `CF-Connecting-IP` 헤더, 없으면 `'unknown'`.
  5. `POST /profile/delete` 2단계: 본문 없음 → 200 `{ confirmToken, expiresAt }`(10분, 세션 id에 묶인 서명 토큰 또는 D1 저장. 검증 가능하면 어느 쪽이든 되나 세션이 바뀌면 무효). 본문 `{ confirmToken }` → 프로필 `deleted_at` 기록, 커리어·스냅샷·명령 로그·idempotency 즉시 삭제, 모든 세션 폐기, 감사 로그 `PROFILE_DELETED`, 204. 토큰 불일치·만료 → 400 `VALIDATION_FAILED`.
  6. `POST /auth/logout`: 현재 세션 폐기, 204, `Set-Cookie`로 쿠키 제거(web 채널). Bearer 채널은 토큰만 폐기.
  7. `DELETE /careers/{id}`: 소유 확인(아니면 404 `CAREER_NOT_FOUND`, 다른 사람 소유도 404), 커리어·스냅샷·명령 로그 삭제, 204. 두 번째 호출은 404. `GET /careers` 목록에서 빠진다.
  8. 세션 미들웨어: `deleted_at`이 있는 프로필의 세션은 401 `PROFILE_REQUIRED`.
- 만지지 말 것: `docs/`, `packages/*`, 기존 라우트 동작(`GET /profile`, `PATCH /profile/settings`, careers sync).

## 제약
- 복구 코드 원문·해시를 로그에 남기지 않는다. 로그에는 `profileId`와 결과 코드만.
- 시간은 기존 `now` 주입 방식을 따른다. `Date.now()` 직접 호출 금지.
- 커밋 메시지는 `T-1-004: …`로 시작, 브랜치는 `T-1-004-…`.
- 서브에이전트 리뷰를 띄우지 않는다. Orca PR 게이트용 `/review:pr` 1회만 예외(`/simplify`·병렬 fork 금지).
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
