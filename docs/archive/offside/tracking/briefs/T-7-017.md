# T-7-017: 확인된 E2E 검사 누락과 간헐 실패 수정

## 목표

운영 배포 코드에서 확인한 #190의 검사 누락과 #207의 실패를 원인에 맞게 수정하고 PR을 연다.

## 참조 명세

- 요구사항: SCR-010, SCR-012, SCR-029, TEST-E2E-004 및 D-70 테스트 완화 금지.
- CLAUDE.md, docs/tracking/README.md, 관련 기존 테스트를 읽는다.
- 운영 검증 SHA는 3640524ce97e4e6905123c139ddec009f071ff5c. 구현 기준은 최신 origin/main.

## 범위

- apps/web/e2e의 기존 테스트·헬퍼 수정. production 앱 코드가 원인으로 확정되면 근거와 좁은 수정 파일을 먼저 오케스트레이터에 보고한다.
- #190 SCR-012: KEEP 자동 수락으로 axe 없이 성공하는 경로를 없애고 실제 역할 변경 제안 화면에서 기존 a11y 검사가 수행되게 한다. 가능하면 고정된 도달 seed를 사용한다. assertion 축소·무조건 skip·오류 무시는 금지한다.
- #207: SCR-010 PlayerCard 진입 애니메이션이 끝난 상태에서 색 대비를 검사한다. 실제 색 대비 위반을 필터로 무시하지 않는다. CompareCards 두 번째 시즌 실패는 trace로 원인을 확인해 결정적인 준비 상태·정확한 상호작용으로 수정한다. force click·고정 sleep·일괄 timeout 상향으로 덮지 않는다.
- #190 충돌 대화상자·nineteen-kickoff 댓글의 흐름 문제는 ego-browser와 단독 실행으로 먼저 확인하고 원인이 확인되는 부분만 같은 범위에서 수정한다. 테스트용 mock·fixture는 가능하지만 실제 사용자 흐름을 왜곡하면 안 된다.
- #197 unit seed 탐색은 브라우저 대상이 아니다. 수정이 필요한 탐색 비용 문제가 있다면 기존 테스트 coverage·assertion을 보존하는 고정 seed 등 좁은 개선안을 보고한다. 비용 확인만으로 timeout 상향·skip·전역 동시성 설정 변경은 하지 않는다.
- 공용 product UI 문자열·domain/content/API·추적 보드·결정 로그를 수정하지 않는다.

## 완료 조건

- 기존 관련 테스트의 assertion을 보존하며 수정한다. D-61: 새로운 테스트 추가 없이 기존 테스트·헬퍼 갱신.
- ego-browser 스킬을 통해 관련 클릭·상태 흐름을 직접 관찰한다. Playwright 반복 실행은 원인 검증·회귀 확인을 위해 함께 사용한다.
- #207은 workers=1, repeat-each=3 이상으로 수정 전·후를 비교하고 결과를 수치로 보고한다. 관련 #190도 실제 검사 실행을 확인한다.
- 필요한 lint·typecheck 및 관련 테스트 통과, 단일 패스 자체 리뷰, 최신 main 동기화 뒤 commit/push/PR까지. merge·배포·이슈 별도 종료는 하지 않는다.
