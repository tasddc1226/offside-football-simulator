# T-4-002: 결정론적 부상·재활·재발·후유증 모델과 career-12 fixture (domain + content)

## 목표

T-4-001의 항등 `onMatchInjury` 훅을 실제 부상 상태기계로 채운다. 경기 `injuredOff` 뒤 심각도·부위·결장 범위가 경기 RNG로 결정되고, MODERATE/MAJOR는 일반 슬롯보다 우선하는 INJURY pending을 열어 EARLY/STANDARD/CONSERVATIVE 재활을 고르게 한다. 복귀 뒤 정해진 창에서 재발을 결정론적으로 검사하고, 영구 능력 변화는 복귀 또는 재발이 확정되는 순간에만 적용한다. 시즌당 강제 결정 상한과 `career-12-injury` 재발 golden으로 이를 고정한다.

## 1. 발생과 우선 pending(D-49)

- `match.ts`는 기존 부상 **발생 여부** roll까지만 소유한다. 발생 시 구형 `matchRules.injury.outMatches` duration roll은 제거하고 `onMatchInjury`가 다음 고정 순서로 `matchRngState`를 소비한다: severity 1회 → bodyPart 1회 → matchesOut 1회. 이 변경으로 영향받은 golden은 revision/결정 RNG가 아니라 경기 RNG draws/hash 변화임을 표로 남긴다.
- 심각도 가중치는 `injuryRules.severityWeights`를 bp로 바꾼 뒤 위험 보정치를 MINOR에서 MODERATE/MAJOR로 이동한다. 위험 보정 bp = `max(0, durabilityPivot-durability) × severityShiftBpPerDurabilityPoint + (fitness < fitnessBelow ? fitnessAddBp : 0) + max(0, age-ageFrom) × ageAddBpPerYear`, 0..MINOR base bp로 clamp. 이동분 75%는 MODERATE, 나머지는 MAJOR(정수 floor 후 잔여는 MAJOR), 세 가중치 합은 정확히 10000. bodyPart는 배열 순서 weighted roll, 결장 확정값은 severity `matchesOut[min,max]` roll이다.
- 새 episode id는 `INJ-${seasonIndex}-${step}-${season 내 episode 순번}`. `diagnosisRange`는 룰셋 min/max, `recurrenceRiskBp`는 bodyPart base, status ACTIVE, rehab/permanentDelta null. availability는 확정 matchesOut, sinceMatchId는 발생 경기다. `INJURED` 타임라인을 남긴다.
- MINOR는 `STANDARD`를 자동 적용하고 pending을 만들지 않는다. MODERATE/MAJOR이며 `season.injuryCount < maxForcedPerSeason`이면 `injuryCount + 1`과 `{ kind:'INJURY', step, episodeId, eventId, version }` forced pending을 만든다. 상한 이후는 STANDARD 자동 처리하고 타임라인은 남기되 결정 수는 늘리지 않는다.
- content ID를 domain에 하드코딩하지 않도록 `injuryRules.event: { id:'EVT-INJ-001', version:1 }`을 domain/content ruleset 타입·strict schema·1.0.0 데이터에 추가한다.
- `PlayStepMatches` 결과에 `forcedPending`(null 또는 INJURY)을 추가하고 `walkToNextDecision`이 경기 직후, 일반 EVENT/CHAPTER/CONTRACT 슬롯보다 먼저 이를 연다. 한 step에 복수 후보면 경기 순서상 첫 MODERATE/MAJOR만 연다. 정상 경기/슬롯의 결정 RNG 소비는 바꾸지 않는다.
- wiring은 `injuryCount`를 closure 변수로 누적하고 getter로 season에 되돌린다. 현재처럼 매 호출에 `initial.injuryCount`를 넘겨 상한이 무력화되지 않게 테스트한다.

## 2. 재활·회복

- `EVT-INJ-001`을 0.1.0·0.2.0 모두 `presentation:'INJURY'`로 전환하고 세 choice에 A=`STANDARD`, B=`EARLY`, C=`CONSERVATIVE`의 `rehabPlan`을 붙인다. previewEffects에는 각 선택의 **복귀 경기 범위, recurrence bp 증감, 출전 기회 대가**가 선택 전에 읽히게 적는다. 기존 즉시 `PERMANENT` 효과는 제거한다. 0.2.0에서 문구를 바꾸면 `authoring:'PROTOTYPE'`, manifest는 계속 `playtested:false`다. 체크섬을 정상 재계산한다.
- `RESOLVE_EVENT`의 INJURY 분기는 `applyRehabPlan` 뒤 availability를 동기화한다. 선택별 확정 결장 수는 이동된 범위에서 EARLY=min, STANDARD=정수 중간값 `floor((min+max)/2)`, CONSERVATIVE=max. episode는 REHAB, availability는 INJURY/확정값이다. 이벤트 outcome roll은 기존처럼 결정 RNG 정확히 1회이며 재활 선택 자체는 추가 roll이 없다.
- 재발 창을 정확히 추적하기 위해 `InjuryEpisode`에 additive 정수 필드 `recurrenceChecksRemaining`(발생/재활 중 0, 복귀 시 `recurrenceWindowMatches`)을 추가하고 domain/contracts strict 스키마·기본 리터럴을 갱신한다. `schemaVersion`은 1 유지한다.
- 매 경기 전 availability가 INJURY였고 경기 처리 뒤 0이 되어 해제되면 해당 REHAB episode를 RECOVERED로 바꾸고 recurrenceChecksRemaining을 연다. 복귀 뒤 선수가 실제 출전한 경기마다, 신규 injury 판정 처리 전에 match RNG 1회로 recurrenceRiskBp를 검사하고 실패 시 counter를 1 감소한다. 성공 시 원 episode는 RECURRED, 같은 부위의 새 episode를 심각도 한 단계(MINOR→MODERATE→MAJOR, MAJOR 유지) 높여 만들고 duration 1회 roll, 같은 forced-pending/상한 규칙을 적용한다. 재발 성공 경기에서는 별도 신규 injury를 중복 생성하지 않는다.

## 3. 후유증 확정과 안전장치

- 후유증은 발생/재활 선택 시 적용하지 않는다. 일반 회복 확정 시 MAJOR만 bodyPart의 첫 `sequelaKeys`에 -1, 재발 확정 시 새 심각도가 MODERATE면 -1·MAJOR면 -2를 적용한다(키가 없으면 변화 없음). 1..99 clamp, `episode.permanentDelta`에 실제 적용 delta를 남긴다.
- 후유증 적용과 동시에 `player.profile.baseOvr`를 현재 archetype roleWeights로 재계산한다. truePotential·scouted range는 건드리지 않는다. 단일 부상/재발로 status를 RETIRED로 만들거나 커리어 진행을 막지 않는다.
- 복귀 첫 실제 출전 경기를 위한 `ChapterCandidateInput`은 현재 trigger 유니온에 맞는 최소 확장을 한다. 신규 trigger `INJURY_RETURN`(importance MINOR)을 추가해 회복 뒤 첫 출전 한 번만 후보로 내보내되, 실제 chapter 정의/화면은 T-4-005 범위이므로 후보가 없으면 정상 통과한다. 이 확장이 지나치게 공용 계약을 흔들면 후보 생성 함수와 테스트만 추가하고 PR 본문에 T-4-005 배선 항목으로 남긴다.

## 4. fixture·테스트

- `career-12-injury`: 기존 시즌 fixture 패턴을 복제하되 seed를 탐색해 MODERATE/MAJOR → 재활 선택 → RECOVERED → recurrence window 내 재발을 실제로 통과한다. seed 탐색 스크립트는 테스트에 넣지 말고 선택 근거 주석만 남긴다. domain fixture·`packages/fixtures` 미러·index export·contracts KNOWN 목록을 모두 등록한다.
- 단위/속성 테스트: 위험 보정 경계와 합 10000, roll 순서/draw delta, 5 bodyPart, MINOR 자동/중증 pending, 상한 2 이후 자동, 세 재활 duration/risk, recovery 상태, 재발 성공/실패/창 만료, severity 상승, 후유증 적용 시점, head sequela 없음, baseOvr 원자 갱신, 같은 입력 hash 동일.
- 기존 모든 golden에 대해 command revision과 결정 `rngState.draws` 불변을 확인하고 경기 RNG 변화는 PR 표에 분리한다. T-3-003의 market/loan 전환 의미가 바뀌지 않아야 한다.
