# T-4-008: Phase 4 콘텐츠 확장 — 팩 0.3.0(0.2.0 + 부상·관계·감독·미디어·슬럼프·윤리·대표팀 이벤트, 포지션 전용 챕터) (content)

## 목표

Phase 4 화면(T-4-005)과 통합 검증(T-4-006)이 프로토타입 한 개씩이 아니라 실제 콘텐츠 풀 위에서 돌도록, [이벤트 카탈로그](../../content/kickoff/event-catalog.md) 후보를 JSON으로 승격해 **새 팩 `0.3.0`**(= 0.2.0 전체 복사 + 확장)을 만든다. 0.1.0·0.2.0은 바이트 하나도 바꾸지 않는다(활성 팩 0.1.0은 LINE TEST 기준선, 0.2.0은 T-4-006 통합 fixture가 병행 사용 중). 스키마·조건 DSL·룰셋·domain 변경은 없다.

## 0. 시작 전 확인과 정지 규칙

- `presentation-events.ts`와 `select-eligible-events.ts`를 읽어 어떤 presentation이 일반 EVENT 슬롯에서 선택되는지(SLUMP·LOCKER_ROOM·ETHICS·MEDIA), 어떤 것이 전용 생성기만 여는지(INJURY·NATIONAL_TEAM·RUMOUR) 확인해 PR 본문에 적는다. 전용 생성기가 룰셋의 고정 `event`(예: `injuryRules.event`, `nationalTeamRules.event`)로만 여는 presentation에는 **같은 presentation의 두 번째 이벤트를 만들지 않는다**(도달 불가). 그 주제는 일반 이벤트(presentation 없음 또는 슬롯 선택 가능한 presentation)로 만든다.
- 조건 DSL 화이트리스트에 없는 필드가 필요하면 만들지 말고 PR 본문 "DSL 후속" 표에 적는다. 스키마(`src/schema/*`)·runtime·domain을 고쳐야만 되는 항목은 빼고 이유를 적는다.

## 1. 팩 0.3.0 구성

- `packs/0.3.0` = 0.2.0의 events·chapters·manifest 복사 + 아래 추가. `PACK_VERSIONS`에 `'0.3.0'` 등록, 레지스트리·`load-content-pack.test.ts`·`packs/0.3.0/pack.test.ts` 추가. manifest는 `compatibleRulesetVersions` 1.0.0, `playtested:false`, checksum은 CLI로 재계산. 활성 팩 상수(`apps/web`·`CONTENT_VERSION`)는 건드리지 않는다.
- 추가 이벤트(카탈로그 ID를 그대로 쓰고, 이미 0.2.0에 있는 ID는 재사용하지 않는다). 각 항목은 카탈로그의 트리거·선택·효과 의도를 따르되 수치는 0.2.0 같은 계열 이벤트와 같은 크기 범위로 맞춘다:
  - 부상·재활(EVENT 슬롯, presentation 없음): `EVT-INJ-003` 머리 충돌(안전 우선 고정 — 세 선택 모두 검사하며 시점·팀 손실만 다름, 규정 거부 선택 없음), `EVT-INJ-004` 재발 징후(과거 부상·조기 복귀 조건, 휴식/제한 출전/완전 출전 → fitness·form CURRENT, 태그). `HEALTH` kind Effect는 쓰지 않는다(ADR-010: T-4-002 재활만).
  - 관계·라커룸: `EVT-REL-003` 주장 멘토링(주장 관계 60+·젊은 선수), `EVT-REL-005` 연패·역할 갈등 라커룸 발언(presentation `LOCKER_ROOM`), `EVT-REL-008` 에이전트 불만(agent 축).
  - 감독: `EVT-MGR-003` 출전 약속 미달 면담(`contract.promiseBreaches`, 0.2.0 `EVT-CON-012`와 트리거·cooldown이 겹치지 않게 step 조건을 다르게), `EVT-MGR-004` 감독 교체 적응(`season.manager.tenureSeasons` 0 등 DSL로 교체 직후 판정).
  - 슬럼프: `EVT-SLUMP-011` 장기 슬럼프(SLUMP, `recentFormAvg` 더 낮은 임계·cooldown 시즌).
  - 윤리·위기: `EVT-ETH-011` 1종(ETHICS). FAIL outcome에는 반드시 회복 경로(후속 이벤트 예약 또는 Effect 만료)가 있어야 한다(outcome 검증기).
  - 미디어·팬: 카탈로그 7절 후보 중 0.2.0에 없는 2종(MEDIA). 외부 SNS 전송을 암시하는 문구 금지.
  - 대표팀: `EVT-NAT-002` 국제대회 직전 조율 — 0절 확인 결과 NATIONAL_TEAM presentation이 전용 생성기 전용이면 presentation 없는 일반 이벤트로 만들고 `대표팀_소집` 태그 조건을 쓴다.
- 포지션 전용 챕터 3종(SCR-023 경기 판단 변형, 백로그 Wave 2): `positionGroups`를 각각 다르게 둔 MATCH 챕터(예: GK 빌드업/롱킥, DF 라인 컨트롤/파울, FW 돌파/연결/공간 창출)를 기존 `ChapterTriggerSchema`의 kind만으로 정의한다(새 trigger kind 금지). 같은 장면이 모든 포지션군에 같은 선택지로 나오지 않아야 하며 이름만 바꾼 동일 choice 세트는 금지(백로그 규칙).
- 공통 규칙: 실제 구단·선수·감독 실명 금지, `safety.minorSafe` 표기, `authoring:'PROTOTYPE'`, 서사 토큰은 허용 토큰만, choice마다 `previewEffects` ≥ 1·`riskLabel`, outcome Effect는 ADR-010 표의 타깃만(RELATION은 관계·평판 축만, attribute 타깃 금지), `stackingRule`·`clamp` 명시, cooldown·weight는 카탈로그 "노출 밀도" 절을 따른다.

## 2. 테스트·인수 조건

- `pnpm --filter @offside/content content:validate`(0.1.0·0.2.0·0.3.0 전부)와 content 단위 테스트 통과. `packs/0.3.0/pack.test.ts`에 이벤트·챕터 수, presentation별 수, 포지션군별 챕터 존재, FAIL 회복 경로, 토큰 검증을 둔다.
- 0.1.0·0.2.0 파일 무변경: `git diff --stat origin/main -- packages/content/packs/0.1.0 packages/content/packs/0.2.0`이 비어 있어야 한다. 기존 golden hash 전부 불변.
- 도달성 증거: `@offside/domain`·`@offside/content`를 Node로 직접 돌리는 스크립트(테스트 파일 안, 예: `packs/0.3.0/reachability.test.ts`)로 seed 500개 × 2시즌 안에서 새 이벤트 각각이 최소 1회 선택되는지 세어 표로 적는다. 0회인 이벤트는 트리거를 손보거나 "미도달·사유"로 적는다.
- 전체 체인: `pnpm install --frozen-lockfile && pnpm lint && pnpm lint:deps && pnpm typecheck && pnpm content:validate && pnpm test && pnpm build`. web e2e는 이 작업이 web을 바꾸지 않으므로 생략하되, `pnpm --filter @offside/web typecheck`·`test`가 통과해야 한다(팩 레지스트리 타입이 web에 노출된다).
