# T-2-015: 분석 이벤트 삽입 D1 변수 상한 청크·알 수 없는 오류 메시지 고정·온보딩 LINE TEST 안내 (api + web)

## 목표

T-2-012(PR #49) staging 예행(2026-09-04)에서 찾은 결함 3건을 LINE TEST(09-08) 전에 닫는다. 새 기능 없음.

1. **`POST /v1/analytics/events`가 20건 배치에서 503**: D1은 문장당 바인딩 변수 100개가 상한인데 `insertAnalyticsEvents`가 모든 행을 한 `INSERT … VALUES (…),(…)`로 넣는다(7열 × 20행 = 140). 웹 큐가 20건마다 비우므로 활발한 플레이일수록 이벤트가 통째로 유실된다. 14행(98 변수)은 성공, 15행부터 실패(staging curl로 확인).
2. **알 수 없는 오류의 응답 본문에 SQL 전문 노출**: `toErrorEnvelope`가 `err.message`를 그대로 내보내 `Failed query: insert into "analytics_events" (…)`가 클라이언트에 갔다.
3. **빈 기기의 온보딩(SCR-034)에 테스트 시즌 안내가 없다**: 허브 배너는 커리어가 있어야 보이는데 새 테스터는 온보딩으로 리다이렉트된다.

## 구현

### 1. 청크 삽입 (`apps/api/src/db/repos/analyticsEvents.ts`)

- 상수 `ANALYTICS_INSERT_CHUNK_ROWS = 14`(주석: D1 문장당 바인딩 변수 100개 ÷ 7열 = 14행). 열을 늘리면 상수를 같이 낮추라는 주석.
- `inputs`를 14행씩 잘라 순차 `db.insert(...).values(chunk)`. 원자성 불필요(분석 데이터, 재시도 없음) — 앞 청크가 들어간 뒤 뒤 청크가 실패해도 되돌리지 않는다. `db.batch`는 쓰지 않는다(D1 batch도 문장별 상한이 같다).
- 테스트 `analyticsEvents.test.ts`(신규): Miniflare 로컬 SQLite는 이 상한을 재현하지 않으므로 **재현 시도 금지**. 대신 `db.insert`를 spy/wrap해 50건 입력 → 문장 4개(14·14·14·8), 1건 → 1개, 0건 → 0개를 단언. 기존 `routes/analytics.test.ts`의 50건 → 202 케이스는 그대로 통과해야 한다.

### 2. 오류 메시지 고정 (`apps/api/src/errors.ts`, `middleware/logger.ts`)

- unknown error(AppError 아님)의 응답 `message`는 고정 문구 `'일시적인 오류입니다. 잠시 후 다시 시도해 주세요.'`. 원래 `err.message`는 로거 엔트리 `errorMessage`(없으면 추가, 500자 절단)로만 남긴다.
- 테스트: `errors.test.ts`(있으면 추가, 없으면 신규) — `new Error('Failed query: insert …')` → 503, body.message가 고정 문구이고 `'insert'`를 포함하지 않는다.

### 3. 온보딩 안내 (`apps/web/src/routes/onboarding.tsx`)

- `useServiceSeason()`의 `data?.notice === 'LINE_TEST'`일 때 첫 슬라이드 아래(다음 버튼 위) caption 한 줄로 `SERVICE_SEASON_NOTICE_KO.LINE_TEST`를 보인다. `data-testid="onboarding-service-season-notice"`. 조회 실패·로딩이면 아무것도 보이지 않는다(허브와 같은 규칙). 캐러셀 구조·버튼 순서는 바꾸지 않는다.
- e2e `apps/web/e2e/service-season.spec.ts` 스텁 모드에 1건 추가: 테스트 시즌 응답 → `/onboarding`에서 안내가 보이고 axe serious/critical 0. 포트 **5193**.
