# T-0-013 — Pretendard dynamic subset 전환과 허브 LCP 측정

> 상태: todo → 워커 배정 시 in-progress. 브랜치 `T-0-013-font-dynamic-subset`. 선행: 없음(T-0-009 후속).

## 목표

현재 `packages/ui/src/tokens.css`가 `pretendard/dist/web/variable/woff2/PretendardVariable.woff2`(약 2MB) 하나를 `@font-face`로 싣는다. 첫 화면에서 2MB 폰트를 받는 것은 01 성능 예산(허브 LCP 2.5초, 3G급 회선 기준)에 맞지 않는다. `pretendard` 패키지가 제공하는 **dynamic subset**(unicode-range로 쪼갠 woff2 100여 개, 브라우저가 화면에 있는 글자 범위만 받음)으로 바꾸고, 폴백 폰트 메트릭을 맞춰(13 구현 체크리스트 "font-display: swap과 폴백 폰트 메트릭") 레이아웃 시프트를 줄이고, 허브 LCP를 측정해 기록한다.

## 범위

만질 경로: `packages/ui/src/tokens.css`(`@font-face` 블록만. 토큰 값은 13 문서와 동일해야 하며 변경 금지), `packages/ui/src/fonts.css`(신설 가능), `packages/ui/package.json`(exports), `apps/web/vite.config.ts`(정적 자산 처리 필요 시), `apps/web/scripts/check-bundle.mjs`(폰트 예산 추가), `apps/web/package.json`(scripts), `docs/`는 만지지 않는다(측정값은 PR 본문에).

새 의존성: 없음이 원칙. Lighthouse 측정은 `npx lighthouse`(전역 설치 없이 dlx) 1회 실행으로 하고 devDependency로 넣지 않는다.

## 설계 결정(변경 금지. 의문이 있으면 질문)

1. **subset CSS를 그대로 쓰지 않는다.** `pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css`는 100여 개 `@font-face`를 담고 있고 `src` 경로가 패키지 상대 경로다. 이 파일을 `packages/ui/src/fonts.css`로 **복사해** `src: url(...)`을 Vite가 해석할 수 있는 경로(`pretendard/dist/web/variable/woff2-dynamic-subset/...` 패키지 import 또는 `../node_modules/...` 상대 경로 중 현재 tokens.css와 같은 방식)로 바꾼다. 파일 상단에 출처·버전(`pretendard 1.3.9`)·재생성 방법을 주석으로 적는다. `font-display: swap`, `font-weight: 45 920` 유지.
2. **폴백 메트릭.** `@font-face { font-family: 'Pretendard Fallback'; src: local('Apple SD Gothic Neo'), local('Malgun Gothic'), local('Noto Sans KR'); size-adjust / ascent-override / descent-override / line-gap-override }`를 추가하고 `--os-font` 스택에서 `'Pretendard Variable'` 바로 뒤에 둔다. 값은 Pretendard Variable의 메트릭(unitsPerEm 1000, ascender 1000, descender −250 계열)에 맞춰 계산하고 계산 근거를 주석에 적는다. **`--os-font` 순서 외 다른 토큰은 손대지 않는다.**
3. **tokens.css는 fonts.css를 import하지 않는다.** `packages/ui/package.json` exports에 `./fonts.css`를 추가하고 `apps/web/src/main.tsx`에서 `@offside/ui/fonts.css`를 `tailwind.css`보다 먼저 import한다(폰트 선언과 토큰의 분리, 앱인토스 채널에서 다른 폰트 전략을 쓸 여지).
4. **빌드 산출물 확인.** `pnpm --filter @offside/web build` 후 `dist/assets`에 subset woff2가 개별 파일로 나오고 2MB 단일 파일이 **없어야** 한다. `check-bundle.mjs`에 "woff2 파일 하나가 200KB를 넘으면 실패"와 "초기 HTML+CSS에서 preload되는 폰트 합 100KB 이하"를 추가한다(기존 JS 300KB 예산은 유지).
5. **측정.** `pnpm --filter @offside/web build && pnpm --filter @offside/web preview`로 띄운 뒤 Lighthouse(모바일 프리셋, 기본 4G 스로틀 + 한 번은 `--throttling.downloadThroughputKbps=1600 --throttling.rttMs=150`의 느린 3G 급)로 허브(`/`)를 3회씩 측정해 **변경 전/후** LCP·CLS·전송 바이트를 PR 본문 표로 적는다. 목표: 느린 회선에서 LCP 2.5초 이하, CLS 0.1 이하. 미달이면 원인(폰트 외 요인 포함)을 적고 멈추지 말고 PR을 연다(예산 재조정은 오케스트레이터 결정).
6. 숫자 요소 `font-variant-numeric: tabular-nums`(13 MUST)는 subset 전환 후에도 유지되는지 허브 화면에서 확인한다(Variable 폰트 subset이 `tnum` 피처를 보존하는지 스크린샷 1장).
