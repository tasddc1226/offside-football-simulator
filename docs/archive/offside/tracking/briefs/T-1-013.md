# T-1-013: Google OIDC 연결(start/callback/merge/unlink)·SCR-030 Google 행·병합 선택 (실검증은 U-003 뒤)

## 목표
web 채널 사용자가 설정에서 Google로 프로필을 연결하고, 다른 브라우저에서 Google 로그인으로 같은 프로필을 되찾는다. Google이 이미 다른 프로필에 연결돼 있으면 ADR-008 병합 규칙대로 "옮기기 / 그 프로필만 사용"을 고른다. 실제 Google 계정 검증은 U-003(클라이언트 ID·시크릿) 뒤에 하고, 그 전에는 가짜 OIDC로 전 흐름을 검사한다.

## 범위
- 만질 경로: `apps/api/**`(라우트·auth·db repos·migration·seeds·wrangler vars·테스트), `packages/contracts/src/auth.ts`·`index.ts`(스키마 추가만), `packages/platform/src/**`(`features` 추가), `apps/web/src/**`, `apps/web/e2e/**`. 그 외 금지.
- 만들 것:
  1. **의존성** `arctic`(정확한 버전 고정, 최근 7일 이내 배포판 금지 — 게시일을 `npm view arctic time`으로 확인해 PR 본문에 적는다). Bindings 추가: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`(secret), `GOOGLE_REDIRECT_URI`, `WEB_APP_URL`, `GOOGLE_FAKE`(로컬 전용 `'1'`). `wrangler.jsonc` `vars`에 로컬 값(`WEB_APP_URL: http://localhost:5173`, `GOOGLE_REDIRECT_URI: http://localhost:8787/v1/auth/google/callback`, `GOOGLE_FAKE: '1'`), 시크릿은 넣지 않는다. `.dev.vars.example` 파일에 키 이름만.
  2. **OIDC 포트** `apps/api/src/auth/google-oidc.ts`:
     ```ts
     export interface GoogleOidc {
       createAuthorizationUrl(state: string, codeVerifier: string): URL;
       exchangeCode(code: string, codeVerifier: string): Promise<{ sub: string; email: string | null; emailVerified: boolean }>;
     }
     export function createArcticGoogleOidc(env: Pick<Bindings, 'GOOGLE_CLIENT_ID' | 'GOOGLE_CLIENT_SECRET' | 'GOOGLE_REDIRECT_URI'>): GoogleOidc;
     export function createFakeGoogleOidc(): GoogleOidc; // start는 콜백으로 바로 리다이렉트하는 URL, code 'fake:<sub>'를 sub·email로 해석
     ```
     arctic 구현: scopes `['openid', 'email']`, PKCE S256, `decodeIdToken`으로 `sub`·`email`·`email_verified`를 읽고 `iss`(`https://accounts.google.com`)·`aud`(클라이언트 ID)·`exp`를 검사한다(토큰 엔드포인트와 직접 TLS 통신이므로 서명 검증은 하지 않는다 — OIDC Core 3.1.3.7 비고. 주석에 적는다). 선택은 `ENVIRONMENT === 'local' && GOOGLE_FAKE === '1'`이면 fake, 아니면 arctic. arctic인데 `GOOGLE_CLIENT_ID`가 비어 있으면 start가 503 `SERVICE_UNAVAILABLE`(앱은 U-003 없이도 뜬다).
  3. **라우트** `apps/api/src/routes/auth.ts`에 추가(전부 `requireProfile`):
     - `GET /v1/auth/google/start`: `state`·`codeVerifier`를 `crypto.getRandomValues` 32바이트 base64url로 만들고 쿠키 `offside_oauth`(HttpOnly·Secure(로컬은 제외)·SameSite=Lax·Path=/v1/auth/google·Max-Age 600, 값은 `state.codeVerifier`)에 둔 뒤 302. rate limit `auth_attempts` kind `GOOGLE_START`, subject `ip`, 시간당 30회 → 429.
     - `GET /v1/auth/google/callback?code&state`: 쿠키의 state와 다르면 `WEB_APP_URL/settings?google=error&reason=state`로 302. 교환 실패도 `reason=exchange`. 성공하면 ADR-008 표대로: `google_sub`로 삭제되지 않은 프로필 B를 찾는다. 없거나 B가 현재 프로필 A → A에 `google_sub`·`email`·`linked_at` 기록(이미 같은 값이면 그대로) → `?google=linked`. B가 있고 A≠B: A에 커리어가 0개면 세션을 B로 재바인딩 → `?google=switched`. 커리어가 있으면 `sessions.pending_merge_profile_id = B.id`, `pending_merge_expires_at = now+10분` 기록 → `?google=merge_required&current=<n>&target=<m>`. 쿠키는 항상 지운다. 감사 로그 `GOOGLE_LINKED { profileId, emailDomain }`(이메일 전체는 넣지 않는다).
     - `POST /v1/auth/merge` 본문 `{ mergeChoice }`(contracts `MergeChoiceSchema`): 세션에 유효한 pending merge가 없으면 409 `MERGE_REQUIRED`가 아니라 400 `VALIDATION_FAILED { reason: 'NO_PENDING_MERGE' }`. `MOVE_TO_LINKED`면 `recover.ts`의 배치와 같은 이동(공통 함수 `apps/api/src/profile/merge.ts`의 `moveCareersAndRebind(db, { fromProfileId, toProfileId, sessionId, now })`로 뽑아 recover.ts도 그것을 쓰게 리팩터. 동작·테스트 불변), `KEEP_LINKED_ONLY`면 재바인딩만. 둘 다 pending을 지운다. 응답 `{ profileId, careerCount }`(contracts `MergeResponseSchema` 신설 = `RecoverProfileResponseSchema`와 같은 형태).
     - `POST /v1/auth/google/unlink`(API-AUTH-006): 현재 프로필의 `google_sub`·`email`·`linked_at`을 null로. 204. 감사 로그 `GOOGLE_UNLINKED`.
     - 프로필 삭제(`executeProfileDeletion`)가 `google_sub`·`email`·`linked_at`도 null로 만들게 고친다(unique index가 재연결을 막던 후속 과제).
  4. **migration** `0002_*.sql`: `sessions.pending_merge_profile_id text`, `sessions.pending_merge_expires_at text`. `auth_attempts.kind`·`audit_log.kind`의 drizzle enum에 값 추가(SQLite에는 CHECK가 없으므로 컬럼 변경 없음. `db:check`로 확인). `GET /v1/profile` 응답의 `linked.google`은 이미 있고, `email`은 응답에 넣지 않는다(ADR-008 "표시와 문의 확인"은 Phase 1 화면에서 이메일 도메인만 보여 준다 → `ProfileSchema`에 `googleEmailMasked: string | null` 추가: `a***@gmail.com` 형태, 첫 글자 + `***` + `@도메인`).
  5. **platform** `Platform.features: { googleLink: boolean }` 추가(web true, toss false). 화면은 이 값으로만 Google 행을 숨긴다(채널 리터럴 비교 금지).
  6. **web SCR-030 Google 행**(T-1-012가 둔 "준비 중" 행을 채운다. `platform.features.googleLink`가 false면 행 자체를 렌더하지 않고 "토스 계정으로 자동 저장 중"을 대신 보여 준다): 연결 안 됨 → "Google로 연결" 버튼(`platform.openExternal(`${API_BASE_URL}/v1/auth/google/start`)`, 같은 탭 이동). 연결됨 → 마스킹 이메일 + "연결 해제"(확인 대화상자: 복구 코드가 없으면 "복구 코드도 없어서 이 브라우저 데이터를 잃으면 되찾을 수 없습니다" 경고 포함) → `POST /auth/google/unlink` → `['profile']` 무효화. 설정 화면 진입 시 `?google=` 쿼리 처리: `linked` 토스트 "Google을 연결했습니다", `switched` → T-1-012의 대조(`reconcileAfterRecovery('NONE')`) 뒤 토스트 "Google에 연결된 프로필로 바꿨습니다", `merge_required` → T-1-012의 선택 대화상자를 Google 문구로 재사용("이 기기의 커리어 n개를 Google 프로필로 옮기기" / "Google 프로필(커리어 m개)만 사용") → `POST /auth/merge` → 대조(`MOVE_TO_LINKED`→`'MOVE_TO_LINKED'`, `KEEP_LINKED_ONLY`→`'KEEP_LINKED_ONLY'`) → 토스트, `error` → 원인별 문장. 처리 뒤 쿼리는 `history.replaceState`로 지운다. 대화상자에서 "취소"하면 pending은 서버에서 10분 뒤 만료된다(그때까지 설정 진입 시 다시 물어본다: `GET /v1/profile`에 `pendingMerge: { targetCareerCount } | null` 추가).
  7. **분석**: `google_link_started`, `google_link_result { result: 'linked' | 'switched' | 'merge_required' | 'error' }`, `google_merge_resolved { mergeChoice }`, `google_unlinked`. 이메일·sub 금지.
  8. **테스트(api, Miniflare)**: start가 쿠키·302·PKCE 파라미터(`code_challenge_method=S256`)를 낸다; state 불일치 → error 리다이렉트 + 쿠키 삭제; 처음 보는 sub → A에 연결; 같은 sub가 B에 있고 A 커리어 0 → switched + 세션 profileId B; A 커리어 1 이상 → merge_required + pending 기록; merge MOVE → 커리어 이동·감사 로그·pending 삭제; merge KEEP → 재바인딩; pending 만료 뒤 merge → 400; unlink → null; 삭제된 프로필의 sub로 재연결 가능; rate limit 31회째 429; 클라이언트 ID 없음 → 503. 전부 `createFakeGoogleOidc` 또는 `fetch` 주입으로 arctic 토큰 엔드포인트를 가짜로 둔다(실 네트워크 0).
  9. **E2E** `apps/web/e2e/google-link.spec.ts`(`E2E_WITH_API=1`, `GOOGLE_FAKE=1`인 로컬 api): 설정 → "Google로 연결" → 콜백 → "Google을 연결했습니다" → 행이 연결됨으로; 두 번째 컨텍스트에서 커리어를 만든 뒤 같은 가짜 sub로 연결 → 병합 대화상자 → 옮기기 → 허브에 두 커리어. 스텁 버전(`page.route`)으로 `?google=merge_required` 진입 → 대화상자 → `POST /auth/merge` 호출 확인. `a11y.spec.ts`에 대화상자 추가.

## 제약
- 이메일 전체·`google_sub`·토큰을 로그·분석·오류 details에 남기지 않는다. 로거 스크러빙 규칙이 있으면 따른다.
- `'toss'`·`'web'` 리터럴 비교 금지(lint), hex 색 리터럴 금지, 토큰(`--os-*`)만. 모든 사용자 문구는 한국어, 브랜드 어휘 금지.
- 새 의존성은 `arctic` 하나. `minimumReleaseAgeExclude`를 추가하지 않는다.
- 커밋 메시지는 `T-1-013: …`로 시작, 브랜치는 `T-1-013-…`.
- 서브에이전트 리뷰를 띄우지 않는다. gstack `/review`·`/codex`·adversarial 리뷰·`/simplify`·병렬 fork 전부 금지. 유일한 예외는 Orca PR 게이트용 `/review:pr` 1회(로컬 모드)다. 리뷰는 오케스트레이터가 한다.
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.

## 오케스트레이터 보충 (2026-09-03)

- **선행**: T-1-012(PR #31)가 main에 머지됐다. `origin/main`에서 시작한다(dispatch 스크립트가 그렇게 만든다).
- **동시 작업**: T-1-016(선수 성별·선호 포지션: `packages/domain`, `packages/contracts`의 player·career-state 스키마, fixtures, web SCR-002/003/004)이 병렬로 진행 중이다. 이 작업은 `packages/contracts/src/auth.ts`·`index.ts`(추가만)와 프로필 스키마만 만지고 player·career-state·fixtures는 건드리지 않는다. `apps/web/src/routes/settings.tsx`는 이 작업만 만진다. `apps/web/e2e/a11y.spec.ts`는 항목 추가만.
