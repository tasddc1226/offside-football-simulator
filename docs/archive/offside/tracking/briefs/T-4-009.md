## 1. D-56 DEV 팩 오버라이드

- `versions.ts`에 `resolveActiveContentPackVersion(): string`을 추가한다. `import.meta.env.DEV`이고 `localStorage['offside:e2e-content-pack']`이 `PACK_VERSIONS`에 있으면 그 값을, 아니면 `ACTIVE_CONTENT_PACK_VERSION`을 돌려준다. `localStorage` 접근은 e2e-seed 훅처럼 존재 검사 뒤에만 한다.
- `engine.ts`의 엔진 팩 로딩과 `content.ts`의 싱글턴이 **같은 함수**를 쓰게 한다(두 값이 어긋나면 화면이 다른 팩의 정의를 읽는다). Web Worker 쪽에서 팩을 따로 고른다면 그 경로도 같은 값을 받도록 메시지에 팩 버전을 실어 보낸다 — 어디서 팩을 고르는지 먼저 추적해 PR 본문에 표로 적는다.
- 오버라이드로 만든 새 커리어는 `contentPackVersion`에 그 팩을 저장하고, 기존 커리어 replay·import·동기화는 저장된 자기 팩으로 계속 동작한다(단위 테스트: 0.1.0 커리어 + 오버라이드 0.2.0 상태에서 replay hash 불변). 설정·확정 화면의 팩 표시(`ACTIVE_CONTENT_PACK_VERSION` 직접 참조 2곳)는 실제 엔진 값을 따르게 한다 — 라우트 파일 편집이 필요하면 **그 두 줄만** 바꾼다.
- 프로덕션 번들에서 죽은 코드가 되는지 `pnpm --filter @offside/web build` 산출물에서 `offside:e2e-content-pack` 문자열 grep으로 확인해 PR 본문에 적는다.

## 2. 라벨 함수(`shared/labels.ts`)

- 관계 축 5종의 방향(최근 `relationshipLog`에서 축별 delta 합 부호 → ↑/→/↓)·단계 라벨(0~100 → 5단계, 경계는 상수), 인기·미디어 단계 라벨(`popularityCenti`·`mediaCenti`), 부상 부위·심각도·재활 계획·회복 상태 라벨, 대표팀 `callUp` 라벨, 감독 신뢰 단계, Effect 만료 시점 라벨(`expiresAt` → "두 step 뒤 만료" 등). 전부 순수 함수 + 단위 테스트. 룰셋 상수를 새로 만들지 않는다.
- 폐기 어휘(`VAR CHECK` 등)·하위 백분위 표현·Base OVR 감소 문구를 만들지 않는다.

## 3. seed 탐색 도구와 도달성 보고

- `apps/web/e2e/helpers/find-seed.ts`(개발용, Playwright 실행 경로·번들에 포함하지 않음): 인자로 팩 버전·목표 presentation(또는 eventId)·최대 시즌 수·seed 범위를 받아 브라우저 밖에서 `@offside/domain`·`@offside/content`를 직접 돌린다. e2e helper가 실제로 보내는 명령 순서(온보딩 → 선수 생성 → 진로 → 입단 테스트 → 첫 계약 → 프리시즌 → 시즌 진행, 결정은 항상 첫 선택지)를 재현하고, 목표 pending이 열리는 seed·시즌·step·eventId를 출력한다. `offside:e2e-seed`의 문자열 seed 해시(FNV-1a)와 같은 방식이어야 브라우저에서 같은 경로가 재현된다 — 기존 `seedDeterministicChapterRun`의 seed로 도구를 검증한다(같은 챕터가 같은 step에서 열려야 함).
- 도달성 보고(PR 본문): 0.2.0(과 main에 0.3.0이 있으면 0.3.0도)에서 presentation 7종(INJURY·SLUMP·LOCKER_ROOM·ETHICS·MEDIA·NATIONAL_TEAM·RUMOUR) 각각의 도달 seed·시즌·step·eventId, 탐색 한도(시즌 2·seed 2,000)와 미도달 사유. 찾은 seed는 `apps/web/e2e/helpers/phase4-seeds.ts` 상수로 저장한다(T-4-005 e2e가 그대로 쓴다).
- 도구·상수는 `pnpm --filter @offside/web typecheck`·`lint`에 포함되되 e2e 실행에는 영향이 없어야 한다.
