# T-2-016: staging 리허설 자동화 커밋 — `playwright.staging.config.ts`·`staging-rehearsal.spec.ts` (web e2e)

## 목표

오케스트레이터가 LINE TEST 준비(U-016) 때 임시 worktree에서만 돌리던 staging 리허설(온보딩 → 선수 생성 → 첫 계약 → 시즌 결산 → 분석 이벤트 확인, `/onboarding` LINE TEST 안내 확인)을 저장소에 커밋해 누구나 `pnpm --filter @offside/web e2e:staging`으로 실제 staging(https://offside-web-staging.tasddc1569.workers.dev)에 대해 재실행할 수 있게 한다. 기본 `pnpm e2e`·CI에는 포함되지 않는다.

## 참조·선행

- 원본 파일(오케스트레이터 작업, 저장소 밖): `<로컬 임시 폴더>`, 같은 경로의 `e2e/staging-rehearsal.spec.ts`. 이 두 파일을 읽어 옮기되 현재 main의 helper·라우트 문구에 맞게 고친다(원본은 `5462dc7` 시점).
- 정본: [LINE TEST 계획](../line-test-plan.md), [T-2-012](T-2-012.md)(서비스 시즌·분석 이벤트), `apps/web/e2e/README.md`(실행 규칙), `apps/web/playwright.config.ts`.
- 선행 없음. T-4-007과 `apps/web/e2e/helpers`를 공유할 수 있으므로 helper는 **수정하지 않고** 필요한 동작은 spec 안에 둔다.

## 1. 작업

- `apps/web/playwright.staging.config.ts`: `baseURL`을 env(`E2E_STAGING_URL`, 기본 staging 주소)로, webServer 없음, `testMatch`는 `staging-rehearsal.spec.ts`만, 모바일 뷰포트·`reducedMotion`은 기본 config와 같게. 실제 서비스에 붙으므로 workers 1, retries 0.
- `apps/web/e2e/staging-rehearsal.spec.ts`: (a) 새 기기 → 온보딩 → 선수 생성 → 진로 → 입단 테스트 → 첫 계약 → FAST 시즌 완주 → 결산 화면, (b) `/onboarding`에 LINE TEST 안내 문구, (c) 생성한 careerId·deviceId를 콘솔과 테스트 attachment에 남긴다(오케스트레이터가 D1 synthetic 행을 정리한다). 실패 시 trace 유지.
- `apps/web/package.json`에 `e2e:staging` 스크립트 추가(`playwright test --config playwright.staging.config.ts`). `apps/web/e2e/README.md`에 실행 절과 "staging에 실제 데이터가 생긴다·정리 절차" 문단 추가.
- 로컬에서 `pnpm --filter @offside/web e2e:staging`을 **1회** 실행해 결과(통과 여부·소요 시간·생성된 careerId)를 PR 본문에 적는다. 실패하면 문구·selector를 현재 main에 맞게 고친다. 두 번 이상 돌리지 않는다.

## 2. 인수 조건

- `pnpm lint && pnpm typecheck && pnpm --filter @offside/web test` 통과, 기본 `E2E_PORT=5211 pnpm --filter @offside/web e2e`가 새 spec을 **실행하지 않고** 그대로 통과(testMatch·testIgnore로 분리).
- staging 1회 실행 결과가 PR 본문에 있다.
