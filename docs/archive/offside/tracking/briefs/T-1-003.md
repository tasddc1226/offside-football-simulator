# T-1-003: ui 컴포넌트 키트 — Radix 래핑과 Phase 1 화면 부품

## 목표
Phase 1 화면(선수 만들기·진로 선택·입단 테스트·제안 비교·계약·대시보드)이 쓰는 부품이 `@offside/ui`에 접근성·토큰 규칙을 지킨 채 준비된다. 화면 자체는 만들지 않는다.

## 참조 명세
- 요구사항 ID: FR-DSN-001, FR-ONB-001(부품만), TEST-E2E-009(접근성 기준의 부품 측면)
- 읽어야 할 문서(순서대로): `docs/development/13-visual-design-system.md`(컴포넌트 명세·상태·크기), `docs/development/06-ui-ux-specification.md`(잠금 표시·선택지·비교 카드 동작), `docs/development/12-brand-guidelines.md`, `docs/screens/01-career-start.md`, `docs/screens/02-season-flow.md`, `docs/screens/03-career-events.md`, `docs/screens/05-hub-and-support.md`, `docs/tracking/phase-1-plan.md` D-16
- 정본 우선순위: docs/development(13·06) > screens > phase-1-plan.md

## 범위
- 만질 패키지·경로: `packages/ui`만.
- 만들 것(각각 `src/components/<Name>.tsx` + 테스트):
  1. Radix 래핑 3종: `RadioGroup`(`@radix-ui/react-radio-group`), `Dialog`(`@radix-ui/react-dialog`; 제목·설명·닫기 버튼·포커스 트랩·`Esc`), `Tabs`(`@radix-ui/react-tabs`). 정확한 버전으로 고정(`^` 금지). 스타일은 토큰만.
  2. `Stepper`: 단계 n/N, 현재·완료·남음 상태, `aria-current="step"`.
  3. `ChoiceCard`: 라벨, 위험도 배지(`LOW|MEDIUM|HIGH`, 13의 색·문구), 미리보기 효과 문장 목록, 선택됨 상태, 비활성(잠금) 상태 + 잠금 사유 문장(06 잠금 표시). `RadioGroup.Item`으로 동작(키보드 화살표 이동).
  4. `CompareCards`: 2~3개 카드 가로 비교(모바일은 세로 스택, 360px에서 가로 스크롤 없음). 행 정의를 props로 받고(라벨·값·강조 여부), 카드마다 주 버튼 슬롯.
  5. `StatusStrip`: 이름·나이·포지션·Base OVR·폼·체력 등 항목 배열을 한 줄 칩으로. 숫자는 `tabular-nums`.
  6. `PlayerHeader`: 이름은 `<h2>`(13 DSN-CMP-001, 크기 `--os-fs-h1`)·팀·포지션·아키타입·등번호는 caption. `DisplayWord`는 브랜드 어휘 전용이라 쓰지 않는다(2026-09-02 정정: 원래 문구 "DisplayWord 활용"은 오기).
  7. `ResultCard`: 결과 종류(`SUCCESS|NEUTRAL|FAIL|FIXED`), 제목, 본문, 적용 효과 목록, 태그 칩.
  8. `DashboardSection`: 제목·설명·본문 슬롯·잠금 상태(잠기면 흐리게 + 사유 문장 + `aria-disabled`).
  9. `CareerTimeline`: 항목 배열(나이·단계·제목·부제)을 세로 타임라인으로. 빈 상태 문구 슬롯.
  10. `Toast`(간단 구현, Radix 없이): 성공/오류 한 줄, `role="status"`, 자동 닫힘 4초, `prefers-reduced-motion`이면 애니메이션 없음.
  11. `index.ts` export 갱신.
- 만지지 말 것: `docs/`, `apps/web`, `tokens.css`·`fonts.css`의 기존 값(새 토큰이 필요하면 추가만 하고 PR 본문에 이유), 다른 패키지.

## 규칙
- 색·간격·글꼴은 `tokens.css` 변수만. 기존 `no-hex-literals` 테스트가 새 파일에도 적용된다.
- 터치 타깃 44×44 이상, 포커스 링은 토큰 `--focus-ring`(없으면 추가), 대비는 13의 기준(본문 4.5:1).
- 모든 상호작용 부품은 키보드로만 조작 가능해야 한다(테스트로 확인: Tab·화살표·Enter·Space·Esc).
- 문구는 props로 받는다. 컴포넌트 안에 한국어 문장을 하드코딩하지 않는다(빈 상태 기본 문구 예외 없음).
- 번들: `@radix-ui/*` 3개 추가 후 `apps/web`의 `pnpm check:bundle` 예산이 그대로 통과해야 한다(ui는 web이 import하므로 web 빌드로 확인. web 코드는 만지지 않는다).

## 제약
- ui는 `contracts` 타입만 import(ADR-005). domain·engine-client·platform import 금지.
- 커밋 메시지는 `T-1-003: …`로 시작, 브랜치는 `T-1-003-…`.
- 서브에이전트 리뷰를 띄우지 않는다. Orca PR 게이트용 `/review:pr` 1회만 예외(`/simplify`·병렬 fork 금지).
- PR 직전 `git fetch origin && git merge origin/main`으로 최신 main을 합친다. `pnpm-lock.yaml` 충돌은 손으로 고치지 말고 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile`로 재생성한 뒤 전체 체인을 다시 돌린다.
