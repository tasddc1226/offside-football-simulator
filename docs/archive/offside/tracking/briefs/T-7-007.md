# T-7-007: 계약 서명 이름 프리필, 제안 비교 카드 "결정 기한" 셀 정리 (이슈 #151·#152)

## 목표

운영 QA 디자인 관점(`docs/qa/2026-09-07-production-three-perspectives/README.md` P2)에서 두 가지가 반복됐다.
(1) 계약 서명 "이름 입력" 모드의 입력창이 빈 값으로 시작하고 선수 이름은 placeholder에만 있어 무엇을 쳐야 하는지 헷갈린다(#152).
(2) 제안 비교 카드의 "결정 기한" 셀에 긴 설명 문장이 들어가 카드 높이가 들쭉날쭉하고 비교가 어렵다(#151). 둘 다 `apps/web` 표시 계층만 바꾼다.

선행: [T-7-004](T-7-004.md)가 `offers.tsx`를 먼저 만지므로, 이 작업은 T-7-004 머지 뒤 `origin/main`에서 시작한다.

## 참조 명세

- 요구사항 ID: SCR-019(제안 비교), SCR-020(계약 서명), NFR-A11Y(입력 라벨)
- 읽어야 할 문서: 이슈 #151·#152, `docs/screens/README.md` §SCR-019/020, `docs/ui/ui-style-guide.md` §폼
- 코드 진입점: `apps/web/src/shared/ContractSignature.tsx`(이름 입력 188~197행, `typedName` 상태, `placeholder={signerName}`), `apps/web/src/routes/career.$careerId.offers.tsx`(제안 카드의 결정 기한 셀 — 워커가 `grep -n "결정 기한\|deadline" apps/web/src/routes/career.\$careerId.offers.tsx apps/web/src/shared/transfer-view.ts`로 찾는다), 테스트 `ContractSignature.test.tsx`, `offers.test.tsx`, e2e `apps/web/e2e/transfer.spec.ts`(서명 입력 라벨을 셀렉터로 쓸 수 있음)

## 범위

- 만질 패키지·경로: `apps/web`만 — `ContractSignature.tsx`(+테스트), `offers.tsx`(+테스트), 필요 시 `transfer-view.ts`의 기한 문구 헬퍼, e2e 기대 문자열.
- 만들 것:
  1. **서명 이름 프리필.** 이름 입력 모드의 `typedName` 초기값을 `signerName`으로 두고(수정 가능), `signerName`이 바뀌면 다시 채운다. `typedReady`는 "공백 제거 후 비어 있지 않음"으로(기존에 `signerName`과 일치해야 한다면 그 규칙을 유지하되 프리필로 기본 충족). 라벨은 `서명할 이름`으로 시작하는 문구를 유지하고(e2e 셀렉터), 보조 문구 한 줄: `계약서에 남을 이름입니다. 필요하면 고쳐 쓰세요.` placeholder는 제거한다.
  2. **결정 기한 셀.** 값은 짧게 고정: 남은 결정 수가 있으면 `` `결정 ${n}번 안` ``, 무기한이면 `제한 없음`. 긴 설명(기한이 지나면 철회된다는 안내)은 카드 밖 목록 상단 캡션 한 줄로 옮긴다: `결정 기한이 지난 제안은 자동으로 철회됩니다.` 카드 본문은 `dl` 격자로 행 높이를 맞추고(라벨 폭 고정), 360px에서 카드 3장 높이가 같아야 한다.
- 만지지 말 것: `packages/domain`, `packages/ui`, `contract.tsx`의 협상 부분(T-7-004), `labels.ts`(T-7-005), docs.
