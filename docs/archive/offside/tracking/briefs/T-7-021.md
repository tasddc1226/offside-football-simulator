# T-7-021: 대규모 커리어 시뮬레이션 1차 — 룰셋 1.5.0 vs 1.6.0 각 1만 커리어 기준선 보고 (실행·집계, 코드 변경 최소)

## 목표

머지된 main(사용자 PR #214·#217·#213 + T-7-019 `career-sim` + T-7-020 가속 포함)에서 `career-sim`으로 **룰셋 1.5.0/팩 0.6.0(운영 활성)** 과 **룰셋 1.6.0/팩 0.6.1(#217 구단 면담)** 을 각각 **1만 커리어** 돌려 밸런스 기준선을 만든다. 사용자 판단(9/14 14:12): 200회는 표본이 부족하고 원작은 약 10만 회까지 돌렸다 — 이번 1만 회는 반복 조정용 기준선이고, 10만 회는 조정 목표가 정해진 뒤 최종 확인에 쓴다(D-79). 끝나면 두 버전의 분포 비교 보고(마크다운)와 재사용 가능한 집계 스크립트가 남는다.

## 참조 명세

- D-79(`docs/tracking/decision-log.md` 2026-09-14), [T-7-019](T-7-019.md)(CLI 사양·컬럼), [T-7-020](T-7-020.md)(`--pure-hash`·`hashProvider`), `tooling/scripts/career-sim.ts`(`--help`), `packages/content/rulesets/1.5.0/ruleset.json`·`1.6.0/ruleset.json`(비교 시 어떤 키가 달라졌는지 `diff`로 확인해 보고에 적는다 — 1.6.0은 `clubMeetingRules` 추가가 핵심), `packages/domain/src/types.ts`(`SeasonResult`, `ClubStint`, `InjuryEpisode`), `tooling/scripts/legacy-population.ts`(기준 모집단 관례 — 수정 금지).
- 오케스트레이터 기준선(200커리어, 1.5.0, 결정 로그 D-79 적용 항목): OVR 정점 33~36세, 은퇴 심사 14/200, 1부 도달 33%, 부상 1.24/시즌, 시즌 40% RESERVE, LEGEND·ICON 155/200. 이 수치가 1만 회에서 어떻게 달라지는지가 첫 관심사다.

## 범위

- 만질 경로: `tooling/scripts/career-sim-report.mjs`(신규, 집계·비교 스크립트 — `seasons.csv`·`careers.csv`·`summary.json`을 읽어 마크다운 표를 출력; Node 내장만 사용, 의존성 추가 금지), `tooling/scripts/package.json`(scripts `"sim:report": "node career-sim-report.mjs"` 1줄). 결과 파일(`tooling/sim-out/**`)은 커밋하지 않는다(.gitignore 됨). 테스트 파일 추가 금지(D-62) — 스크립트는 실제 실행 결과로 검증한다.
- 실행(둘 다 `--jobs 8`, 이 맥은 성능 코어 8·효율 코어 2; 다른 세션·CI가 함께 쓰므로 `--jobs 8` 초과 금지):
  1. `pnpm sim:career --ruleset 1.5.0 --pack 0.6.0 --seeds 10000 --seasons 30 --to-retirement --policy opportunity --position all --jobs 8 --seed-prefix base-150 --out tooling/sim-out/base-150-10k`
  2. `pnpm sim:career --ruleset 1.6.0 --pack 0.6.1 --seeds 10000 --seasons 30 --to-retirement --policy opportunity --position all --jobs 8 --seed-prefix base-160 --out tooling/sim-out/base-160-10k`
  3. 보조(각 2,000커리어): 1.5.0에서 `--policy random`과 `--policy first`도 돌려 정책 민감도를 표 1줄씩으로 적는다.
  예상 시간: 커리어당 1.1초 → 1만 회 `--jobs 8` 약 25분 × 2. 실행은 `nohup … &`로 띄우고 PID를 기록해 자기 PID로만 관리한다. 실패(`failures.csv`)가 0이 아니면 seed·pendingKind·메시지를 보고에 그대로 적는다.
- `career-sim-report.mjs`가 만드는 표(각 버전·정책별, 그리고 1.5.0 vs 1.6.0 차이 열):
  - 커리어: peakOvr·finalOvr·truePotential·잠재 도달률(peak ≥ potential-3) 분위수(p10/p50/p90)·평균, peakOvrAge 분포(히스토그램 5세 구간), retireReason 분포와 REVIEW 은퇴 나이 분포, seasons 수, 1부 도달률과 시즌 5/10/15/20 도달 누적률, 구단 이동 횟수 분포, 계약 수, 최고 주급 분위수, 총 수입 분위수, Legacy 밴드 분포·점수 분위수, 대표팀 차출 수, 주장 시즌 수.
  - 시즌: 나이별(19~49) OVR 평균·p50·n, 나이 구간별(19-22/23-27/28-32/33-37/38+) 출전 시간 점유율·시즌당 부상·평균 평점, 시즌 인덱스별 티어 분포(1/2/3), 역할(STARTER/ROTATION/RESERVE) 분포와 나이 구간별 RESERVE 비율, 부상 시즌당 분포(0~6+)·중상 비율, 계약 종류(PERMANENT/LOAN) 비율, 승격/강등(티어 변화) 빈도.
  - 포지션(GK/DF/MF/FW)·archetypeId·backgroundId별 peakOvr 평균·1부 도달률·Legacy 상위 밴드 비율(표본 n 포함).
  - 표본 오차 안내: 비율 지표는 n=10,000 기준 95% 구간(±1pp 수준)을 한 줄로.
- 만지지 말 것: `career-sim.ts`(버그를 발견하면 고치지 말고 보고), `packages/**`, `apps/**`, 룰셋·팩, docs.
