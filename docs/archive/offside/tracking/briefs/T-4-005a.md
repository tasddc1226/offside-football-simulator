## 1. 구조 (세 묶음이 공유하는 계약 — 바꾸지 않는다)

- `shared/career-route.ts`: `pending.kind === 'INJURY'` → `SCR-022`, `NATIONAL_TEAM` → `SCR-032`, `EVENT`는 활성 팩 이벤트 정의의 `presentation`으로 `SLUMP` → `SCR-021`, `LOCKER_ROOM` → `SCR-018`, `ETHICS` → `SCR-016`, `MEDIA` → `SCR-024`, `RUMOUR` → `SCR-019`, 없음 → `SCR-013`(기존 `EVENT_SCREEN_OVERRIDES`는 그 뒤). 팩 조회는 순수 함수 유지를 위해 `engine/content.ts`에서 파생한 모듈 상수 맵(`eventId → presentation`)으로. `SCREEN_ROUTES`에 SCR-016·018·021·022·024·032를 등록하되 경로는 전부 기존 결정 화면 라우트 `/career/$careerId/event`다(라우트 파일 추가 없음).
- `routes/-phase4/bodies.ts`(새 파일, `-` 접두사라 라우트가 아니다): `export type Phase4BodyProps = { state: CareerState; pending: …; onConfirm(choiceId, extra?): Promise<void>; busy: boolean; error: … }`와 `export const PHASE4_BODIES: Partial<Record<'INJURY'|'NATIONAL_TEAM'|'SLUMP'|'LOCKER_ROOM'|'ETHICS'|'MEDIA', ComponentType<Phase4BodyProps>>>`. **이 묶음은 INJURY·NATIONAL_TEAM 두 항목만 넣는다.** (b) 묶음이 나머지 넷을 같은 파일에 추가한다(그 파일에서 (b)가 고칠 줄은 import 4줄 + 항목 4줄뿐이므로 다른 구조 변경 금지).
- `routes/career.$careerId.event.tsx`: pending 종류·presentation을 보고 `PHASE4_BODIES`에 본문이 있으면 그 본문을, 없으면 기존 `EventDecisionScreen`(SCR-013)을 렌더한다. 확정·재시도·중복 클릭·revision 복구는 `shared/event-screen.tsx`의 기존 로직을 훅 또는 공용 컴포넌트로 뽑아 재사용한다(복제 금지). `event-screen.tsx` 리팩터는 이 묶음만 한다.
- 본문 파일: `routes/-phase4/injury.tsx`(SCR-022), `routes/-phase4/national-team.tsx`(SCR-032). 디자인 계약(480px 게임 프레임, `ScreenIntro`, 패널, `ChoiceCard`, sticky CTA, 토큰, 폐기 어휘 금지, 360px 무가로스크롤)은 `docs/design/mobile-game-refresh.md`.
