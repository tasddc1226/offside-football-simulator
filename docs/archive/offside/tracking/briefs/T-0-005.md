# T-0-005: `apps/api` Hono 앱 구조, D1 스키마(Drizzle), migration, 저장소 계층과 로컬 D1 테스트

## 목표

서버 데이터 계층을 만든다. ADR-002의 서버 역할(프로필·세션·Career 요약·최신 Snapshot·명령 로그·idempotency·서비스 시즌)에 맞는 D1 스키마를 Drizzle로 정의하고, wrangler가 적용하는 SQL migration을 생성하며, 라우트가 쓸 저장소(repository) 함수를 만든다. 테스트는 wrangler의 로컬 D1(Miniflare)에서 빈 DB에 migration을 적용한 뒤 돈다. HTTP 계층(세션 미들웨어, `GET /profile`, 오류 봉투)은 T-0-006, 동기화 라우트는 T-0-008이 맡는다. Cloudflare 계정은 아직 없으므로(U-002) 원격 D1·preview·staging 설정은 하지 않는다.

### 설계 결정(변경 금지. 의문이 있으면 질문)

1. **서버의 Career 행은 요약이다.** 02 DATA-CAR-001의 `currentDate`·`currentTeamId`·`rngState` 같은 진행 값은 Snapshot `state` 안에 있으므로 서버 `careers` 테이블에는 두지 않는다. 컬럼은 contracts `CareerSummary` + 소유자·검증 상태·시각이다.
2. **원자성은 D1 `batch`와 PK·UNIQUE 제약으로 얻는다.** D1에는 대화형 트랜잭션이 없다. 한 요청의 여러 쓰기는 `db.batch([...])` 하나로 보내고, `command_log(career_id, revision)` PK와 `snapshots(career_id, revision)` UNIQUE가 동시 쓰기를 실패시킨다. T-0-008은 "SELECT revision → 비교 → batch[조건부 UPDATE careers WHERE revision = ?, INSERT snapshot, INSERT log…]" 순서로 쓴다. 이 작업은 그 전제(제약과 batch 헬퍼)만 만든다.
3. **서버 idempotency는 HTTP `Idempotency-Key` 단위다**(07 "같은 키 재요청은 최초 응답"). 키는 `(owner_profile_id, key)`로 유일하고 최초 응답의 상태 코드·본문을 저장한다. 클라이언트 명령 단위 멱등성은 engine-client(T-0-007)와 `command_log` PK가 맡는다.
4. **세션 토큰·복구 코드·앱인토스 식별키는 해시만 저장한다**(SHA-256 hex). 원문은 어떤 테이블·로그에도 없다.
5. **JSON 컬럼은 TEXT + 애플리케이션 파싱.** `settings_json`, `payload_json`, `rng_state_json`, `response_body`. 읽을 때 contracts Zod로 검증한다.
6. **서버 발급 ID 형식**: `prf_`, `ses_`, `svc_`, `req_` 접두사 + `crypto.randomUUID()`. 클라이언트가 만든 `careerId`·`commandId`는 접두사를 강제하지 않고 `^[A-Za-z0-9_:.-]{1,64}$`만 요구한다.
7. **시각은 ISO 8601 UTC 문자열(TEXT)**. `integer(mode: 'timestamp')`를 쓰지 않는다(contracts와 같은 표현, canonical 비교 용이).
8. **migration은 Drizzle이 생성한 SQL을 wrangler가 적용한다.** `drizzle.config.ts`의 `out`을 `./migrations`로 두어 wrangler `migrations_dir`와 같은 폴더를 쓴다. 손으로 SQL을 고치지 않는다. additive만 허용(05 "마이그레이션").

### 만들 것

1. `apps/api/wrangler.jsonc`
   - `d1_databases: [{ "binding": "DB", "database_name": "offside-local", "database_id": "00000000-0000-0000-0000-000000000000", "migrations_dir": "migrations" }]`. 주석으로 "원격 ID는 U-002 이후 T-0-010이 `env.preview/staging/production`에 넣는다".
   - `compatibility_date`는 현재 값 유지. `nodejs_compat`는 필요할 때만 켜고 PR 본문에 이유를 적는다.
2. `apps/api/drizzle.config.ts`: `dialect: 'sqlite'`, `driver: 'd1-http'`는 쓰지 않는다(원격 없음). `schema: './src/db/schema.ts'`, `out: './migrations'`.
3. `apps/api/src/db/schema.ts` (Drizzle `sqliteTable`). 컬럼은 snake_case, 타입은 TEXT/INTEGER만.

   | 테이블 | 컬럼 | 키·인덱스 |
   |---|---|---|
   | `profiles` | `id` PK, `recovery_code_hash` NULL, `recovery_code_issued_at` NULL, `google_sub` NULL, `email` NULL, `linked_at` NULL, `toss_anon_key_hash` NULL, `toss_linked_at` NULL, `settings_json` NOT NULL, `created_at`, `last_seen_at` | UNIQUE `google_sub`, UNIQUE `toss_anon_key_hash` |
   | `sessions` | `id` PK, `profile_id` FK→profiles, `channel` (`web`\|`toss`), `token_hash` NOT NULL, `created_at`, `expires_at`, `revoked_at` NULL, `last_seen_at` | UNIQUE `token_hash`, INDEX `(profile_id)`, INDEX `(expires_at)` |
   | `careers` | `id` PK, `owner_profile_id` FK, `status` (`DRAFT`\|`ACTIVE`\|`RETIRED`\|`ARCHIVED`), `revision` INTEGER NOT NULL, `created_service_season_id` FK→service_seasons, `ruleset_version`, `content_pack_version`, `verification_status` (`PENDING`\|`VERIFIED`\|`FAILED`, 기본 `PENDING`), `last_synced_at`, `created_at`, `updated_at`, `archived_at` NULL | INDEX `(owner_profile_id, updated_at)`, INDEX `(created_service_season_id, status)` |
   | `snapshots` | `id` PK(`${careerId}:${revision}`), `career_id` FK, `revision` INTEGER, `checkpoint`, `state` TEXT, `state_hash`, `ruleset_version`, `content_pack_version`, `rng_state_json`, `created_at` | UNIQUE `(career_id, revision)` |
   | `command_log` | `career_id` FK, `revision` INTEGER, `command_id`, `command_type`, `payload_json`, `result_hash`, `created_at` | PK `(career_id, revision)`, INDEX `(career_id, command_id)` |
   | `idempotency` | `owner_profile_id` FK, `key`, `request_hash`, `response_status` INTEGER, `response_body` TEXT, `created_at`, `expires_at` | PK `(owner_profile_id, key)`, INDEX `(expires_at)` |
   | `service_seasons` | `id` PK, `name`, `status` (`PRESEASON`\|`ACTIVE`\|`LOCKED`\|`ARCHIVED`), `starts_at`, `ends_at`, `ruleset_version`, `content_pack_version`, `challenge_set_id` | INDEX `(status)` |

   enum 컬럼은 `text({ enum: [...] })`. FK는 `ON DELETE CASCADE`(profiles → sessions·careers·idempotency, careers → snapshots·command_log). Archive·보상·분석 이벤트 테이블은 이 작업에 없다.
4. `apps/api/migrations/0000_*.sql` + `meta/`: `pnpm --filter @offside/api db:generate`(= `drizzle-kit generate`)로 생성한 파일을 커밋한다. 파일명은 drizzle-kit 기본값을 그대로 둔다(wrangler는 `NNNN_` 접두 정렬을 따른다).
5. `apps/api/src/db/client.ts`: `createDb(d1: D1Database)` → `drizzle(d1, { schema })`. `src/env.ts`: `type Bindings = { DB: D1Database }`.
6. `apps/api/src/db/ids.ts`: `newId(prefix: 'prf' | 'ses' | 'svc' | 'req')`, `CLIENT_ID_PATTERN`. `src/db/hash.ts`: `sha256Hex(text)`는 Workers `crypto.subtle`(domain의 순수 구현은 쓰지 않는다. 서버는 WebCrypto가 있다).
7. 저장소 함수 `apps/api/src/db/repos/*.ts` (모두 `(db, ...) => Promise<...>`, 클래스 없음, 반환 타입은 contracts 타입이나 그 확장):
   - `profiles.ts`: `createProfile(db, { settings? })`(기본 settings는 `ProfileSettingsSchema.parse({ reducedMotion:'SYSTEM', textScale:100, theme:'SYSTEM', defaultSimulationMode:'CHAPTER' })`), `getProfile(db, id)`, `updateSettings(db, id, partial)`(merge 후 Zod 검증), `touchLastSeen(db, id, at)`.
   - `sessions.ts`: `createSession(db, { profileId, channel, tokenHash, expiresAt })`, `findActiveSession(db, tokenHash, now)`(만료·폐기 제외), `revokeSession(db, id, at)`.
   - `careers.ts`: `getCareer(db, id)`, `listCareersByOwner(db, ownerProfileId, { limit, cursor })`(`updated_at DESC, id ASC` 안정 정렬, cursor는 `${updatedAt}|${id}` base64url), `insertCareer`, `updateCareerRevision(db, id, { fromRevision, toRevision, updatedAt, status })` → 영향 행 수 반환(0이면 충돌).
   - `snapshots.ts`: `putSnapshot`, `getLatestSnapshot(db, careerId)`, `listSnapshots(db, careerId, { limit })`, `pruneSnapshots(db, careerId, keep = 5)`(최신 keep개만 남김. 02 "최근 checkpoint 5개").
   - `commandLog.ts`: `appendCommands(db, careerId, entries[])`(batch), `listCommandsSince(db, careerId, afterRevision)`.
   - `idempotency.ts`: `getIdempotent(db, ownerProfileId, key, now)`, `putIdempotent(...)`, `purgeExpired(db, now)`.
   - `serviceSeasons.ts`: `getCurrentServiceSeason(db, now)`(`status = 'ACTIVE'`이고 기간 안인 것 1개), `upsertServiceSeason`.
   - `batch.ts`: `runBatch(db, statements)` — Drizzle `db.batch` 래퍼(빈 배열이면 no-op). 설계 결정 2의 사용 예를 주석으로.
8. 로컬 시드 `apps/api/seeds/local.sql`: `service_seasons`에 `svc_kickoff`(ACTIVE, 2026-09-01 ~ 2026-12-31, ruleset `1.0.0`, pack `0.1.0`, challenge_set `cs_kickoff`) 1행. 스크립트 `db:seed` = `wrangler d1 execute offside-local --local --file seeds/local.sql`. migration에는 데이터를 넣지 않는다.
9. `package.json` 스크립트: `db:generate`, `db:migrate` = `wrangler d1 migrations apply offside-local --local`(기존 echo 대체), `db:seed`, `db:check` = `drizzle-kit generate` 실행 후 `git diff --exit-code -- migrations`(스키마와 migration이 어긋나면 실패. 루트 `pnpm db:migrate`가 turbo로 이 패키지를 호출한다는 점을 유지).
10. 테스트 인프라 `apps/api/src/test/d1.ts`: `wrangler`의 `getPlatformProxy({ configPath: 'wrangler.jsonc', persist: false })`로 `env.DB`를 얻고, `migrations/*.sql`을 파일명 순으로 읽어 `DB.exec`로 적용한 뒤 `createDb`를 돌려준다. 테스트 파일마다 새 프록시(격리). `afterAll`에서 `dispose()`. `getPlatformProxy`가 vitest 4.1과 맞지 않으면 `@cloudflare/vitest-pool-workers`(안정 버전, vitest 4 지원 확인)로 바꾸되 이유를 PR 본문에 적는다. 둘 다 안 되면 멈추고 질문한다.

### 테스트 (Vitest, `apps/api/src/**/*.test.ts`)

- migration: 빈 DB에 모든 migration을 순서대로 적용 → 7개 테이블이 있고 `PRAGMA table_info`가 위 표의 컬럼과 같다(테스트 안에 기대 컬럼 목록을 적는다). 두 번 적용하면 실패한다(멱등 아님을 확인. wrangler가 적용 이력을 관리하므로 그대로 둔다).
- `db:check`가 통과한다(스키마 ↔ migration 일치). CI에서 돌 수 있도록 `pnpm --filter @offside/api db:check`를 `lint` 뒤가 아니라 별도 스크립트로 두고 PR 본문에 결과를 붙인다.
- profiles: 생성 → 조회 → settings 부분 갱신(Zod 통과) → `textScale: 110`은 거부; `google_sub` 중복 삽입은 실패.
- sessions: 만료·폐기 세션은 `findActiveSession`이 돌려주지 않는다.
- careers: 소유자별 목록 안정 정렬과 cursor 페이지네이션(3개 넣고 limit 2 → 다음 cursor로 1개); `updateCareerRevision`은 `fromRevision`이 다르면 0행.
- snapshots: `(career_id, revision)` 중복은 실패; `pruneSnapshots(keep 5)`가 8개 중 최신 5개만 남긴다; `getLatestSnapshot`이 최고 revision을 준다.
- command_log: `appendCommands` batch 안의 한 항목이 PK 충돌이면 전부 롤백(batch 원자성); `listCommandsSince(afterRevision)` 경계.
- idempotency: 같은 키 두 번 → 두 번째는 저장된 응답, 만료된 키는 `purgeExpired` 뒤 사라짐.
- serviceSeasons: 시드 파일을 적용하면 `getCurrentServiceSeason`이 `svc_kickoff`를 준다; 기간 밖이면 `undefined`.
- 기존 `GET /v1/health` 테스트는 그대로 통과한다(앱 구조를 `src/app.ts`로 옮기더라도 `app.request`가 동작해야 한다).
- 순수성: `apps/api/src/**`(테스트·`src/test/**` 제외)에 `from 'node:`가 없다(Workers 런타임).

## 제약

- 원격 Cloudflare 리소스를 만들거나 로그인하지 않는다(`wrangler login`, `d1 create` 금지). 모든 것은 `--local`.
- 로그에 토큰·복구 코드·식별키·이메일 원문을 찍지 않는다. 테스트 픽스처 값도 가짜 문자열을 쓴다.
- 버전은 안정 최신. 프리릴리스 금지.
- 커밋 메시지 `T-0-005: …`. 브랜치 `T-0-005-api-d1-schema`.
- 커밋 트레일러: `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
- 서브에이전트 리뷰를 띄우지 않는다. 예외는 하나뿐이다. Orca가 `gh pr create` 앞에 요구하는 게이트를 위해 `/review:pr`을 **한 번만** 실행한다(`/simplify`·병렬 fork 금지). 리뷰 결과 중 실제 버그·테스트 누락만 고치고 나머지는 PR 본문에 적는다. PR을 연 뒤에는 멈추고 피드백을 기다린다.
