# T-4-010: e2e 간헐 실패 안정화 — season-result.spec 카운트업 건너뛰기 경쟁·signFirstOffer 잔류 경로 허용·CI 실패 아티팩트 업로드 (web e2e + ci)

## 목표

main Browser gates에서 연속 실패한 e2e 2건의 원인을 테스트 쪽에서 제거하고, 다음 실패부터는 trace를 볼 수 있게 CI에 실패 아티팩트 업로드를 넣는다. 앱 코드는 바꾸지 않는다(잔류 결과 화면은 [T-4-011](T-4-011.md)에서 T-4-007 머지 뒤 처리).

## 원인 (오케스트레이터 조사 워크플로 `wf_77670be2-155`, 두 조사자 일치, CI 로그로 확인)

1. `apps/web/e2e/season-result.spec.ts:55` (run 33936575648): `:68-70`이 `count() > 0` 뒤 `click()`을 timeout·catch 없이 호출한다. `apps/web/src/shared/countup.tsx`의 rAF 카운트업이 매 프레임 숫자 폭을 바꿔 같은 inline-flex 안의 `건너뛰기` 버튼이 움직이므로 Playwright stable 검사가 계속 실패하고, 애니메이션이 끝나면 버튼이 언마운트돼 click이 30초 예산을 전부 소비한다. CI(2 worker, CPU 경합)에서만 드러난다.
2. `apps/web/e2e/season.spec.ts:17` (run 33938197514): 실패 지점은 `apps/web/e2e/helpers/player-creation.ts:120`의 `toHaveURL(/transfer-result\?rev=/)`다. 시즌 1 결산 뒤 시장 사유가 `INTEREST`인 seed에서 `signFirstOffer`가 첫 카드(= 안전 잔류 제안)를 수락하면 도메인은 `buildStayState`로 `OFFER_REJECTED(ALL)`만 남기고(`packages/domain/src/simulate.ts:2885-2892`), 계약 화면 `handleAccept`는 무조건 `/transfer-result?rev=N`으로 보내며, 그 loader는 전환 엔트리가 없어 대시보드로 redirect한다. 타이밍이 아니라 seed 의존 상태 경로이며 로컬 `--repeat-each 3`에서 1/3 재현됐다. T-3-005(#65)부터 존재했고 #68과 무관.

## 1. 작업

- `apps/web/e2e/season-result.spec.ts`: `count()`+`click()` 쌍을 버튼이 사라져도 관용적인 bounded click으로 바꾼다(예: `await skipButton.click({ force: true, timeout: 1_500 }).catch(() => {})`). 뒤따르는 `toHaveText(data-value)`·`toHaveCount(0)` 단언은 그대로 둔다(건너뛰기가 먹었든 자연 종료됐든 성립). reducedMotion을 켜서 회피하지 않는다(spec의 의도).
- `apps/web/e2e/helpers/player-creation.ts` `signFirstOffer` 시장 분기: `이 조건 수락` 뒤 두 결과를 모두 허용한다 — `transfer-result?rev=`로 갔으면 `/^(대시보드로|새 시즌 준비)$/` 링크를 클릭하고, 대시보드(`/career/<id>`)로 바로 왔으면 그대로 진행한다. 마지막 단언 `/\/career\/[^/]+(?:\/preseason)?$/`는 유지. helper 주석에 잔류 경로 설명을 한 줄 적는다. 다른 helper 함수는 바꾸지 않는다.
- `.github/workflows/ci.yml` Browser gates 잡에 `actions/upload-artifact@v4`(`if: failure()`, path `apps/web/test-results`, retention 7일) 단계를 추가한다. 다른 잡·단계는 바꾸지 않는다.
- INTEREST 경로 고정 케이스: `localStorage['offside:e2e-seed']` DEV 훅(`apps/web/src/engine/career-actions.ts`)으로 시즌 1 결산 뒤 `INTEREST` 시장이 열리는 seed 1개를 찾아(브라우저 밖 탐색 스크립트는 만들지 말고 e2e 안에서 seed 후보 몇 개를 돌려 찾는다, 최대 20개) `season.spec.ts`에 "안전 잔류 수락 뒤 대시보드로 돌아온다" 케이스 1개를 고정 seed로 추가한다. 20개 안에 못 찾으면 케이스를 추가하지 않고 PR 본문에 시도한 seed와 시장 사유를 표로 적는다.
