# T-4-006: Phase 3·4 통합 검증 — 3시즌 fixture·불변 property·결정 예산·세션 길이·e2e 안정성 (domain + contracts + web e2e, 테스트 전용)

## 목표

## 1. 3시즌 통합 fixture `career-13-integration`

- `packages/domain/src/__fixtures__/career-13-integration.ts` + golden: 프로 첫 계약 → 시즌 1(CHAPTER 모드, MODERATE 이상 부상 1회 → 재활 선택 → 복귀·재발 판정) → 결산(감독 교체 판정이 실제로 일어나는 seed 선택) → 이적시장 → 이적 확정(리그 이동) → 시즌 2(step 8 대표팀 소집 ACCEPT → NATIONAL_DEBUT MAJOR 챕터, 0.2.0 팩이면 LOCKER_ROOM/SLUMP/MEDIA 중 1개 이상 도달) → 결산 → 시즌 3(임대 또는 재계약 협상 1회) → 결산. seed는 이 경로가 실제로 나오는 값을 탐색해 고정하고 탐색 방법·후보 수를 PR 본문에 적는다. 팩은 `0.2.0`(Phase 4 이벤트가 있는 팩), 룰셋은 다른 fixture와 같은 것을 쓴다. 경로 일부가 어떤 seed로도 나오지 않으면 그 단계를 빼고 PR 본문에 이유(조건 DSL·가중치)를 적는다.
- golden에는 revision·stateHash·`rngState.draws`·`seasonHistory` 길이·시즌별 `result.hash`·`clubHistory` 길이·`health.episodes` 수·`careerTags`를 기록한다. 같은 golden을 `packages/fixtures`에도 복제한다(기존 관례).
- 테스트: (a) 2회 재생 hash 동일, (b) 시즌 경계·부상 pending·이적 확정 직전 세 지점에서 JSON 직렬화로 끊었다가 재개해도 hash 동일, (c) 명령 하나를 빼면 hash가 달라짐, (d) Node/workerd 해시 probe와 contracts strict 순회가 이 fixture로 통과.

## 2. 불변식 property(의존성 추가 없음)

- `packages/domain/src/integration-invariants.test.ts`: fixture 명령 로그를 재생하면서 **매 명령 뒤** 검사한다. seed sweep은 `career-13` 명령 로그를 seed 200개로 재실행하되(실패 명령은 건너뛰고 결과가 `ok`인 것만 기록) seed 목록을 상수로 고정한다.
  - P3-5: 이적·임대·복귀로 소속 구단·리그가 바뀌는 명령(`ACCEPT_OFFER`·`LOAN_RETURN`) 전후 `attributes`와 `computeBaseOvr` 결과가 같다.
  - P4-5: `RELATION` 타깃 Effect(관계·평판)가 적용되는 명령 전후 `attributes`가 같고, `activeEffects`·`deferredEffects`에 `kind:'RELATION'`이면서 attribute 타깃인 항목이 없다. `HEALTH` Effect는 `availability`·`recurrenceRiskBp`만 바꾼다(ADR-010 표).
  - P4-1: `relationships` 5축이 항상 0~100 정수, `relationshipLog` 40건 상한, `memoryTags` 축당 상한(룰셋 `relationshipRules.memoryTagsMax`).
  - P3-3: 같은 `commandId` 재전송이 상태를 바꾸지 않고, `expectedRevision` 불일치가 거부된다(시장 명령 4종 전부).
  - P4-6·P3-2: 어떤 FAIL outcome·전부 거절·협상 실패 뒤에도 `pending`이 닫히고 다음 `ADVANCE`가 성공한다(강제 커리어 종료 없음).
  - P4-7: 대표팀 DECLINE·부상 자동 사양 전후 `relationships.managerTrust` 동일.
  - D-36: 저장 상태의 모든 숫자가 정수다(canonical 순회).
- property 위반은 실패 테스트로 두지 말고 PR 본문 "결함 후보" 표에 재현 seed·명령 index·기대/실제를 적고 해당 검사만 `it.skip`에 사유를 남긴다. domain 코드는 고치지 않는다.

## 3. 결정 예산 측정(RULE-TIME-004)

- 위 seed sweep에서 시즌별 사용자 결정 수(pending이 열려 `RESOLVE_EVENT`·`RESOLVE_ROLE`·`RESOLVE_CHAPTER`·`ACCEPT_OFFER`·`NEGOTIATE`·`REJECT_OFFER`·`LOAN_RETURN`으로 닫힌 횟수, 챕터는 판단 수가 아니라 챕터 1회 = 결정 1회)·핵심 경기 챕터 수·챕터당 판단 수·강제 사건(INJURY pending, 자동 사양 제외) 수를 FAST/CHAPTER 모드별로 센다. 평균·최소·최대를 PR 본문 표로 내고, 11 문서 상한(CHAPTER 10·FAST 6·챕터 4·판단 3·강제 2)을 넘는 시즌 비율을 적는다. 상한 초과는 실패 테스트가 아니라 **콘텐츠 예산 관찰**로 보고한다(콘텐츠·룰셋 수정 금지). 측정 코드는 `*.test.ts` 안에 두고 결과를 `console.info` 표로 남긴다.

## 4. Snapshot 크기

- `packages/contracts/src/snapshot-size.test.ts`에 career-13 3시즌 종료 상태와 `PUT` body 크기를 추가한다. 256KB 상한은 실패, 128KB 초과는 경고 로그 + PR 본문 기록. `timeline`·`relationshipLog`·`health.episodes`가 시즌당 얼마나 늘어나는지(바이트/시즌)를 적는다.

## 5. 세션 길이 재측정·e2e 3회 무결점(web, T-4-005 뒤)

- `season.spec.ts`(또는 새 `season-length.spec.ts`)로 FAST 한 시즌과 CHAPTER 한 시즌을 `session-length.spec.ts`와 같은 방식(자동화 시간 + D-22 최소 조작 시간)으로 측정해 목표(FAST 4~6분·CHAPTER 8~12분) 대비 결과를 JSON으로 남기고 PR 본문 표에 적는다. 목표의 2배를 넘으면 원인(콘텐츠 예산/결산 성능)을 분류해 적는다.
- 전체 e2e를 **연속 3회** 돌려(`E2E_PORT=5207`, 매회 새 서버) 3회 모두 무결점이어야 한다. 흔들리는 테스트는 원인을 찾아 테스트 쪽(대기 조건·selector·seed)만 고친다. 제품 코드로 고쳐야 하면 재현 근거를 적고 멈춘다. retries·skip 추가 금지.

## 6. 완료 조건 표 증거

- PR 본문에 phase-3-4-plan 4절 표의 각 행(P3-1~6, P4-1~7, 공통)에 대해 증거(`파일:테스트 이름`, fixture, 측정값)를 채운 표를 넣는다. 이 PR이 아니라 기존 테스트가 증거인 행도 경로를 적는다. 증거가 없는 행은 "없음"으로 남긴다(오케스트레이터가 후속 작업을 만든다).
