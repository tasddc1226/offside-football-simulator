# T-2-007: web 시즌 진입·역할 제안·대시보드 시즌화·능력치 상세 — SCR-005·011·012·029·033 + e2e 포트 override

## 목표

첫 프로 계약 뒤 브라우저에서 시즌을 시작하고(SCR-005 프리시즌 계획 → SCR-011 시즌 준비 → `START_SEASON`), step 1 감독 제안을 결정하고(SCR-012 → `RESOLVE_ROLE`), 대시보드에서 step을 진행하며 일정표·전술실이 시즌 상태(경기 결과·선발 순위)를 보여주고, 능력치 상세(SCR-033)가 Base OVR 구성을 설명한다. 시즌 결산·챕터 화면은 T-2-009·T-2-008이 채우므로 여기서는 자리표시 라우트만 둔다.
모든 확정은 전용 결정 화면에서만 일어나고 대시보드는 아무것도 확정하지 않는다(SCR-029 인수 조건).

## T-2-004·T-2-005(같은 시기 진행)와의 접점

- T-2-005는 `START_SEASON.payload.trainingFocus?`를 붙이고 `seasonHistory[].result: SeasonResult`(`attributeDeltas[].{key,delta,causes[]}`)를 만든다. PR 직전 `git fetch origin && git merge origin/main` 뒤 `@offside/domain`의 `Command` 타입에 `trainingFocus`가 있으면 `toStartSeasonPayload`가 보내고, 없으면 빼고 UI 선택만 유지한다(PR 본문에 어느 쪽인지 적는다). `latestSeasonResult`도 같은 방식.
- T-2-004는 `Pending` CHAPTER에 `chapterId`를 더한다. 이 작업은 `'chapterId' in pending`으로만 분기하고 `RESOLVE_CHAPTER`는 보내지 않는다(T-2-008). `ADVANCE.payload.chapterCandidates`도 보내지 않는다(챕터가 열리지 않으므로 FAST e2e가 안정적이다).
- 두 작업 모두 `apps/web`을 만지지 않으므로 코드 충돌은 없다. `pnpm-lock.yaml`만 주의.

## 제약

- 채널 리터럴 비교 금지, hex 색 리터럴 금지, `--os-*` 토큰만. 문구는 한국어·브랜드 어휘. `useScreenState` 6종만. COMMITTING 중 CTA 잠금·중복 제출 금지.
- 진짜 잠재력·최종 OVR 미노출. 비교 표는 360px에서 `CompareCards`만(3열 가로 스크롤 금지).
- 커밋 메시지는 `T-2-007: …`, 브랜치는 `T-2-007-…`.
- 서브에이전트를 띄우지 않는다 — 리뷰용이든 조사용이든 전부(gstack `/review`·`/codex`·adversarial·`/simplify`·병렬 fork·Agent/Explore 조사 에이전트 금지). 예외는 Orca PR 게이트용 `/review:pr` 1회(로컬 모드).
- e2e는 **`E2E_PORT=5184 pnpm --filter @offside/web e2e`**로 돌린다(9번을 먼저 구현). 그 전에는 `lsof -nP -iTCP:5174 -sTCP:LISTEN`이 비어 있을 때만 실행.
- PR 직전 `git fetch origin && git merge origin/main`. `pnpm-lock.yaml` 충돌은 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile` 뒤 전체 체인 재실행. `routeTree.gen.ts` 충돌은 라우트 생성기를 다시 돌려 해결.
- 명세를 고치지 않는다. 화면 명세와 충돌하면 그 항목만 PR 본문에 적고 나머지를 끝낸다.
