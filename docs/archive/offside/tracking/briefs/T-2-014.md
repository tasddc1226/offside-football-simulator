## D-40 Effect 규칙(이 브리프로 확정)

1. **kind와 target 소유**(ADR 표로 남긴다): `PERMANENT`(attributes) — 성장식(T-2-005)과 명시적 이벤트 outcome만, 단일 ±1(중대 −2~+1); `CURRENT`(form·fitness·morale) — 경기(T-2-005 `conditionRules`)·이벤트·챕터·Phase 4 부상; `CONTEXT`(tacticalFit·squadStatus·positionProficiency) — T-2-002 역할 제안·Phase 3 팀 이동 재계산·이벤트; `RELATION`(managerTrust·captain·rival·fans·agent) — 이벤트·챕터·Phase 4; `DEFERRED` — 어느 Phase든 예약만. 같은 target을 두 Phase가 동시에 직접 대입(REPLACE)하지 않는다.
2. **중첩**: `SUM` 무제한 합산(clamp만), `REPLACE` 대입, `ONCE_PER_SOURCE` 커리어 1회, 신규 **`ONCE_PER_SEASON`** — `appliedSourceIds`에 `season:<index>:<sourceId>`로 기록하고 `seasonBoundaryReset`이 `season:` 접두 항목을 지운다.
3. **만료**: 기존 `STEPS_AFTER`→`AT_STEP`(시즌 안 step 번호), 신규 **`AT_SEASON_END`**(결산 직전 되돌림)·**`SEASONS_AFTER { seasons }`**→저장 시 `AT_SEASON_INDEX { index }`(그 시즌 결산 직전 되돌림). 시즌 경계를 넘는 `AT_STEP`은 다음 시즌의 같은 step에서 만료된다고 **정의하지 않고** 결산 시 강제 만료한다(시즌 로컬). `expireEffects`는 걷기의 step 진입 시(기존)와 결산 직전(신규 `expireAtSeasonEnd`) 두 곳에서만 부른다.
4. **되돌림**: `SUM`은 `−delta`, `REPLACE`는 저장해 둔 `previousValue`로 복원(신규 필드 `activeEffects[].restoreTo?: number`), 둘 다 clamp. `PERMANENT`는 만료 불가(스키마 거부). `CURRENT`의 되돌림은 시즌 경계 회귀(`seasonBoundaryReset`)와 순서가 "만료 → 회귀".
5. **DEFERRED**: `appliesAt.NEXT_SEASON_STEP { step }`만(T-2-005 적용 경로 유지). 적용 시 kind는 target에서 유도(`resolveDeferredKind`, T-2-005) — 이 함수를 `effects.ts`로 옮기고 export. **PR #40 확정 구조 유지**: `FootballSeason.scheduledEffects`(이번 시즌 적용 예정 목록)를 `START_SEASON`이 `state.deferredEffects`에서 통째로 옮기고 walk 중 step마다 푼다. 시즌 중 새로 미룬 효과는 `state.deferredEffects`에 머물다 다음 `START_SEASON`에서 옮겨진다. 이 두 목록의 역할을 바꾸지 말 것.
6. `Effect`에 `reasonTag?: string`(원인 태그, 04 "결과가 0이면… 원인 문구", Phase 4 "관계 변화는 source와 이유 태그를 남긴다") 선택 필드를 더한다. content `EffectSchema`도 같이.

## D-41 시장가치 입력(이 브리프로 확정)

- `packages/domain/src/market-value.ts`: `computeMarketValueIndex(input: MarketValueInput, rules: MarketValueRules) → { indexCenti: number; components: Array<{ key: MarketValueComponent; weightBp: number; valueCenti: number; contributionCenti: number }> }` — 03 식 그대로 가중치 bp(Base OVR 3500, Scouted Potential Mid 2000, Age Curve 1500, Contract 1000, League 1000, Form 500, Popularity 500). 각 성분은 0~10000 centi로 정규화: Base OVR·Potential Mid는 값 그대로 ×100; Age Curve는 룰셋 `marketValueRules.ageCurve[]`(`{maxAge, valueCenti}` 구간표, 초기값 21→7000·25→10000·29→9000·32→6000·99→3000); Contract는 잔여 시즌(`contract.lengthSeasons − 소속 시즌 수`)을 `contractCurve`(0→4000·1→7000·2+→10000); League는 `leagueTier`(YOUTH 2000·3부 5000·2부 7500·1부 10000); Form은 `state.form × 100`; Popularity는 입력 `popularityCenti`(Phase 4 평판이 만들기 전까지 호출자가 5000 고정).
- `MarketValueInput = { baseOvr, scoutedPotentialMid, age, contractSeasonsRemaining, leagueTier, form, popularityCenti }`. **`truePotential`은 입력에 없다**(타입으로 막고 테스트로 보증). 소유: baseOvr·age·form 도메인 현재값, scoutedPotentialMid 프로필, contractSeasonsRemaining·leagueTier Phase 3, popularityCenti Phase 4. 상태에 저장하지 않는다(호출 시 계산). `buildMarketValueInput(state, ruleset)` 어댑터를 두어 Phase 3가 그대로 쓴다.
- 룰셋 `marketValueRules`는 `packages/content` 스키마·`ruleset.json`에 추가(위 초기값).

## D-42 CareerTag(이 브리프로 확정)

- `packages/domain/src/career-tags.ts`: `CAREER_TAG_IDS`(14 문서 16종 `TAG-ONE-CLUB … TAG-UNCROWNED`), `CAREER_TAGS: Record<CareerTagId, { label: string; rarity: 'COMMON'|'RARE'|'EPIC'; evaluateAt: 'SEASON_SETTLED'|'RETIREMENT'; ownerPhase: 2|3|4|5 }>`(카탈로그 표 그대로).
- 상태: 기존 `state.tags`(콘텐츠 기억 태그, 자유 문자열)는 그대로 두고 **`state.careerTags: CareerTagId[]`**(정렬·중복 없음)와 **`state.careerTagGrants: Array<{ tagId; seasonIndex; atRevision; sourceRefId: string }>`**를 추가한다.
- 인터페이스: `grantCareerTag(state, tagId, source: { seasonIndex; revision; refId }) → CareerState`(이미 있으면 무변경), `evaluateCareerTags(state, result: SeasonResult, ruleset) → CareerTagId[]`(결산 훅 — T-2-005 `settleSeason`이 `seasonHistory`에 result를 넣은 뒤 부른다; 평가기는 `CAREER_TAG_EVALUATORS: Partial<Record<CareerTagId, Evaluator>>`에 등록하고 없는 태그는 건너뛴다). Phase 2에서 구현하는 평가기: **TAG-BIG-GAME**(커리어 누적 챕터 SUCCESS 5회 이상 — `seasonHistory[].result.chapters[].decisions[].outcomeKind === 'SUCCESS'` 합), **TAG-DERBY-HERO**(DERBY 챕터에서 SUCCESS 3회 이상), **TAG-IRONMAN**은 조건만 코드화하고 10시즌 전이라 항상 false인 것을 테스트로 고정. 나머지는 등록하지 않는다(Phase 3~5).
- 이를 위해 T-2-004의 `RESOLVE_CHAPTER.payload.outcomes[]`에 `kind: 'SUCCESS'|'NEUTRAL'|'FAIL'|'FIXED'`를, `ChapterRecord.decisions[]`에 `outcomeKind`를, `ChapterRecord`에 `trigger: ChapterTrigger['kind']`를 추가한다(웹 T-2-008이 payload를 채운다 — contracts 스키마에서 `kind`는 필수).
- 타임라인 `kind += 'CAREER_TAG_GRANTED'`(refId = tagId).

## 테스트와 인수 조건

- effects: ONCE_PER_SEASON이 다음 시즌 재적용, AT_SEASON_END·AT_SEASON_INDEX 되돌림 시점, REPLACE 복원값, 시즌 넘는 AT_STEP 강제 만료, PERMANENT+expiresAt 스키마 거부, reasonTag 보존.
- market-value: 03 예시 값으로 성분·합 검증, 가중치 합 10000, `truePotential` 타입 미포함(`expectTypeOf`), 정규화 경계(0·100·연령 구간 끝).
- career-tags: 카탈로그 16종·라벨·희귀도, grant 멱등·정렬, BIG-GAME 5회 경계(4회 false·5회 true), DERBY-HERO, IRONMAN 항상 false, 결산 훅이 타임라인에 남김. 실제 골든(career-05-chapter 등)을 결산까지 돌려 태그 평가가 throw 없이 지나간다.

## 제약

- `Date`·`Math.random` 금지, 정수 저장(D-36), 반올림 함수마다 한 번.
- Base OVR·attributes·truePotential 불변. 시장가치를 상태에 저장하지 않는다. 문구·주석 한국어. 커밋 `T-2-014: …`, 브랜치 `T-2-014-…`.
- 서브에이전트를 띄우지 않는다 — 리뷰용이든 조사용이든 전부(gstack `/review`·`/codex`·adversarial·`/simplify`·병렬 fork·Agent/Explore 조사 에이전트 금지). 예외는 Orca PR 게이트용 `/review:pr` 1회(로컬 모드).
- e2e 전에 `lsof -nP -iTCP:<포트> -sTCP:LISTEN`이 비어 있어야 한다.
- PR 직전 `git fetch origin && git merge origin/main`. `pnpm-lock.yaml` 충돌은 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile` 뒤 전체 체인 재실행.
- 명세를 고치지 않는다(ADR-010 신규 작성만). D-40~D-42와 충돌하면 그 항목만 PR 본문에 적고 나머지를 끝낸다. `apps/*`는 건드리지 않는다.
