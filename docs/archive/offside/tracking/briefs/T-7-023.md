## 근거와 한계

- 면담의 요청/응답과 `PENDING/OFFERED/NO_CANDIDATE/CANCELLED`, 시즌 목표 결과는 저장돼 있다. 다만 `OFFERED` 뒤 특정 계약이 그 면담에서 비롯됐다는 인과 ID는 저장되지 않아 계약 성공을 면담 결과로 단정하지 않는다.
- 부상 에피소드에는 발생 위치, 재활 선택, 회복/재발, 후유증이 있고 같은 revision의 timeline에서 선택 source를 연결할 수 있다.
- 임대에는 소속 이력, 임대 시즌 결산, `LOANED/LOAN_RETURNED` 결정이 있다. 복귀 뒤 과거 원소속 역할 약속은 별도 snapshot으로 보존되지 않아 과거 역할 재평가 설명은 만들지 않는다.
- 구버전의 optional `clubMeeting` 부재와 이력 빈 배열은 가짜 기본 결과가 아니라 빈 상태로 표시한다.

### T-7-025 공유 계약 제안(이 작업에서는 미구현)

- 면담→계약 인과: 시장 제안을 만들 때 각 `Offer`에 optional `origin: { kind: 'CLUB_MEETING'; seasonIndex; contractId; request }`를 고정하고, 수락 시 같은 값을 계약 전환 기록 또는 별도 영수증에 복사한다. `generateMarket`의 `preferenceStatus: OFFERED` 확정 시점과 `ACCEPT_OFFER` commit 시점이 각각 발생 경계이며, 구버전/필드 부재는 “면담과 계약의 연결 기록 없음”으로 표시하고 소급 추정하지 않는다.
- 임대 복귀 역할 평가: `LOAN_RETURN` commit 때 optional 평가 snapshot에 `loanContractId`, `loanSeasonIndex`, `parentContractId`, `parentRolePromise`, `deliveredRole`, `ceilingRole`, `reevaluatedRole`, `applies`, `decision`을 저장한다. 값은 기존 `evaluateLoanReturnRole` 결과를 명령 적용 전에 한 번 고정하며, 구버전/필드 부재는 저장된 임대 출전·복귀 결정만 표시하고 당시 역할 판정을 현재 계약에서 역산하지 않는다.

## 완료 조건

- 저장 근거가 있는 영수증만 홈 요약, 계약/시장, 기록 탭에서 재열람할 수 있다.
- `NO_CANDIDATE/CANCELLED`은 종료 상태이며 다음 성공을 암시하지 않는다.
- 기존 테스트 파일만 필요 최소 갱신하고 focused web test/lint/typecheck를 통과한다. 새 테스트 파일·독립 테스트 케이스는 추가하지 않는다(D-61).
- 360×780 실제 브라우저에서 자연 도달한 상태만 acceptance 근거로 사용하며 IDB를 조작하지 않는다.
