# T-2-008: web 핵심 경기 챕터 SCR-031 — 챕터 후보 전달·판단 확정·결과·새로고침 재생 (TEST-E2E-010)

## 목표

`ADVANCE`가 챕터를 열면(T-2-004) 브라우저가 SCR-031에서 경기 맥락 → 판단 1~3개 → 결과를 보여주고, 판단마다 `RESOLVE_CHAPTER`를 보낸다. 새로고침·뒤로 가기는 확정된 판단까지 재생하고 roll을 다시 소비하지 않는다. 웹이 `ADVANCE.payload.chapterCandidates`를 채워 챕터가 실제로 열리게 한다.

## 참조 명세

- 요구사항 ID: SCR-031, SCR-023(경기 판단 변형, Phase 2는 공통 문구), FR-CHP-001, TEST-E2E-010, 06 "핵심 컴포넌트"(ChoiceCard·ResultCard·ChapterScoreboard), 13 DSN-LINE-001·DSN-MOT-001("핵심 경기 챕터 진입 스코어보드 600ms", 확정값 data 속성 먼저)
- 읽어야 할 문서(순서대로): `docs/tracking/phase-2-plan.md` **D-28·D-38·D-30**, `docs/screens/05-hub-and-support.md`(SCR-031·SCR-023 보충), `docs/tracking/briefs/T-2-004.md`(데이터 계약: `Pending` CHAPTER `{ chapterId, version, importance, matchId, decisionsTotal, resolved[] }`, `RESOLVE_CHAPTER { chapterId, definitionVersion, decisionId, optionId, outcomes[] }`, 팩 `chapters/` 스키마, `selectChapterCandidates(pack, state)`), `docs/tracking/briefs/T-2-007.md`(라우트 자리표시 `SCR-031: /career/$careerId/chapter`, `screenForCareer` 분기, 대시보드 CTA), `docs/tracking/briefs/T-1-009.md`(이벤트 화면·결과 카드 규칙)
- 도메인·콘텐츠 API: `@offside/content` `selectChapterCandidates`, `pack.chaptersById`, `ChapterDefinition`(`decisions[].{id,prompt,options[].{id,label,riskLabel,priorProbability,previewEffects,outcomes[]}}`); `@offside/domain` `MatchRecord`(`season.matches`에서 `pending.matchId`), `season.selection.playerReason`, `ChapterRecord`(`season.chapters`), 타임라인 `CHAPTER_RESOLVED`(refId `chapterId:decisionId:optionId:outcomeId`). T-2-014가 머지돼 있으면 outcome `kind`를 payload에 넣는다(contracts 스키마가 요구).

## 범위

- 만질 패키지·경로: `apps/web`만. `src/routes/career.$careerId.chapter.tsx`(자리표시 대체), `src/engine/career-actions.ts`(`advance`에 `chapterCandidates` 추가, `resolveChapter` 추가, `toResolveChapterOutcomes`), `src/shared/{chapter-scoreboard,chapter-state}.ts(x)`, `labels.ts`, `e2e/`. `career.$careerId.index.tsx`는 CTA 문구만.
- 만들 것:
  1. **`advance`**: `selectEligibleEvents`와 함께 `selectChapterCandidates(engine.pack, state)`를 계산해 `ADVANCE { eligibleEvents, chapterCandidates }`로 보낸다. 단위 테스트: CHAPTER 모드 유스 첫 시즌을 액션 경로로 돌리면 step 3에서 pending CHAPTER(chapterId `CHP-MATCH-001`)가 열린다(실제 팩·룰셋).
  2. **`resolveChapter(engine, careerId, decisionId, optionId)`**: `pending.chapterId`로 `pack.chaptersById`에서 정의를 찾아 `RESOLVE_CHAPTER { chapterId, definitionVersion: def.version, decisionId, optionId, outcomes: option.outcomes.map(o => ({ id, weight, effects, ratingDeltaTenths, kind?, addTags?, removeTags? })) }`. `ExecuteSuccess`(roll·outcomeId·appliedEffects·domainSnapshot).
  3. **`chapter-state.ts`**: `deriveChapterView(state, pack, ruleset)` — 정의·경기·`currentDecisionIndex = pending.resolved.length`·확정된 판단 목록(각각 팩 outcome으로 title·kind·narrative 복원)·완료 여부. pending이 CHAPTER가 아니면서 직전 타임라인이 `CHAPTER_RESOLVED`면 "결과 화면" 상태(`season.chapters`의 마지막 `ChapterRecord`로). 단위 테스트 분기 표.
  4. **SCR-031** `/career/$careerId/chapter?d=<index>`: 가드 — pending CHAPTER(`chapterId` 있음)이거나 결과 상태가 아니면 `screenForCareer`로. `d`가 `currentDecisionIndex`와 다르면 URL을 상태에 맞춰 바꾼다(뒤로 가기가 이전 판단을 다시 열지 않는다). 흐름:
     - **경기 전**(d=0 진입 시 한 번, 같은 화면 상단 고정): 왜 이 경기인가(정의 `importance`·`trigger.kind` 라벨: DEBUT "프로 데뷔전", DERBY "라이벌 더비", CUP_FINAL "컵 결승", DECIDER "결정전", TAG 정의 문구), 상대·대회(`opponent.name`, 리그/컵 `round`, 홈/원정), 선발 여부와 이유(`appearance` 라벨 + `season.selection.playerReason`을 "전술 적합도 차이 +12" 식으로), 감독 지시(`deriveTacticalRoom` 스타일 이름 한 줄). `SUB`면 "교체 투입" 문구(도메인이 0분 경기에는 챕터를 열지 않는다 — T-2-004 리뷰에서 보장).
     - **ChapterScoreboard**(`chapter-scoreboard.tsx`): 시간·스코어·체력·지시. 시간은 판단 순서 라벨(1 "전반", 2 "후반", 3 "종료 직전"; 판단이 2개면 "전반"·"후반"), 스코어는 **표시 전용 규칙**으로 그 시점까지의 득점만: 팀 득점 i는 `floor(90 × i / (goalsFor + 1))`분, 실점도 같은 식, 판단 k의 분은 `k × 90 / (decisionsTotal + 1)` — 상태 저장 없음, 새로고침해도 같은 값(단위 테스트). 체력은 `state.state.fitness`. 진입 600ms 이내 등장, DSN-LINE-001 라인 320ms 1회(챕터 진입은 허용된 세 순간 중 하나), 모션 감소면 즉시.
     - **판단 k**: `prompt` + `ChoiceCard` 옵션(`RadioGroup`; 위험 `RISK_LABEL_KO`; **사전 확률** `priorProbability.successBp`가 있으면 "성공 확률 약 {round(bp/100)}%", 없으면 위험 라벨만; `previewEffects[].label`), "확정"(COMMITTING) → `resolveChapter` → 같은 화면의 **판단 결과 카드**(`ResultCard`: outcome `title`, `kind` 라벨, `narrative.situation`을 `renderNarrative`로, `appliedEffects` 요약, 평점 변화 "평점 {±x.x}") → "다음 판단" 또는 마지막이면 "경기 결과".
     - **경기 결과**: 스코어(최종), 개인 기록(`minutes`·평점 `ratingTenths/10`·포지션군 통계 `stats` 라벨·카드·부상), 변화(폼·감독 신뢰·팬 — 판단 결과들의 `appliedEffects` 합산, 태그 `addTags`), "다음" → `advance`? 아니다 — pending이 이미 null이면 `screenForCareer`(대시보드)로만 이동(명령 없음).
     - **재생**: 진입 시 `pending.resolved`에 있는 판단은 결과 카드로 접힌 상태(펼치기 가능)로 보여주고 다음 판단부터 연다. 확정 뒤 새로고침·뒤로 가기·앞으로 가기 어느 것도 `RESOLVE_CHAPTER`를 다시 보내지 않는다(revision으로 테스트).
  5. **대시보드**: CTA "핵심 경기 — {상대}" (T-2-007 자리표시 CTA 문구 교체). 분석 `screen_viewed`(SCR-031), `chapter_decision_resolved { chapterId, decisionId, optionId, outcomeKind }`.
  6. **E2E**(`e2e/chapter.spec.ts`, TEST-E2E-010): 계약 → SCR-005에서 **CHAPTER** 모드 → 시즌 시작 → 역할 제안 수락 → "진행" → step 3 SCR-031(데뷔전) → 판단 1 확정 → 판단 2 확정 → **새로고침** → 판단 1·2 결과가 접힌 카드로 보이고 판단 3이 열려 있다 → 판단 3 확정 → 경기 결과 → 다음 → 대시보드. revision이 정확히 3 증가(판단 3개 = RESOLVE_CHAPTER 3건), 새로고침 뒤 결과 문구가 같다. 뒤로 가기 두 번 뒤에도 revision 불변. 판단이 2개인 정의면 수에 맞춘다(정의를 팩에서 읽어 루프). `a11y.spec.ts`에 SCR-031 추가.
  7. **단위 테스트**: `toResolveChapterOutcomes`가 팩 정의와 일치(effects 완전성·ratingDeltaTenths·kind), `deriveChapterView` 분기 표, 스코어보드 분 계산, 사전 확률 문구, 재생(확정 2개 상태에서 렌더 → 3번째 열림), 액션 경로 stateHash가 `@offside/fixtures` career-05-chapter 골든과 같다(같은 선택).
- 만지지 말 것: `docs/`, `packages/*`, `apps/api`, T-2-007·T-2-009가 만드는 다른 화면(자리표시 파일 하나만 대체), 동기화·허브·온보딩·설정.
