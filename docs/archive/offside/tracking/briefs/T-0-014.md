# T-0-014: domain 명령 이름을 07 계약에 맞춰 `ADVANCE_STEP` → `ADVANCE`로 정렬

## 목표

`packages/domain`의 Phase 0 명령 이름 `ADVANCE_STEP`을 07 "로컬 명령 계약"과 `@offside/contracts`의 `COMMAND_TYPES`가 쓰는 `ADVANCE`로 바꾼다. 이렇게 하면 engine-client(T-0-007)와 api 리플레이(T-0-008/011)가 명령 로그의 `commandType`을 매핑 없이 그대로 쓴다. 상태 값은 바뀌지 않으므로 golden hash도 그대로다.

## 참조 명세

- 요구사항 ID: 07 "로컬 명령 계약" CMD-SIM-002(`ADVANCE`), ADR-005
- 읽어야 할 코드: `packages/domain/src/simulate.ts`, `simulate.test.ts`, `fixture-determinism.test.ts`, `__fixtures__/career-01.json`·`career-01.ts`, `packages/contracts/src/commands.ts`

## 시작 전 필수

- 워크트리는 `origin/main`에서 만들어졌고 T-0-003(contracts)이 머지된 뒤다(`packages/contracts/src/commands.ts`에 `COMMAND_TYPES`가 있어야 한다). 아니면 `git fetch origin && git reset --hard origin/main`.
- Node 22.13 이상. 전체 체인 통과 상태에서 시작.

## 범위

만질 경로: `packages/domain/**`(이름 변경만), `packages/contracts/src/commands.ts`(주석 한 단락만).

만지지 말 것: 그 외 전부. 로직·fixture 값·테스트 의미를 바꾸지 않는다.

### 할 것

1. `packages/domain/src/simulate.ts`: `Command` 유니온의 `'ADVANCE_STEP'`을 `'ADVANCE'`로. 함수 이름 `advanceStep`은 그대로 두어도 된다. 오류 메시지·주석의 `ADVANCE_STEP`도 `ADVANCE`로.
2. `packages/domain/src/__fixtures__/career-01.json`: 명령 8개의 `"type": "ADVANCE_STEP"` → `"ADVANCE"`. golden 파일은 손대지 않는다(값이 같아야 한다).
3. 테스트 파일들의 문자열 갱신. `grep -rn ADVANCE_STEP packages/` 결과 0건.
4. `packages/contracts/src/commands.ts`의 `COMMAND_TYPES` 위 주석이 "domain Command의 이름과 같게 유지한다"로 이미 바뀌어 있는지 확인만 한다(T-0-003 리뷰에서 수정됨). 남아 있으면 그 문장만 고친다.
5. 타입 고정 테스트 하나 추가(`packages/domain/src/simulate.test.ts`): `expectTypeOf<Command['type']>().toEqualTypeOf<'CREATE_CAREER' | 'RESOLVE_EVENT' | 'ADVANCE'>()`.
