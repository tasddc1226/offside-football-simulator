# T-2-005: 시즌 결산 — `SeasonResult`·성장(훈련·출전·경험·연령)·폼/체력/사기 갱신·출전 약속 이행·원인 태그·결산 hash

## 목표

`SETTLE_SEASON`이 시즌을 닫을 때 결산 결과 `SeasonResult`를 만들어 `seasonHistory`에 남기고, 성장식(D-39)으로 `attributes`·Base OVR을 갱신한다.
시즌 중에는 매 step의 경기 결과로 폼·체력·사기가 움직인다(roll 없음). 결산 화면(SCR-015, T-2-009)이 "OVR 변화"와 "Expected Performance 변화"를 원인별로 분리해 보여줄 수 있게 원인 태그를 남긴다.
저장되는 모든 수는 정수(D-36). 한 시즌에 잠재력을 넘지 않는다(balance-targets "한 시즌 잠재력 초과 0").

## 성장식(D-39, 결산 시 1회, roll 없음)

정수 산술만 쓴다(bp = 1/10000, centi = 1/100). 나이는 결산 시점 `state.age`(증가 전).

1. **연령대**: `U21`(≤21), `PRIME`(22~29), `VETERAN`(≥30).
2. **시즌 성장 예산** `budgetCenti = growthRules.budgetCenti[ageBand] × min(gap, growthRules.gapCap) / growthRules.gapCap`, `gap = truePotential − baseOvr(결산 직전)`. gap ≤ 0이면 0.
3. **출전 계수** `minutesBp = clamp(minutes × 10000 / growthRules.minutesFull, growthRules.minutesFloorBp, 10000)`. 0분 시즌도 훈련 몫(`minutesFloorBp`)은 받는다.
4. **경험 보너스** `experienceCenti = min(ratedMatches × growthRules.experiencePerRatedMatchCenti, growthRules.experienceCapCenti) + (avgRatingTenths ≥ growthRules.goodRatingTenths ? growthRules.goodRatingBonusCenti : 0)`. `avgRatingTenths = ratingSumTenths / ratedMatches`(정수 나눗셈, ratedMatches 0이면 보너스 없음).
5. **능력별 몫** `shareBp(k) = clamp(roleWeightBp(k) × growthRules.roleWeightScale + growthRules.baseShareBp + (k ∈ focusGroup ? growthRules.focusShareBp : 0), 0, 10000)`. `roleWeightBp`는 `player.archetypeId` 아키타입 `roleWeights × 10000`. `focusGroup`은 `trainingFocus`가 `TECHNICAL`(기술 7)·`PHYSICAL`(신체 7)·`MENTAL`(정신 6)일 때 그 그룹, `ROLE`이면 없음.
6. **연령 배수** `ageMultBp(group(k), age)`: 룰셋 `growthRules.ageCurves[group]`(group = `TECHNICAL`|`PHYSICAL`|`MENTAL`|`GOALKEEPING`; `goalkeeping` 키만 GOALKEEPING, 나머지는 위 3그룹) — `[{ maxAge, multBp }]` 구간표(오름차순, 마지막 maxAge 99). 초기값: PHYSICAL 25→10000·28→5000·99→0, TECHNICAL 20→8000·29→10000·32→5000·99→0, MENTAL 23→7000·33→10000·99→3000, GOALKEEPING 26→8000·34→10000·99→3000.
7. **하락** `declineCenti(k) = max(0, age − growthRules.decline[group].startAge) × growthRules.decline[group].perYearCenti`. 초기값: PHYSICAL 29·40, TECHNICAL 32·25, MENTAL 34·20, GOALKEEPING 35·25.
8. **능력별 centi** (한 번에 계산, `Math.trunc` 1회):
   `trainingCenti = trunc(budgetCenti × shareBp / 10000 × ageMultBp / 10000)`, `minutesCenti = trunc(trainingCenti × minutesBp / 10000) − trainingCenti`(출전 부족분은 음수로 표기 — 원인 분리용), `experienceCenti(k) = trunc(experienceCenti × shareBp / 10000 × ageMultBp / 10000)`, `ageDecline = −declineCenti(k)`.
   `carry(k) = growthCarryCenti[k] + trainingCenti + minutesCenti + experienceCenti(k) + ageDecline`; `delta(k) = trunc(carry / 100)`; `growthCarryCenti[k] = carry − delta × 100`.
9. **상한**: `delta(k) = clamp(delta, growthRules.seasonDeltaMin(−3), growthRules.seasonDeltaMax(+4))`, 속성값 `clamp(1, 99)`. 잘린 양은 carry에 남기지 않는다(버린다).
10. **잠재력 cap**: 적용 뒤 `computeBaseOvr(attributes, roleWeights) > truePotential`이면 양의 delta를 `roleWeight` 내림차순(같으면 키 순)으로 1씩 줄이며 `≤ truePotential`이 될 때까지 반복. 줄인 만큼 `causes`에 `POTENTIAL_CAP`(음수 centi ×100)을 남긴다.
11. `player.profile.baseOvr`을 다시 계산해 저장하고 `baseOvr.before/after`를 기록한다. `causes`는 항목별 centi(`TRAINING`=trainingCenti, `MINUTES`=minutesCenti, `EXPERIENCE`, `AGE_DECLINE`, `POTENTIAL_CAP`)를 0이 아닌 것만 남긴다.
12. 룰셋 초기 상수(`growthRules`, `packages/content` 소유): `budgetCenti { U21: 600, PRIME: 200, VETERAN: 0 }`, `gapCap 20`, `minutesFull 2400`, `minutesFloorBp 3000`, `experiencePerRatedMatchCenti 4`, `experienceCapCenti 120`, `goodRatingTenths 700`, `goodRatingBonusCenti 60`, `roleWeightScale 8`, `baseShareBp 1500`, `focusShareBp 2500`, `seasonDeltaMin -3`, `seasonDeltaMax 4`. **이 값은 출발점이다** — 아래 밸런스 테스트가 balance-targets 표를 만족할 때까지 `ruleset.json`의 상수만 조정하고, 최종 값과 측정표를 PR 본문에 적는다. 식의 모양은 바꾸지 않는다.

## 시즌 중 폼·체력·사기(roll 없음, 매 step 경기 뒤)

`createStepMatchWiring`이 step의 경기를 다 돌린 직후 `applyCondition(state, records, rules.conditionRules)`을 한 번 부른다(step당 1회, 경기 0건인 step도 부른다 — 회복·회귀용).

- **폼**: 경기가 있으면 `form += clamp(trunc((avgRatingTenths − conditionRules.formPivotTenths) / conditionRules.formDivisorTenths), −formStepMax, +formStepMax)`(평점 있는 경기 평균; 평점 없는 경기만이면 0). 경기가 없거나 전부 0분이면 `form`을 `seasonBoundaryReset.form` 쪽으로 `formDriftPerStep`만큼 이동.
- **체력**: `fitness = clamp(fitness + fitnessRecoveryPerStep − Σ trunc(minutes / fitnessCostMinutes) − (부상 발생 시 injuryFitnessCost), 0, 100)`.
- **사기**: 경기마다 `WIN +moraleWin`, `LOSS −moraleLoss`, `START +moraleStart`, `NOT_SELECTED −moraleNotSelected`, `UNUSED_SUB −moraleUnusedSub`; step 합을 `clamp(−moraleStepMax, +moraleStepMax)`한 뒤 더하고 `clamp(0,100)`.
- 초기 상수(`conditionRules`): `formPivotTenths 650`, `formDivisorTenths 25`, `formStepMax 4`, `formDriftPerStep 2`, `fitnessRecoveryPerStep 4`, `fitnessCostMinutes 30`, `injuryFitnessCost 10`, `moraleWin 2`, `moraleLoss 2`, `moraleStart 1`, `moraleNotSelected 2`, `moraleUnusedSub 1`, `moraleStepMax 5`.
- 이 값들은 다음 경기의 `expectedPerformance`(selection.ts)로 들어가므로 골든의 선발·출전·draws가 바뀔 수 있다. 시즌 경계에서는 기존 `seasonBoundaryReset`이 그대로 회귀시킨다.

## 출전 약속·역할 변화·DEFERRED

- `promiseFulfilment`: `promised = contract.rolePromise`(계약 없으면 `season.squadRole` 시즌 시작값), `minutesShareBp = minutes × 10000 / possibleMinutes`(possibleMinutes 0이면 0), `delivered`는 룰셋 `contractRules.promiseMinutesShareBp { STARTER: 6500, ROTATION: 4000, BENCH: 1500, RESERVE: 0 }`에서 share 이상인 가장 높은 역할, `fulfilled = rank(delivered) ≥ rank(promised)`. 미이행 결과(감독 신뢰·이적 제안)는 Phase 3 계약 작업이 쓴다 — 여기서는 기록만.
- `roleChanges`: 이 시즌 timeline의 `ROLE_RESOLVED` 항목에서 `type`(refId)·`decision`을 뽑는다. `decision`은 현재 timeline에 없다 — `TimelineEntry.refId`를 `${proposal.type}:${decision}`으로 바꾸고(`resolveRole`), 기존 골든의 refId가 바뀌므로 골든 재기록 사유에 적는다.
- `DEFERRED` Effect(`appliesAt: NEXT_SEASON_STEP`): `startSeason`이 `state.deferredEffects`를 비우고, 걷기(`walkToNextDecision`) 중 각 step에 들어갈 때 `appliesAt.step === step`인 항목을 `applyEffects`(kind를 원래 target의 kind로 해석: `target`이 `state.*`면 CURRENT, `relationships.*`면 RELATION, `context.*`면 CONTEXT, attributes면 PERMANENT — `effects.ts`에 `resolveDeferredKind`를 두고 스키마가 허용하는 target만)로 적용한다. 현재 팩에 DEFERRED가 없으면 단위 테스트로만 검증한다.
- 결산 hash: `hash.ts`의 `hashState`가 쓰는 canonical 직렬화 + `sha256Hex`로 `hash`를 뺀 `SeasonResult`를 해시한다(`hashSeasonResult` export). `SETTLE_SEASON` 응답 `SimulationResult`에 `seasonResult`를 실어 준다(snapshot에도 있으므로 웹은 둘 중 하나만 써도 된다).

## 제약

- `Date`·`Math.random` 금지, 정렬은 안정 키, 반올림(`Math.trunc`)은 함수마다 한 번. 저장되는 모든 수는 정수(D-36).
- `truePotential`·`scoutedPotential*`·`archetypeId`·`context.*`·경쟁자 값은 바뀌지 않는다. `attributes`는 결산 시 성장식으로만 바뀐다(시즌 중 PERMANENT Effect는 기존 경로 그대로).
- 문구·주석 한국어. 커밋 `T-2-005: …`, 브랜치 `T-2-005-…`.
- 서브에이전트를 띄우지 않는다 — 리뷰용이든 조사용이든 전부(gstack `/review`·`/codex`·adversarial·`/simplify`·병렬 fork·Agent/Explore 조사 에이전트 금지). 예외는 Orca PR 게이트용 `/review:pr` 1회(로컬 모드).
- e2e 전에 `lsof -nP -iTCP:5174 -sTCP:LISTEN`이 비어 있어야 한다. 비어 있지 않으면 `until ! lsof -nP -iTCP:5174 -sTCP:LISTEN >/dev/null; do sleep 10; done` 뒤 실행.
- PR 직전 `git fetch origin && git merge origin/main`. `pnpm-lock.yaml` 충돌은 `git checkout origin/main -- pnpm-lock.yaml && pnpm install --no-frozen-lockfile` 뒤 전체 체인 재실행.
- 명세를 고치지 않는다. D-29·D-39와 충돌하면 그 항목만 PR 본문에 적고 나머지를 끝낸다. `apps/web`은 건드리지 않는다(T-2-009).

## 진행 보고

- 체크포인트마다 `orca worktree set --worktree active --comment "..."` 갱신.
- 막히면 질문을 PR 본문 또는 터미널에 남기고 멈춘다.
- 끝나면 PR을 열고 본문에 요구사항 ID, 최종 `growthRules`·`conditionRules` 값과 밸런스 측정표, golden 전후 표(hash·draws), Snapshot 최대 크기, 테스트 방법, 범위 밖 발견 사항을 적는다. 마지막 줄에 `DONE <head sha>`.
