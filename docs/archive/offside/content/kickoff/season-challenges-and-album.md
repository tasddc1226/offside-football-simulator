# SEASON 1: KICKOFF 도전과 시즌 앨범

KICKOFF의 시즌 메타는 순위 경쟁이 아니라 여러 축구 인생을 다시 시작할 이유를 제공한다. 도전은 플레이 방식을 제안하고, 시즌 앨범은 결과보다 선택과 서사를 기억한다.

## 적용 범위

- `createdServiceSeasonId === "svc_kickoff"`인 Career만 KICKOFF 도전에 집계한다.
- `PRESEASON`에는 조건을 미리 볼 수 있지만 진행률은 쌓이지 않는다. `ACTIVE`부터 기록하고 `LOCKED`에서 신규 Career와 신규 진행을 막는다.
- `LOCKED` 뒤에도 이미 얻은 배지와 앨범은 보인다. 진행 중 Career는 생성 당시 ruleset과 content pack으로 끝까지 진행할 수 있지만 지난 시즌 도전에는 소급 집계하지 않는다.
- 하나의 Career가 여러 도전을 동시에 완료할 수 있다. 같은 도전의 보상은 프로필당 한 번만 받는다.
- 보상은 배지, 프로필 장식, 앨범 표지뿐이다. Base OVR, 능력치, 잠재력, 폼, 경기 확률을 바꾸지 않는다.

## 도전 판정 계약

도전 판정은 확정된 Snapshot, CareerEvent, FootballSeason settlement, Career Archive만 읽는다. 화면에서 계산한 값이나 사용자가 선택한 표시 엔딩은 입력으로 쓰지 않는다.

| 상태 | 의미 | 화면 표현 |
|---|---|---|
| `LOCKED` | 선행 기능·단계가 아직 열리지 않음 | 잠금 이유와 필요한 단계 |
| `AVAILABLE` | 도전 가능, 아직 조건 미충족 | 핵심 진행률 1~2개 |
| `COMPLETED` | 조건 충족, 보상 미수령 가능 | 완료한 Career와 근거 |
| `CLAIMED` | 보상 1회 수령 완료 | 완료 날짜와 배지 |

공통 판정 규칙:

1. Career가 KICKOFF에 귀속됐는지 먼저 검사한다.
2. 완료에 사용한 `careerId`, `sourceIds`, ruleset/content pack/legacy 버전을 함께 저장한다.
3. 하나의 명령이 두 번 도착해도 `serviceSeasonId + challengeId + ownerProfileId` 기준 보상은 하나만 생성한다.
4. 조건 정의가 바뀌면 `challengeSetId`를 올린다. 이미 완료한 기록을 취소하지 않는다.
5. 숨은 진행률은 쓰지 않는다. 정확한 숫자를 감추는 도전도 다음 행동은 문장으로 알려준다.

## KICKOFF 도전 10종

### CH-KO-001 라인 브레이커

**목표:** Base OVR 70 이하인 상태로 1부 리그 공식 경기에 데뷔한다.

| 항목 | 정의 |
|---|---|
| 완료 조건 | `competitionTier === 1`, 공식전 출전 시간이 1분 이상인 데뷔 경기 직전 확정 Base OVR이 70 이하 |
| 제외 | 프리시즌·친선전, 경기 뒤 성장한 OVR을 데뷔 전 값으로 소급 사용 |
| 진행 표시 | 현재 Base OVR, 1부 구단 소속/임대 여부, 공식 데뷔 여부 |
| 의도 | 낮은 OVR도 전술 적합도·폼·신뢰로 기회를 얻는다는 핵심 약속 증명 |
| 목표 완료율 | 도전 진입 Career의 8~15% |

### CH-KO-002 빌려 간 팀이 돌려주기 싫어한 선수

**목표:** 임대를 다녀온 뒤 원소속팀에서 주전이 된다.

| 항목 | 정의 |
|---|---|
| 완료 조건 | 임대 시즌 출전 시간 비율 60% 이상, 원소속팀 복귀 뒤 한 시즌 출전 시간 비율 60% 이상 |
| 제외 | 임대 구단 완전 이적, 복귀 전 다른 구단으로 완전 이적 |
| 진행 표시 | 임대 출전 비율 → 복귀 여부 → 원소속팀 출전 비율 |
| 의도 | 임대를 실패가 아니라 경로로 인식 |
| 목표 완료율 | 임대를 경험한 Career의 15~25% |

## 도전 카드 문구 규칙

- 제목 아래에는 조건을 한 문장으로 쓴다. 내부 필드명이나 확률은 노출하지 않는다.
- 진행률은 사용자가 다음에 무엇을 해야 하는지 보여주는 최대 두 줄만 쓴다.
- 완료 문구는 `성공`, `실패`가 아니라 달성한 사실을 말한다. 예: `OVR 68로 1부 데뷔전을 뛰었습니다.`
- 아직 불가능한 도전은 숨기지 않고 선행 기능을 설명한다. 예: `성인 대표팀이 열리면 도전할 수 있습니다.`
- 저조한 기록을 조롱하거나 다른 사용자와 비교하지 않는다.

## 개인 시즌 앨범

앨범은 KICKOFF에 귀속된 Career만으로 결정론적으로 생성한다. 글로벌 랭킹이나 다른 사용자의 수치는 사용하지 않는다.

| 앨범 카드 | 선택 기준 | 동률 해소 | 폴백 |
|---|---|---|---|
| 생성한 선수 | KICKOFF 생성 Career 수와 포지션군 분포 | 해당 없음 | 0명도 빈 상태 문구 제공 |
| 최고의 선수 | Legacy 밴드 우선, 엔딩 희귀도, Legacy Score | 먼저 은퇴한 Career, 그다음 careerId 문자열 | 은퇴 Career가 없으면 `아직 FULL TIME을 맞은 선수가 없습니다` |
| 가장 긴 Career | 결산한 프로 시즌 수 | 총 출전 시간, 생성 시각 | 첫 계약 이후 진행 중인 Career |
| 극적인 복귀 | 중대 부상 뒤 복귀하여 주전이 된 Career, 결장 기간 최장 | 복귀 후 선발 수 | 해당 없음 카드 생략 |
| 한 구단의 얼굴 | 한 구단 소속 시즌 수 최장 | 팬 관계, 출전 시간 | 해당 없음 카드 생략 |
| 대표 태그 | 보유 Career 수 × 희귀도 가중치가 가장 큰 태그 | 최근 획득, 태그 ID 문자열 | `첫 계약` 기본 기억 태그 |
| 시즌의 순간 | `bestMomentRef`의 서사 가중치 최대 | 먼저 확정된 sourceId | 첫 계약 또는 데뷔 |
| 나의 선택 | 가장 많이 고른 위험 라벨과 반복 선택 태그 | LOW→MEDIUM→HIGH 순 | 결정 기록 없음 문구 |

`최고의 선수`는 단순 OVR 최댓값으로 정하지 않는다. 아직 은퇴하지 않은 높은 OVR 선수와 완결된 낮은 OVR 커리어를 같은 척도로 비교하지 않기 위해 Archive의 밴드와 엔딩을 우선한다.

앨범 카드에는 선수 이름, 포지션·아키타입, 해당 사실, 근거가 된 최대 3개의 `sourceId`를 저장한다. 이름을 바꾸거나 콘텐츠 문구가 수정돼도 시즌이 `ARCHIVED`되면 확정 Snapshot을 유지한다.

## 시즌 전환 화면 계약

표제와 서브라인은 다음으로 고정한다.

```text
THE LINE HAS MOVED
새로운 라인이 그어집니다
```

본문은 두 영향을 분리해서 말한다.

- `진행 중인 선수`: 생성 당시 규칙으로 계속 플레이할 수 있고 삭제되지 않는다.
- `새로 만들 선수`: 새 시즌 ruleset, content pack, 도전에 귀속된다.

버튼은 `지난 시즌 앨범 보기`, `진행 중인 선수 계속하기`, `새 커리어 만들기`처럼 평이한 한국어를 쓴다. 새 Career를 확정하는 마지막 CTA에서만 `KICKOFF`를 쓴다. 시즌 결산에는 은퇴 전용 표제 `FULL TIME`을 쓰지 않는다.

## 분석 이벤트

| 이벤트 | 필수 속성 |
|---|---|
| `season_challenge_viewed` | serviceSeasonId, challengeId, state |
| `season_challenge_completed` | serviceSeasonId, challengeSetId, challengeId, careerId, sourceIds |
| `season_reward_claimed` | serviceSeasonId, challengeId, rewardId, idempotencyKey |
| `season_album_viewed` | serviceSeasonId, cardTypes, eligibleCareerCount |
| `season_transition_viewed` | fromSeasonId, toSeasonId, activeCareerCount |

분석에는 선수 이름과 자유 입력 텍스트를 보내지 않는다.

## 출시 판정

- 10개 도전 모두 고정 fixture에서 완료·미완료·경계값 판정이 재현된다.
- GK·DF·MF·FW가 각각 완료 가능한 도전을 최소 6개 가진다.
- 어떠한 보상도 경기 시뮬레이션 입력에 포함되지 않는다.
- 앨범을 두 번 생성해 같은 hash를 얻는다.
- 시즌 전환 중 생성 요청이 정확히 한 `serviceSeasonId`에 귀속된다.
- `LOCKED` 뒤 신규 진행이 생기지 않고 기존 Career가 삭제되지 않는다.
