## 확정 결함

### 1. 온보딩 2단계(정체성)에서 필드를 올바르게 채운 뒤에도 유효성 오류 문구가 사라지지 않음
- **재현 단계**: 캐릭터 생성 2/3단계("나를 소개하세요")에서 이름만 입력한 채 "다음" 클릭 → 성별/국적/주발에 "선택해 주세요" 경고 노출 → 이후 성별(남성)·국적(대한민국)·주발(오른발)을 모두 실제로 선택(내부 상태는 `aria-checked=true`, `select.value=KR`로 정상 반영됨을 확인)
- **기대**: 필드가 유효해지면 해당 경고 문구가 즉시 사라져야 함
- **실제**: 세 필드 모두 올바르게 선택된 뒤에도 화면에는 "성별을 선택해 주세요", "국적을 선택해 주세요", "주발을 선택해 주세요" 문구가 그대로 남아 있음. 이 상태에서 "다음"을 다시 누르면 정상적으로 3단계로 진행되므로, 실제 유효성 검증 로직은 통과했으나 화면 표시만 갱신되지 않는 것으로 확인
- **심각도**: P3(진행 차단 없음, 사용자 혼란 유발)
- **캡처**: functional-03-stale-validation-errors.png

### 2. 커스텀 라디오 버튼이 키보드 Enter/Space로 활성화되지 않음
- **재현 단계**: 시즌 진행 중 "커리어의 갈림길" 이벤트 선택 화면에서 `role="radio"` 버튼에 JS로 `.focus()`를 호출해 포커스를 확인(`document.activeElement`가 해당 버튼과 일치) → Space 키 입력 → 변화 없음 확인 후 다시 포커스 확인(여전히 해당 버튼에 포커스 유지) → Enter 키 입력
- **기대**: WAI-ARIA 라디오 패턴상 포커스된 라디오에서 Space(관례상 Enter도 다수 구현에서 지원)를 누르면 선택되어야 함
- **실제**: Space·Enter 모두 `aria-checked`를 변화시키지 못함(계속 `false`). 동일 요소를 마우스 포인터 이벤트 시퀀스로 클릭하면 정상 선택됨
- **심각도**: P2(키보드만 사용하는 사용자는 이 화면에서 선택지를 고를 수 없어 기능이 사실상 차단됨)
- **캡처**: functional-04-radio-keyboard-noop.png

### 3. 설정 화면의 "상세 버전" 표시가 실제 서비스 시즌 값과 불일치
- **재현 단계**: `/settings` → 데이터 관리 → 상세 버전 확인. 같은 시점에 `GET /v1/service-seasons/current` 응답 및 캐릭터 생성 확정(3/3) 화면의 "룰셋·콘텐츠 팩" 표시와 비교
- **기대**: 설정 화면의 룰셋/콘텐츠 팩 버전이 실제 활성 시즌 값과 일치해야 함
- **실제**: 설정 화면은 "룰셋 1.0.0 / 콘텐츠 팩 0.1.0 / 엔진 클라이언트 0.1.0"으로 표시. 반면 API와 캐릭터 생성 확정 화면은 "룰셋 1.3.0 / 콘텐츠 팩 0.5.0"으로 서로 다름
- **심각도**: P3(정보성 표시 불일치, 버그 리포트 시 잘못된 버전 정보를 참고하게 될 위험)
- **캡처**: 없음(텍스트로만 확인)

### 4. `/no-such-page` 404 화면이 서비스 디자인과 완전히 분리된 순수 텍스트
- **재현 단계**: `/no-such-page` 접속
- **기대**: 브랜딩이 적용된 404 안내 화면(홈으로 돌아가기 등)
- **실제**: HTTP 상태 코드는 404로 정확하나, 화면에는 스타일 없는 `<pre>Not Found</pre>`만 존재하고 `<title>` 태그도 비어 있음
- **심각도**: P3(기능적 문제 아님, UX 개선 여지)
- **캡처**: functional-02-404-bare.png

## 추정 결함·자동화 제약으로 미확정

- **라디오그룹 Tab 순회**: 이벤트 선택 화면에서 Tab 키만으로 순회할 때 포커스가 "스킵 링크 → 선수 상태 보기(summary) → 첫 라디오 → body"로 빠지는 패턴을 관찰했으나, 동일한 시퀀스를 세 차례 재현했을 때 착지 지점이 매번 달랐다(BUTTON/SUMMARY/스킵링크로 제각각). ego-browser 스킬 문서에 명시된 "부하 시 `wait`/`click`/`waitForElement` 타임아웃 가능" 경고처럼, 합성 Tab 키 디스패치의 타이밍 신뢰도가 이 환경에서 낮아 실제 앱의 Tab 순서 문제인지 자동화 도구의 한계인지 구분하지 못했다. 사용자 결함으로 단정하지 않는다.
- **이중 클릭 방지**: KICKOFF(캐릭터 확정)·계약 서명·설정의 "지금 동기화" 버튼을 클릭한 직후 `button.disabled`가 동기적으로 `true`로 전환되는 것을 관찰하지 못했다(항상 `false`). 다만 실제로 연속 클릭했을 때 단계가 중복 진행되거나 계약이 중복 체결되는 등의 부작용은 관찰되지 않았다. React 등 프레임워크의 상태 갱신이 비동기 배치로 처리되어 동기 체크 시점에 `false`로 읽혔을 가능성이 있어, 실제 이중 제출 취약점인지 자동화 체크의 한계인지 확정하지 못했다.
- **탭(`role=tab`) 전환 시 단순 `.click()` 무반응**: 포지션 구분 탭(골키퍼/수비수/미드필더/공격수)에서 순수 `el.click()` 호출로는 반응하지 않고, 완전한 포인터 이벤트 시퀀스(pointerdown/mousedown/pointerup/mouseup/click)를 모두 디스패치해야 전환되었다. 실제 사용자의 마우스 클릭은 이 시퀀스를 자연히 발생시키므로 실사용자 영향은 낮을 것으로 추정 — 자동화 도구의 단순 클릭 호출 한계로 판단하며 사용자 결함으로 단정하지 않는다.
- **시즌 결산 수치 vs "통산" 표 대조**: 커리어 진행 중 다중 시즌 누적 수치를 보여주는 별도의 "통산" 표를 홈/선수/기록 어느 탭에서도 찾지 못해 대조 자체가 불가능했다. 은퇴 화면에서만 노출될 가능성이 있으나 이번 세션은 은퇴에 도달하지 못해 확인하지 못했다. 각 시즌 자체의 결산 수치(시즌1: 23경기·1940분·평점6.5, 시즌2: 6경기·140분·평점6.1)는 애니메이션 종료 후 재조회해도 값이 안정적으로 유지됨을 확인했다.
- **"재발급"(복구 코드)·"로그아웃"·"Google 연결"·"프로필 삭제"·"이 기기 데이터 삭제" 버튼**: 안전 규칙에 따라 클릭하지 않고 존재만 확인했다 — 실제 동작은 검증하지 못했다.

## 콘솔·네트워크 수집 결과 요약

- **오류 수**: `window.onerror`/`unhandledrejection` 훅을 여러 차례 설치해 관찰한 결과 전 구간에서 0건.
- **상태 코드 분포**(직접 확인한 요청 기준): `GET /v1/service-seasons/current` → 200(다회, 정상), `GET /v1/health` → 200 `{"ok":true}`(정상), `GET /health` → 404(경로 자체 부재, API 네임스페이스가 `/v1/` 접두사를 쓰는 것으로 추정), `GET /no-such-page`(프론트엔드 라우트) → 404(정상적인 404 처리).
- **느린 요청**: 관찰된 요청 중 지연이 눈에 띄는 건 없었음(단, 전체 페이지 새로고침 후 훅이 리셋되어 세션 전체의 fetch 로그를 연속으로 수집하지는 못했으므로, 이는 완전한 네트워크 프로파일이 아니라 표본 수준의 관찰임).

## 제안 (우선순위)

1. (P2) 이벤트 선택 화면 등 커스텀 라디오 버튼에 키보드 Space/Enter 활성화 핸들러를 추가해 키보드 접근성을 확보한다.
2. (P3) 온보딩 2단계 필드 유효성 오류 문구가 값이 유효해지는 즉시(각 필드 change 시점) 재검증되어 사라지도록 수정한다.
3. (P3) 설정 화면 "상세 버전"의 룰셋/콘텐츠 팩/엔진 클라이언트 값을 실제 활성 시즌 값과 동기화한다(정적 빌드 상수 대신 `/v1/service-seasons/current` 등 실제 값을 참조하도록 검토).
4. (P3) `/no-such-page` 등 존재하지 않는 프론트엔드 경로에 서비스 브랜딩이 적용된 404 안내 화면을 제공한다.
5. (P3, 선택) 온보딩 이름 필드에 특수문자만으로 구성된 이름을 허용할지 정책을 검토한다(현재는 제한 없음).
6. (P3, 선택) 설정 페이지에도 개인정보처리방침·이용약관 링크를 노출해 랜딩 페이지를 거치지 않고 접근 가능하게 한다.

## 미검증 범위

- 브라우저 네이티브 "뒤로 가기(history.back())" 버튼 자체는 테스트하지 못했다(대신 동일 URL 재방문/새로고침으로 상태 유지를 검증했다).
- 캐릭터 생성 1단계에서의 키보드(Tab/Enter/Space) 조작은 별도 커리어 생성이 금지되어 재검증하지 못했다(이벤트 선택 화면에서만 검증).
- 시즌 결산 수치와 대조할 "통산(다중 시즌 누적)" 표를 찾지 못해 해당 대조 체크는 수행하지 못했다.
- 오프라인 30초 테스트는 규칙에 따라 생략했다.
- "재발급"·"로그아웃"·"Google 연결"·"프로필 삭제"·"이 기기 데이터 삭제"의 실제 동작은 안전 규칙상 검증하지 못했다(존재만 확인).
- 커리어 홈의 내부 스크롤 동작은 페이지 높이가 크지 않아 별도로 깊게 테스트하지 않았다.
- "버그·의견 보내기"(mailto 링크)는 클릭 시 OS 메일 앱이 열릴 수 있어 안전을 위해 실제 클릭은 하지 않았다(href와 주변 텍스트만 확인).
- 콘솔/네트워크 수집은 여러 차례의 전체 페이지 새로고침으로 훅이 리셋되어 완전히 연속적인 세션 로그가 아니다(표본 수준).
- 허브 화면에 다른 세션(디자인 리뷰 등)이 만든 것으로 보이는 커리어("QA디자인0907")가 함께 노출되었으나, 안전 규칙에 따라 열지 않았다.
