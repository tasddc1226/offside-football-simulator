# 운영 플레이 리뷰 — 디자인 관점 (2026-09-07)

- **진행 요약**
  - 커리어 이름: `QA디자인0907`
  - 시작 설정: 19세 · 여성 · 대한민국 · 오른발 · 선호 포지션 중앙 미드필더(아키타입: 중앙 플레이메이커) · 출발 배경 "학교팀에서 만든 기록" → 진로 "상위 팀 테스트를 준비한다" → 강동 로버스(2부, 벤치·15%, 주급 70만원, 등번호 38) 계약
  - 도달 지점: 시즌 1을 CHAPTER 모드로 완주(프로 데뷔전 포함, 12 step), 2부리그 1위로 시즌 결산 완료, 이적시장 제안 4건 비교 화면까지 확인. 설정·게임 가이드·FAQ 페이지 확인. 시간 제약으로 **시즌 2 실제 착수까지는 도달하지 못함.**
  - 뷰포트: 데스크톱(1264~1706px, 환경이 자동으로 조정됨) + 모바일 390×844(CDP 디바이스 오버라이드)
  - heredoc 약 34회, 소요 약 50분 (가이드 권장 30회/45분을 다소 초과)

- **세 줄 결론**
  1. 카드 기반 비교 UI(출발점 선택, 플레이 스타일, 제안 비교, 경기 챕터 판단 선택지)와 다크 테마 스포츠 톤이 화면 전반에서 일관되고 완성도가 높다.
  2. 하단 고정(sticky) CTA 버튼이 스크롤 전 초기 화면에서 마지막 카드·통계 행을 가리는 레이아웃 결함을 최소 4개 화면에서 반복 확인했다 — 우선 수정이 필요한 P1.
  3. 캐릭터 생성 도중 다른 이름·포지션의 선수 데이터가 내 화면에 순간적으로 노출됐고, 허브의 "최근 선수" 카드에도 내가 만들지 않은 커리어가 표시됐다 — 로컬 저장/동기화 경계 설계를 점검할 필요가 있다(추정 원인: 동일 기기·브라우저 프로필을 공유하는 다른 병렬 세션과의 충돌).

### 캐릭터 생성 1단계 — 정체성 (데스크톱 · `design-05`, `design-05b`)
- 좋은 점: 이름/성별/국적/주발 입력이 한 화면에 깔끔히 정리됨.
- 문제점(확정, 재현 불확실): 이름·성별·국적·주발을 입력한 직후 `captureScreenshot()`이 "Not Found" 화면을 반환했고(별도 캡처 없음), 재접속(reload) 시 정상적으로 내 입력값이 복원됐다. 그런데 곧이어(같은 URL, 새로고침 없이) 다시 확인했을 때 화면이 스스로 "확정" 단계로 넘어가 있었고, 그 확정 카드에는 내가 입력하지 않은 전혀 다른 데이터 — 이름 `QA게임성0907`, 포지션 `스트라이커`, 출발 배경 `학원 축구`, 스타일 `슈팅·위치선정·침착성` — 가 표시됐다(`design-05b-create-step2-identity-reload-desktop.png`). 다시 새로고침하자 내 데이터(`QA디자인0907`, 중앙 미드필더, 정체성 단계)로 정상 복귀했다. 이후 단계를 순서대로 다시 밟아 최종 확인 카드(`design-09`)에서는 내가 선택한 값이 정확히 반영됨을 확인했다.
- 심각도: **P1(확정 관찰, 원인은 추정)** — 실제로 화면에 다른 사용자로 보이는 데이터가 노출된 것은 스크린샷으로 확정. 다만 이것이 내 브라우저 세션 내부의 렌더링 경합인지, 동일 기기를 공유하는 별도 세션과의 데이터 충돌인지는 확정 짓지 못함. 근거: 이후 커리어 허브 화면(`design-42`)에서 "최근 선수" 카드로 정확히 같은 이름 `QA게임성0907`(스트라이커, 23세, 청연FC, OVR 72, "진행 중")이 나타났고, 스크린샷 보관 폴더에 내가 만들지 않은 `gameplay-*`, `functional-*` 파일이 동시에 쌓이고 있어 동일 기기·브라우저 프로필을 공유하는 다른 병렬 QA 세션이 있었을 가능성이 높음.

### 계약서 서명 (모바일 · `design-16`~`design-19`)
- 좋은 점: 계약 조건 카드(리그/기간/주급/계약금/역할약속/등번호)가 명확하고, 서명 섹션에 "직접 쓰기"/"이름 입력" 두 방식을 제공하며 이름 입력 모드의 placeholder에 선수 이름을 미리 채워 넣는 디테일이 좋음.
- 문제점 1(확정): "이름 입력" 모드의 인풋에 선수 이름(`QA디자인0907`)이 **placeholder로만** 표시되고 실제 값(value)은 비어 있어, 겉보기엔 이미 입력된 것처럼 보이지만 실제로는 입력을 해야 "서명하고 계약 확정" 버튼이 활성화된다. 사용자가 이미 채워진 줄 알고 바로 버튼을 눌렀다가 비활성 상태에 막힐 수 있음.
- 문제점 2(확정, 경미): "지우고 다시 쓰기" 버튼 라벨이 좁은 모바일 컬럼에서 "지우고 / 다시 / 쓰기" 3줄로 쪼개져 보여 시각적으로 어색함(`design-19`).
- 심각도: 문제점1 P2, 문제점2 P3

### 계약 확정 트레이딩 카드 연출 (모바일 요청·실제 렌더는 데스크톱 폭 · `design-20`)
- 좋은 점: 라이트 그린 배경의 "WELCOME TO 강동 로버스" 카드 + 팀명 워터마크 + 선수명/등번호/리그/역할/주급/기간 요약까지, 계약 완료의 임팩트가 잘 표현됨. 톤 전환(다크→라이트 그린)이 "새로운 시작"이라는 서사와 잘 맞음.
- 문제점: 이 스크린샷을 찍은 시점에 모바일 디바이스 오버라이드가 자동으로 해제되어 데스크톱 폭(1264px)으로 렌더링됐다(자동화 환경 이슈로 추정, 실제 모바일에서의 트레이딩 카드 레이아웃은 별도로 재확인하지 못함).
- 심각도: 관찰 내용은 참고용(미검증 범위 참고)

### 커리어 홈 — 5개 탭 (모바일 · `design-21`~`design-25`, 데스크톱 · `design-43`)
- 좋은 점: 헤더(팀·이름·나이·포지션·OVR), 탭바(홈/일정/선수/계약/기록), "지금 할 일" 카드, 폼/체력/사기 진행 바까지 첫 화면에서 한눈에 파악됨. "선수" 탭은 OVR/폼/체력/전술적합도/감독신뢰 5개 지표 + 라커룸 관계 태그로 구성이 좋음. "계약" 탭은 "휴대폰"이라는 재치있는 섹션명으로 계약 상태를 확인하는 컨셉이 통일감 있음. 시즌 1 종료 후에는 "제안 4건" + "최근 소식"(최근 이벤트 로그) 카드가 추가되어 다음 행동을 자연스럽게 유도함(`design-43`).
- 문제점(확정, 재현 실패로 별도 표기): "기록" 탭 콘텐츠는 실제로 확인하지 못했다 — 순수 DOM `.click()`으로 탭을 전환했을 때 반응이 없어(위 포지션 탭과 동일한 현상) 화면이 "홈" 탭 그대로 남아 있었고, 이를 인지하지 못한 채 파일명을 `기록 탭`으로 저장해 실제로는 "홈" 탭이 중복 캡처됐다. 아래 "미검증 범위"에 표기.
- 심각도: 콘텐츠 자체는 문제 없음(정상 확인된 탭 기준). "기록" 탭은 미검증.

### 프리시즌 계획 (모바일 · `design-26`, `design-27`)
- 좋은 점: 선수 카드 요약(포지션/아키타입/등번호), OVR/폼/체력, 시뮬레이션 모드(빠른 시즌/챕터 시즌)와 훈련 계획(역할집중/기술/신체/정신) 선택 구조가 명확.
- 문제점(확정): "챕터 시즌" 선택 직후 화면에서 하단 고정 "다음" 버튼이 시뮬레이션 모드 카드 하단 설명 텍스트("시즌당 결정 최대 6/10")를 가림 — 입단 테스트 화면과 동일한 패턴.

- **일관성: 4/5** — 카드 스타일, 배지, 버튼 톤, 카피 톤(위트있는 문구)이 온보딩부터 시즌 결산까지 잘 유지됨.
- **접근성: 3/5** — 포커스 링이 뚜렷하고 위험도 표시에 아이콘을 병행하는 점은 우수하나, 스티키 버튼의 콘텐츠 가림(최소 4개 화면)과 서명 인풋의 placeholder/value 혼동 가능성이 감점 요인.

## 제안 (우선순위 순)

1. **[P1] 하단 고정 CTA 버튼과 콘텐츠 겹침 해소** — 입단 테스트 이벤트, 프리시즌 계획, 경기 챕터 판단, 경기 결과 등 최소 4개 화면에서 스크롤 가능 영역의 `padding-bottom`을 sticky 버튼 높이만큼 확보하거나, 버튼 영역에 그라디언트 페이드 처리를 추가해 초기 진입 시에도 마지막 콘텐츠가 가려지지 않도록 수정. 근본 원인이 공통 레이아웃 컴포넌트(예: `os-shell-main` 스크롤 컨테이너)에 있을 가능성이 높으므로 해당 컴포넌트를 한 번에 고치면 여러 화면이 동시에 해결될 수 있음.
2. **[P1] 캐릭터 생성/허브 화면의 데이터 격리 점검** — 캐릭터 생성 중 다른 이름의 선수 데이터가 순간적으로 표시된 것과 허브 "최근 선수" 카드에 내가 만들지 않은 커리어가 나타난 현상을 재현·원인 분석할 것을 권고. 로컬 저장소(예: localStorage/IndexedDB) 키가 기기 단위로 스코프되어 있고 세션/탭 단위로 분리되지 않는다면, 실제 사용자가 여러 탭·프로필로 플레이할 때도 유사한 혼선이 발생할 수 있음.
3. **[P2] 이적 제안 비교 카드의 셀 높이 정렬** — "결정 기한"처럼 내용 길이가 크게 달라질 수 있는 필드는 툴팁/아코디언으로 축약하거나, 카드 간 행 높이를 `align-items: stretch` 등으로 맞춰 나란히 비교가 가능하도록 조정.
4. **[P2] 서명 인풋의 placeholder를 value로 오인하지 않도록 개선** — "이름 입력" 모드 진입 시 플레이어 이름을 placeholder 대신 실제 value로 미리 채워주거나(수정 가능하게), 버튼이 비활성일 때 "이름을 입력해 주세요" 같은 안내를 더 눈에 띄게 표시.
5. **[P3] 온보딩 인트로 슬라이드의 데스크톱 여백 조정** — 데스크톱 뷰포트에서 콘텐츠를 세로 중앙 정렬하거나 카드 높이를 콘텐츠에 맞게 줄여 하단 빈 공간을 줄이면 밀도가 개선됨.
6. **[P3] 좁은 컬럼의 버튼 라벨 줄바꿈 처리** — "지우고 다시 쓰기"처럼 좁은 폭에서 부자연스럽게 쪼개지는 버튼 라벨은 줄바꿈 없는 한 줄로 유지되도록 `white-space: nowrap` 또는 아이콘+짧은 라벨 조합으로 대체 검토.
