# OFFSIDE — 선수 육성 시뮬레이터 개편

2026-09-19 사용자 요청: 기존 개선 순서를 대체하는 전면 개편. 원작 SLB의 짧은 상황→선택→성장 리듬을 참고하며 선수 육성·우연한 기회·경기 성과를 중심에 둔다.

## 제품 기준

- 시즌 중심으로 빠르게 진행한다. 시즌 준비에서 육성 방향을 고르고, 경기 묶음을 진행하며 중요한 선택에만 개입한다.
- 기본 대시보드는 선수 현황·시즌 기록·다음 행동·다음 성취를 첫 화면에 모은다. 전체 일정·순위표·관계 원장은 상세에서 열어 본다.
- 흰색 표면과 선명한 구단색, 큰 기록 숫자, 짧은 피드백을 사용한다. 한 화면에 여러 서문이나 동일 선수 정보를 반복하지 않는다.
- 성장은 실제 능력 변화·출전·평점으로 보여준다. 존재하지 않는 XP나 달성하지 않은 보상을 만들지 않는다.
- 일반 사건은 시즌마다 연속 두 차례 끊지 않고 간격을 두며, 직전 시즌에 본 사건은 쉬게 한다. 처음 보는 후보를 우대하되 seed 기반 가중 추첨으로 커리어마다 다른 경험을 만든다.
- 부상·계약·대표팀처럼 실제 상태를 바꾸는 필수 결정은 자동 선택하지 않는다. 진행·새로고침·재시도에서 결과를 다시 뽑지 않는다.

## 이번 구현

1. 시즌 허브: 최근 경기, 출전·득점·평점, 성장·마일스톤, 접을 수 있는 일정/소식.
2. 육성 준비: 네 가지 훈련 방향을 한 화면에서 비교, 실제 능력과 직전 성장 연결, 선택 면담은 접기.
3. 사건과 결산: 중복 정보 제거, 실제 선택과 성장 결과에 시각적 우선순위.
4. 새 pair 2.0.0/0.7.0: 사건 간격·반복 보호·미경험 후보 우대. 과거 커리어는 생성 버전으로 재생.
5. 검증: 모바일 기본 화면 스크롤, 150% 글자, 키보드, 시즌 완주·저장, 구버전 해시, 새 버전 재생.

본 문서의 디자인·플레이 목표가 이전 브랜드 가이드의 '원작과 거리두기' 및 이전 점진 개선 순서보다 우선한다. 저장/동기화 보존은 플레이어 데이터 보호를 위한 구현 제약이다. 운영 전환은 실제 검증 결과를 기록한 릴리스에서 다룬다.

## 플레이 방법

Node 22에서 `pnpm dev:simulator`를 실행하고 `http://localhost:5301`에 접속한다.
개발 서버에서만 새 선수에게 2.0.0/0.7.0을 고정한다. 운영 서비스 시즌 포인터, 기본 폴백 버전, 기존 선수의 생성 버전은 바꾸지 않는다.

## 육성 기회

- 패스·첫 터치·지구력의 집중 훈련 사건 3종을 추가했다. 각 사건은 커리어당 한 번만 등장한다.
- 도전은 65% 확률로 해당 능력 +1, 성공 여부와 무관하게 체력 −6이다. 안전한 컨디션 정비와 회복도 고를 수 있다.
- 일반 사건 후보에서 현재·직전 시즌에 본 사건을 제외하고 미경험 후보의 추첨 가중치를 3배로 한다. 추첨·선택 결과는 기존 seed/replay/저장 체계를 따른다.
- 일반 필수 사건의 달력 배치를 4·5 단계에서 4·9 단계로 옮겼다. 상태에 필요한 부상·계약·대표팀 결정은 별도로 유지한다.

## 검증 기록

- 도메인 975개, 콘텐츠 489개 통과. 기존 golden hash와 신규 사건의 실제 능력·체력 변화, 같은 seed 재현, 중복 확정 방지를 포함한다.
- 웹 672개 중 화면 변경에 걸린 5개는 문구·접힌 영역 기대값을 갱신했고, 관련 5파일 86개를 다시 실행해 모두 통과했다. 나머지 667개는 전체 실행에서 통과했다.
- 새 pair로 360px 시즌 완주, 진행·결산 새로고침 저장 보존, 첫 화면 CTA 위치, 키보드 상세 열기, 150% 글자에서 수평 넘침 없음 확인. 허브·결산 axe 위반 0건.
- 이전 pair의 시즌 완주 및 다음 시즌 진입 E2E 통과.
- 무작위 선택 정책, 전 포지션, 20명·345시즌 일괄 시뮬레이션 실패 0건. `--verify` 재생 검증 포함. 결과는 `docs/qa/simulator-rebuild/simulation-summary.json`에 보관한다. 이 표본만으로 장기 밸런스가 확정되었다고 판단하지 않는다.
- 전체 타입 검사·린트·의존성 검사, 웹 production 빌드·초기 청크 예산·SEO 검사 통과.
- 전체 병렬 테스트 최초 실행에서는 부하에 따른 시간 제한 실패도 발생했다. 도메인은 워커 2개로 전체 재실행해 통과했다. 이번 작업에서 API 전체 회귀와 운영 동기화는 완료 판정하지 않는다.
- 콘텐츠 검증 경고 13건: 기존 일회성 계약 사건 10건과 신규 일회성 육성 사건 3건의 높은 추첨 가중치/재등장 cooldown 부재 안내. 신규 사건은 의도적으로 일회성이다.

## 범위

운영 배포 전의 플레이 가능한 개편 브랜치다. 새 규칙을 운영 기본으로 승격하는 릴리스와 전체 API·E2E 배포 검증은 포함하지 않는다. 신규 이용자의 기본 화면은 라이트이며, 저장된 테마 선택은 유지한다.

최종 추가 확인: 첫 방문 라이트 테마·선수 생성 CTA·axe 검사 통과. 훈련 문구 변경 영향 검사 6개 통과. 스크린샷은 `docs/qa/simulator-rebuild/`에 보관했다.


## 선수 생성 전면 개편 — 2026-09-19

원작의 짧은 프로필 입력 → 후보 카드 3장 공개 → 최종 선수 카드 흐름을 축구에 맞게 적용했다. 홈의 모든 신규 선수 진입점과 만들던 선수의 수정·재개 화면을 같은 흐름으로 연결한다.

- 첫 화면에서 이름·주발·8개 포지션·출발 배경을 정한다. 랜덤 이름을 제공하고, 국적·성별·배경 설명은 상세 프로필에 둔다. 기본 설정의 320/360px 화면에서는 상세 프로필과 진행 버튼까지 가리지 않고 보인다.
- 포지션별 세 후보를 개별 공개하거나 한꺼번에 연다. 실제 시작 OVR, 주요 능력 6개와 플레이 성향을 비교한다. 후보 수치는 커리어 seed와 고정 룰셋으로 계산하고, 공개·선택·새로고침은 RNG를 소비하지 않는다.
- 최종 선수 카드에서 이름·나이·포지션·OVR·성향·출발 배경을 확인하고 시작한다. 생성 전 안내 슬라이드, 세 패널 입력, 진입 대기 연출, 내부 버전 표시는 제거했다. 확정 후 첫 결정·계약·복구 흐름은 이어진다.
- 폼 입력과 후보 공개·선택은 세션에 보존한다. 저장 오류는 입력을 유지한 채 재시도하고, 같은 틱의 중복 제출은 커리어를 하나만 만든다. 포지션 변경 시 호환되지 않는 기존 후보는 해제한다.
- 후보 투영은 도메인의 실제 `CONFIRM_PLAYER`와 같은 생성 계산을 사용한다. 공개 시작 능력만 화면으로 전달하고 숨겨진 잠재력은 노출하지 않는다. 기존 커리어·규칙·콘텐츠 데이터는 수정하지 않았다.

검증: 웹 전체 83파일 672테스트 통과. 후속 UI/생성 테스트 41개 통과. 1.0.0과 2.0.0의 전 포지션·아키타입에서 후보 능력/OVR과 실제 확정 결과 일치 및 RNG 불변을 확인했다. 브라우저에서 생성·새로고침 복원·중복 확정·저장 재시도·확정 중 이탈 복구·키보드로 첫 계약 완주·복구 코드 재방문을 확인했다. 생성 세 화면의 axe 위반은 0건이다. 라이트/다크, 320/360px, 150% 글자에서 수평 넘침을 검사했다. 타입 검사·린트·production 빌드·초기 청크 예산도 통과했다. 백엔드 통신 검증은 스텁 기반이며 운영 배포는 하지 않았다.

화면 증거: `docs/qa/simulator-rebuild/creation-*.png`. 플레이 진입: `http://localhost:5301/onboarding`.
