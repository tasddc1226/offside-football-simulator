# Jev와 OFFSIDE 적용 검토

2026-09-20 기준. 최근 공개된 TypeSafe AI의 Jev를 대상으로 조사했다. 공식 문서·발표·게임 데모와 현재 저장소 코드를 대조한 설계 검토이며, Jev API 실측이나 운영 연동은 수행하지 않았다.

**판단: 도입을 실험할 가치는 있다. 첫 작업은 게임 외부에서 맥락 판단을 비교하는 실험이고, 검증 후 감독·에이전트의 반응 선택에 제한적으로 적용하는 것을 권한다.** 사용자가 원하는 선수 육성의 몰입감은 과거 선택을 기억하는 인물, 선택의 결과, 성장 피드백, 사건의 간격에서 나온다. Jev는 그중 상황에 맞는 반응을 고르는 부분을 도울 수 있다. 화면의 스크롤, 보상 연출, 콘텐츠 부족은 별도의 게임 설계 문제다.

## 확인한 기술과 한계

TypeSafe는 9월 15일 Jev를 early access로 공개했다. 상태와 질문을 입력받아 정해진 형태의 판단을 반환하는 System One 모델이다. 자유로운 대사나 이야기를 생성하는 용도가 아니다. [공식 발표](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [소개](https://docs.typesafe.ai/introduction)

| 종류 | 반환값 | OFFSIDE 예시 |
|---|---|---|
| Choice | 지정한 후보 중 하나, 후보별 확률, confidence | 감독이 격려·경고·기회 제공·개입 없음 중 무엇을 할지 |
| Score | 정의한 척도에 대한 점수, 분포, confidence | 사건과 최근 선수 상황의 적합도 |
| Noul | 질문에 대한 긍정 확률(0~1) | 이 사건이 최근 선택의 결과로 자연스러운가 |

Choice는 최대 255개 후보, Score는 2~10개 척도를 받는다. 서로 의존하지 않는 질문은 한 요청으로 묶을 수 있다. **Choice의 기본 결과는 최대 확률 후보다. 확률이 제공된다고 자동으로 다양한 사건을 무작위 생성하는 것은 아니다.** confidence도 선택의 올바름이나 플레이어의 재미를 보증하는 값이 아니다. [API](https://docs.typesafe.ai/api), [Choice](https://docs.typesafe.ai/primitives/choice), [confidence](https://docs.typesafe.ai/confidence)

현재 문서의 모델은 `jev-1.13.0`이다. `jev-latest` 별칭은 향후 모델 변경에 따라 결과가 달라질 수 있다. 텍스트·JSON을 입력받고 이미지·음성·영상 입력은 지원하지 않는다. 영어에 가장 강하고 한국어 등 CJK는 동일한 품질을 보장하지 않는다. 고객 요청·응답으로 학습하지 않는다고 명시하지만, 이것이 모든 계정의 무보관을 의미하지는 않는다. [모델 문서](https://docs.typesafe.ai/models)

공급사의 “환각 없음”은 정의한 출력 형식을 벗어나지 않는다는 주장으로 읽어야 한다. 판단 오류가 없다는 뜻으로 받아들이면 안 된다. 공식 한계 문서는 수치 계산·날짜 비교·복잡한 간접 추론·불필요하게 긴 입력·입력에 포함된 악의적 지시에 대한 약점을 설명한다. 능력치·금액·부상 확률·자격 조건은 코드로 계산해야 한다. [한계 문서](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

공급사 발표의 70~500ms와 수백 배 성능 비교는 해당 측정 조건의 결과다. 미국 서부 측정이며 한국 사용자의 지연 보장은 아니다. 게임 개발자 Sprite Fusion의 지형 선택 실험은 5회 요청에서 319~375ms를 기록했다. 게임 적용 가능성을 보여주는 작은 데모로 볼 수 있지만, 축구 시뮬레이터의 재미나 대규모 운영을 입증하지는 않는다. [공식 발표](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [데모 작성자의 기록](https://www.spritefusion.com/blog/generating-game-level-in-real-time-with-jev)

## 현재 코드와 맞물리는 지점

- `packages/domain/src/event-variety.ts`: 이미 최근 반복을 제한하고 미경험 사건의 가중치를 높인다. 난수는 기존 seed 기반 추첨에서 소비한다. 단순 반복 억제에는 모델이 필수가 아니다.
- `tooling/scripts/career-sim.ts`: 브라우저 없이 커리어를 실행하며 `first`, `random`, `opportunity` 선택 정책과 성장·출전·부상·계약·해시 결과를 수집한다. 별도 실험 실행기가 이 엔진을 호출하고 Jev가 합법적인 선택지를 고르는 방식으로 비교하기 좋다.
- `packages/domain`은 외부 I/O 없는 순수 엔진이다. 커리어 생성 시 ruleset/content pack을 고정하고 로컬 Worker와 IndexedDB에서 진행한다. 온라인 모델 의존은 오프라인 진행과 동일 입력 재현에 영향을 준다.
- 실제 서버 구현 `apps/api/src/sync/verify-snapshot.ts`, `apply-sync.ts`는 **명령 전체를 재시뮬레이션하지 않는다.** 상태 해시·형식·버전·불변식을 검증한다. CLAUDE.md의 서버 리플레이 설명보다 이 구현과 ADR-003을 기준으로 설계해야 한다.
- 런타임 생성형 AI 문장을 노출하지 않는 현행 프로젝트 규칙이 있다. 저작된 콘텐츠 ID를 선택하고 준비된 대사를 표시하는 방식은 이 방향과 맞는다. 출시 채널의 최신 외부 정책 충족 여부를 확정한 것은 아니다.

## 적용 우선순위

| 적용 대상 | 권고 | 이유와 전제 |
|---|---|---|
| 자동 플레이테스트·상황 적합도 평가 | 우선 실험 | 기존 CLI와 별도 실험 도구를 이용할 수 있고 실제 저장·진행에 영향이 없다 |
| 감독·에이전트의 반응 | 첫 사용자 기능 후보 | 관계와 최근 행동에 맞는 준비된 반응을 골라 인물의 일관성을 높일 가능성 |
| 사건 편성·연속 사건 분기 | 비교 실험 뒤 검토 | 조건·쿨다운·필수 사건을 코드로 먼저 거르고 맥락 적합도만 평가 |
| 훈련 조언 카드 | 작은 실험 가능 | 경기 결과를 바꾸지 않고 준비된 조언을 고를 수 있음. 기존 수식만으로 충분한지도 비교 |
| 성장량·잠재력·경기 승패·연봉 산정 | 현재 도입 비추천 | 정밀 수치·공정성·재현성과 설명 가능한 규칙이 우선 |
| 무제한 대사·이야기 생성 | 용도 불일치 | Jev는 자유로운 문자열 생성 모델이 아님 |

예를 들어 “출전이 줄었고, 이전 면담에서 기회를 약속했으며, 훈련 태도는 좋다”라는 상황에서 감독 반응을 고르게 한다. 후보는 작성된 `약속 이행 면담`, `전술 역할 조정`, `훈련 격려`, `개입 없음`이다. 답변 문구와 실제 출전·신뢰도 변화는 버전이 고정된 콘텐츠와 규칙이 담당한다. 감독 성향·과거 약속·선택 결과를 저장하는 설계가 먼저 있어야 이 기능이 살아난다. 모델 자체가 장기 기억을 대신하지 않는다.

**모델 확률은 게임의 목표 발생 빈도와 다르다.** 가장 그럴듯한 사건만 계속 고르면 다양성이 낮아질 수 있다. 필수 사건·자격 조건·쿨다운·사건 수 상한은 코드로 보장하고, 적합도 결과를 어떻게 제한된 정수 가중치로 변환할지는 독립적으로 설계·버전 관리해야 한다. 필요한 경우 `개입 없음`을 후보에 포함해 이벤트가 없어도 되는 시점을 허용한다.

## 권장 실험

1. 200~500개의 합성 상황을 만든다. 벤치 장기화·유망주 돌파·부상 복귀·약속 불이행·이적 갈등 등으로 나누고, 경기 수·나이·관계 추세는 코드에서 요약한다. 실제 사용자 이름·계정·전체 저장 파일은 불필요하다.
2. 같은 후보와 상황에 대해 기존 규칙, 단순 성향 규칙, Jev를 비교한다. 한국어 원문과 명확한 구조 필드 중심 입력도 비교한다. 후보 순서를 바꾸었을 때의 변화, 반복 호출, 상충하는 반응을 점검한다.
3. 사람이 답안의 자연스러움·인물 성향 일관성·과거 선택 반영을 블라인드 평가한다. Jev가 스스로 매긴 재미 점수를 성공 지표로 삼지 않는다. 이벤트 반복률·무개입 비율·후보 분포·실패율·한국 환경 p50/p95 지연·실제 입력 토큰도 기록한다.
4. 기존 seed 집합으로 커리어를 돌려 성장·부상·출전·경력 결과가 의도치 않게 변하는지 확인한다. 우선순위가 맥락 추천만이면 실제 엔진 결과는 바꾸지 않는 shadow 방식으로 비교한다.
5. 충분한 개선이 확인되면 감독 반응 한 종류에 제한적으로 적용한다. 최소 목표는 불가능한 선택 0건, 기존 진행/저장 회귀 0건, 기존 규칙 대비 사람 평가 개선이다. 구체적인 개선 폭은 실험 전 고정한다.

최초 실험은 모델 버전·질문 버전·입력 요약·후보 목록·응답을 기록한다. 운영 기능으로 발전시키려면 서버 측 API 키, 호출 제한, 허용 후보 검증, 응답을 사용할 수 있는 career revision 확인, 멱등 저장, 타임아웃 시 기존 규칙 복귀가 필요하다. 온라인 결과를 게임 상태에 반영한다면 결과를 명시적인 외부 입력으로 저장하고 재생에서는 저장한 입력을 사용해야 한다. 모델을 재호출해 같은 값이 나오기를 기대하는 것으로 결정론을 보장할 수 없다. 이는 현재 코드에 없는 신규 설계다.

오프라인·보존성을 우선하면 검토를 거친 콘텐츠 조건과 가중치를 새 콘텐츠 팩으로 발행하는 접근도 가능하다. 기존 팩이나 과거 커리어를 수정하지 않는다. 모델 출력으로 대체 모델을 학습하는 계획은 본 제안에 포함하지 않는다.

## 비용과 도입 조건

공개 가격은 입력 100만 토큰당 **$0.042**, 출력 무료다. 가정상 요청 전체가 2,000 입력 토큰이면 1회 약 $0.000084다. 일 사용자 1만 명이 하루 20회 호출하고 30일 운영하면 월 600만 요청·120억 입력 토큰, 약 **$504/월**이다. 하루 5회면 약 **$126/월**이다. 부가 인프라·재시도·세금·환율은 제외한 산술 예시이며 실제 계정 과금이나 트래픽 전망이 아니다. [가격·한도](https://docs.typesafe.ai/models)

공개 한도는 현재 1,200 RPM과 초당 250,000 토큰이며 변동 가능하다고 명시한다. 위 20회 시나리오는 평균 약 139 RPM·초당 4,630 토큰이지만 피크 트래픽은 따로 계산해야 한다. 모델 접근 권한·계정별 한도·유료 사용 조건을 확인한 뒤 실제 실험을 시작한다. 미국 리전 호출과 실패 복구 때문에 매 프레임·매 경기 세부 판정 호출은 이 게임에 적합하지 않다.

운영 적용 전에 검토할 문서는 [서비스 계약](https://typesafe.ai/legal/mca)과 [모델의 데이터 처리 설명](https://docs.typesafe.ai/models)이다. 공개 계약에는 성능 정보 게시 제한 등이 있으므로 실험 결과를 외부에 공개하려면 적용 계약을 확인해야 한다. 이 문서는 법률 판단이 아니라 구현 전에 확인할 서비스 조건을 기록한다.

**추천 다음 작업:** 별도 실험 도구에서 “감독 반응 선택” 200개 상황을 기존 규칙과 비교한다. 그 결과가 인물의 일관성과 과거 선택의 영향이라는 사용자의 목표에 도움이 되는지 확인한 뒤 온라인 기능을 설계한다. Jev 도입 자체를 전면 개편의 출발점으로 삼기보다, 필요한 게임 메커니즘을 정하고 그 안의 어려운 맥락 판단에 사용한다.
