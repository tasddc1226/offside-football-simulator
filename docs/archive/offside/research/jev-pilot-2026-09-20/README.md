# OFFSIDE Jev 파일럿 — 로컬 실험 결과

2026-09-20. **기존 엔진 실험은 실행했다. Jev 비교는 API 인증 정보가 없어 미실행이다.** Jev 응답을 다른 모델이나 규칙으로 대체하지 않았다. 요청 0회, API 비용 0. 이 기록은 Jev 성능 평가나 도입 효과의 증거가 아니다.

**현재 확인한 우선순위는 반복 사건의 종료·후속 분기 설계다.** “더 똑똑하게 고르는 AI”를 붙여도 선택 후보의 효과가 이미 소진된 상태면 선수 육성의 체감은 개선되기 어렵다. 아래 관측은 실제 운영 데이터가 아닌 합성 커리어에서 얻었다.

## 실험 방법

- 코드 기준: `6c674cb`의 엔진, ruleset 2.0.0/content pack 0.7.0, FAST.
- 동일한 seed 40개, GK/DF/MF/FW 각 10명, 커리어당 10시즌. `random`과 `opportunity` 각 40개를 실행했다. 총 80커리어 실행·800시즌이며 독립 시드 수는 40이다.
- 별도 관측 실행으로 random 40개를 다시 재생했다. 결과 해시 40/40 일치. 관측 코드는 난수·명령에 영향을 주지 않았다.
- 민감도 실험으로 동일 사건에서도 방문 시점에 따라 선택지가 바뀌도록 CLI 사본만 변경해 40개·400시즌을 추가했다. 운영 코드·저장·콘텐츠는 수정하지 않았다.
- 자동 플레이 정책은 인간 플레이와 다르다. FAST라 경기 챕터 선택 체감도 측정하지 않는다. 재미·몰입·한국어 이해·Jev 지연은 평가하지 않았다.

## 관측 1: 재등장 사건이 선택의 수치 결과를 잃을 수 있다

기준선의 사건 해결 916회 중 382회(41.7%)가 동일 커리어에서 이미 경험한 사건 ID였다. 부상·대표팀은 반복 필요성이 있어 이 숫자를 곧바로 결함 비율로 해석할 수 없다. 해당 두 계열을 제외하면 567회 중 115회(20.3%)가 재등장이었다. 계약 등 다른 필수 결정은 남아 있으므로 이 역시 순수한 선택형 서사 사건의 반복률은 아니다.

가장 명확한 사례는 `EVT-REL-008`(에이전트 관계 정리)이다.

| 관측 | 사건당 선택 고정: 기존 CLI | 방문마다 선택 변경: 실험 CLI |
|---|---:|---:|
| 전체 등장 | 104 | 104 |
| 같은 커리어에서 재등장 | 79 | 79 |
| 재등장 중 관계 수치 변화 없음 | 79 | 41 |

정적 코드 근거도 일치한다. 사건 조건은 `relationships.agent < 45`이고, 선택 효과는 `ONCE_PER_SOURCE`다. 같은 효과는 커리어 전체에서 다시 적용되지 않는다. 재발 후 선택을 바꾸면 아직 사용하지 않은 효과가 적용될 수 있지만, 방문마다 선택을 바꾼 실험에서도 41회는 관계 수치가 변하지 않았다.

이는 “아무것도 바뀌지 않은 명령”이라는 뜻은 아니다. 타임라인·사건 해결 기록·후속 상태 등은 별도이며, 표는 **관계 수치 변화**만 측정한다. 모든 반복 사건이 문제라는 뜻도 아니다.

권고: 일회성 면담이라면 종료 태그를 두거나 재발 전용 후속 사건으로 전환한다. 반복 가능한 면담이라면 효과·문구·조건을 함께 설계해야 한다. 수치를 매번 지급하는 식으로 전역 중복 방지를 없애면 보상 반복 획득 문제가 생긴다. 이 변경은 새 콘텐츠 버전에서 검증할 사안이다.

## 관측 2: 현재 random 정책은 사건마다 다시 무작위 선택하지 않는다

`legacy-population-choices.ts`는 선택 키에 seed·pending 종류·event ID·version을 사용하고 시즌·방문 횟수를 넣지 않는다. 따라서 한 커리어에서 같은 사건이 재등장하면 같은 선택을 한다. 이는 재현 가능한 성향 모델로는 유효하지만, 다양한 사람의 순간 선택을 흉내 낸다고 해석하면 안 된다.

이 때문에 방문별 선택을 바꾸는 민감도 실험을 추가했다. 위 반복 문제는 이 실험에서도 일부 남았다. 앞으로 Jev 플레이테스트를 평가할 때도 고정 성향·방문별 탐색·실제 플레이 기록을 서로 다른 비교군으로 둬야 한다.

## 관측 3: 무엇을 좋은 커리어로 볼지에 따라 정책 평가가 바뀐다

| 지표: 같은 40개 시드, 10시즌 | random | opportunity |
|---|---:|---:|
| 실패 커리어 | 0/40 | 0/40 |
| 평균 최고 OVR | 68.33 | 68.83 |
| 시즌당 부상 | 1.06 | 1.36 |
| 1부 도달 | 25/40 (62.5%) | 4/40 (10.0%) |

`opportunity`는 구단 경쟁 순위·전술 적합도를 우선하고 상황에 따라 잔류하는 정책이다. 상위 리그 진출을 최대화하는 정책이 아니다. 두 정책은 시장·역할 등 여러 결정이 다르므로 위 차이를 하나의 행동 탓으로 단정할 수 없다. 같은 초기 seed라도 이후 명령·난수 경로는 달라진다.

최고 OVR의 짝지은 차이는 +0.5였고, 시드 단위 bootstrap 5,000회 탐색 구간은 [0.075, 0.95]였다. 작은 고정 표본·FAST·10시즌의 탐색 결과이며 전체 플레이어에 대한 보증이 아니다.

권고: Jev의 목표를 “선수에게 좋은 결정”이라고만 정의하면 안 된다. 출전 기회, 상위 리그 도전, 소속감, 위험 감수 등을 플레이 성향으로 분리하고 평가 지표도 나눠야 한다. OVR 하나만 최적화하면 원하는 선수 서사를 놓칠 수 있다.

## Jev 비교 실험 준비와 남은 범위

`experiment.mjs`와 `cases.json`에 200개 합성 상황을 만들었다. 약속·부상·전술 적합도·규율·최근 면담 여부의 5종, 감독 성향 4종, 나이 5종, 조건 2종이다. 100개 쌍 각각에서 입력 필드 하나만 바뀌는 것을 검증했다.

비교용 직접 작성 규칙과 맥락 없는 선택 대조군도 실행했다. 이 규칙은 **현재 게임에 존재하는 감독 AI가 아니며 정답 평가자도 아니다.** 데이터가 직접 작성한 조건과 가까워 규칙의 위반 0건은 예상된 결과다. 이를 Jev보다 좋다거나 재미있다는 결론으로 사용하지 않는다. 맥락 없는 대조군은 같은 쌍에 같은 난수 선택을 사용한다.

Jev 실행기는 200개 기본 요청과 40개씩의 한국어·후보 순서 반전·동일 요청 재실행을 포함해 최대 320회 호출한다. `jev-1.13.0`을 지정하고 요청 해시·실제 응답 모델·확률·토큰 사용량·지연을 기록한다. 합성 데이터만 전송하며 2MB 요청 본문 누계에서 중단한다. 자동 재시도는 하지 않는다. API 키는 환경 변수에서만 읽고 기록하지 않는다. 실제 과금은 공급자의 사용량 계측에 따른다. [공식 API](https://docs.typesafe.ai/api), [모델 문서](https://docs.typesafe.ai/models)

인수 기준은 불가능한 선택 0건, 사람의 맥락 적합도 평가 개선, 운영 저장 회귀 0건이다. 사람이 라벨링한 복합 갈등 사례와 블라인드 평가는 아직 없으므로 200개 기본 쌍만으로 감독 역할의 품질을 확정하지 않는다. API 키 확보 후 우선 이 회귀형 사례로 부적합한 후보를 걸러내고, 사람 평가용 복합 사례로 확장한다.

## 재현

Node 22와 저장소 의존성이 설치된 환경에서 실행한다.

```sh
node docs/research/jev-pilot-2026-09-20/experiment.mjs
python3 docs/research/jev-pilot-2026-09-20/analyze.py

pnpm sim:career --ruleset 2.0.0 --pack 0.7.0 --seeds 40 --seasons 10 --seed-prefix jev-pilot-20260920 --policy random --position all --mode FAST --jobs 2 --verify --out /tmp/offside-jev-random
# 위 명령의 policy를 opportunity, out을 /tmp/offside-jev-opportunity로 바꿔 비교군 실행.

node docs/research/jev-pilot-2026-09-20/trace.mjs --ruleset 2.0.0 --pack 0.7.0 --seeds 40 --seasons 10 --seed-prefix jev-pilot-20260920 --policy random --position all --mode FAST --jobs 1 --out /tmp/offside-jev-traced
# JEV_PER_VISIT=1과 JEV_TRACE_PATH=/tmp/offside-jev-per-visit-events.jsonl을 설정하고 out을 별도로 지정하면 민감도 실험.

# TYPESAFE_API_KEY를 로컬의 git 무시 파일 .dev.vars에 설정한 뒤:
node --env-file=.dev.vars docs/research/jev-pilot-2026-09-20/experiment.mjs --live
```

`trace.mjs`는 tooling/scripts 안의 임시 CLI 사본을 실행한 뒤 제거한다. 같은 임시 경로를 사용하므로 동시에 여러 번 실행하지 않는다. `analyze.py`는 이 디렉터리에 저장한 원자료를 재집계한다. 새 엔진 실행 결과를 분석하려면 원자료 파일을 새 결과로 교체해야 한다.

원자료: `*-careers.csv`, `*-seasons.csv`, `*-summary.json`, `event-trace.jsonl`, `per-visit-event-trace.jsonl`. 집계는 `results.json`. 관측 실행 해시는 `observed-careers.csv`와 `random-careers.csv`로 대조한다.

**아직 답할 수 없는 질문:** Jev가 직접 작성 규칙보다 상황을 잘 읽는가, 한국어에서 품질이 유지되는가, 재미와 재방문율이 좋아지는가. 인증 정보와 실제 호출·사람 평가 없이 이 부분을 추정 결과로 채우지 않는다.
