# 13. 시각 디자인 시스템

## 목적

구현자가 원작 야구 커리어 게임의 스크린샷을 복제하지 않고 OFFSIDE의 공통 토큰과 모바일 화면 패턴으로 구현할 수 있게 한다. 컴포넌트 책임과 상태 계약은 [06. UI·UX 공통 계약](06-ui-ux-specification.md)을 따르고, 이 문서는 시각 표현을 정의한다.

2026-09-06 앱 경험 개편은 `main`의 `bd987e7`을 기준으로 `feat/app-experience-redesign`에서 작업한다. 현재 구현 정본은 [tokens.css](../../packages/ui/src/tokens.css)와 [game.css](../../packages/ui/src/game.css)다. 최신 화면별 범위·변경 이유·확인 항목은 [앱 경험 전면 개편](../design/app-experience-redesign.md)을 따른다. 이전 [모바일 화면 개편](../design/mobile-game-refresh.md)은 변경 이력으로 보존한다. 이 문서는 main 병합·운영 배포 완료를 뜻하지 않는다.

| 주요 토큰 | light 배경 `#f6f8fb`, 본문 `#142033`, 강조 `#123b68`; dark 배경 `#101722`, 본문 `#f3f6fa`, 강조 `#8ebcf0` |
| 프레임 | 최대 560px 단일 열, 좁은 화면은 가용 폭 전체, 데스크톱은 중앙 프레임 |

히어로 색과 그림자는 테마별 토큰을 따른다. 기존 모션·저장·접근성·명령 확정 계약은 유지하고 신규 연출 라이브러리를 추가하지 않는다.

## DSN-DIR-001 디자인 방향

확정 방향은 **손안의 축구 커리어**다. 화면을 최대 480px의 단일 플레이 프레임으로 유지하고, 축구장 선이 들어간 짧은 도입부, 읽기 쉬운 상황 카드, 선택 상태가 분명한 옵션, 다음 행동을 차례로 배치한다. 라이트는 블루·슬레이트와 흰색 표면, 다크는 같은 위계의 어두운 표면을 사용한다.

기존의 심야 경기장 중심 팔레트, 흰색 카드 적층 금지, 8px 초과 모서리 금지, 그림자 전면 금지, 데스크톱 1120px·2열 규칙은 이 개편으로 대체한다. 카드 적층은 허용하되 한 카드에는 하나의 역할을 두고, 보조 비교·상태는 접기 또는 탭으로 나눠 긴 설정 폼처럼 보이지 않게 한다. 축구 모티프와 게임의 선택·결과 위계로 정체성을 만든다.

- 원작의 브랜드·고유 구성·자산을 그대로 복제하지 않는다. 화면마다 임의 강조색을 추가하지 않는다.
- 사용자 제공 TDS `.fig`는 로컬에서 구조와 패턴을 조사했다. 해당 파일 내 라이선스는 앱인토스용 사용으로 범위를 제한하고 다른 프로젝트 사용·재가공·재배포를 금지한다고 명시한다. 이는 제공된 문구에 대한 확인이며 법률 자문은 아니다.
- 이번 구현은 TDS 도입이나 UI Kit 이식이 아니다. 명확한 상태, 간결한 정보 계층, 충분한 터치 영역 등 일반 모바일 UX 원칙을 참고해 독립 작성했다. `.fig`, Toss 폰트·아이콘·이미지·컴포넌트·토큰을 앱이나 저장소에 복사하지 않으며 외부 업로드·재배포하지 않는다.

## DSN-LINE-001 오프사이드 라인

브랜드 모티프는 화면을 가로지르는 한 줄의 수평선이다.

| 속성 | 값 |
|---|---|
| 두께·색 | 모바일 2px, 데스크톱 3px, `--os-line` |
| 폭·유지 | 화면 전체 폭, 좌우 여백 없음, 전환 화면 동안 고정, 페이드 없음 |
| 등장 | 왼쪽에서 오른쪽으로 320ms scaleX 0에서 1, ease-out |
| 모션 감소 | 즉시 완성된 상태로 표시 |

등장 허용 순간은 세 개뿐이다.

| 순간 | 화면 | 브랜드 어휘 |
|---|---|---|
| 새 커리어 확정 | SCR-004 확정 직후 | KICKOFF |
| 은퇴 확정 | SCR-025 확정 직후 | FULL TIME |
| 서비스 시즌 전환 | SCR-SVC-001 | THE LINE HAS MOVED |

일반 화면의 구분선은 `--os-border`를 쓰고 `--os-line` 색은 MUST NOT 사용한다. 라인을 장식이나 로딩 표시로 재사용하지 않는다.

## DSN-COL-001 색 토큰

라이트는 `:root`, 다크는 `[data-theme="dark"]`와 `prefers-color-scheme: dark`(단, `data-theme="light"` 제외) 두 선택자에서 같은 값으로 재정의한다. 텍스트와 배경의 모든 조합은 WCAG AA 4.5:1 이상이 MUST이며, 비텍스트 그래픽(라인·게이지·아이콘)은 3:1 이상이 MUST다.

```css
:root {
  --os-bg: #F2F5F8;
  --os-surface: #FFFFFF;
  --os-surface-2: #E9EFF5;
  --os-border: #D5DFEA;
  --os-text: #192638;
  --os-text-2: #52647A;
  --os-accent: #225AC4;      /* OFFSIDE 독립 강조색 */
  --os-on-accent: #FFFFFF;
  --os-line: #146E74;
  --os-success: #23784F;
  --os-warning: #845609;
  --os-danger: #BD3544;
  --os-neutral: #52647A;
  --os-focus: #225AC4;
  --os-canvas: #E5ECF3;
  --os-hero: #132B40;
  --os-on-hero: #F5FAFF;
  --os-hero-muted: #C3D5E5;
  --os-shadow: 0 4px 20px rgb(19 43 64 / 4%);
}

:root[data-theme="dark"] {
  --os-bg: #121B28;
  --os-surface: #1B293A;
  --os-surface-2: #24354B;
  --os-border: #3A506A;
  --os-text: #F3F7FC;
  --os-text-2: #B0C3D9;
  --os-accent: #91BBFF;
  --os-on-accent: #10274B;
  --os-line: #7AD6D3;
  --os-success: #7FD6A3;
  --os-warning: #F2C76C;
  --os-danger: #FF9EA5;
  --os-neutral: #B0C3D9;
  --os-focus: #91BBFF;
  --os-canvas: #0C1420;
  --os-shadow: none;
}
```

- `--os-accent`는 주요 버튼·선택 테두리·강조 텍스트에 쓴다. 채움색 위 텍스트에는 `--os-on-accent`를 쓴다. 이전 옐로우 채움 전용 제약은 폐기한다.
- 히어로의 `--os-hero`, `--os-on-hero`, `--os-hero-muted`는 두 테마에서 동일하다. 배경 장식은 낮은 불투명도의 직접 작성한 SVG이며 필수 정보를 담지 않는다.
- 카드는 배경 단계·여백으로 구분하고 라이트에서만 약한 `--os-shadow`를 허용한다. 테두리는 입력·선택 상태·구분에 사용한다.
- 화면당 강조색은 `--os-accent` 하나다. 성공·위험·중립은 색만으로 구분하지 않으며 DSN-CMP-003의 아이콘·라벨 동반 규칙이 항상 적용된다.
- 포커스 링은 `--os-focus` 2px 실선, 오프셋 2px로 모든 상호작용 요소에 MUST.

## DSN-TYP-001 타이포그래피

본문 서체는 Pretendard, 폴백은 시스템 산세리프다. 숫자를 표시하는 모든 요소는 `font-variant-numeric: tabular-nums`가 MUST다.

```css
:root {
  --os-font: "Pretendard Variable", "Pretendard Fallback", Pretendard, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif;
  --os-tracking-display: 0.04em;
}
```

| 토큰 | 용도 | 크기 / 행간 | 굵기 |
|---|---|---|---|
| display | 브랜드 어휘 전용 | 32 / 40 | 700, 대문자, 자간 0.04em |
| h1 | 화면 제목 | 26 / 34 | 700~800 |
| h2 | 섹션·카드 제목 | 18 / 26 | 600 |
| body | 본문·선택 문구 | 16 / 24 | 400 |
| caption | 라벨·보조 설명 | 13 / 18 | 400 |
| num-xl | 단독 강조 수치 | 48 / 52 | 700 |
| num-lg | 예상 퍼포먼스, 시즌 핵심 지표 | 28 / 32 | 600 |
| num-md | 델타(+2, −3) | 18 / 24 | 600 |
| num-sm | 표·타임라인 수치 | 14 / 20 | 500 |

- 브라우저 200% 확대에서 가로 스크롤이 생기면 안 된다. 크기는 rem, 레이아웃은 상대 단위가 MUST.
- 선수명·팀명은 한 줄 말줄임을 허용하되 전체 이름은 상세 화면과 접근성 이름에서 읽을 수 있어야 한다. 브랜드 어휘와 영문 라벨은 한국어 캡션과 같은 줄에 두지 않는다.
- 최소 본문 16px, 최소 캡션 13px. 12px 이하는 MUST NOT.
- `ScreenIntro` 설명은 보조 설명으로 14 / 24, h1 자간은 `-.035em`이다. 숫자 데이터는 기존 `.os-num`을 유지한다. Toss Product Sans를 추가하지 않는다.

## DSN-SPC-001 간격·그리드

```css
:root {
  --os-space-1: 4px;  --os-space-2: 8px;  --os-space-3: 12px; --os-space-4: 16px;
  --os-space-5: 24px; --os-space-6: 32px; --os-space-7: 48px; --os-space-8: 64px;
  --os-radius-s: 8px; --os-radius-m: 12px; --os-radius-panel: 20px;
  --os-touch-min: 48px;
}
```

| 항목 | 값 |
|---|---|
| 기준 최소 너비 | 360px 검증, 359px 이하 선택 그리드는 단일 열로 축소 |
| 전체 플레이 프레임 | 모바일·데스크톱 모두 단일 열, 최대 480px, `min-height: 100dvh` |
| 바깥 캔버스 | `--os-canvas`; 640px 이상에서 프레임 양측 1px 테두리·약한 그림자 |
| 화면 여백 | 본문 좌우 16px, 하단 `24px + safe-bottom`; 화면 섹션 간 24px |
| 카드·도입부 | 카드 padding 20px, 히어로 padding 24px, radius 20px; 359px 이하 둘 다 padding 16px |
| 터치 대상 | 최소 48px 높이; 주요 CTA 52px 이상, 아이콘 버튼 48×48px |
| 모서리 | 기본 컨트롤 12px, 칩 8px, 선택 카드 16px, 패널 20px, 다이얼로그 24px |
| 작은 선택 | `.os-choice-grid`는 2열, 성별·주발 등의 `.os-segmented`는 2~3열 |

주요 CTA는 `.os-action-dock`으로 본문 흐름에 참여하는 `position: sticky; bottom: 0`를 쓴다. 패딩은 상단 12px, 하단 `12px + safe-bottom`; 두 버튼은 `.os-action-row`로 배치한다. `scroll-padding-bottom: 110px`로 포커스 이동 공간을 확보한다. 가상 키보드가 열린 실기기에서 필드·오류·CTA가 가려지지 않는지는 별도 검증한다. 데스크톱이라고 폼을 여러 열로 펼치지 않는다.

## DSN-CMP-001 PlayerHeader·StatusStrip

- PlayerHeader는 패널 안에 직접 작성한 유니폼 모티프·선수명·소속을 먼저 두고, 포지션·아키타입·등번호를 3열 보조 정보로 둔다. 이름의 h2 의미를 유지한다. 359px 이하에서는 보조 정보가 1열로 접힌다.
- StatusStrip은 가로 스크롤 없이 `repeat(auto-fit, minmax(70px, 1fr))`로 배치한다. 각 칸은 caption 라벨과 num-lg 값이며 첫 핵심 지표 칸만 accent 채움으로 강조한다. 숫자를 카운트업하지 않는다.
- **Base OVR**은 "기본 OVR" 라벨과 고정 수치로 표시한다. 개편된 요약 스트립에서는 첫 강조 칸을 사용하며, 이전의 무조건 48px·2px 테두리 배지 규칙은 적용하지 않는다.
- **Expected Performance**는 "이번 경기 예상"이라는 별도 라벨과 보조 수치로 Base OVR과 구분한다. 기존 계산·공개 시점은 변경하지 않는다. 게이지를 이번 개편에서 새로 구현한 것으로 보지 않는다.
- 폼·체력·사기·전술 적합도·감독 신뢰는 게이지 없이 num-lg 값과 caption 라벨만 쓴다.

## DSN-CMP-002 ChoiceCard·ResultCard

- ChoiceCard 하나가 선택지 하나. 첫 행은 선택 문구와 위험 아이콘·라벨, 다음은 예상 효과 목록이다. 16px 모서리와 16px 패딩을 사용한다.
- 선택 상태는 `--os-accent` 2px 테두리와 체크 아이콘, 텍스트 "선택됨"을 함께 표시한다. 확정 CTA는 카드 밖에 하나만 둔다.
- ResultCard는 패널과 4px accent 상단선으로 결과를 구분한다. 결과 등급(성공·중립·실패)은 아이콘·텍스트·색을 함께 표시하고, 원인 태그는 `--os-surface-2` 칩(8px)으로 표시한다. 다시 보기 동작의 라벨은 "리플레이"다.
- 범용 이벤트는 화면 도입부 → 상황 카드 → 선수 상태 접기 → 선택지 → 확정 순서다. 접힌 상태·비교 데이터는 삭제하거나 별도 계산하지 않는다. 명시적 선택과 확정을 분리한다.

## DSN-CMP-003 위험·델타·0 표시

| 대상 | 색 | 아이콘 | 텍스트 | 예 |
|---|---|---|---|---|
| 위험 LOW | `--os-success` | 원 | 낮음 | ● 낮음 |
| 위험 MEDIUM | `--os-warning` | 삼각 | 보통 | ▲ 보통 |
| 위험 HIGH | `--os-danger` | 느낌표 | 높음 | ! 높음 |
| 상승 델타 | `--os-success` | 위 화살 | 부호 포함 숫자 | +2 |
| 하락 델타 | `--os-danger` | 아래 화살 | 부호 포함 숫자 | −3 |
| 변화 없음 | `--os-neutral` | 점 | 0 | 0 |

- 델타는 부호·아이콘·색 세 가지를 항상 함께 쓴다. 하나만 쓰는 것은 MUST NOT.
- 확정된 0은 num 스케일의 "0"으로, 미집계는 `--os-text-2` 색의 "—"와 aria-label "미집계"로 표시한다. 두 경우의 시각이 같으면 안 된다.
- 카운트업 중인 값은 확정 전까지 `--os-text-2` 색이며 확정 시 `--os-text`로 바뀐다.

## DSN-CMP-004 SeasonTimeline·CareerTimeline·ArchiveCard

- SeasonTimeline은 단계별 점과 caption 라벨, 현재 단계만 `--os-accent` 채움.
- CareerTimeline은 세로 목록이며 사건 유형별 아이콘(DSN-ICO-001)을 앞에 두고 연도 점프를 상단 고정 세그먼트로 제공한다.
- ArchiveCard는 향후 엔딩 화면 계약이다. 엔딩 타이틀을 h2로, 상위 기여 요인 3개를 caption 목록으로 두며 Legacy 총점은 num-lg, 백분위는 보조 정보다. 이번 기존 화면 개편이 엔딩·아카이브 기능을 구현했다는 의미는 아니다.

## DSN-CMP-005 ContractComparison·CompareCards

- **CompareCards**는 컨테이너 너비 기준으로 동작한다. 640px 미만은 세로 카드, 640px 이상인 별도 넓은 컨테이너에서만 표를 사용한다. 현재 480px 게임 프레임에서는 데스크톱에서도 세로 카드다.
- 기존 문서의 세그먼트 이동·"차이만 보기" 토글은 현재 컴포넌트에 구현되지 않았으며 이번 개편의 완료 범위가 아니다.
- 제안 화면은 팀·리그·등번호 다음에 주급·기간·역할 약속·전술 적합도를 2열 요약한다. 계약금 등 추가 조건은 "계약 조건 자세히"에서 확인한다. 모든 제안의 조건을 보존하며 높은 리그와 출전 기회 특징을 기존 규칙으로 표시한다.
- 제안마다 "이 제안 보기"로 계약 검토 화면에 이동한다. 이 동작은 계약 확정이 아니다. 계약 화면은 조건·구단의 약속·선수 서명을 나누고 하단 "사인"에서만 기존 확정 명령을 실행한다.

구현 범위·방향 판정·제스처 제외 조건·접근성·회귀 검사 기준은 [앱형 모션 계약](../design/app-like-motion.md)을 따른다. 새 라이브러리·SDK·라우트·게임 명령을 추가하지 않는다.

## DSN-THM-001 테마

- 기본은 시스템 설정을 따른다. 설정 화면(SCR-030)에서 라이트·다크·시스템 중 하나로 고정하며 `data-theme` 속성으로 적용한다.
- 두 테마는 같은 토큰 이름을 쓰고 컴포넌트 CSS에 hex를 직접 쓰지 않는다. 라이트·다크·시스템 선택과 글자 크기·모션 감소 설정을 그대로 유지한다.
- 공유용 최종 프로필 카드(SCR-028)의 다크 고정과 toss 채널 제출 테마는 기존 후속 채널 계약으로 남는다. 이번 개편이 해당 화면이나 SDK 테마 연동을 새로 구현한 것은 아니다. 실제 제출 시점에 ADR-009와 플랫폼 검토 조건을 확인한다.

## DSN-BRD-001 브랜드 어휘 표기

- KICKOFF, FULL TIME, THE LINE HAS MOVED는 display 토큰으로만 표기하고 바로 아래 caption 한국어 설명을 반드시 둔다.
- 일반 버튼·탭·메뉴에는 브랜드 어휘를 쓰지 않는다. 새 커리어 버튼의 라벨은 "커리어 시작"이다. 화면 단위로 새 영문 대문자 용어를 만드는 것은 MUST NOT이며 어휘 목록은 06 문서가 정본이다.
- 개편 화면의 작은 eyebrow는 화면 맥락을 설명하는 보조 라벨이며 새 브랜드 어휘나 시즌 선언이 아니다. 핵심 행동은 기존 한국어 라벨과 KICKOFF 계약을 유지한다. OFFSIDE 로고는 허브·온보딩·설정에서 홈 링크로 사용한다. 커리어 화면에서는 정적 로고로 표시해 화면의 저장·뒤로 이동 방어를 우회하지 않는다.

## DSN-CHN-001 앱인토스 채널 레이아웃

- 미니앱은 전체 화면이며 프레임워크가 우상단에 닫기(X) 버튼을 그린다. 위치는 `SafeArea.get()` 기준 오른쪽 `right + 10px`, 위쪽 `top + 5px`(iOS) / `top + 10px`(Android). 이 영역 위에 우리 버튼·아이콘을 두면 검토에서 반려된다. PlayerHeader의 우측 액션은 toss 채널에서 X 버튼 아래로 내린다.
- 상·하단 여백은 `SafeArea.subscribe`로 받아 `--os-safe-top`, `--os-safe-bottom` 토큰에 넣는다. web 채널은 `env(safe-area-inset-*)`로 같은 토큰을 채운다.
- 화면 방향은 세로 고정(`Screen.setOrientation`). 가로 레이아웃은 만들지 않는다.
- 이번 화면 개편은 TDS 패키지·UI Kit를 이식하지 않은 독립 UI다. 이 결정은 앱인토스 SDK나 배포 채널의 신규 구현·출시 승인을 뜻하지 않는다. 앱인토스 출시 전 키트 사용 권한과 당시 채널 디자인·검토 요건을 별도로 확인한다. 기존 번들·로딩 예산은 유지하며 라인 모티프를 일반 로딩 표시로 추가하지 않는다.
- 외부 링크는 원칙적으로 두지 않는다. 약관·개인정보 처리방침은 SPA 내부 라우트다. 불가피한 외부 URL은 `Device.openURL`로 열고 `<a target="_blank">`를 쓰지 않는다. 자사 웹·앱 설치 유도 링크는 금지다.
