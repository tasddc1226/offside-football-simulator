# ADR-002. 영속 저장소와 비로그인 사용자 식별

- 상태: 확정 (2026-09-02)
- 관련: [ADR-003](ADR-003-simulation-location.md), [ADR-007](ADR-007-hosting-and-infra.md), [ADR-008](ADR-008-auth-and-account-merge.md), [저장·버전](../development/05-save-and-versioning.md)

## 맥락

원작 야구 커리어 게임은 브라우저 세션에 기록을 남기고 비로그인으로 플레이한다. OFFSIDE도 같은 구조를 원하며, 서버는 "최종 결과 정도"만 저장하는 규모를 목표로 한다. 다만 복구 코드와 소셜 로그인으로 다른 기기에서 이어하려면 최종 결과만으로는 부족하다.

## 결정

**로컬 우선(local-first) 저장**이다. 플레이 중 정본은 브라우저 IndexedDB이고, 서버는 체크포인트 스냅샷과 명령 로그를 동기화 받아 보관한다.

| 저장소 | 내용 | 정본 여부 |
|---|---|---|
| IndexedDB (Dexie) | 현재 Career 상태, 모든 Snapshot, 명령 로그, DRAFT, 설정 | 플레이 중 정본 |
| 서버 D1 | 프로필, 로그인 연결, Career 최신 Snapshot + 최근 checkpoint N개, 명령 로그, Archive, 서비스 시즌 진행 | 복구·동기화·보관 정본 |
| Cloudflare R2 | 오래된 명령 로그와 Snapshot의 압축 보관, 콘텐츠 팩 아티팩트 | 아카이브 |

서버가 저장하는 것은 "최종 결과"보다 조금 많다. Career당 최신 Snapshot 하나(압축 전 256KB 상한)와 명령 로그(명령당 수백 바이트)를 저장한다. 1만 명이 각각 커리어 다섯 개를 끝내도 수 GB 수준이며 D1 무료·유료 한도 안이다.

동기화 규칙:

- 클라이언트는 checkpoint마다 `PUT /careers/{id}`로 Snapshot과 그 사이 명령을 보낸다. `If-Match`에 서버가 아는 revision을 넣는다.
- 서버 revision이 다르면 409를 받고, 클라이언트는 서버 Snapshot을 받아 비교한다. 로컬 revision이 더 크고 서버 상태가 로컬 명령 로그의 조상이면 다시 올린다. 아니면 사용자에게 "이 기기 / 다른 기기" 선택을 준다.
- 오프라인에서도 플레이는 계속되고 동기화만 미룬다. 동기화 실패는 게임 진행을 막지 않는다.

비로그인 식별:

- 첫 API 호출에서 서버가 `profileId`를 만들고 `HttpOnly; Secure; SameSite=Lax; Max-Age=1년` 쿠키를 준다.
- 복구 코드(Phase 1)와 Google 로그인(ADR-008)이 다른 기기 복구 수단이다.
- 쿠키가 막힌 환경에서는 로컬 전용으로 플레이하고, 서버 동기화가 불가함을 설정 화면에 표시한다.

## 이유

- 서버가 시뮬레이션을 하지 않으므로 API 호출은 checkpoint 동기화와 조회뿐이다. 서버 규모는 사용자 의도대로 작게 유지된다.
- 최종 결과만 저장하면 복구 코드와 로그인이 "끝난 커리어"만 살릴 수 있다. 20시즌 진행 중 커리어를 잃는 것이 최악의 이탈 사유이므로 checkpoint 동기화는 필수다.
- 명령 로그를 함께 저장하면 ADR-003의 리플레이 검증과 버그 재현이 가능하다.

## 검토한 대안

| 대안 | 보류 이유 |
|---|---|
| 서버 권위 시뮬레이션 + 서버 저장 | 명령마다 API 왕복, 서버 비용·복잡도 증가, 오프라인 불가. 단일 플레이어에 과함 |
| 로컬 전용 저장, 서버 없음 | 복구·로그인·서비스 시즌 결산이 불가 |
| Supabase Postgres + RLS | 익명·소셜 연결이 편하지만 Pro 요금제 고정비와 Postgres 규모가 과함 |

## 결과

- 01 시스템 아키텍처의 "서버 권위 저장 기본"은 이 ADR로 대체된다.
- 07 API 계약은 명령 API가 아니라 동기화·조회 API로 재정의된다.
- 05 저장 문서의 checkpoint·revision·멱등성 규칙은 그대로 유지되며 실행 주체가 클라이언트 엔진으로 바뀐다.
- 사용자가 IndexedDB를 직접 편집할 수 있다. 단일 플레이어와 비경쟁 도전에서는 허용하고, 경쟁 요소가 생기면 ADR-003의 검증을 켠다.
