# ADR-003. 시뮬레이션 실행 위치

- 상태: Superseded by ADR-013 (2026-09-24). 확정 (2026-09-02)
- 관련: [ADR-002](ADR-002-persistence-and-identity.md), [시뮬레이션 엔진](../development/03-game-simulation-engine.md), [이벤트 엔진](../development/04-event-engine.md)

## 맥락

개발 명세는 서버 권위 시뮬레이션을 권장하고 로컬 실행을 대안으로 두었다. 사용자는 서버를 최소 규모로 유지하길 원한다. 시뮬레이션은 이미 `seed + rulesetVersion + contentPackVersion + command`로 완전히 결정론적이어야 한다는 규칙(RULE-RNG-001)이 있다.

## 결정

시뮬레이션은 **클라이언트의 Web Worker**에서 실행한다. 서버는 플레이 경로에서 시뮬레이션하지 않는다. 대신 같은 `packages/domain`을 Cloudflare Worker에서도 실행할 수 있게 유지하고, 다음 경우에만 서버가 명령 로그를 **리플레이해 검증**한다.

| 경우 | 검증 | 기본값 |
|---|---|---|
| 서비스 시즌 도전 보상 수령 | Archive의 명령 로그를 재생해 state hash 일치 확인 | KICKOFF에서는 OFF, 경쟁 랭킹 도입 시 ON |
| 버그 리포트 | 사용자가 첨부한 Snapshot + 명령 로그를 staging에서 재생 | 수동 |
| 밸런스 리포트 | 익명화된 명령 로그 표본을 배치 재생 | Phase 7 |

검증이 실패한 커리어는 삭제하지 않는다. 보상만 보류하고 사용자에게 "검증되지 않은 커리어"로 표시한다.

## 이유

- 결정론이 이미 요구사항이므로 "클라이언트 계산 + 서버 재생 검증"은 추가 규칙 없이 성립한다.
- 서버 비용과 지연이 사라지고 오프라인 플레이가 가능하다.
- 초기 운영은 개인 도전과 앨범 중심이라 조작의 이득이 없다. 경쟁 요소가 생기면 검증을 켜기만 하면 된다.

## 제약

- `packages/domain`은 Node·브라우저 전용 API를 쓰지 않는다. `Date.now`, `Math.random`, 파일 시스템, DOM 금지. 시간과 난수는 입력으로 받는다.
- 부동소수점 결과가 실행 환경에 따라 달라지지 않도록 정수 연산 또는 고정 소수점을 쓰고, 정렬은 항상 안정 키를 지정한다.
- `truePotential` 같은 숨김 값은 로컬에 존재한다. 화면에 노출하지 않는 것은 규칙이지만 저장소 열람까지 막지는 않는다. 이 한계를 개발 명세에 명시한다.
- 콘텐츠 팩과 ruleset은 클라이언트가 내려받아 실행한다. 미공개 이벤트 문구도 클라이언트에 내려간다. 스포일러 보호는 하지 않는다.

## 검토한 대안

| 대안 | 보류 이유 |
|---|---|
| 서버 권위 | 비용·지연·오프라인 불가. 단일 플레이어에 과함 |
| 하이브리드(결산만 서버) | 두 실행 경로의 동등성 유지 비용이 크고 이득이 작음 |

## 결과

- 01 문서의 명령 처리 계약은 "클라이언트 엔진이 처리하고 서버가 동기화"로 바뀐다.
- 08 테스트 전략에 "브라우저와 Worker에서 같은 fixture의 state hash 일치" 테스트를 추가한다.
- 성능 예산의 "시즌 결산 p95 2초"는 중간급 모바일의 Web Worker 기준으로 재정의한다.
