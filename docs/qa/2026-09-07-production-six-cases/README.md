# 운영 6케이스 플레이 리뷰 — 포지션·배경·전략 매트릭스 (2026-09-07)

2026-09-07 12:52~13:47, 사용자 요청("권장 6회로 돌려보자. ego-browser에서 겹치지 않게 주의해서 sonnet 5 에이전트에게 돌려줘")으로
Sonnet 서브에이전트 6명이 각자 ego-browser 작업공간에서 [offside-lab.com](https://offside-lab.com)(시즌 1 `svc_season_1`,
룰셋 1.3.0·팩 0.5.0)을 플레이했다. 같은 날 오전의 [3관점 리뷰](../2026-09-07-production-three-perspectives/README.md)가
"무엇이 보이는가"를 물었다면, 이번은 서로 겹치지 않는 6개 프로필로 "어떤 조건에서 재현되는가"를 물었다.
케이스별 정본은 `case-1-gk.md` ~ `case-6-dm.md`, 핵심 근거 캡처 19장은 `shots/`에 있다(나머지 캡처는 세션 스크래치패드에만 남김).

## 종합 결론

- **핵심 루프는 6개 프로필 모두에서 끝까지 돌았다.** 19세 시작·첫 갈림길·계약·시즌 결산·FAST 모드가 오류 없이 이어졌고,
  DM 케이스는 17시즌을 지나 36세 자연 은퇴·엔딩·Legacy·보관함까지 완주했다. 병렬 6세션 부하에서 화면 지연은 있었지만 중단·데이터 혼선은 없었다.
- **무출전 고착은 프로필과 전략을 가리지 않는다.** 57시즌 중 20시즌(35%)이 0경기·0분이었고, 순응형(GK)·잔류형(CM)·도전형(WG)·
  대조 실험(ST: 하향 제안 거절과 수락이 같은 0경기)에서 모두 나왔다. 유일하게 CB 안정형만 8시즌 내내 출전했다.
  9/6 결론 ②와 9/7 3관점 P1-1이 세 번째로 재확인됐고, 이번에는 "탈출 수단이 없는 것"이 아니라
  **"원소속에 머무는 한 어떤 선택도 출전을 만들지 못하고, 임대·이적으로 소속을 바꿔야만 회복된다"**는 형태로 좁혀졌다(WG 케이스 시즌 3·6 임대 뒤 즉시 주전).
- **"역할 협상" 버튼 무결과 소진은 4/6 케이스에서 DOM으로 확인됐다.** 같은 구단 재계약에서는 항상 비활성(GK), 클릭 즉시 배너 없이 disabled(WG·CM), 아무 반응 없음(ST).
  자유계약 오퍼에서는 정상 작동한 사례(GK)가 있어 "재계약·일부 오퍼 유형에서만 막힌다"는 조건이 새로 잡혔다.
- **문구·데이터 결함 두 계열이 반복된다.** 라커룸 관계 태그 `PROMISE_BREACH`·`NATIONAL_TEAM_ACCEPT` 원문 노출 4/6, 챕터 제목 "프로_데뷔"(#105) 3/6.
  ST 케이스는 진짜 데뷔전은 "프로 데뷔전"으로 정상이고 **같은 챕터 타입이 재사용될 때만 키가 노출**된다는 원인 단서를 남겼다.
  시즌 결산 표 안에서 "역할 시작/종료"와 "출전 약속"이 서로 다른 역할을 말하는 모순(CM 시즌 4, CB 시즌 1)은 새 발견이다.
- **노쇠·은퇴·Legacy는 설계대로 작동한다.** OVR 32세 정체·36세 첫 하락, 결산의 "가장 큰 원인: 연령"과 신체>기술>정신 수치 근거,
  은퇴 압력 54/100에서도 강제 은퇴 없이 "마지막 휘슬" 다이얼로그, Legacy 78 "레전드", 통산·연대기·최종 프로필 수치 일치, 새로고침 뒤 유지.
  다만 승격전 성공 2회·"승격전문가" 태그를 받고도 17시즌 내내 소속 리그가 "2부"로 표기된 점은 확인이 필요하다(아래 P2-6).

### 실행 절차와 안전 규칙

- 3관점 리뷰에서 확인한 대로 ego-browser 작업공간은 **브라우저 프로필(쿠키·IndexedDB)을 공유**하므로 선수 생성 구간만
  스크래치패드 `create-lock` 폴더 `mkdir` 잠금으로 직렬화했다(획득 → 생성·KICKOFF·자기 커리어 URL 확인 → 해제, 10분 상한, 남의 잠금 삭제 금지).
  잠금 대기는 0분(케이스 1·2·4)~17분(케이스 3)이었고 초안이 섞인 사례는 없었다. 케이스 5·6은 잠금 대기 Bash가 백그라운드로 넘어가
  멈췄다가 오케스트레이터 메시지로 재개했다(포그라운드 `timeout` 600000으로 재실행).
- 안전 규칙은 3관점과 동일: 기존 커리어·프로필·기기 데이터 미접촉, 삭제·초기화·복구 코드·Google 연결 버튼 금지, QA 이름 커리어 1개씩,
  복구 코드 미출력, 피드백 폼 미전송, 외부 링크 미클릭, 상태·seed·스토리지 주입 없음, 생성 뒤에는 자기 커리어 URL로만 이동.
- 시즌 1은 CHAPTER, 이후 FAST 모드가 기본. 케이스별 heredoc 45~95회, 소요 27~85분(잠금 대기 포함). 자연 은퇴 케이스는 약 65분.

### 제품 결함으로 보지 않은 것

- **"강동강동 로버스" 팀명 중복 렌더링**(케이스 5 확정 결함 3): 캡처를 열어 보면 배지 이니셜 "강동"과 팀명 "강동 로버스"가 정상 분리돼 있다.
  `innerText` 추출이 둘을 이어 붙인 자동화 아티팩트다(위 20번 접근성 메모만 남김).
- **"계약 기간 불일치, 2시즌 계약이 1시즌 만에 재계약 창"**(케이스 1 P1): 캡처의 갱신 제안은 "재계약 사전 협상 … 남은 0시즌 대비 +2시즌"으로,
  계약 마지막 시즌에 다음 계약을 미리 협상하는 설계다. 문구 혼동만 남긴다(19번).
- **"다른 기기와 어긋남" 문구 1회**(케이스 6): 여섯 작업공간이 같은 브라우저 프로필을 공유해 생긴 환경 특성. 3관점의 "다른 세션 선수 데이터 노출"과 같은 분류.
- **브리프 라벨 부재·자동화 방법론 오류**: 케이스 2의 "상위팀 테스트 준비" 라벨은 그 출발 카드 경로에 없었고, 케이스 4의 시즌 1 FAST·시즌 2 재계약 오거절은 스크립트 버그다.
  케이스 1의 대표팀 라디오 미확정 20회 반복은 상태 변화 없이 같은 화면을 재조회한 것이라 데이터 영향 없음.
- **허브에 QA 커리어 전부 노출**: 같은 프로필의 정상 동작.

## 잘 된 점 (케이스 공통)

- 포지션별 스탯 가중치·경기 통계·판단 문구가 GK·CB·WG에서 시종 일관했고, 위험도(낮음·보통·높음)와 성공 확률·영향이 매 선택에 투명하게 표시됐다.
- 재활 선택(표준·조기 복귀·보수)의 트레이드오프가 정량 표시되고, 고위험 선택이 실제 재발로 이어지는 인과가 체감됐다.
- "최근 두 시즌 출전이 없었습니다. 하부리그 기회를 비교해 보세요" 배너와 임대 대안이 실제로 열렸다(3·5).
- 시즌 결산의 노쇠 근거, 은퇴 확인 다이얼로그, 엔딩·Legacy·연대기·최종 프로필의 수치 일치와 보관함 노출까지 은퇴 경로 전체가 정합했다.
- FAST 모드는 결정 이벤트가 없는 시즌을 클릭 3회로 끝내 17시즌을 약 1시간에 완주할 수 있었다. "user is controlling"·세션 이탈 오류는 0건.

## 미검증 범위

- 자연 은퇴·Legacy는 표본 1건(원클럽·안전 선택). 이적이 많은 커리어나 지도자 에필로그·병역 경로·참조집단 비교 문구는 보지 못했다.
- 주장단 중재 이벤트(1·4), 외국 국적의 대표팀 소집(5), 케이스 2의 역할 협상(트리거 조건 미충족), 협상 무반응이 모든 오퍼 유형에 해당하는지(5), 은퇴 카드 "이어하기" 동작(6).
- 대부분 시즌이 FAST 모드라 CHAPTER 전용 서사·이벤트 다양성은 시즌 1 한정 관찰. 자동 진행 휴리스틱(위험도 우선)이 고르지 않은 선택지 조합은 보지 못했을 수 있다.
- 콘솔 오류·네트워크 오류는 이번 라운드에서 별도 집계하지 않았다(3관점 기능 문서가 담당).

## 다음 조치 (사용자 결정)
