# offside-threads-post

스레드는 게임 홍보가 아니라 **1인 개발 이야기 연재**로 운영한다(2026-11-11 결정). 글의 주인공은 게임이 아니라 만드는 사람이고, 게임 링크는 넣지 않는다(프로필에 있다).

## 꼭 지키는 것

- **운영자 1인칭으로 나가는 글이다. 초안을 보여 주고 확인받은 뒤에만 게시한다.** 작성 창을 채워 임시 저장하는 데까지가 기본 범위다. 지난 승인은 다음 글에 적용되지 않는다.
- **겪지 않은 일 · 확인하지 않은 숫자를 쓰지 않는다.** 숫자와 사건은 레포 기록(커밋 · PR · `docs/tracking/decision-log.md` · 운영 런북의 장애 기록 · 릴리즈 노트)이나 사용자가 말해 준 것에서만 가져온다. 감정 · 소감은 지어내지 말고 사용자에게 한 줄 물어 받는다.
- **유저 개인정보 · 닉네임 · 다른 서비스 화면 캡처 · 비밀값 · 보안 취약점 세부를 쓰지 않는다.** 매출 · 광고비 같은 돈 숫자는 사용자가 공개해도 된다고 한 것만 쓴다.
- 한 글에 이야기 하나. 500자 안(스레드 한도), 보통 200~350자.
- 로그인 정보는 입력하지 않는다. 로그아웃돼 있으면 사용자에게 부탁한다.

## 순서

### 1. 지난 글 읽기

```bash
{ echo "const CFG = { OUT: '<임시 폴더>/threads-posts.json', HANDLE: 'offside.lab.kr' };"; cat scripts/collect.mjs; } | ego-browser nodejs
```

글마다 본문 끝의 숫자 줄이 반응(좋아요 · 답글 · 리포스트 · 공유 순)이다. 마지막 글 날짜, 최근 다룬 소재, 반응이 좋았던 글을 먼저 정리한다. 같은 소재를 한 달 안에 되풀이하지 않는다.

### 2. 소재 고르기

반응이 좋았던 유형(2026-09-26 ~ 10-30의 56개 기준)

| 유형                   | 예                                 | 반응             |
| ---------------------- | ---------------------------------- | ---------------- |
| 큰 숫자가 있는 순간    | 스토어 스포츠 무료 1위, 탑 10 진입 | 가장 높음        |
| 배운 점 목록           | 광고비 없이 키우며 느낀 점         | 답글이 많이 달림 |
| 솔직한 실패 · 비용     | DB 무료 한도 94% 메일, 5달러 결제  | 꾸준히 좋음      |
| 숫자 결산              | 50일째 PR · 배포 수                | 답글 많음        |
| 기능 나열형 일지       | 날짜 + 고친 것 목록                | 낮음             |
| 축구 중계 한 줄 · 일상 | 축구 보자, 러닝                    | 낮음             |

연재 소재 틀(겹치지 않게 돌려 쓴다)

1. **사고와 복구** — 장애, 잘못된 배포, 그 뒤에 만든 규칙
2. **돈 이야기** — 서버비, 요금제 전환, 광고 실험 결과
3. **안 하기로 한 것** — 접은 기능과 이유
4. **AI와 일하는 법** — 문서 먼저 쓰기, 에이전트에게 맡기는 것과 직접 하는 것
5. **유저가 바꾼 것** — 문의 한 줄이 기능이 된 과정
6. **숫자 결산** — N일째, 시즌 마감
7. **혼자 하는 운영** — 고객 문의, 스토어 심사, 사업자 등록 같은 개발 밖의 일
8. **지속하는 법** — 본업과 병행, 러닝, 쉬는 방식

### 3. 초안

- 말투: 반말 구어체("~했어", "~더라", "~임"). 짧은 줄로 끊고 빈 줄로 문단을 나눈다. 이모지는 없거나 하나.
- 구조는 느슨하게: **첫 줄에 숫자나 사건**(펼치기 전에 보이는 유일한 줄) → 있었던 일 서너 줄 → 한두 줄로 끝. 지난 글 중 반응 좋았던 것 두세 개를 옆에 놓고 길이 · 끝맺음을 맞춘다.
- **AI가 쓴 티를 뺀다**(2026-11-11 사용자 지적). 번호 붙인 교훈 목록, "제일 무서웠던 건" 같은 연결 문장, 교훈으로 닫는 마지막 줄("그래도 ~하더라"), 고른 문단 길이, 설명조 풀어쓰기를 쓰지 않는다. "~함", "~~했음", "ㅋㅋ", "ㄷㄷ"처럼 사용자가 실제로 쓰는 말끝을 쓰고, 다 설명하지 말고 덜 쓴다. 150~~250자면 충분하다.
- 기술 용어는 개발자가 아니어도 읽히게 풀어 쓴다("마이그레이션" → "DB를 바꾸는 배포").
- 주제 칸은 `1인 개발 이야기`(지난 글과 같은 주제).
- 해시태그 · 링크 · "플레이해 보세요" 같은 권유를 넣지 않는다. 답글을 받고 싶으면 마지막에 질문 하나만 둔다.
- **질문형은 세 번에 한 번쯤 섞는다.** 답글이 붙은 글이 좋아요 수에 비해 멀리 갔다(의견 글 좋아요 2 · 답글 10, 50일 결산 6 · 14). 조건 세 가지: 내 숫자 · 실패를 먼저 보여 준다, 답할 사람을 좁힌다("해외 유저 받아본 사람"), 한 줄로 답할 수 있게 묻는다. 첫 줄과 마지막 줄에 같은 질문을 둔다. 끝에 "어떻게 생각해?"만 붙이는 것은 질문형이 아니다. 답글이 달리면 그날 안에 답하라고 사용자에게 알린다.

### 4. 작성 창 채우기와 임시 저장

ego-browser(로그인된 세션)로 한다.

1. `https://www.threads.com/@offside.lab.kr` → "새로운 소식을 공유해보세요." 클릭
2. `input[placeholder="커뮤니티 또는 주제"]`를 누르고 `keyboard.insertText('1인 개발 이야기')`
3. `div[role=dialog] div[contenteditable=true]`를 누르고 `keyboard.paste(본문)`
4. 본문 길이(`innerText.length`)가 원문과 같은지 확인
5. 취소 → "저장"을 누르면 임시 저장본에 남는다. 사용자가 앱에서 읽고 고칠 수 있다.

요소는 이름으로 찾아 좌표를 계산해 `mouse.click(x, y, { label })`로 누른다.

### 5. 게시(확인 뒤)

작성 창 → 임시 저장본에서 글을 열거나 다시 채운 뒤 "게시". 프로필 맨 위에 글이 보이는지 확인하고 주소를 사용자에게 알린다. 인스타그램 동시 공유는 켜지 않는다.

### 6. 기록

레포 밖 마케팅 보관 폴더에 글 본문 · 주소 · 날짜 · 사실의 출처를 남긴다. 3~4일 뒤 반응(좋아요 · 답글 · 조회)을 같은 파일에 적고 위 표를 고친다.
