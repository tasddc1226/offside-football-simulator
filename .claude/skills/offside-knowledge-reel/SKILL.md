# offside-knowledge-reel

축구 상식 하나를 35~45초 릴스로 만든다. 첫 제작은 2026-11-11 「아시안게임 금메달, 군 면제가 아니에요」.
게임 광고가 아니라 **축구 지식 콘텐츠**다. 게임은 프로필 링크로만 잇는다.

## 꼭 지키는 것

- **사실은 출처 2곳 이상으로 확인한다.** 날짜 · 숫자 · 이름을 대본에 쓰기 전에 표로 정리하고 기사 주소를 작업 폴더의 `post.md`에 남긴다. 확인하지 못한 문장은 뺀다.
- **실존 인물의 얼굴 · 실제 구단 엠블럼 · 실제 경기 영상을 쓰지 않는다.** 내레이션과 자막에 이름이 나와도 화면은 얼굴이 보이지 않는 익명 미니어처로만 그린다.
- **화면에 웹 주소 · 스토어 검색 문구를 넣지 않는다.** 캡션에 "프로필 링크" 한 줄만 쓴다.
- **만든 결과를 먼저 보여 주고 올린다.** 공유하기는 매번 확인받고 누른다. 지난 승인은 다음 게시물에 적용되지 않는다.
- **돈이 드는 생성은 시작 전에 예상 비용을 알린다.** 이미지 약 $0.04/장, Veo 3.1 Fast 1080p 약 $0.12/초(4초 클립 $0.48). 11장면이면 약 $6(2026-11 단가).
- **AI 레이블을 켠다.** 장면과 목소리가 모두 생성물이다.
- **작업물은 레포에 커밋하지 않는다.** 소스 · 중간물 · 결과는 레포 밖 마케팅 보관 폴더에 둔다. 프레임 같은 큰 중간물은 클라우드 동기화 폴더가 아닌 임시 폴더에 쓴다.
- 로그인 정보는 입력하지 않는다. 로그아웃돼 있으면 사용자에게 부탁한다.

## 준비

- `gcloud auth login`이 돼 있고 Vertex AI를 쓸 수 있는 프로젝트 ID를 `GCP_PROJECT`로 넘긴다. 토큰은 출력하지 않는다.
- `ffmpeg`, Node 22, 레포의 `pnpm install`(합성이 `@playwright/test`의 Chromium을 쓴다). 의존성이 없는 워크트리에서는 `OFFSIDE_REPO=<설치된 체크아웃>`을 준다.
- 합성 음성: 사용자의 ElevenLabs 계정(브라우저 로그인). 목소리는 "Hyuk - Cold and Clear"를 써 왔다.

## 순서

### 1. 주제와 사실 확인

- 고르는 기준: "~하면 ~한다, 사실일까?"처럼 **흔한 오해를 뒤집는 주제**, 지금 뉴스와 닿는 주제, 마지막에 시청자에게 물을 수 있는 주제.
- 사실 표(문장 · 값 · 출처 2곳)를 `post.md`에 먼저 쓴다.

### 2. 대본

- 뼈대(7문단 안팎, 읽는 속도 1.1배 기준 약 40초): 훅 질문 → 뒤집는 답 → 구체적 숫자 → 사례 → 다른 길 → 지금 뉴스 → "여러분이라면?".
- 숫자는 음성용 대본에서 한글로 풀어 쓴다(34개월 → 삼십사 개월). 자막에는 숫자로 쓴다.
- 문장은 해요체, 한 문장에 정보 하나.

### 3. 음성과 자막 시각

- ElevenLabs 웹에서 대본을 읽히고 mp3를 받는다. 생성 기록의 `alignments`에서 글자별 시작 시각을 얻어 자막 `subs`의 `s` · `e`를 정한다(`character_end_times_seconds`에는 끝 시각이 아니라 길이가 들어 있다).
- 자막은 2~12자씩 의미 단위로 끊고, 핵심어만 `<b>`로 감싼다(라임색).

### 4. 장면

1. 문단마다 장면 1~~2개. 한 장면은 2~~5초. 화풍 문장을 고정한다:
   `Photorealistic miniature diorama, tilt-shift photography, high camera angle about 45 degrees, soft cinematic lighting, muted natural palette with deep greens, tiny anonymous figurines seen from a distance with no recognizable faces, no text, no letters, no numbers, no logos, no flags, vertical 9:16`
2. 첫 장을 만들고 확인한 뒤 나머지는 첫 장을 참조로 넘긴다.
   `GCP_PROJECT=<id> node scripts/gen-image.mjs img/02.png "Same miniature diorama style… <장면> <화풍>" img/01.png`
   참조 장의 소품이 따라오면(시상대가 다른 장면에 남는 식) 소품이 없는 장을 참조로 바꾼다. 429가 나오면 1~2분 뒤 다시 한다.
3. 이미지는 한 장씩 열지 말고 작은 대조표로 모아 본다. 통과한 장만 영상으로 넘긴다.
   `GCP_PROJECT=<id> node scripts/gen-video.mjs img/02.png clips/02.mp4 "<움직임 한 문장>. Slow subtle camera push-in, keep composition, miniature tilt-shift look, no text"`
4. 클립마다 처음 · 끝 프레임을 대조표로 확인한다.

### 5. 합성

`reel.json`을 쓰고 한 번에 만든다. 시간은 모두 내레이션 원본(배속 전) 초다.

```json
{
  "speed": 1.1,
  "tag": "축구 상식",
  "end": 41.04,
  "narration": "narration.mp3",
  "bgm": "bgm.m4a",
  "bars": [0, 4.56, 7.76],
  "scenes": [
    { "clip": "clips/01.mp4", "at": 0 },
    { "clip": "clips/02.mp4", "at": 4.56, "from": 0.4 }
  ],
  "subs": [{ "s": 0, "e": 1.84, "h": "아시안게임 <b>금메달</b>을 따면" }]
}
```

- `bars`는 문단 시작 시각(위쪽 진행 막대), `scenes[].from`은 클립에서 쓰기 시작할 초, `end`는 마지막 대사가 끝나는 시각이다.
- 배경 음악은 게임 곡 `apps/web/src/assets/bgm-loop.m4a`를 복사해 쓴다. 내레이션이 나올 때 자동으로 줄어든다.
- `node scripts/build.mjs reel.json <임시 작업 폴더> out/reel.mp4` → 1080×1920, 30fps.
- 3초 간격 대조표로 확인한다: 자막이 인물을 가리지 않는지, 빈 화면 · 잘린 마지막 줄이 없는지. **소리는 에이전트가 들을 수 없으니** 발음과 음악 크기는 사용자에게 들어 달라고 한다.

### 6. 올리기(확인 뒤)

인스타그램 웹: 새로운 게시물 → 게시물 → mp4 선택 → 자르기 9:16 → 다음 두 번 → 캡션 붙여넣기 → **AI 레이블 추가 켬**, 콘텐츠 예약 · Facebook 공유 끔 → 공유하기 → "릴스가 공유되었습니다" 확인.

- 캡션: 훅 질문 → 핵심 사실 서너 줄 → 참여 질문 → "프로필 링크" 한 줄 → 해시태그 최대 5개. 웹 주소는 쓰지 않는다.
- 붙여넣은 뒤 해시태그 추천 창이 열려 있으면 캡션 칸 위 사용자명 줄을 눌러 닫는다. 캡션 글자 수가 원문과 같은지 확인한다.
- 게시물을 교체할 때는 새 릴스가 프로필에 보이는 것을 확인한 뒤 옛 게시물을 지운다(`/p/<코드>/` 주소 → 옵션 더 보기 → 삭제 → 삭제).
- 끝나면 `post.md`에 주소 · 날짜 · 비용 · 음성 · 출처를 적는다.

## 첫 제작에서 배운 것

- 도형과 도트 그림으로 만든 3D 장면은 품질이 낮았다. 장면은 실사풍 미니어처 영상으로 만든다.
- 배경 음악이 없으면 완성도가 떨어져 보인다.
- 자막을 화면 가운데(63%)에 두면 장면의 주인공을 가린다. 70% 지점이 맞다.
